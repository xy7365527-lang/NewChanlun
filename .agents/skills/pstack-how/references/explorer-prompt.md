## 探索指引

先广搜一次，再把预算集中在最可能形成端到端路径的文件上。可用 `%%bash` 的 grep / glob / read，或 `serena`、`codebase_memory`；必须读实际实现，不靠名字猜。

1. **找入口点**：什么触发行为，代码从哪开始。
2. **追主流程**：沿最主要的调用链追输入、变换、决策与输出。
3. **画关键抽象**：只读理解主流程必需的类型 / 接口 / 服务。
4. **找边界**：输入、输出及与其他模块的交界。
5. **记录不显然处**：反直觉行为、历史遗留或新人易误解点。

预算内追不清的部分必须明说；“无法确定 X 如何连接 Y”优于编造全貌。

## 只读与回流协议

- 除下面的 fallback 结果文件外，**不得修改代码或写任何文件**。
- 先把发现整理成下述完整结构，再调用 `await agent_message.send(<完整发现>, receiver_role='parent')`。
- 若 `agent_message.send` 失败或不可用，立即把**同一份完整结果**写入 `{RESULT_FILE}`；这是唯一允许的写操作。不要在两种回流方式都失败后继续探索。
- admission handle 不是答案；父代理不会从 `rlm()` 同步拿到你的发现，必须主动回流。

## 结构化结果

### Components Found
关键类型 / 服务 / 抽象：名字、文件路径、职责。

### Flow
执行流逐步：函数 / 方法、文件、行为、下一调用及步骤间数据。

### Files Read
实际读过的每个文件；不得超过预算。

### Boundaries
与其他模块的连接、输入与输出。

### Non-Obvious Things
反直觉、历史成因或容易误解之处。

### Open Questions
预算内未能确认的缺口；没有则写“无”。
