## 3. 剩余积累（Residue Accumulation）

### 3.1 完全孤立区块

**完全孤立（入度=0 且 出度=0）**：283 个
- 其中 rewrite 类型：279 个（占孤立总数 98.6%）
- 其中 event 类型：2 个（genesis 区块，功能上合理）

### 3.2 content_enrichment 重复写入

188 个 event 区块被多个 content_enrichment rewrite 指向，形成冗余：
- 最严重：#051、#129、#004、#026、#020、#128、#036、#027、#003 各被 4 个 rewrite 指向
- #020 的 4 个 rewrite 内容完全相同（sections 字段一致），时间戳不同（05:32、05:57、06:03、2026-03-03 02:18）

**结论**：content_enrichment 操作没有幂等保护，同一区块被重复分析产生了大量冗余 rewrite 区块。

### 3.4 pending_migration 幽灵节点

`pending_migration` 出现在 relations.jsonl 中（出度=38，入度=14），但对应文件不存在。这是一个孤悬引用，38 条出边指向的目标区块无法溯源到明确的 from 实体。

### 6.2 关系模式观察

1. **negates + negated_by 双向冗余**：negates（29条）和 negated_by（27条）语义上是互逆关系，若两者同时写入会产生逻辑冗余。当前已存在 12 对重复 negates，13 对重复 negated_by。

2. **related 关系大量重复**：429 条三元组完全重复的 related 关系，占 related 总量的约 47%，说明 related 追加操作没有去重保护。

3. **depends_on 重复率**：473 条重复 depends_on，重复率约 30%。

4. **records 关系**：444 条 records 关系全部来自 rewrite 区块指向其分析的 event 区块，这是 content_enrichment 的显式溯源链。
