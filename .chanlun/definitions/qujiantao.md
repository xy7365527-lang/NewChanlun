## 2. 【N-3】名分收束：区间套 ＝ 纵向级别下钻，只有这一个义

### 2.1 教义条款

> **区间套 ＝ 从大级别往下，用逐级的背驰段收缩范围，把转折点定位准。**
> **纵向一个方向，没有横向义。**

**名分 `[旧缠论]`**。承重：`027-第27课.md:44`【正文】（该课正文界 `:78`，`:44` 在其内）。

**「区间套正本 ＝ 算子 N」不成立。**

### 2.2 五条理由（按承重排序，首条不是「原文没有横向义」）

1. **并列两者等于新造一个同名异物**（最硬的一条）。缠师的区间套有定理原文；代码的横向义**原文零出处**。把两者塞进同一个名字下，是**制造**混淆而非消除混淆——本正本的职责恰恰相反。
2. **原文只有纵向**。110 课全量检索：`区间套` 命中 35 文件／101 处，其中【正文】层 **27 处全部**是级别下钻；`板块`／`选股` 与 `区间套` **零共句**。
3. **那个「统一」在代码里不承重**（三条实测）：
   - `nesting_type` 字段**生产代码零读取**（唯一出现在 `src/newchan/nesting/nesting_operator.py:33` 声明处 + 测试 kwarg）；
   - 跑 [#804](https://github.com/xy7365527-lang/NewChanlun/issues/804) 总缝判别式——同一份数据分别标 HORIZONTAL／VERTICAL 喂进去，四个判定函数**输出逐位相同** ⟹ 方向这个区分不起任何作用；
   - 约束①（级别单调 `k_{i+1} ≤ k_i`）在横向**恒可取等号**、约束②（搜索空间 `|S|` 非增）在纵向**恒取等号** ⟹ **「统一算子」＝两条互不相交的约束做合取**，各自在另一支上退化为恒真；docstring 自陈的「纵向收缩**时间范围**」在 `NestingStep` 五个字段（`nesting_operator.py:33-37`）里**根本没有载体**。
4. **两者是串接不是并列**。横向第六步字面就是「标的内**纵向区间套**」（`src/newchan/nesting/horizontal.py:34`）；教义源自陈「**先横向收缩到标的，再纵向收缩到时机**」。先 A 后 B ⟹ 不是同一算子的两个实例，是流水线的两段。
5. **「算子 N」名分不够**。唯一出处 `tmp/levels-bsp-v2-push.md:205-230`——按 [ADR 0012](../../docs/adr/0012-inference-layer-document-naming.md) 三段式，在 `tmp/` **连推论层都不算**；`docs/adr/` 与 `.chanlun/definitions/` **各 0 命中**。拿无名分抽象当 `[旧缠论]` 概念的正本，方向反了。

### 2.3 连带条款：缠师是**借**「区间套」这个词，不是在用数学的闭区间套定理

**`027:40`【正文】** 缠师自陈「这些级别**不是无限下去的**，因此理论上并不能去证明就是一个如极限一样的点状情况的出现」；`027:50` 重申「不可能达到数学上唯一一点的精度」。

⟹ 闭区间套定理的前提（区间列**无限**且长度→0）**被他自己否掉了**。

**⟹ 硬条款：援引时不得反过来拿数学定理给他的说法加权。** 「区间套定理在缠论里成立」是**错的说法**；成立的是「逐级收缩范围定位转折点」这个**受限的形状**。（第三处不满足见 §3.3：收缩是单边的。）

### 2.4 横向那支：**改名 + 降名分**（编排者三档取甲）

| | 处置 | 判 |
|---|---|---|
| **甲** | **改名 + 降名分**：换一个不叫「区间套」的名字（它做的是**搜索空间收缩**），名分 `[新缠论:选择]`，归入「**重的标的绑定**」那条线 | **采纳** |

**它算什么：给「重」挑标的的，不是走势结构的算子。** 本仓早已归过位：

**名分分层**：「重要绑定标的」＝ `[旧缠论]`（ADR 0010 已裁）；「**用逐级收缩的方式**选标的」这个方法 ＝ `[新缠论:选择]`（原文零出处）。

**一手源先例（`[新缠论:候选]`，撑不住定义）**：《市场天道》正文 p206 编纂者比方「迷失外太空怎么回家：拉尼亚凯亚超星系团→…→中国→城市→区域→你家，其实这就是区间套的应用」。这是整个语料里「横向 ＝ 搜索空间收缩」**唯一的文本先例** ⟹ 本仓那个横向义**不是凭空造的**。**但**：① 编纂者语非缠师语，辅助层不作定义依据（`ch04.md:3` 逐字「权威地位：辅助层，不作定义依据」）；② 那串地址是**纯静态包含**（每级不需确认），而 `horizontal.py:98-114` 的每步都要求一个 **BSP 确认**才能推进 ⟹ 只支持「区间套可类比空间嵌套」，**不支持「选标的是算子 N 的实例」**。

### 2.5 ⚠️ ADR 0011 的「横向」与代码的「横向」＝ 同名异物（须点名，防第 6 次）

六栏对照**无一重合**：

| | ADR 0011 `:21`「横向」 | `nesting_operator.py:22`「横向」 |
|---|---|---|
| 轴 | **时间轴**（同一标的、同一级别切时间） | **标的/资产轴**（同一时刻收候选集合） |
| 输入 | 一层已造好的走势类型序列 | 一组比价线（配置空间／独立边／板块／标的） |
| 输出 | 该层走势类型分段 | 一个 target 标识（角／国家／板块／标的） |
| 递归 | **无**（ADR 0011 `:85` 明写「同级别分解是一次性切分」） | 六步 ＝ 同一操作六次应用 |
| 实装 | **本仓尚无实现**（ADR 0011 `:86` 明写） | 有（`horizontal.py`，`pipeline.py` 在消费） |

**这是本仓已登记的第 5 处同名异物**（前四：① 声部 vs 重；② 三阶段实例单位；③ 操作级别 vs 结构级别；④「次级别」的配仓义 vs 定位义）。**序数「第 5 处」把握中等**（依据是已成文的四处，`analysis/` 480 份里若另有未成文登记会变）；**序数不承重，同名异物这个判定承重**。

### 2.6 「横向落在 ADR 0011 三格之外」的推论

ADR 0011 三格是「纵向向上 = 塔／纵向向下 = 区间套／横向 = 同级别分解」。`nesting_operator` 的横向**落不进任何一格**——它不造级别、不读某层走势分段、不打点、不管筹码。它做的是「这一重该挂在哪个标的上」，即 **L-选标的**层，与区间套（L-判定层）分开列。

⟹ **「算子 N」这个名字承载的是选标的，它把「区间套」这个词借去当自己的名，借错了。**

### 3.5 裁定四：编号域硬要求 + 标准化 K 线载体（本组第二半，与裁定一同等级）

#### 3.5.1 ★ 先订正一句说过头的话

「原始序号不可逆推合并位置」**过强**。合并后每根 K 存的是该组**第一根**原始 K 的序号，而这些序号**严格递增** ⟹ 第 i 组覆盖 `[start_i, start_{i+1}-1]`，**成员集合与双向映射本来就推得出来（二分即可）**。**数学上没丢信息。**

**⚠️ 本轮独立核实发现：这条订正在 Rust 侧已经落成代码，且比裁定表述更进一步——见 §3.5.2 (a) 的冲突登记。**

#### 3.5.2 真问题是三件

**(a) 没有统一入口** ——
- **裁定表述**：每处自己想办法；在案实例 `parser/fractal.rs` 另存一份合并序号 `mid_indices`（`:112` 字段声明、`:137-151` 重建），`:96` 明写「不依赖 `source_index` 代理」、`:125`「`source_index` 单调性不足以精确反推 mid 下标」。**逐字复核成立。**
- **⚠️ 与裁定冲突，照实登记（本轮独立发现）**：Rust 侧**已有一个统一入口**——`parser/inclusion.rs:171` `merged_group_anchor(merged: &[Bar], source_index: usize) -> Option<usize>`，用 `partition_point` 二分实现，docstring `:158-170` 逐字写出了裁定 §3.5.1 的同一条推理（「组 i 覆盖原始序号 `[src_i, src_{i+1})`……故锚 = 最后一个 ≤ `source_index` 的 `merged[i].source_index`」），并自称「本口是组锚的**单一来源**——消费侧禁二次推导（**禁第二查法**）」。**有教义背书**（`chanlun/escalate/adr-chain-confirmation-and-invariant-identity-20260722.md:19` 裁定 3：「合并组锚 = 组内首根序号，非极值发生根」）。**有生产消费者**：`classifier/projection.rs:40/:169`、`classifier/level_view/pan_provider.rs:127`、`backtest/admission.rs:570/:876`（物化锚）、`classifier/nest.rs:557` 引其查法。
  **⟹ (a) 的准确表述须收窄为**：**「原始序号 → 组锚（＝组内首根原始序号）」已有统一入口且已禁第二查法；缺的是「原始序号 → 组号（＝合并位置／merged 下标）」这一步**——`merged_group_anchor` 返回的是**锚的原始序号**而不是**组的序数**，所以 `fractal.rs` 要 mid 下标时仍得自己另存 `mid_indices`。裁定提出的载体（挂「所属标准化组的**组号**」）正好补的是这一步 ⟹ **裁定的形态成立，但它的前提句「没有统一入口——每处自己想办法」在 Rust 侧过宽，须按本条订正**。

**(b) 尾部不稳定** —— 新 bar 到来会改最后一组的边界，某根原始 K「是不是某组起点」会翻。已确认前缀稳、尾巴不稳。（`inclusion.rs:161-162` docstring 自陈「末组覆盖 `[src_last, ∞)`，**尾部仍可生长**」；`chanlun/escalate/adr-chain-confirmation-and-invariant-identity-20260722.md:21`「合并组互不相交、**确认后**稳定」。**逐字复核成立。**）

**(c) 跨语言没有共享的合并序列** —— Rust 一份、Python 一份各自算。那里才是真对不上：**不是算不出，是算的不是同一个东西。**
- **本轮独立核实**：Python 侧的载体是 `merged_to_raw: list[tuple[int,int]]`（每根 merged bar → 原始 K 位置**闭区间**），产出于 `src/newchan/a_inclusion.py :: merge_inclusion`，消费于 `a_divergence.py:108/:119-122`、`a_assertions.py:108-114/:585-591` 等。⟹ **两侧各有一份载体，形态还不同**（Rust 稀疏锚点 + 二分；Python 稀疏区间表），**零对拍**。**(c) 成立且比裁定表述更具体。**

#### 3.5.3 裁定的载体形态

**不产出一条更短的新序列**，而是**保持原始 K 一根一根都在、序号都在**，每根额外挂上「**所属标准化组的组号**」+「**该组标准化后的高低**」。

**为什么成立**：`parser/inclusion.rs` 的包含处理是**有方向的左折叠**（`:21` 逐字「合并是**有方向**的左折叠」；遇包含吞进当前组、遇非包含定稿开新组）⟹ **每一组必然是连续的一段原始 K**，故**稠密标注直接成立，且组号即合并位置**。

**收益**：
- **(a) 与 (c) 直接消掉** —— 原始序号→组号一步得，组号→成员集合一步得，且跨语言可共享同一载体。
- **(b) 消不掉但变成明账** —— 组标记带「**已确认／暂定**」状态位，与 `fractal.rs` 现行的增量纪律（前缀不动、只重算尾部两组）同源，只是抬到地基层。

**代价**：多一份与原始 K 等长的标注（每根几个整数），**判断逻辑一行不改**。

#### 3.5.4 ⟹ 正本硬要求（一句）

> **区间套坐标所在的编号域必须与合并序列显式双向对齐，对齐关系是一份共享载体，不许各处自行推导。**

#### 3.5.5 ⟹ 验收门（写死）

> **新载体推出的合并序列须与现役逐位完全相同（bit-exact 对拍），不同不许合入。**

**理由**：包含处理是笔／线段／中枢／背驰**全部的地基**，动它**没有第二道保险**。
