### gap-B（M23/§15）：祖先在 [λ_e,ρ_e) 全程存活**未论证**（核心 gap）

## §7. 推论：BSP 总数渐近的结构判定（追加，复核 M26 范围内）

> 背景：另一线 codex 证 engine O(n²) 瓶颈下界 Ω(n^1.26)，根因实测 BSP 总数 ~ n^1.26 超线性，称唯一突破口是"结构定理证 BSP 总数线性"。本推论从 M26 元素树 T=(E,par) + M05 级别关系结构判定 BSP 渐近。L0 结构判定，非工程优化。

### 7.1 |E| = O(n)（成立，须不相交规范树前提）

缠论级别递归：级别 k+1 的中枢/走势由**至少 3 个**级别 k 次级别走势构成（中枢=≥3 连续次级别有重叠）。**若**每个级别-k 元素在上一级别恰属 ≤1 父（不相交规范树），则 `N_{k+1}≤N_k/3`，级别数 O(log₃ n)，
```
|E| ≤ n·(1+1/3+1/9+…) = n·Σ(1/3^k) = O(n)   （几何级数收敛）
```
**关键前提（codex 异质确认）**：≥3 规则**本身不证** |E|=O(n)——只有当"constituted by"意味着**不相交父子消耗**（一个级别-k 元素只喂一个级别-(k+1) 父）时才成立。这正是 M26 元素树 T=(E,par) 的 par 单值（每节点唯一父）所保证的——**M26 的树结构（非 DAG）蕴含 |E|=O(n)**。

### 7.2 量的身份混淆——这是核心发现

BSP ⊆ E（确认买卖点是元素子集，每中枢 O(1) 个 type1/2/3）。若 |E|=O(n) 则 **规范 BSP 节点数 = O(n)**。这与实测 n^1.26 **矛盾**。矛盾点（codex 确认）：**两个不同的量**——
- **规范树节点数**（structural node count）：在 M26 不相交树模型下 = **O(n)**。
- **实测 n^1.26**：是**另一个量**——事件流/候选图/版本化重算计数，不是规范树节点数。具体来自：(a) 中枢可**重构/延伸**，一个中枢随时间 emit 多个 BSP（事件计数 vs 节点计数）；(b) 候选中枢**重叠/共享次级别**（一个级别-k 元素属多个级别-(k+1) **候选**，破坏 7.1 的不相交划分——此时引擎数的是重叠候选图非树）；(c) 每 bar 流式**重评估** BSP，计 O(中枢数×bar 数) 事件非 O(中枢数) 节点。

### 7.3 判决（formalization-validity-domain，如实判定）

- **缠论规范 BSP 子集渐近 = O(n)**（L0 结构定理，由 M26 par 单值树蕴含）——**这是真结构定理，已成立**。
- **下界主张 Ω(n^1.26) 须精确化**：只对"引擎必须枚举/处理超线性 BSP **事件/候选**"成立；若主张"缠论规范 BSP 子集超线性"则是**伪命题（量混淆）**。
- **O(n) 引擎的真突破口（codex 异质确认）**：**不是**证 BSP 节点=O(n)（已成立），而是证**引擎能对每个规范 BSP 只 emit/process 一次，无版本化/候选/重评估多重性**——这是**工程实现问题（事件流去重/增量维护），不是缠论结构否证**。acceptance[4] 的 O(n) 目标在结构上**未被否证**（规范 BSP=O(n)），被卡的是引擎把节点计数做成了事件流计数。

**与既有谱系一致**：这是 `project_bsp_event_stream_osb_wall`（BSP 事件流 O(S×B) 墙）的结构层根因——第八墙"事件流全量 marshal+扫描"正是 7.2 的 (c) 流式重评估。结构层 BSP=O(n) 与工程层事件流超线性不矛盾，是节点/事件两个范畴（与本报告 gap-B 的"状态/事件范畴"分离同源）。

**L0 标注**：7.1/7.2/7.3 全 L0（从缠论定义+树结构推渐近，不依赖数据）。实测 n^1.26 是 L2/L3 经验量（事件流计数），与 L0 节点计数 O(n) 不可互相否证——正是它们被混淆才产生"结构否证 O(n)"的假象。codex 异质独立确认量身份分离，无新增 gap。
