## 矛盾报告

### 矛盾描述

**这是一个矛盾，不是三个 bug。** 12 矛盾清单里的 c段缺失（77.6% 趋势无离开段 c）、C7（中枢扩展/延伸/升级未建模）、实证4（BTC 15 倍牛市最高级别被识别为盘整、type1_buy=0），是**同一个定义冲突的三个显现**：**离开段 c（连接段）的归属，在纯重叠扫描下不可判定。**

**事实部分（L0，逐字源码核实，HEAD 06c9739f7e）：**

1. `center.rs::find_centers`（line 79）贪心顺扫：中枢终结后从 `i = last + 1` 继续找下一中枢，**把"离开前一中枢的连接段"吸收为下一中枢的首单元**（line 31–35 注释自述此简化）。
2. `trend.rs::segment_into_trends`（line 99–103）走势组边界 `ue = starts[gi+1]` = 下一组首中枢的首单元绝对索引。
3. `divergence.rs::judge_trend_divergence`（line 179–182）`c_start = 末中枢B末单元 + 1`；`c_start >= t.units.len() → return None`（无离开段，走势未完成）。

三者叠加的充要条件推导（与 `analysis/t_engine_profit_destination.md §2.2g`、`session_handoff_2026-06-20 §3.1` 独立一致）：
- 无 c 段 ⟺ `ue ≤ b_last + 1`（b_last = 末中枢 B 末单元绝对索引）；
- 非末组 `ue = a_next`（下一组首中枢首单元），而贪心吸收**恒令** `a_next = b_last + 1`；
- ∴ **非末组几乎必然无 c 段**（cut_away，非 truly_absent）。BTC 实测：所有无 c 段案例 `c_start == len` 精确相等、全是中间组 → 全是 cut_away。

**经验显现（L2，BTC 4.6M bar structural）：**
- 趋势走势 76 个，无 c 段 59 个（**77.6%**）；type1 全塔单调衰减 165→68→14→3→0，level3 起 type1_buy = 0；
- 最高级别（lad7/level4）在 BTC 4261→63086（+1380%）牛市中只识别出 2 中枢、0 UpTrend、1 Consolidation → 大牛市被折叠成"一个大盘整"（实证4）。

**矛盾的本质（概念层）：**

离开段 c（末中枢 B 之后、创新高/新低那段次级别走势）在缠论里**双重归属**：
- 它是**上涨趋势的离开段**——第37课趋势背驰 5 条件以它为核心（条件4「c 创新高/新低」、条件2「c 含对 B 的三类买卖点」、条件5「c 含 ≥2 次级别中枢」）。没有 c，趋势背驰无从判定，type1 无从涌现。
- 它同时是**通往下一个（反向）走势的过渡**——type1 卖点之后下跌趋势开始，下跌的进入段 a' 从 c 的顶点起算；贪心扫描据此把 c 吸收进下一组的首中枢。

但 `Unit` 是**不可分的原子**（一笔 / 一个次级别走势），代码必须把每个 Unit 归属**唯一**走势。"c 既属上涨离开、又属下跌进入"在原子归属下不可表达——这正是**谱系 540（递归结构的同一-差异双重性）/ 537（BSP 信号的同一-差异双重性）在 c段层的显现**：压缩视图（c 是下一走势的进入）与展开视图（c 是本走势的离开）不可坍缩，但代码当前坍缩到了压缩侧。

### 双方论证

**立场 A（保持现状：c 归下一走势，trends 为不重叠切分）：**
- 定义依据：递归塔的结构干净——`segment_into_trends` 输出的走势是 units 的**不重叠**切分，`encapsulate` 把每个走势封装为**不重叠**的上级单元，`Move(k) ≡ Level-(k+1) 笔`（谱系 540）在"笔不重叠"前提下成立。引入重叠会让上级单元重叠 → 中枢检测、所有级别的递归结构全部改变。
- 代价（已 L2 量化）：趋势背驰几乎从不完美（77.6% 无 c），高级别 type1_buy ≈ 0，最高级别牛市被折叠成盘整。alpha 在方向上产生但无可交易的一类买卖点定位。

**立场 B（c 归上涨趋势：trends 切片可重叠）：**
- 定义依据：第37课明确 c 是**趋势的组成段**（a+A+b+B+c），趋势走势必须包含它的离开段。让趋势组切片延伸到"下一走势方向真正反转的第一个单元"，c 段归属上涨趋势。
- 代价：c（创新高的上涨单元）同时是下跌走势的进入段 → 相邻走势切片**重叠** → 相邻上级单元重叠 → 改变 `find_centers` 在上一级的输入 → **重定义所有级别的中枢与走势边界**。且"离开段到哪里结束、下一走势从哪里开始"无 L0 判据——第9课中枢扩展/延伸"给定性不给定量"（两中枢"重叠多少"算扩展合并 vs 仍是两个中枢，原文留白）。

### 为什么是「定义冲突」而非「实现错误」（四分法 + testing-override 判据）

testing-override.md 判据：**「修复实现需要改变某条定义的含义、边界、或适用范围 → 定义冲突，停下来上浮」。**

- c段修复的任一形态（改 `find_centers` 连接段归属 / 改 `segment_into_trends` 组边界 / 引入重叠切片）**都改变中枢与走势的边界定义**，进而改变 `encapsulate` 输出、改变所有级别的递归塔结构。这不是「不改定义即可修复」的实现错误。
- 「放松条件4（创新极值）」这条看似纯参数的路也被否定为非 bug：`t_engine_profit_destination.md §2.2g 轴B` 已确认下跌 c 段不创新低是 **539号「翻空有效域 ⊂ 非上行」在信号层的同构显现**，是 regime 读数不是判据错误。
- C7（中枢扩展定量判据）原文级留白（第9课定性不定量），属 `no-workaround` 明示的「规格与实现的根本不一致」。

### 待编排者裁决的问题

1. **连接段归属规则**：末中枢 B 之后、下一走势之前的过渡段，归本走势（离开段 c，立场 B）还是归下一走势（首中枢首单元，立场 A 现状）？
2. **走势切片是否可重叠**（c 段两属）：若裁立场 B，是否接受「相邻走势/上级单元重叠」，并据此重写递归塔（影响 standalone T 全部级别 + bit-exact 守卫）？
3. **C7 中枢扩展的定量判据**：第9课「两中枢重叠多少算扩展合并」无原文阈值——是否引入综合层阈值（须独立 L2 标定，且属声明膨胀风险）？
4. **是否切到 v3 nucleus 连接段处理**（`crate::level`）作为 standalone T 的中枢扫描参考，替换贪心 `find_centers`？

> **诚实标注（有效域）**：本矛盾的修复属 H⁰ 构造轴，与已被 L3 证伪的 groupoid 入场轴（`project_type1_realtime_alpha_falsified`：type1 实时无入场 alpha）**正交**——即使 c 段修复让高级别 type1_buy 涌现，也**不自动**产生入场 alpha（实时锚下的转折定位已被证伪）。c 段修复的价值在于**离场信号 + 结构完整性**（幸存项），不在实时抄底。这降低了本矛盾的收益预期，但**不降低其作为定义冲突的严格性**——结构识别正确与否独立于其交易有效域。

### 对抗审查记录：「方案X（不改 find_centers，判背驰时从全局取 c 段）」为何无效

异质红队（codex-challenger，2026-06-20）对「定义冲突」分类提出反驳，主张存在一个满足三约束
（不改边界定义 / 不依赖未来 / 不碰会计层）的实现修复 **方案X**：`judge_trend_divergence` 不从
走势切片 `t.units` 取 c 段，而从全局 `all_units[c_start_global..next_group_start]` 取——切片本身
不变，只扩展背驰判定的读取范围。反驳的核心论点：「c 段在缠论定义上唯一归属本走势，只是实现
切片把它划给了下一组，故不是双重归属」。

**反验算（确定性代数，驳回方案X）：**

```
c_start_local = b_last_local + 1                    （divergence.rs:179，切片重基坐标）
b_last_local  = b_last_global − starts[gi]          （segment_into_trends:121 重基 u−us）
⟹ c_start_global = starts[gi] + b_last_local + 1 = b_last_global + 1
cut_away 的定义（无 c 段）= c_start_local ≥ len
              = b_last_global + 1 ≥ starts[gi+1]
              = c_start_global ≥ next_group_start
```

∴ 在**所有真正缺 c 段的案例**（77.6%）里，`c_start_global ≥ next_group_start`，方案X 取的区间
`[c_start_global, next_group_start)` **恒为空**（BTC 实测「所有无 c 段案例 c_start == len 精确
相等」正是这个等号）。**方案X 在它本要修复的 77.6% 上取出空 c 段，零增益。**

物理含义：离开段单元 c1（创新高那笔）确实存在于全局序列，但它被贪心吸收成了**下一组首中枢的
首单元**（`c1 = all_units[next_group_start]`），落在方案X 区间右端点**之外**。要让 c 段非空，方案X
必须把上界放宽到 `next_group_start + k`，把下一组首中枢的 k 个单元纳入本走势 c 段——而这些单元
同时是下一组中枢的构成单元（封装 + 上一级 `find_centers` 会用到）⟹ c1 被**双重持有** ⟹ 破坏
「每个 Unit 唯一归属一个走势」不变量 = **定义变更**。

**红队反驳被驳回：c 段唯一归属本走势这一前提，恰恰被「c1 物理上就是下一组中枢首单元」否证
——离开段与下一中枢首单元在 cut_away 下是同一个 Unit，这正是双重归属的实体。** 两条出路
（方案X 放宽上界纳入下一组中枢单元 / 改 find_centers 让连接段不被吸收）都是定义变更。**「定义
冲突」分类成立。**

**红队确认 + 论证升级（codex 撤回方案X）**：异质红队验算后**完整撤回方案X**，确认上述几何，
并把矛盾从「代码层 Unit 双重归属」**升级为两条原文之间的定义冲突**——这是比初始论证更精确、
更权威的层次：

> 当 `c1 = all_units[next_group_start]` 被 `find_centers` 贪心吸收为下一中枢参与段后，若同时
> 把 c1 作为本走势 c 段，则 c1 同时满足两个**互斥**的原文定义：
> - **第17课中枢构成**：c1 是「与下一中枢核心区间重叠的次级别走势」=「已进入中枢的参与段」；
> - **第37课 c 段（离开段）**：c1 是「末中枢 B 之后、尚未进入任何中枢的离开段」。
>
> **一个单元不能同时是「已进入中枢」和「尚未进入中枢的离开段」**。这是第17课与第37课在「贪心
> 中枢扫描」实现下的不可弥合冲突——**定义之间的冲突**（`no-workaround` 触发条件之首），不是
> 实现偏差。

这把待裁决问题精确化：**裁决连接段归属，本质是裁决「第17课中枢构成约束」与「第37课 c 段定义」
在边界单元 c1 上谁优先**——这是缠论原文层的裁决，超出蜂群自决范围（`no-unnecessary-escalation`
四分法：定义冲突=选择类/语法记录类，须编排者裁决）。
