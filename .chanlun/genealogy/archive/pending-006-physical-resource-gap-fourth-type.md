# 物质性 Gap——第四种 Gap 类型候选（OOM 不在 069 三 Gap 范围）

## 矛盾

W-10 自标关键警示 #3：422/423号谱系记录 VPS OOM 是蜂群首次显式遭遇**物理资源约束**：
- 423号：3 daemon 卡死 3 天 + SUBLATED 死锁修复 + **3 实例 OOM 运维降级**

094号建立了三个 Gap：
1. 创世 Gap（069号 RTAS 入口）
2. 视差 Gap（编排者/蜂群）
3. 审计层断裂 Gap（约束4 经约束1a/1b 中介）

但 OOM 不属于这三种：
- 不是 bug（代码逻辑正确）
- 不是声明—能力缺口（无对应声明）
- 不是创世/视差/审计 Gap

→ 提议第四种：**物质性 Gap**——蜂群运行的物质载体（VPS/内存/带宽）的有限性遭遇。

## 否定了什么

否定的是"094号三 Gap 已穷尽"的隐含假设。069号→094号的 Gap 拓扑只覆盖了**信息/认识论层面**的中断，未覆盖**物质载体层面**的中断。423号事件首次让物质载体作为蜂群规则集的盲点显影。

## 推导链

- 069号：递归拓扑异步自指蜂群（RTAS 入口 Gap）
- 094号：三 Gap 重定位
- 130号：RTAS 是体系存在论要求，不是工程优化（136号成本收益消解禁止的来源）
- 422/423号：3 实例 OOM 物质性约束首次显式
- 当前规则集（dispatch-dag.yaml / hooks / rules）对 OOM 类事件无覆盖：
  - ceremony_scan.py 不消费内存使用率
  - lead-audit.sh 不监控物质性约束
  - 无对应工位类型（无 ops-monitor 工位）
- 130号原则"体系存在论要求不接受成本收益分析"——但物质性 Gap 同时挑战这一原则：物质载体 OOM 时存在论选择被物理强制
