# 256号：254号定理1——三态逆序递归顺序的形式化跳跃（双轮质询确认）

## 矛盾描述

[Gemini 异质质询——两轮：gemini-3.1-pro-preview 理论层 + gemini-2.5-pro 代码层]

254号定理1 声称"递归顺序 = 三态逆序：先放大、后保留、最后吸收"，理由是"放大态 = 缠论辨识力最强处 = 区间套优先入口"。

## 形式化跳跃（第一轮：理论层）

233/235号对三态分类的定义是**观察属性**（D 算子对不同耦合类型的滤波效果）。
254号定理1将其转化为**操作指令**（区间套的递归执行顺序）。

这一转化缺少形式化依据：

1. ker(D) 描述"哪些耦合被 D 吸收"，不描述"缠论分析应当以什么顺序运行"
2. "信噪比高→优先入口"这一步，在 233/235/254 号任何位置均未经严格建立
3. 缠论的区间套入口由"本级别结构的拓扑完成度（如背驰）"决定——三态分类是跨品种耦合强度的度量，与单品种跨级别递归顺序属于不同语义层

## 代码层脱节（第二轮：gemini-2.5-pro 新增）

**严重性升级：致命**

Gemini 2.5 Pro 直接读取了代码库，发现：
- `CouplingType`（三态分类枚举）在整个代码库中几乎无引用，仅出现在 `discretization_kernel.py` 定义本身、其测试文件、以及 `scripts/t6t7_tristate_diagnosis.py`（离线诊断脚本）
- 在核心编排引擎（`src/newchan/orchestrator/`）、递归管道（`src/newchan/core/recursion/`）、资本流转层（`src/newchan/capital_flow.py`）中**均无基于 `CouplingType` 的排序逻辑**
- 定理1的"三态逆序"递归策略**未在任何在线递归或编排引擎中实现**

**结论**：不仅推导链是形式化跳跃，连实现都不存在。定理1是纯理论声明，没有代码对应，且代码也没有声明遵循这一顺序。

## 反例（第一轮）

边界情景：C-R 处于放大态（三态逆序应当优先），但当前递归级别上走势均未完成（v4 §2.5 等价条件不满足）。

- 按三态逆序：C-R 可以作为入口（放大态第一优先）
- 按 v4 §2.5 等价条件：不能（级别完成是前提）

两个规则冲突，254号没有处理。
