## 一、触发（本轮污染恢复+严格重推导循环）

本轮是一次污染恢复循环：某次 interrupt 后，蜂群面对一个问题——恢复时应当信任哪个状态作为真值，以及如何判定哪些产物是污染、哪些是合法的 pre-interrupt 在制品。处理过程中暴露了三条此前未显式化、但已在实践中运作的判据。它们共同否定了一个隐含假设。

## 二、被否定的隐含假设（201号模式的盲区）

201号（上下文恢复 + 结构修复 session 二阶观察）确立的恢复模式隐含一个假设：**恢复后的文件系统/session 快照本身是可信真值，恢复工作只是补全缺失的结构元数据**（缺 id、缺 block-topology 映射）。201号把恢复判为行动类，因为它假设快照内容正确、只是元数据不全。

本轮否定这个假设的适用范围：**当 interrupt 发生时，post-interrupt 快照可能携带污染**——不是元数据缺失，而是内容本身混入了不该存在的状态，或合法在制品被错误归类。201号的"补全元数据"模式在污染语境下不成立：补全一个污染的快照 = 把污染固化。

这是 **expansion 型否定**：201号的恢复模式在执行中遇到了它自身规定无法覆盖的语境（污染 ≠ 元数据缺失），规定者在更广语境中暴露不足。本号不废除 201（无污染时 201 仍成立），而是划出 201 的有效域边界并在边界外补三条判据。

## 三、三条判据（本号核心 = 语法记录候选）

### 判据一：污染边界按内容 provenance 判定，不按 commit 时间戳

**post-interrupt 即便看似忠实快照也不信任。** 判定某个产物是否为污染，依据是它的**内容来源（content provenance）**——这段内容是在哪个推导链、哪个语境下产生的——而非它的 git commit 时间戳。

理由：commit 时间戳记录的是**持久化时刻**，不是**内容产生时刻**（见判据三）。一段 pre-interrupt 产生的合法在制品可能在 post-interrupt 才被 commit，其时间戳落在 interrupt 之后，但内容 provenance 在 interrupt 之前——按时间戳判定会把它误标为污染。反之亦然。

这是 **no-patch（090号）在恢复语境的应用**：用 commit 时间戳这个易得但错位的代理变量判定污染边界 = 用方便的近似替代严格的判据 = 补丁思维。严格的判据是追溯内容 provenance，即使更费力。

### 判据二：对齐权威 = 干净 transcript，不是派生的 session 文件

恢复时的真值对齐源是**干净的对话 transcript**（生成史本身），不是从 transcript 派生出的 session 状态文件。

理由：session 文件是 transcript 的**派生汇总**，派生过程可能引入错误分类——本轮的具体表现是 **session 文件把 pre-interrupt 的在制品误标为污染**。派生层的分类错误不会出现在 transcript 中（transcript 是原始生成史）。

这与 **012号（谱系优先于汇总）同构**：session 文件之于 transcript，如同汇总之于谱系——汇总为了便利会压扁/重分类生成史中的信息差。恢复时对齐到汇总 = 继承汇总的分类错误。也与 **550号"真值在磁盘不在声明层记忆"同源**，但本号进一步区分：磁盘上的文件也分两层——原始 transcript（真值）vs 派生 session 文件（可能携带派生错误），不是所有持久化文件都等权威。

### 判据三：形式化产物的 git 持久化时机 ≠ 内容产生时机

一个形式化产物的 **git commit 时刻**与其**内容实际产生的时刻**是两个独立的时间点，二者可以错位。

理由（也是判据一的根因）：内容在推导链中产生（产生时机），在某个后续节点才被 git add/commit（持久化时机）。interrupt 可以落在两者之间——内容已产生（pre-interrupt）但尚未持久化，持久化发生在 post-interrupt。此时若用持久化时机（commit 时间戳）作为内容时机的代理，恢复判据会**自相矛盾**：同一段内容按 provenance 是合法在制品、按时间戳是污染。

这条判据是 551号"持久化时机"洞察在恢复域的延伸：551 已观察到 hook 守卫的物质实现可"先于本号落地"（持久化先于结算）；本号把"持久化时机 ≠ 内容时机"提升为恢复判据的根因。

## 四、三条判据的统一根

三条判据是同一命题的三个面：**恢复时不可信任任何派生层/代理变量，必须回溯到内容产生的原始语境（provenance）。**

- 判据一否定 commit 时间戳（时间代理变量）。
- 判据二否定 session 文件（派生汇总层）。
- 判据三给出根因（持久化与产生的时机错位使代理变量失效）。

共同模式 = **代理变量在恢复语境失效**：commit 时间戳是内容时机的代理、session 文件是 transcript 的代理，两个代理在 interrupt 边界都与被代理者错位。这与 formalization-validity-domain 规则同构（代理变量的有效域 ⊊ 定义域），但作用在恢复判据维度而非形式化验证维度。

## 五、边界条件（结论翻转）

1. 若 interrupt 不落在"内容产生"与"持久化"之间（所有 pre-interrupt 内容都已 commit）→ commit 时间戳与内容 provenance 不再错位，判据一退化为平凡，可用时间戳。本号的有效域 = **存在未持久化在制品的 interrupt**。
2. 若 session 文件的派生过程被证明无损（不重分类、不压扁）→ 判据二退化，session 文件可作对齐权威。当前本轮证据：session 文件实际引入了误标，派生有损。
3. 若 transcript 本身被污染（非"干净"）→ 判据二的对齐权威源失效，需更上游的真值源（如外部审计），本号未覆盖此情形。
4. 若某语境下污染 = 纯元数据缺失（无内容污染）→ 退回 201号模式（行动类补全），本号不适用。

## 六、下游推论

1. **恢复流程不能默认信任 post-interrupt 快照**——这会把"恢复"误判为 201号式的"补全元数据"行动类，从而固化污染。恢复语境需先做 provenance 审计，再决定补全 vs 剔除。
2. **ceremony_scan / session-start 恢复逻辑**若以 commit 时间戳或 session 文件作为状态判据，在污染恢复语境会产生错误分类——指向恢复判据应回溯 transcript provenance（生成态推论，非本号结算范围）。
3. **谱系/产物的恢复对齐**应以 transcript 为权威源，session 文件仅作索引/导航，不作真值裁判。
