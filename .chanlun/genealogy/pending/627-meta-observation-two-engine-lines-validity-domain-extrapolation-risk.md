# meta-rule 627：本轮两条引擎线的外推/范畴错误风险扫描

## 一句话结论

本轮存在两条并行的引擎线——(a) 旧 Python/Rust 引擎（ROADMAP M1 已做大量 L2/L3）；(b) theta_v0 严格 Origin canonical engine（A′ 收口轮，L2 刚起步）。按 231：**两条线缩小的是不同的有效域**，旧引擎结论不能代偿 theta_v0 的 L2。本号扫描两类外推/范畴错误风险（旧 M1 结果错误外推到 theta_v0 / theta_v0 L2 否定错误上升为缠论整体否定），结论：

- **两类风险当前均未实例化为违规**——ROADMAP M1 的 L2/L3 结论均明确归属旧引擎线（未冒充 theta_v0 预设）；625 已正确分层诊断（引擎实现层 bug，非 Θ 否证）。
- **但存在 1 个潜在缺口**：625 转述的引擎 bug 未标注归属哪条引擎线（风险2 的前置漏洞）。
- **1 条语法记录候选**：双引擎线并行期间，所有 L2/L3 回测产出与引擎 bug 记录须**强制标注引擎线归属**（(a) 旧 / (b) theta_v0）——这是 231『有效域 ≠ 定义域』在双引擎线语境的运行时纪律，当前未显式化。

## 风险1扫描：旧 M1 结果错误外推到 theta_v0

**风险定义**：把 (a) 旧引擎的『门控=暴露/择时 alpha 未确立』结论当作 (b) theta_v0 的预设结论，跳过 theta_v0 自己的 L2 验证。

**扫描结果：当前无违规实例，但需钉死有效域边界。**

| ROADMAP M1 L2/L3 结论 | 引擎线归属（核实） | 是否外推到 theta_v0 |
|---|---|---|
| E 版正 alpha / E>A>D / 背驰门控进出场 D 被证伪 | (a) 旧引擎（backtest/engine.py + rust orchestrator） | 否（明确旧引擎） |
| 期货 7 标的 E 跨资产未确立择时 alpha（符号 p=0.125/Fisher p=0.68） | (a) 旧引擎 | 否 |
| P3 暴露守恒弱成立（门控≈伪装 buy-hold，门控 alpha 来自 ~92% 暴露） | (a) 旧引擎 | 否 |
| BTC E +2194% / signal_resolution #71（1s+a0=笔 L2 否证） | (a) 旧引擎 | 否 |
| ω regime→美股方向真实数据反向证伪 | (a) 旧引擎 | 否 |
| 619 Origin canonical base / 616 完全分类⊬唯一策略 / 617 C_Θ 参数化 | (b) theta_v0（formal/Origin/, Strict/） | — 全 L0，无 L2 声称 |

**关键判定**：ROADMAP M1 段的 L2/L3 有效域 = 旧引擎线。theta_v0 引擎线（619/616/617）当前产出**全部为 L0**（lake build 绿 = 逻辑/构造正确，非经验有效）。两条线的有效域不重叠——旧引擎的『门控=暴露』是旧引擎在真实数据上的 L2 否定性结果（缩小**旧引擎**有效域），不是 theta_v0 的预设结论。**theta_v0 必须跑自己的 L2** 才能对 theta_v0 的门控/择时 alpha 下任何 L2 判定（231：旧引擎 L1/L2 不代偿 theta_v0 的 L2）。

**潜在外推触发点（监控，未发生）**：若 theta_v0 L2 起步后，蜂群以『旧引擎已证门控=暴露，theta_v0 同理』跳过 theta_v0 自己的 L2 → 即风险1 实例化（有效域膨胀 090：用旧引擎有效域冒充 theta_v0 有效域）。当前无此痕迹。

## 风险2扫描：theta_v0 L2 否定错误上升为缠论整体否定

**风险定义**：若 theta_v0 L2 产出否定性结果（strat≈0%/无信号/门控=暴露），须区分『引擎实现层 bug（工程层，正常修复）』vs『Θ 经验否证（定义层）』vs『缠论整体被否』——禁把工程层 bug 上升为缠论理论被证伪（分层诊断铁律）。

**扫描结果：当前无违规实例，625 已正确应用分层诊断，但暴露 1 个前置缺口。**

- **625 分层诊断正确**：625 把 L2 暴露的 strategy/mod.rs:417 bug 明确归为**引擎实现层 bug**（testing-override 判据：不改定义可修复=实现错误，正常修复），**未上升为 Θ 经验否证或缠论整体被否**。这是分层诊断铁律（MEMORY l2-engine-incompleteness-vs-theta-falsification）的正确执行。
- **★前置缺口（风险2 的漏洞）**：625 转述的 `strategy/mod.rs:417` bug **未标注归属哪条引擎线**——625 原文说『真实市场数据驱动缠论引擎/策略回测』，未区分 (a) 旧引擎还是 (b) theta_v0。分层诊断的三分（引擎 bug / Θ 否证 / 缠论被否）**必须先确定引擎线**：
  - 若 bug 在 (a) 旧引擎 → 该 L2 否定性结果缩小**旧引擎**有效域，与 theta_v0 无关。
  - 若 bug 在 (b) theta_v0 → 该 L2 否定性结果缩小 **theta_v0** 有效域，但仍属引擎实现层（非 Θ 否证、非缠论被否）。
  - **不标注引擎线 = 分层诊断的第一环（引擎层 vs 定义层）缺少前置坐标系**——bug 归属哪条线决定它缩小哪个有效域，未标注则三分诊断的有效域归属悬空。

**潜在上升触发点（监控，未发生）**：若 theta_v0 L2 起步后产否定性结果，蜂群须按四级分层：①引擎产不出信号（theta_v0 工程层 bug，正常修复）②Θ 产信号但不盈利（theta_v0 经验否证，缩小 theta_v0 有效域，可能上浮）③缠论分类/形式化错误（定义层，上浮）④缠论整体被否（**禁**——单引擎单标的 L2 否定性结果不足以否证缠论理论，需 L3 交叉验证且区分实现/定义/理论三层）。当前无此痕迹。

## 二阶模式：231 在双引擎线语境的运行时纪律（语法记录候选）

623 已识别 231 在『蜂群自身工具/spec 层』的连续实例化。本号识别 231 的另一运行时实例化场景：**双引擎线并行期间的有效域归属纪律**。

母规则 231：形式化操作的有效域可能严格小于定义域；两条引擎线各自的 L1/L2/L3 验证缩小的是**各自的**有效域，互不代偿。

**语法记录候选（上浮编排者辨认）**：双引擎线（(a) 旧 Python/Rust / (b) theta_v0 Origin）并行存在期间，所有 L2/L3 回测产出与引擎 bug 记录**必须强制标注引擎线归属**。这是 231 在双引擎线语境的运行时表达，当前未入任何规则文件。理由：

1. **无归属标注 = 风险1/风险2 的共同前置漏洞**——风险1（旧结论外推 theta_v0）和风险2（bug 归属不明致分层诊断悬空）都根源于『L2 结论/bug 未绑定引擎线』。
2. **231 的认识论等级标注（强制）已要求标 L0/L1/L2/L3**，但**未要求标引擎线**——双引擎线场景下，同一 L2 等级在不同引擎线上有效域不同，等级标注不足以定位有效域。引擎线归属是 L2 等级标注在双引擎线语境的必要补充维度。
