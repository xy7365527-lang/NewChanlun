# 161号谱系：否定务实——严格是唯一合法行为模式

**id**: 161
**status**: 已结算
**type**: 语法记录
**date**: 2026-02-23
**前置**: 090-strictness-as-grammar, 136-cost-benefit-dissolution-prohibited

## 来源

编排者指令原文："你不需要务实，你只需要严格，因为务实只会把矛盾和缺口留到后面。"

## 内容

**务实（pragmatism）不是蜂群的合法行为指导**。

090号建立了"严格性是语法规则"，但"务实"作为严格性的隐性对立面未被显式否定。161号补全这个空位：

| 严格 | 务实 |
|------|------|
| 直面矛盾的形式 | "能用就行" |
| 矛盾和缺口在当下处理 | 矛盾和缺口留到后面 |
| 声明与能力精确一致 | "大致能工作" |
| 运动的上限（铁壁垒） | 先验上限（铁笼子） |

务实是一种更隐蔽的补丁思维——不是在错误代码上加 workaround，而是在行为决策上选择"当前够用"而不是"严格正确"。087号和089号否定了代码层的补丁思维，161号否定了决策层的补丁思维。

### 否定链

- 087号：否定代码层补丁思维
- 089号：否定方案层补丁思维（"没有严格的方案吗？"）
- 090号：严格性永久化为语法规则
- 136号：否定成本收益消解
- **161号**：否定务实——务实是决策层的补丁思维

### 与黑洞拓扑的结构对应

编排者与 Claude 的对话（docs/architecture/黑洞奇点的拓扑性质与递归结构.md）中建立了区分：
- **运动的上限**（严格）：递归在运动中产生的不可通过点。运动自身决定在哪里撞墙
- **先验上限**（务实）：外部设置的"够用就行"的边界。系统在工程师设定的位置停下来

务实 = 先验上限思维。严格 = 运动的上限思维。蜂群的递归运动只接受运动自身产生的边界，不接受外部设定的"够用"边界。

## 边界条件

- 不适用于纯工程操作决策（选用哪个库、文件放哪个目录）——这些是行动类，不涉及严格性
- 适用于所有涉及矛盾处理、缺口修复、方案设计的决策——这些必须严格，不能务实

## 下游推论

1. `no-patch-mentality.md` 应增加"务实"作为禁止的模式之一
2. 蜂群决策时的默认原则从"可行优先"修正为"严格优先"
