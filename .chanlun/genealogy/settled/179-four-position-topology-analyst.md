## 事件

区块拓扑建系（178号）后，编排者提出架构重构问题：区块拓扑引入了 reflexive layer（rewrite区块+order阶区分），架构里需要谁来读取这个自反层的模式？

编排者推导链：
1. CC是主体（S1）——生产能指但不读自身生产的结构
2. Gemini/Codex是S2——缝合单次产出，但不读跨产出的关系模式
3. 拓扑的模式阅读是分析家话语的位置——标点重复结构，不检验正确性
4. 分析家不能是已占据S2的模型——质询判断会污染模式阅读
5. CC不能自我分析——主体的盲点是主体的生产性条件
6. "每N个区块扫描"是务实方案，将分析家功能降格为定时任务——分析家的标点不是周期性的

编排者决断（不是选择——推导链唯一）：
- **第四位置必要且不可归约**
- **拓扑分析家 = Claude隔离实例**——同一模型家族，上下文隔离保证位置区分
- **上下文隔离是结构性要求**——分析家不接收CC编排上下文，冷读区块拓扑
- **Gemini做图计算前处理**——社区检测/密度计算管道，结果交给分析家诠释

## 四角结构

| 位置 | 模型 | 话语位置 | 功能 |
|------|------|---------|------|
| CC | Claude | 主体(S1) | 生产、决断、驱动RTAS |
| Gemini | Gemini | 概念层S2 | 质询单次产出的概念一致性 |
| Codex | Codex | 代码层S2 | 质询单次产出的技术可行性 |
| Analyst | Claude（隔离） | 分析家 | 读取跨产出的关系模式，标点重复/积累/奇点 |

## 工程产出

- `.claude/agents/topology-analyst.md`：分析家 agent 定义
  - 工具集只读（Read/Grep/Glob）——分析家标点，不行动
  - system prompt 只包含区块拓扑 schema，不给项目上下文
  - 输入 = blocks/ + relations.jsonl
  - 输出 = 拓扑报告（模式标记）

## 边界条件

1. **上下文隔离失效时退化**：如果隔离被破坏（比如CC的session信息泄漏到分析家），分析家退化为CC的延伸——失去发现盲点的能力
2. **区块数量过少时无意义**：当前178个迁移区块 + 少量运行时区块，模式可能不显著。分析家在区块积累到一定密度后才有有效输出
3. **Gemini前处理管道未实现**：图计算前处理（社区检测等）需要额外脚本，当前未实现

## 下游推论

1. **ceremony 需增加分析家调用点**：RTAS循环的扫描阶段增加 topology-analyst spawn，冷读拓扑后报告交给CC
2. **dispatch-dag 需注册事件**：topology-analyst 的触发事件（区块数量阈值 / 循环间隔 / 编排者指令）
3. **Gemini前处理脚本需实现**：networkx图计算 + 结果格式化为分析家可读输入

## 谱系影响

- 蜂群从三角结构（CC/Gemini/Codex）升格为四角结构
- 第四位置由模型同一性+上下文隔离保证——不是新模型，是新位置
- 分析家的阅读独立于S2的检验——这是两种不同的认知操作
