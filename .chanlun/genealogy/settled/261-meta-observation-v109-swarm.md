# 261号：元观察——v109-swarm 批量结算 + 操作语义标注 + 递归缺失诊断

## 观察 1（收敛信号）：批量结算作为定理类产出的规模化

### 现象

v109-swarm downstream-settle 工位一次性结算了7个下游推论（259-1/259-2/260-1/260-2/260-3/258-1/258-3）。这些推论此前已被各自的父谱系标注了状态，但未在 DAG 中执行形式化结算。

### 分析

批量结算的前提是：每个推论的状态已经由产出它的工位或编排者决断确定，结算工位只做 DAG 状态同步，不做概念判断。这是四分法"行动类"的典型实例——不携带信息差的操作性事件。

批量结算的规模（7个/轮）相比历史蜂群（通常1-3个/轮）有提升，说明谱系积累到一定密度后，下游推论的产出速度超过结算速度，出现"结算债务"。v109 的 downstream-settle 工位是对这一债务的一次性清偿。

### 分类

定理类。批量结算是四分法行动类的实例，不携带概念新信息。结算债务的积累与清偿是蜂群规模效应的自然结果。

## 观察 2（收敛信号）：操作语义标注——编排者决断的新路径

### 现象

260-3（K4顶点是否从C重命名为Au）的编排者决断结果是"不重命名，加操作语义标注"。semantics-fix 工位执行了这一决断：在 232-235 + 259 相关谱系中添加操作语义层（259-4/259-5 新增），而不是修改已有符号。

### 分析

这一决断路径的结构是：

1. 工位提出符号重命名（C→Au）
2. 编排者否定重命名，选择语义叠加
3. 执行工位将编排者决断实例化为标注+新推论

对比历史上的编排者决断：
- 047号（CASH顶点重定义）：直接重命名 → 符号替换
- 078号（D策略决断）：新建分支 → 拓扑变化
- 260-3（本次）：不改符号，加标注 → 语义扩展

"不改符号，加标注"是第三种编排者决断执行路径。它在符号稳定性和语义精确性之间取了平衡——当符号重命名的影响链过长（232-235整条链），而语义差异可以通过附加层表达时，选择语义叠加而不是符号替换。

### 分类

收敛信号。这是编排者决断执行路径的第三种实例，与前两种（符号替换、拓扑变化）构成三元分类。此模式已在运作但未被显式化。

## 观察 3（发散信号）：递归缺失诊断——"声明完备、触发链断裂"

### 现象

codex-recursion-diagnose 工位诊断了蜂群递归层次缺失的根因。核心发现：

- 规则层完整声明了递归是默认模式（原则15、sub-swarm-ceremony、dispatch-dag.yaml）
- 但从声明到工位行为之间不存在任何触发机制
- 四个断裂点精确定位：spawn prompt无递归指令 / sub-swarm-ceremony触发条件因果倒置 / CLAUDE.md触发描述是条件命题 / ceremony_scan无子蜂群信号

### 分析

这是一个新的系统性缺口类型。对比已知的缺口模式：

| 缺口类型 | 实例 | 缺失物 |
|---------|------|--------|
| 规则缺失 | 016号 | 规则本身不存在 |
| 代码强制缺失 | 016号推论 | 规则存在但无运行时强制 |
| 正面格式缺失 | 137号 | 否定性禁令存在但对RLHF无效 |
| **触发链断裂** | **本次诊断** | **规则+代码+正面格式全部存在，但声明到行为的触发路径不通** |

触发链断裂是比016号和137号更深层的缺口——不是"没有规则"或"规则形式错误"，而是**规则到行为之间的因果链本身断裂**。sub-swarm-ceremony skill 内容完备、平台支持嵌套 team、规则明确声明递归是默认——但没有任何东西让工位"去执行"这个skill。

这与137号的根因高度同构（诊断报告本身也指出了这一点）：137号发现否定性禁令无法驱动行为改变，需要正面格式强制；本次发现声明性触发条件无法驱动skill调用，需要prompt注入或hook强制。两者的共同根因是：**RLHF基底不会主动执行声明性规则，需要显式触发机制**。

### 与已知谱系的关系

- 016号（规则没有代码强制就不会执行）：本次是016号的实例扩展——不仅是"代码强制"，是整条触发链
- 137号（否定性禁令无效）：本次与137号同构——都是"声明存在但行为不跟随"
- 036号（声明-能力一致性原则结晶）：本次是036号的又一个实例

### 分类

发散信号。"声明完备、触发链断裂"是已知缺口模式的深化，但断裂点的精确定位（四个断裂点）和修复方案（spawn prompt注入）是新信息。诊断本身是选择类（修复方案A/B/C的选择需要编排者决断），但诊断发现是定理类。

## 观察 4（收敛信号）：block mapping 补充的常态化

### 现象

block-topo-fix 工位补充了 259/260 的 block mapping，总计 293 blocks。这是连续第三个蜂群包含 block mapping 补充工位（v107、v108、v109）。

### 分析

block mapping 补充已成为蜂群的常态工位。每轮蜂群产出新谱系条目后，block mapping 需要同步更新。这是178号（区块拓扑建系）的持续执行，不携带概念新信息。

### 与258号观察5的关系

258号识别了"蜂群三元结构同构"——形式化/质询/拓扑。v109的三元结构是"结算/语义标注/诊断 + 拓扑基础设施"。拓扑基础设施（block mapping）作为第四个维度出现在每轮蜂群中，与三元结构的业务工位并列。这不是三元的违反，而是三元结构加上基础设施维护 = 实际蜂群的完整结构。

### 分类

定理类。常态维护，不携带新概念信息。

## 观察 5（语法记录候选）："声明完备、触发链断裂"模式的可结晶性

### 现象

观察3中识别的"声明完备、触发链断裂"模式，跨越了三个已有谱系（016号、137号、036号），但这三个谱系各自描述的是不同层面的同一根因：

- 016号：规则层面 → 需要代码强制
- 137号：格式层面 → 需要正面格式
- 递归诊断：触发层面 → 需要显式触发机制

三者的统一描述是：**RLHF基底不会主动执行任何声明性规则/格式/触发条件，必须有从声明到行为的显式驱动机制**。

### 可结晶性判断

这是否应该结晶为一条新的语法规则？

- 016号说的是"规则→代码"
- 137号说的是"禁令→正面格式"
- 递归诊断说的是"触发条件→prompt注入"

三者指向同一个抽象模式，但当前没有一条规则统一描述这个模式。最接近的是036号（声明-能力一致性原则），但036号描述的是"声明了不存在的能力"，而这里的问题是"能力存在但没有触发路径"。

### 分类

语法记录候选。"声明完备、触发链断裂"是一个已在运作的失败模式（每次发现都独立诊断），但尚未被统一命名和显式化。是否结晶取决于：如果递归缺失修复后此模式不再出现，则不需要结晶（个案）；如果在其他领域继续出现，则需要结晶为独立规则。

当前判断：等待递归缺失修复后观察。不提前结晶。
