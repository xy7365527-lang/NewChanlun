# 277号：D算子级别口径修正——级别=递归深度，不是K线周期

## 1. 矛盾描述

工位5（oq5-data-verify）的 `oq5_d_operator.py` 直接在月线/年线K线上运行D算子管线（bar→笔→线段→中枢→走势）。这使用了 `level_recursion.md` 中已被否定的**口径B（时间周期级别）**，违反了编排者 2026-02-16 的决断：

> "口径A（递归级别）是唯一正式路径。口径B（多周期独立管线）不在本项目中使用。"

## 2. 后果

直接在月线K线上跑D算子，662根月线产出：52笔、6线段、1个中枢 `[90.54, 110.31]`、0个走势。

DXY 55年历史被读为"一个大盘整"——因为月线K线把日内和日间的所有结构压缩成了一根柱子。2002-2007的120→70（42%下跌）被这个大中枢"吸收"，D算子读不出方向。

这个"中枢吸收效应"不是D算子的真实行为，是**级别口径错误的产物**。

## 3. 编排者论证

缠论的级别不是K线周期。1分钟图上的完整走势类型构成更大级别的笔，更大级别的笔构成更大级别的线段，以此递归。级别是递归深度决定的，不是选择月线还是年线的K线。

直接在月线K线上跑D算子 = 把662根月线当作"基础K线"处理 = 跳过月线内部所有结构。

2002-2007的120→70，如果从日线开始递归，内部有完整的日线趋势、周线趋势、月线级别的趋势（由日线递归上来的）。这些结构被直接用月线K线跑的D算子全部吃掉了——因为月线K线把所有内部结构压缩成了一根柱子。

正确做法：从日线开始跑D算子，让递归自然升级。日线笔→日线线段→日线中枢→日线走势完成→构成更大级别的笔→更大级别的线段→...递归到哪里停在哪里。

这样产出的"月线级别事件"不是"月线K线上的笔"，而是"从日线递归上来的、递归深度达到月线级别的完整结构"。两者区别巨大。

这也解释了为什么实盘操作从1分钟开始——不是因为1分钟"更精确"，是因为缠论的递归必须从最小可操作的基础K线开始，级别由递归自然涌现。

同时解决了Gemini Round 3的否定1（27根年线K线不够）——不需要年线K线，需要的是从日线递归上来达到年线级别深度的结构。日线数据量足够。

## 4. 定义依据

- `level_recursion.md` v1.0（已结算）：口径A（递归级别）是唯一正式路径
- 缠师第12课："级别在本ID的理论中有着严格的定义"
- 缠师第17课："在实际之中，对最后不能分解的级别，其缠中说禅走势中枢就不能用'至少三个连续次级别走势类型所重叠'定义，而定义为至少三个该级别单位K线重叠部分"

## 5. 边界条件

1. 日线数据覆盖范围决定递归能达到的最高级别——如果日线数据从2000年开始（~6000根），递归深度约4-5层，可能达到"季度级别"但不一定达到"年级别"。需要更长历史的日线数据
2. 如果从日线递归上来的结构在2002-2007仍然读不出趋势走势 → 中枢吸收效应在递归口径下也成立 → 需要重新评估三重联立判据的可行性
3. 本项目已有 RecursiveStack（max_levels=6），OQ5管线应复用此基础设施而非重建
