# 362号：B-M 研究线方向修正——编排者数学裁定

**认识论等级**: L0（编排者裁定是概念层方向修正，非经验验证）

## 背景

360号结算了 B-M（Beyond-Morse）研究线的 L0+L1 阶段：optimal_morse(27t) + weighted_morse(20t) + cerf_bifurcation(26t)，共 73 个测试。所有代码和管线验证通过，但 L2 验证（真实数据上的有效性确认）尚未执行。

编排者在 v160 开始前提供了对 DM1/DM2/DM3 三个方向的数学分析，构成对 B-M 研究线下一步（L2 验证）的方向修正。

## 五项洞察

### 洞察1：DM2 加权方向澄清——negates 边应倾向临界

**当前实现**（weighted_morse.py 第 50-66 行）：
```
negates: 4, supersedes: 3, references: 2, depends_on: 1
```
配对策略：优先配对低权重边，保留高权重边为临界。

**编排者澄清**：negates 边倾向于构成概念空间的**骨架**（不可消除的结构性连接），而 depends_on 是**可消去的冗余结构**。这意味着当前加权方向是正确的——negates 边应被保留为临界（概念硬核心），depends_on 边应被优先配对消除。

**推导链**：
1. 355号 L2 否定性结果表明均匀 Morse（所有边等权）不区分关键否定
2. 加权 Morse 的假设：高权重边 = 高信息差 = 应保留为临界
3. 编排者确认：negates 确实是概念空间骨架——否定事件创建了不可消去的拓扑连接
4. depends_on 是传递性依赖，多条 depends_on 路径到同一节点是冗余的（可配对消除）
5. 因此当前权重序 negates(4) > depends_on(1) 的方向正确

### 洞察2：DM1 三角簇硬度——2-单纯形制造共约化障碍

**DM1 结果**（dm1_report.md）：2906 个三角形，β₂ = 1259，Coreduction 简化率仅 33.2%。

**编排者分析**：紧密三角簇（A→B, B→C, A→C 同时存在）制造了**共约化障碍**——三角形内部的边无法被独立配对消除，因为消除任一边会破坏三角形的边界算子关系。

**推导链**：
1. DM1 中 m₀/β₀ = 213.2x（效率极低），原因是余面数普遍 > 1
2. 紧密三角簇 = 三个节点互相有关系 = 概念互依赖的三角形
3. 在谱系 DAG 中，这些三角簇对应：A 依赖 B，B 依赖 C，A 也直接依赖 C（传递闭包）
4. 编排者洞察：三角簇不仅是拓扑障碍，更是**概念硬核心**的信号——三个概念互相支撑形成的结构比链式依赖更刚性
5. 谱系中的实例：007/008/009 三角形（被 010号综合解决），062/064/065 三角形（被 068号否定），166-169 四概念中存在多个三角簇

### 洞察3：DM3 分岔判据层次——权重分布突变可能是拓扑事件先行指标

**当前实现**（cerf_bifurcation.py）定义了三种分岔标准：临界数量变化、Betti 数变化、权重偏移。

**编排者分析**：这三种标准存在层次关系——

| 标准 | 灵敏度 | 先行性 | 语义 |
|------|--------|--------|------|
| 权重分布突变 | 高 | 先行指标 | 高权重边进入/退出临界集 = 否定性事件正在酝酿 |
| 临界数量变化 | 中 | 同步指标 | 拓扑结构正在改变 |
| Betti 数变化 | 低 | 滞后指标 | 拓扑类型已经改变 |

**推导链**：
1. 权重突变在 Betti 变化之前发生——因为高权重边（negates）进入复形时先影响 Morse 函数值分布，然后才引起拓扑不变量变化
2. Betti 变化是"已经发生"的事后确认，权重突变是"正在发生"的预警
3. L2 验证应重点关注：权重突变位置与编排者标记的"关键否定"的时间对齐关系
4. 如果权重突变确实领先于 Betti 变化，cerf_bifurcation 的分岔检测应以权重标准为主、Betti 标准为辅

### 洞察4：L2 验证门槛——两个核心对比

**编排者裁定的 L2 验证标准**：

| 验证项 | 内容 | 预期结果类型 |
|--------|------|-------------|
| 分岔点 vs 大否定对应 | Cerf 分岔点（特别是权重突变型）是否与编排者标记的"关键否定"在时间上对齐 | precision/recall |
| negates 临界性验证 | 加权 Morse 中 negates 边是否显著更倾向于成为临界（vs depends_on 边） | 统计显著性检验 |

**与 355号的区别**：355号用均匀 Morse 的跳跃幅度（粗粒度指标）做验证，结果为弱相关。362号方向修正后的 L2 应使用加权 Morse + 权重突变（细粒度指标），预期 precision 显著提升。

### 洞察5：数学研究异质协作要求——Gemini + Codex 必须参与

**编排者裁定**：数学研究（包括 B-M 研究线的 L2 验证及后续数学推导）不能只用同质 Claude 工位完成，**必须与 Gemini 和 Codex 协作**。

**推导链**：
1. 同质工位（全部是 Claude）的数学推导存在系统性盲点——同一模型家族共享相同的训练偏置，可能在相同的数学推理环节犯相同的错误
2. 异质否定（heterogeneous negation）是蜂群发现引擎的核心机制（012号）——Gemini 和 Codex 的数学推理路径与 Claude 不同，能暴露 Claude 看不见的错误
3. 先例：309号（phase2 异质审查裁定）中 Gemini 的异质质询已证明其在暴露概念盲点上的有效性
4. 数学研究尤其需要异质检验——形式化推导中的错误往往是系统性的（某一类推理步骤的共同弱点），同质审查无法发现

**操作含义**：
- L2 验证脚本的设计和结果解读应经 Gemini 审查（orchestrator-proxy 协议）
- 数学证明或推导步骤应经 Codex 独立验证
- 纯管线代码实现仍可由 Claude 工位完成，但数学正确性判断必须异质
