## 观察结果

### 观察1（定理）：async-self-ref stagnation 误报——session 间隔短 + delta=0 fallback 缺陷

async-self-ref 工位检测到 2条 stagnation 确认为误报。根因：
- session 间隔仅 24秒（v231 和 v232 紧密连续）
- delta=0 时 fallback 逻辑将"无变化"等同于"停滞"

这是 036号声明-能力一致性（spec-execution-gap）的一个实例：stagnation 检测**声称**能检测停滞，但其判据（session 间隔 + delta）在快速连续 session 场景下会系统性误报。声明的能力（检测停滞）与实际能力（在间隔足够长时检测停滞）不一致。

**与 231号有效域的同构**：stagnation 检测的**定义域**是所有 session 间隔，**有效域**是 session 间隔 > 某阈值的子集。当前代码在定义域上运行但在有效域之外产出误报。

**四分法分类**：定理——036号声明-能力一致性 + 231号有效域不等式的联合实例。

### 观察2（定理）：block 缺失孤儿关系——194号 block(762219) 不存在但被5条关系引用

tension-scanner 发现 194号谱系的 block 文件（hash: 762219febc4b...）在 `.chanlun/block-topology/blocks/` 目录中不存在，但 `relations.jsonl` 中有 5条引用该 hash 的关系（3条 tensions_with + 2条 depends_on）。

这是 block-topology 数据完整性的边界情况：关系写入先于/独立于 block 写入，导致"孤儿关系"（指向不存在的 block）。

**结构分析**：194号谱系建立于 v53-swarm（2026-02-25），远早于 block-topology 系统上线。relations 可能是后续 topo-mapper 批量建立的，但 block 文件可能因为 194号内容过长（10 Key 并行诊断，审计结果丰富）导致写入失败或被跳过。

**四分法分类**：定理——数据完整性缺口，不需要价值判断。
