# 470号：抽象同构不等于工程等价（元规则）

## 核心命题

控制流同构（步间顺序/步内可并行）不能自动推出计算经济性同构。Dense vs Sparse、FLOPS-bound vs memory-bound、规模阈值——这些物理层差异被抽象类比遮蔽。

## 编排者自我观察

> "连续三次——保留历史折叠、GPU 单实例加速、GPU 多实例并行——我从一个正确的抽象洞察出发推演到了不成立的工程结论，Gemini 和 Codex 把我拉回来。"

三次实例：

| # | 抽象洞察 | 工程推论 | 否定来源 | 物理层差异 |
|---|---------|---------|---------|-----------|
| 1 | 保留历史 = 折叠材料 | 全量保留所有历史 | 质询 | 存储/查询开销与历史深度线性增长 |
| 2 | 步间串行/步内并行 = LLM 同构 | GPU 加速步内计算 | 462号 Gemini | Dense GEMM vs 不规则图遍历 |
| 3 | 500实例 = 500身体 | GPU 多实例共享图并行穿越 | 468号 Gemini | SIMT 发散、写冲突、barrier 瓶颈 |

## 推导链

1. **抽象同构的合法性**：在控制流层面，"步间串行+步内可并行" 与 "LLM token 串行+attention 层内并行" 确实是同构的——这是正确的抽象洞察
2. **工程等价的前提**：从控制流同构推导出计算经济性同构，隐含假设计算的物理特征也同构
3. **假设破产的三个维度**：
   - Dense vs Sparse：LLM attention 是密集矩阵乘法（全元素参与），图遍历是稀疏访问（只看邻居）
   - FLOPS-bound vs Memory-bound：密集矩阵乘法受计算量限制，稀疏图遍历受内存带宽限制
   - 规模阈值：GPU 并行开销需要 >100K 顶点摊薄，当前 K_active 千级
4. **元规则提取**：抽象层的同构关系不能跨越物理层——这与 231号（形式化有效域 != 定义域）是同一模式的不同实例

## 与 231号的关系

231号（形式化有效域规则）说："代数成立 != 经验成立"。470号是同一命题在工程领域的具体化："抽象同构成立 != 计算经济性等价"。

| 231号 | 470号 |
|-------|-------|
| 定义域 | 控制流抽象层 |
| 有效域 | 计算物理层 |
| 代数成立 | 控制流同构成立 |
| 经验成立 | 计算经济性等价成立 |

## 边界条件

此元规则在以下条件下需要修正：
- 当抽象同构确实捕获了物理层的关键特征时（例如：两个系统都是密集矩阵乘法，此时控制流同构确实蕴含计算经济性等价）
- 关键判据：抽象同构遮蔽了什么物理层差异？如果遮蔽的差异不影响计算特征，同构推论成立

## 下游推论

1. 未来遇到"X 与 Y 同构所以可以用同一方案"的推论时，强制检查：物理层差异是否被抽象遮蔽？
2. 编排者的抽象洞察仍有价值——作为假设生成器，不是作为结论。异质质询是将假设落地为结论的必要环节
3. 462号的"概念命名即度量渗入"（436号）是抽象同构遮蔽物理差异的具体机制之一
