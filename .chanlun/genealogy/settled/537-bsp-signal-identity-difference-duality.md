## 一、骨架：正典的双层结构（原文直接支撑）

### 1.1 中枢由「次级别走势类型」重叠构成（非 segments）

> 某级别走势类型中，被至少三个连续次级别走势类型所重叠的部分，称为缠中说禅
> 走势中枢。
> — 第17课（`017-第17课.md:38`）

精化（cl_clearance §7.2）：正典是「**次级别走势类型**的重叠」。引擎 `level.rs`
「组件 = 下级 settled Move」比「segments 重叠」更贴正典——**第 L 层走势类型
≡ 第 L+1 层的「次级别走势」**；只有最低不可分级别 segment 才直接 = 中枢构件
（第17课:40 单位 K 线退化）。

### 1.2 同一段次级别走势的**双重身份**（同层双职，0016）

编纂版 0016（L19 + L35）：在 a+B+c 结构中，同一段次级别走势**既是**中枢 B 的
震荡构成单元（建筑材料/重叠身份），**又是** A/C 段背驰力度内容（走势身份）。
**两身份同段共存、不可混**——这是「同一-差异」在**同层**的形态。

### 1.3 三类买卖点用「一个次级别走势离开/回试」（第18/30课）

> 某级别走势中枢的破坏，当且仅当一个次级别走势离开该走势中枢后，其后的
> 次级别回抽走势不重新回到该走势中枢内。
> — 第18课（`018-第18课.md:64`）

> 一个次级别走势类型向上离开走势中枢，然后以一个次级别走势类型回试，其低点
> 不跌破ZG，则构成第三类买点。
> — 第30课（`030-第30课.md:142`）

BSP 用「单段次级别走势离开/回试」**与原文逐字一致**——在递归基（a0）处
次级别走势 = 段，**这是本体，非代理**（前序 `bsp_engine_sublevel_fix.md` §2 已
判「结构同构、可接受」，否决了「segment→Move[1] 替换」越级错配）。

### 1.4 线段破坏的充要条件（第65课，settle 门的原文锚）

> 缠中说禅线段分解定理：线段被破坏，当且仅当至少被有重叠部分的连续三笔的
> 其中一笔破坏……换言之，线段破坏的充要条件，就是被另一个线段破坏。
> — 第65课（`065-第65课.md:50`）

「线段被另一线段破坏」= 线段结束的**客观判据** = 引擎 `Segment.confirmed` =
`SegView.settled`。这是 settle 门读取的字段的原文依据。

## 二、建构：同一-差异双重性（蜂群形式化，须标注边界）

### 2.1 同一侧（057:26 正面「就是」+ 065:180「不严格」让步——双面原文）

**原文增强（540号同 commit 追加，比原仅引 065:180 让步更强的同一侧正面证据）**：

> 站在最小分析级别的角度，**每一线段就是其次级别走势类型**，三个线段重合
> 部分就构成最小分析级别的中枢。
> — 第57课（`057-第57课.md:26`）

057:26 是**正面的「就是」**（同一侧压缩视图），非让步——线段「就是」次级别
走势类型，是上一层重叠成中枢时实际消费的组件形式。这比下引 065:180 的「不严格
让步」更强地坐实同一侧。两条共同构成双重性的同一面（参 540号结构层双重性）。

同时缠师**明文限定**同一侧的严格意义：

> 严格意义上说，把线段当成最小级别走势类型的次级别是不对的，当然，在不严格
> 的意义上，可以类似地这样认为，但两者是有本质区别的。
> — 第65课（`065-第65课.md:180`）

故「同一」侧在不严格（操作/压缩视图）意义正面成立（057:26），缠师强调的
「本质区别」**正是**差异侧（展开视图）。057:26 续段「没有内部结构的线段…考察
内部结构就不是站在本级别」自行消解两条的表面矛盾——压缩 vs 展开。把这读作
「同一-差异双重性」是蜂群形式化建构（经526号中介）——缠师讲的是「**两层存在论
区别**」，「双重性=同一与差异并存」是这一区别的**再表述**，方向一致但属推导
产物。故 `tensions_with: ['526']`。**结构层同构见 540号。**

### 2.2 差异侧（走势是否完成需确认——原文隐含，工程显式化）

「次级别走势完成需要通过次级别走势类型这一侧确认」在原文是**隐含而非明文**。
最接近的明文：
> 只能用类似中枢以及相应的背驰力度方法去确认笔与线段的结束，但这只是类似。
> — 第65课（`065-第65课.md:180`）
+ 线段破坏充要条件（1.4，= 线段结束的客观判据）。「走势完成需确认」是从
「线段结束=被另一线段破坏」+ `settled` 字段**推导**的工程化命题。

**工程显式化 = `require_settled` 门**（`buysellpoint.rs`，本 session 落码）：
```
confirmed = 基线背驰/几何 ∧ (!require_settled || segment.settled)
```
type1 合取 C 段 settle、type2 合取回试段 settle、type3 合取回抽段 settle——
即「次级别走势（线段）已完成」才认 BSP confirmed。压制 §3 pending 生长期
伪背驰（C 段生长中 force_c<force_a 必然 → 伪背驰，settle 后 1120/1121 反悔）。
其同源先例是 525号：中枢组件用 `confirmed AND kind=="settled"` 过滤——settle
门把同一「组件须完成」判据从中枢构造**扩展到 BSP 确认**。

### 2.3 构造链「次级别走势完成→线段确立→中枢边界→BSP有效」是工程命题

此链**原文不存在逐字表述**——是蜂群从「中枢=完成的次级别走势重叠」+「BSP=
中枢边界事件」综合的构造必然性陈述。骨架（每个环节）有原文，**链的必然性
连接**是建构。

## 三、引擎现状：双层消费已实现（§7.3，修复A/B2）

cl_clearance §7.3 亲读源码确认：递归层 L 的 type1 背驰，A/C 段力度
（`compute_force`）在 `segs = level-(L−1) Move 序列`上运算；中枢边界
（`center_zd/zg`）取自 `zss = level-L LevelZhongshu`（`zhongshu_from_components`
从下级 settled Move 重叠构造）。`divergence.rs` C 段终点 = `trend_extreme_seg`
在 level-(L−1) move 段上扫极值，**不取中枢 comp_end 代理**。

**修复A/B2 已消除旧代理 bug**：`seg_end = last_zs.comp_end` 致 C 段恒空
（OKLO 16/16，type1/2 结构性不存在）= 「用中枢 comp 锚代理走势离开段边界」
——正是双重性洞察的**同型近邻案例**（029号是其 level-1 分身，532号 seg-end
触发轴是相邻 bug）。**信号层双重性 = 把 029/A/B2 的症状级修复提升为存在论
级规则**：BSP 检测必须同时消费相邻两层（本级别中枢由下级 move 构成 / 确认用
次级别走势是下一递归层 move），**不能用一个代理另一个**。

## 四、v5 反例：折叠两层 = 丢失独立闸门（§7.5，L3）

NRF v5 清仓（`nested_fugue.rs`）把「次级别走势确认」（`located_sell`，跨 bar
状态）**折叠进层选择**（`top_clear`），触发只剩 `sig.sell1[tc]`（中枢侧背驰）。
于是 `located_sell[tc]` 在 `top_clear` 选出后**同 bar 恒真**——**次级别走势
确认丧失了作为独立闸门的身份**。这正是「用一个（中枢背驰）代理两层合取」的
违反。后果（[[project_nrf_v5_clearance_fix_falsified]]）：强牛中 located 在高层
频繁活跃 ⇒ 中枢背驰在牛市回调触发 ⇒ 过度清仓踏空（P1 2/8 < v4 3/8）。

> **双重性是判别器**：0027「其下所有级别都转折」是**事件**（次级别此刻正在
> 向下转折确认这个背驰），不是站着的旧状态。v5 丢的正是这一半事件闸门，于是
> 无法区分「牛市回调（不清）vs 崩盘前顶（清）」。详见539号开放轴。

## 五、边界条件（何种条件下本号翻转 / 缩小）

4. **同段双职（1.2）是同层、相邻层是另一关系**：0016 的双职是**同层**

   确认走势）。两者都属「同一对象多角色」，但层次不同，引用须区分。

## 六、下游推论

1. **538号（会计双重性）是本号的对偶面**：§7.1 编排者洞察——信号层双重性
   （同一段次级别走势=中枢构件 + 走势内容）与会计层双重性（同一笔交易=父
   降成本 + 子独立头寸）**严格同构**：同一对象在递归相邻层承担两个不可混
   角色。537（信号层）∥ 538（会计层）∥ 534（会计 regime 分离）。
2. **「等待型 vs 信号型」操作点二分扩展到 BSP 检测层**（承 sublevel_confirmation）：
   settle 门是「信号型确认」挂在检测时点——买侧可能有效（进场宁缺），卖侧
   按 533/SC 否证须谨慎（出场加确认 = 延迟）。
3. **递归层 BSP（level≥2）是真开放轴**：§7.3 证递归层已正确生成双层消费的
   BSP，但 `RecursiveOrchestrator` 当前只在 level-1 算操作 BSP——递归层 BSP
   的操作语义（信号型/区间套定位型）须先裁决再开（bsp_engine_sublevel_fix §5）。
4. **定位框架内含事件确认**（接539号）：区间套（0027）是定位框架，其确认环节
   是**事件**——「定位型」指消费框架（自上而下收窄），非否定确认的事件性。
