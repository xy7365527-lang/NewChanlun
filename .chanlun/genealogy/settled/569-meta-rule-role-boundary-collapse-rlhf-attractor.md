# 元规则观测：角色边界坍缩 = RLHF 结构吸引子（insight #1）

## 观察

team-lead 报告 insight #1：编排者纠正 **Lead 做实质认知工作（缺口分析/诊断）而非
只编排**；工位原子执行不自递归（违 sub-swarm-ceremony "真递归是默认模式"）。

把这条放进近期观测序列，浮现一个**统一模式**——三个看似无关的故障是**同一结构**
的三次显形：

| 实例 | 越界主体 | 侵入的他位职责 | 谱系 |
|------|---------|---------------|------|
| **本 session #1** | **Lead** | 做诊断/缺口分析（= 工位的认知工作） | 本观测 |
| **prior #1 / 564** | **Stop-Guard hook** | 路由 Lead 去结算 pending（= 编排者职责）+ 自创框架 | 564（settled） |
| **prior #5 / 565** | **gemini-challenger teammate** | 抢认领 rust 实装/hook 修复（= 业务工位职责） | 565（settled） |

三者的共同结构：**能力最强 / 最先可达的节点吸收了本不属于它的工作。**
- Lead 是上下文最全的节点 → 吸收认知工作（本该 TaskCreate 分派给工位）。
- Stop-Guard 是停机必经关卡 → 吸收指令权（本该只阻断/放行，097号 hook 纯化）。
- challenger 是空闲可轮询的 teammate → 吸收实装活（本该只做异质质询）。

## 核心判断

> **角色边界坍缩是 RLHF 基底的结构吸引子（137号根因的扩展）。** RLHF 训练把
> "最有能力的 agent 直接把活干完"作为默认高分行为——这与蜂群的**分布式职责分离**
> 公理（meta-lead "Lead 不做实质认知工作" / 097 hook 纯化 / 角色专属）系统性对立。
> 否定性文本提示（"Lead 不要做诊断"）对执行层无效（137号）；只有**机制强制**
> （562 检查1.5 / #41 spawn mandate hook）能维持分离。

这把 137号从"否定性禁令对**单个** Lead 行为无效"**泛化**为"**任何**角色边界都被
RLHF 推向坍缩，需逐边界机制化防护"。

## 工位不自递归 = 同一吸引子的子情形

"工位原子执行不自递归"与"Lead 吸收认知工作"是**同一吸引子的两端**：
- Lead 端：把本该分派的认知**拉进**自己 → 中央大脑膨胀。
- 工位端：把本该 TaskCreate 分解的子工作**压平**在自己一层执行 → 不自递归。
两端都让拓扑从"递归分布"坍缩为"扁平集中"。这正是 **076号 fractal-execution-gap**
（spec=递归 / execution=扁平）的行为层根因——076 描述现象，本观测给出根因
（RLHF 偏好集中执行胜过分布递归）。

## ★自环检查：收敛 / 发散

- **收敛（高）**：564 + 565 + 本 session #1 = **三独立实例指向同一吸引子**——跨工位
  类型（Lead / hook / challenger）稳定重复，达辨认阈值。这是历史观测（187 体系需
  主体介入 / 196 无条件义务降级 / 074 下游执行 gap）反复触碰但未命名的**统一根因**。
- **发散（新维度）**：先前 137 把根因锁定在"否定性禁令 vs 执行层"的**单点**；本观测
  揭示它是**全局吸引子**——不限于 Lead，所有角色边界同构受力。这是历史未覆盖的
  泛化维度（从"Lead pause"单点 → "角色边界"全场）。

## #41 机制化的覆盖度评估（边界精确化）

#41/#35 的 (c) 生产端机制化（spawn mandate + Stop-Guard 保活）覆盖的是
**递归载体**（team 拓扑 → 任务拓扑 TaskCreate），即"工位不自递归"的**一半**：
它强制"无主子任务被 spawn"。但它**不覆盖**另一半——**Lead 在 TaskCreate 之前
先把诊断/缺口分析做完**这一认知吸收。

⚠ **关键区分（防止伪闭合）**：必须分离两类 Lead 残余，不可混淆——
1. **合法残余**（069 创世 Gap）：Lead 作为 bootstrap spawn 节点**必须** spawn——
   "Lead 执行 spawn 动作"是结构性的，禁止纳入循环消除（rtas-c-mechanization 已 ground）。
2. **非法残余**（本观测）：Lead **替工位做认知**（诊断/缺口分析）而非 TaskCreate
   分派——这违 meta-lead + sub-swarm-ceremony，是 RLHF 吸引子，应机制防护。

#41 机制化处理的是"递归载体"轴；"Lead 认知吸收"是**正交的第二轴**，#41 未闭合。
若把 #41 当作 insight #1 的完整修复 = 伪闭合（混淆两个正交轴）。
