# meta-rule 623：本轮三教训共享元结构——231号在蜂群自身工具/spec 层的连续实例化

## 一句话结论

本轮三条浮现的元层教训**不是三个孤立事件，是同一个元结构的三次实例化**：231号(形式化有效域规则——有效域可能严格小于定义域)在『**蜂群自身的工具与 spec**』上成立。三实例 + 406号观察3(检测器有效域)使 231 的这一适用域达到可辨认密度。其中教训3 对 034号(工具声明≠工具能力)补一新维度——**判断主体从工具本体转移到消费工具的 agent 的认识论方式**。

## 与 621号/622号的边界（不重复 genealogist 已做的工作）

621号是 genealogist 本轮对**教训1单点**的缺口精确化(hooks GUARD 投递错对象 / task-notification 承重点 / 『待改不只待教』)。622号是 genealogist 本轮对**教训2单点**的缺口记录(worktree LFS smudge 失败 = 549/476 同根因新显形面 + 隔离降级 git archive+CARGO_TARGET_DIR)。本号**不重复 621/622 的任何内容**，而是把 621 所记教训1 + 622 所记教训2 作为**三实例模式中的两例**，与教训3 并置，识别更高抽象层的二阶收敛。分工：621/622=单点深度(各自 spec/工具有效域如何落空)；623=跨点广度(三点共享 231 元结构)。

## 教训3 对 034 的新维度（核心净新区分）

034号约束链(016→032→033→034，036 结晶为 spec-execution-gap skill)处理的是：『工具/agent **自身声明** 的能力 ≠ 工具/agent **实际具备** 的能力』——判断对象是工具本体。

教训3 暴露一个 034 未覆盖的维度：『**消费工具的 agent(Lead)对工具能力的认识论判断方式**』——Lead 读 prose 臆断 vs 实测，是两种认识论方式，前者有效域 < 后者。这把声明-能力不一致从『工具侧的客观属性』延伸到『消费侧的主观判断方法』。

**操作化推论(给 Lead，可立即执行，非待编排者)**：判断工具能力的合法方法是**实测(试)**，不是读 prose 推断。读文档形成的能力判断仅为假设，须经一次实测才能作为 spec 输入。这与 formalization-validity-domain 的 L0→L2 区分同构：读 prose=L0(纯声明，零信息增量)，实测=L2(可否证)。Lead 在 spawn/调度决策中以『读文档推断的工具能力』为前提 = 用 L0 当 L2 = 有效域膨胀。

## 二阶模式：231 适用域的扩展（separation）

231号原发生史(222 守恒律范畴错误 / 223 分类不完备 / 230 直积退化)三例**皆为缠论/数学形式化对象**。本轮三实例 + 406观察3(stagnation检测器)揭示：231 的适用范围内部存在异质性——它同样、且高频地适用于『蜂群自身的工具与 spec』，而这一适用域此前未被纳入 231 发生史。

这是 separation(分离型否定)：231 这个统一范畴内部暴露出『域形式化对象』与『蜂群自指工具/spec』两个异质子域。后者此前隐于前者之下，本轮使其达到可辨认密度。
