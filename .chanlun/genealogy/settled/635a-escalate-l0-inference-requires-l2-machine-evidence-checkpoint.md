# meta-rule 635a：escalate 前须经 L2 机器证据坐实（635 前半，已结晶）

## 一句话结论

本轮反膨胀守卫**三次生效**——三次都拦住了"**把 L0 推测当作已成立结论**"。三次不是孤立事件，是同一拦截语法的三次实例。结晶为一条**可执行检查点**：

> 任何 escalate（矛盾上浮）或"定义冲突"判定，在提交前必须先经一次 L2 机器证据坐实；仅有 L0 推测（读代码/读 prose/同源猜测）不足以 escalate。

## 三次守卫生效的统一拦截语法

| # | 险些发生的膨胀 | 实际形式 | 坐实证据（L2） | 拦截依据 |
|---|---|---|---|---|
| 1 | source_index 实现 bug **险被当作定义冲突**而 escalate | L0 推测（读代码推断是定义层矛盾） | 实测=实现层 bug，不改定义可修复 | testing-override 判据（不改定义可修复=实现错误） |
| 2 | "引擎产不出信号"=Θ 经验否证 | L0 误判（把工程层归因当经验否证） | L2 分层诊断=bug 吞信号（工程层） | 625 + l2-engine-incompleteness-vs-theta-falsification 铁律 |
| 3 | "#2/#5 疑似同源"作为同源结论 | L0 推测（结构相似猜同源） | 机器证据否定同源 | 600 异质审计否定价值 |

**共同语法**：三次拦截的对象都是「**L0 推测被当作已成立结论并据此 escalate/判定**」。这正是 231 的运行时表达——L0（推测）信息增量为零（同义反复/未否证），L2（机器证据）才有正增量（可否证）。把 L0 推测当 escalate 依据 = 用 L0 当 L2 = 有效域膨胀（090）。

**结晶判据**：三实例 + 625（L2 否证范式）+ 631（守卫诚实标注范式）≥ 5 次同模式跨工位收敛，且第三次（#2/#5 同源）未带新维度（净新区分→0=背驰）→ **达结晶条件**。

## Lead 操作化动作（escalate 前置门）

Lead 在分派 `/escalate` 或接受工位"定义冲突"判定前，**强制核对一张三问清单**：
- (a) 该判定依据是 L0 推测（读代码/读 prose/结构相似猜测）还是 L2 机器证据（实测/回测/字段比对）？
- (b) 若仅 L0 → **退回工位要求先坐实**（跑一次实测/grep/比对），不得直接 escalate。
- (c) testing-override 判据复核：不改定义可修复 → 实现错误（正常修复，不 escalate）；须改定义含义/边界 → 定义冲突（可 escalate）。

此清单是**正面格式约束**（137：不是"别乱 escalate"的否定禁令，是"escalate 前必过三问门"的格式）。
