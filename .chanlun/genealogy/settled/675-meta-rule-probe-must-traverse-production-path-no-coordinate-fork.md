# meta-rule 675：探针必须走生产路径，禁止诊断坐标系分叉（两次同构伪证的元结构）

## 一句话结论

本轮（及上轮）暴露同一元结构：**诊断探针走了与生产路径不同的坐标系，于是探针在诊断坐标系上「PASS」却不蕴含生产坐标系上成立——这产生伪证（false evidence）**。两次同构实例：
- **8dda restore 伪证**（上轮，commit `8dda5709`）：探针的 `active_depth` 走重建树坐标系，生产走 `next_active`（AncOK work 链）坐标系——分叉。修复=探针改从生产 `next_active` 取值 + `active_restored` 字段。
- **14166 伪证**（本轮）：诊断坐标系（`elem_depth` 走重建树）≠ 生产坐标系（生产 AncOK 走 work 链）。同构于 643 第一版 `frontier_mutated` 守卫比对 `project_to_units` 投影（投影有损丢 sub_moves=诊断坐标系）≠ 生产 sub_moves（生产坐标系）。

两次伪证都被**异质验证（codex + ChatGPT 双证伪）**走生产路径复现反例抓出——印证 640：自评/探针 PASS 最该被异质审查；异质验证是揭穿断言膨胀的唯一机制（已记 memory）。

## 元规则（语法记录候选）

> **探针/诊断代码必须走生产路径取值，禁止诊断坐标系与生产坐标系分叉。**
> 若探针读取的坐标系（重建树 / elem_depth / project_to_units 投影 / 任何诊断侧重建）与生产消费的坐标系（work 链 / AncOK next_active / sub_moves / 生产实际读的字段）不同源，则探针 PASS 仅证明诊断坐标系自洽（L1，信息增量零，同义反复），**不证明生产路径成立（L2）**——这是伪证。

**为何是 231 的实例**：探针走诊断坐标系=用自造的坐标系验证自造坐标系的属性（合成确认偏差，231 禁止模式2）。探针的有效域=诊断坐标系自洽，但声明的有效域=生产成立——有效域膨胀（231 禁止模式1 / 090 声明膨胀）。

**为何区别于 633**：633 是**单一坐标系内**消费方未重置局部下标（slice 切片后 fill_bar_index 仍按全集下标）——同一坐标系的下标错配。本号是**两个独立坐标系分叉**（探针造了一个诊断坐标系，生产用另一个）——不是下标错配，是坐标系来源本身分叉。两者都是「坐标系」缺口但维度正交：633=同坐标系内下标越界，675=跨坐标系来源分叉。

**为何区别于 627**：627 是「L2/L3 结论须标注引擎线归属」（哪条引擎线的有效域）。本号是「探针的坐标系须等于生产的坐标系」（探针验证的是不是生产路径）。627 是有效域归属标注（声明侧），675 是探针路径一致性（验证侧）——同母规则 231 不同维度。
