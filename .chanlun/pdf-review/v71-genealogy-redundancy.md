# v71 谱系冗余候选报告

## 触发背景

v71 新规则允许"A 否定 B / A 扬弃 B / A 分裂为 B 和 C"结构直接写 pending/。但降低阈值不等于允许冗余——若候选与已结算谱系在**核心语义**上重复，仍不应入 pending/。

本报告识别 v70 产出中的候选与 settled/ 中的潜在冗余，**不自动合并**（144 号保护已 settled），由下一轮 challenger 质询决定。

## 冗余候选 #1：486 ↔ 417/449

### 候选 486 描述

- **来源**：soros-full-spec.md §5.2 C
- **内容**：β 三层（背景/骨架/前台）的升降级流程——前台经验证升骨架，骨架长期稳定升背景，背景失效降骨架再降前台
- **结构类型**：分裂（β 单层 → β 三层）

### 已结算谱系 417（sublated-marker-architecture）

- **核心声明**（从文件名推断）：扬弃标记架构——标注"已被扬弃"的内容在 S_net 中的结构性位置
- **语义重叠点**：417 已定义扬弃机制的**架构**表达，候选 486 的"降级"流程（背景失效降骨架再降前台）在语义上是 417 的实例化
- **差异点**：417 是架构总则；486 是具体的三层结构 + 升/降两个方向的流程

### 已结算谱系 449（deposition-articulate-naming）

- **核心声明**（从文件名推断）：沉积-阐发-命名流程——穿越的沉积在 S_net 中形成的命名流程
- **语义重叠点**：449 的"沉积"流程在语义上可能覆盖候选 486 的"前台→骨架"升级（沉积=稳定化，即升级）
- **差异点**：449 是单向流程（沉积形成命名）；486 是双向流程（升+降）

### 冗余度评估

| 维度 | 覆盖度 |
|------|-------|
| 架构层面 | 417 已覆盖 60%——候选 486 的结构分层与 417 的扬弃标记架构同构 |
| 流程层面 | 449 部分覆盖升级方向（沉积），降级方向未覆盖——候选 486 的"背景失效"流程是**新增**的 |
| 三层粒度 | 417/449 均无"背景/骨架/前台"的三层显式切分——候选 486 的细分**有贡献** |

**初步结论**：候选 486 **非完全冗余**，其"三层具体化 + 降级流程"是对 417/449 的**扩展**而非重复。但"扩展"是否达到新谱系阈值？需 challenger 审查。

### 挑战问题

1. 417 的扬弃标记架构在实际 S_net 实装中是否已包含三层粒度？（若是，486 是冗余）
2. 449 的沉积命名流程是否已定义反向（去沉积/降命名）？（若否，486 的降级方向是新增贡献）
3. 候选 486 的三层（背景/骨架/前台）命名是否必要？若改用 417 的已有术语能否表达？
