下一层必须看 `ΔN_t = N_t^#5 − N_t^base`。**PDF §11（p13）三层判定**：声部生成层（depth>0 active）/
净额可见层（`‖ΔN‖_1` 是否非零）/ 经济有效层（Π^overlay/IR/回撤是否改善）。

## 3. ★核心矛盾：P0-3 执行层「接入 R/TW」被已结算谱系阻断（no-workaround）

### 3.1 矛盾精确描述

任务 literal 指令：「separate.rs 接入 strategy::ledger/R/TW 账本并影响真实开平仓」。

此指令与**已结算**谱系/规格三重冲突：

1. **674 号（settled，machine-checked L0）**：账本 R=Π-A-W 与缠论 TW 三阶段**不同构**（不存在
   保守恒量+保操作语义的双向忠实映射）。裁决 = **立场C（双层并置 + 单向有损投影，禁双向同构）**。
   codex-f2 裁定 #6 直接推论：「overlay 一旦执行即**第三**会计范畴，不能挂靠 R/TW 任一账本名下」。
   ⟹ 把 overlay「接入 R/TW」= 强行把第三范畴塞进 R 或 TW = 违反 674 立场C。

2. **多空对冲.pdf §8（p9）原文**：毛分账本有**两种合法用法**——账户型（`∑W_v` 真实 NAV，抵消
   仍发生）vs 诊断型（`∑G_e` 声部覆盖 score，不是 NAV）。**「这两个目标不能混用」**（PDF §8 原文
   `voice-capture score>0 ⇏ self-financing NAV alpha>0`）。当前落地 = 诊断型（‖ΔN‖_1）；升账户型
   overlay 是不同范畴，不是「接线」能达成的。

3. **PDF §10（p11-12）原文**：账户型 overlay 要求 **hedge mode / separated position account**
   （position book 存 `(Q⁺,Q⁻)` 而非 `Q⁺−Q⁻`）。生产是 **one-way/net account**（§10.1：
   `net_target_units=N_t`，同标的多空同时存在被净额化 `+Q−Q=0`）——`net_target_units`
   （coverage.rs:1331）确证：ShortDiff 腿在执行层被净额化（Σε_e·s_e），**生产不保留独立对冲腿**。
   接入执行层 overlay ⟹ 先切 hedge-mode 账户（PDF §10.2）= 重大架构改动，不在本任务范围。

4. **646 号（settled）**：`separate.rs` 用 u64 手数（§9 voice 层 `q_v`，整数）；coverage `LegTarget.
   units` 是 f64 sizing 层资本加权敞口（`base_units×w_depth`）。二者是**不同投影空间**（646 CONFIRM：
   范畴错误）。把 separate.rs 的 u64 P^sep 接进 f64 sizing 诊断 = 646 范畴错误。故 separate.rs 的
   「standalone 不依赖 strategy::ledger」隔离声明**是正确架构边界，不是待修缺陷**。

### 3.2 为何不写 OverlayState 独立第三账本（YAGNI，非补丁回避）

假设绕开「接 R/TW」改为「建独立第三范畴 `OverlayState` 执行账本」（codex-f2 #6 的合规形态）：
- **无消费者**：生产是 net account，不执行独立对冲腿（§3.1-3）——建了没有产者/消费者 = 死机制。
- **无 alpha 依据**：642 L2 已证 net-account overlay `ΔSharpe=0`（PDF §11 b1）——建执行账本无经济
  依据，且会声明系统不具备的 hedge-mode 执行能力（090 声明膨胀）。
- **PDF §11 明令的下一步不是「建账本」**：`depth>0≫0 但 ΔSharpe=0` ⟹「不应再问腿有没有开出来，
  而应检验 ‖ΔN‖_1=0 还是>0」——即**先诊断后账本**，诊断已落地，账本待诊断驱动真实对冲交易时才建
  （f2-impl §2 升级触发条件已写入 doc）。

### 3.3 四分法分类（no-unnecessary-escalation）

此矛盾是**定理类**（已结算 674 立场C + 646 投影空间的逻辑必然推论），**非选择类**——674 已裁定
overlay 必为第三范畴、646 已裁定投影空间分离、642 已 L2 否证 net-account overlay alpha。故本工位

   采集器）在 HEAD 已 commit；literal 剩余「separate.rs 接入 R/TW 影响真实开平仓」被 674+646+PDF
   §8/§10/§11 联合阻断，实装=no-workaround 违规，故不写。零新代码。
2. **定义依据**：区间套.pdf p8 裁决① + 第29课 A3（P0-1）；多空对冲.pdf §8/§9-11/§10（P0-3 三层
   判定 + 诊断型/账户型分野 + net/hedge 账户）；完全分类 PDF C25/C26/C29（P^sep）；输入特征——
   生产 `net_target_units` 净额化 ShortDiff 腿（coverage.rs:1331）满足 PDF §10.1 net account 定义，
   故账户型 overlay 的前提（hedge mode `(Q⁺,Q⁻)`）不成立。
3. **边界条件（翻转）**：若系统切 hedge-mode 账户（PDF §10.2，保留 `(Q⁺,Q⁻)` 独立腿）**且** L2/L3

   674 立场C），则执行层 overlay 值得建——三条件缺一不可。当前三条件全不成立。
4. **下游推论**：separate.rs 保持 standalone L0（隔离声明是正确边界）；overlay 生产度量 = ‖ΔN‖_1
   诊断（已接生产 legs）；f3 策略级回测消费 `overlay_net_delta` 累积 ‖ΔN‖_1（已在 l3_fullwindow）。
   Lead 若坚持执行层 overlay，须先裁 hedge-mode 账户架构（超本任务，且与 642 L2 结论冲突）。
5. **谱系引用**：674（settled，R/TW 不同构+立场C，overlay 第三范畴——P0-3 执行层阻断的核心依据）；
