## 我的核对结论（质询后判定）

对 Codex 的 6 条逐条核对，结论：**否定成立，判定与我独立审查完全一致**。

**#1/#2（致命，判定：成立，非误判）**——这是本次审查的核心发现。逐层核对：

- 代码事实核对：`locate_departure_move_a` 的过滤条件仅为
  `direction==trend_dir ∧ prev_center.end_index ≤ start_index < last_center.end_index`，
  取首尾匹配段拼接区间；`c_start_cache` 同款逻辑（`find` 第一个 `direction==dir ∧
  start_index≥c.end_index` 的段）。两处都**没有**对区间内的反向段做"是否真正回到中枢核心
  `[zd,zg]` 内侧"的判据——这正是 Q4（`judge_pan_div`，同一 diff 内）显式实现的 `reenters`
  闭包所做的事：`s.direction != dir && (Down: s.end_price >= c.zd / Up: s.end_price <= c.zg)`。
  Q5 的趋势侧代码完全没有引用这个判据，是**同一 diff 内两处平行逻辑的不对称实装**。
- 是否被结构性排除：检查 Q3 裁决（中枢延伸 GG/DD 完全分离）——该判据只约束**相邻中枢的外缘
  envelope**，不约束两中枢之间的原始线段是否曾经瞬间缩回前一中枢核心区间而不足以形成新中枢。
  即"中枢没有重叠"不能推出"中间线段没有回撤进前中枢核心"。因此这个 gap 不被其他机制结构性
  排除，是真实的定义忠实度缺口。
- 是否已被测试覆盖：两个新增的 Q5 专项测试（`q5_multi_segment_departure_a/c_interval_flips_
  divergence`）构造的多段场景中，中间反向段都**没有**触及中枢核心（只是趋势内部正常回撤）——
  测试集**没有**覆盖"中间反向段真正缩回核心内侧"这一边界 case，故这个缺口在当前测试矩阵下不可见。
- 定义依据：一类买卖点.pdf Q5——"A,C: Segment → LowerLevelMoveType"，"lower-level move type"
  在 decompose.rs 的语义下是一个**maximal 同标签 run**（Trend 或 Consolidation 块），块边界由
  中枢关系的标签变化决定。当前实现用"同向段首尾桥接"代替"次级别走势类型"，是对 Q5 裁决对象
  粒度的**走样**而非等价简化——不满足"episode 边界应在真正回中枢处断开"这一隐含要求。

**四分法判定**：这是**实现错误**，不是定义冲突（no-workaround 判据：不改变 Q5 裁决本身即可修复
——Q5 定义已经明确"次级别走势类型"是正确对象，当前代码只是对该对象的近似不足，补 reentry 判据
即可对齐，不需要重新定义 Q5）。因此**不需要 /escalate**，应作为代码缺陷直接反馈给 Task #145
工位修复。

**#3（建议，判定：成立，次要）**——C 侧确实缺少独立的"单段兼容性"测试，且兼容性隐含前提比
表面看起来更强（"seg 是 c 之后全局第一个匹配同向段"，而非泛泛的"只有一段departure"）。这是测试
覆盖缺口，不是运行时错误，标"建议"级别合理。

**#4（重要，判定：成立，但严重性可争议）**——核对代码后确认：`extract_signals_orig`（oracle
的调用方）在调用 `judge_first_orig` 前**确实**本地排序了 `segments`（`sorted.sort_by_key(|s|
s.start_index)`），所以当前测试实际调用路径中 oracle 收到的是已排序输入，不构成一个**当前会
触发**的坐标 fork。但 Codex 指出的更根本问题——parity 断言只比较最终布尔计数
（`s_diverge==prod_t1`、`s_mapped==prod_sb`），不直接比较 `(λ_C,ρ_C)` 区间值本身——是真实的
测试深度缺口：如果未来 λ_C 计算逻辑在探针与生产之间出现分叉，只要恰好两边算出的区间仍然导致
相同的 diverge/not-diverge 布尔结果，parity 断言不会失败。这违反 675 号"探针不允许坐标 fork"
的精神（该号谱系要求的是"同一判据链"，不仅是"同一最终计数"）。判定：**测试盲区，重要级别成立**。

**#5（无问题，判定：确认）**——核对 `AbcDivergence::diverges`/`segments_diverge` 代码，比较
算子（`curr_area < prev_area`，严格小于）本次 diff 未改动，只有输入区间端点变化。buy1/sell1
冻结判据未被意外触碰，确认成立。

**#6（重要，判定：成立）**——已用 `cargo test` 核实：`extract_signals_bit_exact_digest_guard`
的 GOLDEN 常量（`0x90c7_9ee6_17e1_1392`）在本次 diff 中确实未变化且测试仍 PASS，证实现有
bit-exact 回归电池的五组合成数据都没有触发 Q5 多段语义分支。Q5 的行为改变完全靠两个新增专项
测试单独见证，没有并入主回归电池防止未来意外退化。判定：**测试盲区，重要级别成立**。
