# area-memo：segments_diverge MACD 面积 (start,end)→f64 冻结缓存（task #57）

工位 ws-areamemo / 认识论：缓存正确性 = L1（管线确定性等价，231号）；计时 = L1（CPU 度量，零信息增量）
/ 代码影响：`rust/src/theta_v0/classifier/mod.rs`（+约75行：`AreaCache` 类型 + `TowerCache.area_cache`
字段 + `cached_segment_area` 辅助 + 5 处函数签名穿线）。`rust/tests/theta_v0_07b_gating.rs` 净 diff = 0
（诊断用临时 test 已移除）。

## 结论

`segments_diverge`（`sublevel_diverges` 内联展开）的两次 `segment_macd_area` 调用改为经
`(start,end)→f64` 冻结缓存查询——首次算出后原样存取，不做前缀和差分（B3 报告明确禁止的方案）。
bit-exact 逐字段验证通过（debug 30K bar 逐 bar `debug_assert` 全通过，累计 123514 个第二类端点，
与 07b 报告数字一致）。缓存命中率极高（300K: 99.73%，1M: 99.91%），07b_extract_second 阶段计时
CL 1M 从 1026ms（07b 门控后基线）降到 670ms（**34.7%↓**），300K 从 90ms 降到 57.6ms（36%↓），
全窗墙钟 CL 1M 从 15.5s 降到 15.0s（3.2%↓）。

**★诚实否定性结果（本工位最重要产出）**：面积计算本身已被 99.7%+ 消解，但 07b_extract_second 阶段
的**标度指数未变**（修前 ln(1026/90)/ln(1M/300K)≈2.02，修后 ln(670/57.6)/ln(1M/300K)≈2.04）——
`segments_diverge` 的**调用次数本身**随 n 近二次增长（300K→1M 调用数 821,098→8,766,346，指数≈1.97），
且每次调用内部仍有 O(subs) 开销（见下）。这推翻/精化了 B3+07b 报告的归因："MACD 面积 O(range) 累加"
不是残余 O(n²) 的**唯一**成分——存在一个正交的第二根因，未在本工位范围内修（见「下游推论」）。

## 定义依据

- 契约锚：`Origin.Divergence.IsDivergence`（`d.forceC.area < d.forceA.area`，Divergence.lean:83）——
  `is_divergence(prev_area, curr_area) = curr_area < prev_area`（严格 `<`，divergence.rs:244，未改）。
- 缓存正确性依据 hist 前缀 append-only 稳定（`MacdState::append` bit-exact，ac75d4b3 已证）+
  `compute_macd_hist_incremental` 的 unstable-tail 语义（mod.rs:658-720：每 bar 末元素 `tail_state`
  是**推测值**，下一 bar `truncate(resume_from)` 丢弃重算——`cached_segment_area` 只在
  `end < stable_len`（`stable_len = cache.macd_state_len`，本 bar 确认边界，恰好排除该末元素）时
  读写缓存，`end >= stable_len` 每次现算，绝不写入缓存。

## 边界条件（会翻转结论的条件）

1. **hist 前缀 append-only 假设被破**（如 `MacdConfig` 改变导致 EMA 参数变化但未触发 `TowerCache::clear()`）
   ⟹ 缓存值失效。已覆盖：`clear()` 显式 `self.area_cache.clear()`（line ~508）。
2. **`stable_len` 边界判断放宽**（如误将 `end == stable_len` 也纳入缓存）⟹ 破坏 bit-exact（tail 值
   下 bar 可能改写）。已用严格 `<` 守卫（`cached_segment_area` 内 `if end < stable_len`）。
3. **`RefCell` 借用冲突**：本函数域内无重入调用路径（`cached_segment_area` 不递归、不跨闭包嵌套借用），
   `borrow()`/`borrow_mut()` 均为叶子级短暂借用，无 panic 风险（已由 1394 lib + debug 30K bar 验收覆盖）。
4. **否定性结果的边界**：若「调用次数 O(n²)」的诊断（见下）在未来审计中被推翻（如证明 subs 增长实际
   有界），则 07b_extract_second 的标度指数应会随本工位而下降——当前 CL 1M/300K 实测未见下降，
   本工位诚实记录该否定，不据此推断"面积累加"归因错误的确切占比（需专项 profile，超出本工位范围）。

## 下游推论

1. **面积累加本身已解**：`segment_macd_area` 的 O(range) 逐点求和不再是重复成本来源（99.7%+ 命中率
   证实 B3 报告"跨-bar 冗余=99.94%"的诊断对**面积计算**这一分量是准确的）。
2. **★新发现的正交根因（未修，留后续工位）**：`rmove_compose.rs::find_second_type_structure`
   （line 144-169）对每个 `parent` 做 `for i1 in 0..subs.len() { for i2 in (i1+1)..subs.len() { ... } }`
   双重嵌套扫描，`divergence_of(m1)` 在**每个 i1**都调用一次；而 `sublevel_diverges`
   （mod.rs line ~1499）内部又用 `subs.iter().position(...)` **线性重新定位** `m` 的下标（`i1` 在外层
   循环已知，但闭包接口只传 `&RMove`，故需二次线性搜索）+ `subs[..idx].iter().rev().find(...)` 找
   `prev`。对仍处于 frontier（未 confirm）阶段的单个 `parent`，若其 `subs.len()=k`（该 parent 尚未
   confirm 期间逐 bar 累积的次级别走势数），则**每 bar** 重算该 parent 的成本 = O(k)（外层 i1）×
   O(k)（`position`/`find` 内层线性扫）= O(k²)，且此 O(k²) 逐 bar 重复直到该 parent confirm——这是
   与"面积累加"完全正交的第二个 O(n²)-ish 源，本工位范围（`segments_diverge` 面积缓存）不覆盖。
   下游工位可评估：(a) `find_second_type_structure` 改传 `i1` 下标避免重新 `position()`；(b) frontier
   parent 的 `subs` 增量缓存（同 07b 门控精神）。
3. 07b/B3 归因文档措辞需订正：「残余 O(n²) 根因 = frontier parent 的 segments_diverge MACD 面积累加」
   应改为「残余 O(n²) 由(a)面积累加 [本工位已解] + (b) find_second_type_structure 候选枚举的 O(subs²)
   重复线性定位 [未解，新工位] 两个正交分量构成」。
4. 信号集完全不变（B2/S2 逐字段 bit-exact），不影响 W-VERIFY(#13) alpha 有效性判定。
