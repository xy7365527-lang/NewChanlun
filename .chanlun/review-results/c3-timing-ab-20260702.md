## 归因口径（如实标注，A1 与 C3 同 commit 不可完全解耦）

1. **总加速 1.19–1.22x 是 A1+C3 合并效应**，无法在单 commit 内完全拆分。
2. **A1 的可隔离证据**：stage `08_levels_centers_clone` 209→27.5ms（−181ms，同标签直接可比）。A1 的 classify-stage 净收益量级仅 ~150ms（08 省 181ms，07c 补 26ms），且被 post 新暴露的 00b 标签（371ms）在「总和」口径上掩盖。A1 另有独立 07c/08 profile 证据（见 07c-memo/08 相关 profile 记录）。
3. **C3 的归因（消去法）**：classify stage 总和在 post **不降反升**（+435ms），但总 wall 降 ~2.5s ⟹ 全部净加速来自**未计时区**（`collect_signals` 的 cand/nest cert + 小转大/反转段路径 + decompose 聚合）。C3 的 `find_move_by_end_index`（partition_point 二分，O(log n) 替线性 `position/find`）恰落在该未计时区（`econ_positive.rs:543/580/644` 小转大/反转段 + `cand_predicate.rs:182/200` div_cand），且逐 bar 调用、move 序列随塔深增长 ⟹ **观测到的 1.2x 主要归 C3**。
   - **口径边界**：C3 收益是「总时降幅 − A1 的 08 stage 降幅」的间接归因，非直接计时（该路径无 stage_profile 埋点）。数据加载（314MB JSON，两侧同）不进净差。

## 结果包六要素

1. **结论**：post(A1+C3) 对 pre(C1) 在 350K 代表窗 decompose/dx 上总加速 **1.19x（real）/ 1.22x（finished）**；其中 A1 隔离收益 = stage08 −181ms（7.6x），C3（未计时 cand/小转大路径）经消去法承担剩余全部净加速。
2. **定义依据**：C3 = commit 4c23604f4c 的 `find_move_by_end_index`（partition_point，前提「LeveledMove 按 end_index 升序」由 debug_assert 守护，release 编译掉）；A1 = `Rc::clone` 替全量 clone（08_levels_centers_clone 埋点）。pre 副本无 `find_move_by_end_index`（grep=0），post 有（grep=1），忠实对照。
3. **边界条件**：结论翻转条件——若换机器/窗口/config，或 05_compose_resume（对照）出现>3% 系统性偏移，则 1.2x 不成立；若未来给 cand/小转大路径加 stage_profile 埋点直接计时，C3 归因可从「消去法」升为直接测量（当前为 L2 间接归因）。
4. **下游推论**：`acc-optB-speedup` 的 C3 项 = 本报告 1.2x 合并加速（C3 主导）。A1+C3 叠加在 C1（2.08x）之上；classify 核心（05_compose_resume ~5.4s）仍是 O(tree)/bar 主瓶颈，未被 A1/C3 触及，归 classifier 核心优化（Task #104/#105）。
