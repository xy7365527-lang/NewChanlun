## 题一（数据）：776 笔 RiskExit 割后走势审计

### 1.1 先修正一条前提：776 笔里只有 89 笔是真止损

原以为 776 笔都是「价格触及结构止损价」。实测**不是**。

按 `trades.jsonl` 自带字段推的 `stop = entry_px ∓ entry_stop_dist`，逐笔检查触发 bar 的 [low, high]：**722/776 两侧都不触及**。这不可能由 `stop_hit` 的定义产生，说明触发路径与「持仓方向的止损被触及」不是一回事。加探针取真值后原因定死（`admission.rs:1236` 一带）：

```rust
let exit_side = match leg.dir {                    // ← 方向取自走势载体 leg.dir
    VoiceSide::Long => FillSide::Sell,
    VoiceSide::Short => FillSide::Buy, ...
};
let stop = open_trades.get(&leg.id).and_then(|o| o.entry_stop)  // ← 价取自开仓 certificate 方向
```

探针实测 776 笔的 `leg.dir` 与开仓 `entry_z.delta` 对照：

| leg.dir | 开仓 delta | 关系 | 笔数 |
|---|---|---|---|
| Long | −1（开空） | **相反** | 258 |
| Short | +1（开多） | **相反** | 434 |
| Long | +1 | 一致 | 35 |
| Short | −1 | 一致 | 49 |

**692/776 = 89.2% 方向相反。** 后果是机械的：开多仓（止损在下方）却按 Short 腿判 `high >= stop`——入场价本就在止损之上，`high ≥ stop` 入场瞬间即为真；开空仓同理镜像。**止损变成开仓即命中的恒真谓词。**

按开仓真实方向重判「价格是否真的触及止损价」：

| | 笔数 | 占比 |
|---|---|---|
| **真止损**（价格确触及结构止损价） | **91** | 11.7% |
| **假命中**（方向错配，价格从未触及） | **685** | 88.3% |

持仓时长的旁证：**687/776（88.5%）的 RiskExit 持仓恰好 2 根 bar**，1 根的 55 笔——合计 95.6% 在 2 根 bar 内被切。这与 memory 在案的「#270 wf8 92.3% 交易持仓恰好 1 bar」病理线是同一条。

RiskExit 分布在 727 个不同 bar（每 bar 1–3 笔），**排除 `force_flat` 全局强平**（那会一次清空所有腿）。

### 1.2 割对率 / 白割率（三档 N，两口径）

出场价口径须先讲清：`fill.rs:3810` 写的是 `exit_px: px`，即 **`px = bar.close`——触发 bar 的收盘价，不是止损价 `stop`**。所以「收复止损价」与「收复出场价」是两件事，下面两口径都以**实际出场价**为基准（那才是账上真金）。

**宽口径**（N 根内触及出场价 = 白割）：

|---|---|---|---|
| 5 | 70 | 706 | 9.0% |
| 10 | 44 | 732 | 5.7% |
| 20 | 31 | 745 | 4.0% |

这个口径**没有判别力**，如实记下：1 分钟 bar 下价格 20 根内回踩一次出场价近乎必然，随机游走也能刷出 96% 白割率。不拿它当结论。

**严口径**（N 根末收盘优于出场价 = 白割，即真的「反向走出去了」）：

| N | 割对 | 白割 | 割对率 | 白割率 | 割对避损 $ | 白割机会成本 $ | 净额 $ |
|---|---|---|---|---|---|---|---|
| 5 | 364 | 365 | 46.9% | 47.0% | 679,505 | 976,530 | **+297,025** |

**笔数上割对与白割各占一半，无方向性**——这正是「止损点与走势结构无关」应有的样子（若止损真踩在结构失效位上，割对率该显著高于 50%）。金额上白割成本略高于割对避损，N=5/10 净 +30 万/+43 万，N=20 收窄到 +7.7 万。

### 1.3 对照组：这些仓位不割会怎样（真正回答「前面赚的怎么解释」）

按 `(position_node_id, entry_bar)` 把 776 笔 RiskExit 配回 bug 态 P0 的同身份仓位，**468 笔命中**（308 笔在 bug 态不存在同身份仓位——止损改变了后续仓位演化）。

| | 笔数 | 名义金额 |
|---|---|---|
| bug 态（不割）平仓更优 = **白割** | 206 | **+7,340,965** |
| bug 态更差 = **割是对的** | 217 | **−2,708,996** |
| 持平 | 45 | 0 |
| **净额** | 468 | **+4,631,968** |

对照 execR 差额 4,626,831 −(−312,337) = **4,939,168**——这 468 笔配对仓位解释了 **93.8%**。

平均持仓：割臂 **28.9 bar** vs bug 态同仓位 **652.2 bar**（22.6 倍）。bug 态这些仓位的了结方式：CloseRoot 187 / ReduceCore 158 / CloseReverseOpen 121 / Hold 2。

**「前面赚的钱」的账因此清楚了**：笔数上割对（217）比白割（206）还多一点，**割本身不是普遍地割错**；问题在金额分布——白割那 206 笔平均每笔 +35,636，割对那 217 笔平均每笔只避掉 12,483，**2.9 倍差**。差额来自持仓时长：不割的仓位平均持有 652 根 bar，让少数大幅盈利的仓位跑完；止损在 2 根 bar 内把它们连同亏损仓位一起切掉。**bug 态的 +4,626,831 不是「靠不止损硬扛出来的」，是「少数长持大赢家没被误杀」。而误杀它们的不是止损纪律，是方向错配的假止损。**

### 1.4 直接回答：割对多还是白割多

- **笔数：五五开**（严口径 46–48% 对 47–48%，三档 N 一致，分侧也一致）。
- **金额：白割多**。同身份对照下白割 734 万 vs 割对 271 万，净 **+463 万**倒向不割。
- **但这个「白割」的成因不是止损理念错，是判据实现错**：88.3% 的触发根本没碰到止损价。真止损只有 89–91 笔，样本不足以裁定「结构止损该不该有」。

## 题二（代码）：π 级联止损的触发判据全文

### 2.1 止损价从哪来 —— 结构价，不是比例

链路：`fill.rs:3909 entry_structural_stop(c, &classification_i)` → `signal.rs:76` 按候选 `(level, source_index)` 查 `BspPoint` → `risk.rs:74 structural_stop(side, bits, stop_in)`：

```rust
StopSide::Long  => { if bits.buy1 || bits.buy2 { stop = pivot_low }
                     if bits.buy3  { stop = min(stop, center.zg) } }   // 取更宽
StopSide::Short => { if bits.sell1 || bits.sell2 { stop = pivot_high }
                     if bits.sell3 { stop = max(stop, center.zd) } }
```

- **1/2 类买 = pivot low（分型低点）；3 类买 = ZG（中枢上沿）**；卖侧镜像（1/2 类卖 = pivot high，3 类卖 = ZD）。
- 类别重合（如 2B∧3B）取**更宽**者（多头更低、空头更高）——`risk.rs:69` 自陈「此裁定不由 spec 推出，是 strategy 层的 Θ_risk 设计选择」。
- 无对应方向买卖点 ⟹ `None` ⟹ 不判止损。
- 入场时**一次性冻结**到 `LedgerOpen.entry_stop`（`fill.rs:4006`），逐 bar 风控门读冻结值，**非 trailing**。

**定性：这是结构判，不是机械价判。** 止损位全部落在中枢边（ZG/ZD）或分型极值（pivot high/low）上，无固定点差、无百分比、无 ATR、无时间止损。teaching 层面它想做的正是「结构失效即离场」。

### 2.2 级联规则 —— 谁被连坐、按什么顺序

`step.rs:131`（`coverage_step_from_buckets_sep_with_risk_seeds`）：

```rust
let mut direct_close_seeds = buckets.close.clone();
for seed in risk_close_seeds {
    push_if_absent(seed);                                        // ① 命中腿本身
    if let Some(carrier) = risk_seed_carrier(tree_prefix, seed) { push_if_absent(carrier) }  // ② 其结构 carrier
}
let closed = close_indices(prev_active, &direct_close_seeds);    // ③ 进现役子树清仓机关
```

- **连坐范围**：命中腿 + 其结构 carrier + `step_active_set_with_subtree_close` 算出的**整个后代子树**。
- **外化正交**：直接父 → `StepTrace.risk_exits` → `RiskExit`；后代 → `silent_drops` → `CloseReverseOpen + via_structural_prune=true`（wf8 实测 109 笔 CloseReverseOpen 里 105 笔带 prune 标记）。
- **顺序**：`runner.rs:1829` 明载「子 StructuralPrune 先于父 RiskExit」。
- **carrier 身份重建**（`step.rs:60 risk_seed_carrier`）：同级严格右端点精确命中 → 唯一左开右闭 span `λ < signal_index ≤ ρ` 兜底 → 多重命中 fail-closed（宁可漏补 seed 留裸腿，也不按方向或宽度猜）。这一段是保守的，不是 776 条的来源。

### 2.3 为什么高到 776 条 —— 不是判据太紧，是方向错配

排除了三条常见解释：不是 `force_flat`（分散在 727 个 bar）；不是止损太窄（`entry_stop_dist` 中位数 312.46 美元、最大 6,051 美元，对 26,000 的 BTC 是 1.2% 中位、23% 上限，不算紧）；不是级联放大（RiskExit 桶只收直接父，后代落 CloseReverseOpen）。

真因如 1.1：`exit_side` 取 `leg.dir`（走势载体方向），`stop` 取开仓 certificate 方向，89.2% 相反 ⟹ 止损判在错误一侧 ⟹ 恒真。776 条里 685 条由此而来。

值得记一笔：`admission.rs:1245` 的注释自己写过「这类腿的 `dir`=走势 eps（**非持仓方向**）」——但那句话是用来解释「不在 `open_trades` 的结构载体腿」的。实测表明，**在 `open_trades` 里的 campaign 腿，其 `leg.dir` 同样不是持仓方向**，而 `exit_side` 恰恰是从它取的。#572 修的是「腿 ID 不再被压平丢失」（那一步确实对），但没碰 `exit_side` 的取值来源；修复前布尔门也是按 `leg.dir` 分桶的，只是从不落地成交，所以这条错配一直不可见。

### 2.4 它跟中枢震荡打不打架

**判据本身有结构避让**：止损位就在 ZG/ZD 上，正常情况下中枢内震荡不会触发——只有真正跌破中枢上沿（3 类买失效）或破分型极值（1/2 类失效）才触发，这与「中枢破坏即离场」同构。

**但当前实现完全没有避让**，因为触发跟价格无关了：89% 的腿开仓即命中。中枢震荡在这里不是被误杀的原因，方向错配才是——它连「打架」的机会都没有。

> ……因为上涨和盘整必然要在图形上完成，而上涨和盘整在图形上的要求，是必须包含三个以上的次级别运动，因此后面必须还至少有一个向上的次级别运动，**这样的买点是绝对安全的，其安全性由走势的"不患"而保证**，这，就是在前面反复强调的第二类买点。

**`blog/049-第49课.md:64`**（承认操作模式内仍有结构风险，但解法是「按模式走」而非设止损）：
> ……但这有一个风险，就是中枢震荡后，不一定就能出现第三类买点，可以直接出现第三类卖点就下跌……如果完全按照以上缠中说禅操作模式，就不存在这个问题了。至于能否达到这缠中说禅操作模式的要求，是技术精度的问题。

### 3.3 判定

**三档取 (i) + (ii) 并存，不取 (iii)。**

- **(i) 原文明确不要止损：成立。** 86课:34 是无条件否定句（「从来没有任何止蚀之类的无聊概念」），26课:90 是明确反对，13课:16 点名否定「按亏损比例止蚀」。三处独立成段、口径一致。
- **(ii) 原文有结构止损语义：成立，且是原文自己给的替代品。** 13课:18 把「止蚀」重新定义为「走势从能搞变成不能搞」，并明确**与盈亏脱钩**（「可能已经大大赢利了」）；16课:32「必须先减仓退出」、24课:36「先出来」是它的具体动作形态。
- **(iii) 认可常规止损：不成立。** 唯一近似的是 22课:636，但它是**条件降级句**——「如果你经常判断错误，止损还是需要的」，前提句是「能熟练判断买卖点就不需要任何特别的止损」。这是对技术不过关者的补丁，不是理论内的正面构件。

**用户命题「缠论本身就可以不用设止损」——原文支持，但带一个前提**：它不是「不管风险」，而是「风控由买卖点体系自身承担」（17课:60「安全性由走势的不患而保证」）。原文取消的是**价位止损**，保留的是**结构退出**。

### 3.4 π 级联止损的教义名分建议

分三层评：

1. **止损价的取法（`structural_stop`）合原文。** 1/2 类买用 pivot low、3 类买用 ZG，正是「该级别买点所依赖的结构一旦破坏就不再能搞」的价格投影，对应 13课:18 的「从能搞变成不能搞」。这不是「按亏损多少止蚀」那一类。**名分：结构失效退出，可归 13课:18 意义下的止蚀。**

2. **级联规则（父关 ⟹ 子树连坐）合原文。** 走势的递归包含关系决定了父级结构失效时子级仓位失去依托，`step.rs` 的子树清仓是这条的实现。**名分：级别包含关系的必然推论，非额外风控层。**

3. **当前实现（`exit_side` 取 `leg.dir`）不合原文，且不合它自己的判据。** 89.2% 方向错配把结构止损降格成「开仓即触发」——这既不是缠论的结构退出，也不是常规价位止损，**它什么都不是**。而 86课:32 恰好描述了这类东西的下场：「就是要触及不同的突破、止蚀位置，让止蚀的刚卖出的又回头」——wf8 的严口径白割 47%、笔数五五开，正是「随机位置被随机触及」的读数。

**结论性建议**：π 级联止损作为**结构层构件**有原文名分（1+2），可以留；**当前的方向取值是实现缺陷**，与教义之争无关，应单独当 bug 处理。在它修好之前，wf8 的 execR −312,337 与 bug 态 +4,626,831 **都不能用来论证「该不该有止损」**——前者测的是方向错配，后者测的是错配缺席。
