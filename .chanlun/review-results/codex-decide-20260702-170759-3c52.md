## 背景定义

- **Layer1**（603号确立）：递归数据类型构造子穷尽——每个move都被assign到某个inductive datatype的constructor，无遗漏（语法完全覆盖）。
- **Layer2**（缠论式6部分动态双射）：更强标准，额外要求 invariant / **complete**（I(x)=I(y)⟹x∼y，商集单射）/ realized / Eval(D_n h)=h健全 / δ无前视 / ∼ₙ截面唯一 / Ext分支集 / π全应对。
- 615候选主张：Layer1 ⊊ Layer2（Layer1是必要非充分条件——满足语法穷尽不自动给出上述语义性质）。

## 本次补全条件1：Layer1可被Layer2完全表达

Layer1与Layer2共享**同一底层载体**——都建立在同一个inductive datatype（`BSPLabelSet`，由 `⟨level:Nat, type:BSPType, side:Side⟩` 三元组构成）之上。Layer2不引入新语法，只对该载体施加额外的语义公理（invariant/complete/realized等六项）。故任何满足Layer1（语法穷尽）的分类天然可表达在Layer2的语法框架内（同一datatype），差异只在**是否满足**Layer2额外要求的语义性质。这满足codex要求的第一个条件。

## 本次补全条件2：至少一个Layer2可分Layer1不可分的具体反例

### 反例：`BSPLabels.twoB_threeB_can_coincide`（`formal/Formal/BSPLabels.lean:105`）

```lean
def vReversalEndpoint : BSPLabelSet where
  labels := [⟨1, type2, Side.buy⟩, ⟨1, type3, Side.buy⟩]

theorem twoB_threeB_can_coincide :
    vReversalEndpoint.has 1 type2 Side.buy = true
    ∧ vReversalEndpoint.has 1 type3 Side.buy = true := by
  constructor <;> simp [BSPLabelSet.has, vReversalEndpoint]
```

这证明：真实市场对象 `vReversalEndpoint`（对应maimai.md:170所述V型反转端点，真实缠论现象，非人造病理case）**同时**满足 `2B` 标签和 `3B` 标签——它不是"要么2B要么3B"（互斥sum type的假设），而是一个对象同时携带两个不同的构造子标签。

### 该反例如何满足"Layer2可分Layer1不可分"

若把Layer1朴素理解为"BSP标签是互斥sum type"（一个move classify成2B**或**3B**或**...，取其一，穷尽即完备）——这是603号"构造子穷尽"的直觉理解方式——则该模型**无法表达**"同时是2B又是3B"这个真实语义状态：sum type强制二选一，会人为丢失"两者共存"这一信息，把v型反转端点错误地压缩成"仅2B"或"仅3B"的单一状态，产生语义失真。

Layer2（真实所需模型）把BSP标签集建模为**非互斥的subset/bit-vector**（`formal/Strict/LevelState.lean:14`："E：信号 买卖点 | bit-vector BSPVector={0,1}⁶ | 否（2/3类可共存）| 非互斥subset"）——这个模型能精确表达`{2B,3B}`同时成立的联合状态，是一个**Layer1的naive sum-type穷尽无法区分/无法表达**、但Layer2的bit-vector模型**可以精确区分**的语义状态。

具体而言：
- Layer1（sum-type穷尽）视角下，"2B∧3B同时成立"这一状态**不存在于其值域**——它只能表示"2B"或"3B"其中之一，两者是同一底层对象在Layer1视角下被人为拆分成的两个不相交case，无法表示其联合。
- Layer2（bit-vector/subset）视角下，`{2B,3B}`是一个良定义的值（bit-vector中两位同时置1），与`{2B}`单独、`{3B}`单独是**三个可区分的不同值**。

这正是codex要求的反例形式：Layer2区分出了一个Layer1（naive穷尽/互斥理解下）无法表达/无法区分的语义状态。

### 该反例同时坐实"complete"性质的缺口（Layer2六项要求之一）

codex#1（`/tmp/codex_classification_answer.md`，615原文已引用）指出Layer2最危险的缺口是"complete"（I(x)=I(y)⟹x∼y，商集单射）。若classifyMove的实现假设"每个move恰好映到一个标签"（互斥sum type，Layer1朴素形式），则该实现在遇到vReversalEndpoint这类真实case时要么被迫丢弃信息（只保留2B或3B之一），要么实现本身出错（尝试单值返回时矛盾）——这正是"Layer1语法穷尽不自动保证Layer2语义完备"的活体例证。

## Response

**决策**：采用不可变 `BSPVector` / `BSPLabelSet` 的非互斥标签集模型；拒绝 `Move -> BSPType` 这种互斥 sum-type 单标签模型。

但对命题本身要收紧：`twoB_threeB_can_coincide` 是合格的代码层反例，用来否定“Layer1 = 互斥 sum-type 穷尽”这个实现选择；它还不足以单独证明原始 603 版“构造子穷尽 Layer1”与 Layer2 的严格真子集关系。

**推理链**：

`twoB_threeB_can_coincide` 证明的是：

```lean
has 2B = true ∧ has 3B = true
```

这足以说明真实对象可能同时携带 `2B` 和 `3B`。因此，若分类器类型是：

```lean
Move -> BSPType
```

或等价的互斥 enum/sum type，那么它必然丢失 `{2B, 3B}` 联合状态，只能投影成 `{2B}` 或 `{3B}`。所以在代码层，`BSPVector` / subset 是正确选择。

但如果 603 号 Layer1 的正式定义只是“所有 move 都落入某个构造子，无遗漏”，并且你又声明 Layer1 与 Layer2 共享同一个 `BSPLabelSet` 载体，那么 Layer1 本身并不必然排斥 `{2B,3B}`。此时该定理不能证明“Layer1不可表达”，只能证明“互斥单标签 Layer1 不可表达”。

更准确的形式应是：

- `ExclusiveSumLayer1 ⊊ BSPVectorLayer2`：成立，`twoB_threeB_can_coincide` 是有效 witness。
- 原始 `ConstructorExhaustiveLayer1` vs Layer2：该 theorem 只证明 Layer2 需要非互斥表示；严格性还需要展示一个满足 Layer1 构造子穷尽但违反 Layer2 `complete / realized / Eval / δ` 等语义条件的分类器。

另外，若按“满足标准的实现集合”来写，方向应是：

```text
Layer2 ⊊ Layer1
```

因为 Layer2 更强，满足 Layer2 必然满足 Layer1，但满足 Layer1 不必然满足 Layer2。

**替代方案**：

拒绝互斥 `sum type` / `enum`：

```lean
inductive BSPType
| type1 | type2 | type3 | ...
```

作为单一返回值。理由是它把共现状态编码成不可能事件，和 `twoB_threeB_can_coincide` 冲突。

拒绝“只靠 constructor exhaustive 证明 complete”。语法覆盖不能推出商集单射、无前视、截面唯一或 `Eval(D_n h)=h`。

**边界条件**：

应推翻本裁决的条件是：后续形式化证明 `2B` 与 `3B` 在真实语义上必须互斥，当前 `vReversalEndpoint` 只是建模错误；或者 Layer1 被重新正式定义为“非互斥标签集构造子穷尽”，那它就不再是 sum-type 目标，`twoB_threeB_can_coincide` 不再能区分 Layer1/Layer2 表达力。

**风险**：

最大风险是概念名混淆。若继续把“Layer1”同时指代“构造子穷尽”和“互斥 sum-type”，严格真子集断言会不稳。建议把反例命题改名为：

```text
Exclusive-singleton BSP classifier is strictly too weak.
```

然后另立一个 theorem 展示：存在满足 Layer1 穷尽但违反 Layer2 `complete` 的投影分类器。这样 615 的严格性证明才闭合。
