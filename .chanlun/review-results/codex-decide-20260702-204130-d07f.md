## Response

**决策**：选 **A：新增 `BspCandType::StructBreak`**。

但只拆 τ 分类，不新增 `GateCertificate` 通道：`StructBreak` 在门控层应为“无 BSP 证书 / gate reject”，仍保留在样本层与 `MuClass.bsp_class()==0` 统计中。

**推理链**：

`Type3` 的领域概念是“三类买卖点”：离开中枢后回抽/回试不重新进入核心区间。P2-R2 零 bit 候选的概念是“已破最后中枢但未背驰确认的结构候选”。这两个几何前提互斥，不能靠 `else => Type3` 合并。

所以最小正确改法是让数据结构表达概念：

```rust
enum BspCandType {
    Type1,
    Type2,
    Type3,
    StructBreak,
}
```

`bsp_cand_type` 精确判别：

```rust
if bits.class_index() == 0 {
    return BspCandType::StructBreak;
}
```

然后再按 `buy1/buy2/buy3` 或 `sell1/sell2/sell3` 分 `Type1/2/3`。这里用 `class_index()==0`，因为 `struct_break_dir` 已被设计为方向 sidecar，不进入桶键；六 bit 全零就是这个分流边界。

三处施工规格：

- `cand_delta`：`StructBreak => false`
- `cand_delta_base_gate`：`StructBreak => false`
- `build_gate_certificate`：`StructBreak => None`

不要复用 `Type3` 的 `descend_type1_anchor_depth`，也不要走 `Nest` 或 `Xzd`。`Nest/Xzd` 是确认类 BSP 证书通道；零 bit 破中枢未背驰候选没有对应的确认语义。现在新增第三个证书通道是过度设计，等有形式化定义再加。

**替代方案**：

B 轻量过滤：拒绝。它能止血，但概念仍然隐形，后续调用者看不到“这是结构破坏候选，不是三类”。这和 673 号先例的处理原则不一致：互斥语义混入同一分支时，应拆分谓词/分支，而不是在下游打补丁。

C 维持现状：拒绝。除非 `docs/chanlun/` 明确把 T3 定义成“非 Type1/2 的候选池残差”，否则把“未破中枢回试”和“已破中枢未背驰”合称 T3，就是文档掩盖代码语义错误。按当前证据，它与 673 的 settled 原则冲突。

**边界条件**：

此裁决应翻转的情况只有三类：

- 文档原文明确规定 T3 是残差候选池，而不是三类买卖点。
- 形式化 specs 给出 `StructBreak` 的独立通过证书，此时再新增 `GateCertificate::StructBreak` 或等价通道。
- 发现六 bit 全零不只来自 P2-R2 `struct_break_dir`，还包括其他无方向噪声；那就不要只用 `class_index()==0`，应把 `struct_break_dir` 或完整 `BspPoint` 传入分类函数。

**风险**：

- gate pass 历史计数会变：以前被误送进 Type3 的零 bit 候选会变成无证书。
- 如果已有报告把这批误分类当成 Type3 证据，需要重标。
- `StructBreak` 名字可能被误解为“可交易结构突破”；建议注释写清：零 bit、破中枢、未背驰确认、样本保留但 τ gate 拒绝。
