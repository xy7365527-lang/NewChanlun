## 矛盾-A：StructBreak(I_γ=∅) 的交易语义边界

### 原文（两份权威全本逐字，`.chanlun/review-results/dlpdf-a-mutex-classification-20260702.md` §2.1/§5 摘录）

状态元组 `z = (ℓ, δ, I_γ, r, σ_p, ω, β, κ, d, c, m)`，其中：

> **I_γ ⊆ {1,2,3}**：一二三类买卖点集合（子集，非坍缩）；δ=+1 时 I_γ={i:B_{i,ℓ}=1}，δ=-1 时 ={i:S_{i,ℓ}=1}；**证书成立当且仅当 I_γ≠∅**。

> 全互斥解释器 C_j=P_j∧⋀¬P_k **+ C_0 兜底**（C_0=⋀¬P_j=保持，即所有类判据都不成立时的默认动作=不交易）。

> L_t = 记录但不交易的证书（原文对"零 bit 无买卖点位"情形的显式记录侧，与"完全静默不留痕迹"区分）。

**原文结论**：零 bit（I_γ=∅，无任何一二三类买卖点位）**不构成买卖点证书**，落 C_0=保持（不交易）或 L_t=记录（不交易但留痕）。二者共同点：**都不产生交易动作**。

## 矛盾-B：level0 免门 vs 原文去根化级别平移自相似公理

### 原文（`递归完全分类买卖点.pdf` §1/§4/§18，逐字摘录）

> 去根化：没有特殊根级别，只有前沿 ℓ_max(t)；根=父级尚为胚元 ∂_{ℓ+1} 的普通子级别；更高级别涌现=同一提升算子 Prom 在前沿再作用。

> 全分类函数 𝒞_Θ(x)=(D_t,(b_ℓ)_ℓ,(χ⁺,χ⁻)_ℓ,Γ,(R(g))_g,𝓡_Θ(Γ),A_{t+1},p̃_{t+1})；**级别平移自相似 𝒞_Θ(S_k x)=S_k𝒞_Θ(x)**（硬公理：整个分类函数在级别平移下等变，任何级别不应有特殊规则）。

### 待裁问题

已知（A 组已判定）：

2. 如果判定违反：是否需要修复（去根化重构：让 `lvl==0` 也统一走"次级别 Type1 下沉"判据，代价=`lvl==0` 无次级别时 `descend_type1_anchor_depth` 恒 `None`，会导致 level0 的 Type2/Type3 全部门拒，这是否是可接受的行为变化）？还是维持现状但需要在文档层显式标注"level0 免门是有效域边界（截断声明），不是平移自相似的实装"？
3. 明确边界条件：什么情况下你的裁决会翻转。

## Response

**矛盾-A**

**决策**：保持现状。`StructBreak(I_gamma=empty)` 在 `build_gate_certificate` 返回 `None`，不新增 `GateCertificate::Rejected`。

**推理链**：`GateCertificate` 当前接口只表示“可被门控消费的交易确认凭据”：`Nest` 走 `n_delta()`，`Xzd` 走 `gate_pass()`，主路径把 `None` 当拒绝/不下单处理，见 [econ_positive.rs](/Users/silencehan/Projects/NewChanlun/rust/src/theta_v0/backtest/econ_positive.rs:314) 和 [GateCertificate](/Users/silencehan/Projects/NewChanlun/rust/src/theta_v0/backtest/econ_positive.rs:889)。原文 `I_gamma=empty` 的核心交易语义是“不构成买卖点证书，不交易”。这一点 `None` 精确满足。`L_t` 的“记录”不要塞进交易证书类型；当前应由样本层 `bsp_class()==0` / `class_index()==0` 和本地 `BspCandType::StructBreak` 满足，门控层不承担审计账本职责。

**施工级规格**：无需代码改动。保留 `BspCandType::StructBreak => None`，保留现有测试 `build_gate_certificate_structbreak_zero_bits_always_none`。若以后需要门控拒绝审计，新增旁路 `GateRejectReason::StructBreak` 或 `GateDecision { pass_cert, reject_reason }`，不要把 `Rejected` 放进 `GateCertificate`。

**替代方案**：拒绝 `GateCertificate::Rejected(StructBreakEvidence)`。它会把“非证书记录”混入“交易证书”接口，扩大所有 match 消费面，并制造误用风险。也拒绝把 zero-bit 继续落到 Type3，那会把“无买卖点位”伪装成三类点。

**边界条件**：若 formal 层把 `L_t` 定为 `C_Theta` 的强制输出对象，且下游验收要求在门控产物层区分“无执行段 / Type1 失败 / StructBreak 拒绝”，此裁决翻转，改为引入独立 `GateDecision`。

**风险**：门控层日志不可区分 `None` 的拒绝原因；如果后续统计只读 gate output，不读样本层，会丢 StructBreak 留痕。

**矛盾-B**

**决策**：维持 `lvl==0` 免门；把它定性为有限塔实现的有效域边界，不声称 `theta_v0` 已全域实现原文去根化平移自相似。

**推理链**：严格说，如果把当前 Rust 直接等同原文全域 `C_Theta`，`lvl==0 || descend_type1_anchor_depth(...)` 确实不是级别平移等变规则。但代码里的 `lvl==0` 是最低可用塔层，没有 `lvl-1` 载体；强行去掉免门会让 L0 Type2/Type3 因无次级别锚全部门拒，直接改变当前回测语义和既有测试，见 [cand_delta_type23_base_gate_level0_and_small_to_big](/Users/silencehan/Projects/NewChanlun/rust/src/theta_v0/backtest/econ_positive.rs:1612)。这是有限实现的截断边界，不是一个值得现在重构的算法 bug。

**施工级规格**：不改 Rust 行为。文档/裁定口径必须写清楚：平移自相似只可声明在内部域 `lvl >= 1 && tower[lvl-1] exists`；`lvl==0` 是 finite-tower boundary adapter。禁止把当前 `theta_v0` 宣称为原文全域去根化 `C_Theta` 的完全实现。

**替代方案**：拒绝立刻去根化重构。没有 sub-L0 / endpoint-complete carrier 前，统一调用 `descend_type1_anchor_depth` 只是把边界缺失伪装成严格性，代价是 L0 Type2/3 全灭。也拒绝造虚拟 sub-L0；那是新模型，不是小修。

**边界条件**：若塔结构能表达真实低一级载体，或验收目标变成“证明 Rust 与原文全域 `C_Theta` 等价”，此裁决翻转：删除 `lvl==0` 特判，所有级别统一走下沉锚判据。若 W-VERIFY 证明 L0 免门贡献了不可接受的假阳性，也翻转为收紧 L0。

**风险**：L0 与内部级别不可完全同质比较；alpha 统计可能被 L0 base-case 主导。最大的风险是文档过度声称“已实现去根化自相似”。

**统一口径**：两条矛盾都不要扩大交易证书接口来承载非交易语义。当前最小正确模型是：`GateCertificate` 只表示可交易确认；`None` 表示 C0/门拒；记录语义留在样本/诊断层；`lvl==0` 是有限塔边界，不是原文全域公理的实现。代码图 MCP 在本环境两次被取消，我用只读文件和现有测试位置核对了上述接口面。
