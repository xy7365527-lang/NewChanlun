## 关键代码：第二类递归组装层（已接入，`mod.rs:1383-1436`）

```rust
fn extract_second_for_level(upper_moves: &[LeveledMove], hist: &[f64], close_src: &[usize]) -> Vec<BspPoint> {
    let mut points = Vec::new();
    let area_cache = RefCell::new(AreaCache::new());
    let stable_len = hist.len();
    for parent in upper_moves {
        second_for_parent(parent, hist, close_src, &area_cache, stable_len, &mut points);
    }
    points
}

fn second_for_parent(parent: &LeveledMove, hist: &[f64], close_src: &[usize], ...) {
    // 次级别中枢：RMove::Compose { centers, .. } 首个（窗口真派生 B 口径核心区间）
    let c1 = match &parent.rmove {
        descend::RMove::Compose { centers, .. } => centers.first()...,
        descend::RMove::Segment { .. } => return, // L0 线段不会出现在 upper_moves
    };
    let subs = descend_leveled(parent); // 坐标侧车：构成 parent 的次级别 LeveledMove 序列
    for side in [Side::Long, Side::Short] {
        let pts = signal::extract_second_signals(
            &parent.rmove, side, &c1,
            |m| sublevel_diverges(m, &subs[..], hist, close_src, area_cache, stable_len), // MACD 面积背驰
            |m| index_of_in(&subs[..], m), // 坐标：侧车按结构身份查回次级别走势的原始 K 序
        );
        out.extend(pts);
    }
}
```

**关键点**：`sublevel_diverges` 已经是「在任意级别的 upper_moves 结构上算 MACD 面积背驰」的通用实现
（次级别走势 source_index 区间 → hist 面积，相对最近同向前驱严格变小）——这是第二类复用的背驰引擎，
**同样的面积计算原语可复用给级别-N 一类**（A/C 段面积比较）。

## 裁定问题（请给出明确单选 A/B/C + 完整推理）

高级别（level≥1）一/三类买卖点候选如何生成：

**(A) 级别-N 直接判定**：在级别-N 的 units（`project_to_units` 产出，携 `fold_direction`）+ 级别-N
centers（`detect_centers_geometric`）+ 级别-N 趋势裁决（`classify_move` 的 `Trend(dir)`）上，跑一套
类比 `judge_first_cached` 的判据——级别-N "线段"角色由 `UnitRange`/`LeveledMove` 承担，A/C 段面积比较
复用 `sublevel_diverges` 同族的面积原语（该原语已在 `second_for_parent` 证明可在任意级别工作）。

- 优点：与原文「每级别全三类」同构，架构对称（is_l0 分支消失，所有级别走同一套逻辑，只是输入换算子）。
- 代价：需要 (i) `UnitRange`/`LeveledMove` → judge_first 判据的适配层（`seg_end` 依赖 `Segment.start_price/
  end_price`，`UnitRange` 只有 `lo/hi`+`direction`，需要从 direction 推断 endpoint 用 hi 还是 lo）；
  (ii) 级别-N 的 A 段定位（`locate_trend_seg_a` 等价物——前一同向中枢离开段，在 `upper_moves`/`subs` 结构
  上找，可能复用 `second_for_parent` 里"序列序最近同向前驱"的模式）；(iii) 级别-N 走势方向 `trend_dir`
  从该级 `classify_move` 输出的 `Trend(dir)` 取（`HigherCenterCandidate`/`Consolidation` 下无 trend_dir，
  该级本轮无一类候选，比照 L0 若无趋势也无一类的语义）；(iv) 信号集会新增，下游（三类完整实装、
  `assemble_gamma`/`extract_signals_force` 等消费者）需重跑验证 GOLDEN/bit-exact。

**(B) 递归 relabel**：不新增级别-N 判定，而是让 L0 一类在高级别语境里"升格"标注（区间套：级别-N 一类的

- **致命疑点（请正面核）**：审计 #119 坐实 **L0 一类在 BTC 300K 恒为 0**（市场事实，机制齐备但 0 触达）。

## Response

**决策**：选 **A：级别-N 直接判定**。

实现上不要做大重构：先把 `else { Vec::new() }` 替换为 `extract_first_third_for_level(...)` 这种 level-native 适配层。L0 旧路径先不动；等 golden 接受新增信号后，再考虑统一成同一个多级 evaluator。

**推理链**：

1. 领域概念上，每个级别都有独立的一/二/三类买卖点。高级别一/三类应由高级别 `units + centers + trend` 判定，不应从 L0 标签继承。
2. `UnitRange.direction = fold_direction(prev)` 已存在，`units 无方向` 这个阻塞理由已经过期。缺的是判定适配层，不是领域信息。
3. (B) 把“区间套精确定位”误读成“低级别标签升格”。区间套可以用低级别走势细化入场位置，但不能要求高级别一类必须先是 L0 一类标签。
4. 当前 L0 一类恒为 0 时，若 (B) 的母集合是 L0 一类，则高级别一类必然恒空。这个疑点成立。
5. 性能上 A 不需要新算法：复用现有 MACD 面积原语和 `AreaCache`，线性扫高级别 `LeveledMove` 即可。不要引入新缓存体系，除非验证显示 O(n²) 回来了。

**实装约束**：

- 起跑级别：所有已构造出的 `level >= 1`，受当前 `l_max`/递归塔输出限制；不要只做 level 1。
- 判定输入：用不可变 view 适配 `UnitRange`/`LeveledMove`，提供 `start_index/end_index/direction/end_price`。`end_price` 暂按方向取 `hi/lo`，但必须测。
- 趋势门槛：一类只在该级 `classify_move == Trend(dir)` 时生成；无趋势就不生成一类。
- A/C 段：按高级别序列找“前中枢同向离开段”和当前破中枢段，面积比较复用 `sublevel_diverges` 同族原语。
- 三类：同样用该级 `units + centers` 的离开/回试关系生成，不从 L0 三类 relabel。
- 二类：保持 `extract_second_for_level` 的递归语义；只共享面积计算/`AreaCache`，不要把二类改成依赖新 emitted 一类标签。
- 性能红线：总复杂度应是 `O(sum(level_moves))`；A 段定位不能每个点回扫全历史。新增检查至少覆盖 `bit_exact_synthetic`、`project_to_units_resume_matches_full`、`cargo test --lib`，再重跑 BSP/GOLDEN、`extract_signals_force`、`assemble_gamma` 及相关 backtest digest。

**替代方案**：

- 拒绝 B：在当前定义下，高级别候选集合是 L0 一类的子集；L0 一类为 0，则 B 恒空。若改成“高级别条件成立后，在低级别内部找定位点”，那已经不是 B，而是 A 加区间套定位。
- 不选 C：没有必要另起架构。所谓更优方案最多是 A 的实现细化：抽一个最小 `LevelUnitView`，复用现有面积引擎。新抽象/新递归标签系统都是多余的。

**边界条件**：

- 如果后续形式化规格明确规定“高级别一类必须由低级别已确认一类标签继承”，则推翻 A。
- 如果 `UnitRange` 的 `hi/lo + direction` 不能忠实表示高级别终点价，A 仍保留，但必须升级输入结构，记录真实 folded endpoint。
- 如果直接判定引入未完成中枢/未来函数，必须改为只用 completed/stable window。
- 如果性能回到 O(n²)，先修 A 段定位和面积缓存，不推翻 level-native 建模。

**风险**：

- 高级别新增信号会改变 GOLDEN，这是预期变化，但容易掩盖假阳性。
- `fold_direction` 是折叠方向，不等同于原生 L0 线段方向；端点价格适配是最大实现风险。
- 三类若照搬 L0 逻辑，可能在高级别“中枢外缘区间”上出现边界语义偏差，需单独 snapshot。
- `mod.rs:256 else { Vec::new() }` 应定性为 **spec-execution-gap 候选：是**。它不是静默简化，commit 里有文档化理由；但该理由的前提已经在同一提交内被 `UnitRange.direction` 满足，之后未复核。应走谱系补记，标成“过期未复核的文档化简化”。
