# 裁定3（G7）：K_Θ 是否缺毛头寸（gross exposure）约束

## PDF 权威（docs/formal-chain/完整的策略.pdf §11 仓位与风险投影）

> 风险可行集 K_Θ(x_t) 必须包含：保证金；强平；最大净头寸；**最大毛头寸**；多空双开；OQ-9；TW三阶段合法性；成本和滑点约束。
>
> 最终策略：π_Θ(x_t) = Schedule_Θ[ LexArgmin_{p∈K_Θ(x_t)} J_Θ(p, p̃_{t+1}) − p_t ]

§15 checklist 未把毛头寸单列为独立 P 项（不在 P1-P10 明文清单里），但 §11 正文明确列出"最大毛头寸"为 K_Θ 必须包含的 8 项约束之一。

## 现状代码

### 1. `KThetaRiskGate`（`rust/src/theta_v0/strategy/coverage.rs:1924-1956`）——实际生效的风控约束门

```rust
pub struct KThetaRiskGate {
    pub force_flat: bool,           // GlobalRiskClose ⟹ K_Θ={0}
    pub stop_long: bool,            // 禁净多仓（hi_cap=0）
    pub stop_short: bool,           // 禁净空仓（lo_cap=0）
    pub no_increase_cap: Option<f64>, // M2/M3 净幅上限=当前|net|
}
fn caps(&self, cap: f64) -> (f64, f64) {
    if self.force_flat { return (0.0, 0.0); }
    let cap = match self.no_increase_cap { Some(c) => cap.min(c.max(0.0)), None => cap };
    let hi = if self.stop_long { 0.0 } else { cap };
    let lo = if self.stop_short { 0.0 } else { cap };
    (lo, hi)
}
```

`caps()` 的入参 `cap = feasible_net_cap(risk) * base_units.abs()`（`pi_theta_position`，coverage.rs:2024-2044）——单一净持仓幅度上限。`feasible_candidates`（coverage.rs:1974-1991）在 `[lo_cap, hi_cap]` 区间内搜索**唯一净持仓标量** `p`（`LexArgmin`）。**架构事实**：v0 执行层是 Nautilus **净额账户**（`net_target_units`，coverage.rs:1272-1280 注释明言："Nautilus 净额账户只持单一净持仓——本函数把毛腿净额化。净额化丢失双开的毛敞口信息...这是 Nautilus 净额兼容的必然降维，非 bug。完整毛分账本执行须 hedging 账户（v0 净额）"）。整个 `π_Θ` 优化变量 `p` 本身就是净持仓标量，**不存在毛头寸作为独立可约束坐标**。

### 2. 毛头寸计算机制已存在，但未接入风控门

## Response

**决策**：构成实装缺口。`leverage_ok` 零生产调用不等于已实装；当前 v0 只能声明“净额执行域内有净头寸约束”，不能声明 PDF §11 的独立最大毛头寸约束已进入 `K_Θ`。

技术选择：短期接入弱形式作为 v0 防线，但合规裁定按强形式处理。

**推理链**：
`K_Θ` 的约束必须作用在实际可行集枚举/裁剪路径上。现在 `feasible_candidates` 只枚举单一净持仓标量 `p`，`KThetaRiskGate::caps()` 只收紧 `|net|`，所以 `gross_notional` / `leverage_metrics` / `leverage_ok` 即使存在，也只是孤立工具函数和单测，不是生产约束。

v0 净额账户里，真实执行坐标只有 `net_target_units`。毛头寸 `Σ|leg_v|` 是多腿/多声部分账本概念，不是这个标量空间里的独立自由度。因此把 `gross_cap` 塞进 `caps()` 最多得到：

`|net_target| <= min(net_cap, gross_cap)`

这能防止净目标过大，但不能表达“多空双开导致净小但毛大”的 PDF 语义。真正的 §11 约束需要决策变量是分账本向量：

`q = [voice_1, voice_2, ...]`

然后在 `LexArgmin` 前约束：

`abs(sum(q)) <= max_net`
`sum(abs(q_i)) <= max_gross`

最后再投影到 Nautilus net account，或升级 hedging account 真实执行多腿。

所以结论是：v0 下 G7 对完整 PDF 定义域结构性不可完全满足；只能做 v0 projection-domain guard。完整满足必须改为 hedging / separated-ledger 决策域。

**替代方案**：
拒绝“函数存在即合规”：零生产调用就是未实装。

拒绝“只在 `KThetaRiskGate::caps()` 加 `gross_cap` 就宣称修复”：这只是净标量上限，不是独立毛敞口约束。

接受最小修复：把 `leverage_ok` 接入 `risk_mode` / `KThetaRiskGate` 判定链，新增 gross binding 诊断；在 v0 中若毛杠杆超限，至少 fail closed：禁止增加或直接 force-flat，具体取决于现有 risk-close 语义。文件范围应是 `rust/src/theta_v0/risk.rs`、`rust/src/theta_v0/strategy/coverage.rs`，必要时 `runner.rs` 只负责传 caps/equity/voices。

**边界条件**：
若后续证明 v0 的 `VoiceNotional` 只是诊断、不会参与任何可交易/可归因分账本，则毛头寸约束在 v0 应退化为 `gross == abs(net)`，不再声称覆盖 PDF 的双开语义。

若引入 hedging account 或内部 separated-ledger optimizer，则应推翻弱形式，直接在向量候选集上约束 `Σ|q_i|`。

若历史 replay 显示 gross gate 从未 binding，历史 alpha 数字可保持；否则所有受影响回测结论必须重跑。

**风险**：
弱修复可能过度保守，尤其当前毛超限但净额账户实际风险不高时会 force-flat。

如果只做诊断不参与候选裁剪，会继续违反 §11。

如果把 v0 弱形式写成“严格满足 K_Θ”，会再次触发 no-claim-inflation 问题。正确表述是：v0 已接入 gross guard，但完整毛头寸 K_Θ 等待分账本/hedging 决策域。
