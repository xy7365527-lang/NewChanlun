```
P1 = 强平/保证金风险,
```

互斥化：`C_1=P_1`，`C_j=P_j∧⋀_{k<j}¬P_k`（j=2..10），`C_0=⋀¬P_j`（兜底），`Σ1[C_j]=1`。

§16 最终形态明确要求单一解释器：`(D_t,O_t,L_t,TWEvent_t) = I_Θ(A_t, {γ:N^δ_{ℓ↓e}(γ)=1}, TW_t, Risk_t)`
——**解释器的输出元组新增了 TWEvent_t**，输入显式包含 `TW_t`（三阶段资金状态）和 `Risk_t`（风险状态），
即 PDF 把强平（P1）和 TW 三阶段事件（P2/P3/P4）都设计成**解释器 fold 本身要处理的谓词**，不是
解释器之外的独立机制。

## Response

**决策**：选 **(ii) 真统一**。但不是把 P1/P3/P4 伪造成 `Candidate` 塞进现有 fold；应升级解释器接口为：

`IΘ(ctx: RiskState + TwState + Active/LegBook, gamma) -> { buckets, order_effect, tw_event, exit_kind }`

`interp::interpret` 当前只吃 `gamma, active`，只产三桶；生产 `pi_theta_step_prebuilt` 再把 `KThetaRiskGate` 交给 `pi_theta_position`；TW 的 `run_closed_loop` 只是并行终态证据，不被真实 π fill loop 消费。也就是现在确实是三套系统，不是统一解释器。

**推理链**：
1. P1 不能实现成“所有候选归 close 桶”。强平必须在 `gamma` 为空时也能平掉真实净仓；候选桶语义不够。P1 应是解释器最高优先级全局分支：清空 active legs、输出 `ForceFlat/RiskLiquidation`、目标仓位为 0，并屏蔽 P2-P10。
2. `KThetaRiskGate.force_flat` 不应继续当第二个语义权威。保留它可以，但只能降级为同一 `RiskState` 派生出的执行安全网/可行集约束。若它能独立触发而解释器 P1 未触发，就是 bug。
3. P3/P4 是账本状态迁移，应作为 `TWEvent_t` 输出分量；不产生仓位订单，也不伪造成候选。但因 PDF 互斥优先级在 P5-P10 前，P3/P4 成立时应消耗本步解释器裁决，普通候选订单被屏蔽或记录。
4. P2 是订单型 TW 谓词，应输出 `CloseOverlay`/typed close effect，进入同一个 schedule/fill/typed ledger，不走 `closed_loop` 玩具动作集。
5. G4/G7/P1-TW 指向同一个接口重构：解释器输出必须带 typed exit reason，且目标应准备迁移到 leg-level。可以分阶段落地，但不能各自做成独立权威岛。

**替代方案**：
- 拒绝 **分层 output-等价**：只扩 `mutex.rs` oracle 不改变真实订单流，P2/P3/P4 仍未进生产解释器，构成“留简化/占位”。
- 拒绝“全塞进 Candidate fold”：破坏 `Candidate = 缠论候选` 概念，且 P1 在无候选时失效。
- 拒绝复用 `closed_loop::hybrid_step` 当生产 TW 决策源：它的输入不是真实 `Candidate/BspBits/Classification`，且没有 `CloseOverlay` 动作。

**边界条件**：
如果 PDF/Lead 明确把 §16 降格为 oracle-only，而非生产验收，裁定可翻转为分层测试。  
如果 P2 被重新定义为纯账本事件、不产生订单，P2 可改为 `TWEvent_t`。  
如果 G7 明确放弃声部级 gross，只保留净额账户，P1 可较长期留在 KΘ scalar guard，但仍不能称为完整 §16 统一解释器。

**风险**：
最大风险是状态双写：TW 在 closed_loop 和 π fill loop 各走一套。必须只保留一个生产 TW 状态源。  
第二风险是未先接 typed exit，导致 RiskLiquidation/CloseOverlay/CloseRoot 统计混淆。  
第三风险是 G7 未落地前，净额 schedule 会误表达毛头寸/对冲腿语义；需用显式 lossy adapter 过渡并重算 golden baseline。
