## 现状代码（我核验到的具体机制，比 mapping 文档更细）

### 1. `interp::interpret(gamma, active) -> Buckets`（`interp.rs:940-999`）

纯函数，签名只有 `(候选集, 活动集)` 两个参数，**不接收 risk gate 或 TW 状态**。fold 规则1-4（Flat候选→record / 反向关闭→close / 无冲突→open / 冲突→record）完全不知道 force_flat 或 TW 阶段的存在。

### 2. `pi_theta_step`（`coverage.rs:2146-2167`）——两阶段串联，gate 只作用于第二阶段

```rust
pub fn pi_theta_step(..., gate: KThetaRiskGate, ...) -> (Vec<ActiveLeg>, f64, Order) {
    let (next_active, p_tilde) =
        coverage_step_classification(classification, tower, prev_active, base_units, voice, registry);
    // ↑ 完全不传 gate；interpret() 内部三桶 + coverage_step_from_buckets 的 A_{t+1}=AncOK[...] 全部与 gate 无关
    let p_star = pi_theta_position(p_tilde, p_t, base_units, risk, weights, gate);
    // ↑ gate 只在这一步把 p_tilde clamp 成 p_star（净持仓标量层面的收窄）
    let order = schedule_order(p_star, p_t, exec_index);
    (next_active, p_star, order)
}
```

### 3. 我核验到的具体缺陷（比 mapping 文档"output-等价"描述更精确的反例）——`coverage_step_from_buckets`（`coverage.rs:1710-1739`）

```rust
for c in &buckets.open {
    let idx = candidate_start + c.gamma_index;
    if idx < work.len() && !raw.contains(&idx) {
        raw.push(idx);   // ← 无条件把 open 候选推入 raw（下一步变成 A_{t+1} 的一部分）
    }
    // ...父链恢复逻辑，同样无条件...
}
let next_idx = ancestor_close_by_id(&work, &raw); // A_{t+1}=AncOK(raw)
```

`buckets.open` 由 `interp::interpret`（不知道 gate）产生，`coverage_step_from_buckets` 把它无条件折进 `raw`→`next_idx`→`next_active`（成为下一 bar 的 `prev_active`）。**这个过程完全不检查 `KThetaRiskGate.force_flat`**。

**具体反例**：设某 bar `force_flat=true`（保证金强平触发）。若同 bar 恰好有一个新 buy1 候选命中 P8 Open Root 规则（`interp::interpret` 不知道 force_flat，正常把它放进 `buckets.open`），则：
- `next_active`（本 bar 算出、下一 bar 变成 `prev_active`）**会包含这个新开的腿**（`coverage_step_from_buckets` 无条件 push）。
- 同一 bar 的 `p_star = pi_theta_position(p_tilde, p_t, ..., gate)` 因 `force_flat` 被 clamp 为 0 → 实际下的订单是 `Close`/`Hold`，这个"新开的腿"**从未在净持仓标量层面真正建仓**。
- 下一 bar（假设 force_flat 已解除），`prev_active` 里这个"幽灵腿"继续参与：`reverse_signal` 关闭匹配、`strategy_target_legs` 深度加权仓位计算（把它当作已持有的父/子声部）、子声部的 `AncOK` 祖先闭合判定（若它是某 ShortDiff 子声部的父 carrier，子声部会因为这个"从未真实建仓"的父在场而被误判为祖先齐全，从而被错误准入）。

这不是"output-等价但表述不同"的风格问题——这是**逻辑持仓簿记（`next_active`/AncOK 状态）与实际已实现净持仓（`p_star`/`schedule_order` 产生的订单）之间的真实状态分叉**，且这个分叉会跨 bar 传播（幽灵腿持续存在于 `prev_active` 直到某个后续 bar 恰好触发对它的 close 规则）。

### 4. TW 事件（P2/P3/P4）现状——与 pi 订单流完全 disjoint

## Response

**决策**：保留当前 `interp::interpret(gamma, active) -> Buckets` 不扩签；新增/扩展外层 full interpreter seam。PDF 的 `I_Θ(A, Γ, TW, Risk)` 应对应 `coverage_step_prebuilt/pi_theta_step` 这一层的组合解释器，不是当前候选级 `ℛ_Θ(Γ,A)` 子函数。

P1 修复点必须在环5和环6之间：`coverage_step_from_buckets` 或其外层 `coverage_step_prebuilt` 接收 `KThetaRiskGate`。`force_flat=true` 时短路为：

- `next_active = []`
- `p_tilde = 0`
- 对所有 `prev_active` 产 `ExitType::RiskExit`
- 跳过全部 `buckets.open`、常规 close、AncOK、G7 gross 缩放

只“跳过 open”不够，会留下旧 active 腿，仍然是幽灵腿。当前 bug 根源在 `coverage_step_from_buckets` 无条件把 `buckets.open` 推入 `raw`：[coverage.rs:1710](/Users/silencehan/Projects/NewChanlun/rust/src/theta_v0/strategy/coverage.rs:1710)，而 gate 只在之后收窄 `p_star`：[coverage.rs:2161](/Users/silencehan/Projects/NewChanlun/rust/src/theta_v0/strategy/coverage.rs:2161)。

**推理链**：

`interpret` 现在是候选 fold 深模块：只排序 Γ、读 A、产三桶，且唯一性证明绑定 `(Γ,A)`：[interp.rs:966](/Users/silencehan/Projects/NewChanlun/rust/src/theta_v0/strategy/interp.rs:966)。P1 是全局账户风险，不是候选属性；若塞进候选循环，`gamma` 为空时无法强平，有多个候选时会重复表达同一个风险事件，还会重写现有 shadow-fold 证明对象。

正确 seam 是 full interpreter result，而不是 Candidate。建议最小数据形状：

```rust
struct FullInterpretCtx<'a> {
    risk_gate: KThetaRiskGate,
    tw: Option<TwProjection<'a>>,
}

struct FullInterpretResult {
    next_active: Vec<ActiveLeg>,
    p_tilde: f64,
    exits: Vec<TypedExit>,       // leg + ExitType / overlay action
    tw_event: Option<TwEvent>,
}
```

`ExitType` 单源已经在 `interp.rs` 落地：[interp.rs:148](/Users/silencehan/Projects/NewChanlun/rust/src/theta_v0/strategy/interp.rs:148)。P1 的 `RiskExit` 由外层 gate 直接产生，不由 `interpret()` 内部产生。

G7 顺序：`force_flat` 必须早于 G7。P1 是全平，不是 gross cap 缩放；同 bar 同时触发时 P1 胜出，G7 不运行。非 `force_flat` 时，G7 仍在 `strategy_target_legs` 后、`net_target_units` 前处理：[coverage.rs:1746](/Users/silencehan/Projects/NewChanlun/rust/src/theta_v0/strategy/coverage.rs:1746)。

TW 裁定：

- P3/P4：新增 `Option<TwEvent>` 输出通道，读取 `TwState/RiskPolicy/RiskMode`，不改 `D/O/L` 候选桶。现有 `stage_progression` 已是可复用判据：[transition.rs:278](/Users/silencehan/Projects/NewChanlun/rust/src/theta_v0/closed_loop/transition.rs:278)。
- P2 CloseOverlay：不能伪造成 `Candidate`。它没有合法 `gamma_index -> coverage element` 映射，会污染 AncOK。最小实现是外层生成“合成 close action/close intent”，优先级高于 P5 常规 close；若 P2 命中，关闭 overlay legs，并屏蔽本 bar lower order-bearing open/close。

**替代方案**：

拒绝扩 `interp::interpret(gamma, active, risk, tw)`：把全局账户/TW 状态塞进逐候选循环，概念层错位，且破坏现有 `(Γ,A)` 证明对象。

拒绝只在 `coverage_step_from_buckets` 跳过 open：只能堵新幽灵腿，不能清掉已有 active；`p_star=0` 后旧腿仍进入下一 bar。

拒绝 P2 synthetic Candidate：`Candidate` 是买卖点候选，P2 是账本/overlay close 谓词。用 synthetic action，不要伪造候选。

**边界条件**：

此裁定翻转的条件只有三个：PDF/形式化明确要求 `ℛ_Θ` 子函数本身定义域改成 `(Γ,A,Risk,TW)`；或 P3/P4 被证明必须屏蔽同 bar 候选订单；或执行层从净额 `Order` 升级到完全 leg-specific order book，P2/P1 可直接在订单账本表达而不经 `p_tilde`。

**风险**：

最大风险是当前 `Order` 偏净额，P2 CloseOverlay 是腿级 close；需要 `TypedExit/close intent` 给 G4/G5 账本消费，否则统计层仍分不清 close 来源。另一个风险是 registry 必须同步标记 `RiskExit` 关闭，否则幽灵腿会从 `PersistentRegistry` 复活。

实装范围：#133 先落 G7 gross 点，但 P1 short-circuit 要插在它之前；#134 复用 `interp::ExitType`，不要另造枚举；#124 改 `coverage_step_*`/`pi_theta_step*` 返回 full result，扩 `mutex.rs` P1..P10 测试。P1/P2/G7 都是语义变更，BTC golden 需要诚实重算；P3/P4 只加输出通道时订单 bit-exact 可保持，除非 runner 开始消费 TW 事件改变资金状态。
