3. **互斥分类 spec M18**（=完全分类 C33/C34，公式相同）：

## 工位的推导（待你裁定）

在固定活动集 + Θ 钉死的腿间比率族（同单位数/κ/depth_weights）内：
- **单根情形**：可行方向只剩整体尺度 c∈[0,1]，LexArgmin 主键 `‖p−p̃‖²_W` 在 `{c·p̃ : c·G(p̃)≤Ḡ}` 上最小 ⟹ `c* = Ḡ/G(p̃)`——**等比例缩放是 spec 可导的**。
- **多根情形**：每根子树可有独立尺度 c_r（跨根无比率约束绑定），J_t 主键最小化的 KKT 给出**非均匀** c_r（按子树范数加权的 water-filling）；「全腿同一 c」是附加选择，spec 未钉。

## 候选方案（毛约束触发 G(legs) > Ḡ 时）

- **方案A：全腿等比例缩放** `c = Ḡ/G`，所有腿 units ×= c。
  - 优点：保所有比率约束（同单位数/κ/深度权重/跨根相对结构）；确定性 O(n)；bit-exact 平凡；单根情形 = spec 严格解。
  - 缺点：多根情形非 J_t 主键严格最优（等权 w 下严格最优是逐根非均匀缩放）。
- **方案B：逐根 KKT 投影**（比率族内 per-root 尺度 c_r，min Σ_r ‖sub_r‖²(c_r−1)² s.t. Σ_r c_r·G_r ≤ Ḡ，c_r∈[0,1]，闭式 water-filling）。
  - 优点：等权 w 下 J_t 主键在比率约束族内的严格 LexArgmin。
  - 缺点：实现复杂度高（active-set 迭代裁 c_r≤1/≥0）；w_v per-voice 在 rust 不存在，"等权"本身是实装假设；数值路径长，bit-exact 审计面大。
- **方案C：优先级截断**（按深度反序整腿砍：先砍最深子声部直至 G≤Ḡ；保祖先闭合）。
  - 优点：保留根腿完整敞口；祖先闭合天然满足。
  - 缺点：spec 无此优先级序（P1..P10 是解释器域，非 K_Θ 投影域）；离散跳变（砍整腿）偏离 J_t 连续投影；同深度多腿砍谁需再造平局规则 = 新的未授权设计选择。
- **方案D：整体拒绝**（G>Ḡ ⟹ 全部腿归零/维持 p_t）。
  - 缺点：过度收缩（K_Θ 恒含更优可行点），明显劣于 A/B，列出仅为完备。

## Response

**决策**：选 **B：逐根 KKT 投影**，但实现成最小闭式 water-filling 版本。A 只是单根退化情形，不作为多根语义。

精确顺序：

1. `strategy_target_legs`
2. `disable_shortdiff` 过滤
3. 若 `!risk.enforce_gross_cap`，不处理
4. `cap = risk.gamma.abs() * base_units`
5. `G = gross_target_units(&legs)`
6. `G == 0` 或 `G <= cap`：不缩放
7. `cap <= 0`：所有 leg `units = 0`
8. 否则按 root 子树分组，求 `c_r ∈ [0,1]`：

```text
min Σ_r A_r(c_r - 1)^2
s.t. Σ_r G_r c_r <= cap

G_r = Σ_{leg in r} |units|
A_r = Σ_{leg in r} units^2   // 当前 Rust 无 per-voice W，等价采用 W=I
```

然后每条 leg：`units *= c_root`，再进入 `net_target_units(&legs)`。

激活开关：**confirm** `RiskConfig.enforce_gross_cap: bool`，默认 `false` 保持 frozen Θ v0 bit-exact；strict/production profile 显式设 `true`。

`risk.rs` 接入：**条件 confirm**。生产路径应调用或复用 `risk.rs` 暴露的 units-space predicate，例如 `gross_units_ok(gross_units, base_units, gamma)`；`coverage.rs` 不应私写一份同义判断。`gross_notional/leverage_ok` 保留为美元空间 Lean 镜像，并用等价性测试锁住：

```text
gross_units <= gamma * base_units
iff
leverage_ok(gross_notional(...), equity, LeverageCaps { gross: gamma, ... })
```

只写测试、不让生产调用 `risk.rs` predicate，不算“死代码真接入”。

**推理链**：strict spec 的 K_Θ 不是“随便缩放规则”，而是 `LexArgmin` 在约束集上的投影。单根时可行族只有一个尺度，B 自动退化成 A。多根时跨 root 没有 spec 授权的比例绑定，所以全腿同一 `c` 会额外制造一个约束；逐根 `c_r` 才反映“root 子树独立、子树内部比例固定”的领域结构。

**替代方案**：A 拒绝为通用语义，因为它在多根时保留了非 spec 概念的跨根相对比例。C 拒绝，因为“深度优先砍腿”不是 K_Θ 投影规则，还会引入新平局规则。D 拒绝，因为 `K_Θ` 内通常存在更接近 `p̃` 的可行点，整体拒绝被严格支配。

**边界条件**：若 Rust 后续引入真实 `w_v`、cost/risk penalty 的腿级投影，B 的 `A_r=Σunits²` 必须升级为对应主键权重。若 lot 网格提前到腿级，连续 KKT 要改成离散 LexArgmin。若 spec 明确要求跨根比例保持，才推翻 B 改 A。

**风险**：主要是 f64 边界抖动、root 分组实现错误、以及默认 `false` 导致配置没开时生产仍无毛 cap。测试至少覆盖：单根退化等比例、多根非均匀、`cap=0`、`G=0`、`G<=cap`、`disable_shortdiff` 后再约束、units-space 与 `risk.rs` 美元空间等价。
