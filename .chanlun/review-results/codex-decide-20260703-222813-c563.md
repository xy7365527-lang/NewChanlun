### 2.1 方向来源分岔点（`recursive_tower.rs:477-493`）

```rust
pub fn project_to_units(moves: &[LeveledMove], blocks: &[MoveBlock]) -> Vec<UnitRange> {
    moves
        .iter()
        .enumerate()
        .map(|(idx, m)| {
            let prev = if idx == 0 { None } else { Some(&moves[idx - 1]) };
            UnitRange {
                start_index: m.start_index,
                end_index: m.end_index,
                direction: center_own_dir_at(blocks, idx)
                    .unwrap_or_else(|| m.fold_direction(prev)),
                lo: m.rmove.lo(),
                hi: m.rmove.hi(),
            }
        })
        .collect()
}
```

`center_own_dir_at`（`decompose.rs:449-457`）：

```rust
pub fn center_own_dir_at(blocks: &[MoveBlock], i: usize) -> Option<Direction> {
    if i == 0 {
        return None;
    }
    let bi = blocks.partition_point(|b| b.end_center < i);
    blocks.get(bi).filter(|b| b.start_center < i).and_then(|b| b.dir)
}
```

`blocks` 是**上一级** `decompose(&centers)` 输出——每块要么 `MoveKind::Trend(Some(dir))`
要么 `MoveKind::Consolidation(dir=None)`。`i==0`（该关系无入边）或落在 Consolidation 块 ⟹
`center_own_dir_at` 返回 `None` ⟹ `unwrap_or_else` 走 `m.fold_direction(prev)`：

```rust
pub fn fold_direction(&self, prev: Option<&LeveledMove>) -> Direction {
    match prev {
        None => Direction::Up, // 首单元无前驱 ⟹ 缺省 Up（几何路径不读取，结构占位）
        Some(p) => if self.rmove.hi() >= p.rmove.hi() { Direction::Up } else { Direction::Down },
    }
}
```

`fold_direction` 是纯 endpoint 比较（外缘 hi 是否升）——不读取任何中枢关系分类、不判断趋势/盘整，
是"结构占位"（`i==0` 分支的注释原文）。

### 2.2 消费点：单元 → 段 → 一/三类判据（`mod.rs:129-173`）

```rust
    let (start_price, end_price) = match u.direction {

    Segment { direction: u.direction, start_index: u.start_index, end_index: u.end_index,

```

`unit_to_segment` **无条件**把 `UnitRange.direction` 写入 `Segment.direction`——不区分该值来自
`center_own_dir_at`（真实 ownership/趋势关系）还是 `fold_direction`（endpoint fallback）。
`extract_signals_with_hist` 内部（`judge_first_cached`、`locate_departure_move_a`、
`departure_move_c_start`）全部按 `Segment.direction` 做匹配：

- `locate_departure_move_a` 用 `s.direction == trend_dir` 筛 A 段候选段。
- `judge_first_cached` 用 `end.dir == trend_dir`（C 段/破中枢段）判断是否触发一类候选。

`trend_dir` 来自**本级** `classify_level`/`decompose` 的块方向裁决（与 unit 自身 direction 来源
无关，是两条独立的方向信号）。只要某个 fallback 单元的 `fold_direction` 恰好等于本级 `trend_dir`，
该单元就能：(a) 作为 A 段候选参与 episode 面积比较，(b) 作为破中枢段本身触发一类候选——两种角色
在代码里没有区分"该单元方向是否有 provenance"的守卫。

## 3. 缠论原文定义（`缠论知识库.md`，权威链第2级/编纂版，供定义忠实度审查）

### 3.1 走势类型二分（§7.1）

> 任意级别的走势类型只有两类：**盘整** 与 **趋势**（趋势再分上涨/下跌）
> **盘整**：某完成走势类型只包含 **1 个** 走势中枢
> **趋势**：某完成走势类型至少包含 **2 个以上** 依次同向的走势中枢

### 3.2 中枢三种发展（§6.7）

> **延伸**：继续围绕 [ZD,ZG] 重叠震荡（表现为盘整）
> **新生**：形成趋势
> **扩展**：形成更高级别中枢

### 3.3 力度、背驰、盘整背驰（§9.1）

> **背驰**：趋势力度比上一次趋势力度弱 → 力量衰竭
> **盘整背驰**：盘整中，当下笔/线段力度比前一笔/线段弱
> **关键**：没有趋势，就没有背驰；盘整里只谈盘整背驰

### 3.4 三类买卖点定义（§10）

> **第一类买点**：某级别**下跌趋势中**，次级别走势向下跌破最后一个中枢后形成的**背驰点**
> **第一类卖点**：某级别**上涨趋势中**，次级别走势向上突破最后一个中枢后形成的**背驰点**
> **背驰-买卖点定理**：任一背驰都必然制造某级别买卖点；任一级别买卖点都必然源自某级别走势的背驰
> **趋势转折定律**：任何级别的上涨转折由某级别第一类卖点构成；下跌转折由某级别第一类买点构成

**定义域观察**：第一类买卖点的定义前提是"某级别**下跌/上涨趋势中**"——该级别必须处于趋势态
（Trend(dir)）。盘整态（Consolidation）在原文里没有方向（§7.1"盘整只含1个中枢"，无"依次同向"
的方向累积；§9.1"没有趋势就没有背驰，盘整里只谈盘整背驰"——即背驰本身在盘整态下降格为"盘整
背驰"这个独立范畴，不是"趋势背驰"的弱化版）。`fold_direction` 给盘整态/无关系单元赋的方向
（hi 是否升的 endpoint 比较）不是原文定义的"趋势方向"——它是工程结构占位（代码注释原文用词），
没有缠论概念对应物。

## Response

**决策**：选 **C：分级处置**

`UnitRange.direction` 继续保留为结构/几何方向，但不得再单独代表“可用于趋势判定的方向”。新增或派生一个不可变的方向资格字段：

```rust
anchor_direction: Option<Direction>
```

判据：

- `anchor_direction = center_own_dir_at(blocks, i)`
- `Some(dir)`：该单元可作为上级一/三类判据的方向锚
- `None`：该单元只能作为序列成员、区间成员、面积累计成员，不能作为 A 段候选、C 段/破中枢段、离开段方向锚

具体替换原则：

```rust
s.direction == trend_dir
```

在上级一/三类判据中应改为：

```rust
s.anchor_direction == Some(trend_dir)
```

适用位置包括：

- `locate_departure_move_a`：筛 A 段候选时必须要求 `anchor_direction == Some(trend_dir)`
- `judge_first_cached`：C 段/破中枢段触发一类时必须要求 `anchor_direction == Some(trend_dir)`
- `departure_move_c_start` 及三类相关离开/突破段判断：凡是把某段方向当作趋势方向使用，都必须要求 `anchor_direction == Some(expected_dir)`

**推理链**：

1. #121 的核心是对的：高级别一/三类应由高级别 `units + centers + trend` 原生判定，不应继承 L0 标签。
2. 但 #121 里“`UnitRange.direction` 已存在，所以方向问题过期”在 Q7 后需要收窄。现在 `direction` 有两种来源：趋势 ownership 方向和 endpoint fallback。两者概念不同。
3. 缠论定义里，趋势背驰的一类买卖点定义域是“上涨/下跌趋势中”。盘整只有一个中枢，无趋势方向；盘整背驰是独立范畴，不是趋势背驰的弱化版。
4. `fold_direction(prev)` 只是 endpoint 比较，不能把盘整 ownership 单元提升成趋势方向锚。
5. 但 fallback 单元仍然是一个完成的次级别走势单元。完全移出序列会破坏时间连续性、区间划分、面积累计和中枢关系，所以不选纯删除。
6. 因此最小正确建模是：**结构方向与判定资格分离**。`direction` 可服务几何，`anchor_direction` 才服务趋势判据。

与 #121 的关系：**收窄 #121，不推翻 #121**。  
#121 的“level-native 判定”继续成立；被废止的只是“`UnitRange.direction` 不论来源都可当真实趋势方向消费”。

信号计数影响：**预期减少，但严格不保证单调**。  
直接原因是 fallback C 段/破中枢段不再能触发一类，fallback A 段也不再能作为背驰比较锚。少数情况下，过滤掉一个 fallback A 后可能改选更早的合法 A，导致个别信号反而出现，所以总体应按 golden 变更处理，不能假设纯单调下降。

**替代方案**：

- **A：全部照常消费**  
  拒绝。它把 endpoint fallback 当趋势方向，违反“盘整无趋势方向、趋势背驰只在趋势中成立”的定义域，也会继续让 Consolidation-owned 单元伪造一/三类信号。

- **B：严格排除 fallback 单元**  
  拒绝作为默认实现。方向锚要排除，但单元本身不该从 episode/序列/面积区间里消失。否则会用代码便利性破坏走势连续性，属于过度修剪。

**边界条件**：

以下任一成立时可以推翻本裁决：

- 领域定义正式改为：盘整 ownership 单元的 endpoint 方向可作为上级趋势方向锚。
- `fold_direction` 不再是 endpoint fallback，而被严格证明等价于某级别趋势 ownership 方向。
- 后续算法不再用 `Segment.direction` 判一/三类，而改成直接以 `MoveBlock::Trend(dir)` 的边界和关系生成候选。
- 实测发现保留 fallback 作为成员仍会通过面积区间间接制造方向泄漏，且无法局部守卫；那应升级到 B。

- `direction` 与 `anchor_direction` 并存后，误用风险会上升；应把命名改清楚，如 `fold_direction` / `anchor_direction`。
- `i == 0` 会自然变成无锚单元，早期高级别信号可能减少。
- 三类买卖点里“离开段、回抽段、突破段”的锚点必须逐处核清，避免只修一类、漏三类。
