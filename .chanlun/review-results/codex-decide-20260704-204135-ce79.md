# 背景：量化策略 alpha 检验的 estimand 选择——696 号四选项裁定

## 项目背景

这是一个基于缠论（一种中文技术分析理论）的量化交易信号回测系统。系统对每笔模拟交易 γ
计算方向签名收益 `X_γ`，按状态变量 z（一个离散分类桶，如 (level, bsp_class, parent_dir)）
分组，检验 `μ(z) = E[X | Z=z]` 是否显著为正（alpha 检验）。

当前生产代码（`mu_estimator.rs`）里 estimand 的精确定义：

```rust
// X_i = δ_i·(H_i − B̂_i) − C_i（原始美元 PnL：方向×(平仓价−开仓价) − 交易成本）
// Y_i = δ_i(H_i−B̂_i) − C_i（残差版本，减去 beta 后的部分，仍是美元量纲，不除以任何风险量）
```

主判据（final-alpha-20260704.md 现行口径）：
- 聚合基 = δ-free `(level, bsp_class, parent_dir)` 三元组分类桶
- 三重判据：`μ̂ > 0 ∧ p_perm < 0.05 ∧ LCB_OOS > 0`（功效不足 → INCONCLUSIVE，非否证）
- 135 号纪律：冻结先于跑数——预注册的 estimand/桶键一旦冻结，不允许在既有数据上事后切换
  estimand 挑好看的结果；既有结论不因 estimand 变化而作废，但不同口径不可比。

## 已裁定内容（690 号，不在本次讨论范围）

690 号已裁定并结算：结构止损距离 `d`（entry 与 stop 的价差）**不进入 z 分类桶键**。三条独立
理由：①权威排除（完整的策略.pdf §16 二十维状态清单里，收了 β/c/m 等维度，明确排除了 d）

**690 号的三条理由全部针对"d 是否进入 z 分类桶键"这一机制，对本次要讨论的问题不构成论证。**

## 本次要裁定的问题（696 号，正交于 690 号）

690 号只回答了"d 要不要进分类桶键 z"。它**没有**回答另一个独立问题：alpha 检验的**结果变量
（estimand，即 μ 公式里的分子 X）应该测什么？

- **立场 A（现状）**：原始 μ(z,a) = E[X | z,a]，X = δ(P_τ−P_t) − C（美元 PnL，不除以任何风险量）
- **立场 B（ChatGPT「问题1.pdf」问题C 的实质主张）**：风险调整 μ_R(z,a) = E[X/d | z,a]
  （单位风险收益，即"每单位止损距离赚多少"，做法类似 sizing 层已经做的 `1/D` 归一化，
  但作用对象是"拿什么当检验的因变量"而不是"下多少仓位"）

**关键区分**：z 桶键在两个立场下完全相同（都不含 d 维）；d 只用来缩放结果变量 X，不进任何
分类维度。690 号的三条理由（权威排除 d 进桶键/层归属/分桶碎片化）都是针对"d 进桶键"这个
机制的论证，对"d 缩放结果变量"这个不同的机制，690 号未曾论证、也未曾裁定。

sizing 层已实装的 `1/d` 归一化解决的是"这笔交易该下多少仓位"，不是"检验用哪个因变量衡量
alpha"——这是两个不同层面的问题，不能因为前者已经实装就推定后者已经解决或不需要实装。

## Response

**决策**：选项 B。`μ_R = E[X/d | z,a]` 进入下一轮预注册，作为 `raw μ` 的 **co-primary**；桶键仍是 δ-free `(level,bsp_class,parent_dir)`，不加入 `d`。

**推理链**：
`X` 和 `X/d` 不是同一个概念。`X` 测原始单位交易/价格层面的正收益；`X/d` 测单位止损风险收益，接近固定风险仓位下的交易质量。标准金融实践里，风险调整收益用于比较不同风险暴露下的策略质量，例如 Sharpe 类指标本质就是“超额收益 / 风险”；但这类指标也有估计误差和分布假设风险，不能随手替代原始收益。 

sizing 层的 `1/d` 和 estimand 层的 `X/d` 不互相替代。前者回答“下多少仓位”，后者回答“检验什么收益变量”。如果当前 `X` 是未按仓位缩放的 per-trade PnL，则新增 `X/d` 不是 double-count；如果未来 `X` 已改成 position-sized PnL，再除一次 `d` 才是 double-count。

选 B 而不是 C，是因为 135 号纪律要求冻结先于跑数；当前基线又是 INCONCLUSIVE，不应把主口径从 raw μ 直接换成一个可能更好看的新变量。选 B 保留历史口径的可解释性，同时把“混合风险未检”变成正式验收门槛：未来 PASS 必须同时证明原始收益为正、单位风险收益也为正。

**替代方案**：
A 的最强理由是最简单、最不扰动生产代码，也最符合 ponytail：不改就没有新复杂度。反驳是它承认了同桶风险尺度混合，却继续让这个缺口留在主判据外；对固定风险交易系统来说不够严格。

C 的最强理由是如果实盘固定风险 sizing 才是真实经济对象，`X/d` 比 raw `X` 更贴近部署收益。反驳是替换唯一主判据代价太大，会使既有 raw μ 结论全部不可比，并且小 `d` 噪声会被放大；在当前无 confirmed alpha 时过激。

D 的最强理由是等 L2 真实利润 witness、A11/A10 架构路线一起定，避免重复协议。反驳是本问题与桶键和架构重构正交，可以在下一轮预注册中独立冻结；挂起只会继续生产 raw-only 结论。

**边界条件**：
翻转到 C：只有当正式目标改为“固定风险仓位后的可执行收益”，且代码中的 `X` 明确仍是 pre-sizing PnL，`d` 是入场前可得、稳定、非后验的风险距离，并接受全链新预注册重跑。

翻转到 A：如果 `d` 无法可靠 ex-ante 取得、近零/异常值占比高，或 L2 witness 已直接使用 position-sized PnL 作为主结果变量。

翻转到 D：如果另外三条路线将在同一冻结窗口内重定义 outcome contract，现在加 co-primary 会制造两个不兼容协议。

**风险**：
co-primary 会降低功效，更多结果会变成 INCONCLUSIVE。

`d` 分母会放大小止损样本，必须冻结最小合法距离、异常处理和成本口径。

旧 raw μ 报告和新 co-primary 报告不可直接比较。

未来若 `X` 改为已按 `qty ∝ 1/d` 缩放的实际 PnL，`X/d` 必须撤下或降级为诊断项。
