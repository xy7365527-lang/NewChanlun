class SNet:
    def __init__(self):
        self._syn_out: dict[str, list[SignifierEdge]] = {}  # 预建索引
        # 778K edges 总量

    def syntagmatic_neighbors(self, sid: str) -> list[SignifierEdge]:
        edges = self._syn_out.get(sid, [])
        return sorted(edges, key=lambda e: -e.weight)  # 排序：O(degree * log(degree))

## 审查维度

### 维度1：副作用一致性

`_thinking_loop` 声称是纯函数（返回 ThinkingResult）。
但设计描述说"每条路径积累 TRAVERSAL_ASSOCIATION"。
`_record_traversal_association` 是副作用方法（写入 self.k_active + self.k_full）。
问题：thinking_loop 如何"积累 TRAVERSAL_ASSOCIATION"？

选项A：调用 `_record_traversal_association` → 产生副作用 → 破坏"纯函数"声明
选项B：在 ThinkingResult 中返回待写入的边列表 → 调用方负责写入 → 纯函数成立，但与返回类型定义矛盾（ThinkingResult 无此字段）

### 维度2：与现有 ARTICULATE 判据的关系

现有 `_check_articulation_encounter`（431号）已产生 ARTICULATE 遭遇。
`_thinking_loop` 的触发条件是"连续 M 步没有 ARTICULATE"。
但 `_thinking_loop` 自己又会产生 ARTICULATE。

问题：
- 两者的 ARTICULATE 来源不同（拓扑不一致 vs. 汇聚点），K_active 如何区分？
- 如果 thinking_loop 触发后又恢复了 ARTICULATE 产出，M 步计数器如何重置？
- 两种 ARTICULATE 共存是否需要不同的 `context` 字段值？

### 维度3：不动点检测的度量引入

设计说"top-K 汇聚节点集合不变"作为不动点判据。

问题：
- K 是常数还是动态的？
- "集合不变"= 严格相等 → 布尔，无度量引入
- 但 `ThinkingResult.cluster_density` 是 float → 明显是度量
- 431号注释明确说 ARTICULATION_THRESHOLD 已移除（布尔，不再使用度量阈值）
- `cluster_density` 与 431号/no-metric 原则是否矛盾？

### 维度4：性能

- 778K SNet edges，syntagmatic_neighbors 返回排序列表：O(degree * log(degree))
- thinking_loop 做多条路径，每条路径 L 步，每步调 syntagmatic_neighbors
- 路径数 P，路径长 L：总调用 = P * L 次
- 每次 syntagmatic_neighbors 返回后要做排序（每次都重新排序，非缓存）
- 高度数 hub（文档中已提及 hub 劫持问题，见 snet_activation.py:478）
- thinking_loop 内部没有去重机制——是否会多次访问同一 hub？

### 维度5：状态管理

- `_thinking_loop` 需要保存自己的 position（独立于 `self.position`）
- 内部路径走完后，`self.position` 不应改变
- 但如果内部调用了 `self.walk()`（改变 `self.position`），状态会污染
- 保存/恢复 position 是否显式处理？
