### 代理类（现实装）

```python
class _AdjProxy:
    __slots__ = ("_rg", "_direction")
    def get(self, vid: str, default=()):
        if self._direction == "out":
            rust_edges = self._rg.out_edges_of(vid)
        else:
            rust_edges = self._rg.in_edges_of(vid)
        if not rust_edges:
            return default
        return [_rust_edge_to_py(re) for re in rust_edges]

class _ActiveIdsProxy:
    __slots__ = ("_rg",)
    def __contains__(self, vid: str) -> bool:
        return self._rg.contains_active(vid)
    def __len__(self) -> int:
        return self._rg.active_count()
    def __iter__(self):
        return iter(self._rg.active_vertex_ids())
    def __or__(self, other):
        return frozenset(self._rg.active_vertex_ids()) | other
    def __sub__(self, other):
        return frozenset(self._rg.active_vertex_ids()) - other
    def __and__(self, other):
        return frozenset(self._rg.active_vertex_ids()) & other

class _EdgeKeysProxy:
    __slots__ = ("_rg",)
    def __contains__(self, key: tuple) -> bool:
        source, target, edge_type = key
        return self._rg.contains_edge_key(source, target, _PY_TO_RUST_EDGE_TYPE[edge_type])
```

### mutation 方法（现实装）

```python
def _wrap(self, new_rg: "RustGraph") -> "RustGraphAdapter":
    return RustGraphAdapter(new_rg)  # 仅分配代理对象，无数据复制

def add_vertex(self, v: Vertex) -> "RustGraphAdapter":
    new_rg = self._rg.add_vertex(_py_vertex_to_rust(v))
    return self._wrap(new_rg)

def add_edge(self, e: Edge) -> "RustGraphAdapter":
    new_rg = self._rg.add_edge(_py_edge_to_rust(e))
    adapter = self._wrap(new_rg)
    # Propagate topology caches if material edge
    if e.edge_type in _MATERIAL_EDGE_TYPES:
        for attr in ('_cached_beta_1', '_cached_terrain'):
            try:
                object.__setattr__(adapter, attr, getattr(self, attr))
            except AttributeError:
                pass
    return adapter

def add_edges_batch(self, edges: list[Edge]) -> "RustGraphAdapter":
    if not edges:
        return self
    new_rg = self._rg.add_edges_batch([_py_edge_to_rust(e) for e in edges])
    adapter = self._wrap(new_rg)
    if all(e.edge_type in _MATERIAL_EDGE_TYPES for e in edges):
        for attr in ('_cached_beta_1', '_cached_terrain'):
            try:
                object.__setattr__(adapter, attr, getattr(self, attr))
            except AttributeError:
                pass
    return adapter

def add_vertices_and_edges_batch(
    self, vertices: list[Vertex], edges: list[Edge],
) -> "RustGraphAdapter":
    new_rg = self._rg.add_vertices_and_edges_batch(
        [_py_vertex_to_rust(v) for v in vertices],
        [_py_edge_to_rust(e) for e in edges],
    )
    return self._wrap(new_rg)

def set_vertex_status(self, vid: str, status: VertexStatus) -> "RustGraphAdapter":
    new_rg = self._rg.set_vertex_status(vid, _PY_TO_RUST_VERTEX_STATUS[status])
    return self._wrap(new_rg)

def merge_vertices(self, keep: str, remove: str) -> "RustGraphAdapter":
    new_rg = self._rg.merge_vertices(keep, remove)
    return self._wrap(new_rg)
```

## 审查要点

### 要点1：revision 字段是否已实装？

Codex 在 review 轮推荐了 `active_revision()`/`edge_revision()` Rust 方法用于缓存失效。
当前代码中是否有 revision 字段？`_rg.active_revision()` 是否存在？

### 要点2：`_AdjProxy.get()` 热循环 FFI 开销问题

Codex 认定 `_AdjProxy` 在 daemon 热循环中是"致命"问题：
- daemon 对 active 全集（可能 5000+ 顶点）调用 `_deg(v)`
- 每次 `_aout.get(v, ())` = 一次 FFI (`rg.out_edges_of(v)`) + list 分配
- 5000 顶点 * 2 方向 = 10000 次 FFI，每步执行

当前实装是否解决了这个问题？`max_degree_vertex` 是否下沉到 Rust？

### 要点3：`_active_ids` 跨 wrap 传播

Codex 推荐：
- `add_edge`：active 不变 → 传播旧 `_ActiveIdsProxy`（或缓存 frozenset）
- `add_vertex`/`set_vertex_status`/`merge_vertices`：active 变 → 新建

当前实装：`_wrap` 每次都 `_ActiveIdsProxy(new_rg)` → 这是新代理对象，每次 `__contains__` 走 FFI。
问题：同一个 adapter 上多次 `vid in _active_ids` = 多次 FFI。

### 要点4：`add_vertex` 中 `active_ids` 继承

`add_vertex` 中如果顶点已存在，当前实装直接调 `_wrap` 创建新代理。
若顶点 status 是 FOLDED，active_ids 不变，但实装没有区分。

### 要点5：`add_edges_batch` 返回 `self` when empty

```python
def add_edges_batch(self, edges: list[Edge]) -> "RustGraphAdapter":
    if not edges:
        return self
```
这是正确的——空 batch 返回自身，Rust 侧不调用。

### 要点6：`_cached_active_edges` / `_cached_all_active_edges` 在 `_wrap` 后是否正确失效

当前 `_wrap` 返回新 adapter，新 adapter `__slots__` 中 `_cached_active_edges` 未设置（slot 未初始化）。
`active_edges()` 用 `try/except AttributeError` 懒加载。
- `add_edge` 会改变 active_edges → 新 adapter 不继承旧缓存 → 正确
- `add_edges_batch` 的 material edge 路径传播了 `_cached_beta_1`/`_cached_terrain`，但没有传播 `_cached_active_edges`/`_cached_all_active_edges` → 正确

### 要点7：`_EdgeKeysProxy.__contains__` 的代价

当前 `_edge_keys = _EdgeKeysProxy(rg)`，每次 `(src, tgt, etype) in _edge_keys` 走 FFI `contains_edge_key`。
这是 O(1) Rust HashSet 查询，代价约 100-200ns，可接受。

### 要点8：内存安全——是否仍有隐式全量复制路径？

当前 `RustGraphAdapter.__init__` 只分配 6 个代理对象（各 2-3 slots），无数据复制。
但 `_wrap` 每次 `RustGraphAdapter(new_rg)` 仍会分配 6 个代理对象。
- 每次 add_edge = 1 次 `_wrap` = 6 个代理对象分配（极小，几百字节）
- 无 Python 侧 Vertex/Edge 数据复制

问：是否还有其他路径导致全量复制？检查 `vertices` property 和 `edges` property 的调用路径。

### 先回答你的 5 个审查点

1. **revision 字段缺失**  
   是，按你给的代码看不到 `active_revision()` / `edge_revision()` 的使用，也看不到 adapter 侧 revision 校验。  
   结果：缓存传播只能靠“操作类型猜测”，**无法证明安全**。

2. **daemon 热循环 FFI 风暴**  
   现状没解决。`daemon.py:528-537` 仍在 Python 热循环里调 `_AdjProxy.get()`。  
   且不止 2*|V| 次 FFI：每条边还会触发 `e.target in _act` / `e.source in _act`，即 `contains_active()` FFI。实际是 **顶点级 + 边级双重 FFI 风暴**。

3. **`_active_ids` 代理 vs 缓存**  
   现状是代理直通 Rust，`__contains__` 每次 FFI。若 traversal 热路径频繁 membership，代价不可接受。  
   这和“B+ 用 revision 驱动缓存失效”的目标不一致。

4. **内存安全 / 全量复制**  
   mutation 路径上 `_wrap(new_rg)` 只建代理对象，**未见 Python 侧全量复制**（这一点通过）。  
   但读路径存在高频 list/object 物化（非全量复制，但会制造大量短命对象）。

5. **遗漏的 B+ 关键组件**  
   - revision API（Rust+Python）  
   - 基于 revision 的缓存有效性判定（而非操作类型猜测）  
   - Rust 侧 `max_degree_vertex`（或等价 degree-in-active 接口）并在 daemon 调用  
   - traversal/daemon 的 active membership 去 FFI 化（快照 set 或 Rust 下沉）
