## 核心缠论定义（定义忠实度上下文）

缠师第31课「取本金」三阶段账本：
- 三阶段：CostReduction（降成本）→ CapitalRecovered（退本金）→ EarningShares（增股数）
- 单向不可逆（OQ-9），campaign 内不回退
- 守恒量 TW = free + holding + withdrawn（逐 bar 不变量）
- L^wc（最坏损失）= max(0, notional_in − withdrawn)：在险本金，退本金推进→L^wc→0
- EnterEarning 合法条件（PDF §10 步骤3，五合取）：
  S=II ∧ W≥I0 ∧ openLegacyLegs=0 ∧ RiskNormal ∧ η≥η⋆
- barrier η⋆ = L^wc + κ·Q（κ≥0 缓冲系数，κ=0基线：η⋆=L^wc）

## 被审代码关键实装

### 1. strategy/ledger.rs — RiskPolicy / TwState 核心

```rust
pub fn l_wc(&self) -> i64 {
    (self.notional_in - self.withdrawn).max(0)
}

pub struct RiskPolicy {
    pub kappa: i64,   // κ≥0，barrier 缓冲系数
}

pub fn eta_star(&self, s: &TwState) -> i64 {
    s.l_wc() + self.kappa * s.notional()   // η⋆ = L^wc + κ·Q
}

pub fn enter_ready(&self, s: &TwState, i0: i64, risk_normal: bool) -> bool {
    s.stage == TStage::CapitalRecovered
        && s.withdrawn >= i0
        && s.open_legacy_legs == 0
        && risk_normal
        && s.tw() >= self.eta_star(s)
}
```

### 3. closed_loop/transition.rs — stage_progression（barrier-gated 三阶段推进）

```rust
fn stage_progression(policy: &RiskPolicy, s: &TwState, risk_mode: RiskMode) -> Option<TwEvent> {
    let risk_normal = matches!(risk_mode, RiskMode::Normal);
    match s.stage {
        TStage::CostReduction => {
            if s.notional_in > 0 && s.holding >= s.notional_in {
                Some(TwEvent::RecoverCapital(s.notional_in))
            } else {
                None
            }
        }
        TStage::CapitalRecovered => {
            if policy.enter_ready(s, s.notional_in, risk_normal) {
                Some(TwEvent::EnterEarning)
            } else {
                None
            }
        }
        TStage::EarningShares => None,
    }
}
```

### 6. Lean TotalWealth.lean — buyCore_preserves_kappa_floor

```lean
theorem buyCore_preserves_kappa_floor
    (p : RiskPolicy) (aN lWcNext deltaQ etaN gN qN : Int)
    (h : LegalBuyCore p aN lWcNext deltaQ etaN gN qN) :
```

## 攻击目标（六点）

1. **barrier-gated 真实性**：stage_progression 中 CostReduction→RecoverCapital 的触发条件是
   `s.notional_in > 0 && s.holding >= s.notional_in`——holding 是通过 ShortDiff(-1) 从 free 转入
   的。schedule_adapter 派生 ShortDiff(-1) 是"每个 Buy 事件执行一次"，但 transition.rs 只看 
   `tw_after_order`（基于订单事件后的 tw_state），而非订单事件后的持仓。问：holding 能真实
   积累到 >= notional_in 吗？campaign_notional = clamp(len/4, 1, 128) 是否人为让 holding 必然
   >= notional_in？
   
2. **κ canonical 正确性**：enter_ready 的 W≥I0 检查中，i0 取 s.notional_in（campaign 本地本金）
   而非账户 NAV。这与 PDF §10 中"W≥I0"的含义是否一致？原文 I₀ 定义是什么？
   
3. **两步 tw_step 的守恒性**：transition_adapter 先执行订单事件（ShortDiff/RecoverCapital）再
   执行 stage_progression 事件（RecoverCapital/EnterEarning）。两步均是 tw_step——TW 守恒在每
   步都成立，但两步之间 stage 状态可能变化影响下一步的合法性判断吗？

4. **funded_campaign 的 free 变负问题**：funded_campaign 设 free=notional, notional_in=notional。
   每个 Buy 事件执行 ShortDiff(-1)，即 free -= 1, holding += 1。如果有超过 notional 个 Buy 事件
   执行，free 会变负。负 free 是否在该模型下合法？是否影响 stage_progression 判断？

5. **Lean 定理 buyCore_preserves_kappa_floor**：Lean proof 是 `unfold LegalBuyCore at h; rw 
   [Int.mul_add]; omega`——这仅是纯整数代数移项，对应的 Rust 实现 buy_core_legal 中是否有与之
   bit-exact 对齐的对应测试？Lean 证明是否真的无 sorry/admit？

6. **L0/L1 标注诚实性**：代码标注 impl=L0/L1，κ=0"恒过"是结构结果——但 stage_progression 中
   CapitalRecovered→EarningShares 的 enter_ready 包含 `s.tw() >= self.eta_star(s)` 。κ=0 时
   η⋆=L^wc=0（因 withdrawn>=notional_in 后 l_wc=0），所以 tw()≥0 恒成立。但 tw()=free+holding+
   withdrawn，若 free 为负且幅度大于 holding+withdrawn，tw() 也可能为负——是否存在 tw() < 0 
   进而 enter_ready 失败的情形？
