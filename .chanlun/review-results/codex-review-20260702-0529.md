## Q1：n_eff 校正是否真落实——实装质量审查

`rust/src/theta_v0/backtest/decontam.rs` 中 `effective_n`：

```rust
pub fn effective_n(x: &[f64]) -> f64 {
    let n = x.len();
    if n < 2 { return n as f64; }
    let mean = x.iter().sum::<f64>() / n as f64;
    let c0: f64 = x.iter().map(|v| (v - mean).powi(2)).sum();
    if c0 == 0.0 { return n as f64; }
    let mut sum_rho = 0.0_f64;
    for k in 1..n {
        let ck: f64 = (0..n - k).map(|i| (x[i] - mean) * (x[i + k] - mean)).sum();
        let rho = ck / c0;
        if rho <= 0.0 { break; }
        sum_rho += rho;
    }
    n as f64 / (1.0 + 2.0 * sum_rho)
}
```

调用链（`rust/src/theta_v0/backtest/wverify_run.rs`）：逐桶按**成交时间序**收集 `X_γ` 序列（`series: BTreeMap<(u32,u8,i8), Vec<f64>>`，`trades` 逐 bar 因果收集顺序即时间序），`n_eff = decontam::effective_n(series.get(&(lv,bc,d))...)`，喂入 `classify_bucket(mean, lcb, ucb, perm_p, n_eff, cv, za, pa)`（`n_eff` 已是 `f64` 形参，非原 `usize`）。

**审查要点**：
1. `sum_rho` 用 Geyer 初始正序列（IPS）方法逐滞后估计 ρk，首个非正 ρk 处截断——但注意此实现是**逐 lag-1 自相关**（不是 IPS 标准的"相邻两项配对和"，Geyer 原方法用于 MCMC 是对 Γ_k = ρ_{2k}+ρ_{2k+1} 配对求和后判断非负性截断）。此处是单项 ρk≤0 即截断，是 Geyer 方法的简化变体还是实质性偏离？对 n_eff 估计的保守性/激进性方向影响是什么？
2. `ck` 分母用全序列 `c0`（非滞后段自身方差），这是标准 ESS 分母口径（ACF 定义），但当 n 较大且序列非平稳（如本例 trades 分布在近 3 年，可能有 regime 漂移）时，`mean`/`c0` 用全序列估计是否会低估局部自相关强度（从而高估 n_eff）？
3. 该函数没有对求和加窗/截断上限保护（`for k in 1..n`——理论上可以遍历到 n-1），对 n=1714（VALIDATED 桶）这种规模，纯 O(n²) 计算（含 wverify_run 156s 跑批），是否存在因为**没有 lag 上限**而产生的数值不稳定风险（远滞后 ck 基于极少样本对 (0..n-k) 估计噪声很大，理论上应该在 lag 接近 n 时因估计方差过大而提前失控）？

## Q3：FWER（family-wise error rate）临界性裁决

11 桶同测（family size=11）。当前 `classify_bucket` 用逐桶未校正 `perm_α=0.05`。

- Bonferroni：α/11 ≈ 0.004545
- VALIDATED 桶 perm_p 报告 `0.000`，真实值 = `0/200` 次置换超观测。加一平滑（Laplace）：`(0+1)/(200+1) = 1/201 ≈ 0.004975`
- `0.004975 > 0.004545` ⟹ 差 0.00043（严格 Bonferroni + 加一平滑口径下**临界失守**）

**审查要点**：
1. 加一平滑是否是这里唯一合理的"真实 p 值"估计方式？R=200 置换下，观测 0/200 次超越，真实 p 值的置信区间（Clopper-Pearson 或类似）上界大约是多少？这个上界与 0.004545（Bonferroni 阈值）的关系如何？
2. 该用 Bonferroni（保守，控制 FWER）还是 BH-FDR（不那么保守，控制 FDR）？11 桶中只有 1 桶名义显著（perm_p<0.05），这种"1/11 显著"的场景下两种校正方法的实际差异有多大？
3. R=200 的置换次数本身是否是这里的瓶颈——如果 R 更大（如 R=10000），观测 0 次超越对应的加一平滑 p 值会降到 1/10001≈0.0001，远低于 Bonferroni 阈值，说明当前"临界失守"更多是**分辨率不足**而非**真实边际显著**的问题。R=200 是否被预注册冻结（改 R 是否违反预注册纪律）？如果是，这是否意味着"当前数据在 R=200 分辨率下无法给出确定性的 FWER 裁决"才是唯一诚实的结论？
