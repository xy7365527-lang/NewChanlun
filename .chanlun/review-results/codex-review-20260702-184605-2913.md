# 审查上下文：673-fix Cand^δ_ℓ 接口级三分拆实装

## 背景

673号谱系裁定：区间套候选谓词 `Cand^δ_ℓ` 原先无差别把 Type1（趋势背驰段 Extreme 判据）套用到
Type2/Type3 候选，导致中间级系统性假阴性（H2 实测 1473 样本 gate_pass=0）。codex 前次裁决①要求
"接口级三分拆"：`cand_delta_type1_extreme`/`type2_completion`/`type3_retest` 三个独立函数 + 薄
dispatcher，且明确要求 **"Type3 需独立第三分支（不可复用 Type2 顶层谓词）"**。

## 已实装代码（rust/src/theta_v0/backtest/econ_positive.rs，刚 commit）

```rust
enum BspCandType { Type1, Type2, Type3 }

fn bsp_cand_type(bits: &BspBits, delta: Side) -> BspCandType { /* buy1>buy2>buy3 优先级坍缩，Long/Short 镜像 */ }

/// Type1 候选谓词：本级趋势背驰段（div_cand Extreme+Weak）。
fn cand_delta_type1_extreme(rung_subs, source_index, delta, hist) -> bool {
    find_move_by_end_index(rung_subs, source_index) 存在 ⟹ div_cand(...)；否则 false
}

/// Type2 候选谓词：一类点后回抽走势完成。
/// docstring 声明：保护边界 = 一类点极值（回抽不破一类点），由上游结构分类器置 buy2/sell2 位时
/// 强制，本谓词"不在 Cand 层重门保护位"。存在性锚 = 次级别 Type1（定律一下沉）。
fn cand_delta_type2_completion(s, source_index, delta, hist, lvl) -> bool {
    lvl == 0 || descend_type1_anchor_depth(s, source_index, delta, hist).is_some()
}

/// Type3 候选谓词：离开中枢后回抽/反抽走势完成（独立分支）。
/// docstring 声明：保护边界 = 中枢 ZG/ZD（离开中枢回抽不入 c.zg/c.zd），与 Type2 的"一类点极值"
/// 锚点/失效条件不同，故不复用 Type2 顶层谓词——但函数体与 Type2 完全一致（同样只调用
/// descend_type1_anchor_depth 做存在性下沉锚定，不比较任何 ZG/ZD 数值）。
fn cand_delta_type3_retest(s, source_index, delta, hist, lvl) -> bool {
    lvl == 0 || descend_type1_anchor_depth(s, source_index, delta, hist).is_some()
}

/// dispatcher（per-rung）
fn cand_delta(cand_type, rung_subs, source_index, delta, hist) -> bool {
    match cand_type {
        Type1 => cand_delta_type1_extreme(...),
        Type2 | Type3 => true,   // 存在性已由 base_gate 门控，per-rung 恒真
    }
}

/// base gate（一次，非 per-rung）
fn cand_delta_base_gate(cand_type, s, source_index, delta, hist, lvl) -> bool {
    match cand_type {
        Type1 => true,
        Type2 => cand_delta_type2_completion(s, source_index, delta, hist, lvl),
        Type3 => cand_delta_type3_retest(s, source_index, delta, hist, lvl),
    }
}
```

## 上游 ZG/ZD 实际强制位置（classifier/signal.rs `judge_third`，bsp3 判定，先于 Cand 层运行）

```rust
fn judge_third(c: &Center, leave_seg: &Segment, retest_seg: &Segment) -> Option<BspPoint> {
    let leave = seg_end(leave_seg);
    let retest = seg_end(retest_seg);
    match (leave.dir, retest.dir) {
        // 3 买：leave.price > c.zg（离开）+ retest.price > c.zg（回试不触及闭区间中枢，严格 >）
        (Up, Down) if leave.price > c.zg && retest.price > c.zg => { ... 置 buy3=true ... }
        // 3 卖：leave.price < c.zd + retest.price < c.zd（镜像）
        (Down, Up) if leave.price < c.zd && retest.price < c.zd => { ... 置 sell3=true ... }
        _ => None,  // 触及中枢 ⟹ 非第三类，bit 不置
    }
}
```

即：ZG/ZD 严格边界（`> c.zg` / `< c.zd`）在 BSP 点构造阶段（`judge_third`，signal.rs）已经是
`Option::None` 短路条件——不满足则该端点根本不产生 buy3/sell3 位，不会进入 `bsp_cand_type` 分派
（`bsp_cand_type` 只在 bits.buy3/sell3 已经为 true 时才会返回 `BspCandType::Type3`）。

## 审查焦点（团队指定）

1. **核心问题**：`cand_delta_type3_retest` 与 `cand_delta_type2_completion` 函数体完全一致（均只调

   ZG/ZD。给定上游 `judge_third` 已经用严格 `>`/`<` 比较强制了 ZG/ZD 边界（产生 bit 位之前），

   站得住？如果必须独立重算，请指出具体会被上游漏判但 Cand 层本应拦截的场景（构造反例或证明不存在
   这样的场景）。

2. **次要问题**：Type2/Type3 两个谓词函数体目前完全相同（只是名字和 docstring 不同），是否构成
   "接口级三分拆"要求的语义分离不足？还是说：既然两者的**存在性锚点**（定律一下沉找次级别 Type1）
   确实相同，只是**保护边界的语义归属**不同（一类点极值 vs 中枢 ZG/ZD），而后者已经在上游 bit 位
   产生时强制过，函数体相同是诚实反映"两者在 Cand 层要做的事确实相同"，不是偷懒复用？

3. 请给出明确判决：是否需要修改代码（Type3 需要独立分叉出与 Type2 不同的函数体逻辑），还是当前实装
   （函数体相同但 docstring 记录语义归属差异）已满足裁决①"三分拆"的要求。

- Type3 的 ZG/ZD 边界已经在 [signal.rs](/Users/silencehan/Projects/NewChanLun/rust/src/theta_v0/classifier/signal.rs:358) 的 `judge_third` 中以严格口径短路：3买 `leave.price > c.zg && retest.price > c.zg`，3卖 `leave.price < c.zd && retest.price < c.zd`。失败时返回 `None`，不产生 `buy3/sell3`。
- Cand 层只消费 `BspBits`，在 [econ_positive.rs](/Users/silencehan/Projects/NewChanLun/rust/src/theta_v0/backtest/econ_positive.rs:676) 的 base gate 中分派 Type2/Type3。它没有 `Center`/`BspPoint.center` 作为参数，重算 ZG/ZD 会变成重复分类器逻辑，且在当前生产路径上是 dead gate。
