# D2 真保证金模型设计 — 审计上下文

## 背景

上一轮 codex 审计（`.chanlun/review-results/codex-p2-design-ruling-20260702.md`）对 D2 原案
（`maint_margin = 名义仓位 × config.margin_rate`）判 **fail**，核心否定：

> 引入一个从未经真实数据校准的新 Θ_risk 参数——把交易所真实的分级维持保证金表坍缩成一个拍脑袋的
> 标量 config.margin_rate。违反 formalization-validity-domain（有效域 ≠ 定义域）。

给出的翻转条件（原文）：

> 若团队有明确计划接入真实 venue/broker 的保证金数据源（而非 config 常数反推），D2 判定翻转为
> 可行；纯 config 常数反推的方案维持 fail。

`liq_flag` 当时还被指出「声称由模拟撮合产，但回测侧不存在任何模拟撮合生产 liq_flag 的模块或
契约——D2 把问题转移给一个不存在的模块」。

## 本轮新设计全文

见 `.chanlun/review-results/margin-model-design-20260703.md`（已作为附件读入，此处不重复全文，
下面摘录审计需要逐条核对的关键设计决策）：

1. **存在论移动**：`maint_margin`/`liq_flag` 不再由 config 常数反推，改为由**交易所公布的分级
   维持保证金表快照**（`MarginSchedule { venue, instrument, snapshot_date, source_url, brackets }`）
   派生。数据源：Binance `GET /fapi/v1/leverageBracket`（分级 bracket + MMR + maint_amount）、
   CME BTC/MBT margins 页面（百分比口径 + 零售 +10%）。
2. **快照版本化**：设计承认「These values change over time」——规则表落为**带快照日期的版本化
   常量表**，不是永久常量。**审计焦点①**：回测历史区间内交易所规则实际变过（bracket/MMR 随时间
   调整），设计只给了「拉一次、落一个 snapshot_date」的机制，但没有说明**回测期间用单一最新快照
   还是逐段历史快照**——这是设计稿本身承认但未解决的缺口，需要 codex 判定这个缺口是否致命。
3. **buffer1/buffer2 归类**：设计把去杠杆/只平仓缓冲显式归为 **Θ_risk 协变参数**（与 ρ/γ/β/κ 同
   类），不冒充交易所数据，理由是「交易所不公布策略该在维持线上方多少开始去杠杆」。协变形式要求
   `B̄_i = B_i / U_ℓ`（无量纲比率，保尺度不变，对齐 risk.rs:311 注释）。**审计焦点②**：buffer 归类
   诚实，但它仍是**未经验证的自由参数**，且直接决定 M1（强平/Liquidation）与 M2/M3 的触发边界。
   设计文档提供了 golden-vector 测试（L1 规则一致性）但**没有提供 buffer 取值对强平触发敏感性的
   分析方案**（即 B1/B2 定多大、错了会怎样、如何隔离其对下游 μ̂ 估计的影响）。
4. **接线方式**：新增只读派生函数 `margin_inputs(positions, equity, schedule, caps, account_model)
   -> RiskModeInput`，**不改** `AccountState` 结构，**不改** `risk_mode()`/`global_risk_close()` 机制
   （两者已实装且被 Lean `risk_mode_complete_unique` 证完备互斥）。只替换 `runner.rs:489-496`、
   `exit.rs:108-117` 的占位 0/false。
5. **账户模型分叉**：one-way/net（只看净敞口 `net_notional`）vs hedge（逐腿分档求和，对齐毛敞口
   `gross_notional`）。CME SPAN 组合风险场景延后为 L2 缺口，v0 只做百分比×名义简化。
6. **liq_flag 产者**：新命名 `SimMarginEngine::liquidation_flag(positions, mark, schedule) -> bool`，
   v0 谓词 `liq_flag ⟺ E_t ≤ MM_t`（与 M1 第二析取项 `E_t < MM_t` 在边界外等价退化）。

### risk.rs：RiskModeInput 契约 + risk_mode 五态机制（已实装，机制正确，非本次审计对象）

```rust
pub struct RiskModeInput {
    pub equity: f64,
    pub maint_margin: f64,
    pub buffer1: f64,
    pub buffer2: f64,
    pub liq_flag: bool,
}

pub fn risk_mode(input: &RiskModeInput) -> RiskMode {
    if input.equity <= 0.0 {
        RiskMode::Insolvent
    } else if input.liq_flag || input.equity < input.maint_margin {
        RiskMode::Liquidation
    } else if input.equity < input.maint_margin + input.buffer1 {
        RiskMode::Deleverage
    } else if input.equity < input.maint_margin + input.buffer2 {
        RiskMode::CloseOnly
    } else {
        RiskMode::Normal
    }
}

pub fn global_risk_close(mode: RiskMode) -> bool {
    matches!(mode, RiskMode::Insolvent | RiskMode::Liquidation)
}

pub fn net_notional(voices: &[VoiceNotional]) -> i64 { /* |Σ n_v| */ }
```

## 缠论/形式化定义锚点（供定义忠实度审查）

- **formalization-validity-domain 规则（231号）**：任何形式化操作的有效域可能严格小于定义域；
  声明有效域=定义域需要与定义域等大的验证，否则是声明膨胀。四个认识论等级 L0（纯代数）/L1（合成
  数据/管线验证）/L2（真实数据，单标的单时段）/L3（交叉验证）。**本设计声称满足的等级是 L1**
  （golden-vector 规则一致性，对照交易所公布数字），**不声称 L2/L3**。
- **no-patch-mentality（090号）**：删除虚构率、用真实规则表替换，不是在虚构率上打补丁。
- **674号裁决C（双账本分离）**：TW 账本（三阶段 free/holding/withdrawn）与 R（会计收益）显式分离，
  不允许双向同构转换。本设计声称保证金模型只读 equity E_t（与 sizing 的 nav 同源），不修改
  LedgerComp/TwState/AssemblyState 任何字段。
- **275号局部依赖原则**：每个节点只管自己的直接依赖。本设计声称保证金模型只依赖 E_t 的**值**，
  不依赖三阶段 stage 转移的**机制**。
