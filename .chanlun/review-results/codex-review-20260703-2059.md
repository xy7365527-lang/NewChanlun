## Codex 最终裁定全文（逐字，未删改）

我做的是静态核验；`codebase-memory-mcp` 调用被取消，只能按仓库源码回退读取。结论如下。

**1. P0-2/P0-3 覆盖关系：部分成立**

#140 的确只是 `TwEvent::Realize(i64)` 这类单账本资金漂移：`free += d_pi`，见
`strategy/ledger.rs:341`、`:415`、`:460`，不构成 position node 或 overlay 账本。#114 的
ShortDiff 也主要是反事实开关，`disable_shortdiff` 剔除腿后比较组合 P&L，见
`backtest/wverify_run.rs:451`、`strategy/coverage.rs:1900`。

但你方"P0-2/P0-3 完全未覆盖、A9/A11 不收窄"的说法过强。当前代码已经有 P0-2 的雏形：
`attach_bsp_carrier_indexed` 明说 `PositionNode` 身份取 `hostOf(g)` 的 carrier id，而非
买卖点叶子，且把严格 `hash(carrier_id, entry_signal, side, generation)` 标成 ceiling，
见 `strategy/coverage.rs:475-494`；测试也断言 position node id 等于 carrier id，见
`strategy/interp.rs:1518-1548`。P0-3 也不是从零：`ledger/separate.rs:1-56` 已有
`P^sep / Leg / Net` 分账本骨架，`coverage.rs:1442-1453` 已有 `overlay_net_delta` 和
`||ΔN||_1` 诊断，但它自己声明"只读诊断、无 overlay 账本、无 R/TW 投影"。

误读点：把"没有完整 overlay/严格 position instance"读成"没有任何雏形"。翻转条件：
若要求的是可交易 overlay 独立盈亏账本或多 instance position id，则缺口仍成立；若只
要求 carrier-level 容器和 `||ΔN||_1` 指标，则已部分落地。

**2. γ/gate 分派层 2B/3B 坍缩：部分成立**

`bsp_cand_type` 明确把非互斥 bits 按 `Type1 > Type2 > Type3` 坍缩，见
`backtest/econ_positive.rs:739-780`；测试还固定了 `buy2+buy3 -> Type2`，见
`econ_positive.rs:1930-1945`。所以信息层面确有"同一个候选同时是 Type3"但只存一个
dispatch type 的损失。

但当前经济路径里 Type2/Type3 大多同路：`cand_delta_base_gate` 两者都走
completion/retest 的同实现，见 `econ_positive.rs:858-875`；XZD 路径也把 Type2/Type3
合到同一确认，见 `econ_positive.rs:1503-1533`。C2 跨条目查找只补 `type2_confirmed`，见
`econ_positive.rs:1240-1253`，不能恢复 Type3 provenance。

误读点：C2 不是完整缓解，只是补 B2 确认。翻转条件：若未来 Type3 有独立 gate、统计或
执行语义，此项升级为成立；若规格明确要求"归根结底第一类/优先级坍缩"为生产语义，则
可撤销。

**3. 二值背驰谓词 D_t^δ：部分需要**

原始二值 D 已存在：`is_divergence`、`segments_diverge` 返回 bool，见
`classifier/divergence.rs:238-274`。更关键的是，你方漏读了集中合取实现：
`classifier/cand_predicate.rs:1-10` 明确写 `DivCand = direction ∧ Comparable ∧ Extreme ∧
Weak`，实现里 direction 在 `:122-129`，Comparable 在 `:131-136`，Extreme 在 `:138-145`，
Weak/D 在 `:147-150`。

所以"代码没有集中体现 B=Context∧D"不准确；至少 gate 候选路径已经集中体现。仍然缺的
是统一命名为 `D_t^δ` 的 canonical 类型/符号，且 `signal.rs` 里仍有若干 `.diverges(...)`
原始调用需要另行确认其上下文保护。

误读点：把 `divergence.rs` 当唯一背驰判定入口，漏了 `cand_predicate.rs`。翻转条件：若
审计发现生产路径直接用 `.diverges` 入场且绕过 `div_cand`，则升为实质缺口；否则只是
形式化/命名缺口。

**4. κ 敏感性网格 B35：成立，维持 B 登记**

`RiskPolicy.kappa` 是 barrier 系数，默认 0 且 `try_new` 保证非负，见
`strategy/ledger.rs:203-229`、`:241-272`；`enter_ready` 和 `buy_core_legal` 直接用
`η_* = L^wc + κQ`，见 `ledger.rs:275-320`。我未找到 κ grid。相反，buffer1/2 有显式
敏感性网格测试 `margin_buffer_sensitivity_grid`，见 `strategy/risk.rs:1268-1283`。

`docs/formal-chain/margin-model-design.md` 在仓库里不存在，所以我不能核实 §3.5 原文
强制语气。即便如此，κ 和 buffer 一样是边界参数，维持 B35 合理。

翻转条件：若后续找到正式规格说明 κ 固定为 0、不要求敏感性，或已有隐藏 κ grid 测试，
则撤销。

**5. Comparable_ℓ 严格合取 B36：不成立，可撤销**

你方关于 `sigma_higher` 的读法是对的：它只在 `selector.rs` 里给 z 向量填上级方向，见
`backtest/selector.rs:183-257`，没有进 `divergence.rs` gate。问题是 Comparable_ℓ 并不是
靠 `sigma_higher` 实现的。

严格合取已在 `cand_predicate.rs` 实现：注释定义 `DivCand` 四条件，见
`classifier/cand_predicate.rs:1-20`；代码要求同一 parent Compose 语境下存在前一个同向
rmove，否则 `return false`，见 `cand_predicate.rs:131-136`；`bsp_div_cand` 还要求能找到
上级 Compose 作为 context，见 `cand_predicate.rs:153-170`。

误读点：把"sigma_higher 未作 gate"误等同为"Comparable 未作 gate"。翻转条件：若规格
要求的 Comparable 必须是另一个"同一上级趋势方向 sigma_higher"谓词，而不是当前 parent
Compose 内同向可比，则需重开。

**6. A4 AncOK/Stale parent None：不成立，建议销项**

你方这条判断基本正确。`recursive_tower.rs:60-75` 是历史发现说明，不是当前 bug。生产
路径用的是 `ancestor_close_by_id`，见 `strategy/coverage.rs:688-698` 和生产调用
`coverage.rs:1894-1896`；旧 `ancestor_close` 索引版被 `active_set_step` 用于测试/Lean
原语，见 `coverage.rs:668-675`、`:740-745`，调用点也在测试块。

更关键的是生产 Stale 分支明确不伪造 `parent_id=None`：注释和分支见
`coverage.rs:1757-1820`；非边界 Closed/Invalidated 会 prune，边界根才 `parent_id: None`，
见 `coverage.rs:1822-1840`。`persistent.rs:1-31` 的四态 overlay 是另一个生命周期持久化
问题，不是 A4 的"索引错位伪造 parent"问题。

误读点：gap 终稿把 persistent overlay 当成 A4 的"部分缓解"，混合了两个不同问题。
翻转条件：若发现生产入场绕回 `active_set_step/ancestor_close`，或 Stale 路径实际构造
`parent_id: None` 的非边界腿，则重开。

**7. γ_t / ηBucket 四态：成立，确认性缺口**

我同意 #158。`Deficit/PositiveUnsafe/PositiveSafe/EtaBucket/eta_bucket` 在 `rust/src` 无
真实实现；`Zero` 也没有匹配到对应 enum/状态。`MuClass` 字段止于 `t_stage`，注释还承认
`ηBucket` 四态未承载，见 `backtest/mu_estimator.rs:70-85`、`:91-156`。

底层连续量和布尔门是有的：`TwState::tw`、`l_wc`、`eta_star`、`enter_ready`、
`buy_core_legal`，见 `strategy/ledger.rs:172-195`、`:269-320`。但 false 分支确实把
`η<0`、`η=0`、`0<η<η*` 都压成"not ready"。`RiskMode` 是保证金/权益状态 M0-M4，见
`strategy/risk.rs:287-349`，不是 γ_t 四桶。

翻转条件：只有找到现有四桶 enum/字段，或规格撤销 z 向量 ηBucket 维度，才会改变。

**8. MuClass vs mutex/解释器状态同构性：生产 π 路径成立，非生产路径有边界**

生产 fill loop 没发现 680 式漂移。runner 在同一 bar 内先处理 realized TW 漂移，见
`backtest/runner.rs:740-754`；随后计算 `k_theta_risk_gate`，把返回的 `risk_mode_i` 和
当前 `tw.stage` 放进同一个 `ZExt`，见 `runner.rs:757-779`。这个 `ext_i` 同时用于 χ 查询
和入场 `entry_z`，见 `runner.rs:800-806`、`:852-859`；P1-P4 决策则拿同一个 `tw` 和映射
后的 risk mode 组 `TwStepCtx`，见 `runner.rs:819-849`。`coverage.rs:2435-2513` 里的
P2/P3/P4 读取的也是 `TwStepCtx.state/risk_mode`。

存在绕开同构的路径，但它们是显式边界：`econ_positive.rs:392-408` 的统计信号用
`ZExt::NONE`；`l3_delta_r_alpha.rs:1495-1558` 的枚举诊断主动投影掉 `risk_mode/t_stage`；
这些不是生产决策链。测试也覆盖了 fill loop entry_z 能拿到 `Some(Normal)` 和
`Some(CostReduction)`，见 `backtest/runner.rs:2093-2105`。

误读点：不能把所有 `MuClass` 构造都等同于生产同构；但也不能把诊断/统计路径的 `None`
当成生产漂移。翻转条件：若发现生产 χ 查询或真实开仓使用 `ZExt::NONE`，同时
`pi_theta_step_traced` 使用非空 `TwStepCtx`，此项立刻变为不成立。
