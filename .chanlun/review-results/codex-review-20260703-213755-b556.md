```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub struct PanDivCert {
    pub source_index: usize,   // 破中枢段端点（因果触发点）
    pub side: Side,             // 向下破=Long / 向上破=Short
    pub center: Center,         // A/C 两次离开的同一中枢
    pub seg_a: (usize, usize),  // A（前一次同向离开末段）source_index 闭区间
    pub seg_c: (usize, usize),  // I(C)（当前离开走势区间）source_index 闭区间
}

fn judge_pan_div(
    c: &Center,
    seg: &Segment,
    segments: &[Segment],
    hist: &[f64],
    src_to_idx: &[usize],
) -> Option<PanDivCert> {
    let end = seg_end(seg);
    // 1. 破中枢核心（因果触发点 = 破段端点）。
    let side = match end.dir {
        Direction::Down if end.price < c.zd => Side::Long,
        Direction::Up if end.price > c.zg => Side::Short,
        _ => return None,
    };
    let dir = end.dir;
    // 窗口：与 seg 同归属本中枢的段（start_index ∈ [c.end_index, seg.start_index]，升序切片）。
    let lo = segments.partition_point(|s| s.start_index < c.end_index);
    let hi = segments.partition_point(|s| s.start_index <= seg.start_index);
    let win = &segments[lo..hi];
    // 回中枢段判据：反向段端点回到核心内侧。
    let reenters = |s: &Segment| {
        s.direction != dir
            && match dir {
                Direction::Down => s.end_price >= c.zd,
                Direction::Up => s.end_price <= c.zg,
            }
    };
    // 2. r = seg 之前最后一个回中枢段。无 r ⟹ 仅一次离开 ⟹ None。
    let r = win.iter().rev().filter(|s| s.end_index <= seg.start_index).find(|s| reenters(s))?;
    // λ_C = r 之后首个同向段起点（I(C)=[λ_C, seg.end_index]，Q5 区间语义）。
    let lambda_c = win
        .iter()
        .find(|s| s.direction == dir && s.start_index >= r.end_index)
        .map(|s| s.start_index)?;
    // 3. A = λ_C 之前、端点破核心的**末个同向段**（注意：只取单段，非区间！）。
    let a = win
        .iter()
        .rev()
        .filter(|s| s.direction == dir && s.end_index <= lambda_c)
        .find(|s| match dir {
            Direction::Down => s.end_price < c.zd,
            Direction::Up => s.end_price > c.zg,
        })?;
    // A 与 C 之间存在回中枢段（显式区间检查——否则是同一次离开）。
    if !win.iter().any(|s| reenters(s) && s.start_index >= a.end_index && s.end_index <= lambda_c) {
        return None;
    }
    // 4. Weak：MACD 面积 C < A。
    let (c_span, a_span) = ((lambda_c, seg.end_index), (a.start_index, a.end_index));
    let (Some(c_idx), Some(a_idx)) = (
        map_src_range_to_close_idx(src_to_idx, c_span.0, c_span.1),
        map_src_range_to_close_idx(src_to_idx, a_span.0, a_span.1),
    ) else {
        return None;
    };
    let abc = AbcDivergence { seg_a: a_span, seg_c: c_span, is_trend: false };
    if !abc.diverges(hist, a_idx, c_idx) {
        return None;
    }
    Some(PanDivCert { source_index: end.source_index, side, center: *c, seg_a: a_span, seg_c: c_span })
}
```

对照：**同一文件**中处理趋势背驰（buy1/sell1）A 段的 `locate_departure_move_a`（`divergence.rs`）在 Q5 裁决下已从"单段"升级为"整个离开走势区间"：

```rust
// divergence.rs（本次 diff 未改动，Q5 裁决下的既有实现，供对照）
pub fn locate_departure_move_a(
    segments: &[Segment],
    prev_center: &Center,
    last_center: &Center,
    trend_dir: Direction,
) -> Option<(usize, usize)> {
    let mut it = segments.iter().filter(|s| {
        s.direction == trend_dir
            && s.start_index >= prev_center.end_index
            && s.start_index < last_center.end_index
    });
    let first = it.next()?;
    let last = it.last().unwrap_or(first);
    // I(A) = [首个匹配段起点, 末个匹配段终点]——整个离开走势区间。
    Some((first.start_index, last.end_index))
}
```

即：buy1/sell1 路径的 A 是 `[首个匹配段.start_index, 末个匹配段.end_index]`（覆盖整个离开走势，含中间反向段的 bar）；而 `judge_pan_div` 的 A 只是**单个**"末个同向段"（`a.start_index, a.end_index`，不做首段回溯）。

pub fn center_block_kind(n_centers: usize, blocks: &[MoveBlock]) -> Vec<Option<MoveKind>> {
    let mut kinds = vec![None; n_centers];
    for b in blocks {
        for k in &mut kinds[(b.start_center + 1).min(n_centers)..(b.end_center + 1).min(n_centers)] {

        }

}

### 发现①（潜在 Q5 忠实度缺口）：`judge_pan_div` 的 A 侧未做区间化，只取单段

如上文对照所示，Q5 裁决原文是通用表述："A, C : Segment → LowerLevelMoveType"——并未把范围限定在趋势背驰。`judge_pan_div` 中 C 侧（`lambda_c..seg.end_index`）已正确做了区间化，但 A 侧 `let a = win.iter().rev().filter(...).find(...)?` 只返回**单个**匹配段的 `(a.start_index, a.end_index)`，没有像 `locate_departure_move_a` 那样向前扩展到"该次离开的首个同向段起点"。

若 A 的前一次离开本身是多段构成（含中间小反向段但未回中枢），当前实现只算最后一段的 MACD 面积，可能**低估** Area(A)，从而比"正确"区间化后更容易满足 `C < A`（即比正确判据更容易产出 PanDivCert——假阳性风险）。也可能反过来（如果面积符号有抵消），请 Codex 独立判断方向和实际影响，并判断这是否是需要修复的真实缺口，还是"盘整背驰 A 段"在原文定义上本就与"趋势背驰 A 段"不同粒度（如果后者成立，请指出原文依据）。

### 发现②（潜在冗余/待确认逻辑）：A/C 之间"存在回中枢段"的显式检查是否重复

`judge_pan_div` 末尾有一个显式检查：
```rust
if !win.iter().any(|s| reenters(s) && s.start_index >= a.end_index && s.end_index <= lambda_c) {
    return None;
}
```
Claude 的推导：由于 `r`（前面已经找到的"seg 之前最后一个回中枢段"）本身满足 `reenters(r)` 且 `r.end_index <= lambda_c`（`lambda_c` 定义为 `>= r.end_index` 的首个同向段起点），而 `a` 是"`end_index <= lambda_c` 且方向为 `dir`"的段，`r` 方向与 `dir` 相反（回中枢段判据要求 `s.direction != dir`），按线段序列的时间线性/不重叠特性，`a.end_index` 应当 `<= r.start_index`（`a` 必然在 `r` 之前，因为 `lambda_c` 到 `r.end_index` 之间按定义没有其他同向段）。若这个推导成立，则该显式检查在 `a` 已被找到的前提下**恒为 true**，是死代码式的冗余安全网（不影响正确性，但可能是"过度设计"或者 Claude 的推导有漏洞需要 Codex 核实）。请 Codex 独立验证这个不变量是否严格成立，抑或存在反例使这个检查**不冗余**（真正过滤掉了某些非法情形）。

### 发现③（待确认但非阻塞）：中枢索引基准不一致（`center_gate[pos]` vs `center_kind[c_idx]`）

见上文"3. 主循环消费"注释——`pos`（来自 `first_match_idx` 三元组查表，重复三元组下取首匹配）与 `c_idx`（`nearest_confirmed_center_idx` 真实下标）在无重复中枢三元组 `(end_index, zd, zg)` 时相同，但理论上可能不同。若不同，是否会导致某一中枢在 type1 门（`center_gate[pos]`）视角下判定为 Trend，但在 PanDiv 门（`center_kind[c_idx]`）视角下同时被判定为 Consolidation（或反之），造成 buy1/sell1 与 PanDivCert 在同一中枢上不再严格互斥？这是既有代码（`first_match_idx`/`nearest_confirmed_center_idx` 二者语义分歧，#93 遗留）与本次新增代码交互产生的，还是本次新增代码本身有责任消解？
