## 2. lag 两档拆解

### 2.1 拆分口径

对每个信号，取 pivot 的 `source_index = P`、确认/决策 bar = `D`：

- `M` = 该索引 `P` 作为**结构对象边界**（中枢的 `si`/`ei`，含 born / new_center / extend 三类事件）在转储中被确认的**最早 bar**；
- **档A（结构必需确认时间）= `M − P`**：从几何端点出现，到承载它的结构对象被前缀塔确认；
- **档B（实现引入的额外延迟）= `D − M`**：结构对象已确认后，买卖点判据还额外拖了多久。

该口径的可用性：全量 1,918 候选中 **1,556 例（81.1%）**的 pivot 索引恰好也是某个结构事件的边界索引，可直接配对。

### 2.2 实测（wf8）

**全量（按类）**

| 类 | 档A（M−P） | 档B（D−M） | 档B 为 0 的占比 |
|---|---|---|---|
| 1类 (n=18) | min 16 / 中位 50 / q3 84 | 中位 0 / p90 95 | 88.9% |
| 2类 (n=587) | min 15 / 中位 51 / q3 74 | 中位 0 / p90 0 | **96.6%** |
| 3类 (n=888) | min 13 / 中位 52 / q3 83 | 中位 0 / p90 0 | **95.5%** |

**逆侧 45 例**（29 例可配对，16 例无同索引结构事件 ⟹ 该 16 例两档**未能判定**，照实登记）

| 档 | n | min | q1 | 中位 | q3 | max |
|---|---|---|---|---|---|---|
| 档A 结构确认 | 29 | 33 | 61 | **124** | 199 | 447 |
| 档B 判据/排队 | 29 | 0 | 0 | **0** | 0 | 165 |

- 档B = 0 的例数 **28/29**；唯一非零例 = #12（L1 多 2类，pivot 76025 → M 76224 → D 76389，档B 165 bar），
  恰是 #647 报告 §残余项点名的两笔之一。
- 分类：2类档A 中位 100（n=22）、3类档A 中位 158（n=7）；两类档B 全部为 0（除 #12）。

### 2.3 两条独立佐证

1. **同批确认**：45 例中 **44/45** 的确认 bar 上同时存在结构事件（中枢 born/extend/broken）；全量 **1,892/1,918 = 98.6%**。
   买卖点与结构对象是同一批被塔放行的。
2. **结构确认延迟基线与 bsp lag 同分布**（这是档B≈0 的独立三角验证）：

   | 事件面 | n | min | 中位 | q3 |
   |---|---|---|---|---|
   | L0 中枢 born (`bar−ei`) | 717 | 14 | 55 | 94 |
   | L1 new_center | 554 | 14 | 53 | 93 |
   | L2 new_center | 133 | 19 | 57 | 92 |
   | L1/L2/L3/L4 extend | 2,459 | 13 | 52–59 | 84–121 |
   | **bsp 全量 lag** | **1,918** | **13** | **54** | **87** |

   下限、中位、四分位全部重合 ⟹ 买卖点确认的时钟就是结构确认的时钟。

3. **cascade 齐放不是延迟源**：同 bar 齐发候选（436 个 bar 上 1,028 例）与单发候选（890 例）lag 分布相同
   （中位 54 vs 54）；齐发组内 pivot 索引跨度中位 0（= 同一锚点的多类点，而非被重排一次性补放的历史点）。

### 2.4 代码级依据

- **确认时点定义**：`backtest/signal.rs::newly_confirmed_step`（`rust/src/theta_v0/backtest/signal.rs:63`）——
  输入是前缀因果分类 `classify_with_tower(l0[0..=i])`，输出是本 bar 相对 `seen` 的 append-only diff。
  该函数模块头逐字记载了旧口径（`source_index==i`）零订单的根因与改口径理由：「买卖点**回溯确认**——其
  `source_index` 的端点常在比 `source_index` 晚的 bar 才被结构（中枢突破/线段确认/背驰）确认入前缀塔」。
  **lag 因此是定义性的，不是 bug。**
- **档A 的来源 = 线段封口**：`parser/mod.rs:316 parse_layer_from_merged` 七步链（包含合并 → 分型 → 笔 →
  线段特征序列 v1）；线段确认由 `parser/feature_seq.rs` 的增量「假设转折点」状态机给出
  （第67/71课，模块头逐字引 071:38「假设某转折点是两线段的分界点，然后对此用线段划分的两种情况去考察」）。
  段的稳定前缀由 `parser/segment.rs:756 confirmed_len()` 证书给出，向上传为
  `ParseLayer.segments_confirmed_len` → `classifier` 的 `l0_confirmed_len` / `tower_confirmed_len`
  （`classifier/mod.rs:1241`）。**pivot 端点必须等到特征序列出现分型（缺口情形还要更久）才进 confirmed 前缀。**
- **档B 为何≈0（判据侧无排队）**：
  - 一类 `classifier/signal.rs:388 judge_first_cached` —— 三道结构门（破最后中枢 / 037:20 破 b 包络极值 /
    A-C 可配对）+ 背驰 D + #607 T3-in-c 分档，全部是**对已确认段的纯函数判定**，无等待队列；
  - 三类 `classifier/signal.rs:555 judge_third_cert` —— 输入是相邻 `(leave_seg, retest_seg)` 段对，
    pivot = `retest.source_index`；判据在 retest 段进入确认序列的当 bar 即成立；
  - 二类 `classifier/sublevel.rs:26 extract_second_for_level` → `classifier/signal.rs:1215
    extract_second_signals` → `rmove_compose.rs:144 find_second_type_structure`，pivot = 回拉走势 m2 的
    `end_index`。二类**多一道结构前置**（parent 必须已是 `RMove::Compose` 且带中枢载荷 `centers.first()`），
    这是二类档B 出现唯一非零例（#12，165 bar）的机制候选；但全量二类档B 零占比 96.6%，**不构成系统性额外延迟**。
  - 增量路径（`classifier/mod.rs::classify_with_tower_incremental`、`sublevel.rs::extract_second_resume`）
    带 bit-exact 铁律与 `debug_assert` 全量对拍，设计上不改变确认时点——实测档B≈0 与之一致。
- **唯一确定的实现档延迟 = 执行 +1 bar**：`strategy/exec::fill_bar_index`（决策 bar 收盘决策 → 下一 bar 成交，
  45/45 例成交 bar = 决策 bar + 1）。这 1 bar 是防未来函数的必需项，不在可压缩面内。

### 3.5 右尾的机制线索（附带发现）

三类逆侧的 retest 段**更短**而 lag **更长**：

| 三类 | leave 段长(中位) | retest 段长(中位) | lag(中位) |
|---|---|---|---|
| 全部成交 (n=505) | 119 | 105 | 58 |
| 逆侧 (n=20) | 82 | **42** | **173** |

且全体三类中 `corr(retest 段长, lag) = −0.03`、`corr(leave 段长, lag) = −0.04`（近零）。
⟹ **lag 不由 pivot 段自身尺度决定，而由 pivot 之后要等多久才出现封口用的特征序列分型决定。**
逆侧样本的画像因此是「**浅而快的回试 + 长确认等待**」：回试很浅（段短）⟹ 止损位（ZD/ZG）离得近；
确认等很久（lag 长）⟹ 这期间价格已朝原方向走远并越过该止损位 ⟹ 确认成交即触发风控。
这条是本票的**附带归因，未做因果证伪实验**（见 §6 未能判定项）。

## 5. 可压缩面候选（只列候选与风险，不实装）

前置：§2 已证**判据层没有可压缩余量**（档B 中位 0）。所有候选必须动**段确认口径**，因而全部触教义。

### 候选 1 · 未闭合尾预挂（候选先挂后证）

- **做法**：`parser/tail.rs` 已把未完成结构显式建模为 `PendingFractal / PendingStroke / PendingSegment`
  （reference:25 逐字要求）。可在 `PendingSegment` 上先产**预警候选**，段真正封口时转正、否则撤销。
- **理论收益上界**：把 lag 压到全量下限附近（p1=18 / p5=23 / p10=27，min=13），对 45 例即中位 155 → ~20 量级。
- **教义风险（高，且有代码内实证）**：
  - `tail.rs` 模块头逐字裁定：「未完成走势只能唯一分类为**当下状态**，**不能**强行分类为最终结果」，
    契约锚 `Origin.ChanlunElements.OpenTail` 把 tail 与 confirmed 明确切开、tail **仅预警不交易**。预挂即违此裁定；
  - `backtest/opsem_dump.rs:255-261` 已登记实证：**「段增长后该段的 `judge_first_cached` 重判为 `false`
    （不再是一类点，几何被后续段改判）」**——提前判会产出后来被结构本身否定的点；
  - 注意这不是**未来函数**风险（用的全是已发生数据），而是**多义性/可撤销性**风险：撤销的候选若已下单，
    等于把「假设转折点」的试错成本变成真实持仓成本。

### 候选 2 · 三类回试提前初判

- **做法**：`judge_third_cert`（`classifier/signal.rs:555`）要求 retest 是**已确认段**且用其端点判 `> zg` / `< zd`。
  可改为：leave 段确认后，对进行中的回试做逐 bar 初判——一旦回试极值已满足「不触中枢闭区间」且反向笔成立即先挂。
- **收益指向性最好**：三类占全量 64%（1227/1918）、占逆侧 20/45，且三类逆侧中位 173 是右尾最重的一块。
- **教义风险（中高）**：回试尚未结束 ⟹ 后续可能继续下探重回中枢 ⟹ 该点根本不是三类点
  （`judge_third_cert` 的严格口径注记：`retest==zg` 单点重叠即「中枢延伸非终结」，等号排除是已结算裁定）。
  提前初判等价于把「回试已结束」这一前提替换成猜测，属**用未完成结构判**。

### 候选 3 · 判定单元下移（笔代段 / 级别下沉）

- **做法**：lag 主体来自线段特征序列封口（需后续若干笔）。若 L0 判定单元由线段改为笔，确认链短一层。
- **教义风险（最高，且波及面最大）**：级别口径整体位移——中枢定义（三段重叠）、走势分解、递归塔层级、
  已冻结的 `class_index` 语义与全部预注册窗口结论都随之作废；与既有 level 塔裁定（`project_level_hole_window_dependence`
  记载的 H2 有效域）直接冲突。**列出仅为完整性，不建议单独走这条**。

### 不构成可压缩面的两项（已排除）

- **cascade / 增量缓存排队**：§2.3 实测齐发与单发同分布，且增量路径带 bit-exact 铁律 ⟹ 无余量；
- **中枢判定本身**：中枢 born 延迟（中位 55）与 bsp lag（中位 54）同分布 ⟹ 中枢层不额外加时。

## 6. 未能判定项（090 照实）
