## 1. 结论

M8 端到端**三系统同开**（M5 overlay 声部执行臂 + M6 cost_model 成本 + M7 三阶段 TW 账本）在同一
BTC OOS 跑批同时开启，产四层报告。核心发现（架构层，编译无关）：

**三系统无需独立组合层——它们已在同一主 loop `pi_theta_fill_loop_overlay` 内共存**：
- **M5**（overlay 声部账本）：`overlay: Option<&mut OverlayState>` hook；

- **M7**（三阶段 TW 账本）：`TwState` loop 内建（runner.rs:840），每笔平仓 `TwEvent::Realize` 入账。

`run_theta_v0_pi_overlay(&ds, &cfg, ...)` 一次调用即三系统全开：`cfg.margin=Some(..)` + `cfg.cost_model=Some(..)`
（M6）+ overlay hook（M5）+ TW 内建（M7）。**组合跑批不需要新接线机制，只需同时设置 config 字段**。

## 3. 边界条件（结论翻转 + 有效域）

1. **LCB 口径有效域（关键，231号强制标注）**：`significance.boot_ci95_lo` 用 `trade_pnls`（**已实现
   平仓口径**，不含 M6 funding/borrow/liq 成本、不含窗口终点浮盈）做 block bootstrap，而 total 层
   `R(Π_max-full)` 含全部成本+浮盈。由于成本拖累 ⟹ `net_r < Σ trade_pnls`（已实现），故
   **`LCB(已实现) ≤ 0 ⟹ LCB(净收益 R) ≤ 0` 更强**——作为 INCONCLUSIVE 否定判据保守正确
   （否定不会因口径近似翻转为假 confirmed）。**翻转**：若要 confirmed alpha（LCB(R)>0），须在 R 的
   逐笔分解序列上做 bootstrap（现 `r_decomp` 只给聚合值，逐笔 R 分解序列不存在）——这是 M8+ 精化项，
   本轮否定性结论不依赖它。
2. **窗口覆盖**：p3 单折 + 前两个 anchored walk-forward（O(n²) 前缀重分类，全 461万 bar 不可行）——
   诚实声明非全量。**翻转**：全窗跑批可能出不同 stage 分布（signal 层若某窗有局部正 drift）。
3. **κ=0 冻结**：M7 c3 裁定口径，正 κ 推迟 M8 后 L3。η_* = L^wc（最小 barrier）。**翻转**：κ>0 ⟹
   η_* 更高 ⟹ treasury 更难达（本轮 κ=0 已不可达 ⟹ κ>0 更不可达，codex M7 依据）。
4. **成本参数 L1**：funding/borrow/liq 是参数化常费率（A10 waiver 豁免外部数据源，不豁免机制）——
   真实历史费率是 L2 外部数据缺口。
