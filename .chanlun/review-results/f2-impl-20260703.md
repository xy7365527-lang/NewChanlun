## 1. P0-2：持仓身份碰撞边界（选项 a）

**codex 问题 4**：`attach_bsp_carrier_indexed`（coverage.rs:484）用 `posId^simp=carrier_id`，同 carrier 同 bar 多买卖点共享 id，会误合并不同批次仓位。Lead 令二选一。

**核实（重复造轮子规避）**：codex §2.1 已坐实——carrier-id 简化 position instance **已在代码里**（非待建），且已标 §14 ceiling。真实缺口只是「边界未显式声明为设计选择」。

**选择 (a) 单 carrier 单 active instance。理由入册**：当前策略每 carrier 至多持一个 active 仓位（无加仓/分批/多 generation），carrier-id 即正确身份，共享 id 不产生错误。**不升级 §13 四元组**——加仓/多批次未实装前，四元组 hash 是无消费者的死机制（YAGNI）。

**守卫**：边界由 `coverage_step_from_buckets` 出口 `next_active` 的 ElementId 唯一性 `debug_assert`（coverage.rs:1721，已存在）看守——同 carrier 若以两个不同 (dir/entry) 同时进 active，assert 触发即暴露越界。

**升级触发条件**（已写入 doc）：策略引入同 carrier 加仓 / 反手双开 / 分批建仓时本简化失效，改 `posId=hash(carrier_id,entry_signal,side,generation)`。

**改动**：coverage.rs:481 注释块新增边界裁定段（选项 a + 理由 + 守卫交叉引用 + 升级触发）。纯文档，零逻辑变更。

## 2. P0-3：overlay ‖ΔN‖_1 只读诊断

**codex 问题 5/6 + 674号**：ΔN 可从净目标差算（只读），但 Π^overlay 需 hedge 腿独立记账不可反推；overlay 一旦执行即第三会计范畴，不挂靠 R/TW。

**实装**：`pub fn overlay_net_delta(legs: &[LegTarget]) -> f64`（coverage.rs:1290），
```
ΔN_t = net_target(全腿) − net_target(剔 ShortDiff 腿) = Σ_{ShortDiff 腿} signed_units
```
代数上 = ShortDiff 反向子声部腿净贡献（= 多空对冲.pdf H_t=−σ_parent·h_t）。∑_t|ΔN_t|=‖ΔN‖_1 = 三层判定的**净额可见层**度量（depth>0 子声部是否真改净头寸）。

**边界（doc 落实 codex 5/6）**：
- 只读从 legs 净目标差算，不建账本、不投影 R/TW（674号第三范畴）。
- ΔN_t 是 sizing 层目标敞口差，**非成交 PnL**——Π^overlay=H_tΔP−ΔC 需 hedge 腿独立成本，不能从此净目标反推。
- **升级触发**：一旦 ΔN 诊断驱动真实对冲交易执行，须升级独立 `OverlayState` 账本（标注对 R/TW 投影损失）。当前只读诊断阶段不建 OverlayState 结构（YAGNI，无累积消费者）。

**测试**：`overlay_net_delta_is_shortdiff_contribution`——ΔN=短差腿净贡献 + 恒等式 net(全)−net(剔ShortDiff)=ΔN + 无短差腿⟹ΔN=0（对应多空对冲.pdf b2 净额不可见）。

**未做（按 codex 5 + ponytail）**：不把 ΔN 累积器穿过 `coverage_step_from_buckets` 全调用链（会触多文件、跨域）。提供纯原语，累积是 caller（f3 策略级回测）的事。
