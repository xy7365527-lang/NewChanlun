## 摘要（三句话）

1. **缠师对跳空有完整、成体系的处理，而且在【正文】里**——第 77 课正文给了缺口的**定义、完全分类、级别归属、跨周期传递性**四件；第 18/33/36/57/59 课正文把跳空钉死为「**级别无限低的走势**」，可以充当中枢之间的连接段、可以充当中枢震荡的一段、在显微镜下与普通线段无区别。
2. **缠师那条定理的原话是「跳空不改变任何事情」**（`075:137`，答疑）——跳空**不改变笔、不改变线段**，它只是一个级别低到不可再分的走势。**跳空在缠论里从来不是例外，是最低级别的常态。**
3. **本仓代码的隐含假设不在「价格」上，在「时间刻度」上**——包含/分型/中枢三处判据是纯价格区间比较，对跳空天然免疫；**唯一承重的隐患是笔的间隔判据 `gap_ok` 数的是 K 线根数**（`parser/stroke.rs:62`），它隐含「每根 K 覆盖的时间大致相等」。这条假设在美股上会被隔夜/周末打破，但**打破的后果需要实测，本次调研测不出来**。

## 二、代码现状（五条，逐条打开确认，行号已独立复核）

### 1. 包含处理 `rust/src/theta_v0/parser/inclusion.rs` —— 纯价格，无时间

- `inclusion.rs:38` `fn contains(a,b)`：判据 `(a.high>=b.high && a.low<=b.low) || (b.high>=a.high && b.low<=a.low)`。**只有 high/low**。
- `inclusion.rs:73` `fn strict_dir(prev,cur)`：只比 high/low 的严格同向变化，决定合并方向。**不看 source_index 差、不看 timestamp 差**。
- `inclusion.rs:49` `fn merge(acc,b,dir)`：high/low 取 max/min；`:58` `timestamp: acc.timestamp` 只是**被动沿用段起点**，不参与「是否合并」。`untradable: acc.untradable || b.untradable`（或运算，坏 bar 会污染整个合并段）。

**结论**：包含处理对跳空**免疫**（判据里没有时间）。**但同一件事的另一面**：周五收盘 K 与周一开盘 K，只要价格区间满足包含关系，会被**无差别合并成一根**——代码不知道中间隔了 65 小时。这是「不受影响」还是「该受影响却没受」，属教义问题，本调研不裁。

### 2. 分型 / 笔 / 线段

**分型** `parser/fractal.rs:35` `detect_fractals`：在 `merged[i-1], merged[i], merged[i+1]` 三元组上只比 high/low；分型的 `timestamp`（`fractal.rs:58`/`:65`）从中 K 透传，不参与判定。**无时间判据。**

**笔（theta_v0 现役）** —— **本调研查到的唯一承重隐患**：
```
rust/src/theta_v0/parser/stroke.rs:62
fn gap_ok(a: &Fractal, b: &Fractal, min_gap: u32) -> bool {
    let diff = b.source_index.saturating_sub(a.source_index);
    diff as u32 > min_gap
}
```
- 调用点：`stroke.rs:88`、`stroke.rs:315`，参数 `config.new_stroke_min_gap`。
- 默认值 `new_stroke_min_gap: 3`（`rust/src/theta_v0/config.rs:63`，字段声明 `config.rs:44`）。
- 文件头自陈（`stroke.rs:15`）：「间隔用**原始 K 序号**（`source_index`），不是合并后序号——「按原始 K 计数」」。
- `source_index` 的实际来源：`backtest/data.rs:274` `source_index: i`（for 循环下标）、`nautilus/bar_adapter.rs:46` 由调用方传入的序号。**是纯计数器，与 timestamp 完全解耦。**

**跳空对「间距」意味着什么**：`gap_ok` 数的是**原始 bar 根数差**。周五最后一根 K 与周一第一根 K，`source_index` 差 **1**，而实际时间差 **65 小时**。所以 `gap_ok` 隐含的假设是「**每根 K 覆盖的时间大致相等，故根数差 ≈ 结构距离**」。BTC 24/7 下该假设成立；美股下不成立。**注意方向**：跳空**不会**让 `gap_ok` 更容易或更难通过（它对时间不敏感），它只是让「通过 `gap_ok` 的那些笔」在时间维上不再可比。

> ⚠️ 题干提到的 `merged_gap >= 2` 在 **theta_v0 现役链里查不到**；它在并行的另一套引擎 `rust/src/stroke.rs`（`fn check_gap`，`:83` 起）里：`merged_gap = cand.idx - start.idx`（**合并后 K 根数差**）、`raw_gap` 经 `merged_to_raw`（`rust/src/bi_engine.rs:200` 一带）换算回原始根数差，新笔要 `merged_gap >= 2 && raw_gap >= new_raw_gap_min`。该文件的 `Fractal`（`rust/src/fractal.rs:21`）**根本没有 timestamp 字段**——比 theta_v0 更彻底的纯索引。两套判据数的东西不同（合并后根数 vs 原始根数），但**都是计数、都不含时间**，本条结论对两套同时成立。

**线段** `parser/segment.rs`：`grep gap` 的命中全部是 `Interval::gap`（`segment.rs:95`：`(self.high < b.low) || (b.high < self.low)`）——这是**特征序列的价格缺口**（缠论线段破坏判据里的「缺口」），与日历时间无关。**同名异物，别混。** 线段构造未见额外的索引/时间相邻性判据。

### 3. 中枢 `rust/src/theta_v0/classifier/center.rs` —— 纯价格区间

- `center.rs:210` `center_from_segments` / `center.rs:252` `center_from_window`：判据 = 方向交替（`dir_alternates`，仅 `center_from_segments` 有）+ `compute_zd(a,b,c) < compute_zg(a,b,c)`（三段 low 的 max < 三段 high 的 min）。**纯价格重叠。**
- `Center` 结构体定义在 **`types.rs:122`**（不在 `center.rs`），字段仅 `zd/zg/dd/gg/start_index/end_index`（`types.rs:123-133`）；`start_index`/`end_index` 由 `center.rs:228-229` 从段的索引继承。**无 timestamp 字段。**

**跳空穿过中枢会怎样**：代码里**没有任何「必须逐根经过」的检查**。一根跳空整根越过 zd~zg 的 K，在中枢构造判据里完全不可见——不报错、不标记、不降级。这与 `028:770`「跳空的级别是无限低的，不构成任何中枢中的一段」在**结论上一致**（跳空本来就不该当中枢的一段），但代码是**因为压根没看**才一致的，不是因为实现了那条教义。**这个区别在美股上可能变得承重**（见判定节）。

### 4. `Bar` 结构 `rust/src/theta_v0/types.rs:49` —— timestamp 是真的，但**不是度量**

```rust
pub struct Bar {
    pub source_index: usize,
    pub timestamp: Timestamp,   // types.rs:18, i64
    pub open/high/low/close: Tick,
    pub volume: i64,
    pub untradable: bool,
}
```

**（a）字段名下装的是不是索引？逐个赋值点核过**——两条生产赋值路径装的是**真时间戳**，不是索引伪装：
- `nautilus/bar_adapter.rs:59` `timestamp: nb.ts_event as Timestamp`（Nautilus 行情事件时间）；
- `backtest/data.rs:275` `timestamp: date_to_timestamp(&raw.dates[i])`（CSV 日期列）。
- 其余 `timestamp: i as i64` 一类赋值（约 45 处，检索式 `grep -rn "timestamp:" rust/src/theta_v0`，共 47 处命中）**全部落在 `#[cfg(test)]` 或测试夹具内**。

> 对照：本仓在案的「字段名下装索引」实例是 `classifier/nest.rs:43-50` 的 `NestInterval{start_time,end_time}`，已由 `.chanlun/definitions/qujiantao.md:234` 定案（「全仓所有赋值无一例外是 `<索引> as u64`」）。**`Bar.timestamp` 不是那一类。**

**（b）⚠️ 但生产链不用它，而且它也不能用**——两条独立的观察：

1. **不用**：`timestamp` 在整条 parser 链（inclusion → fractal → stroke → segment → center）中**只被透传，从未读出参与任何判定**（`inclusion.rs:58 acc.timestamp`、`fractal.rs:58/:65 mid.timestamp`）。唯一读它的地方是 `types.rs:62` `tie_key()` —— **平局裁决排序**，不是度量。
2. **⚠️ 不能用（本调研新发现，上游报告未覆盖）**：`backtest/data.rs:188` 的 `date_to_timestamp` 把 `"2016-01-03 23:00:01+00:00"` 解析成整数 **`20160103230001`**（YYYYMMDDHHMMSS 拼成的 i64）。这个数**单调但非度量**——23:59:59 → 次日 00:00:00 的差是 **1**，而 23:00 → 23:01 的差是 **100**。类型注释（`types.rs:17`）也自陈「只用于排序，不参与价格运算」。
   **⟹ 结论**：就算日后有人想「用 timestamp 算真实时间间隔来修跳空」，**在 CSV 回测路径上这条路是堵死的**，必须先换 `date_to_timestamp` 的编码。（NT 路径的 `ts_event` 是纳秒，是可度量的——**两条生产路径的 timestamp 语义不一致**。这一点本身也是一处未登记的隐患。）

### 5. `untradable` 标记 —— 语义是「这根 bar 数据坏」，承载不了「休市」

- 声明：`types.rs:57`；文档注释 `types.rs:46-47` 写的语义是「缺 OHLC / `high<max(open,close,low)` / `low>min(open,close,high)` / volume=0 / **halt / limit flag**」。

## 三、判定：**中等**

> 三档定义（题干）：几行 / 中等（加一层跳空处理，笔与中枢的定义不变）/ 动地基（笔或中枢的定义本身要重裁）。

### 为什么不是「动地基」

**因为缠师已经把跳空裁完了，而且裁的方向是「不用改」。**

- `075:137`【答疑】「**跳空不改变任何事情，如果这缺口在线段里，还是线段；在笔里，还是笔。**」——**这是对本题的直接回答，而且提问者问的正是「用在期货上老是跳空」**（期货有隔夜缺口，与美股同构）。
- `018:52`【正文】把跳空定为「最低级别」的走势类型，`028:770`【答疑】进一步「不构成任何中枢中的一段」，`057:28`【正文】「在1分钟级别显微镜下，没有区别，都可以看成是没有内部结构的线段」。
- 定义层证据（本报告 §1E）：中枢是纯价格区间（`018:24`）、包含是纯高低比较（`065:24`）、笔的间隔数 K 根数（`077:38`）——**缠论的基础判据里一个时间量都没有**，所以时间轴上戳个洞，判据本身无从被改变。

**⟹ 笔与中枢的定义不需要重裁。**「动地基」被否掉的依据是原文，不是代码。

### 为什么不是「几行」

四条实测缺口，每条都要真写东西：

1. **`untradable` 承载不了休市，也承载不了停牌**（`bar_adapter.rs:42-43` 自陈 TODO）。美股一上来就有停牌、涨跌停熔断（LULD），而 halt/limit 那一路**从来没接过**。这不是加一个 if，是要接 venue instrument 状态。
2. **timestamp 在 CSV 路径上不可度量**（`data.rs:188` 的 YYYYMMDDHHMMSS 编码），而 NT 路径是纳秒——**两条生产路径 timestamp 语义不一致**。任何想「按真实时间间隔判点什么」的改动，第一步就得先统一这两条路径的时间编码。这是数据类型层的改动，会牵动 fixture 与对拍。
3. **`gap_ok`（`stroke.rs:62`）用根数代表结构距离**，这个假设在美股上不成立。**改不改是教义选择，但「测一下差多少」是必须做的**——而 `qujiantao.md:1302` 已把它登记为「未测 / 无人跟进」。
4. **缠师给了跳空的完全分类（`077:22`：不回补=强 / 回补后续新高新低=平 / 回补后不新高新低=弱），本仓一处都没实现**。检索 `rust/src` 无任何缺口回补状态机。这是**新增一层**，不是改几行——而且按 `077:24`，衰竭性缺口的判定直接给出「至少制造一个更大级别调整」的力度结论，**它是有交易含义的**，不是装饰。

### 「中等」的具体内容（建议，非裁定）

**A. 必做（不做就不能上美股）**
- `untradable` 补 halt / limit-up-down 两路，接 venue 状态（`bar_adapter.rs:42-43` 的 TODO 兑现）。
- 统一两条生产路径的 timestamp 编码为可度量的单调时间（`data.rs:188` 换掉 YYYYMMDDHHMMSS）。**否则第 4 节 (b) 那条路一直是堵的。**

**B. 必测（`qujiantao.md:1302` 第 25 条的兑现）**
- 同一段美股数据，`source_index` 坐标 vs 真时间戳坐标，跑出笔/线段/中枢/买卖点的**真值差异幅度**。**本调研测不出来**（只读调研，无实测授权），只能确认「代码只认计数、不认时间」这个事实。
- 对照组建议：同一美股标的的**日线**（隔夜缺口全被吃进 bar 内，序列近等距）vs **5min**（缺口显式存在）。差异若接近零，则 `gap_ok` 那条隐患自证无害；若显著，才谈改判据。

**C. 可选（缠论正宗，但不是上美股的前置）**
- 实现 `077:22`–`:30` 的缺口三分类与回补状态机。名分 `[旧缠论]`（判据全部有正文原文）。

**D. 明确不做**
- 不要在 parser 层为跳空加特判。`075:137`「跳空不改变任何事情」是原文明令；`057:28` 说得更死——在本级别显微镜下跳空和普通线段「没有区别」。**在包含/分型/笔/中枢里给跳空开特例，是违背原文的。**
