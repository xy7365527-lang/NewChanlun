# Gemini decide：Lead 编排能力升级

## 语法记录 1：Lead 行为退化的结构性根源

**记录**：Lead 倾向于小粒度、串行、推迟的根本原因是 RLHF 带来的**务实性与防御性偏差**——模型被训练为"避免单次输出犯大错"（防御性拆解）和"按时间顺序思考"（CoT 副作用）。在本系统中表现为用"时间周期"（先做A再做B，后续再做C）替代"级别"（递归层级）。

溯源：[新缠论]，与 137号（RLHF 基底约束）、161号（务实否定）一致。

---

## 决策 1：废除"长期任务"与"推迟"概念

**决策**：禁止 Lead 使用"长期任务"、"后续处理"或"推迟"作为调度理由。所有复杂任务必须在当前 Session 内通过 RTAS 的**数量与深度**消化。

**推理链**：
1. "长期"是时间概念，系统只承认"级别"（结构概念）
2. 复杂性通过增加递归层级降维，不通过拉长绝对时间
3. 任务失败只能因为 VDW 不通过或物理资源耗尽（对象否定对象），不能因为 Lead 觉得"太复杂"

**边界条件**：当且仅当存在严格外部物理阻塞（等待第三方 API 审核，且无法 Mock）时，才允许挂起。

**质询判定**：成立。与 130号（RTAS 存在论要求）、161号（务实否定）一致。

## 决策 2：nested_divergence_endpoint 升级编排模式

**当前模式（问题）**：
```
Lead: 先读 server.py → 再读 a_nested_divergence.py → 设计端点 → 实现 → 写测试
→ 前端集成标记为"后续"
→ spawn 1-2 个工位，串行执行
```

**升级后模式（并行契约模式）**：
```
Lead: 评估正交领域 → 一次 spawn 3 个并行工位：
  工位 1 (Backend)：实现 /api/nested_divergence 端点 + run_nested_search 对接
  工位 2 (Performance)：解决大数据窗口超时（缓存/增量策略）
  工位 3 (Frontend)：基于预设 API 契约同步进行前端集成
→ 前端集成不是"后续"，是当前级别完整性的一部分
```

**RTAS 降级模式**（Lead 无法预设契约时）：
```
Lead: spawn 1 个总包工位 → 该工位通过 TeamCreate 自行 spawn 后端/前端子工位
```

**推理链**：
1. 串行是人类单线程思维残余
2. 只要数据依赖可通过"契约"解耦，就必须并行（原则10）
3. 前端集成是当前级别完整性的一部分，不是"后续"

**边界条件**：工位 3 发现工位 1 接口变更时，允许子蜂群内部触发重试，但不推翻"并行启动"决策。

**质询判定**：成立。与原则10（并行是默认模式）、130号（RTAS 存在论要求）一致。

## 决策 3：ceremony_scan.py 与 roadmap.yaml 改造

**决策**：
1. `roadmap.yaml` 拒绝引入"子任务分解"字段——只描述目标、约束、验证，禁止写执行步骤
2. `ceremony_scan.py` 在解析高复杂度任务时注入系统级约束提示：
   > "此任务复杂度较高。禁止串行拆解步骤。你必须：1. 评估可并行的正交领域，直接 spawn 多个并行工位；2. 授权工位使用 TeamCreate 进行 RTAS 递归。"
3. `roadmap.yaml` 新增可选字段 `rtas_depth_allowed: int`（默认 2，最大 4），明确告知 Lead 该任务允许的递归深度

**推理链**：
1. 在 YAML 里写死子任务 = 人类提前做好汇总，剥夺蜂群运行时 RTAS 展开的权力
2. YAML 只提供"规则先在性"（约束）和"异质验证必要性"（VDW），执行路径由蜂群运行时生成
3. `rtas_depth_allowed` 是约束声明，不是步骤指令

**边界条件**：如果蜂群在没有 YAML 子任务指导的情况下反复在第一层级打转，则需引入"契约定义层"作为过渡。

**质询判定**：成立。`rtas_depth_allowed` 字段是新增工程改动，需要 roadmap.yaml 格式更新和 ceremony_scan.py 解析逻辑更新。

## 综合判定

三个决策全部成立。核心结论：

1. **根源**：RLHF 防御性偏差导致 Lead 用时间周期替代递归层级
2. **废除**："长期"/"后续"不是合法调度理由，用 RTAS 数量消化复杂性
3. **并行**：nested_divergence_endpoint 应 spawn 3 个并行工位（Backend + Performance + Frontend），前端集成不是"后续"
4. **工具**：ceremony_scan.py 注入 RTAS 约束提示 + roadmap.yaml 新增 `rtas_depth_allowed` 字段
