## 1. 结论（六要素 1）

### 1.1 两个"完全分类"是两个不同的东西

| | 走势的完全分类（第17课） | 群论的完全分类（spiral/orbit） |
|---|---|---|
| 分类对象 | **走势形态**：盘整 / 趋势（再分上涨/下跌） | **操作与级别转移**：D∞ 轨道 / 五操作群作用 |
| 完备性来源 | 中枢 count：1中枢=盘整、≥2依次同向=趋势（互斥+完备，`trend.rs::classify`） | Burnside 引理 506→46→2→1（有限群作用于有限集的轨道穷尽，`orbit doc §2`） |
| 所属轴 | **H⁰ 形态学**（`T doc §0.4`） | **groupoid + H¹**（操作/转移） |
| 数学性质 | **格运算 lattice meet ∩**（中枢=区间求交），**非群运算**，**不能 σ-等变**（`center.rs` 头注 + `T doc §1.3 line133-135`） | D∞=⟨h,τ⟩ 群作用，σ=h²³（升一级别），τ²=e（手性翻转） |
| 引擎实现 | `rust/src/recursive_t/`（T 算子，#69 用） | `rust/src/spiral/`（D∞ 群机，与 unn bit-exact） |

**关键**：orbit doc §6 明确——"轨道枚举与不变量枚举是**形式对偶**，内容不相交"。群论穷尽的是 **H⁰ 不变量（58条）+ groupoid（变化合法性）+ H¹（变化率不变）三轴**；它**不分类走势形态**。走势"分盘整/趋势"这件事在群框架里属于 **H⁰ 的对象生成（中枢涌现）**，而中枢涌现被显式标注为"**涌现 ≠ 等变**，D∞ 群作用里没有'交集'这个运算"。

### 1.2 三者在哪里结合、哪里分离

**结合点（设计 + 实现）：**
- **(A) 走势完全分类 ⊗ 递归 ⊗ 买卖点 — 在 `recursive_t`（#69 引擎）内统一于 H⁰ 构造轴。** 同一个 `f`（算子 T = `apply_t`：步骤a `find_centers` → b `segment_into_trends`(走势分类) → c `judge_divergence`(买卖点) → d `encapsulate`(封装上级单元)）在每个级别迭代（`mod.rs::iterate`，`aₙ=f(aₙ₋₁)` 第65课）。买卖点是**走势分类的伴随输出**而非独立信号：type1 = 趋势背驰终结（步骤c），type3 = 中枢离开回抽（步骤a 派生）。`types.rs` 注："买卖点（T 迭代的伴随不变量，不是独立信号）"。
- **(B) 群论 ⊗ 递归 ⊗ 买卖点-操作 — 在 `spiral` 内统一于 H¹ 操作轴。** r 坐标=递归级别，σ=h²³=级别提升，σ⁻¹=Δr=−1=降级闭合（`operation.rs`：F=RadialAscend / C=ChiralSeam τ / E·D=RadialDescend σ⁻¹ / A=非群）。买卖点（信号层 `BarSig`/`BspEvent`）**驱动**群操作（`signal.rs`：buy1/sell1 confirmed → φ=0 奇点 → F/C 势源）。
- **(C) 设计意图（`T doc §0.4` 三轴正交）：H⁰（T 走势分类）产方向 → H¹（D∞ 操作）消费方向但不产生方向。** 这是**唯一**把两者挂接的蓝图："T 输出 M_k 上涨趋势 → Op h⁺ 建核心仓；T 输出次级别卖点 → σ⁻¹∘τ 下沉做空（E sink）；T 输出趋势顶背驰 → τ 清仓（C）"。

**分离点（实现现实）：**
- **(D) 两个引擎不共代码。** `rec_engine.rs`（#69 操作层）的全部 import = `prove_guards` + `types::Direction` + `fugue_v3::SUB_LIQ_FACTOR` + `trading::types::Polarity`——**零 spiral import，零 GroupAction，零 D∞**。
- **(E) #69 引擎显式声明无群代数。** `prove_guards.rs:238`：「spiral 群关系（h²³=σ / τhτ⁻¹=h⁻¹）→ **不移植**（T 引擎无 D∞ 群代数表示，无对应物）」。群不变量只以**弱化的 panic 守卫**移植（`Δr=−1` → `sub<parent`，`prove_sink_descends`；σ-不变配额 `prove_sigma_quota`；relabel 不变 `prove_relabel_invariant`），群作用的**代数本身不在 #69**。
- **(F) #69 操作层是手写 dispatch，非字面 D∞ word。** `route_bsp` 用 `nearest_active_parent`(级别) + `is_buy`(买卖点) + 父向(方向) 命令式分派 sink/recover/flip/ascend；注释把它们映射为 σ⁻¹∘τ 等，但代码不实例化群元素。spiral 才是把五操作类型化为 `Operation::group_action()` 的那一个（且 A 强平 `return None` 显形"非群"）。
- **(G) #69 与 spiral 非 bit-exact-linked。** bit-exact 关系是 **spiral ↔ unn**（`project_spiral_engine_v2_bitexact`）；`recursive_t` 是独立"真递归"引擎，复现的是它自己的 flat baseline（`rec_driver` 对照 flat `route_bsp`），不复现 spiral 群机。

## 2. 定义依据（六要素 2）

- **走势完全分类**：`缠论知识库.md:298-300`「任意级别的走势类型只有两类：盘整与趋势（趋势再分上涨/下跌）；盘整=1个走势中枢；趋势=≥2个依次同向中枢」。`trend.rs::classify` 满足此定义（`centers.len()>=2` 且外缘同向 → 趋势；否则盘整），完备+互斥由中枢 count 保证 → **#69 的走势分类是严格的第17课结构分类**。
- **中枢=格运算非群运算**：`center.rs` 头注「重叠=区间交集∩，是格运算(lattice meet)，不是群运算……不能用 σ-等变描述」；`T doc §1.3 line133`「D∞=⟨h,τ⟩ 群作用里没有'交集'这个运算」。→ 走势完全分类**结构上不可能**由群论生成。
- **群论完全分类=操作/转移轴**：`orbit doc §0`「枚举的是 D∞ 的轨道+转移结构（作用 groupoid）——回答'什么变化合法/非法'」；§6「H⁰（58不变量）/ groupoid（NR推论）/ H¹（扬弃）三轴正交、内容不相交」。
- **买卖点=T步骤c输出**：`T doc:343`「背驰=T步骤c)（走势完成判定），买卖点就是T步骤c)的输出」；`operator.rs::apply_t` 步骤c `judge_divergence` 产 type1、伴随 `detect_type3` 产 type3。
- **递归恒等**：`types.rs` + 谱系540「Move(k)≡Level-(k+1)的笔」；`mod.rs::iterate` 把 `apply_t` 沿级别迭代。

## 3. 边界条件（六要素 3）

结论"部分结合（双线）"在以下条件翻转：
- **→ 完全结合**：若 `rec_engine.rs` 改用 `spiral::GroupAction` 类型驱动 `route_bsp`（而非手写命令式分派），**或** `recursive_t` 平空路径与 `spiral` 群机达成 bit-exact 同构证明。此时群论⊗走势分类⊗递归收敛为单一引擎。
- **→ 范畴错误（被否决方向）**：若要求"走势完全分类也必须群论化（σ-等变）"，则 `center.rs`/`T doc §1.3` 的"中枢=格运算非群运算"标注失效——但这会触发 **222号范畴错误**（混淆 H⁰ 形态轴与 H¹/groupoid 操作轴 = 有效域膨胀）。**走势分类不应群论化**是设计定理，不是缺口。
- **群论"完备性"的有效域**：Burnside 穷尽性仅在**环面（mod R 回绕）**成立；真实有界级别阶梯上 σ 在顶层无像 → ⟨σ⟩ 退化为 monoid 非群（`orbit doc §1.2`）。群"完全分类"是操作空间的 L0 代数完备，**非走势空间的经验完备**。

## 4. 下游推论（六要素 4）—— #69 平空严格性

编排者约束：平空只能通过 **级别 + 买卖点 + 走势完全分类**，绝不硬编码。核实结论：

**好消息——#69 平空已经满足三要素，非硬编码：**
1. **走势完全分类**：消费 T 算子输出（`extract_view` → `view.nodes[k]` = `trends.last()` 的 TrendNode；盘整/趋势由 `trend.rs::classify` 完备分类）。
2. **买卖点**：`route_bsp` 由 buy/sell（T 步骤c 背驰输出）分派；LegPair 平空触发 = 反向买卖点 fire（`g_pair`）。
3. **级别**：区间套定位（`nearest_active_parent` / located 链）；平空走对应级别 sink/flip，主力级别由 `emergent_top` 锚定。
4. **否定线非硬编码**：止损 = 进场**末中枢核心区间 [ZD, ZG]**（`extract_view:89-95`，第17课区间套），空腿止损=涨破 ZG，多腿止损=跌破 ZD。这是结构破坏判据，不是写死价格。

**严格性修复方向（no-hardcode 的正确形式）：不是"把走势分类群论化"（=222号范畴错误），而是让三轴各司其职：**
- **级别**（H⁰ 逆遍历/区间套）：平空目标级别 = located 链顶 source / nearest_active_parent，确保"次级别卖点走次级别 sink，主力不动"（对照 547号 cascade 翻错级别根因）。
- **买卖点**（T 步骤c）：平空只在**走势完成（背驰确认 type1）OR 否定线破坏**时触发——这两者都是走势完全分类的输出，不是独立计时器。
- **走势完全分类**（H⁰）：用"该级别走势是趋势已完成 / 盘整中"判定平空时机（趋势未完成不平、背驰确认才平）。
- **潜在严格性缺口**：#69 操作层（route_bsp/sink/recover）是手写，群合法性仅以**弱化 panic 守卫**保证（`prove_sigma_quota`/`prove_sink_descends`），群代数（h²³=σ）不移植。**若编排者要求"平空必须是群合法 word（σ⁻¹∘τ）"这一更强严格性**，严格形式是：把平空路由委托 `spiral::GroupAction`，或证明 #69 平空算子与 spiral 群机 bit-exact——目前二者非 bit-exact-linked（spiral↔unn 才是）。这是一个**选择**（需编排者价值判断：弱化守卫够不够严格 / 是否要求字面群机），非定理，建议走 escalate 而非自决。

**群论 NOT 从分型构成性递归长出来——不严格的根因确认（指控成立）。** 但必须精确区分两件事：

## 7.3 群论框架（spiral/orbit）的不严格根因——三条 L2 证据

1. **spiral 零分型引用**：`grep -rn "fractal|分型|fenxing" spiral/` = **空**。spiral 消费预构建的信号层（`BarSig`/`BspEvent`/`CenterBook`），这些是分型链的**下游产物**——群作用从不触碰分型构成。
