**开收盘根的数据质量注意**：#944（旧 A/C 永续对照臂）实测「收盘根 15:30 ET 失配 72.2% 最差、开盘根 09:30 ET 37.0% 最好」（ADR 0020 引）。决策源统一美股后该对照臂名分降为历史对照臂，但「开盘/收盘根的流动性结构差异」是数据事实，试运行的信号生成时段（尤其收盘根）须纳入数据质量监控，不因名分变化而豁免。

### 2.2 流动性门槛

- **预注册容量判据（沿用）**：单笔成交额 ≤ 该 bar 成交量 **1%**（backtest-protocol §3.3，X=1 预注册常量）。
- **不可交易 bar（沿用）**：`volume = 0` 的 bar 不可交易（backtest-protocol §1.2）。
- **试运行建议门槛 [待编排者确认]**：
  1. 入场信号 bar 的成交量 ≥ 单笔名义 ×100（1% 容量常数倒推）；
  2. 设标日级流动性下限（如日成交额下限），防低流动性标的混入候选池。
  具体数值待编排者拍，落定前不设默认真值。

## 3. 数据质量门槛

### 3.1 bar 完整性

- **1min 口径（沿用 backtest-protocol §1.2）**：缺 OHLC、`high < max(open,close,low)`、`low > min(open,close,high)`、`volume = 0`、halt/limit flag 的 bar 标为**不可交易**；每品种不可交易 bar 占比 **> 5%** ⟹ 结果中显式标注数据质量警告（不豁免，只标注）。
- **tick 口径（ADR 0023 §三）**：去重前移到落盘层——主所判定 + 条件码黑名单 + 丢 TRF + `sip_seq` 消歧键，产出 consolidated Parquet(ZSTD) per-symbol/per-day。去重是引擎前置不是省盘优化（per-venue 重复不先去会虚增笔的 K 线根数，tick→Bar 直算吃不了原样数据）。
- **对拍规格**：EQUS.MINI（17.55GB，十标 2023-03+）↔ Massive 重叠段对拍，#1042 已移 Out of scope，口径随实施票细化——试运行前不依赖对拍，但十标 tick 回测上线时须有对拍。

### 3.2 断连处置（联动 #1237 演练）

- **Massive WS**：断线重连 + 按 `sip_timestamp` 区间从 REST 回补对账（ADR 0023 §三.4；#1044；`src/newchan/massive_ws.py`——回补 = 该日全量重拉，幂等覆盖）。
- **Databento Live**：后台线程重连 + 缺口补齐；启动序列 = reconciliation → 冷启动重放 → 缺口补齐 → 影子账 ↔ Portfolio 对账，全部通过才恢复意图产生（`trading_system/live/runner.py`）。
- **演练联动（本票新增的放行前置）**：试运行放行前，做一次**数据断连 + 恢复演练**——断连 → 重连 → REST 回补 → 对账一致（bar 数/OHLCV 与断连前连续，无重、无漏）。纪律对齐 #1237（全 agent 数据面迁移收尾票）的「反向恢复演练通过前旧路径不退役」：**未演练不放行**。演练最小验收口径 [待编排者确认]，见 §5 决策点 5。

### 3.3 延迟容忍

- **时间精度口径（ADR 0023 §三.2）**：历史段 ns 全精度、实时段 ms 精度（WS 毫秒 ×1e6 归一纳秒，实时行 ns 低位 = 0）。对账以 `sip_timestamp` 区间锚定。
- **引擎执行延迟 = 1 根 K**（Θ_exec「延迟 1 根 K，下一根 open 成交」，backtest-protocol §5.4）。
- **延迟敏感判据（沿用 §5.4）**：延迟 2 根 K 后 Sharpe 跌幅 > 50% ⟹ 收益依赖不可实现的即时执行。
- **试运行延迟容忍上界 [待编排者确认]**：feed 延迟必须 < 1 bar 间隔（1min 口径 < 60s，信号 bar 闭合前送达）。超时按断连处置（回补 + 该 bar 信号作废）。具体数值见 §5 决策点 6。
