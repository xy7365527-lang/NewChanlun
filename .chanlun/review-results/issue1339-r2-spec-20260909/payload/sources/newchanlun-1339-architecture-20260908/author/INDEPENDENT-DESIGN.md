# 从完整调用推导的生产架构候选

> #1339 第二阶段，服务整图 #1323；独立修订版 R1，已整合分类目录并修订 IP-H01/IP-M02，待独评复核。候选组织，未采纳、未成为 SPEC、未实施。
> 首稿未读取 B/A2/C3/C2 候选、比较图或旧 #1321/#1322/#1325/#1326 原件。与现有候选是否收敛尚未比较。

本候选由五个承重 Module 组成：**结构与操作读法、逐重经营账、共同责任、执行事实与投影、同源观察**。同一套生产核包含这些模块；Module 数目不等于进程或服务数。结构主干只有一条，每个重有自己的持久经济权威；共同责任模块保存足以在某重账不可读时保守核实所有适用共同约束的资料。它不替重写成本、不把净省变成资金。唯一执行入口必须先取得持久责任许可，所有真实回报先在共同安全顺序域同时建立原报和待核约束，再解释并应用到原责任重。

这一组织的主要代价是：不能用一个数据库总事务把全部责任问题藏起来，需要明确处理跨账的悬而未决状态、证据撤回与外部效果窗口；共同责任与外部接纳共用的持久安全顺序域仍是共同依赖。收益是 RF-01 所需的单重账故障后继续新增路径不需要恢复故障重账，也不要求前端或策略调用者协调账目。以下都是可供选择及后续反证的设计，未声称已经实现或具备资金安全、性能及收益证明。

## 1. 先写调用，不先画盒子

### U1：读全分类、查看扩展及小转大

```text
session = observe.open(scope={instrument, source, input_revision, rules_revision,
  mode, run, generation}, knowledge=AsKnown(frontier))
catalog = session.catalog()                     // 全部定义分支及能力，不按实例有无裁剪
page = session.snapshot(filter={level, kinds}, detail=Full)
change = session.changes(after=page.cursor)
event = session.explain(change.event_ref)        // 前后对象、关系、判据、获知前沿
used = session.explain(event.consumption_refs)    // 每重所消费版本、决策、准入、外效、账
```

调用者只持有逻辑会话、范围、快照和游标；不读数据库 LSN、拼账版本或自行从矩形推出中枢扩展。完整快照可晚于市场头，但必须返回其准确切面。因故障只能交付局部结果时返回 `Partial` 和缺项，不能以空集合替代。一项必要条件与其后确认的现象各有可追的记录；小转大不由定位失败产生。第 3 节承接完整分类目录，第 8 节给快照和变更协议。

### U2：两个重同源观察、各自经营，部分成交后改价

```text
s = structure.advance(accepted_market_input)    // 一份 ClassificationRevision
rA = chong[A].advance(s.ref, explicit_policy_refs)
rB = chong[B].advance(s.ref, explicit_policy_refs)
// advance 内完成操作分解、主动定位、Voice 单向合成、准入请求；返回持久 decision_ref。
// 调用方不调 reserve -> persist -> send，不选择谁先拿钱。
r = chong[A].inspect(rA.decision_ref)
// r 能是有据的动作/等待/拒绝；有动作时追到统一外效计划和实际回报。
```

A/B 的操作级别、资金、方向可不同；同一输入不因 A 的经营参数改变主干或 B。核心修订不重新测算原逻辑订单首次量；当前挂价的经营决定引用新核心版本，旧框清算引用首次冻结框。计划不是成交，`advance` 返回也不意味着场所确认。全部提交细节由第 5 节 Interface 藏住；同一逻辑订单跨物理改单的量守恒见 P7。

### U3：A 的账不可读，B 继续新提交

```text
r = chong[B].advance(s.ref, explicit_policy_refs)
// 共同责任模块在同一次准入序列化点核：B 完整账、A 责任上界、所有共同约束。
// 满足 RF-01 且 B 本身合规、有足够自身权利时，必须进入新 Committed 状态。
health = observe.open(scope).snapshot(filter={chongs:[A,B]})
// 可同时看到 A 账缺失、A 保留责任、B 新决策/提交；局部展示不参与准入。
```

这里不是让 B 使用 A 的最后可用余额。A 的最大责任必须由独立域已保存的授权、订单、外部事实、场所约束及估值依据核实；包括发送不明、迟到成交、费用和清算相关责任。任一适用共同约束不可核实，B 的新增停止。第 7 节给足够条件、具体前后状态、失败及恢复窗口。

### U4：退出尾账后重新建 Voice，断线按当时可知续接

```text
chong[A].advance(retraction_revision, explicit_policy_refs)
execution.accept(raw_external_report)           // 不指定“当前Voice”，按原责任身份匹配
page = session.resume(old_cursor)                // 可续则接同流；不可续则明确返回 Gap
past = observe.open(same_run, knowledge=AsKnown(old_frontier))
```

迟到成交属于旧 Voice 的责任史，新的 Voice 与旧尾账可以同时可查；不会把旧 fill 归给同标的的最新重。按当时可知回放使用当时已经接纳的输入和政策，不能从最终 bars 猜本金或从最终结构回贴早期信号。

## 2. 由调用推导的核心类型和写入权

下列为逻辑型草图，函数体尚不存在；类型名不冻结语言、存储或线格式。

| 类型 | 保护的知识与主要索引 |
|---|---|
| `RunIdentity` | `run/session/generation + source_namespace + instrument_mapping + mode + rules_revision + input_revision`。运行账代际与观察连接分开；重开浏览连接不重开经济账户。 |
| `ObjectRef` | `(run_generation, structure_generation, object_id, revision)`；坐标另有 raw/merged 名字空间。索引支持对象修订史、源区间到对象、父子边正反向、被经营消费引用。 |
| `ClassificationRevision` | 一份主干塔及其全部对象/分类事实/关系/变化，输入前沿、规则和分类目录版本。操作读法只引用它；不能写回其对象。 |
| `AxisClaim` | `axis_id/domain_witness/leaf_or_formula_instance/evidence_refs`，外包 `applicability / computation / knowledge / validity / purpose`。域内总函数没有 Unknown/Other 叶；未裁边界是明确未实现义务，不能伪删定义域。 |
| `OperationView` | 重、操作级别、角色规则、完整唯一段序列、Unassigned 部分、主干引用。多个重同规则可共享不可变结果，经营消费水位仍逐重保存。 |
| `LocateTrace` | 请求目标、逐级条件候选全表/选取、独立力度、相邻包含与构造来源、适用性、停止原因；几何长度/判据深度/Voice 代际分别存。 |
| `ChongRecord` | 不透明 `chong_id` 和已裁 `(S,ℓ,Q)` 构成要件；固定 Q，开户资金来源，政策版本，单个 TStage、成本/本金/增长权益、全部 Voice 和经济应用史。ID 不裁定同 `(S,ℓ)` 可否同时多实例；重生/复用限制须在身份 SPEC 显式落定。 |
| `VoiceRecord` | 所属重、不可变开局载体/方向/证书/开局量依据/父关系；业务生命周期与责任终结各有状态。结构修订只更新后来依据，不重写开局。 |
| `DecisionRecord` | 同一次判定的原始并存谓词、typed action、量与价来源、结构/读法/定位/账版本、政策版本、经济准入及拒因。不是外部已成交事实。 |
| `ResponsibilityRecord` | 唯一责任 ID、原重/Voice/决策、申请及获准最大量/责任集合、全部关联物理命令、执行形态、政策和场所证据版本、状态、逐重应用回执。这里只管共同约束与外效许可，不保存可花余额或另算成本。 |
| `ExternalFact` | 原报、接纳 token、影响约束集合、received/first_known、场所/账户/事件身份、命令/更正关系。Capture 先封可能影响域，才解析风险语义；原报不可覆写。 |
| `ConstraintEvidenceState` | 每项共同约束的待核 token 集、已核接纳前沿、证据版本/有效条件、未解决缺口；Open 由这些字段推导，不能直接写一个布尔覆盖待核事实。 |
| `LogicalOrderFamily` | run/chong/voice/已裁逻辑 key、冻结总量 L、原方向/旧框、全部物理 revision、已确定累计量、独立成交分配潜量及版本共享/互斥关系、唯一剩余量转移记录。当前价可变，不新生第二份 L。 |
| `ApplicationReceipt` | `(chong_id, external_fact_or_allocation_id)` 唯一应用，账前后版本及字段变化、原责任。记录已接纳与已应用是两件事。 |
| `ObservationCut` | 市场前沿、结构版本、逐重账/消费版本、共同责任版本、外部事实及应用水位、政策版本、范围清单；满足第 8 节依赖闭包。 |

写入权按事实内容分，而不是按加载、计算、保存阶段分：

| 权威事实 | 唯一可写者 | 它不能替谁做决定 | 提交与恢复边界 |
|---|---|---|---|
| 原始市场输入和更正 | 输入接纳 Adapter 后的市场接纳器 | 不能按执行价格修正结构源 | 来源身份去重后持久化；重放完全相同接纳序列。 |
| 主干塔、Classification、结构关系及变更 | 结构 Module 的单个受栅栏保护写者 | 不接受任一重反向改判据；不由 UI 修补 | 一个结构修订原子发布对象、关系、撤回和证据。 |
| 操作读法/主动定位 | 结构 Module 内独立只读 Interface，由重调用 | 不造第二主干、不另造宽松判断 | 结果绑定结构版本；缺失/截断有原因；纯结果可复算。 |
| 每重权利、专属筹码、Voice、TStage、成本与应用史 | 该重经营账写者 | 不写另一重、不覆写原始外部事实 | 每重单写者 epoch；本地事务同写状态、收据、待申请/发布项。 |
| 共同责任许可、总帽证据、转移托管 | 共同责任 Module | 不做方向仲裁、不定新资金政策、不计算 TStage | 许可与最大责任增加同一持久事务；减小须满足账回执和外部证据。 |
| 原始外部事实、待核影响范围及身份解析 | 执行 Module 的唯一接纳 Interface，经共同安全顺序域持久提交 | 不从意图虚构 fill；场所快照不覆写逐重成本；旁路缓存不解释风险语义 | CaptureExternal 同时 Recorded 原报和 Pending token；语义解析仅在该屏障后；Applied 仍逐重独立。 |
| 物理命令及发送状态 | 执行 Module 的受栅栏写者，经共同安全顺序域提交 | 不能自己从中枢决定价格/量；不能绕责任许可 | 发送前持久化 `MayHaveSent`，然后调用 Adapter；只允许同身份查询/幂等重投。 |
| 观察快照、目录、流 | 观察 Module 的可重建投影写者 | 不创造资金/结构事实/准入 | 读取已提交域和闭包切面；只发布观察记录。 |

共同责任记录与逐重账分别保存、校验并可独立读取，是 RF-01 的组织承诺。把它们放同一个故障即全库不可读的存储实例，不满足单重隔离试验的前提。此处不规定采用数据库分片、独立 WAL 还是其他持久介质；必须在 SPEC 给出能实现这些事务与故障隔离保证的具体技术。共享宿主整体死亡、共同责任域不可用都可能暂停新增，不承诺零停顿。

## 3. 全分类的计算和完整发布

**完整目录是强制输入，不是实现枚举的倒影。** 本修订绑定独立 `CLASSIFICATION-CATALOG.json` 的 r2-reviewable 版本（SHA-256 `b8713384045dd3f15dad14cd5f77d89a92c4176bbe3487d6ba4a09432041106f`）：62 轴/公式族、10 组合合同、32 证明/同步/选择定位项；第一阶段 44 ST 仅用于追溯，不能证明叶完整。逐轴写者、实际输出、消费、转换与验证边界见 [分类整合附录](independent-design-classification-integration.md)，结构化字段在同名 JSON。62 不是已证的数目，32 也不是 32 个新待裁语义，其中 G-003 明确不是缺口。每个分类目录条目必须携带：对象/轴/级别/角色、良构域谓词 D、所有分支谓词 P、组合约束 C、合法转换 T、来源及边界裁定、见证与反例、证明或完整分区论证、生产/观察实现状态。目录缺失或证明缺失须原样列为缺口。

对每个有限叶轴，目标义务为 `∀x, D(x) → Σ_i 1[P_i(x)] = 1`；亦可分别证总覆盖与两两互斥。公式化无限分支族需参数域、索引唯一性和边界论证。实现返回 enum 只给单值形状，不能证明其计算与 P 等价、不能证明 D 非空。验收必须分别证明：语义目录无遗漏、实现忠实每个判据、生产入口实际计算、观察完整传递、前端可达。可执行样例、属性测试和有限浮点/整数穷举都有自身射程，不替代无穷域的证明。

静态分区/互斥、实现等价、构造不变量和已证转换性质按 `(axis,semantic_version,implementation_hash,numeric_policy,construction_policy)` 绑定为可复用 ProofPackage；未变版本不逐bar跑Lean或重证全域。每次真实推进仍须验证具体输入的域、身份/证据前件与有效包，实际计算全部对象/分类/关系，输出 `EvaluationReceipt(input_frontier,proof_package_refs,domain_witnesses,computed_scope,outputs,transition_refs)`。覆盖收据是实际执行及范围的可核记录，不能仅填“全轴已算”；其完整性验证器也须与实现版本绑定。规则/程序/相关策略变化使旧包不再适用，重新验证受影响部分，旧历史保留原包。

`structure.advance` 内先按来源规则验证输入域，然后调用唯一判定核，最后封装事实。所有已裁类别均有可查询路径，即使当前没有实例。未裁边界不进入“合法第四类”，也不能用诊断补判；当前输入落入该边界时记录 `UnsettledBoundary{rule_ref,input,evidence,blocked_claims}`，结果明确不是完全分类完成。领域内算法无结果而无此已登记边界，应作为实现完整性失败，不降级成普通数据不足。

计算分组及访问路径如下，逐项映射见 JSON 的 80 行：

| 结构知识 | 由同一结构 Module 计算并发布 | 特别防漏 |
|---|---|---|
| 包含/分型/笔/线段 | raw↔merged 成员和锚、局部四分类、双坐标新笔、前缀/尾部、P2 两序列/缺口/终结 | 首锚不冒充极值根；未扫完不冒充无终结；禁止 strict 失败走优化宽档。 |
| 中枢构造与发展 | 严格 ZD<ZG 核心、三成员/连接段、冻结核心和动态 GG/G/D/DD、延伸/离开/首回试/破坏、核心分离域关系 | 不造候选中枢；外缘等号分支、九段计全部有效段、重切子窗及真正高级对象全部输出。 |
| 走势与跨级发展 | 完成三分类、形成/settled/Turn、盘整技术突破方向、前驱继任、TrendSixState 和 CenterStates 等现行目录轴 | 六态/三态的具体叶与转换只承接目录来源，不以三分类替代；未完成信息不能塞进完成三分类。 |
| 背驰/买卖点 | 结构比较对与全 Cand 集分开，L 首末速度带符号；MACD 前提及 OR 各项；六谓词与合法组合 | 64 为编码全集；Origin LevelView 的同类B/S互斥排除37个、最多27个抽象允许，逐点载体另核；2/3并存不能first-match。 |
| 主动定位与关系 | 全条件候选集、每层选择/力度/适用性/血缘、EmptySubs/NoAlign/SelectedGateFalse/SelectedGateTrue、全集只读评价、成本/基底停止 | N/A 不填 true，几何长不当判据深度；无锚不叫小转大。 |
| 描述与高级结果 | 强弱/中继等原始观察、同知时点的各级事实、具名共振、回拉/高级结果 | 原始描述不升成强制分档，见 G-003/G-021；必要条件不当已发生；多个不同轴事实不相互覆盖。 |

**小转大轨迹例**：在 k40 有末次级中枢第三点必要证据，只产生 `NecessaryConditionObserved`；k47 若出现有充分来源证据的 q 级接替及更小级背驰关系，才生成相应已发生事件，引用原事实与新 q 实例，first_known=k47；若 k47 仍延续则保留必要条件史，不生成小转大。具体“充分来源证据”必须来自目录及正本，不由本架构发明。

## 4. 每重经营的完整状态与独立性

每次 `chong.advance` 只消费一份不可变 Classification，取得该重唯一操作读法，并在相应目标上实际运行主动下钻。返回的全部结构谓词与操作失败原样保留；该 Voice 本刻最终动作按既有 typed action 规则唯一确定，动作互斥不删原始并存事实。规则或量政策未齐时留下准确 `AwaitingPolicy(policy_ids)`；不自动 Hold、不自动拒绝结构、不进入准入。

逐重账保存以下两套相互引用但不互相替代的状态：

- **经营状态**：持久重的开户/等待/经营/停止新增；单个 TStage（降成本、退本金、允许方向的赚股）、目标及其版本；一系列 Voice 的不可变开局依据、活动子链、退出。经营终结后仍保留该重及全部成本史。
- **经济状态**：自有现金/权益、固定 Q、实际筹码/原义务、冻结目标量、已实现现金流、实际费用与未分配项、本金目标/实际回收、增长权属、毛占用与预留、未决订单及尾账。每个字段都由真实输入或明确批准的政策应用得到；尚未批准计算的字段只保留原料和具体阻塞原因。

基线 d=0 与短差 d≥1 分开；回本前 `M=N`，同重所有结构层的减持/回补在一次本地状态跃迁中共同验证不穿零及 `[0,Q]`，不能逐信号分别验。动作量固定基 `w(d)Q`，量的首次测量/政策/有效域冻结，未批准上档参数不采用 0.32。价格波动只改变估值，不改成本；一次亏损往返和迟到费用都写真实账。手续费、funding 毛腿、borrow 空腿三类来源/计量/归属分别可查，不伪造多张外部账单。

TStage 以真实现金流及已批准本金/费用政策推动。线性空头没有赚股第三相，回本后仍保留空头债务；不由“虚拟成本=0”宣称场所隔离或无风险。费用跨零后的阶段回退、分母零、本金定义、增长会计桥未裁部分明确阻塞相应跃迁，但不丢原事件，不把已裁三阶段全部重标未知。

中枢震荡有效域内按已裁上下边经营；三类卖点使旧回补函数适用域结束，停止其新增准入，继续处理已发/已成责任。完成上移时本重保持基线，其他独立重继续自己的判定。新中枢建立新的经营依据，旧框仍服务旧责任清算。

容量取规模，频率决定是否开重：保存买/卖分列计数、窗口、样本、置信与稀疏原因；不把频率揉进成本速率。行情换档与 `W>C` 资金换档为两个事件族，前者保留结构触发，后者保留资金/容量证据与 `C`、`W-C` 分出关系。固定 Q 不原地变更；增长所得、资本及新重承接须具名政策。第 5 节跨重转移协议可执行已批准分拆，不能替用户决定分多少、归谁或如何解释本金。

成本评价只读同一账目事件：保留正负事件与费用及每项纳入/排除原因；按已裁 95% 单边下界、月块、事件≥30、月块≥12、≥3 不重叠窗各过线且合计≥50%全史的纪律准备输入。取样“实际下降”与亏损的张力、零时长、C_before≤0、后闸参数先解决才给正式读数。软件运行正确、统计过门和真实市场有效性分别报告。

## 5. 新提交和共同责任协议

### P1：由决定到可发送命令

Interface 为 `chong.advance`；以下步骤都是 Module 内部协议，不由上层业务或 UI 排序调用。

1. 该重单写者用账版本 b、结构版本 s、政策 p 生成 `DecisionRecord`，本地原子写 `Prepared(decision_id,b,s,p,quantity,desired_orders)` 及私有权利锁定。尚无可发送命令。本地并发命令以期望账版本 CAS 串行，失败重读同一规则，不重复生成 Voice。
2. 向共同责任申请。共同安全顺序域的单个持久事务先检查 P4 的相关待核集合为空、当前证据版本及有效条件成立，再检查该重权利证明、本重既有未决、全部适用共同帽、执行形态、场所约束及 RF-01 证据；原子写 `Reserved(responsibility_id,owner,bound,versions,grant_epoch)`，并把该最大责任纳入总约束。结构/规则已失效则不得发放新许可；资源不足不裁掉结构事实。
3. 该重本地原子写 `Committed`，关联不可复用许可、冻结量/旧框、目标状态和待发送清单；回传含精确提交哈希的 `LocalCommitReceipt`。未经此步，该许可不可发送。
4. 共同责任核验 receipt 与当前许可，原子转为 `Dispatchable` 并生成唯一物理投影计划的输入。授权标志和外效计划同一持久边界；已知撤回/代际失效则变 `NotDispatchable` 并走未发送撤销。计划只能引用已批准分配/净额投影政策；无政策即准确等待，保留原责任。
5. 执行写者在最后发送边界经同一共同安全事务验证许可、结构有效性 epoch、退出/权限、P4 全部相关待核集合及当前证据版本/有效条件、P7 逻辑量预算，然后持久写 `MayHaveSent(command_id,plan_hash,responsibility_refs)`；持久提交之后才调用场所。撤回与此边界由同一个共同责任顺序域裁定：撤回先进入该域则不可发送；`MayHaveSent` 先进入则按可能已发处理，不能承诺事后撤回可阻止已在飞行的报文。

**撤回的因果顺序不通过重命名“生效”解决**。本候选采用以下保守的结构修订屏障，属于待采纳的软件协议：

- t0：市场输入已接纳；结构写者在解释这个可能更新/撤回现有结构的输入之前，先向共同责任顺序域持久写 `BeginRevision(tower, input_frontier, writer_epoch)`。由该序列化点起，该塔范围内引用旧结构的新 reserve 和新的 MayHaveSent 都暂停；本地纯计算/Prepared 可继续，但不能越过公共准入。
- t1：结构写者实际计算并获知撤回，立即保存真实 `first_known_at=t1` 及所知输入前沿，不能改成共同域后来收件时间；观察可报告这条已知撤回及正在提交状态。因为屏障已在 t0 建立，t1 以后不存在利用旧依据取得新公共许可/新 MayHaveSent 的窗口。
- t2：结构修订对象/关系/撤回先持久提交；共同域接纳全部受影响引用的撤销及新结构有效版本，验证修订 commit 回执后，才原子写 `EndRevision`。旧 Prepared 在此重核；旧 Reserved/Committed 若已失效只可走撤销，不恢复发送资格。
- 任何命令若在 t0 之前已跨 MayHaveSent，它已处于不可判定是否发送的外效窗口，即使网络调用实际晚于 t1，仍按既有在途处理并执行获准的查询/取消；不能称为 t1 后的新准入。反之仅有普通 grant 而尚未跨此边界者在屏障期间不得发送。

首次计算也服从屏障；任一可宣布撤回的管理输入/规则更正/重算同样先取得屏障，不能有无屏障的第二撤回生产者。结构写者或共同域在 t0–t2 故障则该塔新增维持暂停，恢复器核修订日志再解除。这里承诺可验证的持久顺序，不承诺跨进程零延迟；其明显代价是同塔每次结构修订和新增发送之间有串行点、可能影响逐tick吞吐。能否改成更细依赖范围/并发验证需后续证明，首稿不以未证明优化减掉屏障。此屏障不依赖故障重账，只依赖结构/共同域；RF-01 中 B 仍须具有当前可用结构依据才能提交。

**避免无限结构输入饿死新增**：首稿把同塔处理组织成可重放的有限轮：完成当前输入修订并 EndRevision 后，必须为这一发布版本完成一个经营轮，再处理下一 BeginRevision。经营轮的参与集合从轮开始时的健康写者代际确定，故障者按 P3 封闭，不等它的回执；每个参与重在该版本上完成一次决定/准确等待结果。有限轮内同时请求作为同批提交，仍使用批准的资金政策，不按顺序抢钱。轮封闭后才到的新请求进入下一轮，新市场输入排队或背压，不能无穷抢在就绪经营轮前。该调度只给计算/提交机会，不授资金优先权；不要求运行追上无限输入速率。

RF 活性前提明确为：配置中的重集合有限、当前输入前缀有限且计算可终止、健康写者/结构/共同域获得公平调度并能持久提交、请求本身在已批规则下可准入。若有健康写者实际上不返回，须以故障隔离流程封闭其代际及保留可核责任，不可永远卡全员轮。不能仅凭有限样例有 Committed 路径证明活性，实施要在持续输入+单重故障的受控测试中显示 B 跨过新 Committed；队列增长、每轮全重负担、fencing可靠性和该性质均未实证。没有设置时延SLO或资金分配默认值。

**共同依赖的实际代价**：共同域不可用或不能确认 BeginRevision 时，新的生产结构修订也不能越过这道发布计算屏障；原始市场输入仍可独立接纳，已提交结构和历史只读仍可用。纯结构函数仍能在隔离研究/故障诊断模式执行，但不把该模式输出作为同一生产会话已发布的新状态或新准入依据。此组织使生产结构推进在调度上依赖共同域，违反不了“经营结果不得改结构判据”的语义约束，但牺牲了公共经济域故障时生产结构继续推进的可用性；该取舍必须在候选比较中显眼报告，不能以‘模块逻辑独立’隐去。

**失败窗口**：步骤 1 后重崩溃，无公共许可无发送，恢复本地 Prepared；步骤 2 后本地未提交，公共责任保留，查到本地 Prepared/明确 abort 后才撤销；本地不可读不能因超时回收。步骤 3 后 receipt 丢失，由恢复器按 decision_id 重取并重传，不能新 grant；步骤 4 后执行未接单，从持久输出恢复；步骤 5 后无响应，无论进程认为有没有发出，都保留可能全额执行责任并查询命令身份，不盲发新单。

每个写者使用独立单调 epoch，持久介质与执行入口拒绝旧 epoch；仅内存租约不够。时钟/存储失去保证时必须停止对应新写者与发送，不用 timeout 推断独占。具体栅栏载体、故障模型和事务原子性待 SPEC 选技术并实证。

### P2：增加责任先保留，减少责任后确认

公共约束使用每重可能责任集合 `R_i`，包括已持有、未发送已承诺、发送不明、部分成交剩余、费用/强平/更正义务；集合需要同时表达多空/现金/名义/保证金/外部位置，不以净目标一个数替代。对于新增动作，把动作所有合法结果集合纳入后再准入。可核约束为每个适用 j 的 `∀r∈joint(R_i), C_j(r, evidence, policy)≤cap_j`；相关性已知则保留，未知取覆盖真实可能状态的保守组合，不把相反腿默认互相抵消。

责任增加必须先写公共记录，再允许私有账和外部生效；责任减少必须先有外部终态/更正证据，且该**具体责任或已确定分配份额**的所有参与私有账已持久应用，再提交新的上界。回执集合由责任/分配关系决定，不能扩大为整个物理批次或全体重：已能独立证明 B 的分配与剩余责任时，B 自己的回执即可减小 B 的对应界，A 的界继续保留。若某个净额 fill 尚不能分清 A/B 归属，该共享部分本就不可独立释放，等待是明确代价；不能为释放 B 偷选配对政策。不得从投影屏幕余额、净额减少、cancel requested 或超时导出释放。若私有账崩溃，公共上界可偏大，保留偏大但可核的责任正是 RF-01 继续路径的代价。

上界需要有限且对当前判断有效，不只是一个历史数字：必须带价格/货币换算、场所负债与强平规则、资金费及尾费覆盖、有效条件和重新核实触发器。线性空头或外部缺口若可带来无界/不可证责任，不能写“初始保证金就是最大损失”。此时 RF-01 前件不满足，暂停所有受该共同约束影响的新增。

### P3：同 slot 并发和两类换档

同一明确 slot 的多个请求形成批次，记录 slot 完成依据（水位或受控输入结束标志）；不能按线程调度/到达先后偷偷决定资金赢家。slot 的市场/结构输入水位来自其独立接纳域，不来自每个重的回执。共同域保存当 slot 可申请者的写者代际集合；封闭故障 A 的申请代际和接纳 A grant 在同一顺序域线性排序。封闭前已接纳的 A 许可照原最大责任计入，封闭后才抵达的旧代际申请拒绝为 StaleWriter，不进入当前资金竞争；这只是失效写者隔离，不是给 B 资金优先级。完好写者的批次关闭不等待 A 出 Prepared 或 slot-end；A 恢复后用新代际、新当前依据提出请求，不把旧申请倒插到已完成批次。A 故障前获得的有效优先/预留权不得因故障被剥夺，仍在其保留责任内。批次全部请求在全部约束下可接受则一并保留；只部分可接受时，资金分配政策必须给出已批准决议。未有政策就保存 `AwaitingAllocationPolicy`，本候选不选择 FIFO、级别优先、比例缩量或“全拒即默认政策”。独立其他 slot 是否可越过争用批次同样由批准资金政策规定，不能后台默插队。

换档采用明确的权利转移对象 `(transfer_id,kind,donor,new_chong,rights,policy,evidence)`。源重先本地锁住拟分出权利；共同责任登记不可花托管项；源重本地确认扣出；目标新重本地写入 `PendingActivation` 及入账凭据；共同责任收到双方回执后把同一托管权利唯一交给目标，目标据此激活。源扣出后目标尚未入账的崩溃窗口，权利停在托管而非被重复花；目标未确认不得让源“超时退款”。取消只在共同责任证明未激活并以唯一决议返回源时发生。尾订单仍挂源责任，不能随转移移动；若拟转权益仍承担尾责，转移保持等待或携带已批准的明确承担协议，不能暗迁债。多接收重逐份转移，不用更名旧重掩盖分拆史。

## 6. 外部事实、净额投影、撤回退出和尾账

### P4：外部接纳、约束失效与逐重应用

R0 的独立 inbox→事后通知共同域会留出陈旧许可窗口，IP-H01 已指出该组织缺陷。本修订把**规范外部接纳、约束闸、Reserved 和 MayHaveSent 放在同一个持久安全顺序域**。执行 Module 仍负责协议和解释，共同责任仍不算私有成本，但这几项提交共用一个受 fencing 保护的顺序；不能由跨域消息模拟它们已原子。独立传输缓存/大报文 blob 和只读 inbox 索引可以存在，其内容在 Capture 成功前不得被任何生产者解析为风险事实或作为已知经营输入。

1. 唯一接纳器以可信连接身份确定保守范围，在风险语义解析前提交 `CaptureExternal(token,raw_bytes_or_durable_hash,source_epoch,cursor,received_at,conservative_scope)`。**同一事务**持久保存原报为 Recorded，并将 token 加到该范围每项可能受影响共同约束的 `Pending` 集合；未知具体责任先封整个相关场所账户，连账户身份也不可信则封所有可能相关账户。pending 一经提交，该范围 reserve 和尚未跨界的 MayHaveSent 均不能通过；网络确认接纳只在提交之后。此时只读传输元数据，不预先判断“这是普通 fill，应该无风险”。
2. 持久屏障之后才解析金额、费用、成交/更正/规则含义及责任关联，记录真实 `first_known_at` 和原 received 时间。获知不可核时屏障已在，不能把 known 改成后来收到通知的时间。早到 fill 可在 ack 前按 client_id/查询证据绑定；不能证明关联则 Unmatched，不能归最新 Voice。没有可靠事件 ID 时必须建立场所序号/查询去重合同；无法区分两笔同形 fill 就保留冲突。
3. 解释器产出带 token、完整源前缀、引用证据版本、影响范围及责任包含证明的 `ResolveEvidence`。共同域原子验证其依赖仍当前，只删除证书明确覆盖的 pending 项，安装已核证据或 `Unverifiable` 缺口。**Open 是“全部相关 pending 为空、无未决缺口、当前证据/时效/源连续性均有效”的推导值**。e1→e2 连续 Capture 后，Resolve(e1) 不能删除 e2；范围缩窄也须证明 e1 对释放范围无影响，不能擦掉其他 token。旧证书若依赖版本变化，必须重核。grant 与 MayHaveSent 在同一事务读取这一完整条件，不能只读某个 Valid 标志。后续通知丢失最多延迟显示/应用，不能重新打开闸。
4. 生产者闭包包含全部可能改变责任或共同约束的输入：fill/reject/cancel/fee/bust、未知手动或其他程序订单、账户快照及对账差异、行情估值/汇率、场所负债/保证金/强平/费用/权限规则、源断续和证据到期。它们均先 Capture 或 BeginEvidenceRevision 再解释；无“先独立算出失效、再异步通知”的旁路。grant/MayHaveSent 还在提交点核证据有效条件/到期，而非依赖定时消息准时送达；时钟不可核也关相应闸，不自选过期时长。市场输入若同时用于结构与估值，分别满足 BeginRevision 与此接纳屏障，不能只封结构而留下陈旧估值。
5. Recorded 后的逐重应用仍独立。按已批准投影/归属政策建立持久 AllocationRecord；内部相反权利交付标 InternalAllocation，不伪装场所 fill。每重本地以 `(fact_or_allocation_id,chong_id)` 唯一键写 ApplicationReceipt、数量/现金/费用/成本/责任变化；同 key 同内容重放无变化，异内容冲突。累计报与逐笔报由同一规范化器核差；更正/bust 引用前报并按可证因果链应用，缺前项等待。场所快照仅是校验事实，不直接覆写私账。P2 责任减小仍等待该责任对应私账收据。

**RF-01 的健康继续路径不等故障账应用**：如果 A 的普通 fill/fee 已在保留的 A 最大责任集合内，解释器可仅凭共同域原许可、场所证据及外部连续事实证明“继续保留原集合足够”，清除此 token 的相关待核项；无需降低 A 的界，也无需等 A Applied。全部共同约束仍可核时 B 正常新 Committed。只有确需降低责任来腾容量时才等对应私账回执；需要扩界则在 Resolve 同事务先纳入新界并核全部约束，不存在证明则保持关闭。

**接纳崩溃与恢复**：在 Capture 前崩溃，未确认消息依场所重放/查询恢复；生产解释不得先于 Capture。若日志写失败，受控接纳器和发送者不能继续凭内存旧闸工作。Capture 后解释前崩溃，pending 持久留存；解析后 Resolve 前崩溃，仍关闭，重算沿用 token；Resolve 后通知丢失，从相同日志恢复已核状态。重新启动一律先闭合受影响新增，取得新 writer epoch，重建 pending/已核前沿/证据缺口，校验全部源游标连续性后才重开；不是从旧 Open 布尔恢复。源头无法重放或补齐、存在未知外部写者时，相应前件不成立。独立 blob 丢失使 token 无法解析同样保持关闭。

接纳调度与 P1 结构/经营轮组成可重放的有限轮：先处理已接纳前沿的全部 pending 至有据结果，再给就绪经营请求有限公平机会，随后接纳下一批待解释原报。原报可背压，已知风险不得隐藏或推迟封闸；不存在相关未核输入且证据仍有效才可能发送。持续输入可造成排队，持续无法核实的约束不能保证新增。对 RF-01 前件持续成立的有限前沿，故障 A 不进入等待参与集，普通回报验证不要求 A 账，B 必须实际越过新 Committed。其活性/吞吐尚未模型检查。

不宣称网络恰一次；目标是可证明身份内的逻辑应用一次、原报全保留。统一安全日志不可用会同时暂停外部规范接纳与新许可/发送；传输缓存可继续收原字节，不能声称它已成为生产 Recorded。该共同依赖是本候选为消除 IP-H01 接受的明确代价。

### P5：相反毛权利的物理投影

经营账始终保留每重毛权利与义务。投影输入是已提交的逐重决定及批准执行形态；输出是物理目标/命令及全归属映射。净零不会删除两重账；某一重退出可重新产生净外效。物理确认不自动代表任一特定重已取得全部请求量；部分 fill 的归属遵循已批准映射。混合市价/限价、同 slot 相反订单若在当前投影模型无定义，候选返回具名 `ModelOrderUnspecified` 和待裁输入，不能随便先市价或先高后低；未定模型的试验臂必须显式指定 TestOnly 顺序，不进入生产/正式验收结论。

ADR0021/#937 条件生效前保持净账验收、毛账归因；逐笔独立形态获准后，执行方式、权威记账用途和验收口径在同一迁移代际切换。两种形态均只有一份相应外部事实来源。实现名称不复刻旧 VOICE_EXEC/sep_legs，但不删其已裁协同切换义务。

### P6：撤回和退出矩阵

| 撤回时原状态 | 状态变化和外部动作 | 保留/释放条件 |
|---|---|---|
| Prepared，无公共许可 | 记依据撤回，取消本地尚无外效准备 | 本地事务解锁；无假 fill。 |
| Reserved/Committed，确认未进 MayHaveSent | 公共域原子关闭发送资格，保留取消决议；私有账应用后关闭 | 双方回执证明不可再发送，才撤责任。 |
| MayHaveSent，尚无可靠响应 | 标依据失效、停止新增；按批准权限查询/请求取消 | 保留可能全成范围；timeout 不终结。 |
| 已部分成交，余量在场 | 保留已成，申请撤余；取消与 fill 可交错 | cancel ack 只证明其语义范围；迟到 fill 继续接纳，不能先释放全部。 |
| 已满成 | 不抹成交；若批准退出则产生新的平仓责任 | 新平仓也过约束/制度/权限，不能假定 reduce-only 支持或一键清空。 |
| 业务已终结，费用/更正未齐 | 旧责任以尾账状态持续接纳 | 依据场所可证明的剩余责任界与对账规则减保留，不设任意“过 N 秒即终结”。 |

例：逻辑目标量 100（仅测试单位），先 fill 40，取消请求后再 fill 20，后到 cancel ack；已成=60，剩余未执行=40 的最终可核性取决于 ack/查询语义和回报缺口。乱序收到 ack 再收到原已发生 fill 20 仍得到 60，重复 40/20 均不重加。Voice 可停止经营，但该 60 和费用及后续 bust 均归原责任；相同 `(S,ℓ)` 的新 Voice 不接旧收据。

业务退休需无新经营许可、活动子链按已裁规则终结；责任退休另需所有命令可核终态、全部已知 fact 已应用、账实对齐、仍可能的未来费用/更正责任有有效覆盖或可证为零。历史原始事实和所有归属不可删除，即使责任退休后仍可接纳合法更正；若更正超出此前覆盖，重新进入故障/对账状态并冻结受影响新增，不能宣称永远不会发生。退出动作权限未给时只执行已获权限的取消/查询，保持待授权及责任，不私自补偿或强平。

### P7：同一逻辑订单改价的物理修订与总量守恒

逻辑订单按已裁 scope/key 续挂，首次冻结量为 L；改价只新增该订单的物理 revision，不能申请第二份 L。共同域保存 `LogicalOrderFamily` 和每个物理命令的量分配。对方向固定的这一动作，任何可发送版本必须证明：**已确定累计执行量 F + 各份独立可成交额度分配的最大可能未计执行量之和 ≤ L**。每份分配须列其全部物理版本；有场所累计总上限及版本互斥证据的原子 amend 链共享一份分配，旧/新互斥版本只计一份链级潜量，amend 控制命令本身不获额。能够独立成交的旧/新命令必须分开计量；共享关系或归属不明时不得据此创建第二份分配或释放原潜量。其中“未计”包含已在场发生但尚未接收到的潜在 fill；不能因场所状态声称 cancelled 就视其为零。净额投影中的每份逻辑分配同样受本合同，物理净量够小不免除逻辑毛量限制；归属未定不能铸造某重剩余额度。后来的反向回补是自己的逻辑动作，不能借改价暗换方向或增加首次量。

具体能力分两条，有据才选择：

- **原子改单**：仅当获准场所合同明确保证同逻辑链的“历史累计成交+全部版本剩余”受一个总量上限、改单确认/拒绝及查询能恢复这条链时，才采用该能力。请求表达的是总冻结上限 L；若场所 API 使用剩余量，其参数转换必须依版本化累计量且保证原子。旧版本失效与新版本生效是场所保证的同一操作。只有 replace 名称或修改 client_id 不构成证明。丢失回应时保留原链总潜量并按原 amend_id 查询/场所幂等重投，不另发一条独立单。
- **取消后替换**：其余具备可证终态/完整累计回报能力的场所，用 `Active→CancelRequested→AwaitingFinality→RemainderCertified→ReplacementPrepared→ReplacementCommitted→Active`。CancelRequested/普通 cancel ack 都不转移旧潜量。只有证据同时证明旧命令今后不能执行、截至该终态全部历史成交已在累计量/完整事件前沿中覆盖，才计算 `remaining=L−F_all_revisions`。共同域以 family/version CAS 唯一锁定这份剩余分配；本地冻结新价修订并回传 receipt 后，公共域原子把已证不可能再执行的旧分配转到新 command revision，随后才可进入 P1 Dispatchable/MayHaveSent。没有终态累计完整性能力就等查询补齐；永远不能取得则此种改价不能完成，不能偷偷双活。

100/40/20 反例的结果因此确定：L=100，已收40但旧命令仍可执行60时，新独立价单可分配量为0。取消期间旧单再成20，最终可靠查询确认累计60且以后不可执行，则新价单最多40。先到 cancel ack、迟到20并不早释放；若查询累计60早已包含该迟到20，后来逐笔报只补细节不重加。旧命令发送不明时最多潜量继续保留，不得开替代单。

取消/改单拒绝使旧版本继续按其可核潜量有效；改价需求可以等待或由明确经营决定撤回，不能把拒绝当取消成功。新订单拒绝后该物理分配可按终态证据回收，重试仍同 family，不重测 L。取消发送前/发送后丢响应、终态证据提交后本地未提交、ReplacementCommitted 后 receipt 丢失、公共转移后发送前崩溃均按持久 family/revision/command/receipt 身份恢复；一个 family 只有一个未决剩余分配转移，不得恢复时再造第二替代 command。旧/new ack 乱序按命令族归位，不改当前价决定或原冻结框。

场所终态证据的能力范围必须明写：它要覆盖不可再执行和历史累计完整性，不只覆盖当前订单状态。后来的真实 bust/更正仍走 P4：在解释前封相关约束，按原 family 记事实，重核剩余预算；不自动恢复旧已取消单，也不自动补单。若外部更正推翻此前的终态/上界保证，记录实际超界并暂停，不把设计不变量冒充能控制场所违约的承诺。后续处理依已获退出/调整权限，原报永远不裁掉。

P7 是 IP-M02 的修订。所列场所能力均未在本轮验证；模型检查和故障试验必须逐步核 F+各潜量，而非只看最后净持仓或账户 Q。

## 7. RF-01 的实际继续路径与恢复

### R1：A 账不可读，全部共同约束仍可核

故障前共同责任域已经持久保存 A 的全部已授权责任集合、每个命令是否可能发送、不可复用许可、外部事实水位与有限责任证据；这不是从 A 当前余额即时查询才能拿到的缓存。A 账写者被隔离后不得新取 grant；所有场所新发送仍经过共同域，旧失控写者也不能越过 epoch 栅栏。

共同域记录 A 写者已隔离并封闭其新增申请代际后，批次不再等待 A 的 slot 结束消息。A 已获公共 Reserved/Dispatchable/MayHaveSent 项的全量责任已在故障界内覆盖；**仅存在 A 私账、尚未获得 grant 的 Prepared 不需要也不能声称被共同域枚举**：它没有发送能力，封闭代际后无法新增外效。在途 grant 申请与封闭按 P3 唯一顺序决定是否纳入上界。B 的新增若对其所在可核范围全部可准入，必须完成提交，不因 A 没有回执而等全员 barrier。若 A 的旧写者仍可能越栅栏发新命令，则上界前件已不成立，不能套用 R1。

故障后，P4 接纳 A 的 ack/fill/fee 时先原子 Recorded+Pending，再解释。可证明仍被 A 原最大责任覆盖并满足全部共同约束时，Resolve 保留原界且清本 token，不等 A 私账；记录 AwaitingBook 继续由 A 恢复后应用。需要扩界则先原子核新界，未知外部订单、超界更正或无法证明的规则变化保持关闭进入 R2。

**具体前后状态**：设公共毛额度帽 100，净名义帽 80（纯测试参数，非产品默认）；A 在已核合同/场所保证下可能承担的整个责任集合使毛额度最多 40、净方向量在 `[0,40]`，B 完好账已用 20 并申请加 10。两者在本测试坐标同方向，所有可能净量≤70；其他逐重、保证金/费用/结算约束也已在本例给齐有效证据。共同域无需读 A 账即可从 `Reserved(A≤40,B=20)` 变为 `Reserved(A≤40,B=30)`；B 完成本地 Committed、公共 Dispatchable 及发送边界，A 账仍不可读。此时毛≤70、净≤70，各自资金不互借。验收必须观察到 B 实际新提交记录，而不只是返回“允许”或 PartialView。

该算例只演示已知有界维度的提交路径；真正责任是向量/集合，不能用 40 一个数代替场所维度。若真实空头最大资金责任无界，不能应用这个算例。某项共同约束虽然非毛额度（如共享结算余额、币种、净风险、账户模式、费率、停牌权限）却不可核，同样必须暂停新增。

### R2：责任上界或任一共同约束不可核

P4 在第一次解释风险事实前已经持久 Pending 并封住受影响新增，解释后共同域把具体缺口写成 `Unverifiable(evidence_gap,affected_scope,frontier)`；不签发任何依赖它的新许可，也阻止尚未跨 MayHaveSent 的新增发送。已有外部回报继续接纳；取消/减责动作仅按批准权限和自身最坏责任评估，不因名称“减仓”绕过所有闸。UI 可继续读取可信历史/局部状态，不能恢复经济资格。

### R3：A 恢复，B 已继续经营

恢复器先取得新 A writer epoch；核检查点哈希、事件前缀、共同域 A grant/dispatch 状态、外部事实身份与水位。按原 decision/responsibility/receipt identity 重放 A 的未应用事实，核 A 自有账与全部未决；不能重跑 bars 重新发一轮订单。将共同域未决列表和 A 本地列表对照：公共 Reserved 无本地 commit 保留并查明；本地 commit 无公共发送许可则不发；外部已成未入账则应用一次；无主外部事实须先匹配。A 应用回执齐备后重建当前责任集合，经共同域原子替换旧上界，才恢复 A 的新增资格。B 的历史不回滚、不借给 A，不要求 B 停下来等 A 重放。

### R4：共同安全域/事实解释或传输/结构域/观察域故障

共同安全域不可用：规范 Capture 和所有依赖其许可的新增暂停；传输缓存可收字节但不是已规范接纳，不能凭最后余量分头下单。事实解释器不可用时 pending 留存；传输/源不可用时不能把“没回报”当没成交，保留最坏范围，源连续性/证据有效性不能证则相关新发送暂停。结构域故障：已提交有效状态仍可查，不能把旧证据无限期视作适用于未来新增；按结构/制度前件停止相应新判断。观察域故障：经济账不从 UI 回补状态；同源投影可重建，经济是否继续仅由其真实前件决定。

**恢复测试必须覆盖**：P1 五个持久边界、fill Recorded 未 Applied、Applied 回执未送公共域、cancel 与 fill 乱序、A 单账损坏、A 责任界失效、任一共同帽证据缺失、恢复中新 B 提交、旧 writer 复活。恢复前后逐重资金/筹码/成本/TStage/Voice/许可/外部效果计数逐项对拍，最后净头寸相同不够。

## 8. 同源快照、查询、变化、撤回、续接和回放

观察 Module 有 `open / snapshot / changes / explain / resume / catalog` 一组 Interface；HTTP、WebSocket 或其他传输都只是 Adapter，共享同一个 session handle 和 run/generation，不能订阅时另起默认实时核。调用者不协调内部事务版本。

### O1：一致切面与分页

每个权威提交带完整依赖引用：逐重 b 引用所消费 s、政策 p、公共 grant 及其所应用 fact；公共责任版本引用各相关回执；外部事实引用原命令/更正前报。观察器只能发布依赖闭包已经具备的版本组合。一个完整切面可包含某重“最新结构已到而经营尚未吸收”的真实状态，但必须同时携带其旧 consumed_s 和 pending 前沿；不能把旧决策声称为对新结构的决定。

快照 token 锁定 `cut_id, scope_manifest, catalog_revision, indexed_projection_revision`；所有分页都从该切面持久历史取，不能下一页读新头。关系端点和证据引用必须在切面内可解或显式列为范围外详情引用；结构已删除的端点不能遗留为有效边。对象、关系、状态、依据、使用关系都在范围清单中，不只统计 marker。完整性仅对所请求范围成立；缺某重就交 Partial/missing_scopes/last_trustworthy_cut，不声称整个系统当前完整。

索引从设计第一天就有：类型/级别/时间/重到对象，实体修订史，结构→所有经营消费反向表，责任→所有命令/fact/账回执，policy→所有受影响决定，knowledge_frontier→各域版本。索引是只读可重建派生，不能回写权威；构建水位不足则不交“完整查询”。

### O2：变化与撤回

每个观察 session stream 的持久批次包含单调 seq、base_cut、next_cut、batch_id、对象和边的增/改/替代/撤回、每项 before_revision/after_revision、原因/证据、获知前沿。一个批次原子应用至客户端范围状态；同 batch_id 重投忽略，缺 seq 或 base_cut 不符缓冲并请求缺口，不跳过。跨源顺序来自 cut 依赖，不冒充场所全局自然顺序。撤回不自动删除经济引用；变化包给 `affected_decision/responsibility` 查询路径。

前端用后端校验后的分类/字段渲染；页内折叠、级别过滤和图形抽稀仅影响显示，不修改完整结果。目录总能列出当前无实例的合法类、限制和证据状态；任何 ST/FG 都能通过列表/详情/关系/时间线访问。正式前端布局未设计，本候选给明确可达语义入口和消费验收，不声称页面已可用。

### O3：续接和两种历史语义

游标绑定 session/generation/scope/cut/stream_seq。断线恢复先校验同会话范围和保留边界；有历史则从 cursor 后连续回放，最终与 next_cut 快照逐字段相等；过期返回 `Gap{from,to,reason,new_snapshot_token}`，明确重建，不能静默接最新。旧代际消息即使 object_id 同名也拒绝安装；session 新建不会接管旧经济回报。

`AsKnown(frontier)` 仅消费在该接纳前沿已知的市场/结构更正、经营/政策、外部事实及其当时处理关系。分别保留 market_span、首次获知/确认前沿、received/applied 时间；后来的 revision 不覆盖过去。`RecomputedWithRevision(v)` 是另一个明确模式，绑定后来输入修订及规则，不混入当时决策史。首次部署前若没有历史接纳/政策/外效序列，则无法证明真实“当时可知”；可做注明假设的重算，不补造时间。

## 9. 历史、paper、live 同核与旧引擎终态

相同生产核从标准化输入推动结构、操作分解/定位、逐重经营、共同责任、执行计划、事实应用和观察；模式只替换真实变化的 Adapter：市场输入与时钟、执行反馈/场所协议、必要存储实现。它们不能带第二份买卖点或成本判定。历史与实时均按已裁结构源美股 tick；永续执行价差只入执行成本。历史原始序列顺序、时钟、政策/能力配置、模型/种子、数值/编译版本均绑定，双跑比较完整结构/关系/逐重账/计划/事实/观察；不能用共享错误的增量与全量互拍当独立真值。

历史模拟 Adapter 执行已裁严格穿越、开盘取优、GTC、不提前知道失效 expiry，以及限价/市价双滑点比较纪律；OHLC 内先高后低未知不能造路径。同 slot 市价+限价和反向多重仍有未裁模型语义，本候选如实留阻塞，候选顺序以显式测试输入验证协议闭合，不能把这个测试选择带入正式生产。paper Adapter 接受受控模拟反馈或经授权的模拟场所事实；live Adapter 接真实回报。某模式同核不表示其数据/制度/能力/权限已获证，模拟确定性不能证明场所成交或逐仓隔离。

## 11. 深模块检查、代价与未解决问题

| Module | 深度与删除测试 | 泄漏检查及代价 |
|---|---|---|
| 结构与操作读法 | `advance/read/locate/catalog` 隐藏整个构造、唯一判据、全分支/血缘、主动下钻；删除会让每重与UI各自实现结构 | 输入域/规则语义属于必要Interface；存储、塔缓存、扫描调度不得泄漏。全历史与全分类发布有真实空间/计算代价。 |
| 逐重经营账 | 一个 advance 隐藏Voice/阶段/量/成本/提交与恢复；删除则调用者协调完整资金史 | 不把 reserve/commit/send 暴露给策略；事务和私有账故障隔离实施复杂。 |
| 共同责任 | 一个 grant/resolve 内部 seam 隐藏所有共同约束、上界、转移托管与发送栅栏；删除就回到每重互查余额 | 不能让它复制成本/作信号仲裁；公共序列化点可能成吞吐瓶颈，保守上界会降低资本利用；本候选修订屏障让生产结构推进依赖该域，有限经营轮防饿死但吞吐/活性仍未证。 |
| 执行事实与投影 | 命令/fact seam 隐藏场所幂等、接纳、归属和reconcile；模拟/受控/真实Adapter是真实变化点 | 不能让Adapter看到中枢再推价格；场所无法幂等/回查就必须暴露不确定性，不能藏成成功。 |
| 同源观察 | 单会话隐藏闭包快照、分页、变化、撤回、续接与历史索引 | 前端无需版本拼接或分类重判；多域闭包和保留会耗存储并增加延迟。 |

没有额外 load/validate/save 三层 Module；它们属于各自权威内部实施。输入/执行 Adapter 有真实可替换角色；单纯转发原参数的 transport wrapper 不另算深 Module。系统总组织的复杂性不能用五个小 Interface 的数量掩盖，跨域协议和证明都是成本。
