### IP-H01：外部事实使责任界或共同约束失效后，尚无阻止陈旧公共许可的因果协议

严重度：H；状态：OPEN。关联 RF-01, FG-022, FG-024, FG-029, FG-032, AC-12。

证据：author/INDEPENDENT-DESIGN.md:160,163；author/INDEPENDENT-DESIGN.md:203,209；author/INDEPENDENT-DESIGN.md:230,249。

P4 允许原报先在独立事实域 Recorded；R1 随后更新责任证据，R2 的禁止新增则始于共同域写入 Unverifiable。结构撤回有 BeginRevision 在实际获知前封住 reserve 与 MayHaveSent，但责任界/共同约束失效的外部事实没有对应的前置栅栏、接纳水位检查或原子失效交接。最后发送时读取共同域的当前证据版本，并不证明另一独立域没有已经获知的失效事实。

可复核交错：

1. A 账不可读；共同域留有当时可核的有限责任界，B 自有权利与旧版本共同约束均足够。
2. 事实域接纳合法更正/bust、未知外部订单或费规证据，已可确定原责任界或一项适用共同约束不可核；原报已经 Recorded。
3. 向共同域通知延迟、丢失或处理器此时崩溃，共同域仍持旧 Valid 版本。
4. B 在这个窗口取得新 Reserved，或已有 Committed 的命令跨过 MayHaveSent；随后才写 Unverifiable。此时 RF-01 的暂停前件已经发生，却有新增许可/外效越过。

不能签署 RF-01 在异步外部事实更新期间的暂停保证；与单纯尚未实现存储不同，这是未闭合的两个权威域之间的先后关系。

修订须闭合：写明全部使责任界/约束改变的接纳生产者如何在首次解释/获知前或同一持久边界封住受影响准入；若采用接纳前沿与已核前沿，grant/MayHaveSent 必须原子证明没有未核输入或失效，并有域故障与重放恢复规则。允许选择其他能排除该交错的协议，但须保留真实 known 时间，不能事后改称才生效。

后续验证：在失效原报持久接纳、解释、共同域失效安装各边界注入崩溃/消息延迟。；分别让 B 申请 reserve 和已有许可尝试 MayHaveSent，失效获知后均不得新越过；此前已跨边界者保留在途责任。；不能对被保证仍覆盖的普通 fill 一律等待坏 A 私账，从而破坏 RF-01 健康继续路径。。

### IP-M02：部分成交后改价缺少跨旧新物理命令的冻结总量替换协议

严重度：M；状态：OPEN。关联 FG-027, FG-029, FE-03, AC-08。

证据：author/INDEPENDENT-DESIGN.md:27,39；author/INDEPENDENT-DESIGN.md:159,163；author/INDEPENDENT-DESIGN.md:213,228。

U2 和 FG-027 承诺同逻辑 key 改价而保持首次冻结量；P1 描述新 Prepared/Reserved/Committed，P6 描述取消/晚到 fill，但没有为同逻辑订单给原子 amend 能力合同或取消后替换状态机，也没有把每个物理命令的可能剩余量共同约束在这份冻结量内。唯一责任 ID、不可复用 grant 和共同毛帽都不能单独建立该逻辑量不变量。

可复核交错：

1. 逻辑订单首次冻结量为 100，原命令已成 40，旧命令仍可能执行余量 60。
2. 核心修订需要改价；实现按现有 P1 为新价命令提交剩余 60，同时对旧命令仅发 CancelRequested。
3. 旧命令晚到成交 20，新命令成交 60，最后累计 120。选择足够大的本重 Q、专属现金和共同帽，这一轨迹仍通过那些总额约束，却超过该逻辑订单冻结量。
4. 若直接复用同一 grant 为替换命令发送，则又缺少旧命令授权如何被撤销/拆分以及恢复如何辨别的状态。

当前文字没有排除双活命令导致逻辑目标超量，也没有给出 U2 所声明的部分成交后改价如何实际完成；不能靠最终将事实完整入账来恢复冻结量承诺。

修订须闭合：为逻辑订单和其物理命令族给出持久修订/替换关系与额度守恒：已确认成交加所有旧新命令可能执行量不得超过冻结许可量。选择具证的场所原子改单，或等待旧命令最终可核量后再发差额等具体路径，并写明取消确认缺口、晚到 fill、拒改单和每个崩溃窗口如何恢复；不替用户自定场所能力。
