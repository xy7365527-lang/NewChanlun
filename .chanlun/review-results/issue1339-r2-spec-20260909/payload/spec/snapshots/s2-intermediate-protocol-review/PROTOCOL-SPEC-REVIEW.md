## 技术判断与真实门

每域单写 SQLite WAL、独立进程、先持久对象后发布引用、短读固定切面与唯一 X 是可实现方向。SQLite 官方文档确认 WAL 的同机约束、跨库无集合原子性及 3.51.3 的 WAL-reset 修复；它也明确持续交叠读者可能使 checkpoint 饥饿，所以“读事务短”不能替代实际 WAL 管理与隔离证据。[SQLite WAL](https://sqlite.org/wal.html)

以下是具体反例驱动的实施验证项。它们已经被本稿的义务禁止，当前没有实现可据以判定失败，不能因为尚未跑过就统一上调为架构缺陷。它们也不能在拆票时从实施范围消失。

### PG-01：持久化、读者与空间隔离

反例：多个短读彼此交叠也可使 WAL checkpoint 一直无清空窗口；E 或经济查询积压可耗尽共享卷，或经济命令归档留在 S 关键空间。仅不同数据库文件/一个 budget 配置值不证明隔离。

必须取得：明确实际生效的域级空间约束、S 核验/历史分区预算、WAL/checkpoint/reader-gap 与归档策略，并在受测负载、慢读、E 本域写失败和存储预算触达时验证 S 正式提交、查询、撤回继续。不得将可控经济积压重新命名为共享硬件故障而免测。

名分：实施技术细化及进程级验收；已有 C08.7/C09.3–6 禁反压合同，不据此判当前 SPEC 违约。对应 AT-04 / AT-11 / AT-12。

### PG-02：S 有限服务

反例：若核验一次无限扫描整段历史、入队写占满单写者，或每条结构修订永不完成，FIFO 每点 1 仍无法产生真实稳定点。真实失效和无限过载则不满足持续合规前件。

必须取得：固定获准能力 profile 的证书/依赖有限规模、有限工作和存储容量，覆盖持续输入、长但有限队列、重复风暴、无新行情及失效一次终态；记录队列次序、实际核验、后续结构 Commit。

名分：实施能力与活性验收；非新增资金分配策略。对应 AT-12。

### PG-03：完整条件实例

反例：把场所实际要求在调用点有效的权限只编入 E-only，或把非单调更正当单整数水位，可能使旧资格在错误阶段通过。

必须取得：逐实际 policy/adapter 枚举闭合条件与权威阶段，漏项/源跳号/更正/过期/时钟不可核均测试；只能靠无有效性证明的远端读者准确 Unsupported，不能使用已采纳窗口放松剩余阶段义务。

名分：SPEC 承载合同已在；实例与真实能力验证未执行。对应 AT-08 / AT-15。

### PG-04：X 调用权与实际发送隔离

反例：SDK 自动重试或旧进程仍有直发凭据时，数据库 CAS 一次并不等于实际只尝试一次；提交 MayHaveCalled 后崩溃可留下真实零调用但无法安全重试的责任。

必须取得：检查最终调用链、并发同 ID、CAS 前后杀进程、旧 epoch 复活、旧凭据副本及后台发送；X 阶段条件必须约束同一受控调用，强幂等重投只有独立获准且实证后才开放。

名分：已有 C07/C09 合同要求；部署及场所验收门。对应 AT-09 / AT-15 / AT-16。

### PG-05：责任集合、Pending、P7

反例：先 cancel ack 后迟到 fill，或旧 Resolve 清掉新 token，或为释放 B 等待整批 A 回执，分别会低估潜量、重开旧资格或破坏 RF-01。

必须取得：按所有持久边界注入崩溃/乱序/重复，逐步比较 F+独立潜量；A 账不可读但旧界覆盖时 B 实际新 Committed；部分释放只用参与账收据，未定归属不暗分配。

名分：继承合同的独立模型与进程验收门；具体场所累计完整性仍需证据。对应 AT-07 / AT-08 / AT-10 / AT-13。

### PG-06：不可变切面与 AsKnown

反例：文件已写入缓存而对象引用先持久发布，或普通流回收连带删去命令去重身份，或 E 恢复后将晚到应用写进旧 cut，都会破坏持久性或历史语义。

必须取得：对象内容与目录持久化先于 S 引用提交，crash/reopen 下无悬空已发布引用；固定分页/delta 重建一致；归档查询覆盖身份有效代际且不可读不建新 ID；双跑按实际依赖向量比对。

名分：既有条款的存储/恢复实现与验收门。对应 AT-04 / AT-11 / AT-14。
