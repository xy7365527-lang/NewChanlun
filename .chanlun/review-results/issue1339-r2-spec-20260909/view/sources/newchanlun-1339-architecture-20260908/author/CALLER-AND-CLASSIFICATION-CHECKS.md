# 完全分类与后端观察：共同检查场景

这些检查把用户最新硬要求落实到可审阅结果，不选择具体架构，也不声明当前代码已经实现。基准是第一阶段已确认范围与COMPLETE-CLASSIFICATION-REQUIREMENT.md；44个ST是导航项，实际分类分支以CLASSIFICATION-CATALOG为准。

## C-01：列出可处理的全部分类

调用者要先知道：这个规则版本对哪些对象作什么分类，全部类别有哪些，输入域和边界是什么，哪些类别组合合法。后端须给可核查的完整分类目录及能力状态，前端能遍历目录抵达每类的说明和实际对象；当前输入没有某类实例，不应让该类别从能力目录中消失。

验收分别核三件：语义目录是否全、实现是否覆盖全、观察是否传出全。只把enum序列化不证明判据完备；只把已有样例画全不证明输出目录完备。目录中尚未裁定的端点必须写明来源与所阻塞的唯一归类，不能默填Other或把该输入从良构域悄悄删去。

## C-02：检查某个当前走势

调用者指定标的、数据/规则版本、逻辑会话、观察级别和获知前沿，查看全部适用对象。后端对每个良构且输入齐备的分类域，必须给恰好一个合法分类结果及成立依据；正交轴按其合法组合共同返回。形成、完成、转折、知识不足、用途与有效性分别保留其定义位置。

验收取每个叶分支的见证输入、每个相邻判据的等号/端点、每个明确不可达组合及缺输入状态。需要对全输入域的不漏不重提供可复核依据：形式化证明、可检查的逻辑分区论证，或有明确有限域的穷举。有限样例和属性测试只证明其执行射程，不能冒充无穷输入域的完备性证明。跨级同一判断另用同输入同输出执行锁。

## C-03：追问刚发生的小转大或中枢扩张

调用者从变化列表进入事件详情，能看到它属于哪个完整分类分支、涉及哪些对象/级别、原状态和后状态、具体判据、结构组成、发生区间与首次获知/确认时点。必要条件成立、实际发生和后续确认分别按正本返回；小转大不能由下钻失败补出。中枢扩张须把关系判据与实际高级构造分开：已构造时给高级对象和血缘；尚未构造时给所缺组成或依据，不能把一个升级布尔值冒称为高级结构已成立。

验收遍历目录内的合法状态转换及禁止转换，对所有相关关系验证反向追溯和版本引用。多个可并存事件应一起可见；使用优先级仅保留一个属于漏输出。定义不能从静态快照唯一推出的历史转换不得伪造为曾发生事件。

## C-04：断线后继续看，或回到当时可知的历史

调用者拿已有游标续接同一逻辑会话。能续接时返回不漏不重的变化/撤回；超出保留范围时明确缺口并交可恢复的一致快照。重切、修订或更换输入版本后，旧事实有明确替代/失效关系，晚到旧会话消息不能改新会话。

验收同时打开两个会话，制造断线、重复和乱序、结构重切和后知修订。按当时可知回放不能把后来确认提前；最终重算是另一种明示语义。完整切面可以由版本组合表达，但要说明涵盖哪些结构对象和重，缺失部分必须可见。

## C-05：从结构结果追到各重实际行为

调用者从同一结构事实查看哪些重消费了它、各自作了什么判断、哪些请求获准或受限、什么真正成交、如何改变成本/本金/阶段，以及还有哪些未结责任。前端只读，不能用显示的标签自行补判准入。结构结果撤回不删除真实成交。

验收包含原有11FE和RF-01四场景。故障重的最大责任与全部共同约束可信时，完好重必须完成新提交；任一相关约束失去可核实性则暂停新增。观察能够展示PartialView本身，不证明经济路径满足该故障继续要求。

## 不同方案统一报告方式

每个场景分别报告：现有设计的具体责任及引用、调用者能拿到什么、何处需补协议或改变组织、验证如何执行、仍缺什么。语义分类完备、实现行为正确、后端发布完整、前端消费完整四层各有证据，不能以其中一层替代其他层。
