# #1339 本轮已确认的需求决定

## RF-01 单重账目故障时其他重有条件继续新增操作

状态：用户已确认。用户原答：“要求：满足这些条件时，其他重必须能继续”。

单个重的账目发生故障时，若其他重的账目完好，且故障重可能占用的资金上限与共同约束仍可核实，其他重必须能继续新增操作。共同约束也无法核实时暂停新增操作。

这新增一条可用性要求，不预选软件组织。后续方案必须逐项说明其前提如何证明及失效后如何停止新增操作。

验收草案：

- 令重甲的权威账目不可用；保留甲仍可信的最大资金责任，令重乙自身账目与全部适用的既有共同约束可核实；乙新的合法请求必须能够完成新增操作所需的提交。
- 随后使甲的最大资金责任无法核实；不得继续批准新增操作，保留未结责任并等待恢复。
- 另设独立反例：甲的最大资金责任仍可信，但某项既有共同约束无法核实；同样暂停新增操作。这里不增加新的共同约束或数值政策。
- 甲恢复并对账时，不覆盖乙已发生的动作，甲的迟到成交、费用与原责任归属保持。

观察需求：各重账目是否可信以及可信前沿；故障重资金责任上界及依据；共同约束版本和可核实状态；各重继续或等待的具体原因；恢复后对账与责任归属。

边界：没有选定A2或任何存储/提交组织；没有批准资金复用、实际交易或逐腿出口切换；没有从内部故障隔离推定场所物理隔离；没有另加固定恢复时延或可用性百分比。
