## 问题陈述

用户需要一份真实贯通的严格多重赋格程序：同一份结构判断供各操作级别的重使用，各重保有专属筹码、Voice、阶段与毛账，最后按场所能力形成物理订单。用户也需要从前端看到后端完整算出的结构、并存关系、修订和撤回，并追到各重实际消费的依据。现有独立结构出口、简化回放和交易脚本无法凭各自能跑就证明这条完整链成立。

当前已核的断点包括六态未进入所查生产装配、中枢关系在信号增量中丢失、逐点六位买卖点缺少每级 LevelView 的生产桥；所查执行路径还有调用前持久占有、恢复接线及旧直发入口的缺口。这些是有界静态结果，既不是全仓不存在相关能力的结论，也不是本轮已修好的功能。

单重故障不能无条件拖停其他重；公共经济故障也不能使健康的结构域停止正式产出。完整回放、paper/live 及旧程序迁移必须共同遵守这些规则，不能在某个模式下切换为简化判据。

## 解决方案

采用已采纳的 R2：结构域 S 独立产生正式结构，各重账 Bᵢ 独立经营，经济安全域 E 保存共同责任及财务放行，唯一执行入口 X 消费精确命令的一次调用权。前端只读这些权威结果。S 不等待 E、经营轮、经济回执或全局总览，跨域视图明确标出各自实际前沿。

财务交付 E-Release 之后，后来获知的经济风险仍可能来不及阻止这份已交付精确命令的首次调用；最大责任持续保留。这是用户已采纳的窗口。适用条件仍须在各自规定的阶段真实核验；普通准备没有此例外。S-Execute 之后至真实调用之间的在途窗口同样显式保留。

本 SPEC 提出具体技术承载与实施分段，交付能力覆盖 #1323 全部六项终点。未裁语义、资金政策及场所能力逐项作为依赖门保留；不得通过长期返回未知、只做接口或削去某一阶段完成整图。

## 实施决定

### C01 范围、权威与完成门

1. 完成范围是 #1323 六项 Destination，#1339 只是本总单的需求与架构来源。结构教义以已裁正本及其原文/Lean 权威边界为准；R2 不重裁数学语义。R2 与旧 R1 的关系严格按 CR-01–20，只继承其中明确保留的条款，不把旧共轮、单个 MayHaveSent 或共同故障停结构接回。
2. 全分类承接 44 ST、62 CC 和 10 LC；经营承接 35 FG、11 FE；观察承接 20 OB；工程状态承接 16 ES 并应用 R2 替代；故障及协议承接 RF-01、RF-02、14 RA 和独评 6 I。计数仅表示目录覆盖规模，不能作状态总数或已运行证明。
3. 每次发布绑定规则、目录、程序、schema、数值配置、输入来源和政策版本。任何未支持的适用域都列出精确对象、字段、条件与原因；不默默降级到另一引擎或判据。范围内未实现、未证或未决的必需项未清，整体验收不得通过。
4. 本 SPEC 的技术提案列在 C09；批准本稿仅批准写明的方案和依赖边界。不得据此推断真实账户、投入金额、资金分配、退出权限、main 合入或未指定的场所已经获批。

### C02 标准输入与唯一结构核

1. 标准输入包含 source namespace/epoch、instrument、原始事件身份和修订、原始坐标、received_at、逻辑输入顺序、替代关系及来源证据。结构源遵守已裁美股 tick 边界；时间聚合、重采样或执行市场价格不得偷偷改变结构级别语义。
2. 一条纵向主塔只产生一份 Classification。每一级使用相同判定，级别差异只通过真实输入表达。唯一生产 owner 实际执行完整构造；各重、查询层、Python 外壳和前端不得重判。
3. S 接纳自己的输入，在解释可能改变现有判定的输入前持久 BeginStructureRevision，关闭相关范围条件执行门；计算之后原子 CommitStructureRevision，公布对象、分类、关系、见证和变化。计算时的 first_known 不能改成后来的经济收件时间。
4. 良构性、计算状态、知识状态、有效性与市场分类分轴。空输入、数据缺口、进行中、N/A、已撤回、未支持各有准确结果。合法原始结构到良构域的投影必须验证，不能靠先过滤反例获得分区完备。
5. 结构自身提交成功即可发布和查询；没有 E/Bᵢ/X 时仍能继续新的正式结果、撤回和替代。S 自身存储损坏另按结构故障处理，不声称此时仍可正式推进。

### C03 完全分类、真实构造与证明桥

1. 分类目录为每个 CC 固定对象类型、适用域 D、判据或公式、边界、结果型、来源、构造见证及变化规则。先区分真正互斥判断、角色字段、集合关系、公式构造和描述观察：恰一分支只作用于明示对象域上的真正互斥判断；多角色、关系和同时成立事实须全部输出，不能用 first-match 擦除。例如同一中枢的核心、外缘和内部极值应同时存在，坐标的组锚和极值根也不能只能二选一。
2. 对真正分类的静态分区证明、各类真实输入投影、程序与定义等价、合法联合构造及转换不变量分别验收。角色/集合验全部必需成员、身份/引用和联合约束；公式验输入域、计算定义及边界，描述观察验来源与适用限度，不强造互斥档。证明按规则/程序版本复用；每次输入仍实际计算全部适用对象和条目，不以静态表或“已算”收据替代。
3. 覆盖包含/分型/笔/线段、中枢核心和外缘、延伸/扩展/新生、高级构造、完成三类型、六态及位置三态、力度/背驰、小转大、全部买卖点、区间套、分解与级别递归。每个结果有对象身份、适用域、状态、证据、规则版本和可知时点。
4. 小转大必要条件与实际已发生转折分开；扩展关系与高级对象已构造分开；六位逐点 BSP 与每级 LevelView 分开。64 个编码中至多 27 个约束允许签名不等于已证 27 个可构造，验收必须有实际构造或不可达证明。

### C05 持久重、Voice、阶段与权利

1. 重由标的、操作级别、专属筹码刻画并跨 Voice 持续。TStage、目标、成本史和毛账每重独立；Voice 的开局依据与身份不可改写，退出后旧回报仍归原责任。
2. 重内一次本地状态跃迁合成各结构层动作并验证单向、不穿零和已定范围。重间相反方向同时保留，不作方向仲裁；物理净零也不能删除两重经营事实。
3. 固定 Q、实际持量、原始义务、增长权益、首次冻结订单量分别记账。d=0 基线与 d≥1 短差分开；回本前同量回补、动作量既有形状及有效域保留，不填未批高档参数。
4. 成本只由真实现金流、成交、费用及更正改变；价格估值变化不能改成本。亏损往返和迟到费用如实入账，手续费、funding、borrow 的来源、计量坐标、归属和未分配项分别可追踪。
5. 降成本、回本金、允许方向的赚股阶段都在范围内。线性空头无赚股第三相且债务仍在。本金细义、跨零回退、分母零和固定 Q 到增长权利的会计桥由具名政策门约束，不能靠虚拟成本为零推断物理风险为零。
6. 容量决定规模，频率决定是否开重；原始买卖计数、样本、窗口和稀疏原因保留。行情换档与资金溢出换档两个事件族分别保留触发证据、原重持续经营和新重承接。
7. 权利转移按固定 transfer 身份完成源锁定、共同托管、源扣出、目标待激活、双方回执、唯一激活。目标未确认不准源超时退款；尾责不暗迁；多接收者逐份记账。

### C06 共同责任、外部事实与分配

1. 每重责任集合覆盖持仓、已承诺、未知发送、部分成交余量、费用、强平及更正潜量。每个适用共同约束对覆盖真实可能状态的组合成立；净抵消不产生可复用资金。
2. 责任增加先在 E 持久保留，再允许对应本地和外部生效；减少须具备该责任不可再执行/累计完整性的证据及其参与账的持久应用回执。回执集合仅含实际关联账，不扩大为全批次或所有重。
3. 单重 A 账坏而 A 最大可能责任及全部共同约束可核时，健康 B 必须能新 Committed。A 的普通回报已被旧责任包含时，E 可保持该责任并核实清除对应 Pending，不等待 A Applied。共同约束不可核则暂停受影响新增，不把初始保证金当最大损失。
4. 规范外部接纳先将原报和保守受影响范围的 Pending 同事务持久写入，再解释风险语义。无法认出具体责任时封闭相应账户范围；范围不可信则扩大到全部可能关联范围。任何风险解释旁路都不能先使用旧资格。
5. Resolve 只删除其证据覆盖的 token；连续 Capture 的后一个 Pending 不被前一个清掉。Open 由全部相关 Pending、证据缺口、源连续性、时效与规则共同推导，不恢复旧布尔缓存。
6. fill/reject/cancel/fee/bust、手动或其他程序订单、账户差异、行情估值/汇率、保证金/权限/时钟变化均进入相应闭包。传输缓存不是生产 Recorded；日志失败后不能靠缓存继续新放行。
7. 同事实/分配 ID 与重 ID 同内容只应用一次，异内容冲突；累计与逐笔报使用同一规范化合同。缺来源身份或无法区别同形事实时保留冲突，不能按内容去重误吞真实成交。更正按前件因果应用，账实快照不能直接覆写私账。
8. 同 slot 完整请求集使用可证输入水位关闭，失效申请者代际与许可同序。全部请求可共同满足约束时一并保留；资源不足、配对、费用归属或插队缺政策时等待具名决议。S 本地核验 FIFO 不得成为资金分配政策。

### C07 R2 精确交付、调用占有与订单生命史

1. 本地 Prepared、公共 Reserved、本地 Committed 和 Dispatchable 仅推进财务准备。E-Release 在同一安全事务核全部财务条件、Pending、证据及责任；命令的逻辑族、冻结量、物理修订、投影、目标 X/epoch、完整条件清单必须已固定。
2. ReleasedExact 紧贴真实精确交付，不能先批量签候选再等待政策或选择 Voice/方向/数量。每个条件记录 ID、权威、依赖及失效源、检查阶段、证据覆盖、核验能力和失败结果；漏一项则 Unsupported，不能 Release 或执行。
3. E-only 条件须逐项证明批准语义只要求交付点成立且后续责任已覆盖；必须在 S 或 X 调用阶段成立的条件不能降级成历史快照。共同市场证书带来源 namespace/epoch、事件与修订、集合或规范前缀、替代关系和实际依赖，不能比较不相干整数游标。
4. S 对已交付固定命令在本地稳定点完成一次条件核验。引用仍有效而全局结构号较旧不是自动失效；撤回、替代、缺依赖、过期或不可核则持久最终 Denied/Aborted。已有 ExecuteCommitted 只返回原收据，不铸第二份资格。
5. X 持久 OwnAttempt 以命令唯一身份和内容绑定，从 Ready 原子变为 MayHaveCalled；只有本次首次成功者可尝试一次场所调用。相同 ID 不因换 epoch/计划/证书重建，重复、并发与恢复仅查询旧状态。
6. MayHaveCalled 在真实调用前持久提交。提交后崩溃，即使可能尚未真正调用，也保留最大责任，不自动重发。同 ID 重投仅在另有获准且已实证的场所强幂等合同下开放；本 SPEC 不提供通用网络恰一次承诺。
7. 财务状态、S 权威 Undecided/终态、X NoRecord/Ready/MayHaveCalled/Observed 分轴；观察 Unknown/Unavailable 另携 last_known、权威域及 query_frontier。没有记录、超时或未见回报不能证明未发送或释放责任。
8. 逻辑订单首次量 L 冻结，改价不重测 L。始终保持已确定累计执行 F 加各独立可成交分配的最大未计潜量不超过 L。原子 amend 仅在真实累计上限/版本互斥合同成立时共用一份额度；否则等待旧单不可再执行且历史累计完整，再以族/版本 CAS 唯一转移剩余量。
9. 固定测试例 L=100、已收 40、旧单仍可成 60 时新独立价单额度为 0；取消中再成 20，累计 60 且终态完整后新单最多 40。该数值是测试单位，不是资金默认。cancel ack、replace 名称、maker/ALO 标签均不能替代相应能力证明。
10. 结构撤回后保留已在途和真实成交；查询、取消及退出各有独立权限与前件。旧框终止新经营不终止尾账；业务退出和责任退休分开。未来更正超出原覆盖时如实记录并封受影响新增，不裁掉原报凑不变量。

### C08 正式观察、前端与当时可知历史

1. 结构目录即使某类当前无实例也可访问；每类实例均能从前端导航到属性、并存关系、证据与修订。后端提供所有结果，前端负责显示和筛选，不补判结构或计算资金资格。
2. 正式结构快照固定 session/generation、structure_cut、catalog_revision、scope 和 index_frontier。分页不跨切面，结构 delta 带 base/next、持久序号和原子批次；恢复续接与同 cut 快照逐字段相等，缺口显式 Gap，旧代际明确拒收。
3. 结构来源/父子/修订索引随 S 提交。跨域消费反向索引另带经济水位，不阻断结构发布、撤回或结构查询。
4. 跨域总览携各权威域前沿、consumed_structure、Pending、缺项及可信旧 cut。结构可正式完整而经营总览仍不完整，两者分别显示。禁止用单一“部分”标签掩盖后端漏算。
5. 前端逐级、逐对象、逐重只读联查：结构形成/确认/撤回、操作候选与选中失败、Voice/阶段/成本、订单投影、部分成交、责任和尾账；真实事实、知识、有效性及准入结果不可混为一个颜色。
6. AsKnown 使用实际 S/E/B/X 记录和依赖向量；恢复的晚到应用不能回填为故障当时已处理。RecomputedWithRevision 独立命名并绑定输入/规则，不冒充当时可知。
7. 慢客户端只能失去本次会话租约或收到 Gap；不得持有数据库长读事务等所有消费者确认。结构流的保留/回收不等待经济 ack；已交付命令的不可复活身份与结果单独安全保留。

### C09 本稿提出的技术承载、调度与恢复

以下是待本 SPEC 批准的工程方案；不宣称已安装、已测或已有性能数据。

1. 首个实现采用同一宿主上的独立进程：S、E、X 和各 Bᵢ 分别拥有独立持久域；前端查询外壳为只读进程。核心判断和经营 reducer 采用 Rust，现有 Python/NT 外壳仅承担模式输入、协议与展示适配。进程间走带版本和身份的本地消息协议，消息到达不等于持久提交。无需把每个结构级别拆成进程。
2. 每个域一份独立 SQLite 数据库和 WAL，由该域单写者进行有限事务；不使用 ATTACH 跨域原子提交，不以共享连接或统一事务管理器串起 S/E/B。所有权威提交采用 WAL + synchronous=FULL，macOS 开启 fullfsync；锁/持久化/文件系统前件启动时验证，不满足则拒绝相应写入。SQLite 运行版本必须包含官方 WAL-reset 修复（3.51.3 及后续，或有明确修复证据的回移版本），并锁定实际依赖版本。官方说明 WAL 不用于网络文件系统且跨库不提供集合原子性；这些约束决定本提案的同机边界。[SQLite WAL](https://sqlite.org/wal.html)、[同步设置](https://sqlite.org/pragma.html#pragma_synchronous)。
3. 一域损坏、阻塞或重启的试验只影响该域数据库及进程；S/E/B 之间不共享应用级锁、读写事务或故障恢复闸。共享宿主、物理磁盘或系统整体故障仍可能同时影响各域，首版不承诺跨机器高可用或磁盘灾难隔离；不能把这种整体故障用作 RF-01/RF-02 应测局部故障的替代。
4. S 的长期历史使用内容寻址的不可变批次对象和版本索引；先持久写完整对象，再由同一 S 事务发布可达引用，崩溃留下的不可达对象可以回收。发布读数从短事务取得固定 cut 的不可变引用，分页不持有写事务或跨请求读事务。持久 delta 按独立保留策略存储，落后消费者收到 Gap 并从指定 cut 重建。
5. S 条件请求按本地持久接纳序 FIFO 排队；每次结构 Commit 后、下一 Begin 前，如队列非空恰核验一项，然后让下一结构输入推进。无结构输入时仍逐项有限服务；新请求不能插到既有请求前。核验只读有限本地证书与 S 数据，不做 E/RPC/场所调用；条件不成立一次最终拒绝，不等待未来行情。该配额 1 是核验调度方案，不决定财务分配和物理订单先后。
6. 每个已交付命令在 S 队列中最多一份持久就绪身份，重复交付不增加排队项或调用权。普通 busy 不拒绝，已有项在有限本地服务下推进；S 本地存储失败则准确保留交付未知和责任，恢复按原 ID 查询，不另造 Release。部署容量依据获准在途集合、证书规模和实测负载配置，核验队列和长期历史分配独立的存储预算，不能让经济订阅断线积压结构关键存储。本提案不新增发送前的跨域容量预留/租约协议，也不承诺无限过载时活性；受测有效域内的 busy、重复包和容量处理不得造成健康持续合规请求永久得不到核验。
7. S/E/B 的写事务核数据库持久 writer_epoch；事务写入与 epoch 更替同序。X 是唯一持有场所写凭据并执行网络请求的进程；其他域和旧脚本在获准部署中无该凭据。X 的适配器在 X 内部受控调用，不能委托另一个仍有直发权的异步后台；SDK 对写请求的隐式重试、后台提交及恢复重投必须逐层核实并纳入一次调用合同，未能禁用或证明其幂等能力时该 adapter 不得发送。
8. 首版 X 不自动跨主机接管。重启/换代先由部署监督器确认旧进程及发送子进程已退出，并取得持久发送身份和排他进程锁，再核原 MayHaveCalled/在途记录；无法证实旧发送者隔离时不开新发送。锁或 epoch 本身不取消已发网络请求，其责任继续保留。旧凭据副本、旧启动脚本或另一 OS 身份可绕过 X 的部署验收失败，须先撤销旧发送权或更换限定凭据，相关实际外部动作另按权限执行。
9. E 重启先恢复 Recorded/Pending、证据及源前沿、责任集合、Released 和对应 S/X 状态，不能从旧 Open 恢复。B 恢复重放原归属应用，不从场所净仓重建成本。S 恢复未完成修订时保持相应条件门关闭，自己的恢复不等待 E。
10. 不可复活命令身份、内容摘要、判定和一次调用占有记录为长期审计事实；可迁往只读分段归档但查询必须覆盖全部有效代际，归档不可读不得把历史 ID 当新 ID。回收普通流游标不回收命令去重依据。
11. 版本升级先离线验证 schema/原始事实/责任 crosswalk，发布新 writer_epoch 后旧写者不得再写。回退保留新外效和尾责；旧程序不能理解新责任格式时，只允当前受控收尾路径接管，不删除日志后恢复旧交易。

### 复用、独立性与有效域

现有组件测试仅作先例，按[测试缝附件](inputs/TEST-SEAMS.md)明确其实际覆盖后复用：已有回放稳定排序和首分歧报告、六态端点例、候选修订/撤回例、LevelView 持久重开、HTTP/WS 客户端以及逐重毛账算式。现有对拍仅信号面硬断言、PASS 可含 inconclusive、同进程第二实例恢复、忽略测试或缺依赖跳过，都不能计作本 SPEC 通过。

新增一个从正式 launcher 启动的完整会话测试夹具承载上述外部行为，使用两个独立新进程双跑及真正杀进程/重启。结构、状态、账本/责任和外效各面差异均硬判，不继承旧 expected/advisory 规则掩盖差异；样例必须实际产生其待测对象、动作和回报，不能以空域通过。具体样例数量服务于行为覆盖，不成为产品最低重数。形式分区/投影与协议有界模型是相应独立 oracle，不能全由生产 reducer 自证。构造用例覆盖每个声称合法的分支/转换，未构造分支明确失败，不靠“跑了很多历史数据”证明穷尽。

故障注入覆盖持久提交前后、回报先后、丢包、重复、重启、writer 换代、账不可读和局部存储失败。运行报告保存输入/schema/构建/政策/能力 hash、实际负载、故障与调度序列、完整输出、未执行项以及独评绑定面。文档枚举、模型运行、进程级故障、UI、场所能力分别报告，不相互冒充。
