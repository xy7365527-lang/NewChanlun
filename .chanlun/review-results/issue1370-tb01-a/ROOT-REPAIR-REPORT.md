## 持久顺序

独评 DUR-M02 确认：已发布票面 AC4、SPEC C09.4 与接口合同要求完整批次先持久可读，再发布可达引用。旧实现在一个事务中插入批次并更新结构根，虽然原子，但不存在所要求的中间持久阶段。

现增加 `persist_batch_before_publish`：先核本 attempt 的 epoch、Begin 身份和已发布 generation；以独立有限事务持久完整 batch，核内容地址、实际字节和长度，提交成功后才进入结构发布事务。已有同 ID 而字节不符时拒绝，不能覆写。后一个事务复核同一所有权、完整批次与当前输入前沿，并原子更新对象、关系、修订和索引根。

前沿正常变化仍条件取消本 attempt。未知中断不自动清 Begin；失败可以保留未引用批次，不将删批次或 reset 当恢复。真杀恢复、历史修订、Delta 和回收仍由 B/C 及其明确下游承接，不能用本修复替代其验收。

DUR-L01 同时修正：取消函数返回实际是否释放，保护性跳过时不再输出“已释放”。单测直接核另一 token/epoch/generation/state 下零清理，以及重复取消返回 false。

## 精确读取与错误边界

独评 R4 的三项 M 均有具体反例：Python 将 REAL/BLOB 用 `str()` 包装为成功整数；嵌套整数允许 float/null/bool；Rust CLI 将七处坏 JSON 替换为空数组/对象并成功返回。

现明确投影字段只接受持久 i64 整数，外发为规范十进制字符串；Python 与 Rust 均拒绝浮点、布尔、文本、越界及未声明空值。只有 observation 的可空窗口保留 null。JSON 列必须是文本及声明的数组/对象，解析失败沿原错误边界返回；Rust meta 行错误也不再被丢弃为缺项。内部计算、原始身份、规范批次和对象哈希的整数表示保持原样。

浏览器比较列明确显示 `cur > prev` / `cur < prev`，消除只显示符号时的操作数方向歧义；未增加价格重判。
