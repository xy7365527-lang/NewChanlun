# #1371 R13–R14 实现说明

R13修复三项自动评审发现。源坐标须为规范非负精确整数，落在i64与当前平台usize的共同域，保留大于2^53与稀疏坐标。一个S计算序中的同一坐标只能归一个业务身份，该身份多个合法revision继续共享原坐标；非法输入使接纳事务回滚，排序/见证映射不再用0或-1兜底。

四类发布索引的六个代字段由Rust与Python共享的同义检查核为1..当前发布代；撤回代额外允许NULL。检查全表，包括在所有历史cut外的未来活动/已撤回对象，不以查询过滤隐藏损坏。初始cut-0无发布索引，合法待发布原始事实与未Commit批次仍可保留。

writer epoch的持久值、配置值和恢复目标使用同一规范非负i64解析。坏持久值为StorageUnavailable，坏配置为InvalidDomain，合法但过时代际仍StaleWriter，恢复仍须严格递增；没有浮点转换或相等文本自授权。

R13独评又发现：仅advance检查存量源坐标，不能满足AC7对接纳/恢复的停写要求。R14将全体已接纳raw_events（含未发布部分）的坐标与双向身份归属检查置于所有结构读写的共同根门。Rust根门返回已校验原始向量，advance复用同一Begin事务读集，不再重复取数；结构解释仍在持久Begin之后。Python相同门覆盖当前/AsKnown结构读；既有/api/meta仍是原始meta诊断入口，不宣称它证明结构健康。

对三轮原件各按其版本解释：750f的自动评审反例、b9的部分修复与AC7打回、6189的共享门增量。报告不改写旧失败，也不把新二进制称为旧二进制同字节。

本地验证包含46项正式结构会话测试、9组双端完整性回归（71次CLI、37次Python读取，27个预期Python拒绝）、45项R13历史运行与新增两轮红灯负控。浏览器产品字节与R12相同，10项消费者函数回归复用R13执行记录，不重复宣称新GUI运行；真实强杀与独立补充以REVIEW原件的版本绑定为准。
