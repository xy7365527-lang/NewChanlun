### Q1　#1394 链与 E.Capture/Resolve → B.ApplyAllocation 是否在同一正式会话入口下接通

**结论：没有接通。** 两套操作由同一 owner 二进制服务，但现有正式入口运行（C6a、C7a）的 manifest 都不带 `finance`，FIN 处于关闭状态。两链唯一的同跑是进程内单元测试 `c4a_fin1_*`：它没有 CommitDecision，Reserve 走 `persist` 直调；被 Apply 的 fill（alpha）与被 Prepare 的决定（beta）也不是同一重。

证据：

- **同一二进制同时分派两类操作**，见 `rust/src/economic_session/service.rs:1419-1455`：
  - E 处理 `ChongAdvance`、`ImportResponsibility | Reserve | CloseApplicants`（`finance::write_with_ingress`）、`CaptureExternal`、`ResolveEvidence`。
  - B 处理 `PrepareDecision | CommitDecision | AbortDecision`、`ApplyAllocation`、`BindVoice`。
  - CLI 入口在 `service.rs:1477`；`e_economic_session` 与 `b_chong_session` 都调 `economic_session::cli(bool)`（`rust/src/bin/*.rs:3`）。
- **Resolve 已按 FIN 责任界核验**：`tb03c_e.rs:198` 调 `finance::covered_pending`。若图像带 `finance`，`tb03c_e.rs:200-210` 会再用「已保留责任的 `source.covered_facts`」核一遍。所以合链语义已就位，缺的只是一条贯通的运行。
- **C6a 驱动** `s_session/tests/tb03c_query_runtime.py`：
  - 只发 CaptureExternal / ResolveEvidence / ApplyAllocation（958–974、1228–1248）以及 ReadView / Watch / HTTP。
  - 信封为 `economic-session/1`（629）。
  - SEED manifest 是 `economic-manifest/1` + `book_revision: tb03c-book/1`，没有 `finance` 键。
  - 输入被 `INPUT_HASHES`（59）冻结，runner `.github/scripts/run-1406-c6a.py:754-764` 还要求「相对 REVIEWED_SOURCE 的差异 ⊆ CI_FILES」。
- **C7a 驱动** `s_session/tests/tb03c_runtime.py`：只有 WE5，没有 finance，故障点在 step-014 Resolve。
- **#1394 的正式驱动** `s_session/tests/tb03b_runtime.py`：真实 `s_structure_session`（115、150）+ tb03b-finance/1，经 ChongAdvance 推进，不发 TB03C 操作。
- **唯一的合链测试** `finance_tests.rs:1114-1217`：
  - 流程：`PrepareDecision beta` → Capture / Resolve / Reserve 两种顺序 → restart → `ApplyAllocation` 作用于 **alpha**（1193–1194）。
  - Reserve 用 `persist` 直调（1098–1105）。
  - 没有 CommitDecision，也不过 socket。
- **command_id 尚未与决定绑定**：`tb03c_allocation.rs` 只在 97/104 行要求 `command_id` 字段存在，在 349 行复制。

**AC1 的最小接线**：

1. **S1**：进程内同一重的 Prepare → Reserve → Commit → Capture → Resolve → Apply。生产码零改动。
2. **S5**：同序列走正式 socket，再加 Q 公共 HTTP 读取。

「fill 必须属于某个已 Committed 的 grant」属新语义（真实 X 调用后的回报与责任下降，票面写明归 TB04-F）。本片不应默认补上，如要纳入需根裁定。

**可运行验证**：
