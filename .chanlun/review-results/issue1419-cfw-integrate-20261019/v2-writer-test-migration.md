## 需主控确认的偏离

裁定设想「约 85 处 v2 写入测试改只读断言或迁 S3」。实测 v2 写函数（init/accept/advance/recover_core）**仍是 S3 测试的种子与差分 oracle**：`generation.rs` 的 `OracleDb`（`oracle_historical_revision_parity`）、`aux_index.rs`、`source_audit.rs`、`financial_session_tests.rs`、`content_producer.rs` 的 `tb02a_facts::build` 对拍都靠它。删去或改写这些写者行为测试，等于撤掉 oracle 自身的保真锁。故本清单做法：

1. 生产入口全拒（已落），核心写函数只在测试可达（`#[cfg_attr(not(test), allow(dead_code))]`）；
2. 原测试**不删**，重新定性为「测试种子/oracle 保真锁」，每行给出 S3 侧承接或候选；
3. 「候选」= 按主题检索到的 S3 测试，**未逐条核读确认断言同一判据**——这是剩余工作量，需编译可用后与独审一起逐条落实。

若主控坚持字面执行（写者行为测试一律改只读/迁 S3），需另定 S3 差分对拍改用什么 oracle。
