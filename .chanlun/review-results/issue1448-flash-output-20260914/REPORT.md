# #1448 Flash 工蜂输出格式补强

名分：本票工作草稿。Sandcastle direct Codex 工蜂已固定为 `deepseek/deepseek-v4.1-flash / max`。两次长任务虽然正常退出，最终消息仍是非法 JSON；封装器保留 `failed` 是正确行为，原记录没有改写。

本机 Codex CLI 和当前封装器原本已经使用 `--output-schema`，本地 Router 也保留 `text.format`。这些事实不能证明上游强制执行该约束。本次只把完整 schema、字符串数组要求及合法形状示例追加到模型可见提示，并要求最终消息简短。只读工蜂仍在返回值中保留必要发现，只有获准写产物的任务才把详细结果写文件。严格解析、失败判定、模型路由和权限边界保持原样。

相关封装器回归 41 项通过；最终措辞另经真实子进程提示传递测试通过。随后同一路由执行一次真实只读探针：读固定文件并计算摘要，18 秒内完成，返回 JSON 经封装器成功解析。71 字节文件的 SHA256 为 `06610f767f56666770c90a7f5658582ccb0c6503ca3714992f810dac282edd6d`，与管理者独立复算相同。实际会话、前后版本及退出状态见 `RUNTIME-RESULT.json`，源文件摘要见 `CHECKS.json`。

结论仅为提示补强后的这次格式探针成功，不保证未来长任务永不输出非法 JSON，不把历史失败改成通过。原生子代理管理的是外部 Codex 工蜂；外部进程并未注册成 App 原生 child。本报告不授权 main 合入，也不关闭 #1323 业务总图。
