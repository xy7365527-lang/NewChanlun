# 订单递归研究目标与分支协议 v4

日期：2026-10-03。绑定研究图 #1465、候选研究 #1467、实验 #1468、架构 #1469，承接方法票 #1470。名分：在制研究协议，不是教义、生产 spec 或一般定理。回应用户“看了数学工作流，有需要把目标重构吗”。

## 目标与实际修改范围

**研究目标：在明确的订单事件可见域中，判断哪些订单信息构造能满足缠论基底与向上递归的语义要求、成立需要哪些条件；在共同历史、决策时点和资源预算下，检验递归表示相对于同信息非递归表示的增量价值；据此提出有证据支持的用途和条件性架构变化。**

保留原验收 P1 合法构造、P2 实时忠实、P3 递归增量、P4 用途与架构。保留“观察路径后构造”和“直接订单簿演化构造”两条 F₁ 路线；保留 queue-only 变化、原始来源和原义 F₂。不预定候选成功，不要求与成交塔强等价，也不把修完现有引擎的全部问题设为前置。

v3 已撤销必须复用旧 kernel 的预设，并区分成立、反驳与未决。v4 将这些原则落实到研究对象、具体分支、推进依赖、停止及重启条件；没有把失败命题改弱，也没有新增研究已完成的结论。旧报告、定义、声明锁和证据保留。

本次修改的是研究执行协议与当前进展页。经 `get_goal` 核实，本聊天活动 goal 仍为原正文且状态 active；现有工具只能修改其状态，不能原位改写 objective。本文件不冒称聊天目标字段已更新，不以假标完成或新建重复目标绕过。原 goal 与本版范围相容。

## 先区分对象，再判断构造

| 对象 | 本研究怎样处理 | 什么不算成功 |
|---|---|---|
| R_W：由订单价量得到的具名观察路径，再构造 F₁ | 冻结观察函数、单位、精度、时钟、完整分解和确认关系；检验其输出与原义 F₂ 的接口 | 有价格量纲或画出波形，不足以取得缠论语义；加权观察值不自动成为可成交价 |
| R_D：直接由有类型订单簿演化构造 F₁ | 明定多变量对象、方向、区间、连接、完成及上递归语义；检验与既有概念的对应 | 供需正负不能直接当价格方向；另造的订单结构未完成语义桥前保持新结构候选身份 |
| 订单信息附加于价格结构 | 作为信息价值对照及可能的用途结论；可用于 B/B_seed 的具名设计 | 即使有效，也不能代替 R_W/R_D 的合法性，不能称“挂单递归已经成立” |

对某候选 c，`H_V(c)` 是明确场所协议 V、初态、排序和缺口规则下的有效历史域；`O_t(h)` 是截止 t 真正可见的观察。候选定义中必须写出有效段中断、未知状态及活动尾部的处理。没有观测到的撤单原因、隐藏流动性或其他场所信息不能填入。

“任意允许初始构造是否存在”的开放问题，与“某个 c 在 H_V(c) 上是否成立”分开。一个反例只否定它实际覆盖的候选和命题；若要排除整个候选类，必须明确类的量词并给出类级论证。不能因所有已试实现失败而宣称所有订单递归不可能。

## 四组可检验命题

| 命题 | 要回答的问题与验收 | 有效的否定或不足 |
|---|---|---|
| P1：合法构造与递归 | 对独立分解关系 R₁，明确证明域内每个历史恰有一份完整分解；给出非空完成见证。对带成员、层级与生命周期的 X_k，证明具名 F₂ 产物满足 X_(k+1) 的原义要求、同判据、完整分类、闭合及有限输入的递归终止依据 | 第二份合法分解、有效域内无解、来源/端点不接续、混级、非法子核心或无依据的完成证书可反驳对应命题。程序确定性、局部几何及恒为空的产出均不足 |
| P2：实时忠实与实现 | 独立语义与实现对应；保存发生、可知、确认与发布时点；在具名输入契约下检查逐前缀、重发、缺口、乱序及持久化恢复。一般主张须有一般证据，有限样本只给有限结论 | 用未来快照回填、以后确认回标为当时已知、静默跳过缺口、相同已知前缀得到不同已确认对象，均打回相应准入 |
| P3：递归的增量价值 | 冻结一个用途、外部标签、确认集、构造和选择预算；四臂公平比较，主要终点为 C−B_seed。报告效应大小、不确定性、稳定性与资源代价 | 只有订单信息有效、F₁有效或训练集有效不足以证明 F₂ 增量。未达到预设实质效应的证据须区分效应不足与统计不确定，不能仅因不显著断言零效应 |
| P4：用途和架构 | 从 P1–P3 的成立条件、失败原因及用途推出所需数据、状态、恢复、确认、吞吐和执行能力；给出可复用、需补足与待测部分 | 未测量不声称低延迟收益；只有预测证据不声称净收益。不能从“高频数据”直接推出必须更换生产架构或硬件 |

P1 不要求每个有限前缀都产生上层完成走势。允许规范定义的前导、活动尾部、NoCore 及尚未升级的片段；但必须明确其归属并另给非空完成/升级见证，不能用永远不产出规避命题。改变有效域、确认规则、参数或语义必须另立版本并解释变化，不能继承原命题的通过状态。

## 推进依赖与实验边界

数学主线先处理真正决定候选去留的定义缺口和最小反例，再为有清晰契约的命题完成证明或 Lean 检查。证明路线、反例搜索、定义审计可以往返，没有“必须先形式化整套旧引擎”的固定流水线。

真实消息的取得、协议重建、成交对照、时钟与恢复检查，以及 A/B 的数据准备不依赖完整 F₂，可以先行。B_seed 的构造也必须具名；若 F₁ 语义仍未定，只能作为带此限制的探索结果。任何 C 都标明实际使用的 F₁/F₂ 版本与资格；不能把未合格几何 C 改名后当作主确认实验。

四臂继续为：A 使用成交历史；B 使用同一可见订单历史的非递归特征；B_seed 在 B 上增加与 C 完全相同的 F₁ 单元及 active 状态；C 再增加 F₂ 表示。所有臂共享决策时点、标签、分区及可比模型/搜索预算。分别解释 B−A、B_seed−B、C−B_seed；只有条件匹配时才作所声明归因。确定性递归没有向完整原历史添加信息，待检验的是受限模型与预算下的表示价值。

当前 Coinbase 一分钟仅用于探索性的协议与重建验证，没有决定最终研究市场，也不是确认集。市场、任务、δ、划分、最小实质效应、误差估计、费用及成交假设仍待具名冻结。若主张交易用途，再完成实际成交、排队、延迟、容量和费用证据；报价预测不能替代这一层。

## 分支状态、停止与重启

| 分支 | 当前处理 | 何时继续或停止 |
|---|---|---|
| R_W-v0 及已查旧 F₂ 入口的直接复用 | 保留 Stage2、5、6、8 的限定反例；退出“找到接口即可合格”的路线 | 只有明确修订候选或新增足以消除具体反例的语义证据才重开。重复换入口而没有新依据不继续；不顺手修全仓生产问题 |
| R_W-DC-v0 | 保留 Stage4 的定义内 Lean 证据；语义桥、全域程序精化、独立审查和 F₂ 完整资格仍开放 | 下一数学工作限定为一个成员/同级/生命周期齐全的组装关系及最小区分见证。若不能给出独立关系，就登记定义缺口，不无限补适配器 |
| R_D-v2 及其他直接构造 | 供需符号复制价格方向等被否定适配不复活；直接多变量路线仍开放 | 新候选先说明解决哪个已知缺口、代价及反例目标。没有新假设或证据，不在相同桥接失败上重试；不得因该候选失败关闭整条路线 |
| P2 与 P3 的数据前置 | 接续 Stage9，完成已取得样本的恢复检查和负控制，不重新下载或重跑已完成重建 | 字段/排序不足时停对应检验并记录缺口；可独立的数学工作继续。样本只能支持其具名协议，不据此报告普遍恢复正确或市场价值 |
| P3 主确认与 P4 采用判断 | 准备协议和条件性架构论证；主确认依赖具名候选资格与实际冻结项 | 缺条件时不发通过结论；采购、预算扩张或生产采用另行请求决定。不能将未运行的实验写成否定结果 |

每次尝试先写一个可核查主张、有限资源上限和退出条件，保存失败目标、反例、输入版本及复现命令。同一失败只有新的可检验原因才重试；沿现有接续协议，连续两轮无实质证据进展或达到该轮上限即停止当前尝试，转向仍有独立证据路径的已授权工作，并记录重启条件。这不是关闭总目标，也不重置累计消耗。

作者自检、机器检查和独立语义审查分别记账。现有父模型切换能力限制下不绕过用户要求派发，待审小包保持待审；这只限制需要独立审查的结论准入，不阻止其余研究。没有独立审查不能自封独评通过。
