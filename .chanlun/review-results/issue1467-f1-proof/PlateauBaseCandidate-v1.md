## 2. 输入域与初态

### 2.1 有类型原始历史

输入为一个品种、一个已知连续序号 epoch 的完整订单簿初态 `B0`，以及 `e1,...,en`。每个事件保留原始载荷、订单 ID、买卖方向、价位、数量、源序号、源时间及前后状态。

本次抽象订单簿至少支持新增、减量撤单、成交减量和改单。新增量须正、撤成交量不能超过残量，订单 ID 与方向/价位须匹配；改价或重排优先级必须保留协议给出的顺序与身份。例子只用新增与部分/全部撤单，不借未发生的成交制造数据。这里“合法”指上述状态守恒与限价簿约束，不冒充某一交易所协议的全面验收。

以源序号确定不可逆顺序。相同时间戳按源序号排；跨源缺少全序、丢号、无法恢复前态、订单残量矛盾时，记录缺口并终止此构造的连续 epoch，不排序猜测、不用零填、不越过缺口造完整对象。原始事件仍保留。

### 2.2 观察及明确限域

先固定价位 `b=100`，令 `q_i` 为 `B_i` 中该价位买队列总量。这不是订单流累计净量，而是每次事件后的存量。即使价格不动，增、撤、成交仍可改变它。

`F1_Q` 的观察是 `x_i=q_i`，类型 `QuantityAtPrice(100)`。

为了给出完全可查的最小候选，输入域 D 限定为：`x0=x1`；每个已经结束的最大常值平台至少含三个事件后观测；末尾未结束平台可以尚不足三个观测。相邻平台值必不同。三个观测对应三个真实、不同的源事件，不是三次查询同一状态。别的队列事件可以使选定队列数量不变，但不得从原始历史中删除。

这是明确的窄域选择，**不是**全体合法订单历史。短平台一旦结束，就给域外证据，不能偷偷删掉它再接续原构造。本候选没有把所有域外历史强制分类的方案。

例子的初态：

```
S0: Bid, p=100, q=10
A0: Ask, p=102, q=10
p=99 的辅助买队列为空
```

全部价位在例中固定，最优买价 100、最优卖价 102 始终不变。辅助订单 `Uj` 均在 99，不改变最优价。它们是合法原始事件，也暴露本候选的平台计数对观察流的依赖，不能将这一点藏起来。

## 3. F1 的对象、完整分解关系与完成证据

### 3.1 初始核心不是从上层递归来的

把 D 中的最大常值平台记为 `P_i=[s_i,t_i]`，值为 `c_i`。第三个事件后状态到来时，建立底层核心候选：

```
K_i = (平台 ID, [c_i,c_i], 三个不同事件的等值见证, 平台成员)
birth(K_i) = s_i + 2
```

其右端 `t_i` 在首次不同值出现时才确定；以后同值到来只延长当前平台，不创建新的核心。这里的单点核心是借第 35 课的基底构造形状作的新选择，**不是**放宽 F2 的严格区间规则。`F1_Q` 的“数量平台可作核心”以及 `F1_W` 的“观察价平台可作核心”均未被原文逐字指定，不标作旧缠论。

### 3.2 独立于扫描程序的分解关系

令 `d_i=sign(c_i-c_(i-1))`，`i>=1`。所有符号非零。一个分解合法，当且仅当其核心间边序列由下列块组成：

1. 每块是连续且非空的边索引区间 `[a,b]`；块内所有 `d_i` 相同。
2. 相邻块的符号相反，因此块不可再向相邻块合并。这就是最大同向性。
3. 块按原顺序无遗漏、不重复覆盖已经有反向见证的边；其后留一个尚未完成的尾块。
4. 第一块拥有 `K_0,...,K_b`；以后每块 `[a,b]` 只拥有 `K_a,...,K_b`。前一块的末核心 `K_(a-1)` 不再归入后一块。
5. 第一块的原始事件域是 `(0,t_b]`；后续块是 `(t_(a-1),t_b]`。其轨迹共享边界状态 `B_(t_(a-1))`，不共享边界之前的事件或整个核心。

分解唯一性可直接证明，不依赖“某程序每次返回同样结果”：符号相同的两个相邻边之间不能切，否则违反最大性；符号不同处必须切，否则违反块内同向性。于是所有切点被符号关系唯一确定。最大常值平台本身也由相等关系唯一确定；核心拥有者与原始事件区间又由规则 4、5 唯一决定。

这只证明**给定本地关系后**唯一，未证明所有合理 F1 都给同一分解，更没有从唯一性推出与缠论原义等价。平台选择、坐标选择、中心独占约定都已公开，不能藏在算法中冒充市场强制的唯一答案。

### 3.3 类型、端点与活动尾部

每块至少有一个自己拥有的核心。一个核心的块记为本候选的盘整型；两个及以上核心的块，因核心值严格同向且不同，记为本候选的上行/下行趋势型。方向字段来自块符号，不以“盘整”消除方向信息。

后续块起点为前块末状态，终点为自身末平台的最后状态。区间 `range` 是包括这两个边界状态在内的最小值与最大值形成的闭区间。原始轨迹是跳变的阶梯路径；区间中的每个实数不必都被订单簿实际经过。我们保留跳变，不制造中间订单事件。

对象在没有反向核心时只处于活动尾部，哪怕已经有两个、十个同向核心，也不输出完成对象。观测停止不会自动完成尾部，不能将“核心够数”当成“走势完成”。末尾平台不足三次时还只是待建立核心。

### 3.4 完成与确认分开

块 `[a,b]` 的完成支持是下一核心 `K_(b+1)` 的三次等值见证，以及：

```
d_(b+1) = -d_b
```

结束端点是 `t_b`，确认时间是 `s_(b+1)+2`。端点位置先由平台转值确定，反向平台达到三次观测后才确认。不存在输入字段 `completed=true` 或由外部提供的完成 Bool。

反向核心属于后块。它可以被前块的证明引用，但没有被前块消费为成员。这正是“证据支持”与“对象拥有成员”的区别。未来同值延长该反向平台、或产生更多平台，不会改变已经确认的切点与成员。

对于只有一个自有核心的块，上述规则仍能定义结束；但它与原义盘整完成及盘整后类型变化的完整对应尚未证明。因此主算例特意让三份对象各自含两个核心，避免以一个局部核心直接替代本次所需的三个完整对象。

### 4.2 数量轴上的父核心确实非空


| N3 | e10…e12 | K3=20 | 10→20 | 上，1 核心盘整 | K4=10，e15 |
| 尾部 | e13…e15 | K4=10 | 20→10 | 活动下行，暂 1 核心 | 未完成 |

N2 从共享状态 20 向第一个自有核心 10 的运动，已经给出方向；不等第二个自有核心才开始判断方向。N2 在反向核心 20 成立时完成，不能并入 N3，也不能消失。这排除了“重新起串须先等两自有平台”所导致的连续输出 Up、吞掉中间 Down 的错误。

所以方向交替是本关系的一般性质，不只是长算例偶然满足；原始事件覆盖也没有破口。但候选的类别序列确实出现“趋势→盘整→盘整”。这尚未证明符合 `017-第17课.md:36` 的完成后转化为其他类型的原义要求。不能把“盘整带不同方向”未经论证就当作原文说的两种不同类型。本报告的数学分类按自有核心个数有定义，原义的完整分类资格仍欠这一条。

## 5. 不同版本 F1_W：具名加权盘口观察价

该版本是母任务提出的进一步待验构造，本节对其重新计算，没有预设它已获原义资格。记作 `R_W^fresh`，避免与任何既有同名报告混同。

在同一初态与同一事件历史中，最优买价 `b=100`、最优卖价 `a=102`、卖队列量 `K=10` 恒定。定义每次事件后观察：

```
W(B_i) = (a*q_i + b*K)/(q_i+K)
       = 100 + 2*q_i/(q_i+10)
```

W 是盘口状态函数，具有价格量纲，落在 100 与 102 之间。本例没有实际成交，W 不是成交价，也不是报价档位上实际挂出的订单价格。

对正数量 `u<v`：

```
W(v)-W(u) = 20*(v-u)/((v+10)*(u+10)) > 0
```

因此等值平台、方向符号、最大同向边块、核心归属、端点索引、完成支持和确认时刻都保持。此处有独立分解关系的等价证明：严格单调性使相等关系和符号关系双向对应，再代入第 3 节定义；不是仅让一个程序换列再跑。

| 核心 | q | W 的精确值 | 核心出生 |
|---|---:|---:|---:|
| K0 | 10 | 101 | 3 |
| K1 | 20 | 304/3 | 6 |
| K2 | 12 | 1112/11 | 9 |
| K3 | 6 | 403/4 | 12 |
| K4 | 10 | 101 | 15 |
| K5 | 16 | 1316/13 | 18 |
| K6 | 11 | 2122/21 | 21 |

同样由三个完成对象得到：

```
range_W(M1) = [101,304/3]
range_W(M2) = [403/4,304/3]
range_W(M3) = [403/4,1316/13]
ZD_W = 101
ZG_W = 1316/13
ZG_W-ZD_W = 3/13 > 0
```

所以价格量纲的父核心算例是 `[101,1316/13]`。完成时刻仍为 e21，成员与原始事件完全不变。最优价没有运动，队列数量运动却给 W 产生了三个实际完成的候选基底对象。

严格单调映射只保证本节的次序和区间事实，不保证力度。等时长两个变化 `q:1→3` 与 `q:10→13`，数量增量分别是 2、3，而 W 增量分别是 `40/143`、`3/23`，大小关系反转。这已经足以否定“严格单调所以力度比较自动继承”。既有 `L=Δv` 的全部结构与时间义务仍需独立处理。

## 6. 输出到 F2 的类型与最早未过的语义桥

```
CompletedF1Move<Axis, ConstructionId> {
```

`Axis` 分别是 `QuantityAtPrice(100)` 与 `BookObservationPrice(R_W^fresh)`。完成状态由证据构造，不能靠任意 Bool 创建。原始事件日志是输出的一部分；标量不能恢复的订单身份、方向和各档变化仍可回查。

## 7. 明确未决义务与可复核反例

1. **覆盖面**：合法数量历史 `10,11,12` 每平台只有一次，D 不接纳。不能删除短平台或将其混入相邻块来假装全域成立。需要新的 F1 选择或对本窄域的用途作限定；不涉及先修旧引擎。
2. **观察流稳定性**：在 `10→20` 后仅看到一次 12，前对象暂不能确认；增加两笔 99 档辅助订单事件即可让 12 平台成立并确认。这个反例说明完成依赖整个订单事件流，不能声称对无关队列消息增删不变。它不违反本次确定输入域内的唯一性，但影响候选的市场解释与稳定性。
3. **无限延伸**：每个 q 平台三次观测，平台值 `10,11,12,...` 可以由合法新增持续产生。本 F1 永远只留一个活动上行对象。由局部合法性与唯一性推不出原文“走势终完美”的普遍市场命题；若要该命题，必须说明所研究市场域或补足论证，不能外加完成 Bool。
4. **单核心对象的语义**：第 4.3 节的 `10,20,10,20,10` 已实际生成向下盘整后接向上盘整。分解和方向没有漏失，但“盘整→盘整”能否符合 `017:36` 的类型转换要求未过原义审查。主算例没有依赖此处获得三份完成对象。
5. **基底核心资格**：三次同数量/同 W 观测不是三笔同价成交。这是启始程序的新选择。第 84 课允许研究它，第 35 课不能被改引成它已被作者定义。
6. **W 的有效域**：严格单调保真的证明用到了 a、b、K 恒定且 K>0。任一量变化，W 仍可计算，但不能沿用这个单变量证明；新报价、清空队列、价差变动都需要重新检查。
7. **上层完整性**：目前只算到三份已完成 F1 对象和父核心，没有推出父走势完成，也没有三买、力度、背驰或交易盈利结论。不能把父核心出生直接升格为父走势完成。

这些是候选自身的精确负债，不构成“订单事件不能生成任何缠论递归起点”的不可能性证明。尤其，直接数量轴到实际价格失败，并不否决 W 或其他观察定义；W 的有限算例通过，也不解除原义准入义务。
