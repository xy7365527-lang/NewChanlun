# Stage26：真实原生事件接入直接报价块

日期：2026-10-04，绑定候选研究 #1467 与实验前置 #1468。运行时 profile 为 `rd-q-native-available/1`。名分：有限回放研究证据，`semantic=not_reviewed`。

## 本轮结论

既有 Coinbase/BTC-USD 2021-01-01 首分钟样本产生 13,489 个模型事件和 6,835 个已确认符号块。另一份 BigInt 价量簿与分块实现逐行核对通过；新进程恢复、物理截断、长缺口恢复、缺序不补及合成边界检查通过。主簿终态与 Stage9/16 的完整 State SHA 完全相同。

这补充 R_D-Q-moving-v1 的真实输入、可知时钟和持久化恢复证据。它不证明一般 Rust 精化、全场所协议、完整缠论走势或 F₂ 递归闭合，也没有测量预测或收益增量。作者的第二份实现仍属于作者自检，独立语义审查尚未完成。

## 输入与构造

[开工卡](Stage26WorkCard.md)固定了输入、资源上限和失败条件。[实现](native_quote_blocks.rs)的前 16,954 字节保持 Stage9/16 解析器、State 字段与方法不变，[来源指纹](stage26-core-origin.json)记录复制边界。主 State 按原 consume 重建；观察副本只按主 State 实际应用的连续原生序号调用同一 apply。捕获时缓冲的原记录单独保留，恢复时从 pending 重建该来源账。

一条原生消息的净簿变化映射为至多一个模型事件，不能把实现内部的 remove/readd 拆成两条。映射为：open 对应新增，match 对应执行，canceled done 与 resting size decrease 对应撤减。保留原生类型与 normalization；改单减量没有被冒称原生撤单消息。received、非在簿 done/change 和同量 change 不生成模型事件，仍留在应用账。

正常订单沿其连续数量片段更新，输出匿名 fragment rank；原订单身份只留原始行情、运行内存及私密检查点。size increase 等超出当前单片段撤减模型的有效变化设为显式 barrier，旧活动块按未完成退出，再从真实后状态重新锚定，不能跳过后跨接。

极大同号块遇首个反号模型事件才确认。端点取反号事件之前的模型边界报价，EOF 没有确认权。暂未知盘口与真实无有效报价分开记录。整侧耗尽、锁定或交叉报价时 geometry 为空，后续恢复不回填历史空端点。同序号且完整簿相同的快照只重申；同序号冲突或倒退快照拒绝。前向快照和断连切断原域。

## 三种时刻与发布边界

native_event_at 是来源消息时间；captured_line/captured_at 是原记录捕获位置与时间；available_line/available_capture 是其真正应用和可知时刻。快照或迟到消息补齐后，可以重建原生顺序的中间态，但新增确认只能发布在补齐当下。

本 profile 使用原生逻辑路径并附捕获可知时刻。Stage17 则每个捕获行只读取应用完成后的单一发布状态，两种时钟的输入序列不同，不能把块数直接作优劣比较。确认块可能指向先前发生的端点，后续实验必须按可知时刻使用它。

连续基线用时 13,922ms，含文件处理与输出；这不是生产端到端延迟或架构性能基准。
