# Stage48 全事件切点分区合同 v1

2026-10-04，#1467，作者执行合同；在求解器编写前锁定。HEAD=`3397901b1917b42071c9d8a876ff9e6de0b6460e`。上位意图为 `stage48/Intent-v1.md`，不得把本合同解释成完成资格。

1. 输入为 Stage47 的 H_EV 有限正整数 Q 历史，初态 x0=x1；空输入保留独立给定初态（见具名订单记录）。最大常值平台原样计算，不删除短平台。每个已满三事件平台是一枚候选点核，保存全平台当前成员；已封口者记 ClosedCore，开放末平台已成熟者记 UnsealedCore。未满三事件者无核。
2. 节点为全部实际事件位置 `0,…,n`。边 `(s,e)` 拥有全部 `(s,e]` 事件，共读状态 x_s；range 取 x_s…x_e 全状态，不用核心包络替代。s<e。
3. CORE 边不得部分切过任何已成熟核心：与某 ClosedCore 的事件成员相交就必须完整拥有它；与 UnsealedCore 的任何成员相交则拒绝，因为无法把未封口平台当已固定自有核，也不能忽略它。自有 ClosedCore 至少一枚，恰一枚记 P；至少两枚严格逐次上移为 U、严格逐次下移为 D，否则拒绝。P 的概念方向为 null。
4. TREND-NORM 在 CORE 上要求 U 的共享起态等于全路径最小值、结束态等于全路径最大值且两者严格异价；D 镜像。P 不另添方向、形状或完成假设。
5. TREND-ONLY 在 TREND-NORM 上排除 P 边，仅研究全趋势必要合同子问题。每个 profile 单独求图，不在失败后换 profile 接管。
6. BASE 是上述有限关系。开放短平台可作为一条有核边的无核尾部；它后来成熟并跨旧切点时，旧 BASE 边可以消失。这是有限必要关系，不是已经确认完成的输出。
7. 另设 CLOSED-CUT 比较：边所消费的全部事件均位于已封口的原始平台中，即 `e < s_open`，其中 s_open 为当前最后平台起点。这一名字指被消费的来源片段已封口；**不要求 s/e 都是平台末端**，已经封口的短平台内部事件切点仍枚举。它是显式附加条件，不默认为原义必要条件、不用来修复 BASE。空历史没有正边。
8. 路径必须从0至具名固定k，且以精确块数b分类；尾部严格是(k,n]。也提供总路径数（对该k求和），但不得把不同k混为同一覆盖问题。空路径仅属于(k=0,b=0)。对“旧e6边界”另加LOCK(6)条件，明确它是候选锁，不是假定语义完成事实。
9. 全部路径计数用 DAG 动态规划和 BigInt，绝不截断计数。最多保存每个单元格前两条见证，这只是输出压缩，不参与计数或零/唯一结论。每个(s,e)都求一次边判据，拒绝原因保留计数。
10. 另列 THREE-TREND-STRICT：恰三条边、均U/D、方向交替、三条完整range严格交集，且路径仍为0至固定k。这是额外接口条件，绝不把其通过称作父核或父完成资格。全枚举所有三条边连接，精确BigInt计数。
11. 坐标 occurrence=e，评估可知前缀=n，语义完成/确认=null；ClosedCut边另记来源目录已固定所需的封口事件。下一枚成熟核可为开放核，只引用已存在的固定三事件种子，不将其当前全平台末端说成最终末端。源事件物理时钟来自具名订单记录，不由候选端点回填可知时刻。
12. 重复峰值样例为10³,20³,30,25,30,10³,20³。先实际报告首U在固定自有核K@1/K@4且后继K@10成熟的全部合法终点；再寻找同k、同b路径见证。若额外比较“端点达到截至后继成熟证据的全支撑极值”，明确命名 WITNESS-HULL-EXTREMUM，不能偷偷加入三个基础profile。
