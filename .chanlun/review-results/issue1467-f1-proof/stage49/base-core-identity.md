## 3. 可反驳的 Token → Center 桥

### 3.1 先不把身份证放进变量名

令 `h=(e₁,…,eₙ)` 为固定协议下有效历史，`x_j` 为固定观察函数在 e_j 后的值，源事件不得因无核而删除。最大常值平台为 `P_i=[s_i,u_i]`，值 `c_i`，当前可观测成熟条件 `u_i−s_i+1≥3`，初次成熟时点 `β_i=s_i+2`。`T_i=(s_i,c_i,β_i)` 只叫成熟 Token；若平台仍开放，u_i 不是最终成员末端。

三种对象不同：

```text
Seed(j)  = (e_j,e_(j+1),e_(j+2)), 三次同值的形成见证
Token(i) = 同一最大原始平台中这些 Seed 的稳定索引
Center C = (seed witnesses, level, member interval, member roles,
            fixed core, exterior support, extension/retirement witnesses)
```

一个长平台中多份 Seed 可以见证同一 C；某一 C 也可能拥有多个原始平台的 Seed。反之，不同价的固定点 Seed 不能在保留 `core(C)={c}` 的同时无条件映到同一 C。要知道实际是哪一种，必须独立给映射 `ρ_h:Token→Center` 与它的身份判据，不能把 `ρ_h(i)=i` 当作证明结论。

### 4.3 `10³,20³,10³,20³`

Token为A=[1,3]@10、B=[4,6]@20、C=[7,9]@10、D=[10,12]@20，成熟时刻3/6/9/12。四份 Token 确实是四份独立来源的**形成见证**。

下面给出不靠ID的条件身份证明。额外固定：

1. 每个成熟 Token 恰归某份本级实例，该实例固定点核心等于它的 Seed 值；
2. 同一实例在成熟 Token 的时间次序上拥有凸区间；不同本级实例不交错占用同一批构成 Token；
3. 该构造以一个实例连续拥有的同值 Token 块为最大块，遇不同值成熟 Token 才切换；切换后旧实例不复活。

由1，A与B不能同一实例，因为同一固定点核心不可能同时等于10和20。若A与C同一实例，由2的凸序性，B也应属于该实例，与1矛盾；故A≠C。同理B≠D。相邻价不同又逐一分离，其余跨越相异 Token 的组合均由相同论证分离。所以四实例不同有明确结构理由，**不是名字不同**。这里1–3是待检 F₁ 的桥前提；它们不能倒装成从35单行已经取得的结论。

若另取每实例自有成交/观察点为外缘，则四外缘依次为点10、20、10、20，相邻数值关系为U/D/U。此时才可条件性调用35：若A/B确实属于同一原义最低上涨，C的出现提供该上涨不再延续的证据。它不同时决定旧上涨原事件切点，也不把B/C直接变成第二份独立完整下跌。把A/B、B/C、C/D三对都输出为三个完整 Move，还会把B、C作为构成中枢重复计数，违反37的归属要求；本轮不重做旧共享核证明。

因此四个成熟 Token 既不自动等于四枚原义实例，也不等于三份可直接喂 F₂ 的完成走势。C_RET-v0将在自己的具名身份关系内实际给四实例，完整 Move 构造另欠。

## 5. 替代核对象 `C_RET-v0`：时间区间实例，价格核心仍可为点

这项候选保留观察函数、三次成熟门、原始平台目录作为形成证据和旧M-2数值判据，**另建实例关系**。它不是Stage45的E外缘方案，也不拿E的结论再算一次。新的地方在于同价 Seed 可属于同一实例，短波动有明确实例成员地位。

### 5.1 独立关系定义

对有限前缀，按时间排列全部成熟 Token 的值串 `c₁,…,c_m`，不得过滤不利方向。将这个串按相等值切成**最大连续同值组** G；注意分组对象是成熟 Token 串，两个相邻 Token 之间允许有未成熟的原始平台。

每组G产生一个候选实例：

```text
c(G)          = 组内共同值
start(G)      = 组内首个 Token 的平台起点
seed(G)       = 首Token的前三源事件；后续同价Seed为追加形成支持
core(G)       = [c(G),c(G)]                     （固定）
next(G)       = 后一不同值组的首Token（如已成熟）
end(G)        = start(next(G))−1               （只在next已成熟时封定）
confirm(G)    = start(next(G))+2                （只确认核实例的区间封定）
members(G)    = 原事件 start(G)…end(G)          （不漏短平台）
support(G)    = {(e_j,x_j): j属于members(G)}     （保留来源，非去重值集合）
outer(G)      = [min x_j, max x_j] over support(G)
```

**支撑合同选定为自有事件后的观察点。** 不把共享入口状态 `x_(start−1)` 或每事件前后区间计入中心外缘；不是声称这些状态不存在。若形成一个 Move，其完整范围仍按自有事件及两端状态的完整路径计算，不能复用本中心 outer。这是本候选的具体新F₁支撑选择，需语义验收；不得声称原文普遍强制P型或E型支持。

尚无任何成熟 Token 时，全部事件保留为 NoCore/待定前导。第一份实例之前的事件保留前导。末实例只有当下暂定区间和原始尾部视图；**整个未封对象都不声明已经发布为完整成员**。新不同值平台在第一、第二次观察时仍是未定短尾，第三次成熟后，其从起点开始的三事件归新实例，旧实例才封到它之前。实现可用缓冲表达，不得先确认这三事件属于旧实例后再回写。

在同价回返例中，旧实例一直未封：e4的离开、e5的回返不会改一份已发布旧实例。e7只新增同价Seed支持；未来若出现不同价成熟平台，旧实例的完整成员和outer才最终封定。若某时已存在不同价成熟组，后来的10将属于新的10实例，永不把已封旧10复活。

### 5.2 一般性质与证明

**命题R1（核实例关系唯一）。** 每个有限观察词的上述实例关系唯一；每份实例的Seed群、已封成员区间、核心、外缘和封定时刻唯一。

证明：最大原始平台分解唯一，成熟条件与起点确定，故成熟 Token 串唯一。有限有序串的最大同值连续组唯一。后组首起点唯一，故每个已封组末端和确认时刻唯一。有限成员支撑的min/max唯一。这里证明的是候选定义内核实例关系，不是完整走势分解唯一。

**命题R2（来源全保留）。** 前导加按start顺序的实例区间，在每个当前前缀不漏不重地覆盖原事件；开放尾实例只作暂定视图。

**命题R3（已封核实例追加稳定）。** 一旦G在β_next封定，任意有效追加都不改变G的全部字段。

**命题R4（实例身份由成员结构而非ID给出）。** 两枚Token同属一实例当且仅当它们之间成熟Token串全为同值。不同值中间Token阻止跨越合并，同值但被短无核波动隔开则合并。证明由最大同值组定义直接得到；这是一条可被源义或F₂反例推翻的新选择，不是原文已裁。
