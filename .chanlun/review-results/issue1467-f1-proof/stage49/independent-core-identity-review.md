## 4. C_RET 的普通证明和独立程序结果

按原稿 `:129–166` 的声明，取全部成熟平台的**值串**，划分最大连续同值组。这里“之间全同值”应读为包含两个端点的闭序区间。这一关系由数据和条款确定，没有用ID自证。

R1成立于该声明关系内：最大原始常值段唯一，成熟起点唯一；相邻成熟 Token 不同值处必须切开、同值处不得切开，故组边界唯一。后组首起点确定前组末端，成员、min/max与确认时刻均确定。它同时给出有限词上的存在性和唯一性，不是原义完整走势分解的存在唯一性。

R2成立：首实例起点之前的前导、相邻起点间的区间、末实例到当前末端的暂定区间首尾相接，恰好覆盖每个原始事件一次。无成熟平台时全部是NoCore前导。前导和开放尾的视图都不能被额外解释成已经封定的结构对象。

R3成立：旧组封定时，下一异值平台的前三个事件已存在；该平台起点及其之前的全部平台已经固定。未来追加不可能在过去插入新的成熟 Token，也不能跨过既有异值组回并。旧组成员、种子起点、core、outer、确认时刻于是全部固定。逐步追加不变通过归纳推出任意有限追加不变。

R4就是最大同值凸序组的等价关系。对中间出现异值成熟 Token 的两枚同值 Token，凸序归属与固定核心共同禁止其仍属一组；对短无核波动分隔的同值 Token，则候选明定合并。第二项不是原文已经证明的必要性。

仓外 `independent-check.mjs` 另写了逐事件状态机。它不调用作者的平台构造或分组函数：每来一事件先进入开放视图，当前同值串第三次出现时才识别一份成熟见证；若异值，则从旧开放视图撤出这三事件，封定旧实例，给新实例。冻结作者的纯函数另从其源码载入，仅用作对拍对象。另枚举成熟 Token 的所有连续分组切法，检查同值与最大性约束下只有一解。

## 6. 支撑类型与交付门

原稿 `:141–148` 和代码 `:62–65` 选定的是实例自有**事件后观察点**的支撑。程序没有吸入 `x_(start−1)`。例如 `10³,20³` 的第二实例中心outer为点20；若以后把其事件e4–e6构成一份拥有入口状态的Move，完整路径范围至少包含从10到20的入口变化，不能直接拷贝中心outer当Move范围。当前包没有生成这种Move，因此也没有提供该范围的实现或完成证明。

采用的内容只限于：

1. 035具名逐笔成交最低点核的原义角色，不被递归严格父核规则倒过来否决。
2. 形成Seed、成熟Token、实例身份、封定与Move完成必须区分；原平台最大性不能填身份空缺。
3. C_RET在声明的新关系内具备有限词存在唯一、原事件覆盖、closed追加稳定以及可执行的成员和outer；未封字段允许随成熟证据重分。

仍阻断原义a₁/F₂升级的缺件是：订单观察的合法lift，C_RET回返/切换/归属与原义维持破坏的关系，完整Move分解及成员边界、实际完成证书，完整范围与固定F₂的全部组件义务。没有补这些内容，就不能把本次PASS抄成“核身份已获原义认证”或“F₁已构建完成”。
