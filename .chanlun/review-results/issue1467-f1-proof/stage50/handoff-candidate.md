# Stage50：局部提升与联合重分的两个承接桥类反例

2026-10-05，#1467。研究工作草稿；基线已核 `d9ad8c54e969e1258cde1134ba3ec6d6db800e44`。本稿与 `candidate-evidence/` 为本工位新增，Stage49冻结材料不改。作者开发检查通过；独立审查另行进行。

**本轮没有得到新的合格完整F₁，但把 RC49 修复必须改变的条件进一步钉死了。** 在同一40事件历史及镜像上，先冻两类承接合同，再穷举事件切点：

1. **EHL50-v1：局部两核提升。** 父支撑限于扩张两实例及连接的最小区间，并保留旧同层核心目录完备时，不能取得三个各含自有本级核的完成孩子。证据是核心数 `3≤2` 的矛盾，不依赖首/末孩子固定窗口、每孩子三条原始腿、Norm或P方向。
2. **JH50-v1：保留旧结束门的联合覆盖。** 即使取消贪心重启、容许所有事件切点，若保留原同层目录、P/U/D分类和RC49局部结束门，e23要完整覆盖到e16仍被迫产生 U→U；镜像 D→D。加原义接续后分区全集为空。仅把尾留在e8仍可行，但没有完成所要求的扩张交接。

两个结论都限定于明写的桥类。左扩父支撑后的三片严格几何对照实际存在；改变未确认分析视图的核心目录、成员或完成规则也没有被本轮否定。没有靠新增 pending 名称宣布修好，没有签发新的原义完成对象。

## 1. 冻结条件与输入

[桥类冻结定义](candidate-evidence/handoff-classes-v1.md)先于本轮程序运行写入。它不是原义充分公理化；尤其“旧RC49目录在当前新分解中仍完备”是**候选限制**，不是教义。

输入固定为 Stage49 的 `same_up_counterexample.json` 与 `same_down_mirror.json`。原40事件、初态、W观察、腿与已封实例字节不变。截止t只读 `sealedAt≤t` 的实例，另核其全部成员和退出支持的可知时刻不晚于t。没有把完整文件中的未来核心提前放进前缀。

每个新片段保存 `(a,b]` 原事件、`B_a…B_b` 状态支撑、实际首末值和完整range；每个核心另存q/W两尺度的core、outer及实例成员，不继承Stage49未显式保存全对象W字段的过宽说法。镜像通过 `700−x` 的原词及同一真实订单协议给出，不只是反向改标签。

同层完整Move各至少一枚自有本级核心、同层构成核心不复用；跨层父子引用同批低层来源仍允许。我们未假定原核必须分别放在三个孩子的第一和第三份；也未要求原始端点已是全范围极值。

## 2. 来源约束：扩张形成、具名承接、父走势完成分开

源义工位的 [扩张承接合同](expansion-handoff-contract.md)已给出对应区分。本工位另读实际原文，并采用下述范围：

- `020:32,44,52–58` 在真正前后同级中心与Zn指标的语境中，给出更高级中枢**形成**。不能一面完整授予这些前提，一面因程序缺证书把源义形成降成“可能发生”。本轮旧RC49区间实例并未取得全部这些原义前提。
- `035:18,20,22–24` 要求完整下层走势的经过范围，并允许具名结合重分；其例子先有B1/B2/B3的资格，不由括号创造资格。单个本级Move不能含高一级中枢，故“把两个核合一个ID，再继续原level0 U”也没有自动获准。
- `049:138` 的连接具有相应次级别身份和三类点来源；不是任意连接腿。它不能让e9那一条原始腿凭名字升级为完整level0 Move。
- `017:1150` 说高级核形成时本级也可看成一个核，`057:40` 有从1234改按3456观察的具名重分。它们支持保留旧证据而改变分析视图，**不支持永久把旧目录当新视图唯一完备目录**；也没有授权将高层对象直接降级送回旧F₂。
- 一核P仍以完成为前提，P本身无概念方向。038的操作P+P许可不自动证明固定自然F₂闭合；本轮没有加入“所有P/P皆非法”的门。

020没有给出 `父core=两个outer交集` 的一般公式。下文把这项交集只记为数值扩张诊断，真正F₂ core 必须由具名三孩子的完整range重算。

## 3. EHL50-v1：局部两核区域的任意三切分均失败

在e15已知的K1/K2上，局部父候选 `H12` 的精确载荷如下：

| 字段 | 实际值 |
|---|---|

| 状态支撑 / 自有事件 | B5…B12 / e6…e12 |
| 实际起末q | 1140→1136 |
| 全部来源range | [1100,1140]；W=[11320/111,11728/115] |
| 扩张对 | K1/K2，两枚level0实例，源区间分别B5…B8、B9…B12 |
| 中间连接 | e9，完整保留 |
| 数值扩张 | K2.ZD=1136>K1.ZG=1130，K2.DD=1135≤K1.GG=1140 |
| outer相交诊断 | [1135,1140]，**未当作已证F₂ core** |
| 原义完成孩子 / 父完成证据 | 均无；输出保存失败证书，不填true |
| 局部区间外来源 | e1…e5与e13…e15保留；没有因提升而删除 |

e15在这里表示“两枚实例按RC49自己的封口政策均可读取”的核算时刻，不是宣称原义高级核必须等到e15才形成。源义工位已指出，其部分数值在e13便可见；本轮不把候选封口政策升为中枢成立的sustain门。

**普通证明 EHL。** 假设局部区间内只有完整目录中的K1、K2两枚可供level0孩子拥有的实例。若存在三个完整level0孩子，每个至少拥有一个该级核心，且同层构成核心不复用，则从三个孩子各取一枚自有核得到三个不同目录元素。但目录只有两个，矛盾。三个孩子可以是任意长度、任意原事件切点、任意P/U/D；证明不需要指定Ci属于第一孩子、Cj属于第三孩子。正常跨层嵌套不影响三个**同层孩子**之间的计数。

程序在B5…B12的全部15组 `5<a<b<12` 双切点上实际检查，得到0份满足每孩子至少一核、核不复用及目录覆盖的三片。e23的K3/K4区域B13…B20、e31的K5/K6区域B21…B28各同样15组/0份；镜像全部相同。这里不是拿7事件或7腿去套旧“至少9成员”门。

该矛盾排除的是下列合取：

`局部pair-hull支撑 + 旧level0目录在新视图仍完备 + 三完整level0孩子 + 每孩子自有核 + 同层不复用`。

它没有反驳020；若源义前提全部成立，却与这组承接假设不相容，应改查目录身份/完备性或支撑提取，不能说真扩张未形成高级核。

### 左扩实际打开了必要几何空间

将父支撑向左扩大为B0…B12，引入K0，不预留旧M0为不可分孩子。任意双切点共55组，恰4组可分为三个各一核的必要片段，其中2组严格三交成立：

| 切点 | 自有核 | 三份真实range | 父三交 | 实际端价净方向（仅诊断） |
|---|---|---|---|---|
| 0→5→8→12 | K0 / K1 / K2 | [1000,1140] / [1100,1140] / [1110,1140] | [1110,1140] | Up / Down / Up |
| 0→5→9→12 | K0 / K1 / K2 | [1000,1140] / [1100,1140] / [1135,1140] | [1135,1140] | Up / 无净方向 / Down |

另一两份切点0→4→8→12、0→4→9→12的首段最高1040，与后续range不能严格三交。所有连接事件都在这些真实range中；例如第一条正面对照首孩子包含e5，最高1140。

两份严格结果都只是 `kindIfCompleted=P/P/P` 的必要关系，未签完成。第一份虽有端价净方向交替，也没有因此取得P参与Z3的原义桥；第二份中间端价相等，更不能强填Up/Down。它们还改变了旧M0对K0/K1的独占归属，因此**不能同时声称保留原e15的M0完成声明**。本轮保留旧记录，只把新分区作为独立未发布视图。

这两份对照说明本例不能被写成“任何分法几何都不够”。它们也说明020诊断用的outer交集不会唯一指定父核范围：不同必要子分解得到不同三交，只有真正合格的下层分解才可决定哪一份是原义父核。

## 4. JH50-v1：联合求解保留旧结束门仍无完整覆盖

这一类已经不作RC49那条贪心重启。它允许对指定前缀所有事件边界、任意块数联合求解，但保留下列**必要条件**：

1. 每块拥有连续、专属的旧目录实例；一核才可能P，多个核必须逐一按outer同向分离才可能U/D。
2. P必须有下一枚已封outer重叠核心；U/D必须有下一枚已封且不再沿旧方向延续的核心。这保留RC49实际的后继成熟门，**不**用“最后还有一枚锚”代替结束证据。
3. 作为原义相邻完成对象，不得U→U或D→D；不额外禁P/P。

我们把第2条仅当完成必要条件，所以搜索关系实际比“这些对象确已完成且端点正当”更宽。宽关系若已为空，任何保留这些门的更强完成关系也不可能给该目标覆盖。这避免了把无证据的P真值塞进求解器。

### e23的普通证明

截至e23，K0…K4均已封。要求消费到e16，故必须覆盖K0、K1、K2、K3，K4只作后继证据。关系串是：

```text
K0 --Up--> K1 --Overlap--> K2 --Up--> K3 --Overlap--> K4
```

第一块必须拥有K0。它若只含K0，P的必要结束门失败，因为下一K1仍严格上方。它若含K0/K1，是可能U，并由K2重叠给结束门。它若再含K2，便既不是一核P，也不满足逐核同向趋势。因此第一块的自有核强制为K0/K1，类型U。

剩余第一核K2同理：只含K2时下一K3严格上方，P结束门失败；包含K2/K3得到U，由K4重叠给结束门。因此后块强制为K2/K3、U。两块连续覆盖到e16，得到U→U，违反第3条。任意事件切点不能改变这条核心串推理。镜像全部换为Down，证明不变。

程序还把原事件边界全部枚举出来：若暂不加第3条，恰有两份切分 `0→8→16` 与 `0→9→16`，两份都为U/U；加后为空。可见无解不是强制旧e8切点造成，甚至让e9连接事件归左也不能解决类型接续。e9归左的第一份range仍按真实路径重算，不假装原M0已经包含它。

| 可知前缀 / 消费终点 | 保留类型及旧结束门，不查U/U、D/D | 加原义同向接续限制 |
|---|---:|---:|
| e15 / e8 | 1份，U | 1份必要候选 |
| e23 / e16 | 2份，均U/U | 0份 |
| e31 / e24 | 4份，均U/U/U | 0份 |
| e23 / 仍只到e8 | 1份，U | 1份必要候选，其余全部尾部 |

“必要候选”始终不是原义完成验收。表中的e15 U保留真实范围[1000,1140]、成员e1…e8、专属K0/K1和K2在e15可知的结束门；没有用可继续增长的末活动U制造反例。

允许e23停在e8确实仍有完整来源归属：前段e1…e8，尾e9…e23，尾的原状态、q/W全范围和已封K2/K3/K4都保存。我们没有将这个活动尾判为非法，更没有要求每个有限前缀都完成。但它未交出向上所需的新三完整或新P/反向走势，不能用“已经保留pending”冒称本次交接已完成。

## 6. 与旧反例的区别及必须改变的条件

Stage32的两个障碍是：给定原子层三孩子各至少3名成员时7不足9；或旧两窗口分别完整位于首末孩子时中间最多1原子。Stage33补该骨架的直接订单可达性，Stage38加强输入为有原段结束证据仍击中九段固定包窗的严格三交。它们不被本稿重命名。

本轮EHL只要求每个完成孩子至少一个**本级核心**，直接允许所有事件切点，不假定每孩子三条原始腿，也不指定旧核在哪个孩子。JH则从局部贪心算法的单次失败推进到**保留固定目录/旧结束门的全分区空集**。它们回答了“只换成联合求解或局部升层能否修复RC49”的具名问题。

下一构造至少须在对应路线实质改变以下之一，并重新取得证据：

- 保留旧目录时，局部pair-hull承接必须扩大支撑，或者原先对可用完整孩子的角色解释有误；本轮已给左扩的严格几何对照，但完成尚缺。
- 保留同级目录与指定消费目标时，不能继续完整继承RC49的P/U/D局部结束门；仅改优化目标、First/Last或多等一个已封锚不能改变e23的强制U/U证明。
- 若改变当前分析目录或级别承接，须保存旧实例证据并给新视图的成员、核身份与三完整来源；不能把“本级也看一枢”改成将高层H降级后继续旧U。
- 若新分解需要移动K1、拆开或改级旧M0，须明确撤销RC49那项完成声明，不能一边改自有成员一边宣称此前已发布对象稳定。

这些是由反例导出的分叉，不替用户决定生产路线。也没有推出所有候选都必须某种固定首/末孩子模板或标准形。
