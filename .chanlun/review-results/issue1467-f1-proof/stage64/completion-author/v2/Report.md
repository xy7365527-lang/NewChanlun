# C64 v2：有限证书的前沿扫描表示定理

研究票1467，2026-10-05，修订作者稿，待新上下文复审。只替换旧C64的采用口径；原Report.md、EQ64、旧数值与证据包保持冻结。

## 1. 修订结论及范围

独评R1–R4成立。原C64没有证明全序列结论，本版不再援引它。下面给出明确扫描算子S和条件定理C64v2：固定自然数事件索引、锚点和读法后，有限证书检查、跨ID前沿唯一、源义可靠/覆盖、目标可达性及全承重解释稳定足以使S产出唯一、前缀稳定、最终覆盖目标的完成序列。Own的不重不漏由算法输出区间归纳得出，不作为输入假设。

这些是**本表示定理的充分前提**。本包没有证明实际订单Ω满足它们；有限可枚举证明包也不被宣布为一切合法F₁的必要条件。语义End只是证明中写明“程序应表示什么”的关系，程序不调用End、不需要独立外部Iref或oracle。语义关系可以在同一数学模型中由原文规则解释，不能反过来定义成“扫描器恰好输出的东西”以空转地证明覆盖。

本版只检验独评给出的两个局部压力例，不新增行情、F₁源义实例或EQ64数值实验。

## 2. 精确载体、身份和目标

### 2.1 历史、锚点与支持范围

预先固定合法完整历史集合Γ（成员可为有限终止历史或无限分支），令Ω恰为Γ成员的有限前缀集合，因此每个输入前缀都有合法完整延长。H_k=(e₁,…,e_k)，k∈ℕ；状态0为起始状态。H_k≼H_l指相同的前k条事件及同一配置，l≥k。价格、时间戳等字段可以为别的数域，但本定理的前沿、端点、支持位置与依赖秩全部用自然数。

固定配置ρ，包含读法、层级q、材料/速度/端点约定；固定启动锚s₀∈ℕ。算子只从k≥s₀调用。前导上下文H_{s₀}必须明确提供且不可变，其事件属于支持上下文，不属于本次输出区间。输出范围从(s₀,k]开始。中途启动若需要更早证据，输入必须保留那段证据；缺失不能假定存在。双向无限历史不在此定理范围。允许不同运行选择不同s₀，但不能在同一运行追加后悄悄移动锚点。

原始引用是确定的索引引用i↦e_i，没有预先给出任何完成对象的归属或分区。以后Own(X)将由已证边界构造，而不是输入唯一分区。

### 2.2 前沿身份独立于未知终点

对每个s₀≤s≤k，活动身份固定为I(s)=(ρ,q,s)。身份不含待求u，不随当前k变化。临时ID、证书ID、发现路径只是别名；只要ρ/q/s相同，必须归入同一个前沿桶。不同读法或层级不在同一桶，也不在同一输出序列。

`Active(H_k,s)`是总定义、单值的候选状态读法，允许“尚无核/未取得类型/等待证据”；不是完成记录。活动状态可随新事件变化，禁止靠“发布后冻结”的操作代替源义稳定证明。

记录R=(I(s),u,F)中，u是证书提出的结束点，F是全部承重的**完成态解释**：完整中心目录及成员、类型、实际比较臂角色、价格/力度端点约定的标识、语义读法等。R不包含任意临时证书ID或“最先找到哪份证明”的选择。Own_R在输出时定义为事件索引集合{s+1,…,u}。若解释需要更多字段，必须纳入F及后述稳定/一致性要求，不能躲在日志里。

### 2.3 目标语义与真正可达域

对合法完整分支h定义同读法目标关系E_h(s,u,F)：来源语义认为从I(s)开始的这个对象恰于u结束，完成解释为F。h可以是无限分支；有限终止历史也可作目标h，但其覆盖前提要求支持真的在其长度之内。**E_h不可调用扫描S，也不可由S的输出定义。** 它不必是外部系统或另一个解析器；它是本模型中的语义规范。

定义Reach_h是下列归纳规则生成的最小集合：s₀∈Reach_h；若s∈Reach_h且E_h(s,u,F)，则u∈Reach_h。定义整个选定读法的目标域T_h为本次启动范围内所有需要报告的源义结束。要求T_h的每个目标确实具有一个s₀出发的**有限E路径**；并且T_h恰为从Reach_h出发的E边。这个前提禁止把另一个横向读法的重叠对象混进本序列，也禁止程序只覆盖自己的成功样本后再缩小T_h。

Reach是语义关系的有限路径可达性，不是扫描器的实际到达集合；二者相等要在第5节证明。我们不预设T_h已是唯一分区、不预设E的端点唯一，也不预设对象数有限。

## 3. 表示定理的明确前提

以下对配置ρ固定后的Ω及目标h普遍量化，不得为当前检查失败的历史临时删域。

**H1（有限搜索和检查总性）。** 对每个H_k和s₀≤s≤k，有可计算的有限自然数界b(H_k,s)。按代码0,…,b解码有限规范候选；每个解码/检查终止并返回拒绝或一份R及有限证明树。无外部End调用。拒绝不是“换宽松规则再试”。每份接受证据只能引用0…k的实际前缀、已列明配置与证明树；u必须满足s<u≤k。检查器实际核#873值及相应规则前件，不接收调用方的完成Bool。有限界可以来自结构候选/证明语法的规范化；本包尚未为实际Ω造出这种规范化。

**H2（良基求值而非空泛无环）。** 证据/结构解释的每个求值节点有秩(ℓ,j,d)∈ℕ³，以字典序比较；每个实际递归依赖严格下降，每节点依赖列表有限且能总定义地取得，所有非递归原语为总函数。证明树中用到的源角色、核构造、比较臂、速度和已结束b等全部列为依赖；不得藏一条对当前I(s)完成的反向依赖。初始材料是秩最底的原始解释节点，允许没有更低走势类型。ℕ³字典序良基，具体构造的总性由此归纳得到。H1的有限枚举界与H2的节点总性是不同假设，互不代替。

**H3（跨ID和跨前缀一致）。** 记A(H_k,s)为H1得到的全部接受记录的集合，按R的语义值而非证书ID去重。要求它至多含一个R。并要求扩展保持：若R∈A(H_k,s)且H_k≼H_l，则R∈A(H_l,s)。这不仅保持u，还保持F里的全部承重解释及其真实来源资格、已确定核角色和端点语义。等价实现方式是已接受规范证明在扩展中可重放且仍可发现。H3跨ID地合并同一s；只证明每个临时ID内部唯一不够。每个前缀内唯一加扩展保持，推出任意两时刻接受的记录相同。

**H4（源义可靠）。** R=(I(s),u,F)∈A(H_k,s)时，对每个合法延长h≽H_k，都有E_h(s,u,F)。这包含原B-L/B-D/B-S：真实材料到实际速度、规则的全部角色前件、所结束对象与u，以及035趋势结束时关联的后继转向核和NE。来源支持可以晚于u，但全在H_k。P不用普遍补同级TrendDiv；它使用真正适用的证书。035没有给精确u，u的来源定位必须独立证成。

**H5（有限发现覆盖）。** 对T_h中每个E_h(s,u,F)，存在有限r≥u，使H_r≼h且该R∈A(H_r,s)。若证书的原始最大支持为m，仅有m有限还不够；必须保证检查/规范枚举确实在某个有限r找到它。这里r可能>m，可包括确定解释所需后续材料，不能在算法里把未知证据先补真。对有限h必须r≤|h|；无限分支不要求每个I(s)最终结束，只对确实存在目标结束的对象要求此项。H5不是把Ω缩成已发现证书的历史。

**H6（目标域与Next）。** 满足2.3的完整目标可达性。`Next(ρ,q,s,u)=I(u)`和Active(H_k,u)均总定义、单值，u>s。并须有来源解释证明：对该读法的E边，I(u)是前对象之后的真正直接活动身份，而非任意重启ID或转向核本身；同读法连续关系没有被中间另一目标对象跳过。这是局部“从结束点接续”的语义前提，不输入整个唯一分区。I(u)没有被自动赋予完成、方向或固定F₂孩子资格。

来源定理怎样推导H3–H6，是具体F₁的实质研究任务。本表示定理只证明这些前提成立之后的序列结论，不能通过设置字段为true声称前提成立。

## 4. 前沿扫描算子S

以下是纯前缀算子。每次可从s₀重算，或用已证明等价的增量缓存；不会查询E_h。

```text
S(H_k):
    require k >= s0
    s := s0; output := []
    loop:
        records := distinct semantic records A(H_k, s)
        if records is empty:
            return (output, frontier=I(s), buffer=(s,k], Active(H_k,s))
        if records has more than one element:
            return ContractConflict(s, records)   # 无有效表示结果
        R := its unique element (I(s),u,F)
        if not (s < u <= k):
            return ContractConflict(s,R)
        append R with Own={s+1,...,u} to output
        s := u                       # 唯一Next的左界
```

冲突分支用于把违反H1/H3的输入报告为合同失败，绝不从不同终点中选最小、最大或“更可靠”的一个放行。返回冲突时该次调用不发布其临时output。有效前提下不会到此分支；它也不能保护尚未被证实H3的候选免于将来反证。

**连续就绪前段。** 只检查当前s的可用记录；即使别的s已有证据，前沿未到达它就不发布。设最终语义链第n条边的内在就绪时刻r_n为它首次出现在A(H_k,s_n)的最小k；则有效发布时间是K_n=max(r₀,…,r_n)，不是单独r_n。一个调用可以连续发布多条已就绪边。

**尾部消歧。** buffer=(s,k]只是尚未发布的原始事件缓存，不是“一个已知仍未完成对象的Own”。它可能已经含多个真实结束但尚未按序确认的对象。frontier=I(s)是唯一下一待判身份；其真实终点尚未受证时不得把整个buffer归它。完成Own只在u受证后派生。若buffer空，Active(H_k,k)是等待新材料的空候选，不是零长完成对象。

**类型时序。** Active可在核出现时显示发展态P/U/D或尚未取得类型；该读法须总定义，但不主张发展态不变。完成类型只随F受证发布，其延伸稳定由H3/H4支撑。真正Next独立形成自身核和证书；等待前段不使缓存中的后段自动成为F₂输入。

## 5. C64v2及完整证明

**定理。** H1–H6成立时，S对每个H_k总是有限终止，产生唯一结果；输出边界严格前进，记录各有源义结束；完成Own两两不交，与唯一缓存一起覆盖(s₀,k]；合法前缀扩展下完成记录列表为前缀关系；对每个固定h最终准确覆盖T_h，并按连续就绪最长前段发布。这里“唯一结果/分解”指固定ρ、q、s₀及目标读法，不主张跨读法唯一。

### 5.1 求值总性和扫描终止

对ℕ³字典序作良基归纳。叶子调用总定义原语；节点只有有限个严格低秩依赖，各依赖按归纳假设终止，结合函数总定义，所以该节点终止。于是每个候选检查终止。b有限，A可由有限循环算出。H3排除冲突，H1给每次成功u>s；自然数势能k−s每次至少减1，因此成功轮最多k−s₀次，最后必返回。s=k时不可能接受u>k，所以必返回空buffer。有限无环这个弱条件没有被单独当总性证明。

### 5.2 跨ID边界及语义唯一链

先证明E在可达s上的唯一性，而不把它预设为唯一分区。若同一h及s∈Reach_h有两条目标E_h(s,u,F)、E_h(s,v,G)，H5各给有限r、r′。在共同前缀H_max(r,r′)中，H3延伸保持把两记录都带入同一A桶；H3单值性迫使(u,F)=(v,G)。有限h同样成立，因为两支持都在h内。故每个可达s至多一条目标边。

以对象序号n作归纳：s₀固定唯一；若s_n唯一且有目标边，刚证的性质给唯一(u_n,F_n)，令s_{n+1}=u_n。若没有边，链停于这个唯一活动身份。每一步u_n>s_n由H5和H1得出，故边界严格增加。由Reach的最小有限路径定义，每个可达s都在这条归纳链上；H6的T范围保证没有另一条不可达但同读法应报告的结束被漏掉。若换读法则应另起配置，不能加入本链。

### 5.3 扫描的可靠性和无跳过

对S的成功轮数归纳。起点是语义链s₀。若轮首s=s_n，接受R由H4是E_h(s_n,u,F)；5.2唯一性保证它正是第n条目标边，H6保证Next=I(u)是直接后继，故新前沿s_{n+1}。空A时停止而不试别的s，因此不会越过任何等待确认的前对象。输出全部属于T_h；完成解释F也由H4取得源义，而非仅有数值边界。

### 5.4 Own不重不漏由区间归纳推出

初态output空、buffer=(s₀,k]，覆盖结论成立。假设已输出区间依次为(s₀,s₁],…,(s_{n−1},s_n]，两两不交，其并为(s₀,s_n]。新u=s_{n+1}>s_n，把旧buffer=(s_n,k]分成不交的(s_n,u]和(u,k]；前者成为新Own，后者为新buffer。于是归纳不变量保持，全部事件(s₀,k]恰覆盖一次。前导上下文[0,s₀]仅为支持，不进入Own。证据引用可重用既有或后继事件，不等于事件所有权重复。

这一步只用自然数半开区间及扫描相邻边界；没有假设输入已给唯一完成对象分区。

### 5.5 完成列表的前缀稳定与全承重解释保持

固定H_k≼H_l，对S(H_k)输出轮数归纳。首轮在同一s₀。旧轮接受的R由H3仍属于A(H_l,s)，后者至多一份，故新扫描必须接受相同R，包括u、F及由u派生的Own，不能插入一个较早不同终点。前沿因此同为u，下一轮重复。归纳得S(H_k).output是S(H_l).output的前缀，新调用只能在旧末前沿之后追加。

语义稳定没有藏在程序“冻结”动作中：H3要求核角色、对象身份、实际力度/端点等所有承重解释在真实合法扩展下保持；H4保证同一记录在每个延长分支仍为源义结束。发展态Active和buffer不在完成列表稳定主张内，它们随新材料变化。

### 5.6 最终覆盖与就绪时刻

以固定h的目标链序号n归纳。H5给第0条的某有限发现前缀，故其最小r₀存在；S在r₀从s₀直接取得它。假设前n−1条最晚在K_{n−1}发布，第n条最小r_n有限。令K_n=max(K_{n−1},r_n)，H3确保前面每条和第n条的证据在H_Kn均存在，S逐前沿走到s_n并输出第n条。所以每个有限序号目标最终发布；H6使这覆盖T_h的每个目标，不限于程序先前成功到达的子域。

反之第n条在k发布，算法此前必已连续发布0…n−1；每条都有接受记录，故k≥r_i（i≤n），所以k≥max_i≤n r_i。两向合起来，最早发布恰为K_n。S(H_k)因此是满足所有r_i≤k的最长连续前段，不按证据到达顺序重排。自然数严格端点及u≤k使任一有限前缀的输出有限，即使h有无限多目标也不发生有限时刻无限循环。

若当前前沿在h上永不结束，没有E目标就不触发H5存在要求；H4禁止伪造证书，算子保持待判缓存。没有把永不结束当工具错误，也没有要求无穷历史必须产生无穷完成对象。

## 6. 两个局部压力例的修复演算

`scan-check.mjs`实现第4节的记录级扫描，候选表模拟已检查的有限证据到达；它不实现缠论源义检查，不把这些表认作满足H4/H5的市场模型。唯一用途是检查R1/R3的序列机制。

**例一：同左界两个临时ID。** 在k=2，X给(I(0),1,F₁)，Y给(I(0),2,F₂)。旧“每ID一终点”逐个成立。新A按I(0)而非X/Y分桶，得到两份不同语义记录；扫描返回`ContractConflict`且本次发布为空。不能选择1放行，也不能把Y改成I(1)悄悄重解释。另检相同记录的两个证明ID只去重为一条，说明冲突针对语义内容而非证书数量。若错误证据到更晚才出现，这属于H3延伸稳定/一致性被反证，前提失效；本算法不能把未经证明的前提变成永不出错的保证。

**例二：后段先就绪。** X=(0,1]在r₀=5就绪，Y=(1,2]在r₁=2就绪。k=2时，扫描只看s₀=0，A为空，输出[]；Y可以缓存在别的桶，但不发布。k=3/4仍[]。k=5时先取X，将s设为1，再取已就绪Y，输出[X,Y]，Next=I(2)，buffer=(2,5]。因此K₀=5、K₁=max(5,2)=5；[]是[X,Y]的前缀。k=2的buffer=(0,2]不能被冒称一个已知未完成对象的Own。新增事件3…5是支持/缓存材料，并不归入X或Y的Own；在这个记录级控制中没有给它们额外源义。

小检验还逐k核半开区间覆盖与完成列表前缀，确认旧的“各对象r就发布”会得到[Y]→[X,Y]且非前缀。没有重跑旧EQ64检查或旧行情。
