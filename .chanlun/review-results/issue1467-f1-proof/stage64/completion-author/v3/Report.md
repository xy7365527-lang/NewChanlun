# C64 v3：有效记录表示与完整扫描程序总性

研究票1467，2026-10-05，ER1修订作者稿，待独立审查。本版是v2的有效性补定理，旧各版本冻结不改；v2已审通过的集合论六段证明和H3/H5/H6强假设全部保留。

## 1. 结果与准确适用域

ER1成立：有限候选不保证其输出的任意语义值相等可判，“Active是总函数”也不保证有求值程序。本版选定一个具体的有限树记录值代数V，给出规范化N、编码C、判等及桶去重程序，证明它们对V的值相等可靠且完备；另给具体Active₀程序。由此，在下列有效前提和v2的H1–H6成立时，v2完整扫描S的每一步（含去重、冲突检查及Active返回）都是可计算、终止的。

这里V是**每个值均由有限数据组成的可数载体**，不是说所有可能记录只有有限多个。每个前缀上候选有限仍由H1承担。

本定理把v2抽象F的载体具体实例化为V，F相等明确是下面的带类型、按位置的数据值相等。**这不是任意原文表述的等义判定，不是有限程序的行为等价判定，也不是可计算实数的相等判定。** 这些对象不进入V。不能把无法表示的源义字段删掉以通过检查。

实际订单Ω是否能把全部承重F忠实表示于V、能有效地产生完整证书以及满足H3/H5/H6仍未证明。本版也不把V或有限证书架构规定为所有F₁的门槛。

## 2. 明确载体与规范编码

### 2.1 值与相等

取带标签的不交和，按有限树归纳定义：

```
V ::= Nat(n), n∈ℕ
    | Int(z), z∈ℤ
    | Rat(q), q∈ℚ
    | Bytes(b), b为有限字节序列
    | List(v₁,…,v_m), m∈ℕ且v_i∈V
```

同标签叶子的值按其数学值相等；List按长度和逐位置值相等；异标签值永不相等。因此Nat(1)、Int(1)、Rat(1)是不同记录值。记录schema必须固定字段类型，例如价格字段都用Rat，不能一张证用Nat、另一张用Rat再期待自动合并。列表次序是本载体语义的一部分；无序集合若需表示，另须给有效排序/规范代表并证明对应，不能靠本报告自动获得集合商的判等。

可编码的完成记录R固定为六元组：

```
(schemaTag:Bytes, ρ:Bytes, q:Nat, s:Nat, u:Nat, F:V)
```

schemaTag为本版本固定字节串`C64v3-record`，ρ标识固定读法及配置。临时证书ID不在R中；它可以留在外层证明收据。所有v2承重字段必须在F内以固定schema表示，例如类型标签、按源序列出的中心/成员索引、角色记录、端点有理数、速度读法标识。这里列举说明表达能力，不声称现行源义对象已被完整编码。

### 2.2 可接受的原始有限表示

程序入口是有限JSON树，无引用、无函数、无循环对象；叶子数值一律用十进制字符串，禁止IEEE浮点代替精确整数。允许原始形式如下：

- `["n", digits]`：非空十进制数字串；允许前导零。
- `["z", integer]`：可有一个前导负号的非空十进制整数字符串；允许负零和前导零。
- `["q", numerator, denominator]`：两串同上，分母非零，正负号均可。
- `["b", hex]`：偶数长度十六进制串，允许大小写，空串表示空字节序列。
- `["l", [node₁,…,node_m]]`：有限列表。

每种构造子精确检查长度和字段类型；未知标签、额外字段、零分母和非法数字必须返回EncodingError，不能略去坏字段后继续。记D为通过语法及非零分母检查的这些有限树，Val:D→V按2.1解释。

### 2.3 规范化N与序列化C

N对树结构递归：Nat/Int用精确任意精度整数转无前导零标准十进制，整数零总写`0`；Rat先把分母变正，再以gcd(|a|,b)约分，零规范成`0/1`；Bytes转为小写hex；List保持顺序并逐项N。输出仍用上述标签，但各叶子已标准化。

C(x)是N(x)的无空格JSON序列化。规范树只含数组和来自有限标签、十进制字符、小写hex的ASCII字符串，故序列化无依赖locale、浮点舍入、对象键序或隐含Unicode规范化。编码无需哈希，判等直接逐字节比较C，哈希只用于文件冻结。

**正规形定理N。** 对所有x,y∈D：

1. N终止且有效可计算，N(x)∈D；
2. Val(N(x))=Val(x)，N(N(x))=N(x)；
3. `C(x)=C(y) ⇔ Val(x)=Val(y)`。

**证明。** 自然数/整数十进制转换和比较是有限整数算法。欧几里得gcd每轮余数严格小于上轮正除数，因此终止；非零有理数唯一的正分母互素表示给Rat规范形的唯一性，零统一为0/1。每个字节有唯一两位小写hex，因此Bytes唯一。对有限树节点数归纳：叶子已证；List只有有限个更小子树，逐项终止，顺序及长度保留。两List值相等当且仅当各对应子值相等，归纳得到正规形逐项相同；异标签不可能正规形相同。故N保值、幂等，且正规形相同当且仅当值相同。最后规范树的JSON编码可按JSON数组/字符串语法唯一解析回同一树，故编码相同当且仅当正规形相同。合并得到3。证毕。

这实际证明了可靠性（同码不误合并不同V值）和完备性（相同V值不会因2/4与1/2等写法不同而误报冲突），没有凭“canonical”一词代替证明。

## 3. 从所选F到原v2语义的边界

v2的集合论定理可以直接实例化在F=V、R为上述六元值元组；H3中的“语义记录相等”在这个实例就是2.1规定的数据值相等，不再是未指定的等价关系。H4仍须证明这些记录字段对来源对象的解释是真的，H5仍须覆盖所有目标，不因编码成功而成立。

若另外已有一个抽象F_old及等价关系≈，希望将其接入本有效实例，则必须额外提交忠实桥J，至少满足：

- 每个所需目标/接受记录的完整承重F_old有可取得的有限编码x∈D；
- `J(Val(x))≈J(Val(y)) ⇔ Val(x)=Val(y)`，对本次所需编码的像成立；
- E_h、H3稳定性、H4可靠性和H5覆盖沿J保持，不能丢掉区别承重对象的字段。

第二项是相等反映与保持，不能仅证明“相同编码表示相同旧语义”就称完备。若旧语义允许任意程序或实数表达式，未必存在这种有效忠实桥，本报告不声称存在。选V作为定理实例不等于替实际Ω自动补出了J，也不许可删去无法编码的目标。

## 4. 去重、冲突和Active的具体有效程序

### 4.1 完整记录规范化与桶

`RecordCode`检查输入精确含ρ、q、s、u、F五字段；加入固定schemaTag，把它们编码成六元List值，再用C。s/u等位置以Nat编码，比较使用任意精度整数。无额外承重字段被忽略。证明ID只能在记录之外，若放入记录输入则拒绝，避免被偷偷当成F或者偷偷删除。

给H1返回的有限接受记录数组L，依次运行RecordCode；坏编码返回EncodingError。对合法项，用码串完全相等去重，保留不同规范码的有限数组。没有用概率哈希决定相等。

**桶引理。** 此程序终止，并且去重后码串集合与`{R的V值:R∈L}`一一对应；因此零项、单项、多项判定分别正确表示抽象A为空、单点或冲突。

**证明。** L有限，每项规范化按定理N终止；每个新码最多比较此前有限多个码，有限ASCII串比较终止。定理N排除误合并与漏合并，记录六元组是List故同样适用。计数只数有限数组长度，因此三个分支正确。证毕。

此处能发现的是**本次有限接受结果内的值冲突**，不是判定全未来是否满足H3、不是辨认H4真假，也不是判断任意两句原文是否等义。坏编码属于表示接口失败，不能作为“没有动力学证书”正常停止。

### 4.2 Active₀的有限、可计算返回值

为本有效表示定理固定一个保守但实际有内容的活动接口：

```
Active₀(H_k,s) =
  (I(s), observedThrough=k,
   status=EmptyBuffer 若s=k，否则 AwaitingEvidence,
   bufferLeftExclusive=s, bufferRightInclusive=k,
   bufferedEventCount=k-s)
```

每个字段都用V里的Nat/Bytes/List。I(s)=(ρ,q,s)；k由已解码有限事件列表长度取得，先检验0≤s≤k。程序不运行任何End谓词，也不试图判断buffer是否已含未报告的完成对象。`AwaitingEvidence`表示扫描暂停后前沿仍待判，不声称“真实对象尚未结束”或“尚无核”。该接口实际返回身份、观察范围和缓存大小；不是返回一个等待无限求值的表达式。

**Active引理。** Active₀在合法输入上有效可计算、有限终止，并准确给出上述描述值。证明：有限列表长度可通过一次有限遍历取得；Nat解析、比较、减法是终止整数算法；只构造固定数目的有限叶子和列表，N及C按定理N终止。无递归的源义识别调用。证毕。

Active₀实例化v2允许的待证候选状态，不给发展态P/U/D提前认证，也不削弱完成F的类型、角色或一般动力学义务。若消费者还要求实时发展态分类，应提供一个额外有效分类程序及正确性证明；该新增接口不在本次Active₀结论内。

## 5. 对v2有效前提的准确补充与完整扫描补定理

保留v2全部H1–H6（尤其H3、H5、H6不削弱）。加入如下限制：

- **E1输入/记录表示**：每个输入事件和配置是明确可解码的有限数据，所有扫描读取的索引和数值操作有指定有效程序；接受R落在第2节的有限载体。实际来源价格若不在ℚ等已给类型里，必须另给表示桥，不能直接代入本例。完整记录与语义解释不得含未列明的函数/不可判商。
- **E2求值有效性**：H1的界b、枚举、解码、检查器都以有效程序给出，并在其声明域内终止；H2节点依赖列表及组合原语也必须有效可计算、输出有限数据。v2只说“总函数”的地方在本可执行实例中加强为“有程序且经证明总”。有限低秩依赖的良基归纳因此证明的是程序终止，而不只是抽象函数存在。所有源义检查仍是需要实际提供并证明的参数，本包没有实现一套完整缠论检查器。
- **E3完整返回**：去重和冲突分支固定用4.1的程序；Active返回固定用Active₀；索引比较、Next、Own和buffer使用自然数有限数据构造。Own可输出区间对(s,u]，若展开索引列表，则u−s有限次迭代。不要为完整返回值另加未经证明总性的UI计算。

对v2 H3“等价实现方式”的措辞作版本内订正：旧证明在扩展中可重放且仍可发现，是H3的**一种充分实现方式**，不是必要方式。同一记录在不同前缀由不同证明获得也能满足H3；本版不额外强求旧树原样重放。

**定理C64v3-E。** 在v2 H1–H6及E1–E3成立的所选有限数据实例中，采用上述程序实现v2扫描S，得到有效可计算的完整返回值；每个前缀的调用有限终止。在合法前提下其完成记录经Val解释后恰等于v2抽象S，完整记录规范码亦唯一且前缀稳定。对任意有限候选桶，只要其检查器终止并返回此载体值，程序能正确报告该桶的编码失败或值冲突；这不验收全局H3及源义合同。

**证明。** 以扫描成功轮数归纳模拟v2 S。E2和v2低秩归纳给每轮有限候选检查；桶引理把码去重严格对应于抽象值集合，故空/单点/冲突三个分支与抽象分支一致。单点时解码R为同一u/F，Nat检查、Next及Own构造终止；势能k−s严格下降，与v2相同，最多k−s₀次成功轮。空桶时Active引理保证最后的返回也终止；冲突/编码失败为有限错误值，无半份正常结果。由此完整程序总性成立。

模拟归纳又说明在H1–H6合法域中输出语义值与已审抽象S相同，故沿用v2的语义链唯一、可靠无跳过、Own加buffer覆盖、目标最终覆盖及K_n公式，**不重证也不弱化它们**。对已稳定记录值，定理N的唯一编码使其码在延长前缀保持相同；v2语义列表前缀关系因而运输为规范码列表前缀关系。临时证明ID、发现次序不进入规范记录。Active和buffer随前缀变化，仍不纳入完成列表稳定主张。证毕。

这是数学上的算法终止证明，使用通常的有限输入、足够内存和精确整数计算模型，不是任意大小输入在固定硬件资源内必成功的性能保证。附属mjs展示具体算法与小检验；运行时资源耗尽须照实报错，不作为无证书或相等结论。

## 6. 新增检验与不变边界

`effective.mjs`实现N/C、完整记录编码、有限桶去重和Active₀；`effective-check.mjs`只检查本次ER1新增操作：

1. 有理数约分/负分母/零、带前导零整数、hex大小写、嵌套列表的规范一致；超过2^53的整数保持精确；异标签、不同数值与列表次序差异不合并。
2. 同一完整记录的不同有理数写法被合并；F值真正不同时给值冲突；非法分母/标签/额外记录字段报编码失败。
3. Active₀在空和非空缓存上给准确I(s)、观察范围、缓存大小；越界前沿拒绝。

这些检验不枚举原两序列压力例、不调用旧scan-check、不重跑EQ64或行情。具体计数及结果见effective-result.json；有限测试不是定理N对任意有限树证明的替代。

保留来源订正：035是**连续三笔同价交易**；084免前置递归与#865一般完成义务的结合是合读解释，并非084逐字陈述。EQ64及其全部范围保持不变。

本包允许复审采用的是选定有限记录实例上的有效性补定理；实际Ω的证书完整性、全部承重字段可表示性、H3一致保持、H4/H5源义桥、H6直接Next与可达性均未验收。没有把“编码可计算”升级成“源义结束可计算且完整”，也没有把外部Iref新增为F₁门槛。
