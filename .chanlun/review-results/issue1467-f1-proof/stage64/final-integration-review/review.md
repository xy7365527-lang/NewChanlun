## 2. 数学结论：有限树正规形与 ER1

**载体正确。** Report:19–49 用归纳有限树定义带标签不交和 V；V 可数且一般无限，每个元素有限。Nat、Int、Rat 不混同，List 保持次序，Bytes 以字节值为语义。这确实指定了要判的相等关系，而不是把任意函数或实数表达式的相等藏进“canonical”。原始输入限于有限 JSON 树；循环对象、函数、访问器、稀疏 JS 数组或非 JSON 对象不是这个接口域。

**Val/N/C 的终止及双向正确性成立。** Report:53–65 的整数转换是有限精确计算；分母非零后可化为正数，gcd 的正余数下降保证终止，零分子最终为 0/1。子树递归严格下降，有限列表逐项结束；故 N 有效、保值且幂等。各标签有唯一叶正规形，List 由长度和各位置决定正规形。规范 JSON 中无对象键顺序或浮点数，且可以唯一解析，因此 C 相同当且仅当 V 值相同。可靠性与完备性均有证明，不仅是有限测试支持。

**完整记录没有在本实例中被偷偷投影。** Report:31–37、83 规定固定 schemaTag、ρ、q、s、u、F 六元组，外部输入恰五字段。临时证明 ID 被明确放到外层；若混进记录则报错。F 可表示嵌套的类型、成员列表、角色和端点数据；但没有把“有表达能力”说成“已证明现行源义 F 都有此表示”。Report:69–77 对旧语义 F_old 要求全部承重内容可取得编码，以及 J 的等价保持／反映和 E/H3/H4/H5 运输；这阻止靠删字段或拆成不忠实标签掩盖 ER1。实际忠实桥尚未提供，是采用边界，不是此条件定理中的隐蔽假设。

**桶引理成立。** 每项正规化终止，有限数组上逐串比较终止；正规形定理保证既不误合并也不漏合并。empty/single/ValueConflict 正确对应当前接受值集合的 0/1/多值。编码失败单独返回错误，不能当作空桶正常继续。桶只判断眼前有限结果，不能证明全未来 H3，更不判断 H4 源义真值。

**Active₀ 已补实际求值。** Report:98–109 只返回身份、观察长度、缓存区间、计数和待证／空缓存状态；实现校验有限事件值后使用精确自然数减法并构造有限树。它不再返回任意的、可能不可计算的 Active 总函数。v2 允许待证候选状态，因此这是合法实例化；它不保证实时发展态 P/U/D 分类，也未删去完成 F 所需语义。空缓存不是零长完成对象，AwaitingEvidence 不是“源义对象尚未结束”的断言。

## 3. H1–H6 加 E1–E3 的逐轮模拟

Report:113–125 保留 H1–H6，尤其未削弱 H3 全记录一致／延长保持、H5 真正有限发现、H6 直接 Next 与完整可达性。E1 明列有效输入及记录载体；E2 将界、枚举、解码、检查、依赖列表和组合原语落实为有程序且经证明总；E3 固定编码、Active₀ 和自然数索引输出。原 H3 中“等价实现”订正为“充分实现”，也未增加必须重放同一证明树的要求。

模拟的不变量是相同前沿 s 和已输出记录经 Val 后与抽象 S 相同：

1. 每轮由 H1/E2 与 H2 良基依赖得到有限、终止的接受列表；依赖良基性和枚举有限性仍是不同前提。
2. 桶引理把编码集合与抽象接受值集合一一对应，空、单点、冲突走同一分支。
3. 单点包含相同身份、u 和 F；H1 的 s<u≤k 给相同 Next、Own 和严格下降势能 k−s。最多 k−s₀ 轮成功，s=k 后只能空桶。
4. 空桶后的 Active₀ 及 buffer 构造终止；错误返回不给半份正常列表。表示域外编码错误是接口失败，没有被拿来伪造正常终止。

故补定理的完整返回值可计算、有限终止，且合法域完成记录与 v2 抽象 S 逐轮一致。唯一链、可靠无跳过、Own 加缓存覆盖、语义前缀稳定及 K_n=max(r₀,…,r_n) 随该模拟运输。N 的唯一性进一步把语义完成列表稳定运输为规范码列表稳定。Active 和 buffer 不被运输为不变值。

未发现外部 oracle：运行步骤只用有效参数及有限树操作，E_h 留在证明规范中；H4/H5 必须另证，既不由扫描结果定义 E，也不让程序运行时查询 End。此证明是通常精确整数、有限输入且资源足够的算法模型结论；固定硬件的栈／内存耗尽不构成数学反例，也不能误报成 EncodingError、无证书或相等。
