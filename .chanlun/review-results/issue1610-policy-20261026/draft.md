# #1610 返修草稿：资金、数量与政策引用分维

状态：P 类候选；非作者第二轮复审 PASS，待用户批准。报告见 review/ROUND2-REVIEW.md；本文件不是批准或落地记录。2026-10-26。

## 问题
原草案不仅有 R1/R8 引用缺陷，还把保证金杠杆 L 错认成价格，导致错误的换算规则；将 1,110,400 USDC 算术结果直接写成 BTC 数量也不成立。本稿撤回这两条推荐，保留四问并明确先后依赖：Q4 量纲与定标政策 → Q3 数量档冻结；Q1、Q2 可独立处理。

## 权威依据
1. ADR 0029 `docs/adr/0029-common-cap-contention-policy.md:15,23,27,31`：责任不得超 cap；取出超空闲部分拒绝；改额新版本，过期不损既有授信。
2. ADR 0040 `docs/adr/0040-funding-signature-and-chong-derivation.md:34,41,44,52-59`：Q_total 是 USDC 整数；L 是 margin_leverage；逐重金额按容量分配；开局批 ⌈Q/L⌉ 是金额；q_ref 指 funding-record。
3. ADR 0031 `docs/adr/0031-principal-batches-phase-predicate-corporate-actions.md:12,34`：本金批为现金/保证金，拆股重基 fixed_q。第 12 行没有 ⌈Q/L⌉ 公式。
4. ADR 0034 `docs/adr/0034-quantity-tier-policy-growth-equity-shift.md:14,17,20,23,26,29-30`：数量档版本冻结、未定只挡对应深度；数量/资金两种溢出口径在开重时冻结；本稿修正有歧义的 Q/q_ref 表述，不把两种合法口径删成一种。
5. ADR 0041 `docs/adr/0041-degrees-of-freedom-configurable-not-excluded.md:17-30`：自由度入版本化记录；签署门默认 AwaitingPolicy；合法候选保留。
6. ADR 0043 `docs/adr/0043-chong-reversal-account-continuity.md:112`：换向声部不按开局量重新缩放档量。本稿不新增逐声部市价重算。
7. C8 作者说明实际位于 [#1610 评论 6295406793](https://github.com/xy7365527-lang/NewChanlun/issues/1610#issuecomment-6295406793)，日期 2026-10-20；独审链见 archaeology.md，不能用作者自述代独审。

## 候选与推荐裁定
### Q1：新 cap 小于现有责任
A 已裁边界直接沿用：不能使新 cap 生效后低于责任，不能强平或挪用旧责任。推荐在同一原子生效点检查新 cap 与现有责任，冲突即拒绝该生效事件、保留原生效版本；失败不部分切换 funding/cap/policy。等于责任允许，低 1 拒绝。旧版本已过期时不能以“保留旧版”恢复新授信。
“先存未生效提案、释放责任后另发显式激活事件”是合法管理方式，不是死锁；它不等于让低 cap 生效，也不等于重新解释 ADR 0029 已裁的取出拒绝。本稿不新增自动排队协议。若需要自动待激活策略，归 #1599 统一处理，不能借本票静默改成已采纳。

### Q2：引用与逐重数值
A 沿用 q_ref 指 funding-record 的已裁形状；B 推荐把 C8 已独审实现的“授权引用 + 逐重派生金额”正式写入正本：q_ref 定位 profile 的授权身份，另绑定 version；每重金额来自绑定同一签署版本与 (S,ℓ) 的确定性派生记录，C8 载体为 manifest.chongs[i].funding.Q。禁止把 funding-record.cap 的总金额当每重金额。
逐重派生引用也是合法候选，若选择须新 schema/book 版本、显式迁移消费者；不因 #1590 旧草稿而排除。推荐沿用现形状以避免无收益迁移，但固定版本不能在运行中换解析策略。

### Q4：金额、数量与定标（先于 Q3）
A 直接确认：`funding.Q` 为逐重资金金额，`fixed_q` 为固定资产数量；cap、C_amount、cash_g、P 为金额，units_g 与 tier_quantity 为数量。杠杆 L 无量纲，`ceil(Q_amount/L)` 仍为金额，不是股数或 BTC 数量。Q_total 的既有签署与三重分配金额不改。
C 待裁推荐：动作基记 `Q_units`，容量/资金基记 `Q_amount`；正本和新合同显式区分，不能靠同一个 Q 自动推断。新域的数量定标放在具名版本化量档记录中，`quantity_basis` 可选 `signed_units`（直接签固定数量）或 `frozen_quote`（按一次冻结的、可审计报价与单位尺度换算）；未签默认 `AwaitingPolicy{quantity_basis}`，推荐 `frozen_quote`，减少用户手填股数且能复算。合法的 signed_units 保留，不作为错误排除。
对 frozen_quote，记录整数有理价格 `p_num/p_den`（货币计量单位/数量 quantum）、报价原件引用、时间、货币尺度、数量 quantum、舍入规则及版本。推荐 `Q_units = floor(Q_amount_scaled * p_den / p_num)`；必须先把 USDC 名义整数转为该报价的货币计量单位，p_num、p_den 均正。换算不再乘杠杆，因为 Q_amount 已是 ADR 0040 的名义动作资金基，L 只计算本金保证金。溢出拒绝，零数量不激活，余款留资金账且不得伪造 quantity。
首次报价取样另签具名 `quote_time_policy`，不交数据 owner 自选：候选 `activation_request_asof`（推荐）以已持久化的首次激活请求为锚；候选 `profile_signature_asof` 以绑定 profile 版本的签署事件为锚。两者都在量档版本中签一种；首次激活锚与 profile 签署锚不得混用。对后续 q_rebase，前者以已授权且持久化的 q_rebase 请求为新锚，后者以该次新量档版本的签署事件为新锚；不能继续引用旧 profile 的签署时点代替新版本锚。拆股按既有比例重基，不触发市场报价再选取。推荐请求锚是为了让首次激活/重基按各自动作时点定标，签署锚保留为先签后执行的合法选择。
每个锚保存事件 ID、事件时间 `t_anchor` 和当时已封存的报价输入快照 ID；快照须固定于选价前。报价须与签署的市场/标的/来源/价格字段匹配，且发生时间与首次观察时间均不晚于 `t_anchor`、存在于该快照、报价年龄不超过政策签署的 `max_quote_age`；不在本稿猜定年龄数值。合格集合按发生时间、首次观察时间、来源内稳定报价 ID 的字典序依次取最大；同 ID 内容冲突拒绝定标。来源须有稳定 ID 与可验证首次观察时间，否则该源不满足此政策。没有合格报价、缺锚/快照/有效期签署则保持 `AwaitingPolicy` 或待数据状态，不选锚后报价、不读现价、不换另一时点规则兜底。恢复/重试沿用同一锚和快照；想换锚只能走明确的新版本/已授权 q_rebase，不能通过重复激活请求刷新定标。
时间策略与 `max_quote_age` 是 P 门待签政策；真实报价原件、发生/观察时间、货币尺度、quantity quantum 是数据 owner 按已签规则提交的事实。记录时间只是证据，不能代替上述选取政策。`signed_units` 不需要报价时点策略，不因 frozen_quote 的缺项被额外阻塞。
冻结粒度是重的量档版本，不是每 bar/每个新 Voice；之后只有已授权 q_rebase、新版本和拆股路径可改变数量。缺定标记录不得读当前市价兜底。数值尚未签，不能把现有测试 fixed_q=1 当真实金额的换算结果。
资金溢出时，quantity 路径比较 `Q_units + units_g` 与同单位 C_units；capital 路径比较逐重 Q_amount + cash_g 与 C_amount。q_ref 是引用字符串，不能参与加法。跨维容量须绑定同一定标记录。#1598 正在处理 overflow_trigger 的 units/capital/mark_value 选择；本票只提供分维接口，不先替它裁触发策略，也不删 mark_value 候选。
### Q3：L1 的冻结档量
A 沿用必须有版本内冻结 tier_quantity、`floor(Q_units*347/1000)`、不运行时现算、未定只挡该深度的规则。
C 待裁修正：1,110,400 是 3,200,000 USDC ×347/1000 的金额结果，不能直接认定为 BTC quantum 数量。旧 ADR0040 的数字保留历史出处，新增订正说明；新记录需等 Q4 的定标证据和签署，才能产出 tier_quantity。不得机械补“tier_quantity:1110400”后宣称严格量档已验收。
例（仅量纲示范，不是签署值）：若 Q_amount=3,200,000 USDC、数量 quantum=0.001 BTC、冻结价格=100 USDC/quantum，则 Q_units=32,000 quantum，档量=11,104 quantum。报价、货币/数量尺度改变必须重新签版本，不能复用此例作为默认。
