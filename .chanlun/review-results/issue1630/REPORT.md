# #1630：replay-drop 模式累计分配轻微超线性——定位与有界读数

- 编号：#1582、#1596、#1628、#1633 为 PR 号，其余为 GitHub Issue 号。
- 来源：#1597 票面观察项（#1588 memory 分片评审 Info3）。票面读数 20,000 → 49,995 根（n ×2.5）时 `alloc_total` 426.5 → 2,018.4 MB（×4.7）。
- 远端：windows-5090 WSL，`nc-remote` 私有 target（`NC_TARGET=sandcastle-issue-1630*`），release 构建。
- 数据：`btc_1m_full.json`（sha256 `16ea13d5…707b`，探针启动时校验）。窗口口径同 #1493/#1588：尾 `W` 根去前 5 根取前 n 根，默认 `W=50000`。
- 探针：`issue1588_parse_mem_probe <data> replay-drop <n>`。

## 结论

1. **当前 main 上该超线性已不存在**，main 自 #1596 合入（`439be77560`）起就是线性的。票面读数取自 #1596 合入前的分支提交 `1bc3534014`（`eng-debt-1588/memory`），该分支不含 #1582。
2. **来源是线段阶段 `IncrSegments::append` 的重扫跨度**，不是 #1597 初步归因中的 `can_reuse_segments=false` 整段重建。旧分支上重建次数为 0。按 #1582 之前的语义，未决第二种候选会把 `earliest_unsealed_from` 一直钉在早处，于是每 bar 都要从同一个早起点重扫到末笔，跨度随 bar 数线性增长；同时每笔跨度的分配本身也随跨度上升（见下），累计分配至少 Θ(n·跨度)。
3. **消除它的是 #1582**（`24c2fa068f`，TB-02-X「未决第二种候选封段」）。`1bc3534014..439be77560` 之间改动 `rust/src/theta_v0/parser` 的提交只有 #1582 和 #1596 自身的 squash；#1596 squash 的 parser 内容就是 `1bc3534014` 分支内容。
4. **不改生产代码**。本票只在探针里加了逐 bar 段续扫跨度读数（`rescan_span`），作为段阶段线性的长期判据；末 bar layer 摘要修前修后逐位相同（见下）。

## 定位方法（临时插桩，未入提交）

在库里设一个全局阶段标记，探针的计数分配器按阶段归账：1 = 包含状态追加，2 = 新笔扫描，3 = 新笔输出，4 = 分型，5 = 线段，6 = tail，7 = 装配。同时统计 `can_reuse_segments=false` 的次数与逐 bar 重扫跨度。插桩提交 `bdc93fcb35`/`e24d109235` 与旧分支临时提交 `51617d0b0e`/`5969582f86` 都已丢弃，只用来取读数。

## 有界论证

逐 bar `ParseLayerIncr::append` 各阶段的分配：

- **线段（phase5）**：`IncrSegments::append` 从 `resume_seg_start` 起建 `FeatureSeqState` 重扫到末笔，分配与重扫跨度成正比。在 HEAD 上（跨度 ≤ 132），插桩实测比例 24.8–29.7 B/笔，从 20k 到 1M 都稳定，所以在这个跨度范围内 phase5 累计 ≈ c·Σ跨度。旧分支跨度到上千时比例升到 45.9–77.5 B/笔（见上），c 不是全域常数。
- **包含状态（phase1，占总量 ~70%）**：每 bar 是常数个 `Vec::push`（摊还 O(1)，扩容拷贝总量 ≤ 2× 终态容量；探针 top bar 全是 2 的幂边界上的扩容），外加持久坐标树（#1394 `CoordsRef`）的路径复制。分配**次数**每 bar 从 42.9（W=300,000 的前 49,995 根）经 46.4（100k）、48.5（200k）缓慢升到 53.8（W=1,000,000 的前 999,995 根），斜率约每翻倍 +2.5 次，与 O(log n) 路径复制相符（**推断，未逐类型核实**）。字节量在测量噪声内是平的（每 bar 约 3.8 KB）。
- **新笔扫描、分型、tail、装配（phase2/4/6/7）**：每 bar 常数，或者只在 2 的幂边界扩容。

**界的性质（如实说明）**：重扫跨度由数据决定，不是结构上的常数界。只要某个段在 L 笔里一直没有被确认，这段时间里每 bar 至少要付 Θ(L)，而且旧分支数据显示单笔成本还随 L 上升，所以最坏情况至少是 Θ(n·L)，精确的阶没有测定。#1582 之前，未决第二种候选让 L 无界增长（49,995 根时达到 1,885）；#1582 之后，候选会封段，实测 L 最大为 527（2M 根）。`rescan_span` 已经写进探针输出：如果跨度均值随 n 上升，说明该回归重新出现。它只能抓到 L 变大这一路；每笔成本这一路要靠 `alloc_total` 的 KB/bar 一起看，探针不按阶段拆分。

`rescan_span` 是上界代理，不是精确的重扫笔数。同输入早退（`segment.rs` 中 `n == self.strokes_len && last_stroke == self.last_stroke` 直接返回）的 bar 实际不重扫；`keep == 0` 时实际从 `find_overlap_start` 起算，n<3 时不扫。这三种情况都会被高估，所以均值平就说明实际重扫也平。
