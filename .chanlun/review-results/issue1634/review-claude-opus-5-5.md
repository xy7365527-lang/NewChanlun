## 逐项判定

### 1. 成因：成立，不是数据缺陷，也不是正本允许的结果

**main 的写法**
- `origin/main:rust/src/theta_v0/parser/inclusion.rs:627-641`（完整事实入口）：方向证据为空时，只要遇到包含，就置 `initial_direction_unsettled = true` 并 `continue`。
- 同文件 `:1026-1042`（紧凑 `append`）：同样置 `self.unsettled = true`。
- 此后 `:609` 和 `:981` 的 waiting 分支会无条件 `continue`/`return`，再也不检查相邻 raw 的严格对。
- 源码注释直接写着「转『永久未定』（#1392 语义保留）」。

**正本的要求**
- `baohan.md:119`（本分支 v1.6 与 main v1.7 文字相同）：在首个相邻 raw 非包含严格对出现之前，保持未定前缀；该对出现后，以它的方向自序号 0 左折叠。只有「长期没有非包含对」时才保持未定。
- `baohan.md:182` 的 #1342 受影响代码清单已经把这一处点名：「紧凑状态的永久 unsettled（`:843` 遇包含即停）→ 非包含对出现即解锁并自起点重折」，归 #1393。
- 数据中 raw 1→2 就是严格向上（`logs/head_shape.txt` 第 2 行，4261.48→4280.56），所以按正本不可能只剩单组。

**旁证**：main 自己的批量核 `process_inclusion`（`origin/main:inclusion.rs:110-147`）就是「先扫描首个非包含严格对，再 `fold_all`」，与正本一致。也就是说，main 内部三个入口本来就不一致：批量核正确，紧凑和完整事实两个入口错误。REPORT 没有利用这条证据（见 L-5）。

**数据侧**：恒价根的相等区间按 `baohan.md` 的包含定义（`>=`/`<=`）属于互含，是合法输入，不需要清洗。

### 2. 「坍缩 ⟺ 首对互含」与起点 213,599：结论充分，而且比 REPORT 的论证更强

**窗口起点公式**
- 已核对探针源码 `origin/codex/1629-endpoint-prune:rust/src/bin/issue1588_parse_mem_probe.rs:437-440`（`all[len-W..]` 后取 `[5..]`），起点 = n − W + 5，与 REPORT 的表格一致。
- 7 个窗口的读数与 `logs/degenerate-window-probe-af6976de06.txt` 第 2–8 行逐个对上；W=4,613,599 那一行取自 `big-full` 日志第 135 行。
- 首对是否互含，与 `logs/head_shape.txt` 末段的输出一致。

**为什么比经验论证更强**：从 main 的代码可以直接推出，「坍缩 ⟺ 首对互含」对任意起点都成立，不只限于这 8 个样本。
- 若首对互含，直接进入永久 waiting，merged 只剩 raw0。
- 若首对不互含，第 2 根就建立 `evidence`；未定门的条件是 `evidence.is_none()`，之后永远不会再触发。

**213,599 反例**：足以排除「开盘平盘段是坏数据」这一解释。

### 3. oracle.py：忠实于正本、独立于 Rust；但起点 104 的校验范围被夸大了

**逐项对照正本**
- `contains` 用 `>=`/`<=` 双向判断；`strict_dir` 用双严格条件。
- 上合并取 max/max，下合并取 min/min。
- 初始方向取首个**相邻 raw** 非包含对，而不是 acc 对 incoming，与正本「相邻 raw」一致；之后每步用 acc 对 incoming 更新方向。
- 自 bars[0] 开始左折叠。
- 实现没有引用任何 Rust 产物。

**我的独立重算**
- 我另写了一份实现，对 `BTC_HEAD_5_140` 重算，结果为 24 组，与 `EXPECTED_MERGED` 逐元素相同。
- 夹具确实有区分力：若改成「默认 UP」，结果是 23 组，不通过；只有「默认 DOWN」会巧合通过，因为本段首个严格对是 18→19 向下。

**起点 104 校验的局限**
- main 在首对非包含时走的就是普通左折叠，所以这项校验只证明了 oracle 的 contains/strict_dir/merge/量化与 Rust 在 4.6M 根上一致。
- 它**没有**校验「未定前缀自 0 重折」这一分支，而这恰恰是本票的争议点。
- 这一分支的正确性另由两点支撑：代码只有三行，可以直接对照正本审读；W 在起点 0/5 的结果与 oracle 吻合。REPORT 写「证明 oracle 忠实」，说过头了（见 L-1）。

### 4. 回归锁：红绿成立，没有奖励黑客
