## 结论：仍 BLOCK（R2、R5 不过；must_fix 1–5 五条都已改到位，但第 2 条改出来的新定义带着一个判据漏洞）

一句话：第二稿把上一轮 5 条必改都落实了（s-cache/S7/#1641 协调、「本代新增可达节点集」定义、裁定五措辞、:218 单列与问 4、问 3 三候选），**但新写的 node 分区止步规则「遇到 node 分区里已有的摘要即停」比现役全闭包核验器松**。我读了 `rust/src/s_content.rs`：全闭包核验器的证书单位不是摘要，是 `(NodeDigest, Flavor)` 对（`s_content.rs:1978/5078`，注释「值节点按 (摘要, 上下文) 去重」），且 `Verifier` 带 `Mode`——Public 模式下遇到模板占位节点直接拒（`:1370`、`:4417` 附近 `if self.mode != Mode::Template`）。同一个摘要在 Template 根下核过、后来被 Public 根引用，全闭包读法会重核并拒绝，草案的 Δ 读法会在 node 分区命中后止步放行。这正是 #1481 第 24 行已裁的「异位置同摘要按新上下文重核」，草案与它相反；也正是 #799 禁的「同一判断的宽严两档」。另外全闭包实际核的根是四个（`content_manifest.rs:1226` 先核 `metadata.scope`，再核三根），草案只写「三根」。

### 专项 (3)：node 分区与止步规则

- **集合定义可支持折叠 ≡ 在线**：内容寻址 + 节点表只插入，roots(g) 的可达闭包在 g 时算与事后算相同；ledger 事务只在内容库 Commit 成功后提交，失败 attempt 不污染；「首次认证代」归纳成立（命中 node 分区的节点，其子树在首次可达代已全部入分区）。
- **漏洞 1（必改）**：止步键只有摘要。全闭包读法的去重/证书单位是 `(摘要, Flavor{Value|JsonInner})` 再加核验器级 `Mode{Public|Template}`。需把 node 分区主键与「本代新增可达节点集」的计数单位改为同一组键，否则 Δ 读法在边界处比全闭包读法松，验收 1 的负例（模板占位进 Public 根）会把它抓出来，但 spec 字面不该先写错。
- **漏洞 2（必改）**：根集合漏 `metadata.scope`（Public 模式 verify_ref）。
- 边界边的 kind/extent 核对不是问题：内部边只有摘要（`digest_at(&body, 8)`），四字段只在 ContentRef 根上核，草案 (c) 已覆盖。
