## 裁定落地

### A1：紧邻配对证不再向后搜索

`classifier::historical_bound_third_cert` 现在：

1. 用既有 `partition_point(start_index < center.end_index)` 取得旧框右边后的第一条；
2. 该条就是 leave；
3. 下标 `leave_idx + 1` 的下一条就是 retest；
4. retest 与 leave 不互反时立即 `None`；
5. 价格仍只交给既有 `signal::judge_third_cert` 相对该框 `ZG/ZD` 判定；
6. 价格失败也立即 `None`，不向后滑窗。

原先 `find_map` 越过同向走势寻找远期反向对的行为已删除。

### B1：共享枢轴等值坐标保留

边界仍为 `start_index >= center.end_index`，没有错误改成 `>`。函数文档明确写入：

- `signal.rs::nearest_confirmed_center` 的 `end_index <= seg_start`；
- `signal.rs::trend_third_class_in_c` 的 `partition_point(start_index < boundary)`；
- `divergence.rs` 的 `start_index >= prev_center.end_index`。

因此正例 leave 的 `start_index` 可且应等于旧框 `end_index`。

### A2：alive=None 的精确旧绑定可达

`CenterEventMachine::resolve_kill_target` 在 `alive=None` 时先检查：

- `trigger == ThirdClass`；
- `target=Some(t)`；
- `historical_bound` 的完整框身份精确等于 `t`；
- `t` 仍存在于 `consumed` 链。

四项均真才返回 `KillResolution::HistoricalBound`。其余 `alive=None` 路径仍为
`ArenaEmpty`；alive 存在时既有 `Alive`、`Tolerated`、`Stale`、`MisKill` 顺序和含义未改。

### A3：seen 只登记已投递 Owner

historical 候选仍按事件键 `(source_index, bits_disc)` 竞争。现在先做 `seen.contains`，只有
候选实际插入 `by_event` 后才 `seen.insert`。同事件的 release 落选 Owner 不登记 seen，可在后续
事件重试。

同事件多 Owner 的 `debug_assert_eq!` 保留；测试在 debug 捕获断言并核对 seen 只有胜者，在
release 直接核对确定序首项和落选者后续可投递。

### B2：一事件一 Owner 一清算保持不变

historical 四边证通过后，同 `(source_index, 侧)` 的 regular 最近中枢副本仍被抑制。测试名、
注释和断言均明确写成“一事件一 Owner 一清算”；没有放开双杀。

### D：seen 键语义命名

原三处 `(usize, CenterId, usize, u8)` 改为：

```rust
HistoricalSeenKey {
    level,
    owner,
    source_index,
    bits_disc,
}
```

只改表达，不改键字段或哈希语义。
