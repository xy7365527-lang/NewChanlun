## 实装

### 1. 同事件多 Owner 投递

`step_center_oscillation_impl` 的 historical 候选表现在使用：

```rust
BTreeMap<(usize, u8, CenterId), BspPoint>
```

同一 `(source_index, bits_disc)` 的不同 `CenterId` 不再覆盖、落选或触发 debug panic。
投递顺序继续由 `BTreeMap` 确定。

同时另用不带 Owner 的事件集合记录是否已出现同事件绑定；每多出一个合法 Owner，调用：

```rust
witness.record_historical_multi_owner_same_event(level)
```

该计数是纯观测，不进入任何路由或清算判据。

### 2. regular 副本抑制不变

`historical_event_keys` 仍是：

```rust
HashSet<(source_index, bits_disc)>
```

因此一个事件绑定多个合法 historical Owner 时，这些 Owner 各自投递；同事件的 regular
“最近中枢”副本仍整体被抑制。放开的是合法多 Owner，不是非 Owner 连坐。

### 3. seen 等于已投递

建表阶段现在只做：

```text
seen.contains(key) -> 已投递则跳过
```

不再 `insert`。路由循环内仅在以下顺序完成后登记：

```text
requires_binding
→ is_bound
→ push_point_historical_bound(...)
→ seen.insert(HistoricalSeenKey)
```

候选、落选、`is_bound` 失败或 push 前 panic 均不会提前消耗 seen。

### 4. Standards 轻 smell

复审所列 `resolve_kill_target` 两分支重复 helper 为可选顺手项。本车没有抽取：A2 已复审验收，
且本票的最小必要修复全部位于 A3；为避免回动 A2 路由优先级，本车保持该函数逐字不变。
