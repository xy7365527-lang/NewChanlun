## 1. Schema 扩展

新增字段只追加在既有 `certificate` 对象的旧字段 `role` 之后：

| 新字段 | 含义 | 缺席口径 |
|---|---|---|
| `center_si` | `CenterId.start_index` | `null` |
| `center_zd` | `CenterId.zd` | `null` |
| `center_zg` | `CenterId.zg` | `null` |
| `leave_si` | leave 区间 start index | `null` |
| `leave_ei` | leave 区间 end index | `null` |
| `retest_si` | retest 区间 start index | `null` |
| `retest_ei` | retest 区间 end index | `null` |

完整三类点身份为：

```text
(level, source_index, side/disc,
 CenterId=(center_si, center_zd, center_zg),
 leave=[leave_si, leave_ei],
 retest=[retest_si, retest_ei])
```

其中 `level`、`source_index`、`dir`、`bsp_bits_class_index` 是原
`certificate` 字段。对拍脚本以三类 bit 判 `buy/sell`，并断言其与既有
`dir=Long/Short` 一致；没有复制或重命名旧字段。

## 2. 生产者到决策账本链

```text
signal.rs::judge_third_cert
  └─ BspBits.third_class_entry = Some(生产者 CenterId + leave/retest)
       └─ Classification/BspPoint
            └─ 实际选中 Candidate
                 └─ fill.rs 在决策层冻结到 OpsemEntrySnapshot/LedgerOpen
                      └─ opsem_dump.rs 追加到 trades.jsonl.certificate
```

`ThirdClassEntryIdentity` 是只读归因载荷，不是第七个 BSP bit：

- `BspBits::class_index()` 仍只看原六 bit；
- `BspBits` 的相等关系与历史 `Debug` 字节形状仍只看原六字段；这是刻意的
  schema-only 语义，既有 Debug-FNV/金标准不扩锚；
- 载荷正确性另由定向测试直接守：不同载荷、六 bit 相同仍判等且 Debug 不含载荷字段名；
  生产者签发后经 Candidate clone/copy 不丢、不串；
- 排序、候选判定、订单、数量、价格和成交顺序均不读取新增载荷；
- writer 读取决策账本开仓快照；`None` 只写 `null`。

`trades.jsonl` 沿用既有决策账本架构：`open_trades` 在挂净额 Order 前登记，
`entry_px` 是决策 bar 价。故本票只证明“生产者证书候选 → 决策账本行”的
身份自含与可回连，不把该身份表述成逐笔 Order/fill 的执行因果。逐腿执行账属于票外大改。
