# #606 S1 第三修复车——换结构：level 传参穿透，删反查机器

## 1. 结构更换理由（引评审证据）

两轮影子评审（`/tmp/codex-research-456/review-606.md`、`review-606fix2.md`）判定：「`judge_segment`
不知级别 → 占位 0 + sidecar 收尾按身份反查 `classification.levels[lvl].bsp` 补齐」这条路线**每一版
都生新错**：

- review-606.md F5：signal.rs 侧捕获键不含 level，跨级同身份互吞（后写覆盖，永久丢一条）。
- review-606.md F6：level 反查失败静默落 L0 占位，与真实 L0 记录无法区分。
- review-606fix2.md #3（F5 修复版）：候选级别表用 `levels[*next % levels.len()]` 环绕分配，doc
  称"耗尽才计入 unresolved"与代码不符——多级命中时把 L1 的 grade 错配给 L3（"从丢一条变错配到
  别级"，且记录数照样对得上，比原来更难发现）。
- review-606fix2.md #2：F6 的 `unresolved` 全仓无人消费（不进 eprintln、不进断言），记录直接丢弃，
  比原来落 L0 更隐蔽。
- review-606fix2.md #1：F4 把锁①对齐反查键后，键唯一断言退化为 collector 内部 HashMap 结构本身的
  重复验证（tautology），检测力归零。

**编排侧裁定**：不再补丁反查逻辑，换结构——`mod.rs` 的塔循环 `for level_idx in 0..=l_max` 本就持有
真实 level，让它直接穿透传参到捕获点，捕获时用真 level 生成记录，彻底消灭"level 缺失待补"的中间
态，不再需要任何反查/候选分配/unresolved 概念。

## 2. level 传参穿透——签名与调用点清单

**两函数签名改动**（`rust/src/theta_v0/classifier/signal.rs`）：

- `extract_first_third_resume(..., level: u32, ...)`（新增参数，紧随 `cached_count`）——生产
  incremental 重放的真实调用点，`mod.rs` 塔循环 `level_idx` 直接传入。
- `judge_segment(..., level: Option<u32>, ...)`（新增参数，紧随 `gauge`）——`Some(level)` 来自
  `extract_first_third_resume`（生产路径）；`None` 来自 `extract_signals_with_hist_anchored`（全量
  fallback，也是 `extract_first_third_resume` 内部 debug_assert 对拍重算路径——非生产逐 bar 调用点，
  不参与捕获，避免与真实捕获重复写入）。

**全部调用点**：

| 文件:行 | 调用 | 传值 |
|---|---|---|
| `classifier/mod.rs:2151`（is_l0 分支） | `extract_first_third_resume` | `level_idx as u32` |
| `classifier/mod.rs:2166`（L≥1 分支） | `extract_first_third_resume` | `level_idx as u32` |
| `classifier/signal.rs`（`extract_first_third_resume` 内 `judge_range` 闭包，advance+tail 两次调用共享同一闭包） | `judge_segment` | `Some(level)` |
| `classifier/signal.rs`（`extract_signals_with_hist_anchored` 主循环） | `judge_segment` | `None` |

`recursive_tower.rs:2149`（诊断 provider，`level_cand_delta` 内的独立 `signal::judge_first_cached`
直调）核实**零改动**——该调用点走独立复刻路径，不经 `judge_segment`，不参与本捕获（`git diff` 对该
文件为空，验证见 §4）。

捕获点本体（`judge_segment` 内 `judge_first_cached` 返回后、`points.push` 前）：`level: Option<u32>`
为 `Some(lvl)` 且 sidecar 打开时，直接用 `lvl` 生成 `FirstClassGradeRecord`，不再置 0 占位。

## 3. 反查机器删除

- `signal.rs`：`GRADE_SIDECAR` thread_local 从 `HashMap<GradeSidecarKey, Vec<...>>`（键不含
  level，按签名分组防互吞）简化为纯 `Vec<FirstClassGradeRecord>`（每条已携真实 level，无需分组）。
  `GradeSidecarKey`/`grade_sidecar_key` 整体删除。
- `opsem_dump.rs`：`OtherwiseDomainSignature`/`otherwise_domain_signature`/
  `otherwise_domain_candidate_levels`/`merge_frame_captures`（候选级别反查+顺序分配机器）整体删除，
  换成 `upsert_frame_captures`（纯 upsert，无候选/无反查）。`OtherwiseDomainSidecarSummary.unresolved`
  字段、`OtherwiseDomainSidecarCollector.unresolved` 字段删除。`observe_frame` 签名从
  `observe_frame(&mut self, classification: &Classification)` 简化为 `observe_frame(&mut self)`
  （不再需要反查用的 `Classification` 入参）；`runner.rs:527` 调用点同步简化。
- F1（thread_local 泄漏，`finish()` 内 take）修复原样保留。

## 4. 锁名分诚实化

删「三锁」表述（eprintln 前缀 `wf8 一类点 T3-in-c 分级三锁+五桶` → `分级观测`；测试名
`otherwise_domain_wf8_three_locks_and_buckets` → `otherwise_domain_wf8_grade_buckets`；doc 标题同步）。
保留并改名三项统计口径：

- ①**账平**（`native+otherwise == records.len()`）——doc/断言消息注明"构造性恒等，非独立验证"。
- ②**基数对拍**（`records.len()` vs `center_lifecycle.jsonl` Reset 行数）——doc/断言消息注明"不排除
  漏一多一相抵"。
- ③**五桶分级分侧计数**。

原"锁①键唯一"（`seen_keys.insert` 断言）整体删除——键唯一现由 collector 内部 upsert `HashMap` 结构
本身保证，测试里重新验证只是验证数据结构本身，不构成独立证据（review-606fix2.md #1 指出的 tautology）。

upsert 键仍为 `(level, source_index, side, CenterId(si,zd,zg))`（不含 `center_end_index`，延伸不改
身份，F7 口径——同键覆盖保留末次重判——继续保留）。
