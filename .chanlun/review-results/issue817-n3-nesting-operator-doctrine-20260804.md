## 0. 一句话结论

**「区间套正本 ＝ 算子 N」不成立。**

- **纵向**（级别下钻）是 `[旧缠论]` —— 缠师原文有定理、有名字、有整整一课的图解。
- **横向**（配置→角→板块→标的的搜索空间收缩）是 `[新缠论:选择]` —— 缠师 110 课**零出处**，出自本仓一份**推论层**文档（`tmp/levels-bsp-v2-push.md`，无名分、无裁定背书）。
- **两支在代码里共用的那个壳是空的**：`NestingType` 这个字段**全仓无一处被读取**；实测把同一份数据分别标成 HORIZONTAL 与 VERTICAL 喂进去，四个判定函数输出**逐位相同**。按 [#804](https://github.com/xy7365527-lang/NewChanlun/issues/804) 裁定一的判别式，这里不是「两个判断」，是**零个判断差异**——类型标签是惰性装饰。
- 更要命的是**两条约束各自只在一支上有约束力**：约束1（级别单调）在横向上按其定义式 `k_{i+1} ≤ k_i` 恒可取等号；约束2（搜索空间收缩）在纵向上 `S` 不变、恒取等号。**「统一算子」＝两条互不相交的约束做合取，不是一个真正的推广。**

⟹ 把纵向与横向并列为「同一算子 N 的两个实例」，承重的是「两者外形都是单调收缩序列」，**不是「它们在系统里干同一件事」**。这正是本仓元判据点名的「拿外形当分类维度」。

## 2. Q1：缠师原文里「区间套」是什么

一手源 = `docs/chanlun/text/blog/`（110 个文件，108 课 + 序篇 + 附）。`区间套` 出现在 **35 个文件**中。下列所有引用均已核第三项（正文／答疑层级）。

### 2.1 定义句与定理（全部【正文】）

> **`027-第27课.md:36`【正文，正文界 `:78`】**
> 「学过数学分析的，都应该对区间套定理有印象。这种**从大级别往下精确找大级别买点的方法**，和区间套是一个道理。」

> **`027-第27课.md:44`【正文】**
> 「定理：某大级别的转折点，可以通过**不同级别背驰段的逐级收缩范围**而确定。」
> **`:42`**「推而广之，可以证明**缠中说禅精确大转折点寻找程序定理**」

> **`027-第27课.md:46`【正文】**
> 「换言之，某大级别的转折点，先找到其背驰段，然后在次级别图里，找出相应背驰段在次级别里的背驰段，将该过程反复进行下去，直到最低级别，相应的转折点就在该级别背驰段确定的范围内。」

> **`061-第61课.md:1`【正文，正文界 `:56`】** 课题名逐字：「第61课：**区间套定位标准图解**（分析示范六）」
> **`:26`**「在没有证据否定背驰之前，就要观察从65开始的一段其内部结构中的背驰情况，**这种方法可以逐次下去，这就是区间套的定位方法**，这种方法，可以在当下精确地定位走势的转折点。」

**⟹ 定义要素三条**：递降对象＝**背驰段**；递降轴＝**级别（大→小）**；产出＝**转折点/买卖点的精确位置**。

### 2.2 「只有纵向一个方向」——查实

**110 课全量 `区间套` 命中中，没有一处指向纵向以外的方向。** 检索式与结果：

- `grep -rn "区间套" docs/chanlun/text/blog/` → 35 文件，逐条读过；【正文】层 27 处（见附录 A 的完整清单），【答疑】层其余。
- **【正文】27 处全部是级别下钻**（`027:36/38/40/42/44/46/48/50/60`、`032:28/32`、`037:22/30`、`049:36`、`053:20`、`056:36/50/58`、`057:40`、`058:30`、`060:54`、`061:1/8/20/24/26/34/44`、`070:44`、`072:56`、`086:42/52`、`093:30`、`098:18`、`102:26`、`108:22`）。
- **零处**把「区间套」用在**选标的／板块／国家／配置**上。`板块`、`选股` 与 `区间套` 在 110 课内**从不共句**。

⟹ **缠师的区间套只有纵向一个方向。** 标签 `[旧缠论]`。

### 2.3 定位工具 vs 结构概念

**是定位工具**，且缠师自己把这一点讲得很死：

> **`102-第102课.md:26`【正文，正文界 `:48`】**
> 「……随便说一个，就是**区间套方法的应用**。如果市场走势没有本ID所揭示的整体结构，那么**区间套是不会存在**，也就是没有操作意义的。因此，**区间套的方法，就是走势必完美的一个重要的应用**。有了区间套，买卖点的精确定位才有可能……」

⟹ 走势必完美是**结构**，区间套是建立在它之上的**应用/方法**。二者不同层。

> **`053-第53课.md:20`【正文，正文界 `:36`】**
> 「注意，这里和区间套定理是没有冲突的，当30分钟进入背驰段，**为了更精细的定位，用倍数更大的显微镜去看这段走势**，这是极为自然的。」

⟹ 「显微镜」比喻——观察工具，不是被观察对象的性质。

**一处名词化用法（须登记）**：`086-第86课.md:42`【正文，正文界 `:84`】「并不是任何的小级别买点，都必然**在大级别买点对应的区间套中**」——此处「区间套」被当**名词**指该方法产生的那个收缩区间。**这是「方法」的产物被名词化，不是「走势的性质」**，但用词上确有二义，引用时须分清。

**与 ADR 0013 的一致性**：ADR 0013 裁定七已把区间套定名为「**向下定位器**」（`docs/adr/0013-partition-machine-bidirectional-form.md:119/127`），并在 `:129` 明写「**区间套是主动调用的定位工具，不是被动性质**——不调用就不收敛」。**本节与该裁定一致，不重推**，此处只补齐 `102:26`／`053:20` 两条原文锚（ADR 0013 引的是 `027:44/:46/:50` 与 `027:68`）。

### 2.4 对冲词

| 出处 | 对冲词 | 强度 |
|---|---|---|

| `027:48`【正文】 | 「**理论上**，大级别的转折点，可以精确到笔……不过这些其实都**意义不大**」 | 自我降级 |

### 2.5 数学「闭区间套定理」：借词还是真用

**借词（类比），不是引用定理。** 三条依据：

1. **缠师自己说是类比**：`027:36`「和区间套**是一个道理**」、`:50`「这个**思路是一样的**」——两处都用类比句式，没有一处说「由区间套定理可得」。
2. **他自己指出前提不满足**：闭区间套定理要求区间列**无限**且长度→0，才有唯一交点。`027:40`/`:50` 两次点名「级别不是无限可分」「不可能达到数学上唯一一点的精度」。**前提不成立 ⟹ 定理的结论（唯一点）不可用**，缠师明知并明说。
3. **本仓已查出第三处不满足（不重推）**：ADR 0013 `:261` 登记 [#852](https://github.com/xy7365527-lang/NewChanlun/issues/852) 探针自陈——「**收缩是单边的**——右端点被锚死在同一个 `src`，不是高数区间套那种两端同时收紧」。⟹ 连「嵌套区间列」的形式条件在实装里也只满足一半。

⟹ 标签：`[旧缠论]`（借词事实本身是原文明写）。**「区间套定理在缠论里成立」是错的说法**；成立的是「逐级收缩范围定位转折点」这个**受限的形状**。

## 3. Q2：仓内「横向区间套」是什么，与纵向是不是同一个东西

### 3.1 `nesting_operator.py` 全文（132 行）读完的结构

| 单元 | 行 | 内容 |
|---|---|---|
| 模块 docstring | `:1-9` | 自陈溯源 `[新缠论] levels-bsp-v2 §二：统一区间套算子 N`；`N : (SearchSpace, Level) -> (Target, BSP_confirmation)`；「纵向和横向区间套都是 N 的实例」 |
| `NestingType` | `:19-23` | 两个变体 + 两行注释（见 §1 ②） |
| `NestingStep` | `:26-37` | 五字段：`nesting_type` / `search_space: frozenset[str]` / `level: int` / `target: str` / `bsp_confirmation: BSP\|None` |
| `NestingPath` | `:40-66` | `steps` 元组 + 三个只读属性 |

| `check_search_space_contraction` | `:82-93` | 只读 `len(steps[i].search_space)`，要求非增 |

**两个变体各自做什么：什么也不做。** `nesting_type` 字段只在 `:33` 被声明，**全仓无任何一处读取它**（检索式 `grep -rn "nesting_type" src/ tests/ | grep -v "nesting_type="` → 只剩 `:33` 声明与测试的 kwarg 默认值 `tests/test_nesting/test_nesting_operator.py:25`）。

### 3.2 横向那支的输入输出，以及「那是选股不是走势结构」

**输入输出（教义源逐字，`tmp/levels-bsp-v2-push.md:213-220`）**：

```
横向实例：
  N_horiz(S_i, k_i) → (S_{i+1}, k_{i+1})
  从搜索空间 S_i（如配置空间）下钻到 S_{i+1}（如独立边集合）
  级别可能同时降低：k_{i+1} ≤ k_i
```

实装侧（`horizontal.py:51-58` `StepResult`）：输入 = 上一步产出的 `BSP` 确认；输出 = `target: str`（「本步产出的目标（**角/国家/板块/标的**/空串）」，`:57` 逐字）。

**「那是选股/筛标的，不是走势结构」——核实结果：一半对。**

- **对的一半**：产出物确实是**标的集合的元素**（角／国家／板块／标的），不是走势结构对象（笔／段／中枢／走势类型）。第五步 `STOCK` 的字面含义就是「板块内选标的」（`horizontal.py:33`）。**这条成立。**
- **不能一笔带过的一半**：它**不是纯选股**——每一步的通行证是**该层比价线上的一个买卖点确认**（`horizontal.py:9-11` 逐字：「入口 = 上一步产出的买卖点确认；操作 = 在当前层的**比价线集合中等背驰、确认买卖点**」）。也就是说，横向的每一步内部**仍然要跑一次走势结构判定**，只是判定的对象从「某标的的价格序列」换成了「某比价线（如 E/$、C/$、R/$）的序列」。
- **⟹ 精确表述**：横向不是「选股 vs 走势结构」的二选一，而是「**把走势结构判定搬到比价线上，用它的结果做搜索空间的剪枝**」。它是**选标的的控制流**，其中**嵌了**走势结构判定。把它说成「纯选股」会漏掉后半句；把它说成「和纵向一样是走势结构操作」会漏掉前半句。

**一处必须点出的实装事实**：横向的第六步 `VERTICAL_ENTRY`（`horizontal.py:34`「标的内纵向区间套」）——**横向序列的终点就是交棒给纵向**。这说明教义源自己也把两者当作**串接的两段**（先横后纵），而不是同一操作的两个可互换实例。§2.3「标准交织路径」（`tmp/levels-bsp-v2-push.md:263-280`）逐字：「**即：先横向收缩到标的，再纵向收缩到时机。**」

### 3.3 共用的部分是真共性还是同一个壳——按 #804 判别式实测

**判别式（`#804` 裁定一逐字）**：「把两级的输入换成同一份数据喂进去，**两边输出必须逐位相同**——不同就是两个判断。」

**实测**（一次性探针，`PYTHONPATH=src python3`，未入库）：

```
HORIZONTAL: (True, True, True, (True, []))
VERTICAL  : (True, True, True, (True, []))
逐位相同: True
MIXED     : (True, True, True, (True, [])) == H: True
```

（同一条两步路径，只改 `nesting_type`，分别过 `check_level_monotonicity` / `check_search_space_contraction` / `check_termination` / `validate_path`。）

**读法（要小心，判别式在这里是反着用的）**：#804 的判别式设计用途是「两份**实现**是不是同一个判定」。这里只有**一份**实现加一个**惰性标签**，所以「逐位相同」不能被读成「两支语义相同」，只能读成：

> **`NestingType` 不进入任何判定。它在代码层面没有承重。**

**真共性检验要看的是另一件事——两条约束各自在哪一支上有约束力**：

| 约束 | 纵向 | 横向 |
|---|---|---|
| 约束1 级别单调 `k` 非增（`:69-79`） | **有约束力**（`N_vert(e,k)→(e,k-1)` 必降） | **无约束力**——教义式 `k_{i+1} ≤ k_i` 允许取等，横向可以整段不降级 |
| 约束2 搜索空间 `\|S\|` 非增（`:82-93`） | **无约束力**——`N_vert` 同一条比价线 `e`，`S` 不变，恒取等 | **有约束力**（配置空间→角→板块→标的，真收缩） |
| 约束3 终止性（`:96-109`） | 共用，但终止条件写的是 `len(search_space)==1`——**这是横向的终止条件**；纵向的终止（「到最低级别」）**代码里没有任何检查** | 有约束力 |

⟹ **「统一算子 N」＝把两条互不相交的约束做合取，每条在另一支上退化为恒真。** 这不是「找到了共性」，是「把两组约束打包进一个 dataclass」。

**还有一处更硬的**：docstring `:87` 自陈「纵向的每一步收缩**时间范围**（大级别背驰区域→小级别精确点）」——**代码里没有任何字段承载时间范围**，`NestingStep` 五个字段里没有时间/区间。所以纵向那一支所谓的「收缩」，在这份实现里**根本没被表达**，更谈不上被检查。

## 4. Q3：区间套正本是不是算子 N

### 4.1 「算子 N」是谁提出的、在哪、有没有裁定背书

- **出处**：`tmp/levels-bsp-v2-push.md`（《全球资本流转拓扑：级别与买卖点 v2》），`:1-6` 自陈日期 2026-02-27、上游「文档一（本体论）、v4（K4配置约束）」、下游「文档三（操盘方法）」。定义式在 `:205-230`（§2.1 统一区间套算子），代数性质在 `:291-305`（§2.4），总结表 `:1007` 逐字「统一区间套算子 N | 纵向和横向是同一算子的实例」。
- **名分**：按 [ADR 0012](docs/adr/0012-inference-layer-document-naming.md) 裁定二的三段式，`tmp/levels-bsp-v2-push.md` 落在 **推论层**（「`analysis/` + `docs/` 无名分散件」——它连这两个目录都不在，在 `tmp/`）。**它不是正本层。** 正本层是 `.chanlun/definitions/` / `docs/adr/` / `CONTEXT.md`。
- **裁定背书**：**无。** 全仓 grep `算子 N|算子N|统一区间套算子` → 命中 5 处，其中 **`docs/adr/` 与 `.chanlun/definitions/` 各 0 处**；命中全部在 `.chanlun/review-results/`（[#809](https://github.com/xy7365527-lang/NewChanlun/issues/809) `:108`/`:243`、[#789](https://github.com/xy7365527-lang/NewChanlun/issues/789) `:298`、[#840](https://github.com/xy7365527-lang/NewChanlun/issues/840) `:148`）与一处同名无关项（`docs/canonical-coverage-rust-impl.md:234` 的 `N_ℓ` 是**归一化算子**，不是本组这个 N——**同名异物，登记**）。
- **`.chanlun/definitions/` 里没有 `qujiantao.md`**（15 份定义文件清单见 §7 附）。⟹ **区间套至今没有正本层文档**，这正是 #817 要产的东西。

### 4.2 正面回答

**不是。理由按承重排序：**

1. **名分不够**：「算子 N」只有推论层出处、零裁定背书；而「区间套」的纵向义有 `027:44` 的**缠师定理原文**与一整课图解（第61课）。**拿一个无名分的抽象去当一个 `[旧缠论]` 概念的正本，方向反了。**
2. **横向义在原文里零出处**（§2.2 已查实）。把它与纵向义并列为 N 的两个实例，等于把 `[旧缠论]` 与 `[新缠论:选择]` 塞进同一个名字的两个槽位——**这是造同名异物，不是收敛同名异物**。
3. **共性不承重**：§3.3 实测——类型标签零读取、两条约束各自在另一支上恒真、纵向的「时间范围收缩」在数据结构里根本没有载体。**「都是单调收缩的嵌套序列」是外形描述，不是共同判定。**
4. **两者是串接关系不是并列关系**：横向第六步就是「转纵向」（`horizontal.py:34`），教义源 §2.3 自陈「先横向收缩到标的，再纵向收缩到时机」。**先做 A 再做 B ⟹ A 与 B 不是同一算子的两个实例**，是流水线的两段。
5. **本仓已有的坐标系更准**：ADR 0011 `:19-21` 的三格（纵向·往上=造级别／纵向·往下=区间套／横向=同级别分解）+ ADR 0013 裁定七的「向下定位器」，已经把区间套定死在**纵向·往下**这一格。`nesting_operator` 的横向那支**不落在这三格的任何一格里**（它是第四件事，见 §5）。

### 4.3 若要保留「共性」，精确陈述应该长什么样

**能写出来的最强共性只有这一条**（写出来是为了让它可被证伪，不是为了背书）：

> **共性候选 C**：设一步操作为 `(S, k) ↦ (S', k')`，若恒有 `S' ⊆ S` 且 `k' ≤ k`，且序列有限步内到达 `|S'|=1 ∧ k'=k_min`，则称该步属「收缩步」。纵向与横向都是收缩步。

**这条为什么不足以支撑「同一算子」**：

- **它太弱**——任何「逐步剪枝直到唯一」的搜索过程都满足它（二分查找、决策树下降、`tmp/levels-bsp-v2-push.md` 之外的任何 beam search）。**判据挡不住反例 ⟹ 不是特征刻画。**
- **它丢掉了区间套的全部内容**——缠师定理的承重部分是「**递降对象是背驰段**」「**次级别背驰段必含于本级别背驰段内**」（`027:38`【正文】「而这背驰段，一定在季度线的背驰段里，而且区间比之小」）。**共性候选 C 里没有背驰，也没有「含于」**。横向那支的每步产出（角／板块／标的）之间确有集合包含关系，但那是**标的集合**的包含，与**时间区间**的包含不是同一个偏序。
- **想把 C 写成一条可执行判据，代价是把两个不同的偏序当成一个**——这正是 #804 裁定一「规则落在语义不落在形状」要挡的东西。

⟹ **建议（本票不裁，供 #817 主裁参考）**：`nesting_operator` 的横向那支改名（候选：`SearchSpaceContraction` / `TargetSelection`），把「区间套」这个词**留给纵向**；`NestingType` 枚举随之消失。这与 [#809](https://github.com/xy7365527-lang/NewChanlun/issues/809) `:243` 第 6 格已登记的收敛项⑤「`src/newchan/nesting/` 的横向算子改名还是并入——**同名异物必须消灭一个**」同向。

### 4.4 一条对横向义有利、必须照实登记的证据（编纂本，辅助层）

《市场天道》正文 p206（PDF p224）4.21 节「这就是区间套的定位方法」，在引完第102课之后，编纂者插了一段**自己的**比方（**非缠师原文**）：

> 「区间套到底该如何应用？打个比方：如果有一天，你不小心迷失在了外太空，如何回到自己家呢？请别慌张，我们的详细地址是拉尼亚凯亚超星系团→室女座星系团→本星系群→银河系→猎户臂→古尔德带→本地泡→本星际云→博尔特云→太阳系→地球→中国→城市→区域→你家，其实这就是区间套的应用。」

**核验**：OCR 在 `docs/chanlun/text/tiandao/ocr/ch04.md:5775` 起；**已按本仓纪律回图人眼核**（PyMuPDF 渲染 PDF p224 @170dpi 后人眼读图），逐字一致。页码换算「正文页 = PDF 页 − 18」成立。

**这条的分量（不要高估）**：

- 它是**编纂者的比方**，不是缠师的话。`docs/chanlun/text/tiandao/ocr/ch04.md:3` 逐字：「**权威地位：辅助层，不作定义依据**」。标签只能是 `[新缠论:候选]`（他人的经验断言），**不是 `[旧缠论]`**。
- 它确实是**空间/集合层面的嵌套收缩**，是「横向 = 搜索空间收缩」这个读法在整个语料里**最近的一处文本先例**。⟹ 本仓那个横向义**不是凭空造的**，它有一个编纂本先例。
- **但它与代码里的横向仍不是一回事**：那串地址是**纯静态包含**，每一级不需要任何确认；而 `horizontal.py` 的每一步都要求一个 **BSP 确认**才能推进（`:98-114` `entry_condition`）。⟹ **比方支持「区间套可以类比为空间嵌套」，不支持「选标的流程是区间套算子的一个实例」。**

## 5. Q4：ADR 0011 的「纵向造级别／横向读级别」与本组的关系

### 5.1 两个「横向」的所指

| | ADR 0011 的「横向」 | `nesting_operator.py:22` 的「横向」 |
|---|---|---|
| 逐字 | `docs/adr/0011-operation-decomposition-layer.md:21`：「横向（**同级别分解**）｜读级别：选定一层，把市场切成一段段该层走势类型」 | `src/newchan/nesting/nesting_operator.py:22`：「横向：**搜索空间收缩**（配置→角→板块→标的）」 |
| 沿什么轴 | **时间轴**（同一标的、同一级别，把时间切成一段段） | **标的/资产轴**（同一时刻，把候选集合从全局收到单只） |
| 输入 | 一层已造好的走势类型序列 | 一组比价线（配置空间 / 独立边 / 板块 / 标的） |
| 输出 | 该层的走势类型分段 | 一个 target 标识（角／国家／板块／标的） |
| 递归 | **无**（ADR 0011 `:85` 逐字「横向方向上没有递归，同级别分解是一次性切分」） | 六步是「同一个操作的六次应用」（`horizontal.py:5` 自陈） |
| 实装 | **本仓尚无实现**（ADR 0011 `:86` 逐字） | 有（`horizontal.py`，`pipeline.py` 消费） |

### 5.2 裁定：**是同一个词的两个所指——同名异物，须点名说破**

两者**没有任何一栏重合**：轴不同、输入不同、输出不同、递归性相反、一个无实装一个有实装。

**这是本仓已登记的第 5 处同名异物**（前四处：①「声部」vs「重」— ADR 0012 裁定五 / AGENTS.md `:129`；②「三阶段实例单位」— ADR 0013 裁定二；③「操作级别 vs 结构级别」— [#842](https://github.com/xy7365527-lang/NewChanlun/issues/842) R-2；④「次级别」的配仓义 vs 定位义 — ADR 0013 `:305` R7）。**计数按仓内已成文的登记数，若别处另有未成文的登记，本数字须上调。**

### 5.3 一个更值钱的推论：`nesting_operator` 的横向是 ADR 0011 三格之外的**第四件事**

ADR 0011 `:86` 的三格是「纵向向上=塔／纵向向下=区间套／横向=同级别分解」，ADR 0013 `:117-127` 补成「一重 ＝ ⟨挂载层 k，横向读法，向下定位器，一份筹码⟩」。

**`nesting_operator` 的横向落不进这四个位置里的任何一个**——它不造级别、不读某层的走势分段、不打点、不管筹码。它做的是**「这一重该挂在哪个标的上」**。

**这件事在本仓已有一个名字**：[#840](https://github.com/xy7365527-lang/NewChanlun/issues/840) 报告 `:148` 逐字记录「#805 四层：L-构造 `apply_t` / L-判定 `descend`（区间套）/ L-操作 `sink` / **L-选标的（算子 N）**」。⟹ **本仓自己早已把「算子 N」放在「L-选标的」这一层，与区间套（L-判定）分开列。** 这与本票 §4.2 的结论同向，且**先于本票**。

⟹ **N-3 的答案在 #840 那一行里已经半成型了**：算子 N 是 L-选标的层的东西，区间套是 L-判定层的东西。本票把它补全成：**「算子 N」这个名字承载的是选标的，它把区间套这个词借去当自己的名，借错了。**
