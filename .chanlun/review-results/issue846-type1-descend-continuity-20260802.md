## 0. 一句话结论

**结构无空档，标签有空档。**

裁定七的**存在半句**（一类点 = 走势的结束；结束时最后一个次级别走势也结束）在全历史 **36,175 条链上零反例**。
裁定七的**归类半句**（那必然是次级别的一类点或类一类点）在现有 `div_cand` 口径下 **92.03% 不成立**，
且失败的头号成因是**方向判据**（63.8%），不是力度判据（18.3%）。

**#846 票面预设的两个分支（"证实"/"否证"）都没有干净命中。**

## 1. 被测的到底是哪一句

ADR 0013:152 逐字：

> **★ 一类点／类一类点的递归无中断（编排者 2026-08-01 当场裁定）**：某级别一类点 ＝ 该级别走势的**结束**；该级别走势由次级别走势类型递归构成 ⟹ 它结束时，构成它的最后一个次级别走势也结束 ⟹ 那必然是次级别的一类点（趋势背驰）或类一类点（盘整背驰）。**逐级无空档。**

这句话有**两个可分别测量的半句**，本探针把它们拆开测：

| 半句 | 内容 | 本仓的可测形式 | 实测 |
|---|---|---|---|
| **存在半句** | 一类点 = 走势的结束；结束时最后一个次级别走势也结束 | ① 信号 `source_index` 是否真是 `tower[lvl]` 中某段的 `end_index`；② 该段的 `sub_moves` 里是否真有 `end_index == source_index` 的段 | **36175/36175 全过** |
| **归类半句** | 那**必然是**次级别的一类点或类一类点 | 那个对齐段跑 `div_cand` 是否判真 | **Type1 lvl≥1 只有 7.97% 过** |

两半句成败完全不同，**不能合起来说"证实"或"否证"**——详见 §8。

## 2. 方法

### 2.1 被测函数与三分

`rust/src/theta_v0/backtest/econ_positive.rs:815-843` 的 `descend_type1_anchor_depth`。它返回 `None` 有三个互斥来源（读函数体确认）：

| 成因 | 代码位置 | 含义 | 算不算断链 |
|---|---|---|---|
| **A** | `:822-824` `if subs.is_empty() { return None }` | 已到递归底（塔以线段为底，笔不在塔的级别阶梯内，[#520](https://github.com/xy7365527-lang/NewChanlun/issues/520) 订正 / `4a8105c0ea`） | **不算**——基底选择 |
| **B** | `:826` `find_move_by_end_index(subs, source_index)?` | 结构上对不齐 | **算**——命题的直接反例 |
| **C** | `:835-837` `if !anchor_ok { return None }` | 对齐了但 `div_cand` 判假 | **算，性质不同**——可能是判据口径 |

另有第四桶（本探针单列，旧报告叫 `base_none`）：`tower[lvl]` 里根本没有 `end_index == source_index` 的段 ⟹ 下钻从未启动。**这一桶才是"存在半句"第一步的直接检验**。

### 2.2 探针

新增 `econ_positive.rs:7681` `type1_descend_continuity_dx`（`#[test] #[ignore]`），仿照 `:7175` 的 `l2_depth_distribution_dx`（当年产旧两组数据的那个），把它 `:7299-7301` 的

```rust
if is_type1 {
    continue; // Type1 走本级 div_cand，不下沉——非本群
}
```

**反过来**选出 Type1 群，同时保留 Type2/3 群作同批对照。递归被展开成可观测循环，逐级记录 成功/A/B/C。

**两处与模板的口径差异（明记）**：

1. `LMIN` 从 1 改到 **0**。一类点落在塔的哪一级是待测量、不是已知——不收 level0 就分不清"Type1 = 0 条"是"没有"还是"没收"。事后证明这一改是必要的：200k 试跑窗里 level1-4 的 `buy1|sell1` 全为 0，只有 level0 有（全史则各级都有，见 §3）。lvl≥1 各行仍与旧数据同口径可比。
2. 预过滤从"至少一个 type2/3 bit"放宽到"至少一个 bsp bit"，让 Type1 进采集域。**Type2/3 群的采集条件未变。**

### 2.3 忠实性（两道机器校验，测试真封处断言为 0，实跑均 0）

- 展开循环的返回值与真 `descend_type1_anchor_depth` **逐信号**对拍：`trace_mismatch = 0`。
- 外化失败分支的 `div_cand_why` 与真 `div_cand` **逐次**对拍：`parity_violation = 0`。

复制体与生产判据的等价由测试守护，不靠人眼。

### 2.4 与生产的关系（诚实标注）

生产 `build_nest_certificate:1019` 的 base gate **只对 Type2/3** 调 `descend_type1_anchor_depth`；Type1 走 per-rung `div_cand`（本级/上级语境），**不下沉**。故 Type1 群的读数是**命题测量**，不是生产现行行为——读数不改变任何信号集。

## 8. 判断（观察陈述，不是裁定）

### 8.1 哪一类占主导

**C 压倒性占主导；B 恒为 0；A 只在塔底出现。**

Type1 lvl≥1：C = 277/301 = **92.03%**（顶层）、290/301 = **96.35%**（含链尾终止）；B = **0/301**；A 只在链尾 @L0 出现 11 次。

### 8.2 指向"真断链 / 实现对不齐 / 判据太严"中的哪一个

**不是单一指向。按 §1 的两个半句分开答：**

**(a) 存在半句 → 完全证实，但证实力度要打折。**

`base_none = 0`（36175/36175）+ `B = 0`（36175/36175）。"一类点 = 该级别走势的结束"、"它结束时最后一个次级别走势也结束"这两步，在实装里**零反例**。

**但**：§6 已指出 B ≡ 0 是 `recursive_tower.rs:191` 构造不变量（`父.end_index ≡ subs.last().end_index`）的**恒真后果**。这条读数证实的是"塔是自洽的递归构造"，**不构成对缠论命题的独立经验支持**——命题在这一半句上说的正是"递归构造"这件事本身，实测拿到的是同义反复。

`base_none = 0` 那一半**是真信息**：BSP 识别层与递归塔层是两条独立管线，信号坐标本可以落在段的中间而不落在端点上，实测 36,175 次全部落在端点上。这一条支持"一类点 = 走势的结束"。

**(b) 归类半句 → 未证实，且失败的主因指向"实现对不齐"，不主要是"真断链"或"判据太严"。**

理由四条：

1. **对象一直在。** 每一步都找得到那个"结束在同一个 bar 上"的次级别走势。断的不是结构，是**给这个对象贴标签的那一步**。**这排除了"真断链"。**
2. **头号失败是方向判定（cond1，63.79%），不是力度判定（cond4，18.28%）。** cond1 用的 `dir(s)` 来自 `cand_predicate.rs:85-96` 的 `rmove_dir`，对 `Compose` 的实现是：
   ```rust
   (Some(f), Some(l)) if l.hi() >= f.hi() => Direction::Up,
   (Some(_), Some(_)) => Direction::Down,
   ```
   **只比 `hi()`，不比 `lo()`，且作用在中枢吸收窗（`compose_level` 的产物，本性是盘整对象）上。** 一个"结束在价格底部"的窗口，只要它末个子段的 `hi` 不低于首个子段的 `hi`，就被判成 Up。§6 取样显示这种错判在买卖两侧对称发生。**这是实现对不齐的典型签名：对象对、坐标对、标签错。**
3. **cond3+cond4（Extreme/Weak）合计 34.83%**——这一部分才是"判据口径"的份额，而且 §6 显示 cond4 的失败样本力度是**明显增强**（差数倍），在现有口径下判"非背驰"是判据在正常工作。
4. **两群无分离（§7.1）。** 若归类半句真的是 Type1 特有的结构保证，Type1 与 Type2/3 的成功率应当拉开数量级。实测 7.97% vs 8.56%，**方向还是反的**。这说明现在这个 12% 左右的通过率**与"是不是一类点"无关**，是 `div_cand` 在中枢窗上的通用命中率。

### 8.3 对判据口径本身的三条发现（上报，不自行改；#817 未裁）

1. **`rmove_dir` 对 `Compose` 的方向判据是"只比 hi 的外缘启发式"**，作用在盘整性质的中枢窗上。它是 cond1 失败（占 C 类 63.79%）的直接输入。这一条**不属于 #817 的教义问题，属于实装问题**——同一个走势对象，方向该怎么读，本仓有一个未经论证的粗糙约定。
2. **`div_cand` 的比较基准写死在"同父 `sub_moves` 内前序最近同向段"**（`cand_predicate.rs:138-141`）。这个基准天然是**趋势背驰**的形状。裁定七要求的"类一类点（**盘整背驰**）"在这个判据下**没有入口**——不是"判得严"，是**根本没有对应分支**。这会系统性地把本该算"类一类点"的对象推进 C 桶。C 桶里 cond3+cond4 的 34.83% 有多少属于这一类，**本探针测不出来**（要先有 #817 的准入判据才能测）。
3. **中枢窗常只有 3 段，判据可用信息很薄。** `segs=3` 时，方向交替下前序同向段最多一个；§6 里 cond1 样本有多例同时"无前序同向段"（即使方向判对也会栽 cond2）。**背驰判据被搬到中枢吸收窗上时，它赖以工作的"同向段序列"这个前提本身很弱。**

### 8.4 对 ADR 0013 与 SPEC #847 的直接后果（陈述后果，不代裁）

按 #846 票面的后果声明对照：

- **"证实"分支的条件（B 类 ≈ 0，非 A 成因的断链罕见）——只满足前半。** B = 0 成立；"非 A 成因的断链罕见"**不成立**：C = 92.03%。
- **"否证"分支的条件（B 类显著）——不成立。** B = 0。

⟹ **两个预设分支都没有干净命中。**实测落在票面没预设的第三种形态：**结构无空档，标签有空档。**

因此：

- 裁定七的**存在部分**可以坐实。**SPEC [#847](https://github.com/xy7365527-lang/NewChanlun/issues/847) 的 S4 向下定位器可以按"塔里必然找得到那个对齐段"接线，"L0 以上取不到即报错"写成不变式是安全的**（36175/36175 支持，且有 `recursive_tower.rs:191` 构造不变量兜底）。
- 裁定七的**归类部分**（"那必然是次级别的一类点或类一类点"）**在当前口径下不成立**，且不成立的主因（cond1，63.79%）是实装的方向判据，不是缠论命题。**且 §7.1 的两群无分离说明：即使修好方向判据，也还要解释为什么 Type1 与 Type2/3 的通过率一样。** 要么先修 `rmove_dir` ／补盘整背驰分支再重测，要么把裁定七的归类部分降为待验。**本探针不替编排者选。**
- 裁定五（"各重在同一个最精确的点上收敛"）依赖的是**归类部分**——一条链能逐级收敛到最精确点，靠的是每一级都认得出那个点。实测 Type1 链 **max_depth = 2**，301 条里只有 11 条（3.65%）钻到塔底。**"收敛"在当前实装里基本不发生**，与 ADR 自己写的"这条保证当前在本仓是空转的"（`docs/adr/0013-...:95`）一致。

## 9. 没测到 / 局限 / 自相矛盾的地方（照实）

1. **level4 的 Type1 = 0 条**（全史）。最高级的行为**完全没测到**，不能据本报告说任何关于 level4 一类点的话。

3. **未测"次级别 BSP 层自己怎么标这个点"。** 本探针问的是"那个对齐段跑 `div_cand` 判不判真"，**没有**去查 `cls.levels[L−1].bsp` 里是否存在坐标为 `src` 的 buy1/sell1，也没查 `pan_div`（盘整背驰证书）。那是对归类半句的另一条独立测法，**可能给出不同答案**——因为 BSP 层的一类判据（`signal.rs:506` 的 `diverged && t3_in_c_present`）与 `div_cand` 的四条件不是同一套。**本轮没做，不宜据本报告断言"次级别 BSP 层也认不出这个点"。**
4. **B ≡ 0 的证实力度已在 §8.2(a) 打折**，不要把它当成对缠论命题的独立经验支持。
5. **旧两组数据的绝对计数与本次不可比**（1473 vs 16409，同一全史窗口，见 §7.3），本报告只对齐比率，**未追查信号集变动的成因**。
6. **`div_cand` 口径本身未裁**（#817 悬着）。C 桶里有多少属于"应算类一类点但现有判据无分支"，**测不出来**——写"测不出来"，不写"不受影响"。
7. **只测了 BTC 一个标的。** 跨标的（ES/CL/GC/…）未测。
8. **探针复杂度 ≈ O(bar × 累计 BSP 点数)**（每 bar 重扫该级全部已发现 BSP 点，沿用 `l2_depth_distribution_dx` 的循环形状），全史 156 min。要扩到多标的需要先改这个循环。
