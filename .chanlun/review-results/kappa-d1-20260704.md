## 1. 结论

### (a) κ fixed-point 语义（有理定点 num/den）

`RiskPolicy.kappa: i64`（不能表达 0.5）→ 改为**有理定点** `kappa_num: i64 / kappa_den: i64`：

- 新构造闸 `try_new_ratio(num, den)`：`num≥0 ∧ den>0` 合法（gcd 约分到最简），否则 `None`。
- `baseline()` = `0/1`，`try_new(k)` = `k/1`（委托 try_new_ratio），三闸都保 κ≥0 constructor-only 不变量。
- κ=0.5 由 `try_new_ratio(1, 2)` 诚实承载（codex 明令「不允许静默改成 {0,1,2}」）。

两个数学消费点改为零截断整数比较（无浮点，保 bit-exact 账本域）：

| 消费点 | 旧（i64 κ） | 新（num/den） |
|--------|------------|--------------|
| `eta_star(s)` | `L^wc + κ·Q`（i128 clamp） | `⌈L^wc + (num·Q)/den⌉` = `(L^wc·den + num·Q + den−1)/den`，i128 中间域 clamp |
| `buy_core_legal(...)` | `a+L^wc+κΔQ ≤ η+g−κQ` | 两边乘 den>0 保序：`(a+L^wc)·den + num·ΔQ ≤ (η+g)·den − num·Q` |

**为何 f64 被否**：ledger.rs 账本是 bit-exact 整数域，barrier 比较须确定性；f64 引入非确定性破坏不变量（ledger 原注释已明确「避免浮点非确定性」）。

**为何上取整不损失精度**：对**整数** η，`η ≥ η_*(有理)` ⟺ `η ≥ ⌈η_*⌉`，`η < η_*` ⟺ `η < ⌈η_*⌉`。故所有既有整数比较调用点（enter_ready / eta_bucket / stage_progression）**零改动**即得精确有理判据。

## 3. 边界条件（结论翻转）

- 若换更长/更波动窗口使 RecoverCapital 门可过 → Stage II 可达 → barrier（κ）成为 II→III 的 binding 约束 → 此时 κ 网格才对可达性有区分力（当前 100k 窗未触发）。

- 若上取整语义被用于**非整数** η（未来 η 改浮点承载）→ `⌈η_*⌉` 等价性失效，须回退到两边乘 den 比较。
