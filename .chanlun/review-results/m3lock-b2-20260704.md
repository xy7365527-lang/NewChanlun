# M3 分类互斥穷尽运行时断言（Task #10，goal m1m4-signalfull-oos b2）

结果包（六要素）。分支 `gap3-rework-codex9-fix`，未 commit（按任务约束）。

## 1. 结论

为 M3 分类状态锁定（`𝒳 = ⊔_z C_z`，运行时 `Σ_z 1_{C_z} = 1`）实装了两级运行时守恒断言，全部落在生产路径可复用的纯函数上，两级测试零违例：

- **单一真相源**：`l3_delta_r_alpha::ledger_disposition(t) -> LedgerDisposition`（三态枚举 `Kept` / `SameBarCensored` / `NonPositivePx`）。`build_mu_from_bars` 生产循环中两处原有的**裸 `continue`**（`exit_bar ≤ entry_bar`、`entry_px/exit_px ≤ 0`）被替换为对本函数的显式 `match`——排除口径不再散落，成为可被断言复用的账本项。
- **运行时断言**：`l3_delta_r_alpha::assert_m3_partition(ledger, records)`，两级守恒任一违例即 panic（no-workaround：违例=分类函数缺陷，停下上浮）：
  - **守恒 2（records→buckets 互斥穷尽 + 值域封闭）**：δ-free 主裁决键 `κ(r)=(level, bsp_class, parent_dir, force_state)` 重算分桶，`Σ_z |C_z| == records.len()`（互斥=单笔单键构造性；穷尽=无笔落零格）；键分量值域封闭断言 `bsp_class∈{0,1,2,3}`、`parent_dir∈{-1,0,1}`、`delta∈{-1,1}`（逃逸态=分类函数产出未声明分类=穷尽破缺）。
  - **守恒 1（ledger→records 穷尽账本）**：`|ledger| == kept + Σ显式排除类`，且 `kept == records.len()`——ledger 无笔既不进 records 又不落任一显式排除类（无静默丢弃）。
- **两级测试**：
  - 快速单测 `m3_partition_synthetic_holds`（合成鞅跑真实生产路径，非手搓 TypedTrade）+ `m3_out_of_domain_parent_dir_panics`（否定性见证：造 `parent_dir=5` 越界 record，`catch_unwind` 断言值域 panic 真实触发；并对照守恒 1 kept≠records 也 panic——证断言非死代码）。
  - `#[ignore]` 长跑 `m3_partition_btc_fullhistory`（BTC 全 walk-forward OOS 窗逐窗同源 ledger+records 零违例）。

**长跑结果（L2 真实数据）**：BTC 5 个 OOS 窗（2023-02-17…2025-06-30），`Σ|ledger|=2300`、`Σkept=Σ|records|=2256`，44 笔落显式排除类，M3 分区**零违例**，用时 87s。

## 2. 定义依据

- **TARGET_STRATEGY_MAXFULL.md §M3**（`docs/formal-chain/路线.pdf` p13/p19 转写）：验收判据 `𝒳 = ⊔_z C_z`，运行时 `Σ_z 1_{C_z} = 1`；δ-free 主裁决桶 `Z_decision=(level, bsp_class, parent_dir, ForceState, ExitType, …)`（**而非** 含 δ——`i_class` 与 δ 共线会自毁置换检验）。
- **分区对象锚定**：断言的分类格 = 生产/统计双路共用的 δ-free 主裁决键（`wverify_run.rs::deltafree_verdict` 的 `BTreeMap` 桶键、`perm_test::DeltaFreeKey`）。`bsp.rs` 顶注明确 `no_exclusive_trichotomy` 已证、`BspBits` 非互斥（2/3 类可共存）——故互斥穷尽**不施加于 BspBits 位向量**，而施加于 `bsp_class()` 主类号（`{0,1,2,3}` 取最低）投影后的桶分配。这是本任务分区对象的关键区分：M3 分区是 z→桶的单射覆盖，不是 BspBits 内部三分。
- **输入特征满足定义的条件**：`build_mu_from_bars` 逐笔 `records.push` 后，每笔 `ResidualTrade.class` 经 `κ` 提取键并 `BTreeMap.entry` 累加——单笔恰好触发一次 entry ⟹ 互斥构造性成立；`Σ|C_z|=Σ(单笔计1)=|records|` ⟹ 穷尽。守恒 1 补齐 records 之前的穷尽（ledger→records 无静默丢弃）。

## 3. 边界条件（结论翻转条件）

以下任一成立则断言 panic / 结论翻转：

1. **值域逃逸**：`bsp_class()` 产出 >3（当前 6-bit 掩码投影天然封闭 {0,1,2,3}，若未来改 bsp 分类逻辑引入新主类）；`parent_dir` 越出 {-1,0,1}（`z_of_candidate` 从 `Vertical` 三值映射，若新增垂直角色）；`delta` 越出 {-1,1}（Flat 占位 δ=1 不进开仓门，若 Flat 泄漏进 records）。
2. **静默丢弃回归**：未来在 `build_mu_from_bars` 分桶前新增 `filter`/裸 `continue` 而不走 `ledger_disposition` ⟹ 守恒 1 的 `kept ≠ records.len()` panic（守恒 1 正是防此回归的护栏）。
3. **双计**：若同一笔被 push 两次或键提取非确定 ⟹ `Σ|C_z| > |records|`（守恒 2 panic）。
4. **exit_z 接入分桶键**：当前分桶键用 `entry_z`（A7 `exit_z` 未进桶键，待 codex 裁决 Task #12）。若 codex 裁定 `exit_z`/`exit_type` 进 `Z_decision`，桶键维度扩展，断言需同步扩键——否则守恒 2 仍恒等但分区语义已变（届时须新 prereg 冻结口径，不得静默改）。

## 4. 下游推论

- M3 验收判据 `Σ_z 1_{C_z}=1` 从「离线可算」升为「生产路径运行时不变量」——任何消费 `build_mu_from_bars` 的路径（`wverify_run` 全套 W-VERIFY、`highlow_mu` 高低配、跨品种 L3）产出的 records 都满足分区性质，下游 μ/μ_R 估计无「未分类残差泄漏」。
- 守恒 1 使「排除笔账本」显式：44/2300 笔（BTC）落 SameBarCensored/NonPositivePx，这是 treatment-on-the-treated μ 口径的诚实边界（同 bar censored + 非法价不进 μ 估计），非静默丢弃。
- M3/M4 交界标定（TARGET_STRATEGY_MAXFULL.md §3.1）中 M3「分类状态」项的运行时锁定条件已满足；M4 双收益/双主判据在此分区基础上聚合。
