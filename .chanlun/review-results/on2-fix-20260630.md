1. **recursive_tower.rs:417** 新增 `project_to_units_resume(moves, cache)`——复用 `cache` 前缀，只对 `moves[cache.len()..]` 续投影追加，避免 per-bar 全量递归 `rmove.lo()/hi()` 整棵子树（O(nodes)/bar = O(n²)）。

## 前缀不变假设（改前必做的关键判断）

**结论：前缀不是恒不变，但本级 `upper_moves` 的修改语义是纯粹的「clear-or-append」。**

- `upper_moves` 在代码里只有两个修改点：line 856 `clear()`（cascade_reset）+ line 887 `extend(tail_upper)`（永远只 append）。**从不原地改写末段。**
- 古怪线段重划（bar 1464 seg[9] end 1384→1170，frontier 原地改写）发生在**输入 units**（下级投影的产物），通过 line 848 `frontier_mutated` 守卫 → line 851 `cascade_reset` → line 856/861 同步清空 `upper_moves` + `projected_units`，向上 cascade 传播。
- 故 `projected_units` 与 `upper_moves` 修改边界严格对齐：append 时增量追加（line 949），clear 时同步清空（line 861）→ **bit-exact 成立**。

## 边界条件（结论翻转条件）

- 若存在 `upper_moves` frontier 被原地改写而**不经** cascade_reset 清空 `projected_units` 的路径 → 下一级 units 读陈旧投影 → 整塔判定漂移，bit-exact 破裂。代码审查未发现此路径（upper_moves 只 clear-or-append）。**codex 异质审计（#107）独立否证此点：VERDICT bit-exact HOLDS。**

## codex 异质审计（#107，硬节点，通过）

codex（/tmp 干净目录，read-only sandbox）独立逐项验证 bit-exact，无否证：
1. **写入点**：`upper_moves` 唯二写入 = `Rc::make_mut().clear()`（伴随 projected_units 清空）+ `Rc::make_mut().extend(tail_upper)`（append-only）；无前缀元素原地改写/索引赋值。
2. **frontier 重写**：落在输入 `units`（从 Segment 重建），被 `frontier_mutated` 守卫捕获——`UnitRange` 派生全字段 PartialEq（end/dir/lo/hi 全比较），`scanned` 窗口覆盖已扫区（`detect_centers_windowed_resume` 仅在 `i+2>=len` 退出 ⟹ 同长/增长输入全覆盖），shrink 被长度守卫捕获。codex 独立指认 mod.rs interior-rewrite 回归测试（L1 投影不变但深层 sub_moves 变 = 古怪线段重划守卫）。
3. **投影局部性**：`fold_direction(prev)` 只读当前+前一 rmove.hi()，lo/hi 只递归当前子树 ⟹ idx 投影只依赖 `upper_moves[i]` 与 `[i-1]`，增量 tail 投影与全量逐字段一致。

codex 给出的不变量：每级 `upper_moves` 要么与 `projected_units` 联合 reset，要么在排除输入前缀变异后 append-only；index i 的投影只依赖 `upper_moves[i]` 与 `[i-1]`。
- 若 `fold_direction(prev)` 依赖前驱以外的更远上下文（当前仅依赖 `moves[idx-1]`）→ 增量投影 tail 首元素 prev 失真。当前实现 prev 严格取 `moves[idx-1]`，与全量一致。
