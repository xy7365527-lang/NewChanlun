## 一、跨 h 违反点定位（操作语义层，L0 源码）

### 1.1 资本池 / units 结构

`rec_engine.rs` 的核心仓 = 单一 `TInstance`（`instances[level]`），`highest_active()` / `nearest_active_parent(j)` 定位。三原语的资本流：

| 原语 | 行号 | 资本流 | 是否动核心 |
|---|---|---|---|
| **sink** O6 | 1310 | 从 `instances[p]` 减 `m=quota(mob_base)` 下放 sub 开短差 | **是——抽核心** |
| **add** O3 | 1484 | 平 sub 短差 `m=quota(u_sub)`，`give=m×sb/pb` 升回 parent | **否——还核心** |
| **recover** O7 | 1358 | 平 sub 整条 `u_sub`，`give` 升回 parent | **否——还核心** |

### 1.2 跨 h 违反 = sink 的 `mob_base`（不是 add）

**编排者诊断措辞需修正（诚实上报）**：诊断把"次级别 add 抽干核心"当跨 h 违反。**代码层 add 不抽核心——add/recover 把资本还回核心**。真正抽核心的是 **sink**（`rec_add(&mut self.instances[sub], short_u, ...)` 后 `rec_reduce(&mut self.instances[parent], m, ...)`）。跨 h 违反的精确形式：

```rust
// sink @ 1314-1319（默认 enable_hold_anchor=false）
let mob_base = if self.enable_hold_anchor {
    (u_p - self.instances[parent].anchor).max(0.0)
} else {
    u_p                       // ★ 违反点：整个核心 units 当机动仓
};
let m = quota(mob_base);      // = u_P/3，每次反向 BSP 从核心抽 1/3
```

**违反操作语义 §3.4（exhaustive-operation-classification）**：`9 操作轨道 = H⁰(O1,O2 核心仓 2/3) ⊕ H¹(O6,O7 机动仓 1/3 短差)`。H⁰ 核心是骑走势的不变量轨道，**不应被次级别短差消耗**。默认 `anchor=0` ⇒ `mob_base=u_P` ⇒ sink 抽**整个核心**的 1/3，反复抽 → 几何衰减 → 踏空主升浪。`nearest_active_parent(L1)` 在中间无活跃层时 = 最高级别核心本身 ⇒ **次级别 L1 反向 BSP 直接 sink 最高级别核心**（编排者诊断的"跨 h 抽干"精确机制）。

### 1.3 跨 h 抽干的 L3 直接证据（recover=0 + sink≫recover）

| | OFF (BTC/Struct) | full-ON (BTC/Struct) |
|---|---|---|
| sink / recover | 2744 / 1376 | 3066 / **0** |
| sink_by_level | [1740,691,180,133] | [2111,734,148,73] |
| recover_by_level | [1093,250,27,**6**] | [0,0,0,**0**] |

**OFF 下高级别核心 sink 后几乎不升回**（L3 sink 133 vs recover 6 = 22×）；**full-ON 下 recover 全归零**（add 全替代 ⇒ 核心**永不整条回补**，只能 add 部分 1/3 回补）。这是"骑主升浪的核心被抽干"的铁证——也证明 full-ON 比 OFF 更严重（add 替代 recover 让回补更慢）。

### 1.4 ANCHOR 是 h-locality 修复的正确实装（无守恒冲突）

`enable_hold_anchor`（552号）= enter 时划核心趋势底仓 `anchor = m×(1−MOBILE_FRAC) = m×2/3`（H⁰），sink/drain 配额只作用机动仓 `u_P − anchor`（H¹ 1/3）。**这精确实现操作语义 §3.4 的 H⁰⊕H¹ 分离**：核心 2/3 死扣（sink 不抽），机动仓 1/3 做次级别短差。

**与 `prove_sink_recover_balance` 无冲突**（编排者点名的潜在矛盾，no-workaround 检查）：该守卫是 campaign 边界**计数器**（sink 总数 == recover 总数，已从 panic 降级），anchor 只改 sink 的**抽取量** `mob_base`，不改 sink/recover 的**计数配对**。`prove_sigma_quota(m, mob_base)` 验证 `m = mob_base × MOBILE_FRAC`——anchor ON 时 `m=(u_P−anchor)/3` 仍 σ-不变（配额作用于机动仓基准，守卫注释 1338 已预留接口）。**无真矛盾，不走 /escalate。**

## 四、"更深处的因"——四个独立失血源，有效域两两不交叠（L3）

编排者要求：若 BTC 仍踏空，如实报告更深处的因。**full-ON 踏空不是单一跨 h 违反，是四个独立失血源叠加，各自有不同 regime 有效域，方向相反，单一 h 不变量不可能同时对齐：**

| 失血源 | 机制 | 有效域（何处有益）| L3 证据 |
|---|---|---|---|
| **① 跨 h sink 抽核心** | sink 抽整核心而非机动仓 | h-locality 修复**仅强牛单边**有益 | BTC 无H⁰ −52.9→+687（ANCHOR）；OKLO −110pp |
| **② recover=0（add 全替代）** | 核心永不整条回补，只 add 部分 | 强牛中加剧核心僵死 | full-ON recover_by_level=[0,0,0,0] |
| **③ 做空腿失血**（539号）| 短差空腿强牛逆势累积 | ANCHOR 死扣放大（核心不防御）| OKLO short_pnl 4.6×；BTC ANCHOR net_short 67→76% |
| **④ H⁰ flip 门**（next-c）| 拦核心纠错 flip 卡错向 | **仅 OFF 深亏 regime**有益，OFF 盈利净害 | BTC full-ON+ANCHOR −91.2 vs 无H⁰+ANCHOR +687.2（**H⁰ 贡献 −778pp**！）；ES h0blk=61 砍 −297pp |

**支配性发现（本工位最大 L3 增量）**：**剥离 H⁰ 后 h-locality 在 BTC 从 −52.9% 跃到 +687.2%（+740pp）。** H⁰ flip 门是 ANCHOR 之上对强牛标的（BTC/ES）的**支配性失血源**——它拦截核心纠错 flip（next-c 单边定理：OFF 盈利 ⇒ H⁰ 净害），把核心卡在错方向，net_short 飙升，做空腿失血爆炸。**full-ON 三 env 全开把 H⁰（害强牛）和 h-locality（救强牛）捆在一起，二者方向相反，互相抵消后净负。**

**这就是"更深处的因"**：regime 不是单一 bug，是这四个失血源的有效域不交叠的涌现表象——
- ① 救强牛 / 害震荡
- ④ 救 OFF 深亏（GC/BRN）/ 害 OFF 盈利（BTC/OKLO/CL）
- ②③ 强牛特有

**①④ 在 BTC（强牛 ∧ OFF 盈利）上方向相反**：① 要修（救），④ 要关（关才救）。full-ON 同时开 ①修+④开 = 净毁。**没有任何单一操作语义不变量能同时对齐这四个 regime 函数**——这是 regime 不可溶解的结构根因。

## 五、结果包六要素

### 1. 结论
跨 h 违反点定位完成（L0）：sink 的 `mob_base` 默认 = `u_P`（整核心当机动仓），违反操作语义 §3.4 H⁰(2/3)⊕H¹(1/3) 分离；**add 不抽核心（还核心），真正抽核心的是 sink**（修正编排者诊断措辞）。h-locality 修复 = 既有 ANCHOR（核心 2/3 死扣），无守恒冲突。**L3 决定性否证编排者假设**：h-locality 正确执行后 regime 不溶解，反而发散 9×（[−26,+55]→[−54.8,+687.2]）。BTC full-ON+ANCHOR=−91.2% 仍踏空（更糟）。"更深处的因" = 四个有效域两两不交叠的独立失血源叠加，单一 h 不变量不可能同时对齐。**支配性失血源 = H⁰ flip 门**（剥离后 BTC +740pp）。

### 2. 定义依据
- **exhaustive-operation-classification §3.2/§3.4（L0）**：`9 轨道 = H⁰(O1,O2 核心 2/3) ⊕ H¹(O6,O7 机动 1/3 短差) ⊕ 径向递归(O3,O4,O5) ⊕ 平凡(O8,O9)`；O3 add = 不动 h 同级别短差腿部分重建。输入满足：sink 默认 mob_base=u_P 消耗整核心 = 违反 H⁰ 不变量轨道（核心仓不应被 H¹ 短差消耗）。
- **552号（L3）**：ANCHOR = H⁰⊕H¹ 分离实装；anchor 吃涨有效域 = 强牛 regime ⊊ 全标的，震荡是结构税。本工位是其在 orbit9 full-ON（含 O3 add）路径的再验证——结论一致。
- **next-c 单边定理（L3，10/10）**：OFF 盈利 ⇒ H⁰ ON 劣化（r=−0.842）。本工位剥离 H⁰ 隔离实验直接验证：BTC/ES（OFF 弱/盈利）剥离 H⁰ 后 ANCHOR 极有效。

### 3. 边界条件（结论翻转）
- 若 **8 标的全为持续单边强牛**（net_short→0），则 h-locality 修复可能全部转正 ⇒ 假性"溶解"。反例：当前样本含震荡（OKLO/BRN/CL）⇒ 不翻转，发散成立。
- 若 **H⁰ 改为 regime 门控**（next-c §七：OFF_strat<−10% 才启 H⁰），则 ①④ 在 BTC 上的方向冲突可解（H⁰ 不开 ∧ h-locality 开 ⇒ BTC +687%）。但这是**外挂 regime 门控**（编排者禁止的白名单补丁），且 OKLO/BRN 震荡仍崩（②③ 未解）⇒ 仍不溶解。
- 若 **add 配额 quota 改大逼近 recover**，则 recover=0 缓解（②减弱），但 add≈recover 语义坍缩 ⇒ 退回 next-a 占位。
- 若 **bear 窗（真下跌段）替代 net-up 全程**，强牛踏空机制消失 ⇒ 有效域翻转（委托 next-b/task#58 已测）。

### 4. 下游推论
- **regime 不可由单一操作语义不变量溶解**——这是 L3 结构结论。任何"统一配置普适"的尝试都会撞上四源有效域不交叠。**正确架构 = 承认 regime 是多失血源涌现表象，per-regime 选择配置**（与项目所有 regime 函数同构）。
- **h-locality（ANCHOR）应作强牛 regime 专用配置**，不入 full-ON 默认。其有效域 = 持续单边强牛（BTC/ES）。
- **H⁰ flip 门与 h-locality 在强牛标的方向相反**——full-ON 三 env 捆绑是结构错误（把救强牛的 ANCHOR 和害强牛的 H⁰ 绑死）。若要用 h-locality，必须同时关 H⁰（但关 H⁰ 又害 GC/BRN 深亏标的）⇒ 死结，确认 regime 不可统一。
- **OKLO/BRN/CL 震荡失血根因不在跨 h（h-locality 加剧而非缓解）**——在 ②③（recover=0 + 做空腿），指向 539 做空腿 regime 函数（独立失血源，h-locality 修不了）。
