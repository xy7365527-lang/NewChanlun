## 一、结论

**H⁰（背驰段反向 flip 拦截门）的真实判别量不是 bear/bull 标签，而是 `OFF_strat`（无 H⁰ 基线的已实现盈亏符号）。**

核心定理（L3，10/10 无反例）：

> **单边定理**：若 OFF 基线盈利（OFF_strat > 0），则 H⁰ ON 一定劣化（ΔH⁰ = strat_ON − strat_OFF < 0）。
> 完整 10 个 OFF盈利数据点全部满足，最不伤的也是 ΔH⁰ = −1.9pp。零反例。

定量刻画：

- **Pearson r(OFF_strat, ΔH⁰) = −0.842**（强负相关；远超第二名候选量）
- **回归**：ΔH⁰ ≈ −1.05 × OFF_strat − 16.8（斜率≈−1 = H⁰ 拦截损益 ≈ −(被拦 flip 的边际贡献)）
- **判别阈值**：OFF_strat < −10%（深亏区）⇒ H⁰ 改善，准确率 87%（20/23）

GC/BRN 改善的真实原因：它们的 OFF 基线**深亏**（GC −12~−23%，BRN −26~−55%），被拦的 flip 在 OFF 是亏损源（无效 flip）。CL/BTC/OKLO 劣化的真实原因：它们的 OFF 基线**盈利**（CL +3~+20%，BTC +8~+49%，OKLO +55~+118%），被拦的 flip 是盈利引擎的一部分（有效 flip = 纠错机制）。

## 二、定义依据

H⁰ 门的精确语义（`rust/src/recursive_t/rec_engine.rs:1543-1559`，注释 159-169）：
- 触发位置：`route_bsp` 的核心级分支（`None` → `highest_active()=Some(cc)` → `dir != cdir`），即 **O1 整仓换向 flip**（清全塔 + 反向 enter）。
- 拦截条件：`enable_h0_skeleton && !flip_confirmed` ⇒ no-op（`n_h0_flip_blocked += 1`）。`flip_confirmed = type1 走势完成（φ=0 seam，judge_divergence 创新高确认）`。
- 语义：背驰段（⊋ type1，未创新高）反向 BSP 被拦 → 不在背驰段提前翻向，骑走势等下一 confirmed 定位点。

**有效/无效拦截的操作定义**：
- 有效拦截（拦得对）：被拦的 flip 若执行（OFF）会亏损 → 拦掉=改善 → ΔH⁰ > 0
- 无效拦截（拦得错）：被拦的 flip 若执行（OFF）会盈利 → 拦掉=劣化 → ΔH⁰ < 0

由于 ON 与 OFF 唯一差别就是 flip 被拦（ON flip_log≈空，OFF flip=2~6），**ΔH⁰ ≡ −(被拦 flip 的净损益贡献)**。这把"有效/无效拦截"严格等价为"OFF 中 flip 的损益符号"，而后者由 OFF_strat 强代理（r=−0.842）。

## 六、边界条件（结论翻转条件）

1. **单边定理翻转**：若出现 OFF盈利 且 ΔH⁰≥0 的数据点，单边定理被否证。当前 10/10 无反例，但样本仅 10 个 OFF盈利点，扩到更多标的/时段可能出现 |ΔH⁰|<2pp 的边界翻转（ES/Or 已逼近，−1.9pp）。
2. **OFF_strat 阈值依赖样本**：−10% 阈值是 23 点拟合，跨标的稳健性需更大样本。QQQ（中亏 −9% 却劣化）说明阈值附近（−10%~0%）有"亏损来自做空腿而非 flip"的混杂区。
3. **OFF_strat 是半先验量**：需先跑 OFF 基线才能算 OFF_strat，不是纯先验市场结构量。作 regime 门控时是**自适应判别量**（滚动窗口已实现盈亏决定是否启 H⁰），不是离线静态标签。
4. **若 a₀ 来源改变**（Segment→Stroke）或级别配置改变，flip 触发分布改变，判别量需重测。

## 七、下游推论

1. **H⁰ 不应作全局开关**：作全局 ON 会砍掉 OFF盈利标的（CL/BTC/OKLO）的纠错 flip，净害。应作**条件门控**：仅在基线深亏（OFF_strat < −10%）的标的/regime 启用。
2. **H⁰ 的本质是"纠错抑制器"不是"churn 滤波器"**：原设计意图（587 候选A）是"不在背驰段提前翻向，骑走势"。但实证显示被拦的 flip 多数是**纠错**（把早期错误方向翻回真实趋势），尤其强牛（BTC）。H⁰ 在趋势市抑制纠错 = 卡死错向（BTC liq 5→16）。这与设计意图相悖——背驰段反向在趋势市恰恰是必要的方向修正。
3. **与 539 号耦合**：QQQ/DX 的"OFF亏损但 H⁰ 更亏"指向 [[project_t_short_leg_regime_function]]（做空腿=亏损唯一来源）——这些标的亏损根因在做空腿而非 flip，H⁰ 拦 flip 还升高 net_short 加重做空失血。H⁰ 与做空腿是两个独立失血源，不能用 H⁰ 修做空腿问题。
4. **regime 门控候选**：OFF_strat（滚动已实现盈亏）可作 H⁰ 的自适应门控信号，但需先解决"亏损来源归因"（flip 失血 vs 做空腿失血），否则在做空腿失血标的（QQQ）上误启 H⁰。
