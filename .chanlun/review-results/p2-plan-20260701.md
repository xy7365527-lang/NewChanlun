## 0. 权威依据（三源交叉）

## 2. 分叉1 裁定：R1 vs R2 —— **定理（唯一决定 R2），约束严格排除 R1**

### 硬约束（裁决 §10「P4桶键必须含六类型」+ 蜂群 bit-exact 铁律）
不动 MuClass 六维分桶键 / bit-exact μ-key。可观测锁：`bit_exact_battery_digest`（signal.rs:1624）用 `{pts:?}`（BspPoint Debug 含 bits）拼 FNV，GOLDEN=`0x37d2_45a7_cdc5_505a`——**任何改变现有输入下 buy1/sell1 的输出会翻转 digest**，回归立即可见。

### R1（破中枢∧趋势 ⟹ 直接置 buy1=true）：**违约束，排除**
推导（纯 L0）：
```
R1 改 bits.buy1（signal.rs:318 现有输入下 false→true）
  ⟹ 改 class_index()（bit0 翻转，types.rs:229）
  ⟹ 改 MuClass.i_class（mu_estimator.rs:97）
  ⟹ 改分桶键（buckets HashMap key 变）＋ 翻转 bit_exact_battery_digest GOLDEN
  ⟹ 违反「不动 μ-key」硬约束 ＋ 大面积 Gamma/seen-set 回归
```
∴ R1 被硬约束**唯一排除**——这是定理，不是价值选择。

### R2（buy1 保严格「趋势背驰」不变，为零bit破中枢候选注入独立结构方向源 struct_break，力度作 z feature）：**成立，但须精确界定"什么变/什么不变"**

R2 的**朴素读法有一个隐性缝隙**（swarm advisory 说"完全不碰 bit-exact"过于乐观，本方案必须补严）：
- 因为**方向唯一来源是六 bit**（§1 坐实），若"注入方向源"仍通过置 buy1/sell1 实现 ⟹ R2 退化成 R1，一样碰 class_index。
- 故 R2 严格成立的**充要条件** = 方向源**不经过 BspBits 六 bit**，而是**在候选层新增一个独立的结构方向字段**，让 Flat 判定与 μ 采集**改读该字段**，而 `bits`/`class_index`/`bit_exact_battery_digest` 全不动。

严格形式（no-workaround，一次到位，不留半成品）：

```
新增 BspPoint.struct_break_dir: Option<Side>   // None=非破中枢结构候选；Some(Long/Short)=破中枢趋势方向
  - 由 signal.rs judge_first_cached 在 broke∧trend∧A/C可配对 时置 Some(trend方向)，与 macd_c_lt_a 无关
  - buy1/sell1 语义**完全不动**（仍仅 macd_c_lt_a 才置）⟹ class_index 不变 ⟹ digest 不变 ⟹ 桶键不变
候选方向恢复（interp.rs candidate_dir 层，不改 conf_plus/conf_minus）：
  dir = if 六bit方向存在 → 原 candidate_dir(bits)
        else if point.struct_break_dir==Some(s) → s        // 零bit破中枢候选恢复方向
        else → Flat
```

**为什么这不碰 μ-key**（逐项）：
- `class_index()`/`MuClass.i_class`：只读六 bit，struct_break_dir 不参与 ⟹ 不变。
- `MuClass` 的 `delta`：现在会因"恢复方向"从"无（Flat不建桶）"变为"有（Long/Short）"——但 delta 的**取值域/推导口径**（z_of_candidate: Long→+1/Short→−1）没动，只是**新候选进桶**，不是桶定义变。这是**样本集变化（预期行为变更）**，不是桶键结构回归。
- `bit_exact_battery_digest`：锁 `extract_signals` 输出的 BspPoint 序列。**新增字段 struct_break_dir 会改 BspPoint 的 Debug ⟹ digest 必翻转**——这是 R2 的**必然代价**，须诚实处理：GOLDEN 需按新语义重算，且用逐 case 对拍证明「六bit部分逐字段不变，仅 struct_break_dir 新增」（见 §5 bit-exact 风险面第 (2) 项）。**不得**把 struct_break_dir 排除出 Debug 来假装 digest 不变（那是声明膨胀）。

### 分叉1 结论
- **R1 排除**（定理：违「不动 class_index」硬约束）。
- **R2 采纳**，但严格形式 = **新增独立结构方向字段（不经六 bit）**，非"注入方向源"这个模糊说法。R2 唯一碰 bit-exact 的点是 `bit_exact_battery_digest` GOLDEN（因 BspPoint 新增字段），须重算 + 逐 case 证明六 bit 部分不变——这是**受控的、可证的**改动，不是 R1 那种桶键结构回归。**分桶键 MuClass 定义零改动。**

## 3. 分叉2 裁定：力度进 z 是改分桶键还是 selector 复合键旁路 —— **定理：selector 独立 feature 通道，不碰分桶键**

### 关键澄清：PDF 有**两个 z**，不是一个
- **分桶键 z**（§7/§10/P4）：`(ℓ,δ,I_γ,NestDepth,DivType,ExitType,…)`——**离散**买卖点类型键，当前实装 = `MuClass` 六维，`buckets: HashMap<MuClass,Welford>`。
- **选择器状态 z**（§6 方案A）：`(…,MACDarea,PriceAmplitude,PriceSpeed,ForcePower,…)`——**连续**力度特征，进 `LCB(μ(z,a))>θ` 的条件。

二者同符号，不同语义层。坐实：`MuObservation{class:MuClass, x_gamma:f64}`（mu_estimator.rs:175）——观测**只携桶键+收益，无力度字段**；`mu_lcb(class:&MuClass,…)` 只吃 MuClass。

### 裁定（定理，非选择）
把**连续力度特征塞进 MuClass** = 用连续变量做 HashMap 桶键 = 桶数爆炸（每个不同 area 值一个桶，n̄→1，winner's curse 极大）+ 改分桶键（违约束）。∴ **力度特征不进 MuClass**。

正确实现层 = **selector 的独立 feature 通道**（不碰 MuClass）：
```
路线（最小增量，符合 PDF §6「力度作特征」原义）：
  A. 力度特征作候选的 sidecar payload（Candidate 携 force features: {macd_area, price_amplitude, price_speed}）
     —— 不进 MuClass，不进 buckets 桶键
  B. selector 增一层力度门（在现有 μ-LCB 门之外/之内），门函数 = Weak_Θ(force_features)（词典序/可配置）
     —— 或按 PDF 方案A：μ(z,a) 的 a=action，z 含力度特征作**分层估计的协变量**，用独立 estimator（非 MuClass buckets）
```

**"DivType 进桶是否改 MuClass"的子裁定**：PDF §7 分桶键含 `DivType`。若 DivType = 背驰类型枚举（趋势/盘整/无），它**进桶就是新增 MuClass 第七维 = 改分桶键**（违约束），除非它能被现有 `i_class`（B1/S1 是否置位=是否一类背驰）语义覆盖。**裁定：当前阶段 DivType 不新增进 MuClass**——一类背驰信息已由 `i_class` 的 B1/S1 bit 编码（div_bucket 投影 UClass 已用此，mu_estimator.rs:118-119）。若 W-VERIFY 阶段要区分"趋势背驰 vs 盘整背驰 vs 结构无背驰"三态，那是**独立的分桶键扩展工位**（改 MuClass，需单独 escalate + 重算 bit-exact），不在本 P2 方案范围。

### 分叉2 结论
力度进 z（§6方案A 的选择器状态 z）= **selector 层独立 feature 通道 + Weak_Θ 力度门**，**不碰 MuClass 六维分桶键**。这是定理（连续变量做桶键在数学上退化 + 违约束）。DivType 若要进桶键是**另一个工位**，本方案不含。

### 现状（坐实）
- theta_v0 引擎（`src/theta_v0/classifier/divergence.rs`）：**只有 MACD 面积**（`segment_macd_area`/`segments_diverge`），无 DIF、无价格振幅/速度。段头 253-266 已诚实标注此 gap。
- **旧引擎（`src/divergence.rs`，顶层，非 theta_v0）已有完整 DIF 实装**：`dif_peak_a/dif_peak_c`（110-111）、T6=`dif_a>0 && dif_c<dif_a`（316）、T4=B段黄白线穿0轴（370）、三维度 `check_three_dim`（304-317）。**⟹ DIF 逻辑可移植，非从零写**（成本估算修正：swarm advisory 未发现旧引擎已有 DIF）。
- `compute_macd` 输出：需确认 theta_v0 的 `compute_macd` 是否输出 dif/dea 序列还是仅 hist（现 `AbcDivergence.diverges` 只吃 hist）。**改点前置依赖**：若仅 hist，需扩 compute_macd 输出 dif（浮点域隔离在 divergence.rs，不碰整数几何）。

### 改点位置（Weak_Θ 词典序）
```
divergence.rs 新增（力度原语层 §A，浮点隔离）：
  - segment_dif_metric(dif序列, start, end) -> {回抽0轴, 峰值}   // 黄白线主判据原语（移植旧引擎 T6/T4）
  - segment_price_amplitude(closes, start, end) -> i64（L0整数tick，|Δ价|）  // 振幅原语（可无浮点）
  - segment_price_speed(closes, start, end) -> f64（|Δ价|/Δbar）             // 速度原语
  - enum WeakThetaMode { MacdArea, Dif, PriceAmplitude, Lex }               // §34课「三套OOS」+默认Lex
  - fn weak_theta(mode, force_features_a, force_features_c) -> bool         // 词典序: level元门∘[DIF主▷area次]
AbcDivergence.diverges 改为委托 weak_theta（mode 从 config 读，default=Lex）；segments_diverge 保留 MacdArea 作 mode 之一。
```

**词典序语义**（PDF 14页 + swarm 待判点 B）：`Weak_LEX = {Weak_level 若level可判; Weak_DIF 若DIF可判; Weak_area 否则}`。级别配套是元门（当前 τ 门控雏形 = 级别结构主干），DIF 主 ▷ area 次。**非 AND/OR**（swarm 待判点 B 用 027:30「只要其中一个符合就可以」否证 AND，用第34课「黄白线最重要」否证纯 OR）。

### 认识论标注（强制）
- Weak_Θ 各 mode 的**接口正确性** = L1（管线，逐例验证词典序逻辑）。
- 「哪个 mode 有 alpha / 词典序优于单 MACD」= **L2/L3**（需三套 OOS：MACD/Force/LEX，PDF §7「分层报告 MACD/Force/LEX」），本方案**不声明**，留 W-VERIFY（#23）。

## 5. bit-exact 风险面（逐项，L0/L1）

| 改动 | 触碰对象 | bit-exact 风险 | 碰 μ-key？ | 处置 |
|------|---------|---------------|-----------|------|
| (1) 新增 `BspPoint.struct_break_dir: Option<Side>` | BspPoint 结构 + Debug | **中**：改 BspPoint Debug ⟹ `bit_exact_battery_digest` GOLDEN 翻转 | 否（不进 class_index） | GOLDEN 重算 + 逐 case 对拍证「六bit逐字段不变，仅新增字段」；**禁**把字段排除 Debug 假装不变 |
| (2) candidate_dir 增 struct_break_dir 回退分支 | interp.rs 方向消歧 | **中**：改变哪些候选非-Flat（新增 Long/Short 候选进样本）= **预期行为变更**非回归 | 否 | 新增候选进 μ 样本是 P2 目标；须证「原六bit方向候选的 dir 不变」（回退分支仅在零bit时触发） |
| (3) 力度特征 sidecar（Candidate 携 force features） | Candidate 结构 | **低**：新增字段，不进 PartialEq 用于桶键/不进 MuClass | 否 | 独立 payload，selector 消费 |
| (4) selector 增 Weak_Θ 力度门 | selector.rs 过滤 | **低-中**：改变哪些候选过门 = 预期行为变更 | 否 | 门是新增筛选层，MuClass/mu_lcb 不动 |
| (5) divergence.rs 增 DIF/振幅/速度原语 + weak_theta | divergence.rs 浮点层 | **低**：浮点隔离在 divergence，整数几何/BspBits 不碰 | 否 | 移植旧引擎 T6/T4；default=Lex 会改 macd_c_lt_a 取值 ⟹ 传导到 (1) 的 GOLDEN |
| (6) compute_macd 扩输出 dif（若需） | divergence.rs | **低**：新增输出字段，hist 不变 | 否 | 前置依赖，hist bit-identical 保 |
| **R1（对照，已排除）** | class_index/MuClass | **高**：桶键结构回归 + digest 翻转 | **是** | 排除 |

**风险面总评**：R2 路线的 bit-exact 触点收敛于 **(1)+(5) 联合导致的 `bit_exact_battery_digest` GOLDEN 重算**——这是**一处受控的、可逐 case 证明的**改动（六 bit 部分不变，仅 struct_break_dir 新增 + macd_c_lt_a 因 default mode 变化而变）。**MuClass 分桶键定义（level/delta/i_class/parent_dir/short_swing/position 六维）零改动**——这是硬约束的核心，R2 严格满足。

**⚠ 待 codex 对审的 open point**：(1)+(5) 使 `macd_c_lt_a`（进而 buy1）在 default=Lex 下取值可能变（因判据从纯 area 变词典序）。这**会改现有输入下的 buy1** ⟹ **改 class_index** ⟹ **碰 μ-key**！

**这是本方案的真矛盾候选，必须裁定（不硬选）**：
- 若 Weak_Θ default=Lex **改变 buy1 语义**（哪些破中枢候选置 buy1），则它碰 class_index = 违约束，退回 R1 困境。
- **严格解**：把 Weak_Θ 词典序**仅用于 selector 力度门（分叉2 通道）**，**buy1 的判据保持纯 `macd_c_lt_a`（MACD 面积）不变**——即 §34课词典序**不下沉到 buy1 定义层**，只在**选择器筛选层**生效。这样：buy1/class_index 语义冻结（μ-key 不动），力度升级全部发生在"候选是否被 selector 选中"层（LCB(μ(z,a))>θ 的力度门），符合 PDF §6方案A「MACD 从**gate**降为 feature」原义——**gate 层（buy1）冻结，feature 层（selector）升级**。
- **∴ 修正 §4 改点**：`AbcDivergence.diverges`（喂 buy1 的 ②）**不改**，保持 `segments_diverge`（MACD 面积）；Weak_Θ 词典序**只在 selector 力度门**用。DIF/振幅/速度作**候选 force feature sidecar**（分叉2 通道），不喂 buy1。这样 (5) 不传导到 (1) 的 GOLDEN——digest 仅因新增 struct_break_dir 字段翻转（可逐 case 证六 bit 不变），**不因 macd_c_lt_a 取值变而翻转**。

**修正后风险面**：R2 唯一 bit-exact 触点 = (1) 新增字段导致 GOLDEN 重算（六 bit 值逐 case 不变，可证）。**μ-key 零改动，buy1 语义冻结。** 这是严格解（no-workaround：不把词典序硬塞进 buy1 制造 μ-key 冲突，而是精确分层——gate 冻结/feature 升级）。

## 8. 结果包（六要素）

1. **结论**：分叉1=R2（新增独立结构方向字段 struct_break_dir，非经六bit；R1 违约束排除）。分叉2=力度进 selector 独立 feature 通道 + Weak_Θ 力度门，**不碰 MuClass 分桶键**。**关键修正**：Weak_Θ 词典序仅用于 selector 力度门（feature 层），buy1 判据冻结为 MACD 面积（gate 层）——避免词典序下沉 buy1 制造 μ-key 冲突。R2 唯一 bit-exact 触点 = BspPoint 新增字段导致 GOLDEN 重算（可逐 case 证六 bit 不变）。
2. **定义依据**：PDF §6方案A（宽候选+力度作特征+LCB选择器）、§7/§10（P4桶键含六类型、P2非唯一硬门）、§34课词典序（Weak_Θ 参数化+三套OOS）；MuClass 六维分桶键（mu_estimator.rs:69-75）；class_index 双射（types.rs:229）；candidate_dir 方向唯一来源（interp.rs:206 + types.rs:202-212）。
3. **边界条件（结论翻转）**：
   (a) 若 codex 判「Weak_Θ 必须下沉到 buy1 定义层」（背驰 canonical 定义就是词典序，非仅 selector），则 buy1 语义变 ⟹ 碰 class_index ⟹ R2 亦违约束 ⟹ **真矛盾 → escalate**（本方案的 open point，待 #31 裁定）。
   (b) 若真实数据上 struct_break_dir 恢复的候选集为空（所有破中枢候选本就有六bit方向），则 R2 对消选择偏差增量=0（L2 才能判，本方案不声明）。
   (c) 若 DivType 三态区分被 W-VERIFY 判为 P4 桶键必需，则需独立扩 MuClass 工位（改 μ-key），不在本方案。
4. **下游推论**：#32 impl 按 §7 改点；#31 codex 须重点审 §5 的 open point（Weak_Θ 是否下沉 buy1）——这是唯一可能翻转"不碰μ-key"的点。#23 W-VERIFY 承接三套 OOS（MACD/Force/LEX 分层报告）。
