## 三、新发现的问题

### 3.1 §7 配置编号引用错误（确定性错误）

§7 第 289 行：
> "例外：全局盘整态（配置#14，独立边全部为0）"

但 §5.5 枚举表中：
- **#3** = (0, 0, 0) = 全局均衡，独立边全部为0
- **#14** = (-, 0, -) = 动产房地产同跌商品盘整

§7 应引用 **#3**，不是 #14。这是 §5.5 枚举表新增后与 §7 未同步导致的编号错误。

**严重程度**：中。不影响逻辑（描述文字"独立边全部为0"是正确的），但编号引用错误会误导查表操作。

**修复**：将 §7 的"配置#14"改为"配置#3"。

### 3.2 §5.4 命名模式与 §5.5 编号配置的交叉引用缺失

§5.4 定义了 6 个命名模式（A-F），§5.5 定义了 27 个编号配置。两者之间没有显式映射。

隐含映射：
| 命名模式 | 独立基底 | 对应编号 |
|---------|---------|---------|
| A（全面流入单角） | (+,-,-) | #7 |
| B（轮动） | (+,-,0) | #16 |
| C（全面盘整） | (0,0,0) | #3 |
| D（独立边同向正） | (+,+,+) | #1 |
| E（独立边同向负） | (-,-,-) | #2 |
| F（背驰共振） | 跨配置模式 | 无单一编号 |

**严重程度**：低。读者可以自行对应，但显式映射会提高可用性。

**建议**：在 §5.4 每个模式描述中标注对应的 §5.5 编号。

### 3.3 §2.3 加法守恒的约束力澄清

v4 §2.3 现在正确地将 Σ net(V) = 0 标识为"有向图的拓扑恒等式"。但文本将其与乘法恒等式并列为"两个独立的、都严格成立的约束"，暗示两者都有约束力。

精确地说：
- 乘法恒等式约束派生边的价格水平（给定独立边，派生边的值被唯一确定）→ 有实质约束力
- 加法恒等式 Σ net(V) = 0 对任意边方向赋值都成立 → 不约束边方向的组合

加法恒等式的实际用途是**簿记工具**（计算每个顶点的 net flow，如 §5.5 表中的 net($) 列），而非约束工具。它不排除任何配置——27 种配置全部满足 Σ net(V) = 0。

**严重程度**：低。v4 已经比 v3 大幅改善（不再说"严格的守恒是乘法形式"），且正确标识为"拓扑恒等式"。但"约束"一词仍有轻微误导。

**建议**：将"两个独立的、都严格成立的约束"改为"两个独立的、都严格成立的恒等式"，并在加法守恒后补充一句："此恒等式不排除任何边方向组合，其作用是为每种配置提供顶点净流量的簿记框架（见 §5.5 net($) 列）。"

### 3.4 §1.1 构造原则与现有代码 make_ratio_kline 的隐含冲突

v4 §1.1 声明：
> "比价序列的构造是逐时刻 A(t)/B(t)。"

现有代码 make_ratio_kline 的实际行为是 OHLC 各自除法（high/high, low/low），这与逐时刻构造原则不一致。Gemini §5.1 已识别此问题。

v4 文本本身的声明是正确的。但 v4 没有显式标注这个原则与当前代码实现之间的差距。

**严重程度**：低（就 v4 文本而言）。v4 是理论框架文档，不需要标注代码实现状态。代码层面的修复是独立的工程任务（make_ratio_kline docstring 已在 commit 5164e6d 中标注待重构）。
