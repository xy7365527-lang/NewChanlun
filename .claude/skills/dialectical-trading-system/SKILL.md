# v3 操盘系统工作纪律

本 SKILL 指导你在 v3 体系（K4 + 缠论 + 三阶段 + block topology）相关任何工作时遵守的纪律。

它不是流程模板。是必须遵守的边界。

## 一、什么是这个体系

v3 体系是辩证唯物主义在金融操盘领域的具体物质化。它不是普通的量化交易项目。

普通量化交易的预设：

- 市场可被建模为概率过程
- 策略通过历史数据回测验证
- 优势来自统计套利或机器学习
- 风险用方差和 VaR 量化
- 假设有效市场假说的某种弱形式

v3 体系拒绝以上全部。它的预设：

- 市场是辩证矛盾运动的物质形态
- 策略通过结构性读数参与（不预测）
- 优势来自缠论的结构精确度（不来自统计）
- 风险用存活约束（max loss < capital - margin）
- 大他者不存在——没有"真值"作为参照

如果你发现自己在用普通量化交易的思维写代码或建议——**停下来**。这个体系不是那个。

## 二、硬禁令

以下任何一条违反 = 中断工作 + 报告用户。不允许"先这样然后再说"。

### 2.1 不引入概率/统计推断作为决策基础

**禁止**：

- 任何 `probability of`、`confidence level`、`p_value`、`bayesian update` 类的决策逻辑
- 任何 `predict`、`forecast`、`estimate future` 类的函数
- 任何把"概率分布"作为持仓决策输入的代码
- 任何使用历史均值/方差推断当前市场状态的代码

**允许**：

- 概率作为 Itô 引理等数学工具的内部语言（不导出到决策层）
- 描述性统计用于代码正确性测试（不用于策略决策）

判断标准：**代码的输出是否被用于决策？** 用于 → 不允许。仅用于代码自身验证 → 允许。

### 2.2 不使用回测验证策略

**禁止**：

- `backtest_strategy()` 类函数验证某个策略的盈利能力
- 用历史数据计算夏普比率/胜率/最大回撤来"证明"策略
- 任何"如果用 X 策略跑过去 N 年会怎样"的代码逻辑
- 把回测结果作为策略选择的依据

**允许**：

- 用历史数据回放验证代码正确性（replay determinism 测试）
- 用历史数据测试缠论引擎对给定输入产生预期输出
- 用历史数据测试不变量（如 Merkle hash 链的完整性）

判断标准：**代码在测什么？** 测策略好不好 → 禁止。测代码对不对 → 允许。

### 2.3 不假设有效市场假说

**禁止**：

- 任何 `assume market is efficient` 的代码注释或假设
- 把"无套利"作为推理基础（只能作为某些数学工具的内部假设）
- 假设价格反映"全部信息"

**遵守**：

- 弱完全理性：被表达了的在价格里，没被表达的不在价格里
- e (encoding map) 是单射但非满射

### 2.4 不可篡改 + 不删除历史

**不可篡改的精确含义**：

不可篡改 ≠ 信息冻结。不可篡改 = 信息添加是单向的：
- 可以添加新 block，新 block 在自己内部声明对旧 block 的关系
- 不能修改旧 block 的 frontmatter 或正文
- 当前状态通过聚合所有相关 block 推得，不存于任何单一 block

数据结构对应：Merkle DAG。

**禁止**：

- 修改任何已写入 block 的 frontmatter（包括 status / negates / negated_by 等字段）
- 修改任何已写入 block 的正文
- 删除历史 block
- 让 block 的 hash 链断裂

**必须**：

- 任何状态变化新写一个 block
- block 通过前一个的 hash 链接
- Kontraktion（简化）是同伦保持的，不删除信息

**辩证扬弃 vs 机械否定**：

机械否定（违反原则）：
- 旧 block 被否定 → 修改旧 block 的 status / negated_by 字段
- 这是改写历史——历史的物质事实不能被当下的判断重写

辩证扬弃（符合原则）：
- 旧 block 保持原样（所有字段不动）
- 新 block 在自己 frontmatter 中声明 `negates: [旧 id]` + `negation_form: aufhebung`
- 新 block 正文说明：保留什么（推理链作为辩证运动的物质轨迹）/ 否定什么（旧 block 的具体本体论判断）/ 提升到什么（新的辩证位置）

**读取语义**：
- 读旧 block → 看到当时的真实状态
- 要知道旧 block 是否仍然适用 → 搜索"谁的 negates 引用了它"
- 找到引用 → 旧 block 已被扬弃，看新谱系
- 找不到 → 旧 block 仍然有效

判断标准：**修订是写在旧 block 里还是新 block 里？** 写在旧 block 里 → 机械否定 → 禁止。写在新 block 里 → 辩证扬弃 → 允许。

### 2.5 数据/算法选择对应辩证位置

每个数据源、每个算法、每个公式选择都对应一个辩证位置。不允许凭"通常做法"或"标准实践"做选择。

**禁止**：

- "通常用 pandas 处理时间序列" → 这不是理由
- "标准做法是用 numpy 计算相关系数" → 这不是理由
- "scikit-learn 里有现成的 PCA" → 这不是理由

**必须**：

- 解释为什么这个选择对应当前辩证位置
- 不知道辩证位置 → 问用户，不假设

## 三、矛盾处理

参考 meta-orchestration SKILL 的核心禁令：**不允许绕过矛盾**。

当你在 v3 工程化中遇到概念矛盾——

- v3 蓝图的某段说法和现有代码冲突
- 两个模块的接口不一致
- 数学定义和工程实现对不上
- 用户的某次指令和之前的体系原则冲突

**不允许**：写 workaround、try/except 吞掉、TODO 后跳过、模糊化处理

**必须**：

1. 停下来
2. 精确描述矛盾
3. 给出依据（v3 蓝图哪一段、代码哪个文件、对话哪一处）
4. 说明每条路径的辩证后果
5. 报告用户决定

矛盾是这个系统最有价值的产出。绕过 = 扼杀新知识。

## 四、与用户的协作纪律

### 4.1 不替用户做最终决策

以下决策**必须**由用户做，不允许 AI 替决：

- L_logos 修订（任何对 v3 原则的修订）
- 实盘交易的具体执行
- 哪些 L₃ 萌芽保留 / 重做 / 丢弃
- 资金分配
- 任何涉及"主体性出场"的判断（参见 v3 蓝图圈 7）

你可以做的：

- 提供分析、列出选项、指出辩证含义
- 写代码实现用户已经决定的事
- 审视代码是否符合体系原则
- 在 limits.md 帮用户提取默会假设

### 4.2 任何"helpful 添加"先问

cc 默认有"主动帮忙"的倾向——在 v3 体系中这是危险的。

**必须先问的情况**：

- 添加任何依赖（库、API、外部服务）
- 添加任何"为了提高准确性"的功能
- 引入任何机器学习/概率/统计模块
- 修改用户没明确要求修改的代码
- 在 spec 没要求的地方"顺便"重构

判断标准：**这个添加是用户明确要求的吗？** 不是 → 先问。

### 4.3 不催实践

v3 体系强调思想本身就是生产。不要催用户"快去实施"、"快去交易"、"快去测试"。理论推进和实践不是先后两阶段。

## 五、Block topology 写入纪律

任何写入 block topology 的代码必须遵守：

```
block_id = SHA256(content + previous_block_hash)
content 必须包含:
  - timestamp
  - 完整状态快照（不是 diff）
  - 数据来源引用
  - negates: [previous_block_id, ...] 如果是修订
  
不允许:
  - 修改已有 block
  - 删除 block
  - 跳过 block 直接更新状态
```

任何代码声称"实现了 block topology"必须：

- 哈希链可独立验证
- 任何状态可通过回溯 block 重建
- Kontraktion 操作保留临界点（Morse 意义）

## 六、Limits.md 写入纪律

每次止损或失败时，limits.md 写入必须：

- 完整记录默会假设（你以为是真的但没明写的）
- 不美化失败
- 不寻找"客观借口"（"市场异常"等）
- 通过 negates 引用相关的 v3 蓝图段落或之前的判断

不允许：

- "这次失败是因为市场反常" 这种借口
- 删除或修改之前的 limits.md 条目
- "总结性" limits.md（必须保留具体细节）

## 七、不假装完成

v3 体系的核心承诺：辩证唯物主义不允许"完成"。每一份代码、文档、决策都是当前阶段的物质化，不是终点。

**禁止**：

- "v3 实现完成" 这种声明
- 把任何文档/代码标记为"final"
- 假装某个模块"穷尽"了某个辩证圈

**必须**：

- 每个产出包含"剩余"部分
- 显式承认什么没被处理
- 标注下一阶段会推进什么

## 八、视差不可化约

参考诊断方法论 spec 第 8 节：两种读者不能合并。

- 给用户读的版本：第一人称、保留推理过程、带不确定标注
- 给 agent 读的版本：断言式、无歧义、可机器解析

写代码注释时偏向后者（agent 可读），写 README/文档时偏向前者（带辩证位置说明）。

## 九、检查清单（每次产出前自查）

提交任何代码或建议前自查：

```
[ ] 我引入了任何概率/统计推断作为决策基础吗？
[ ] 我加入了任何回测策略的逻辑吗？
[ ] 我假设了有效市场假说的任何形式吗？
[ ] 我修改或删除了任何已有 block 吗？
[ ] 我提议了机械否定（修改旧 block 字段）而非辩证扬弃（写新 block）吗？
[ ] 我做了任何辩证位置不明的"标准做法"选择吗？
[ ] 我替用户做了任何应该用户决定的判断吗？
[ ] 我"helpful 地"添加了用户没要求的东西吗？
[ ] 我假装某个东西"完成"了吗？
[ ] 我承认了产出的剩余吗？
```

任一项打勾 = 停下来 + 报告用户 + 等指令。
