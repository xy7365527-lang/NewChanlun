## CODEX RESPONSE（完整输出，未截断）

### Q1. spec §13 祖先关系 `p: C_ℓ → C_{ℓ+1}` 是结构映射还是值比较？

**VERDICT: confirm（确认偏离 spec）**

§13 defines `AncOK(A)={a∈A:Anc(a)⊆A}` and says the ancestor relation depends on `p:C_ℓ→C_{ℓ+1}`; that is a structural parent-container map, not `(λ, eps)` equality. §7.2 and §10 also use `p(g)` as the parent container whose direction and ledger leg are semantically real.

The Rust model agrees: `CoverageElement.parent` is documented as `par(e)` from true `Compose` nesting, not level/value fabrication (coverage.rs:61, :84). `extract_elements` builds that parent chain from `sub_moves` (coverage.rs:107, :145).

So yes: `held_leg_tree_index` using `(level,ρ,eps)` / `(level,λ,eps)` is not `p`; it is only a value-key remapping hack (coverage.rs:905). As a proven injective resolver it could be tolerated. Here it is not proven and L2 already falsified its useful effect.

### Q2. 修复方案（对象身份追踪）是否对齐 spec §13？是否非 AncOK 放宽？

**VERDICT: refute（方案不成立）**

"Use TowerCache object identity" is not a valid plan as stated. `TowerCache.upper_moves` is stable internally (classifier/mod.rs:345), but the strategy does not consume cache references. `classify_with_tower_incremental` returns value snapshots, moving/cloning towers on the way out (classifier/mod.rs:715, :750). `run_theta_v0_pi` passes that returned `tower_i` into `pi_theta_step` (runner.rs:552), and strategy rebuilds `CoverageElement` from it every bar (coverage.rs:1131, interp.rs:307).

Worse: the current `Stale` path fabricates `parent: None` (coverage.rs:1059). Since `ancestor_close` only checks actual parent indices in `raw` (coverage.rs:395), this turns "unresolved parent" into "boundary root." That is an AncOK relaxation unless the leg was truly rooted at ∂.

**STRICTER alternative:** carry explicit stable structural IDs through `LeveledMove -> CoverageElement -> ActiveLeg`: `id`, `parent_id`, `is_boundary_root`. If an old active leg cannot resolve to the current structural element, prune/close it or keep its original `parent_id` for AncOK checking. Do not rewrite it to `parent=None`.

### Q3. 对象身份追踪 vs 值比较的 bit-exact 影响 / CoordDrift 在对象身份下如何处理？

**VERDICT: partial**

Tail append does not inherently break a deterministic structural ID. Higher-level root appearance does break per-bar `Vec` indices: the code says `extract_elements` starts from highest non-empty level (coverage.rs:111), and the interp comment explicitly says a new higher level restructures roots and remaps indices (interp.rs:360). That refutes "just use `CoverageElement.parent` across bars."

But pointer/object identity also breaks under the current API because returned towers are cloned values. A strict ID must be deterministic, not a pointer. It must preserve classifier bit-exact value output or deliberately separate ID metadata from value equality. The existing bit-exact contract is about full vs incremental tower values (classifier/mod.rs:605); ab5f5a29d only proves the current value-key path did not reduce Stale or Sharpe (runner.rs:280).

Also stop saying "λ drift" as fact. The code asserts `lambda` is stable under extension (interp.rs:92, coverage.rs:842). The real falsified claim is narrower: `(level,λ,eps)` did not hit usefully in L2. That may mean the key identifies the wrong object or lacks parent/container identity, not that `λ=start_index` drifted.

CoordDrift under structural ID: resolve by ID first. Then update `rho/source_index` from the current element and assert `current.rho >= old.rho` for extension. `rho>=source_index` becomes an invariant check, not the identity predicate.

### Q4. 是否有更严格的方案（对齐 spec 数学）？

**VERDICT: confirm（提供更严格方案）**

**STRICTER alternative:**

1. Add deterministic `ElementId` / `MoveId` to tower construction, e.g. `(level, ordinal_in_compose_output)` plus child IDs embedded in `LeveledMove`. Full and incremental paths must generate the same IDs.
2. `extract_elements_with_ids` emits `CoverageElement { id, parent_id, ... }`, not only per-bar `parent: Option<usize>`.
3. BSP candidates get `CandidateId { level, source_index, bits_disc, gamma_index }` plus `parent_id` from `attach_bsp_to_tree`.
4. `ActiveLeg` stores `id`, `parent_id`, and root-boundary status, not just `(level, dir, source_index, lambda)`.
5. Carry `A_t` by ID. Build `raw_ids=(A_t\D)∪B`. Apply `AncOK` over `parent_id` closure. Missing non-boundary parent means prune, not root.
6. When an active move ID resolves in the current tower, refresh its current coordinates and current parent chain. That handles higher-level root restructure without weakening §13.

That is the spec-aligned fix. "Use object identity" without this ID layer is handwaving and likely another zero-Sharpe patch.

### 1. 结论

Codex 异质审查（对抗性 refute）裁决：候选修复方案（对象身份追踪）**方向正确但不充分**；同时揭露当前实装已存在的 spec §13 偏差（Stale 路径伪造 parent: None = AncOK 放宽）。

**修复方案裁决**：
