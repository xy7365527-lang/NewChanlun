## 裁决：B（碰巧过现有测试但有未覆盖漏洞）

**机器证据坐实的漏洞**（Codex 发现 + 代理独立复现确认）：
`frontier_mutated` 守卫只比对 `project_to_units` 投影出的 `UnitRange`，该投影是**有损的**
（丢弃 `LeveledMove.rmove.subs` / `sub_moves`）。当 L0 frontier 改写使本级输入投影
`(start,end,direction,lo,hi)` bit-identical 但底层 `sub_moves` 变化时，上级守卫漏 reset，
导致上级 `cache.levels[k].upper_moves` 的**深嵌套 sub_moves 陈旧**，且 BSP memo（key 三长度）
同时复用陈旧 BSP。

### 复现（代理独立验证，非信 Codex 总结）

probe 通过真实守卫入口 `classify_with_tower_incremental`：
- v1 段账本：组C 末段 `Up[32,36] 115→147`，warm cache。
- v2 段账本：仅末段 `115→147` 改为 `115→140`（内点改写：组C max-hi=148/min-lo=115 不变 ⟹ L1[2] 投影 lo/hi 不变）。

PROBE_DBG 输出坐实：
```
L0:  frontier_mutated=true  ⟹ L0 reset（正确，重扫产新 sub_moves）
L1:  frontier_mutated=false ⟹ L1 不 reset
L1 cached_bsp_key v2=Some((1,1,0)) == v1  ⟹ BSP memo 命中复用旧值
深嵌套：L2cache[0].L1[2].L0subs = (115,147)  ← 陈旧！正确应为 (115,140)
```
cache.levels[1].upper_moves（L2 走势）的 sub_moves[2].sub_moves[2] 仍是 v1 的 147，
未被 v2 的 140 更新。BSP memo key 三长度不变 ⟹ 连 BSP 也是 v1 旧值。

### 为何现有测试 PASS（有效域 vs 定义域）

`bit_exact_per_bar`（8000 真实 CL bar）PASS，`assert_eq!(inc_cls,leg_cls)` + `inc_tower==leg_tower`：
- `Classification.levels[k]` 只含 `moves/centers/bsp`，不含 LeveledMove 嵌套 sub_moves。
- `tower_snapshots` 只捕获每级 INPUT 快照（`mem::take(&mut moves_tower)`），不含顶层
  `cache.levels[top].upper_moves` 的深嵌套。
- 陈旧的深 sub_moves 只在以下路径才浮到被比对的输出：
  (a) 更高一级（L3+）消费该陈旧 L2 走势；
  (b) `extract_second_for_level(&lc.upper_moves)` 读 sub_moves 的某字段进入 B2/S2 判定，
      且陈旧值实际翻转某个背驰/坐标决策。
  我的 probe 构造里陈旧字段（价 147 vs 140）未翻转任何 B2/S2 决策 ⟹ Classification 仍相等。
  8000 bar CL 序列同理——没踩到"投影不变 + 嵌套变 + 嵌套差翻转高层决策"这一格。

**这是 L2 有效域问题**：bit-exact 在 8000 CL bar 上经验成立（有效域），但守卫的
完备性（定义域）依赖一个未被验证的前提——"投影相等 ⟹ sub_moves 相等"，该前提**为假**
（`project_to_units` 有损）。8000 PASS 不能证明守卫完备，只能证明该序列未触发反例。

## 逐点核对（Codex + 代理）

- **1a** consumed+2 对"本级 UnitRange 值变"够（窗口读 [i,i+1,i+2]，退出 consumed+2>=len）。
  漏洞不在窗口深度，在投影有损（见上）。
- **1b** 时序一致：reset 后立即写 cached_units 再重扫。无独立漏洞。
- **2a/2b** L0 第一类 confirmed C 段端点来自分型/笔/线段（需右邻 K），不覆盖当前 inclusion
  尾 acc ⟹ 尾 hist/close_src 改写不影响 L0 第一类。**但**高层经 stale sub_moves +
  `sublevel_diverges`/`index_of_in` 读 hist 时坐标可陈旧（与主漏洞同根）。
- **3a/3b** `update_closes_cache` O(1) 快路径只看尾 close、增量校验只看 close 不看 close_src，
  裸 helper 前提不完备。但生产路径 phase B inclusion 只 pop/push 尾 acc（前缀不动，
  `inclusion.rs:395-400`），合并保留 acc.source_index 仅更新 close ⟹ 当前未构成主反例。
  phase A→B 裸反例通常发生在线段空阶段，`mod.rs:719` `cache.clear()` 兜底。
  **留待加固**：快路径+增量校验应同时校验 close_src，否则前提隐式不可证伪。
- **4a** 仅性能：break 跳出 loop，循环外仍归还 closes/close_src；唯一空 Vec 路径是
  panic+catch_unwind，下 bar 退化重建（非正确性）。

## 边界条件（裁决翻转条件）

本裁决 B 成立的前提（可证伪）：存在一个 bar 序列使得某级 frontier 改写后
**投影 UnitRange 不变但 sub_moves 变，且该差异翻转更高级别的 center/B2/S2/depth 决策**。
probe 已坐实 sub_moves 陈旧（数据层 100% 确定）；尚未坐实"翻转高层决策"的完整端到端反例
（需 L3 消费链或 sub_moves 价差进入背驰判定的构造）。
若能证明 sub_moves 的任何字段都不可能进入任何高层判定（即陈旧 sub_moves 是纯死数据），
则降级为 A——但这需要遍历 sub_moves 的所有 consumer，工位 F 未提供此证明。

## 影响声明

- 影响模块：`classifier/mod.rs` 增量塔守卫（frontier_mutated）+ BSP memo。
- 不影响：parser、L0 第一类、closes 缓存正确性（3a/3b 当前生产路径未触发）。
- 修复方向（不在本审查产出，留给工位 F）：守卫比对从有损投影 `units[..scanned]` 改为
  比对**携 sub_moves 的本级输入**（即 moves_tower/upper_moves 的 LeveledMove 序列前缀），
  或在 L0 reset 后强制 cascade reset 所有更高级别（最严格、bit-exact 退化）。
