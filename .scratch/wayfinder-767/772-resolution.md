# 裁定：并行纪律——多会话同写一张图的冲突口径

会话日期 2026-07-30。事实底稿见本票上一条评论（GitHub API 对 issue 正文**没有任何条件写/乐观锁**；`gh issue edit --body` 是整体替换；覆盖是静默的，事后从 timeline 也查不出来）。

## 订正开票前提：丢的不是决策，是索引

开票时把这题写成「静默数据丢失，无解」。**这个前提要收窄。**

wayfinder 的规矩是「一条决策只活在它自己那张票里」——图正文的 `## Decisions so far` 按设计**只是索引**：一行 gist + 一个链接。决策正本是子票的 resolution comment，而 comment 是 append-only 的，并发写根本碰不到它。

所以并发覆盖丢的是**索引里的一行**，不是决策本身。而且这一行是**可再生的**：列出这张图所有已关子票，跟正文里已有的行对账，缺哪行补哪行（`gh api repos/<owner>/<repo>/issues/<map>/sub_issues --paginate` 过滤 `state == "closed"`）。

这把原判的「无解的静默丢失」降级成「**可检测、可重建的索引漂移**」。四条裁定都建立在这个订正上。

## 裁定

### ① 写入协议 = 保留正文整体重写 + 对账重建

不改成评论追加。理由：图正文「一次加载看完全貌的低分辨率视图」是 wayfinder 的核心价值（skill 正文明写），换成评论流就得让每个读者自己按时间折叠重建当前状态，而且没有字段标记哪条已被覆盖——为了一个可再生的索引，牺牲图的主要功能，不划算。

三条纪律：

1. **窗口压到一次操作**：要写的那一刻才 `gh issue view <map> --json body` 读正文，读完立刻拼好新正文写回。不要开会话时读一次、干完活再拿旧副本写回。
2. **写前重比**：读正文时记下 `updated_at`，真正发 PATCH 之前再 `gh api repos/<o>/<r>/issues/<map> --jq .updated_at` 查一次；变了就重读重拼。这是**应用层自拼的读后重比，不是原子操作**——中间仍有毫秒级的 TOCTOU 残窗。它挡的是人类/会话尺度（秒级以上）的真实竞态，不宣称消除竞态。冲突就重试一次；再冲突则停下来报给人，不要盲目循环。
3. **对账重建**：见裁定④。

### ② 认领竞态：不管，接受偶发重复

不加机制。理由：GitHub 的 assign 是「加进集合」不是互斥，本来就锁不住；HITL 票必须真人在场，撞车当场可见；AFK 票撞车的代价只是一个子代理白跑一次。加锁成本高于损失。

### ③ 迷雾毕业：谁清的雾谁毕业

`## Not yet specified` 段只由「本次解决的这张票让这片雾变清楚了」的那个会话动。两个会话同时毕业同一片雾 → 开出两张重复票 → **重复票是看得见、能关掉的**，比静默丢失轻得多：后发现者关掉后开的那张、在关票理由里指向先开的那张。

不采「任何会话都可动」（重复率明显上升），也不采「集中到开图会话」（雾清了却要等下一次开图才能变票，节奏被拖慢）。

### ④ 对账节拍：每次走图会话开头

走图会话本来就要加载图、查 frontier（可取的票），顺手把「已关子票列表」跟正文里的决策行一比，缺行当场补。成本一条查询，且**丢行最多存活一个会话就被抓回**。

不采「只在图收口时」（中途每个会话读到的都可能是残缺图，而图的作用正是让会话快速定位，残缺图会让人重复提问），也不采「只在怀疑时」（静默覆盖的特点就是看不出来，「怀疑」这个触发器本身不可靠）。

### ⑤ git 层冲突：移出本票，只挂指针

工作区/分支撞车有现成解——`/resolving-merge-conflicts`，且 git 会把冲突显式标出来、拒绝静默丢改动。正本里挂一行指针即可。

**工作区隔离**：**写仓的无人值守子代理强制开独立 worktree（`Agent` 工具 `isolation: "worktree"`），只读子代理不强制。** 理由：本仓事实上已经在跑几十个 worktree（本票事实底稿第 4 节实测），成本只有零点几秒；而主仓撞车有实伤前例（`git stash` 抹掉未提交改动）。只读子代理开 worktree 纯属浪费。这条把现状从「各会话约定俗成」提升为**明写的规则**——仍是声明制自执行，不设巡查/CI 硬门，与 `delivery-discipline.md` 同款。
