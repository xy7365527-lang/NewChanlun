### ② 固化在图上，不固化在会话第一句

不做可粘贴的开场模板，不新建本仓 skill、不新建 slash 命令。走图会话第一句仍然只是 `/wayfinder <图链接>`。开场纪律靠**图 Notes 的「每会话必读」清单**把文件拉进上下文——该机制已在跑（本图 Notes 现有清单让本会话开场读到了 `issue-tracker.md`），零新增载体。

**否掉「什么都不固化」的理由**：#772 定的已关票↔正文对账、写正文前压 `updated_at` 重比，以及本票定的一次一问，都是**本仓特有**动作，`~/.agents/skills/wayfinder/SKILL.md` 正文里没有；正本没被读进来就会静默跳过——#776 就是这么翻车的。

**否掉「做开场模板」的理由**：模板要人记得去粘贴，与「记得去读正本」是同一个失效模式，没有改善。而 Notes 清单是开图时抄一次、之后每次自动生效。

这条同时解掉原票待裁 3（载体）：载体 = 正本文件 + 每张图 Notes 里的一段清单，不新建任何 skill / 命令。

### ③ 清单由正本给默认版本，开图时照抄进 Notes，各图按域追加

不采「每张图各写各的、正本只规定要有这一节」。理由：手写就是会漏——本图 Notes 那条清单是手写的，它点了 `issue-tracker.md` 和全局 `CLAUDE.md`，**没点正本**（当时正本还不存在），而漏的恰恰是最关键那份。默认清单另有一个好处：正本改名或搬家时只改默认清单，新图自动跟上。

**代价**：每张图 Notes 开头都会有一段近乎相同的样板，图正文变长——而图的核心价值是「一次加载看全貌」（#772 裁定①原话），样板花的是这个预算。

### ④ 默认清单只列仓内三份，全局文件不进清单

默认清单 =
1. `docs/agents/wayfinder-workflow.md`（本仓 wayfinder 正本）
2. `docs/agents/issue-tracker.md`「Wayfinding operations」段（tracker 物理操作）
3. `AGENTS.md`（#517 定的全 harness 唯一正本入口）

全局 `~/.claude/CLAUDE.md` 的三段（模型路由表 / 派发授权 / 动手前先挂 ticket）**不进清单**，改为把其本仓适用要点补写进 `AGENTS.md`。

两条理由：一是 `~/.claude/CLAUDE.md` 在 Claude Code 里本来就自动注入，清单点它是白点一次——清单的全部价值在于拉那些**不会自动进来**的文件；二是 Kimi（主力运行时）读不到它，而 `AGENTS.md` 两个 harness 都读得到。

**否掉「保留它 + 加一句 Kimi 改读 AGENTS.md」的理由**：那会让清单里带 harness 分叉，每个开图的人都要先判断「我现在是哪个 harness」——而清单本来就是拿来免判断的。

**代价**：全局 CLAUDE.md 的一部分口径要在仓内复写一份，两处日后可能漂移（与③同款代价）。

按域追加的示例写进正本：纯决策图（如本图）不必读 `AGENTS.md` 之外的重型文件；**碰代码的图应追加 `AGENTS.md` 里指向的域文档**（如 `delivery-discipline.md`、`generation-constitution.md`）。

### ⑤ 无人值守票不做同款固化

research / 可 AFK 的 task 不需要开场清单。理由：本票要治的失效模式是「人开新会话、上下文是空的、本仓特有纪律进不来」；派子代理时本体手里有图、有票、有正本，prompt 是照现场写的，**没有「忘了读」这个失效模式**。另外 #776③ 已定何时该派子代理、#772 裁定⑤已定写仓要不要开 worktree，再定一个派发骨架是三处口径叠着，容易打架。子代理该带什么上下文，归 [票型 × 模型档位 #781](https://github.com/xy7365527-lang/NewChanlun/issues/781)。

**代价如实记**：子代理 prompt 质量全靠本体当场发挥，同一类活派两次带的上下文可能不同，目前无机制兜底。
