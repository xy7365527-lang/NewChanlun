## Resolution（2026-07-30，`/grill-with-docs` 一次一问，编排者逐条裁定）

四件事全裁，另加两条会话中当场浮出的订正。

### ① 收敛的单位：先裁总缝，再逐概念

**不逐个概念切七张票**，第一批只开**一张总缝票**，裁一条横穿所有概念的规则：

> 同一个判定，级别的差异只准以数据形式传进去，不准写成按级别分叉的两套代码；凡分叉一律举证，举不出就出局。

理由：靶子已被 [#787](https://github.com/xy7365527-lang/NewChanlun/issues/787) 立图前提改成「设计一套能每级复用的」而非「40 套里投票选一套」，⟹ 40 套里有一大类的毛病是**同一个毛病**（同一判定写了两份）。[#789](https://github.com/xy7365527-lang/NewChanlun/issues/789) 点名最烂的区间套（4 坐标系 + 4 停止级）与中枢（同塔 L0 与 L≥1 定义不同）都有大块落在这条缝上；[#801](https://github.com/xy7365527-lang/NewChanlun/issues/801) 实测 `theta_v0` 已 90% 是目标形态、`is_l0` 分叉即 40 套的机制源头之一。**先切七张 = 在不知道剩多少分歧面时定边界。**

代价照实记：**串行、慢**。总缝票走完前第二批一张开不出来。

### ② 权威次序：三方分层，不排名次

- **缠师原文管语义**——「这个概念是什么」，不可推翻；
- **Lean 形式化管边界**——原文没讲的端点与退化情形，`formal/Origin/` 定义式即该类问题的正本；
- **生产代码没有发言权、只有否决权**——不得以「现在就这么跑的」为由支持一条口径，但可用实测读数打回一条裁定。

**为什么必须分层而非排名次**：现成的三级递减权威链（博文 > chan99 > 思维导图）遇到 40 套里的一大半会直接失效——原文是自然语言讲课稿，**根本没处理端点**。实例：中枢核心区间非空，Rust 严格 `<`（[#321](https://github.com/xy7365527-lang/NewChanlun/issues/321)）vs Lean 弱 `≤`，`rust/src/theta_v0/classifier/center.rs:13` 自陈「Lean 侧未随 #321 跟进」；「单点核心（`ZD==ZG`，三段重叠退化成一个价位）算不算中枢」原文一字未提。

**直接推论：[#321](https://github.com/xy7365527-lang/NewChanlun/issues/321) 那次是裁错了层**，不只是跟进不及时——端点问题归 Lean 管，却只裁了 Rust 侧。

### ③ 裁定的收尾：文字正本 + 受影响代码清单

裁定票关票需两件，缺一不可：

1. 文字正本落 `.chanlun/definitions/` 对应文件；
2. 附**受影响代码清单**，点名到文件行号（Rust / Lean / Python 各几处）。真改码进下游实施链，由该清单驱动。

**「在代码注释里登记口径分歧」不再算合规收尾**——注释可以写，但**必须带票号**；分歧只能存在于已开的票里，不能只存在于注释里。

实测规模：仓内这种做法**只有 1 处孤例**（`center.rs:13`），不是泛滥的习惯——但它孤零零活到今天，恰说明**没有任何机制会去清它**。

### ④ 正本载体：沿用 `.chanlun/definitions/`，补名分

**会话中当场撞出的事实**：`.chanlun/definitions/` 里躺着 **15 份、4295 行**定义文件，而 **`AGENTS.md` 一个字都没提它**——`AGENTS.md:23` 指定的单 context 是根 `CONTEXT.md` + `docs/adr/`。**这批文件没有名分**：写了、在仓里、内容不少，但全 harness 正本入口不指向它，照 `AGENTS.md` 进场的人（含 Kimi 主力运行时）根本读不到。**本图立图前提那个病的又一个标本。**

裁定：一概念一份继续当正本，补两件——
1. `AGENTS.md` 立该目录为**缠论教义唯一正本入口**，与权威链并列（**权威链管「证据从哪来」，该目录管「裁完的结果是什么」**）；
2. 每份文件固定三行头：正本声明 / 最后裁定票号 / 受影响代码清单指针。

**主控自决一处（已报编排者）**：15 份文件的三行头**不在本会话补齐**——「最后裁定票号」与「受影响代码清单指针」现在填不出真话，只能编。改为在 `AGENTS.md` 把三行头立成规范，各文件的头由该概念裁定票落地时填，避免落一批空壳头。

### ⑤【订正】`src/newchan/nesting/` 不是同名异物

本票票面（转述 [#789](https://github.com/xy7365527-lang/NewChanlun/issues/789)）称该目录的「区间套」指横向搜索空间收缩、**与缠论区间套完全无关**。**实读源码，该判定撤回**：

```
src/newchan/nesting/nesting_operator.py
  统一区间套算子 N : (SearchSpace, Level) -> (Target, BSP_confirmation)
  「纵向和横向区间套都是 N 的实例。」
    HORIZONTAL = 横向：搜索空间收缩（配置→角→板块→标的）
    VERTICAL   = 纵向：级别下钻（同一标的，级别 k → k-1）
  概念溯源：[新缠论] 全球资本流转拓扑：级别与买卖点 v2
src/newchan/nesting/horizontal.py
  「六步不是六种操作，是同一个操作 wait_divergence -> confirm_BSP -> narrow_scope 的六次应用。」
```

**不是撞名，是编排者自己写下的一次统一主张。** 且与 [#787](https://github.com/xy7365527-lang/NewChanlun/issues/787) 刚立的「双向递归」前提正面相关——这里冒出的是**第三个方向**，而仓里已有人试着把其中两个统一成一个算子。**「没人知道已经有什么」第三次现形。**

处置（编排者裁定）：**算子 N 的统一性主张进区间套那张概念裁定票**——该票需同时回答「区间套的正本定义是不是算子 N、纵向与横向是不是它的两个实例」。**应用域（选标的）仍在 [#787](https://github.com/xy7365527-lang/NewChanlun/issues/787) Out of scope 内不动**；界内的是算子的统一性，因为它直接决定区间套正本该写成一个算子还是一个级别下钻程序。
