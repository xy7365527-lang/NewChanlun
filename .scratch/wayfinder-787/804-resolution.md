## 裁定一：规则落在**语义**，不落在代码形状

> **同一个判定，每一级必须跑同一个判定；级别的差异只准以传进去的值出现，不准是另一套判据。**

**判别式**：把两级的输入换成同一份数据喂进去，**两边输出必须逐位相同**——不同就是两个判断。

**否掉「形状口径」的三条理由**：

1. **上位约束已排除它**——[#799](https://github.com/xy7365527-lang/NewChanlun/issues/799) 裁定十一原话：grep 挡不住「另写一份同义代码」；`div_cand` 与 `sublevel_diverges` **零共同标识符**，任何语法扫描都抓不到。本票若落在形状上会与它正面打架。
2. **实测四个病灶只有一个是形状病，而它恰恰最易伪装**——`if level == 0 { A } else { B }` 改写成 `TABLE[level]` 即可让 `level ==` 的 grep 归零，而两级仍是两套中枢定义（[#794](https://github.com/xy7365527-lang/NewChanlun/issues/794)），分歧一点没变。另三个（`div_cand`/`sublevel_diverges`、实验箱 `c327_weak_*` 重抄、π 门 `Type2|Type3 => true` 免判）**没有一个能被 grep 命中**。
3. **本图元判据**：拿产出的外形当分类维度是本仓已撞三次的错误。承重的是「它在系统里干什么」。

**配套两条**：
- **grep 降级为分诊线索，不是判据**——命中不等于违规，零命中不等于合规。
- **机械锁走对拍测试**（属 #799 的「行为不变式」类）；据其附带原则「只编译不执行的锁按无锁计」，**本条落地的前置 = 先让 CI 跑 `cargo test`**（#799 已定为下游实施链第一条动作）。

**明写代价（090 照实）**：语义口径贵——每条判据都得配对拍测试，写不出对拍就立不住；形状口径一条 grep 即可。取贵的那条是因为便宜那条抓不到本仓实际有的病，**不是因为它没缺点**。

## 裁定二：举证门 = 例外可以有，但必须**自带退场条件**

票面 ① 原来担心的「误伤」情形——「同一判定吃不同输入类型是合法的」——**走图当场查实：这条辩护在本仓的实际代码里不成立**。

```
pub fn center_from_segments(a: &UnitRange, b: &UnitRange, c: &UnitRange) -> Option<Center>  // center.rs:210
pub fn center_from_window  (a: &UnitRange, b: &UnitRange, c: &UnitRange) -> Option<Center>  // center.rs:252
```

**签名逐字相同**，同类型进同类型出；差别只有 `center_from_segments` 开头一句 `if !dir_alternates(a,b,c) { return None }`。`recursive_tower.rs:304` 的 `compose_level` 用 `let build = if is_l0 {..} else {..}` 分派（`:859` 的 `compose_level_resume` 同款）。**这与 [#799](https://github.com/xy7365527-lang/NewChanlun/issues/799) 裁定十的 `div_cand`/`sublevel_diverges` 是同一个形状**，且正踩在 #799 判别式「看两套判据是不是接在同一个 if-else 上」的正面。

**但它与背驰那条有一处真差别：它已经带着一份举证书**——`center.rs:235` 起的文档注释「★诚实有效域（非补丁）」：上级单元是中枢外缘区间、**无内在缠论方向**，故方向交替不可判；援引 `Origin.CenterStates.classifyDevelopment`（上级发展态用外缘判据，本就不要求方向交替）背书。

**裁定：这类理由算数，但举证成立须同时满足三件**——

1. **指得出实质**：不是「这样方便」，而是能指出上级输入确实不含该维度，且有权威源背书（原文 / Lean 定义式）；
2. **写得出退场条件**：举证书**必须回答「这条缝在什么条件下消失」**，答不出的一律不算数。这是本图 Notes「另起一套必须配退场条款」在教义层的同一条纪律（成因即 `theta_v0/mod.rs:13-18` 只写前半句、`recursive_t` 因此挂到今天）；
3. **不超上限**：按 [#799](https://github.com/xy7365527-lang/NewChanlun/issues/799) 裁定二，此类缝**全仓上限 3 条**，触顶即必须做强版（把缺的维度上载进数据类型）。

**否掉的两端**：
- **全认（只要说得出理由就算）**——这类辩护太好补，40 套口径里相当一部分事后都能写一份形状类似的，规则自废。
- **全否（缺维度不是理由，回去改数据类型）**——实测现役只有 1 条缝且有 Lean 背书；砍它要动数据类型、**成本从未估过**，且 Lean 侧上级本来就用外缘判据，硬收成一个可能与形式化打架。

**明写代价**：中枢那两套算法因此还要并存一段时间，等第二批中枢概念票来收。

## 裁定三：举证书的载体 = 随概念走，不另建台账

- **正本**写进该概念的 `.chanlun/definitions/<概念>.md`，作**例外条款**段（含退场条件 + 票号）；
- **谁点头** = 裁该概念的那张票，**不为每处例外单开票**（否掉「每处单开一张票批」：严但慢，每发现一处就得停下走一遍流程）；
- **代码注释只留一行指路且必须带票号**（[#793](https://github.com/xy7365527-lang/NewChanlun/issues/793) 关票判据：光写在注释里不算合规收尾）；
- **不建总清单**（否掉「单建一份总台账」：多一份文件要维护，且与定义文件必然对不上）。上限 3 处小到数一遍就知道。

**明写代价**：清单是散的，想知道用掉几处得翻 15 份定义文件；真逼近 3 处时可能要回头补一份汇总。
