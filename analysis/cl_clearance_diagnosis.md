## 结论（一句话）

CL v4 从 +221.5%（v2）坍塌到 +2.7% 的全部差距（+1.14 log）**几乎不是
"区间套没递归到位"**——区间套递归到位（deep_fires=2764，located 记忆
下探到 ladder6）；真实死因是**双机制耦合**：(1) 清仓判据的参照层 `top`
被定义为"历史累积≥10 中枢的最高阶梯"（棘轮式单调攀高），叠加"confirmed
Sell1 ∧ located 同层同 bar"合取，在 CL 这种 5.5M bar 高波动标的上把清仓
频率**压死在 3 次**（与 OKLO 完全相同）——波动率信号被合取的稀疏性淹没；
(2) 不清仓原则让 root 永不重置，单棵永续树封顶在 recL2（持全史穿三次
油崩，−14807），**v2 的 +242482 最大 alpha 源（recL3/long 9 笔）是"清仓-
重涌现"的产物，不清仓即消失**。修复方向（普适，非 CL 特化）：清仓参照系
从"棘轮累积层"改为"当前正在走势完美的最高级别（located 活跃层）"，让清仓
频率成为波动率的**涌现函数**。

## §1 CL 清仓事件时间线（v4 vs v2）

### 1.1 清仓计数与出场词汇分解

| | sellpt（清仓） | negate（否定线） | flip/recover | cascade | eod | n_trades |
|---|---:|---:|---:|---:|---:|---:|
| **v2**（nrf_final） | **127** | 53 | flip 634 | 6 | 1 | 821 |
| **v4**（不清仓） | **3** | 148 | recover 416 | 3 | 1 | 571 |

v2 的 C 规则在"每个根卖点"清仓 ⇒ 127 次；v4 §6 合取（confirmed
Sell1@top ∧ located）把清仓压到 3 次。**v4 的 sellpt=3 与 OKLO 的
sellpt=3 完全相同**——这是诊断的第一个信号：CL（5.5M bar、MDD −94%、
三次年度腰斩）与 OKLO（447K bar、单边强牛）清仓次数一致，说明清仓频率
**与标的波动率脱钩**，被合取结构钉死。

### 1.2 这 3 次清仓落在哪里？

JSON 缓存只记录计数（sellpt=3），**不含 3 次清仓的精确 bar**（需引擎
插桩重跑才能定位）。但年度 P&L 给出**否定性证据**——这 3 次清仓**没有
落在任何一次油崩前的顶**：

| 油崩年 | BH_log | v4_log | v4−BH | 解读 |
|---|---:|---:|---:|---|
| 2014（油价腰斩 −46%） | −0.6068 | −0.5935 | +0.0133 | v4 ≈ 全吃 |
| 2015（续跌） | −0.3818 | −0.3617 | +0.0201 | v4 ≈ 全吃 |
| 2020（COVID） | −0.2440 | −0.2380 | +0.0060 | v4 ≈ 全吃 |

三次深崩年 v4 与 BH 的差异全部 < +0.02 log（且这点微小优势来自 slice
短差，非清仓）。**若 3 次清仓中有任何一次落在崩盘前的顶，对应年份 v4 应
显著优于 BH（像 v2 那样）——数据上没有发生。结论：这 3 次清仓在崩盘
保护上零贡献，它们触发在结构上无害/迟到的位置。**

## §3 区间套递归到位吗？——否定"没递归到位"假设

任务假设之一："区间套是否没递归到位导致高级别完美没被识别"。**数据否证
这个假设**：

| 区间套活性指标（CL v4） | 值 | 判定 |
|---|---|---|
| deep_fires（下探到 < k−1 的次数） | [0,0,0,**2626**,122,16] = 2764 | ✓ 大量下探 |
| nest_fire_sell（卖侧定位触发） | [0,0,12284,2016,**154**,17] | ✓ 高层有产出 |
| located 到达层 | 直到 ladder6（recL4） | ✓ 高级别完美被识别 |

区间套**递归到位了**：证据下探到 a0（2764 deep fires），卖侧定位记忆
（located_sell）在高层 ladder5/6 都有产出（154/17 次）。**"高级别走势
完美"被识别了**——located_sell 在高层有非零产出就是证明。

**所以失效点不在区间套递归活性，在清仓判据如何消费这些 located 记忆。**

## §4 真实失效点（一）：`top` 棘轮 + 同层同 bar 合取

### 4.1 清仓判据的代数结构（L0，从代码定义）

`nested_fugue.rs` line 422-425 定义参照层：
```rust
// 当前最高 θ 涌现层（C 清仓判据层 + F 入场层）。
let top = (floor_ladder..MAX_LADDER).rev()
    .find(|&k| depth_ref.theta(k, None, SUB_COST_Q, SUB_COST_MIN_OBS).is_some());
```
line 459-471 清仓合取：
```rust
if sig.sell1.get(top) && located_sell[top].is_some() {
    unwind_to(0, ...);  // 全链清仓
}
```

`depth_ref.theta(k)`（`depth_ref.rs` line 90-110）**只要求 `bufs[k]` 累积
≥ `SUB_COST_MIN_OBS`(=10) 个中枢**就返回 Some。缓冲是"最近 50 个中枢"的
环形队列，**只在新中枢边界变化时更新**（line 50-86）——中枢一旦入缓冲就
持久保留（与时间无关）。

### 4.2 棘轮性（L0 推论）

> `top = max{ k ≥ 2 : 该层历史累积观测过 ≥10 个中枢 }`

这是一个**单调攀高的棘轮**：一旦高阶梯累积满 10 个中枢，`top` 就升上去
**永不回落**（缓冲不会因时间流逝清空）。CL 跑 5.5M bar / 16 年，高阶梯
（ladder5/6）的中枢必然累积过 10 个门槛 ⇒ **`top` 长期卡在高阶梯**。

### 4.3 合取被稀疏性钉死（L0+L2）

清仓要 `sell1[top] ∧ located_sell[top]` 在**同一最高 top 层、同一 bar**
同时成立。`top` 越高：
- `sell1[top]`（该层 confirmed Sell1 趋势顶背驰）越稀疏（高层 BSP 事件少）；
- `located_sell[top]`（该层区间套定位记忆活跃）越稀疏，且破极值即失效
  （line 417-419）；
- 两稀疏信号同 bar 对齐的概率 → 趋近零。

**实证锚点**（在册 §6 判别力，`nrf_v4_strict_accounting.md` line 73-77）：
OKLO 单条件版本（任意 confirmed sell@top，无 located）清仓 **77 次**；
加 located 合取后清仓 **3 次**——**located 同层合取砍掉 96%**。located
合取是绑死频率的主因。

### 4.4 反直觉的方向（诊断核心）

> **波动越大 → 结构涌现越高 → `top` 棘轮越高 → 清仓判据越严 → 清仓越少。**

这与任务直觉（"CL 波动大应该高级别完美更频繁 → 清仓比 OKLO 多"）**方向
完全相反**。当前 `top` 定义把"涌现更高"翻译成"判据更严"，于是 CL（top高）
和 OKLO（top较低）殊途同归都清 3 次——波动率信号被棘轮 + 合取淹没。
**这正是为什么同一判据没有产生不同频率：判据的参照系选错了。**

**v2 总 ≈ +461.8K cash vs v4 总 ≈ +16.2K cash。**

### 5.2 recL3 alpha 是"清仓-重涌现"产物（L2）

`root_entries`（每层新建 root 计数）：
- **v2**：`[0,0,27,90,32,9,0...]` = 158 个 root，分布到 ladder5（recL3）**9 个**。
- **v4**：`[0,0,1,3,2,0,0...]` = 6 个 root，**最高 ladder4（recL2），ladder5=0**。

v2 清仓 127 次 ⇒ 每次清仓后下一个买点**重新建 root** ⇒ 158 个 root 在
16 年的**多个上涨周期里各自重新涌现**，其中 9 个爬到 recL3（每个持
~216872 bar ≈ 150 交易日，落在某轮上涨周期内，+242482）。

v4 不清仓 ⇒ root 永不重置 ⇒ 只 6 个 root，**单棵永续树封顶 recL2**，且
这个 recL2/long 持全史（2.24M bar，跨 2014/2015/2020 全部崩盘）⇒ **−14807**。

> **recL3 的 +242482 不是"v2 更会选 recL3"，而是清仓让 root 在每轮新
> 上涨周期重新涌现到高级别的副产品。不清仓 = 单棵树被深崩按穿 = 高级别
> 长持腿从 alpha 源（+242482）反转为亏损源（−14807）。**

### 5.3 两机制耦合

机制一（§4）与机制二（§5）不是独立的——**清仓正是让 root 树重置、级别
重新涌现的机制**。不清仓 → root 冻结 → 树封顶 recL2 → 该层"完美清仓"
判据（sell1∧located@top）更难触发 → 更不清仓。这是一个**自锁循环**：
v4 把清仓做成"最高涌现级别完美"的函数，而最高涌现级别（就 root 树而言）
又被"不清仓"压低、就 `top` 棘轮而言又攀到信号稀疏的高位——两头都让清仓
失活。

## §6 修复方向（普适化，非 CL 特化）

任务要求："同一判据自然产生不同频率"——清仓频率应是波动率的**涌现
函数**，不是 per-asset 白名单。当前缺陷已定位为**参照系选错**。候选修复
（均为预注册假设，待 L3 验证；不实装、不声明已验证）：

### 候选 A（首选）：清仓参照系 = "当前正在走势完美的最高级别"

把 `top` 从"棘轮累积层"改为"当前 located 活跃的最高级别"：
```
top* = max{ k ≥ floor : located_sell[k].is_some() }   # 当前正在完美的最高级别
清仓 ⟺ sig.sell1[top*]                                 # located 已由 top* 定义蕴含
```
- **普适**：所有标的同一条规则（最高正在完美的级别出现 confirmed 顶背驰
  ⇒ 清仓），零 per-asset 参数。
- **频率涌现**：CL 高波动 ⇒ 高级别下跌走势频繁完美（located 频繁在高层
  活跃）⇒ 清仓多；OKLO 单边强牛 ⇒ 高级别完美罕见 ⇒ 清仓少。**同一判据，
  频率随结构涌现自然分化**——这正是任务要的形式。
- 与在册同构：把"涌现级别"从"历史累积棘轮"改为"当前活跃事件"——同
  `最高涌现级别σ作regime观测量`（在册：级别~时间尺度，须看当前窗口而非
  全史累积）的修正方向一致。

### 候选 B（配套）：清仓真正重置 root，允许重新涌现

清仓后 root 归零、下一买点重建 root（恢复 §5 的"重涌现"机制），但保留
A 的严格触发（只在最高完美级别清，非 v2 的每根卖点清）。A+B 联立预期同时
回收：(1) 崩盘前清仓（§2 的 +2.15 避险），(2) 上涨周期 root 重涌现到
recL3（§5 的 +242K alpha），且不吃 v2 的全部踏空成本（−1.01）。

### 预注册判据（先于运行声明）

| 判据 | 内容 | 否证条件 |
|---|---|---|
| **R1** | 修复后 CL 清仓次数 > OKLO 清仓次数（频率随波动率涌现） | CL ≤ OKLO ⇒ 参照系仍未解耦，A 否证 |
| **R2** | CL 三次主油崩（2014/2015/2020）至少 2 次年度 v4* 显著优于 BH（清仓落在崩盘前顶） | 三次全 ≈ BH ⇒ 清仓时点仍迟到 |
| **R3** | CL 上涨年（2010/2011/2016/2017/2019）v4* 不显著劣于不清仓 v4（清仓不踏空牛市） | 上涨年大面积转负 ⇒ A 退化为 v2 过度清仓 |
| **R4** | 八标的 P1 不低于 v4 的 3/8（OKLO/QQQ/GC 正域不被破坏） | 正域标的 P1 翻负 ⇒ 普适性证伪，沦为 CL 特化 |
| **R5** | root_entries 高层（recL3/ladder5）在 CL 上 > 0（root 重涌现激活，候选 B） | 仍为 0 ⇒ 重置机制未生效 |

**R4 是普适性的硬约束**：修复必须在不破坏 v4 现有正域（趋势域）的前提下
回收 CL——否则就是把"清仓频率 regime 函数"从涌现退化为标的白名单
（在册 `regime 函数系列` 第十余例的反面教材）。

## 边界条件（何种条件下本诊断翻转）

1. **3 次清仓的精确 bar 未知**：本诊断用年度 P&L 反推"清仓未落在崩盘前
   顶"（§1.2）。若引擎插桩重跑后发现 3 次清仓中有≥1 次确实落在崩盘前顶
   但被后续 negate/recover 抵消，则机制一的"频率压死"诊断需补充"清仓后
   立即重入"的二次失效。当前数据（三崩盘年 v4≈BH）排除了这种可能性，但
   插桩可证伪。

# §7 双重性重评估（2026-06-13 编排者洞察 + 五路核验 + 三路对抗）

## §7.1 编排者洞察（待核验命题，已核验）

> 信号层双重性，与会计双重性同构：
> - **会计层**：同一笔物理交易，父级别 = 降成本，子级别 = 独立头寸。
> - **信号层**：同一段（次级别走势），该级别 = 中枢构成单元（建筑材料），
>   次级别 = 走势内容的代表。
>
> BSP 检测正确形式：中枢用该层 segments 定义（中枢 = segments 重叠）；
> BSP 的"次级别走势"用下一层递归栈的 moves 输出判断；两者在不同递归层，
> **不能用一个代理另一个**——必须同时消费两层。

## §7.2 核验结论一：双重性正典正确（措辞需精化）

五课原文交叉确认（L0，权威链：博文 > 编纂版）：

| 论断 | 原文出处 |
|---|---|
| 中枢 = **三个连续次级别走势类型**的重叠（**不是** segments；只有最低不可分级别才退化为单位 K 线重叠） | 0010 §走势中枢 L5；blog/017 L38/L196/L294 |
| 背驰力度比较对象 = **次级别走势**（MACD 仅辅助）；顶背驰 = 离开中枢的次级别走势力度衰竭 | 0016 §背驰 L35/L68；blog/017 L248 |
| **同一段次级别走势双重身份**：在 a+B+c 中既是中枢 B 的震荡构成单元，又是 A/C 段背驰力度内容（**两身份同段共存**） | 0016 L19 + L35 |

**精化两处**：
1. 用户"中枢就是 segments 的重叠"→ 正典是"**次级别走势类型**的重叠"。
   引擎 `level.rs` "组件 = 下级 settled Move" **比用户措辞更贴正典**。严格
   关系：第 L 层走势类型 ≡ 第 L+1 层的"次级别走势"；只有最低级别 segment
   才直接 = 中枢构件。
2. 用户"不能混用"：0016 L19 显示同一次级别走势在**同层**身兼二职（中枢
   构成 + 背驰内容），非跨层。用户真正指的"两层"= **本级别中枢（由下级
   move 构成）vs BSP 确认用的次级别走势（下一递归层 move）**的相邻层关系
   ——这层关系经区间套 0027 确实成立。

**与会计双重性 534号严格同构**：同一对象在递归相邻层承担两个不可混的角色。
534号（会计层）已结晶为谱系；**信号层这条对偶尚未结晶**（见 §8）。
