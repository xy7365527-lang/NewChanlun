## 总判决

**IBKR maker 执行在"跑赢 BH / 跑赢 1min"的可行域内，且本报告把母报告的
核心缺口（fill rate ≥66% 未验证）部分闭合：对全部 5,120 个真实信号 fill，
队列末位成交下界（价格穿越挂单价 ≥1 tick）在挂单等候 30 秒时已达 66.6%、
60 秒时 74.4%——前沿被下界覆盖，不依赖队列位置、不需要 co-location。
绝对正收益层维持母判决：需 rebate ≤−0.2bps × fr≥92.2%，而 92.2% 连
队列首位上界（touch，60s 92.1%）都只是勉强触及——co-location + 做市商
计划必需且不充分。但绝对收益符号由 regime 决定（零摩擦天花板 −3.84%），
所以执行建议不是部署独立 1s 策略，而是把 1s maker 作为执行精化层。**

## 1. fill rate 的 OHLCV 可验证上下界（本报告核心增量）

母报告把 fill rate 当纯参数轴（L0-模型）。本报告用真实 1s 行情界定它：
对每个 fill（在 bar close 价 p 挂限价单），统计其后 W 秒内：

- **touch 率** = P(价格触及 p) —— 上界：触及即成交 = 队列首位（co-lo 领地）
- **cross 率** = P(价格穿越 p ≥1 tick) —— 下界：穿越则限价单必成交 = 队列末位
  （普通 API、零队列优先级的最差情形）

真实 fill rate ∈ [cross, touch]，区间内落点由队列位置决定。窗口按真实
时间计（1s bar 在静秒缺失）；capped 口径把窗口封顶到同一 trade 内下一个
fill（挂单不能跨越下一信号事件），是策略一致的口径：

| W(秒) | touch（上界） | cross（下界） | 下界 vs 前沿 |
|---:|---:|---:|---|
| 1（=母模型窗口） | 40.2% | 15.7% | 远低于 66% |
| 5 | 71.5% | 38.9% | 不足 |
| 10 | 81.2% | 49.4% | 不足 |
| **30** | 89.8% | **66.6%** | **≥ 跑赢 BH 前沿 65.8%** ✓ |
| **60** | 92.1% | **74.4%** | ≥ 跑赢 1min 前沿 ~66% ✓ |
| 300 | 94.6% | 84.4% | < 绝对正收益前沿 92.2% ✗ |

（n=5,120，全分母——窗口为零的 fill 计为未成交；fixed 口径数字略高，
见 JSON。分 kind 看，entry/exit/pair_open/pair_close 四类在 W=30-60s
的 touch/cross 无显著分化，±4pp 以内。）

三个直接推论：

1. **母模型的 1-bar 窗口严重低估可达 fill rate**。母模型未成交即下一 bar
   追价，对应 W=1s（touch 40%/cross 16%）；真实执行可以等 30-60 秒——
   信号间隔允许（capped 口径已扣除冲突窗口，66.6%/74.4% 是扣除后的数字）。
2. **相对 alpha 前沿被队列末位下界覆盖** ⇒ "fr≥66% 是否现实"的回答是：
   现实，且不依赖速度基础设施。价格穿越限价 ≥1 tick 时成交与队列位置
   无关，普通 IBKR API（百 ms 级延迟）足够——延迟只损失窗口最前沿
   ~0.1-0.5s，对 30-60s 窗口的穿越概率影响在 1pp 量级。
3. **绝对正收益前沿（92.2%）在上界之外**：cross 下界极限 84.4%（300s），
   touch 上界 60s 才 92.1%——即便队列首位（co-lo）也只是贴着前沿，且还
   需叠加 rebate ≤−0.2bps（CME 做市商计划）。母判决"必需且不充分"成立
   且被收紧：**不是基础设施问题，是该格点本身贴边**。

## 2. 等候窗口与未成交处置的配套（撤单 vs 追价）

挂单 30-60s 后若仍未成交，价格已不利漂移 30-60s，追价成本远高于母模型的
1-bar chase（均值 0.50bps）——所以等候窗口必须配撤单处置。母网格 best
（撤单）模式 IBKR 行（f_fill=0）：

| fr | 30% | 50% | 70% | 80% | 90% | 100% |
|---|---:|---:|---:|---:|---:|---:|
| best（撤单）复利% | −8.2 | −11.0 | −11.0 | −9.7 | −7.4 | −3.8 |
| worst（追价）复利% | −35.8 | −27.9 | −19.1 | −14.3 | −9.2 | −3.8 |

撤单模式下**所有 fill rate 都跑赢 BH（−20.9%）**——可行域对 fr 的敏感性
几乎消失（−3.8 ~ −11.0 的窄带），fill rate 风险被处置规则吸收。配套规则：

> **挂限价于信号价，等候 ≤60s（被下一信号事件截断则提前撤），未成交撤单
> 不追价。** 开仓侧错过即错过（与缠师"不患得患失"同构）；平仓侧是例外——
> 必须退出时只能追价，这部分对应 worst 模型，但平仓 fill 只占一半。

## 3. IBKR 实际费率结构（f_fill 落点）

| 项目 | 金额/侧（1 手 CL） | bps（CL≈$70 即名义 $70K） |
|---|---:|---:|
| IBKR 佣金 fixed | $0.85 | 0.012 |
| IBKR 佣金 tiered（≤1,000 手/月档） | $0.85 + 透传 | ≈同量级 |
| NYMEX 交易所费（非会员） | ~$1.45-1.50 | 0.021 |
| NFA/监管 | ~$0.02 | 0.000 |
| **合计 maker（限价成交，无点差成本）** | **≈$2.3-2.5** | **≈+0.033-0.036** |
| taker 额外过手 1 tick 点差（$10/tick） | +$10 | +1.42 |

- CME 期货无公开 maker-taker rebate；maker 与 taker 的费用差**全部来自
  点差**（1 tick = 1.42bps），不来自费率表。f_fill≈+0.035bps ≈ 网格的
  f=0 行。
- tiered vs fixed 在本量级（16.5 fills/天 ≈ 350 手/月）差异 <$0.1/侧，
  不改变格点归属。
- 中间价策略不存在：CL spread 通常 1 tick，tick 内无可挂价位（CME 不支持
  sub-tick），挂单策略只有"join best（被动）"与"cross（=taker）"两档——
  本报告全部分析即被动档。

## 5. 执行方案建议

**不建议把 1s CL 作为独立策略部署**——可行域内最好格点是"少亏"
（IBKR maker fr=74%: ≈−17%/年 worst、≈−11% best）或贴边微利
（MM rebate 格点 +1.9~5.3%，Sharpe 0.19），绝对收益符号由 regime 决定
（零摩擦天花板 −3.84%），执行层修不了信号层（杠杆轴母报告已判死亡）。

**建议形态：1s maker 作为执行精化层**，服务于任何更高床位（1min+）的
正 alpha 信号：

1. 信号触发后挂限价于触发价，等候 ≤60s，未成交撤单（开仓侧）/追价（平仓侧）；
2. 预期节省 ≈1.4bps/侧（taker 点差），按 cross 下界 74% 折算净省
   ≈1.0bps/侧——对 1min 床位 645 主笔/年 ≈ 13bps/年的纯执行增益，
   零信号层风险；
3. 普通 IBKR API 即可（百 ms 延迟不伤 30-60s 窗口），无 co-lo 投入；
4. 若未来要坐实区间内落点（66.6% 与 89.8% 之间的真实 fr）：
   databento MBP-10 单月 ≈$5.9 / 全年 ≈$103（母报告成本探针），队列重放
   可把落点从 L0 升 L2；IBKR paper trading 是零成本但低保真的替代。

## 6. 边界条件（结论何时翻转）

1. **成交条件性未建模（区间端点之内的第二缺口）**：touch/cross 界定的是
   成交概率，不是成交后的条件 pnl。被成交的单恰是价格走向不利的单
   （逆向选择），母模型按 fr 无条件抽样成交，对 maker 偏乐观——母报告
   §6.2 已声明，本报告的界不消除该偏差。若逆向选择把有效摩擦推高
   >0.58bps/侧（盈亏平衡），相对 alpha 前沿右移。
2. **单 regime**：2024-06→2025-05 下行年。touch/cross 率是波动率的函数，
   低波动年窗口内穿越概率下降，下界可能跌回前沿之下——前沿覆盖结论
   limited to 本 regime 的波动水平。
3. **挂单等候的机会成本**：60s 等候期间信号价已陈旧；capped 口径处理了
   与下一信号的冲突，但未建模"等候期间错过的更优重挂价"。
4. **延迟假设**：百 ms 级 API 延迟对 30s 窗口影响 ~1pp 的估算是线性外推
   （L0），未实测 IBKR 单程延迟分布。
5. by_kind 表（JSON）分母仅含非零窗口 fill，数字偏高 3-5pp，勿直接引用；
   主表为全分母口径。

## 六要素结果包

1. **结论**：fill rate 从纯参数轴（L0）升级为 OHLCV 界定区间（L2 端点）：
   挂单 30-60s 下真实 fr ∈ [66.6%, 89.8%]（30s）/ [74.4%, 92.1%]（60s）。
   相对 alpha 前沿（66%）被队列末位下界覆盖 ⇒ IBKR 普通 API maker 可达，
   co-location 非必需；绝对正收益前沿（92.2%+rebate）连队列首位上界都
   只是贴边 ⇒ co-lo 必需且不充分。执行建议：不部署独立 1s 策略，
   1s maker 作为高床位信号的执行精化层（净省 ≈1.0bps/侧），配套规则
   "挂单 ≤60s 未成交撤单不追价"。
2. **定义依据**：fill 集合 = V2oa25_ht 信号磁带在 1s 床位的全部 5,120 个
   交易侧（cl_1s_maker_fills.json，磁带指纹守卫在母报告 PASS）；
   touch/cross 判据 = 限价单成交的微结构必要/充分条件（穿越 ≥1 tick ⇒
   限价必成交；未触及 ⇒ 必不成交）；窗口按 timestamps_ns 真实时间。
3. **边界条件**：见 §6——逆向选择条件性未建模（对 maker 偏乐观）、
   单 regime 波动水平、延迟线性外推。
4. **下游推论**：① 母报告 §6.1 "若真实 fr<60% 连相对 alpha 也丢失"的
   担忧被排除（下界 66.6%>60%，在等候 ≥30s 的执行纪律下）；② 任何实盘
   执行模块的默认单型应为"限价 60s + 撤单"，不是市价单；③ MBP-10 采购
   （$103/年）的用途从"验证 fr≥66 是否可能"收窄为"定位区间内落点"——
   优先级下降，因为两个相对前沿已被下界覆盖；④ 执行精化层是 1s 数据的
   唯一生产用途（信号层维持"秒级=观测分辨率"）。
5. **谱系引用**：母判决 cl_1s_maker_execution_results.md（本报告闭合其
   §6.1 核心缺口的前沿覆盖部分）；CL 秒级 a0 回测判决（盈亏平衡
   0.58bps/侧不变）；卖飞修复 t1×bracket（touch 模式限价回测须过 next
   模式守卫——本报告 cross 下界即同款保守判据的 fill rate 版）；
