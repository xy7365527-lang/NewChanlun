# `moves_from_zhongshus` 聚合逻辑诊断 — 是否"太激进"？

**认识论等级**：静态代码分析 L0；缠论原文考据 L0（定义）；60d 单窗口实证 L2（QQQ 单标的单时段，可否证）；21.6 年跨多窗口实证 L2（含多段牛熊涨跌，否证鲁棒性强——21 年含 08 金融危机、20 疫情崩盘、22 熊市等多个反向大段）。

---

## 摘要（核心判定）

**聚合逻辑没有 bug，无需修改。** 用户的假设"聚合太激进（8 中枢被收敛成 2 走势）"在 60d 单边行情上看似成立，但被长历史数据**彻底证伪**：同一套 `moves_from_zhongshus` 在 **884893 根（21.6 年，2004-10~2026-05）** 上产出 **350 个走势**（不是 2 个），递归逐层涌现到 **L4**（L2 72中枢/L3 17中枢/L4 3中枢）。

数据量与涌现深度单调递进：**60d（4680根）→2走势→L1；2年（99816根）→33走势→L3；21.6年（884893根）→350走势→L4**。

"8 中枢→2 走势"不是聚合过度，而是 **60d 窗口（2026-03~05）恰好是一段单边上涨**的真实结构结果——它完全符合缠论第17课的趋势定义。

---

## §1 聚合逻辑做了什么（静态代码）

`src/newchan/a_move_v1.py::_greedy_group`：贪心扫描 settled 中枢序列，相邻中枢按以下判据归组：

| 判据 | 条件 | 含义 |
|------|------|------|
| `_is_ascending(c1,c2)` | `c2.zd > c1.zg` | 后枢固定区间下沿 **严格高于** 前枢上沿 = 区间递升不重叠 |
| `_is_descending(c1,c2)` | `c2.zg < c1.zd` | 后枢固定区间上沿 **严格低于** 前枢下沿 = 区间递降不重叠 |
| 二者皆否 | 区间重叠 | **截断点** → 开启新走势 |

合并规则：**连续 + 同向（同为递升或同为递降）+ 区间不重叠** 的中枢归入同一 `trend` 走势；方向翻转或区间重叠处截断。

> 用户的描述"方向相同的连续中枢自动合并成一个走势"——**准确**。但关键在于：这是否符合缠论？

---

## §2 缠论原文：这正是趋势的定义

**缠师原文（第17课，2006-12-18，`docs/chanlun/text/blog/017-第17课.md` L44-48）**：

> 缠中说禅趋势：在任何级别的任何走势中，某完成的走势类型**至少包含两个以上依次同向的**缠中说禅走势中枢，就称为该级别的缠中说禅趋势。该方向向上就称为上涨，向下就称为下跌。

逐条对照用户的质疑：

| 用户质疑 | 缠论原文判定 |
|---------|------------|
| "是不是方向相同的连续中枢自动合并成一个走势？" | **是，且这正是趋势定义**。趋势 = 至少两个以上**依次同向**中枢。 |
| "单边上涨所有中枢同向 → 永远只有 1 个走势？" | 在**纯单边段内**是的——单边上涨本身就是"一个上涨趋势走势类型"。 |
| "缠论说'两个中枢之间构成一段趋势'，不是'所有同向中枢合并成一个走势'" | **此处理解有偏差**。原文是"至少两个**以上**"，趋势可包含**任意多个**同向中枢。不是"每两个中枢一段"。 |

**结论**：`_greedy_group` 把连续同向递升中枢合并成一个趋势走势——**严格符合**缠论第17课的趋势定义。这不是 bug，是定义的忠实实现。

## §3 实证 1（60d）：单边行情 → 2 走势是真实结果

`qqq_5m_ohlcv_60d.json`，4680 根，2026-03-05 ~ 05-29：

```
L1 中枢总数: 8 (settled: 8) → L1 走势数: 2
Move[0] trend down 中枢[0..1] ×2   (一段下跌)
Move[1] trend up   中枢[2..7] ×6   (一段单边上涨，6 个递升中枢)

相邻 settled 中枢关系：递升 6 / 递降 1 / 重叠截断 0
方向翻转次数：1
```

8 个中枢里，0 处区间重叠，只有 1 次方向翻转（下跌转上涨）。即这 60 天的真实结构就是"一段下跌 + 一段单边强上涨"。6 个递升中枢合并成一个上涨趋势 = 缠论趋势定义的精确应用。

**L2=0 的根因**：递归构造要求 L2 中枢 = ≥3 个连续 L1 走势类型的重叠（第17课）；`RecursiveStack` 终止条件 `len(moves) < 3`。只有 2 个 L1 走势 → 无法 bootstrap L2。这是**单边行情缺乏足够异向走势**的结构性结果，不是聚合压缩。

## §4 实证 2（21.6 年）：决定性证据 — 聚合产出 350 走势、涌现 L4

`qqq_5m_av.json`（Alpha Vantage 付费版拼接 260 个月），**884893 根**，2004-10-01 ~ 2026-05-29：

```
L1: 63324 笔 / 6325 线段 / 1159 中枢 / 350 走势 / 815 买卖点
L2:                            72 中枢 / 70 走势 / 51 买卖点
L3:                            17 中枢 / 16 走势 / 14 买卖点
L4:                             3 中枢 /  1 走势 /  2 买卖点
→ 有效涌现深度 L4

settled 中枢 1158 个，相邻关系：递升 696 / 递降 459 / 重叠截断 2
350 个走势：上涨 194 / 下跌 156，up/down 充分交替；每走势含中枢数 min=2 / max=15 / 均值=3.3
```

**这彻底证伪"聚合太激进"**：
- 同一套聚合逻辑，在含多段牛熊反复的 21.6 年数据上产出 **350 个走势**（不是被收敛成 2 个）。
- 走势方向 up/down 充分交替（696 次递升、459 次递降），聚合在每次方向翻转处忠实截断；仅 2 处区间重叠截断（占比 <0.2%，说明中枢序列绝大多数是清晰的同向递进或反向跳变）。
- 350 个 L1 走势 ≫ 3 → L2（72中枢/70走势）→ L3（17中枢/16走势）→ L4（3中枢）逐层正常 bootstrap。

聚合的"合并"只发生在**真正同向递升/递降**的中枢之间；行情一旦反复，立即切分新走势。它既不过度合并，也不过度切分。中间点（2 年/99816 根→33 走势→L3）进一步确认涌现深度随数据反复次数单调递进。

## §5 与 TradingView 851 labels 的口径辨析

用户提到"TV 在同样数据出 851 labels"作为聚合有问题的反证。这是**口径不可比**：

- TV 缠论指标的 labels 包含**笔端点、分型、线段端点、中枢边界、各类买卖点**等多种标注的叠加，且通常**多个固定周期级别同时绘制**（5min/30min/日线分层叠加）。
- 引擎的"走势数"是**单一递归树**中某一级别的走势类型计数，语义完全不同。
- 对照基准应是引擎 L1 的结构总量：21.6 年全样本 63324 笔 + 6325 线段 + 1159 中枢 + 815 买卖点 = 7万+ 结构标注，远超 TV label 数。**350 走势 ≠ 350 labels**——走势是比笔/线段高几个层级的聚合单元。若取可比量，引擎 L1 买卖点（全样本 815）与 TV 买卖点类 label 数量级相当；TV 851 是某窗口内所有类型标注叠加，不是走势计数。

TV 的 851 不证明聚合有问题，只说明"走势"与"label"不是同一种对象。

## §6 是否存在真正可改进的点？（诚实声明）

聚合无 bug，但有一个**定义层面的观察**（非 bug，记录待结算）：

缠论第17课强调**走势分解的多义性**（同一段走势可有多种合法分解，通过级别相对性隐含）。`_greedy_group` 采用**唯一的贪心最大合并**——在同向段内总是合并到最长。这是一种**确定性选择**，丢失了多义性。

- 这**不是 bug**：产出严格符合趋势定义，且确定性对工程可复现性有利。
- 若未来需要"走势的多义分解"（如同时输出最细/最粗两种分解供不同级别消费），这是一个扩展点，**需走概念结算流程**（改变走势分解的定义边界），不能擅自 workaround（no-workaround 规则）。

**因此本次不修改任何代码**——按 no-patch-mentality「代码能做什么就声明什么」：聚合当前的能力（确定性最大合并、忠实趋势定义）是正确的，不存在需要修复的缺陷。

## §N 结论（六要素）

**1. 结论**：`moves_from_zhongshus` 聚合逻辑**没有 bug，无需修改**。"8 中枢→2 走势"是 60d 单边行情的真实结构结果，符合缠论第17课趋势定义；21.6 年数据（884893 根）上同一逻辑产出 **350 走势、逐层涌现 L4**（L2/L3/L4 = 72/17/3 中枢），证伪"聚合太激进"假设。L2=0（60d）的根因是**数据窗口的行情结构（单边、缺反复）**，不是聚合压缩。

**2. 定义依据**：缠论第17课"趋势 = 至少两个以上依次同向走势中枢"（`docs/chanlun/text/blog/017-第17课.md` L44-48）；`_greedy_group` 的递升/递降判据（`c2.zd>c1.zg` / `c2.zg<c1.zd`）= 缠论"依次同向、区间不重叠"；递归门槛"本级别中枢 = ≥3 连续次级别走势重叠"（第17课）。实证输入：60d（递升6/递降1/重叠0/翻转1/2走势）、2年（33走势/L3）、21.6年（递升696/递降459/重叠2/350走势/L4）。

**3. 边界条件（结论翻转条件）**：
- 若 batch（段中枢 `zhongshu_from_segments`）与流式（`ZhongshuEngine`）在长历史数据上出现分歧 → 需复核（60d 已交叉验证一致，recursive_5min_qqq.md §2）；
- 若放宽 `stroke_mode`/`min_strict_sep` 使笔/线段更细 → 中枢数变化 → 走势分组随之改变（但这是改变结构定义，非聚合问题）；
- 若缠论"走势分解多义性"被正式形式化为需求 → 当前的唯一贪心分解将被认定为"不完备"（届时走结算流程，非 bug 修复）。

**4. 下游推论**：递归级别涌现深度由**走势类型数量**决定，走势数量由**行情反复次数**决定，与 bar 数解耦（bar 数必要非充分）。这修正了 `recursive_5min_qqq.md` 的初步推测"bar 数量级决定级别"——21.6 年 vs 60d 的 189× bar 数差异背后，真正驱动 L1→L4 的是行情含 459+ 次下跌方向翻转（21 年跨越 08 危机、20 崩盘、22 熊市等多个反向大段）。对"用更细周期/更多 5min 数据涌现主级别"的工程设想：**单纯增加 bar 数无效，必须跨越含足够趋势-盘整-反趋势交替的时段**。

**5. 谱系引用**：107号（段中枢已结算，递归用段中枢）；002号 + 第25/31课（看级别不看编号）；第17课（趋势定义 + 走势分解定理 + 本级别中枢=≥3次级别走势重叠）。**不确定是否有"走势分组粒度↔走势分解多义性"的既有谱系**——若 `moves_from_zhongshus` 的"唯一贪心分解 vs 缠论多义分解"此前未被记录为概念分离，§6 的观察可作为**待结算候选**（但本次不触发结算，因当前产出无矛盾、符合定义）。

**6. 影响声明**：纯诊断分析，**未修改任何 src/ 生产模块**（聚合逻辑确认正确，无需改）。新增/复用：数据缓存 `qqq_5m_av.json`（AV 884893 根 / 260 月）；诊断脚本 `scripts/diagnose_moves_aggregation.py`；本报告 `analysis/moves_aggregation_diagnosis.md`。配套实证见 `analysis/av_recursive_5min_qqq.md`。
