## 1. 缠论原文依据（一级权威博文，逐字引用）

### 1.1 级别的意义 = 买卖量（26课:34）

> "所以，对于本ID来说，任何的卖点都是卖点，任何的买点都是买点，本ID唯一需要
> 控制的只是买卖的量而已。级别的意义，其实只有一个，基本只和买卖量有关，
> 日线级别的买卖量当然比1分钟级别的要多多了……即使对于本ID这样的资金量来说，
> 1分钟的卖点本ID也会参与，只是可能就只卖5万股，跌回来1分钟买点买回来。"

→ **约束 C1**：卖点必须响应（不允许"忽略 sell1"），但响应的量由级别决定。
小级别卖点只动小级别的量。

### 1.2 级别错配禁令（44课:48）

> "你不可能按30分钟操作，而一见到1分钟顶背驰就全部扔掉，这就变成按1分钟级别
> 操作了。"

→ **约束 C2**：级别 k 的卖点无权清空级别 j>k 的仓位。当前单体 master 正在
违反此条。

### 1.3 分层出仓的正面授权（44课:50）

> "对于有一定量的资金来说，即使按30分钟操作，当见到1分钟的顶背驰时，也可以把
> 部分筹码出掉，然后根据后面的回调走势情况决定回补还是继续出，**这样的操作，
> 对一定量的资金是唯一可行的**，因为这种资金，不可能在任何一定级别的卖点都
> 全仓卖掉。"

→ **约束 C3**：多级别分层出仓不是工程发明，是原文宣告的"唯一可行"形态。

### 1.4 每层独立的持股/持币循环（45课:14-18）

> "假设你是按30分钟级别操作的……一个30分钟的买点买入后，就进入一个持股的
> 操作中……当这个30分钟的卖点出现时，卖出，然后就进入持币的操作里，直到一个
> 30分钟的买点出现。"

→ **约束 C4**：每一层都是完整的 45 课二元 FSM（持股↔持币由**该级别**买卖点
切换），层与层时钟互不同步。

### 1.5 每重对应资金与筹码（40课:20-22，经 deep_think 转引）

> "每一重都对应着一定的资金与筹码……每一层次的操作都是独立又在一个整体的
> 操作中。"

→ **约束 C5**：配额按级别切分（slice 模型），各层独立操作，整体只是总账。

### 1.6 量的尺度 = 该级别历史震荡幅度（38课，经 deep_think §5.4 转引）

> "选择一组历史上某级别平均震荡幅度最大的股票。"

→ **约束 C6**：级别的"量"有一个原文给出的可测尺度——**该级别的历史平均
震荡幅度**。这是配额涌现的结构基数（不是人为预设百分比）。

## 2. 架构

### 2.1 总图

```
SignalTape（级别隔离事件流，已有）
      │
CenterBook + DepthRef（市场性质：各层中枢边界 + 因果滚动典型振幅，已有）
      │
positional layers：每个 BSP 承载层 k ∈ [floor, MAX_LADDER) 一个独立层
  layer@k = 45课二元 FSM（FLAT → ARMED → [PENDING] → LONG → FLAT）
    入场：buy1@k 布防 + 次级别区间套确认（与在册 master 逐字同构，每层独立）
    出场：sell1@k 清**本层**全部股数（只动本层配额——44课）
    配额：w_k = θ_k / Σ_j θ_j（θ = DepthRef 因果滚动 P50 中枢相对振幅）
      │
总账：单一现金池 pool。NAV = pool + Σ_k shares_k × close。
  层入场金额 = min(w_k × NAV, pool)；出场回笼进 pool。层内股数守恒。
```

### 2.2 与单体 master 的关系

不是替换参数，是把"一个 FSM 拿全仓"换成"N 个 FSM 各拿涌现配额"。
段级层在 top20 踏空 gap 中照样出场（无妨，它只持有段级配额）；
recL2+ 层只响应 recL2+ 的 sell1（10 年 15 次量级）——高层配额接近 BH，
这是特性不是 bug（在册 §6.1 预言）。熊市中各级别卖点依次触发、仓位
逐级递减——避跌能力按层保留。

### 3.1 为什么配额不是预设百分比（任务关键约束的满足方式）

"60/30/10"式预设违反两条：(a) 级别是涌现的——预设比例假定层集合先验已知；
(b) 比例数值无原文出处。本设计中：

- **层集合**从事件流涌现（D1）：BTC 早期只有 segment 层活动，递归塔生长后
  recL2/recL3 层自动获得事件；
- **配额数值**从结构涌现（D2）：θ_k 是该级别中枢振幅的因果滚动统计——
  级别越高振幅越大 ⇒ 配额自动随级别递增，精确实现 26 课"大级别大量"，
  且比值由**这只标的自己的结构**决定，不同标的不同时期各不相同；
- **资金迁移**从结构涌现：新级别涌现 → θ 集合扩张 → 低层配额占比自动下降
  → 低层下次出场回笼的资金被高层入场吸走。资本随递归塔生长向上迁移，
  无人指挥。

## 4. 与既有失败序列的区别声明（先验诚实）

迄今所有多声部实验 ≤ 单声部（deep_think §5.2 清单）。本设计与它们的范畴差：

1. 既往声部 = **master 持仓窗口内的短差切片**（修持仓期 alpha，已被 scco 修好）；
   本设计的层 = **独立的仓位本体**（修空仓期踏空——voice 结构性不可达的时空）。
2. 既往声部判据 = master 信号的衍生/代理；本设计每层判据 = 该层自己的
   buy1/sell1（45课完整二元循环）。
3. 既往失败的 bar 级 churn 病灶在低级别伪事件；本设计 floor=2（segment 起），
   且层数由 BSP 事件流天然有界（BTC 实际 ~4-5 层）。

最大未兑现承诺原样继承（deep_think 待决项5）：N 层总收益 > 单体最优在本仓库
**零 L2 证据**——本实验就是第一个检验。

三条全过 = 假设确认；P1∧P2 过而 P3 不过 = 机制正确但配额结构待调

的在册单调性不能通过仓位分层实现，需回到出场门范畴修复（解法假设 2）。

## 7. 回测结果（L2，已回填）

见 `analysis/positional_fugue_btc_results.md`。判决摘要：

**仓位极性是回测揭示的隐藏主轴**。设计 §3 默认 D4/D5 是"每层独立 45课循环"
（从持币开始、buy1 入场）——回测命名为 **cycle45**，BTC +152%，**低于**单体

所有 slice 默认持有满仓，confirmed 卖点@k 削减本层、confirmed 买点@k 回复
（26课:34"仓位一直不变……卖点减少买点回复，但绝对不加仓"逐字）——BTC
**+1247%**，超 scco（+630%）近 2 倍，逼近 BH（+1380%）。

## 8. 嵌套递归 vs 并列配额——编排者两条约束的回应与会计辨析（2026-06-12）

编排者补充两条关键约束（这是对 hold26 的修正方向）：

> 约束 A（嵌套非并列）："不是 60/30/10 的并列配额——是嵌套递归。高级别持仓
> **内部**，次级别在做短差；次级别持仓内部，次次级别又在做短差。高级别看
> 次级别的操作 = 短差降成本。每一层对上一层来说都只是'短差降成本'。"
>
> 约束 B（操作对象）："操作对象不是反向笔，是**趋势级别的反向线段**。笔是 a0
> 不参与递归操作，递归到线段级别为止。"

**约束 B 全盘采纳**（已是在册定论）：本设计 floor=segment（FIRST_BSP_LADDER=2），
笔（ladder 1）= a0 构成性例外，不作操作床位（77/78课线段是最低走势类型部件；
谱系 [[project_recursive_fugue_depth1]] bi 级关闭、[[counter-segment-voice-stack]]
笔级不可开三方收敛）。本文档全部操作对象表述统一为"该级别 buy1/sell1 事件"
（= 趋势级别反向线段的力度终结判据，38课"内部结构的背驰或盘整背驰结束点"），
无"反向笔"表述。

**约束 A 触及一个被本 session 数据否定的概念分叉，必须严格辨析，不能机械采纳。**

### 8.1 并行 NRF 工作流的实现与 BTC 否证

今天（2026-06-12 04:03-04:08）一个并行工作流已把约束 A 的"嵌套递归短差"
完整形式化（`nested_recursive_fugue_design.md`，§0 逐字引用编排者原话）并实现
（config.rs NRF1/NRF2/NRF2q + level_operating_unit.rs CounterSeg 子腿 +
nested_recursive_fugue_backtest.py）。BTC + OKLO 双标的回测已落盘
（`data_cache/nested_recursive_fugue_backtest.json`）。结果（Δ vs BH）：

| 方案 | 机制 | OKLO Δ | BTC Δ |
|------|------|--------|-------|
| V2oa25_ht/emht（单体 master 基线） | 单 FSM 全仓 | +1492/+1462 | −750/−743 |
| NRF1 | emht + entry_voice 短差 | +948 | **−1153** |
| NRF2 | NRF1 + CounterSeg 反向线段子腿 | +1058 | **−1165** |
| NRF2q | NRF2 + 振幅配额 | +1994 | −1485 |
| **本 session hold26**（per-level 独立槽） | N 个独立 26课恒仓 slice | — | **−133**（+1247%）|

**嵌套递归短差（NRF1/NRF2）在 BTC 上全部比单体 master 更差**（−1153 < −750），
而被编排者归为"错"的并列配额（hold26）几乎追上 BH（−133）。这是一个真实的
概念矛盾，必须解释而非掩盖。

### 8.2 根因：NRF 实现了 §2.3 子腿但漏掉了 §3 per-level 槽

读 config.rs：`NRF1 = entry_voice + V2oa25_emht`、`NRF2 = NRF1 + rev_sub_depth=2
+ CounterSeg`。**两者都建立在 V2oa25_emht 单体 master 基座上**——master 仍是
单 FSM 全仓，段级 sell1 仍清全仓（emht 拦截时才由 voice 短差化）。NRF 设计
文档自己的 §3 写明"master 从单一全仓 FSM 改为 per-level positional 槽集合"，
**但实现没做这一步**——NRF 实现了 §2.3（嵌套子腿）却漏掉了 §3（per-level 槽）。

hold26 正是 §3 的实现：N 个独立 positional 槽，段级 sell1 只清段级槽，
recL3 配额 0.63 持有穿越牛市主干（+733K）。**§3 才是 BTC 解，§2.3 是有害叠加。**

### 8.3 会计辨析：约束 A 的"短差降成本"语义被数据否定

NRF 设计 §0 声称"每一层既是 positional 又是短差……一个递归塔的两个视角"。
