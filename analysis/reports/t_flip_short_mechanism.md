## 1. 核心发现：途径 b（sink 次级别短差）在翻转版里完全消失

| 途径 | 出生标签 | BTC 笔数 | BTC pnl | CL 笔数 | CL pnl |
|------|---------|---------:|--------:|--------:|-------:|
| **a 核心翻空（全仓）** | `flip` | 2536 | **−909,020** | 2826 | **+115,877** |
| **b 次级别短差（1/3 仓）** | `sink` | **0** | 0 | **0** | 0 |
| 入场建空（核心） | `entry` | 0 | 0 | 1 | +978 |

**用户预期"翻转版 = 核心翻空 + sink 短差"是错的**：翻转版不是在 sink 短差之上**叠加**翻空，而是把
短差**替换**为纯核心翻空。sink 途径 0 笔。

**根因（结构性，非数据偶然）**：`drive()` 中翻转检查 `(core..MAX_LADDER).any(反向BSP)` 在前且 `return`。
所有 BSP 都涌现在 ladder 3（= `LADDER_MOVE` 走势级 = core 层），同级别反向 BSP 抢先触发翻转返回，
**永远到不了 sink 分支**。最亏/最赚笔全部 `L3` 印证 core 恒在 ladder 3。

⟹ 翻转版的空头盈亏 = 翻空（flip）盈亏的全部；"翻转版短差亏多少"无意义（0 笔）。

## 4. 引擎改动（严格标注，非启发式）

- `FugueResult` 加 `trade_origins: Vec<&'static str>`（与 trades 平行；其他引擎空 vec）。
- `TPositionEngine` 加 `origin: [LegOrigin; MAX_LADDER]`（Entry/Flip/Sink），建仓点写入、平仓点 push。
- `finish()` 加对齐断言 `trade_origins.len() == trades.len()`（violation=panic=验收）。
- `dump_trades_json` 加第 12 字段。19 单测 + 481 lib 测试全绿。

途径区分用引擎打标的 origin，**非** shares/ladder 启发式——因翻转版 core_ladder 虽恒在 3，但严格
归因要求显式标注（exit_reason 不能区分途径：flip 既平翻空核心又级联平子腿）。
