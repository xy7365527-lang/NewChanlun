# 秒级K线（ohlcv-1s）可行性调研 + 试水拉取报告

日期：2026-06-11　|　认识论等级：**L3**（CL + BRN 双标的真实数据各1年 + CL 1个月双时段；编排者确认套餐内拉取免费）

## 结论

**可行，已拉取 CL 1年秒级数据（5.96M bars，$0）。** 但增益形式与任务背景设想不同：

- **预注册字面判据失败**：秒级数据上平均 **1.01 笔/分钟**（阈值 3）——"1分钟的一根K线在秒级展开成完整的笔/线段/中枢结构"这一设想被否证（结构性原因，见 §4）。
- **递归空间增益的正确形式成立**：同源同时段对照（1s vs 聚合1m），笔膨胀 16.2×、线段膨胀 14.7×、递归塔 **+1~2 层**（1个月：lid3 vs lid2；1年达 lid4）。递归赋格的展开单位是**腿**而非单根K线——1min 笔平均跨 ~16 分钟，该窗口在秒级有 ~16 笔，线段级中枢可以形成。

## 3. 引擎可行性实测

| 负载 | 耗时 | 吞吐 |
|---|---|---|
| 577K bars 纯流式（RecursiveOrchestrator.process_bar） | 0.2s | 3.5M bar/s |
| 5.96M bars 纯流式 + 递归7层 | 4.2s | 1.4M bar/s |

- 任务引用的 ~78K bar/s 是**带每bar信号层读取的回测吞吐**；纯结构流式快 ~20×。按 78K bar/s 估算带信号回测：1年秒级 ≈ 76s，全历史 ~110M ≈ 24 分钟。**量级无障碍。**
- 内存：1年（309MB JSON → Python list ~1.5GB 含对象开销 + Rust 紧凑结构）无压力。全历史 ~110M bar 的 Python list 侧约 15-20GB 会紧张——届时需 numpy 数组或分块喂入（接口层改造，引擎本身无碍）。
- 数据质量：两次拉取 dropped nan = 0，价格范围 sane（55.12~84.52），无 BRN 式坏 bar（OHLC=0.08 前科）。

## 4. 结构密度判决（核心）

同源对照（同一个月数据，1s 原始 vs 聚合 1m）：

| 指标 | 1s a0 | 1m a0（同源聚合） | 膨胀 |
|---|---|---|---|
| bars | 577,388 | 28,679 | 20.1× |
| 笔 | 29,068 | 1,797 | 16.2× |
| 线段 | 2,819 | 192 | 14.7× |
| L1 moves | 172 | 11 | 15.6× |
| 递归涌现 | lid2: 38zs/14mv，**lid3: 3zs/1mv** | lid2: 2zs/1mv | **+1层** |

CL 1年（5.96M bars）：277,794 笔 / 27,243 线段 / 1,579 L1 moves / lid2: 386zs / lid3: 33zs / **lid4: 2zs/1mv**。

BRN 1年（5.30M bars，2024-06~2025-06）：258,387 笔 / 25,265 线段 / 1,394 L1 moves / lid2: 336zs / lid3: 28zs / **lid4: 2zs/1mv**——与 CL 同构，递归塔增益跨标的复现（L3）。BRN 平均 16.3 成交秒/分钟、0.79 笔/分钟（字面判据同样失败，跨标的复现）。

### BRN 数据质量专项

BRN 原始 6,118,547 行中 **823,450 行（13.5%）OHLC 全空但 volume>0**（CL 无此现象）。单日样本刻画：空行与正常行同一 instrument_id，全部 volume>0——这是 ICE 的**非定价成交**（EFP/基差/大宗等不参与价格形成的成交类型），Databento 以 UNDEF_PRICE 输出、`pretty_px` 渲染为空字符串。只有量没有价，**丢弃是唯一正确处理**（不是数据缺陷）。坏 bar 守卫（low<5 或 high>500，BRN 1min OHLC=0.08 前科同款）触发 0 次；清洗后价格范围 58.40~87.95 正常。

**两种增益形式的区分**：

1. **"单根1min K线内展开"（任务背景设想）→ 否证**。平均 1.01 笔/分钟。结构性原因：成交稀疏（20 成交秒/分钟）+ K线包含合并进一步压缩序列，而严格笔定义需要 ≥5 根合并后K线。即使 RTH 峰值时段也达不到 3 笔/分钟。这不是数据源能修的——换 tick 自聚合也改变不了成交稀疏本身。
2. **"递归塔整体下移一层"（递归赋格的真实需求）→ 成立**。原 1min 塔的最底层（笔，时间尺度 ~16 分钟）在秒级塔中对应线段~L1 move 层，其下有真实笔中枢（1年 386 个 lid2 中枢）。原"笔级别无真中枢、递归到线段级就停"的限制被解除：同一物理时间尺度的宿主腿，在秒级 a0 下其次级别有完整中枢结构。

## 六要素结果包

1. **结论**：秒级数据可行（源✓/费用$0✓/引擎✓/递归+1~2层✓）；但"单根1min K线内展开完整结构"否证（1.01笔/分钟<3）。
2. **定义依据**：笔=严格新笔定义（≥5根合并K线+分型，《忽闻台风可休市》）；递归层=RecursiveOrchestrator 七层塔（项目级别涌现口径）；膨胀对照=同源数据消除时段混杂。
3. **边界条件**：① 结论基于 CL/BRN（高流动性油链期货）——低流动性品种成交秒更稀疏（BRN 16.3 vs CL 20.1 成交秒/分钟已现梯度），膨胀系数更低，递归增益可能消失；② get_cost=$0 已由编排者确认为套餐属性，账户/计划变更后费用结论失效；④ 若递归赋格的设计强依赖"父腿的每根K线内有子结构"（而非"父腿时间窗内有子结构"），则增益形式2不适用，秒级无用；⑤ 1.01笔/分钟是全时段平均，若只在 RTH 高峰操作，局部密度约为平均的2倍仍 <3。
4. **下游推论**：递归赋格 depth=entry−3 的钉死（O_sub0 否证：bi级无中枢）在秒级 a0 下解除——原 bi 层变为有中枢的层，递归空间+1。但 O_sub0 的否证逻辑（父腿前提否定子腿前提的语法性矛盾）与级别无关，秒级重验仍可能复现同构否证——多一层空间 ≠ 多一层正 alpha。
5. **谱系引用**：递归深度1判决（O_sub0 两票收敛，memory: project_recursive_fugue_depth1）；1min分辨率不可约（project_1min_resolution_irreducible——该结论针对 Γ→Δ 可定性，与本调研的递归空间问题不同轴，不冲突）；θ绝对阈值三次失配（秒级振幅更小，θ相对化在秒级更必要）。
6. **影响声明**：新增 3 个数据文件 + 3 个脚本（_db_sec_probe/_db_sec_pull/_db_sec_density.py）+ 本报告；未改动任何引擎/回测代码；未改动任何定义。
