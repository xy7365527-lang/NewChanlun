# 线段瓶颈诊断结果（QQQ 日线 1000 根）

> 认识论等级：**L2**（真实 QQQ 日线，逐根 streaming，结论可否证）
> 诊断脚本：`scripts/diag_segment.py`（可复现）

## 结论（与原始假设相反）

**线段检测不是瓶颈，线段算法没有 bug。** 原始问题陈述的三个前提经实证全部不成立：

| 原始前提 | 实证结果 | 判定 |
|---------|---------|------|
| "72 笔 → 6 线段，压缩比太高" | 线段 #3 特征序列高/低点**双单调递增**，按 67/71 课就是一段 | 缠论正确 |
| "TV 在类似数据上有几百条线段" | TV 这份导出覆盖 QQQ **全历史**（$19→$637），近窗（>$250）只有 **16 笔 / ≤3 线段** | 基准错配 |
| "线段太少导致买卖点为 0" | 买卖点 0 的真因是**只算线段中枢，缺笔中枢**，与线段数正交 | 误诊 |

**真瓶颈**：系统只在**线段中枢**级别计算买卖点（`zhongshu_from_segments`），
全代码库**无任何笔中枢路径**（`grep 笔中枢/bi_zhongshu/stroke_zhongshu` 零命中）。
同一份 72 笔，线段中枢 = 1，**笔中枢 = 12**（真实算法）/ 23（贪心估算）。
TV 的 137 买卖点正是**笔级别**信号（CZSC 默认出笔买卖点）。

## 定义依据

### 1. 线段 #3（笔 25..49，342→540，+58%）是单段，符合 67/71 课

特征序列（向上段 = 向下笔序列）经包含处理后的元素（`diag_segment.py` 白盒 trace）：

```
高点序列: 412.9 → 429.9 → 439.1 → 503.5 → 515.6 → 539.2   (单调↑)
低点序列: 395.3 → 416.8 → 421.6 → 483.8 → 494.5 → 510.1   (单调↑)
```

- **第67课**：线段被破坏 ⟺ 特征序列出现「顶分型」（向上段）。顶分型要求中间元素高/低点同为三者最高。
- 高点单调递增 ⟹ 任意中间元素的高点都低于右邻 ⟹ **不可能出现顶分型**。
- 第一个顶分型出现在笔50（539.2），由笔52（493.6）跌破触发 → 在此正确断段（`s1=49`）。
- 笔32/34/36 的「右包含」合并（取大-大，`a_segment_v1.py:298-307`）符合第67课"上升线段特征序列按向上处理"。

### 2. 线段数对比是反向的

- TV 近窗（price>250）笔 = **16**；引擎笔 = **72** → 引擎产笔比 TV **多 4.5×**。
- 16 笔 → TV 近窗线段 ≤3；引擎线段 = 6 → **引擎线段比 TV 多，不是少**。
- TV 这份 JSON 的 `bar1/bar2` 是指标内部 pivot 索引（1..440），与图表 bar 不对齐；
  价格跨 $19→$637 证明覆盖全历史。大跨度线段在此导出里也只有 6 条（color 4293422810，span 56-205）。

### 3. 中枢级别错配是买卖点 = 0 的充要原因

`recursive.py:99-104`：链路 `BiEngine→SegmentEngine→ZhongshuEngine→MoveEngine→BuySellPointEngine(level_id=1)`，
其中 `ZhongshuEngine.process_segment_snapshot` 只调 `zhongshu_from_segments(seg_snap.segments)`。

- 6 线段按三连重叠：仅 seg1-3 重叠 [342,388] → **线段中枢 = 1** → 买卖点 0。
- 同一 72 笔喂真实中枢算法（笔包装为 segment）→ **笔中枢 = 12**。
- 12 笔中枢 → 一/二/三类买卖点可达数十个，与 TV 137 同量级。

## 边界条件（结论翻转的条件）

1. 若 TV 基准改为**同一 1000 根近窗**（而非全历史导出），且 TV 在该窗仍显著多于 6 线段 →
   则需重新审视线段算法（当前数据下此条件不成立）。
2. 若数据窗口换成**震荡市**（非 2023-2025 单边牛市）→ 线段会自然增多，压缩比下降，
   "12:1" 本就是强趋势数据的特征，不是普适常数。
3. 若线段算法的「向上合并取大-大」被证明违反原文（需回溯 67/71 课博文核验包含方向）→
   翻转。当前 trace 显示合并后高低点双单调，无论合并方向都不产生中间分型，故此条非关键。

## 给编排者的决断点（选择类，四分法分类）

引擎 `0 买卖点` vs TV `137` 的差距，根因是**级别口径**，有两条互斥路径：

**路径 A：下移基准级别到笔中枢**
新增 `zhongshu_from_strokes` + 笔买卖点引擎，本级别 = 笔中枢（12 个），线段中枢升为 level 2。
对齐 TV CZSC 默认口径（笔买卖点）。代价：递归塔整体下移，需重核各级别语义。

**路径 B：保持线段中枢为本级别，换数据窗口验证**
当前 6 线段/1 中枢对强趋势牛市是缠论正确的。若目标是验证算法而非操盘信号，
应换震荡市标的/时段（L3 交叉验证），而非在牛市窗口追求多买卖点。

二者改变的是「本级别」的定义，属 level 口径决断 → 需编排者价值判断，蜂群不静默选择。
