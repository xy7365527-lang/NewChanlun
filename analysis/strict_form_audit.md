## 结构性发现

**1. 失败模式的统一形状**：被否证的外加判据（SC 六位、R1、R3、SubAny、循环结构、Climb）全部是**在 confirmed 事件之上再加一层等待/过滤**——纯延迟或反选。存活的判据（θ 成本门、41课门）是**成本/持仓判据而非择时判据**。这印证核心原则：买卖点定义自身携带 regime 信息，外加择时层只能破坏它。

**2. D3 方向行近似是系统性的**：2b/3c/4e 三处的"段"都用 D3 方向行 run 近似同级别分解段。Sequence38 判决已确认：分型/方向行近似在子腿被否证，事件流（div/BSP）严格形式为正。HoldTrend 的衰竭判据（TrendExhaustion）目前是 D3 近似——它的严格形式应是**事件流形式**（相邻 Up 段创新高用段端点价格、盘背用 div 事件已经是事件流 ✓，但段切分本身用方向行 ✗）。

**3. candidate 事件无原文地位**：原文操作点都是结构**完成**的确认点（三买=回抽完成不回中枢；背驰=段完成的力度比较）。唯一的"提前"是 38课答疑:258 的区间套提前——那是用次级别结构把确认点定位得更早，不是用未完成结构预判。T6（candidate Buy3）属于后者，无原文地位。

## §5 降成本/挣股数实现状态（2026-06-11 编排者追加审计）

### 5.1 机制实现审计（ledger.rs，三视角对抗验证确认）

降成本→挣股数的完整机制链**已实现且算术无截断**（Workflow 三 lens 对抗验证，
C1 双 lens confirmed）：

1. **降成本相**（`LedgerPhase::CostReduction`）：ShareConserving 腿闭合
   `profit=(sell−buy)×shares` 落袋 `cumulative_recovered` →
   `cost_basis -= profit/total_shares`（[ledger.rs:295](../rust/src/trading/ledger.rs)）。
   **对称无截断**：亏损腿使成本回升，无 `max(0,·)` 钳制——"降成本提款机 bug"
   先例的截断模式在本账本不存在。
2. **单向相变**：`cost_basis ≤ 0` → `EarningShares`（ledger.rs:297-299）。逆向
   路径在类型层面不存在（`EarningShares` 变体无 cost_basis 字段）。
3. **挣股数相**（`AmountConserving`）：开腿即时 `total_shares -= shares`（卖出
   离仓），闭腿 `total_shares += shares×sell/buy`——同金额买回，buy<sell 时
   股数净增（挣股数），buy>sell 时净减（**挣股数也可能亏股数**，对称建模 ✓）。

### 5.4 空头侧挣股数语义判决（编排者问题3）

**当前系统无净空头持仓**：`MarketMode` 仅 `Stock` 变体（futures INV-3 显式
声明不包含）；runner 状态机仅 FLAT/ARMED/LONG 无 SHORT 态；唯一入场构造是
买入。`DiffSide::Short` 腿是**多头持仓内**的先卖后买减仓短差，非净空头。
"空头挣负股数"在当前系统**无定义域**——非实现缺陷，是系统不做净空头。

**更强的否定性结果**（Workflow lens B，L0 纯代数）：编排者设想的"cost_basis
降到 0 后空头仓位（负股数）递增"在守恒律算术下**不可构造**——
- 多头挣股数相变（cb≤0）寄生于价格域的内在下界 0；空头侧价格**无上界**
  ⇒ 严格对偶没有正则的相变触发；
- 空头 = 股数债 D + 现金堆 C。盈利的现金守恒空头循环（低买还债、高再卖）
  **必然缩债**（ΔD = −h(1−b/s) < 0）；敞口递增的循环必然是亏损循环（高补低卖）；
- 对偶的"挣"= **债清偿加速**，其吸收态是 D=0（头寸自我了结）——是终止相，
  不是增长相。

故空头的严格对偶不是"挣负股数"而是"债清零提前"。若 F1 期货实装净空头：
`assert side==Short`（ledger.rs AmountConserving 臂）须升级为守恒律×头寸符号
穷举 match，`ConservationLaw` 需现金守恒变体、`LedgerPhase` 需
`DebtReduction{debt_shares}` 相——现有"第三种守恒律不可静默引入"的穷举设计
正是该扩展的预期接口。

**DiffSide::Long 子腿**（先买后卖）：CostReduction 下与 Short 共用守恒算术 ✓；
EarningShares 下被 `open_sub` 显式拒绝。对抗验证细化：Long 腿金额守恒在
**盈利分支与多头挣股数严格同构**（净增股公式逐字相同），但全局非同构——
资金源外部（需现金字段）vs 自筹、亏损分支是偏函数（需 total_shares≥V/s 守卫）、
且有清算重复计入耦合（cumulative_recovered 作资金源会被 total_value 公式
双计）。当前拒绝是严格的（"未定义"精确指当前状态空间未定义）；扩展后可定义，
开放轴非 bug。

### 5.5 对抗验证新发现（守卫缺口，低频但在册）

1. `close_position` 的 `total_shares≤0` 早退先于清腿：earning 相全仓开腿时
   master 出场会吞掉在途现金（当前空有效域，earning 触发后与 5.3 叠加可达）；
2. AmountConserving 腿开放期间在途现金 V 不驻留账本任何字段——未来引入逐 bar
   净值曲线会在该窗口系统性低估 equity（不变量未在 docstring 声明）；
3. `total_shares≥0` 是构造不变量但无断言守卫（frac>1 会静默转负为"意外净空头"）；
4. T5 的 Python/Rust 对账分歧面**仅亏损子路径可观测**（盈利侧两边巧合同为 0.0）
   ——5.3 的触发腿恰是亏损路径，分歧真实存在（Python 该笔 cb_exit=+4.92 vs
   Rust 0.0；pnl 两边一致）。
