## 2. Phase 3 证伪：churn 不来自 collapse

### 2.1 移除 collapse 几乎零差异

Phase 3 实装（`unified_recursive.rs` C 块）：翻转仅在 `chain.len()==1`（根独存）时发生——
移除 `unwind_to(1)` collapse，子先经 D 独立回补（逐仓独立：子平仓不影响父），根稍后 len==1 翻。
单测：`full_recursive_chain_enables_flip`（加 recover bar 后 len==1 翻转）+ 9 其他，cargo test 10/10。

实测：八标的 Δ 全 < 3.5pp（OKLO +0.4/CL −2.0/BTC +3.5）。trades 几乎不变（CL 2282→2259）。
**移除 collapse 没有消除 churn**——编排者"全仓翻空 churn ← collapse"假设证伪。

### 2.2 churn 的真实来源：翻转的空头结构降成本

CL P3：2259 trades，仅 3 sellpt（flips 极低）。churn 主体 = 翻转产生的空头子做降成本
（E spawn 2000+）+ 回补 + 否定。这是翻转机制的**结构性产物**，非 collapse。逐仓独立改变的是
collapse（罕见），不触降成本循环（主体）。

### 2.3 翻转长偏净负不可约

8 标的 BH 全正（长偏）。翻空捕获下跌，但长偏标的的下跌是**回调（恢复）**——翻出多头结构
错过上涨恢复 + 空头被否定（有界失血）。这是**有效域问题**（formalization-validity-domain）：
翻转有效域 = 双向/空偏 regime；当前 8 标的全长偏 = 翻转有效域外。机制精化（4 次）无一能修，
因为问题不在机制，在**资产 regime 与翻转有效域的错配**。
