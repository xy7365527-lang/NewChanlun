## 2. 编排者假设证伪 + 递归确认的 regime 三态

### 2.1 假设："递归确认消除 CL 过度清仓" —— 证伪

| 标的 | 基线 | P1（sell_any 清仓） | P1+0（+递归确认） | 递归确认 Δ |
|---|---:|---:|---:|---:|
| **CL** | +126 | +15 | **+6** | **−8pp（未修复，反略降）** |
| OKLO | +1078 | +1324 | +388 | **−935pp（摧毁）** |
| BTC | +773 | +793 | **+1375** | **+582pp（巨幅恢复，逼近 BH +1380）** |

**CL 未恢复**：CL 的崩溃来自 sell_any 触发的 type3 清仓**本身**（Phase 1：+126→+15），非清仓
频率的弱确认。递归确认减少清仓频率，但 CL 剩余的清仓仍是 sell_any 误触发 ⇒ Δ=−8pp 无效。

### 2.2 递归确认 = 减少清仓频率 = 又一 regime 函数

递归确认门把弱确认清仓转为降成本 spawn ⇒ **等价于减少清仓频率**。最优清仓频率 regime 分化：

| regime | 标的 | 递归确认（减清仓）效果 | 机制 |
|---|---|---|---|
| **需频繁清仓** | OKLO | **−935pp 摧毁** | 强单边牛，频繁清仓抓 type3 顶+再入，减清仓=踏空 |
| **需罕见清仓** | BTC | **+582pp 巨幅恢复** | 强持有，过度清仓损 alpha，减清仓=持住吃 BTC 牛 |
| **sell_any 本身坏** | CL | −8pp 无效 | 崩溃在 sell_any 误触发非频率，减频率不解 |

这是 MEMORY 反复出现的「清仓频率 regime 函数不可约」的第 N 次确认——递归确认只是清仓频率的
又一旋钮，**不存在普适的清仓频率/确认强度**。

### 2.3 BTC +1375 的 regime 特异性（notable）

BTC 在 P1+0（递归确认清仓）下 +1375%，全五配置最佳，逼近 BH +1380。BTC = 强持有标的，
递归确认的"罕见清仓"正中其 regime（少动 ≈ BH）。但这是 regime 特异，不泛化（OKLO 同配置 −935pp）。

## 3. 结果包六要素

1. **结论**：当前配置确认 = Phase 0+1+2（sell_any ∧ 递归确认 → 翻转，P1 2/8）。隔离 Phase 1+0
   （sell_any + 递归确认 + 清仓，P1 1/8 最差）证伪编排者"递归确认修复 CL"假设——CL Δ=−8pp 未修复；
   递归确认是又一 regime 函数（OKLO −935pp / BTC +582pp）。基线 URS（5/8）仍绝对收益最优普适配置。

2. **定义依据**：编排者 Phase 0/1/2 规格；递归确认 `confirmed(k)=settled(k)∧∃BSP(k-1).confirmed(k-1)`；
   清仓频率 regime 谱系（534/540/nrf 系列）。代码：`unified_recursive.rs` C 块门（sell_any ∧
   recursive_confirmed）× 动作（清仓 unwind_to(0) vs 翻转 spawn(m=N)，C_CLEAR_NOT_FLIP 实验开关）。

3. **边界条件**：结论翻转条件——(a) 若按 regime 选配置（OKLO/GC/BRN/DX→P1, QQQ/ES/CL→基线,
   BTC→P1+0），则组合 P1 可达 8/8——但那是 per-asset 白名单（regime 门），非普适零 flag；
   (b) 若目标改风险调整（MDD），翻转配置（P2/P2+0）8/8 优 BH；(c) CL 的修复轴在 sell_any 触发
   层（非清仓频率层），未探。

4. **下游推论**：(a) **五配置无单一普适超基线**——分阶段补完（sell_any/翻转/递归确认）在长偏标的
   绝对收益均未超基线 5/8，每项是 regime 函数 ⇒ 若求普适绝对收益，回退基线 URS；(b) per-asset
   regime 白名单可达 8/8 但违反零 flag（regime 门=136号成本收益消解的对偶=regime 不可约的承认）；
   (c) BTC P1+0 +1375 = 强持有标的少动制胜，可作 BTC 专属配置候选（regime 特异）。

5. **谱系引用**：清仓频率 regime 函数不可约（534/540/`project_nrf_v4_strict_accounting`/
   `project_constitutive_throughput_falsified`「四形态全测无一普适」）——本次递归确认是第 N 形态，
   同样 regime 分化。`project_nrf_v3_root_flip_falsified`（翻转否证，本轮条件化翻空安全但长偏净负）。
   编排者假设证伪 = 否定性结果（缩小有效域：递归确认的有效域 = 需罕见清仓的 regime，非普适）。
