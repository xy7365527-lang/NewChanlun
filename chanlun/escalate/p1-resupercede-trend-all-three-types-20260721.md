# 裁定草案：P1 重议——趋势域终端背书收二三类

- 日期：2026-07-21
- 状态：**草案**（待编排者拍板）
- 来源：grilling #106/#127→#128 审计后编排者教义澄清
- 前置裁定：关③ P1（pan-terminal-endorsement-ruling-20260718.md）

## P1 原裁定

趋势族（Trend）事件的合法终端背书 = 窗口 `[c_start, t*]` 内**破 B 一类点（owner=B ∧ buy1|sell1）**；二/三类点不视为充分背书。

教义依据（原裁定引用）：
- 027:66：「第一类买点肯定是趋势背驰构成的」
- 037:20：趋势背驰 c 段必须创新极值
- 061:28：背驰点与三类点分述为两件事
- 024:18：「任一背驰必然制造某级别买卖点」

## 重议理由

### 1. 原裁定的推理跳跃

P1 从"趋势背驰定义了一类买卖点"推论"趋势走势段内只有一类合法终端背书"。这是过度推理：

- 027:66 说的是**一类买卖点的构成来源**（趋势背驰），不是**趋势走势段内只有一类合法**
- 027:66 后半句"盘整背驰构成的买点在小级别**意义不大**"——"意义不大"是相对说法，不是否定。在严格体系里"意义不大"≠"不处理"
- 024:18 说的是背驰制造买卖点，没说**只有背驰制造的买卖点才合法**

### 2. 全定义策略要求

本项目的核心 goal = "完全互斥分类的全定义策略"。P1 在趋势域排除二三类 = 全定义策略在趋势域**不完全**：

- 趋势走势中的二买（回调不破）和三买（中枢突破回踩）客观存在
- 不定义它们 = 有买卖点落入无类状态
- 090 违规：声明"全定义"但实际在趋势域没定义二三类

### 3. 实盘后果

P1 排除趋势域二三类 ⟹ 实盘遇到趋势走势中的二三类买卖点不做：

- 趋势走势是利润最大的行情
- 趋势里的二买（回调入场）和三买（突破回踩）是最安全的入场点
- 放弃它们 = 趋势行情只做最稀少的一类（背驰确认点）
- #128 审计实证：Trend 族 465 案中 type1 仅 95（20.4%），其余 370 案（79.6%）被排除

### 4. 编排者教义澄清（grilling 2026-07-21）

> "每个买卖点都是某级别的一类买卖点"——趋势走势里 L0 的一个二买，它是更低级别的一类买卖点。它不因为出现在趋势走势段内就不存在或不该做。
>
> "意义不大"不是没有意义。在严格体系里必须处理。

## 重议裁定

**趋势族（Trend）事件的合法终端背书 = 窗口内同向（confirm_side）一/二/三类点全合法**——与盘背族（P2）同构。

- 一类（buy1/sell1）= 背驰确认点，趋势走势的核心定义点
- 二类（buy2/sell2）= 回调不破点，趋势走势的安全入场点
- 三类（buy3/sell3）= 中枢突破回踩点，趋势走势的延续确认点

owner=B 身份合取保留（背书对象 = 本事件 a+A+b+B+c 趋势的 B 中枢）。窗口 `[c_start, t*]` 与最早性确定性不变。confirm_side 方向谓词不变。

## 影响

- `terminal_bits_in_book` CWindow 分支 Trend 域移除 `(buy1||sell1)` 限定
- 证书索引 Trend 域二三类进入 → typed_found 命中率显著上升（#128 审计预期 ~25-35%）

- 旧口径对照读数保留（bit-exact 回归锁用于验证变化量）
