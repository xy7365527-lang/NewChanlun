## 三、四类判别口径（可复核）

判定点仍是 `admission.rs` 的 `if n_clean == 0 { if n_certs > 0 { MissingCausal } else { MissingCert } }`。
对每个落 `missing_cert` 的（候选 × 账本级）格，用键 `(event_level, price, anchor)` 现场读诊断账本，
按下列**优先级**归一类（重叠情况见 §5，未抹平）：

| 类 | 判别式（dump 字段直读） | 含义 |
|---|---|---|
| **④ 结构性不可满足** | `event_level > diag.max_event_level` | 该事件级从未被 `sync_events`（`for level in 1..n_levels`）派生过 ⟹ 键永不被生产 |
| **⑤ 键错配** | `diag.reg_same_price > 0` | 同级同极值价**有**已登记确认事件，组锚不同 ⟹ 三元键不命中 |
| **② 谓词不成立** | `diag.unconf_exact > 0`（精确同键）或 `diag.unconf_same_price > 0`（同价异锚） | 事件已产出，被 `admission.rs` `!event.divergence_confirmed` 丢弃 |
| **③ 装配缺口** | `diag.miss_same_price > 0` | 事件确认，但 `extreme_price`/`group_anchor` 解析不出（`n_anchor_misses` 同一前件） |
| **① 产出缺口** | 以上全零 | provider 在该级该脚根本没产出事件 |

字段定义（写入点均在 `absorb_exts`，与生产登记同源）：

- `max_event_level`：`sync_events` 实际派生过的最高事件级（= tower `n_levels-1` 的运行期最大值）。
- `reg_same_price`：`(level, price)` 下已登记（确认 ∧ 锚可解）的事件身份数。因本格 `missing_cert`
  ⟹ 精确三元键必空 ⟹ 这些登记必然挂在**不同组锚**上。
- `unconf_exact` / `unconf_same_price`：被 `!divergence_confirmed` 丢弃、且两元锚可解的事件，
  分别按三元键 / 二元 `(level, price)` 计数。
- `miss_same_price` / `miss_no_price`：确认但缺锚事件，按极值价可解 / 不可解分列。
- `unconf_no_anchor`：未确认**且**锚不可解（两重缺陷，无法归到具体键，只能作该级上界）。

**计数语义警示**：未确认事件不过 `seen` 去重（`absorb_exts` 在 dedup 之前 `continue`），
故 `unconf_*` 是**逐次出现计数**，跨 bar 重复派生会累加。因此本报告只用它做**有/无**判据
（这正是分类所需），**不**拿它与已登记事件数比大小。

**④ 的机制复核（实测）**：三窗全部 500 个 ④ 格，`level == chain.top` 的比例 = **100%**
（318/318、66/66、116/116）。即 ④ 恒发生在链顶那一级——正是票面所述「链查询要 `event_level = book+1`，
而派生只到 `n_levels-1`」的机制。低级别（L0/L1/L2）上出现的 ④（合计 2+20+79 等）不是反例，
而是**回放早期塔层数尚未长起来**时的同一机制（当时的塔顶就在低级别）。

## 五、重叠与不可分（090 照实）

优先级归一类会掩盖重叠，故原始指示器组合照实列出（三窗合计）：

| 非零指示器组合 | wf7 | wf8 | p3fold | 说明 |
|---|---:|---:|---:|---|
| `unconf_exact` + `unconf_same_price` | 2042 | 1720 | 1931 | ② 的全部；两者恒同现（同价集合 ⊇ 同键集合），非独立信息 |
| `STRUCT`（单独） | 318 | 66 | 116 | ④ 的全部；**从不与任何其他指示器同现**（该级根本没派生过事件，逻辑自洽） |
| 全零 | 248 | 568 | 279 | ① 的全部 |
| `reg_same_price` + `unconf_*` | 3 | 2 | 0 | ⑤，同时也有同价未确认事件——归 ⑤（键错配是更强的证据） |
| `reg_same_price`（单独） | 0 | 1 | 0 | ⑤ |

**不可分残留（照实）**：

1. **① 的内部不可再分**。① 定义为「该 `(级, 极值价)` 上诊断账本全零」。它无法区分
   「provider 扫描到该脚但整段 run 被 `project_extended_windows_carried_only` 判非法而未进入
   事件构造」与「该脚根本不在任何合法 run 的 `seg_c.1` 上」。要分开，需要在
   `derive_level_events` 的 run 扫描层再落一层「非法 run 覆盖的源坐标区间」账本——本票未做
   （超出「拆四类」授权，且属新增探针）。
2. **③ 为空是本轮实测结论，不是永真定理**。`miss_*` 计数器恒零只说明当前 main 上
   `n_anchor_misses` 在被查询级上不发火；换个数据窗或改 `resolve_triple_anchor` 供给线，
   ③ 可能复活。判别口径已埋好，复跑即可读。
3. **② 的「教义必然 vs 实现缺陷」本票不判**。本票只交付「② 占 78%」这个可测量；
   这 78% 里哪些是「中枢内部往返本就不产生父级买卖点」（教义必然），哪些是
   `divergence_confirmed` 的合取门（T4 回拉 0 轴 ∧ T3 三买 ∧ T2 破极值 ∧ T5 力度）过紧，
   需要另开一票逐条拆 `pair_confirmations` 的失败分量。**#252 那条 11%~33% 的分母之争不必再打**
   ——② 的占比是候选池分母下的直接读数，与教义预期不同量纲，只能作「上界性质」看：
   **教义必然至多能解释 78%，不可能解释更多**。

## 六、旁注实测：`index.get(id)` 落空（比票面预估严重）

票面要求「给个计数即可」。实测结果反而是本票最硬的副产品：

| 窗 | `missing_causal` 行数 | 键域身份总数 | 其中 `index.get` 落空 | 被因果守卫剔除 |
|---|---:|---:|---:|---:|
| wf7 | 253 | 254 | **254** | **0** |
| wf8 | 141 | 141 | **141** | **0** |
| p3fold | 104 | 105 | **105** | **0** |

**读法（事实）**：三窗全部 `missing_causal` 格中，键域取到的每一张身份都在
`self.index.get(id)` 上落空并 `continue`；**没有任何一张证书是被因果守卫
（`judge_at > anchor_index`）剔除的**。`missing_causal` 这个标签当前 **100% 名不副实**——
它记的是索引缺失，不是因果越界。

**推断（标注为推断，非本票裁定）**：这与 `NEST_GATE_INDEX` 的 `events=725 / indexed=61`
（wf8 实测行）方向一致——绝大多数已登记事件从未进入证书索引，故按身份反查必然落空。
这条线属于 #740 的「环节 × 性质」拆账里独立的一档，建议单开票。
