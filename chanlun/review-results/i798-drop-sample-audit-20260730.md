## 二、次级别留存查法说明（交付物；先立查法，再判样本）

### 2.1 架构前提（编排者提示，实测验证通过）

候选枚举入口是双层遍历（`rust/src/theta_v0/strategy/interp.rs:1222-1233` / `1240-1252`）：

```
for (level_idx, level) in classification.levels.iter().enumerate()
    for point in level.bsp.iter()
```

⟹ **每个级别的每个买卖点各出一个候选**，全部级别的候选行都在同一份 dump 里
（wf7 实测候选级分布 L0 1119 / L1 484 / L2 258 / L3 83 / L4 82，与该结构一致）。
次级别不是外部装置，就是低一级的同一引擎实例——查法不需要新探针。

### 2.2 对应键 = `(price, anchor)`，这是生产代码自己的跨级同一性

`NestChainGate::chain_lookup`（`admission.rs:1066-1077`，#797 插桩版行号）对候选脚做
恰好存在扫描时，用的正是 `(price, anchor)` 二元键逐级横查：

```rust
layer.cross_level_query(price).matches.iter().any(|e| e.group_anchor == anchor)
```

即**生产系统本身就以 (极值价, 组锚) 作为「同一个转折点在各级别的身份」**。用它作父级↔次级别
对应键不是本票发明，是沿用生产口径（两元锚单一来源 = `projection::anchor_resolver`，禁第二查法）。

### 2.3 级别映射（被丢事件的「次级别」是谁）

② 格坐标 = (dump 行, 账本级 g)。被丢的事件在 **event_level = g+1**（`admission.rs:1089`：
`event_level = book + 1`）。其次级别 = **级 g** 的买卖点——即 dump 中
`level == g` 且 `(price, anchor)` 相同的候选行（当候选自身 level == g 时就是本行自己）。

### 2.4 「留住」的判据

次级别实例行的 `admit` / `channel` 字段（`record` 落盘于 `admission.rs:1703-1723`）就是
「是否作为买卖点存在且被消费」的直接记录：`admit == true`（`xzd_pass` / `nest_pass`）= 该级
实例进入 fill loop 被消费；`admit == false`（`xzd_gate_fail` / `nest_n_delta_false` / `cert_none`）
= 该级实例也被拒。判定取**同向**（`dir` 相同）实例——同一极值脚上的异向候选是另一笔交易，
不算「这一条被留住」（编排者点名的坑，已避开）。

### 2.5 对应键覆盖率实测（查法成立的证据）

对三窗全部 5693 个 ② 格：**level == g 且 (price, anchor) 相同的候选行存在率 = 100%**
（wf7 1242/1242、560/560、219/219、21/21；wf8 1044/1044、552/552、108/108、16/16；
p3fold 1277/1277、478/478、166/166、10/10）。机制解释（推断）：② 格的前件是该格
`status == missing_cert` 而非 `missing_existence` ⟹ `existence[g]` 扫描已命中
⟹ 级 g 投影层在该 (price, anchor) 上有登记 ⟹ 该级 bsp 存在 ⟹ 双层遍历必然把它枚举成候选行。
对照：不限 ② 的一般跨级匹配率只有 ~30%，100% 是 ② 前件带来的，不是键太松。

### 2.6 查法边界（照实）

- 同向限定后约 11% 的样本在级 g 上**只有异向实例**（多为 k≠g 的格）——归「查不到」，入疑义清单；
- `admit=false` 的次级别拒绝臂几乎全是 `xzd_gate_fail`（Xzd 回退门 Type2/3 评估不过 /
  无执行段），**该拒绝本身对不对是另一问**，本票不越界判它，只登记「未被消费」这个事实；
- dump 只覆盖门开分支记录的候选；未被枚举成候选的买卖点不可见——但 2.5 的 100% 存在率
  说明对 ② 总体这不构成缺口。

## 三、判定规则（机械、可复现；教义锚）

**Q1 父级该不该丢**（被丢事件在 event_level g+1 的确认，对照原文）：

- 该格 `gap == "broken"`（同一条链更高账本级已 `closed`）⟹ **不该丢?（谓词有偏候选）**。
  教义锚 = 第 20 课区间套：更高级别背驰已确认而同一脚的本级事件反而未确认，与逐级向下
  背驰嵌套的预期冲突。此类**只作候选、全部呈交疑义/定向清单**（§7），不拍板。
- 否则（`gap == "missing"`，上方无任何闭合）⟹ **该丢（推断）**。教义锚 = 第 53 课
  （中枢震荡不产生该级别买卖点）+ 第 36 课（多数证书本就落在次级别自身）。
  **置信声明**：dump 无该级走势结构载荷（中枢震荡 vs 趋势背驰不可直读），此判是
  prima facie——「没有任何更高级证据反对丢弃」，不是逐条结构核实。要升到逐条核实
  必须拆 `pair_confirmations` 分量，票面明令不拆。

**Q2 次级别有没有留住**：按 §2 查法——级 g 同 (price,anchor) 同向实例中存在 `admit==true`
⟹ 留住；同向实例全 `admit==false` ⟹ 没留住；无同向实例 ⟹ 查不到（疑义）。

**组合**：该丢+留住 = 教义正确；该丢+没留住 = 真丢失；Q1 触发 broken = 谓词有偏(候选)；
查不到 = 疑义。

## 四、抽样口径（可复现）

- 单元 = (dump 行, 账本级 g) 的 ② 格（与 #797 计数分母同型）。
- 固定序 = (文件行号升序, 账本级升序)；分层 = 窗 × 账本级。
- 每层配额：L0=15、L1=15、L2=4、L3=2（层内不足全取）；系统抽样 step = ⌊N/n⌋，
  取 index 0, step, 2·step, …。
- 实际 n = 108（3 窗 × 36），≥ 票面 60；L0/L1 每层 15 满足票面「重点层 ≥15」。
- 复现：跑 §头部命令，输出与本报告数字逐字一致（本次落盘前已 shasum 校验）。
