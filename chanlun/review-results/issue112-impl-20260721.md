## 改动清单

1. `NestChainGate::admit()` 的唯一 nest 判定源由 fixed
   `typed_lookup(lvl, source_index, delta)` 切换为
   `typed_lookup_multi(lvl, source_index, delta, confirm_index)`：
   - `anchor_index = confirm_index`，沿用 #111 已接受的全链 `judge_at <= anchor` 因果守卫；
   - 准入真值取 `MultiLevelTypedLookup::merged.0`；链深取 `merged.1`；
   - multi 为 `None` 时才进入原有 Xzd fallback；旧臂 Xzd 复用、
     `build_xzd_fallback` 补评、`cert_none` 三分支的代码与语义未改。
2. fixed `typed_lookup` 仍在 `admit()` 中读取，但只落 `NestGateObs::single_admit`；
   不参与准入。L2 `nest_gate_admit` 旧臂双读及既有 cross/reuse 账本保持原样。
3. `NestGateObs` 新增：
   - `typed_hit_levels`：multi 命中级别集合（升序、去重）；
   - `single_admit` / `multi_admit`：fixed 与 multi 的 `Option<bool>` 对照列。
4. `NestGateStats` / `NEST_GATE_CHAIN` 新增：
   - `level_hits={...}`：按 nest 级别累计的命中候选数；
   - `single_multi_divergence`：fixed 与 multi `Option<bool>` 不相等的候选数。
5. 新增 `has_bridge_key_multi(source_index, delta)`，entry 惰性索引重建前置改查
   `by_end_multi`。#76 exit 侧仍调用 `has_bridge_key(lvl, ...)` 与 `typed_lookup(lvl, ...)`。
6. 删除 `MultiLevelTypedHit`、`MultiLevelTypedLookup`、`typed_lookup_multi` 上 #111
   expand 阶段的 `#[allow(dead_code)]`。
7. 判定谓词未分叉：fixed/multi 都只读取 `cert.certificate().n_delta()`；未新增第二查法，
   未修改 `typed_lookup_multi` 查询语义。

## D 项：multi key 惰性重建前置核验

结论：`has_bridge_key_multi` 健全，**无需修复维护点**。

- `absorb_exts` 是 first-wins 单写点；事件通过 confirmed 与 identity 去重后，先以同一个
  `id`、同一个 `seg_c_full.1`、同一个 `is_long` 同步写入：
  - `by_end[(event.level, seg_c_full.1, is_long)]`；
  - `by_end_multi[(seg_c_full.1, is_long)]`。
- 两张 key 表都在 `sync_index()` 之外增量维护，不依赖 lazy rebuild；lazy rebuild 只更新
  `NestCertificateIndex` 与终端背书账本指纹。
- 因此 `has_bridge_key_multi == false` 构造性推出 `typed_lookup_multi == None`；true 允许因
  level 下界、终端背书或 causal guard 产生保守假阳性，只会多 rebuild，不会漏 rebuild。
