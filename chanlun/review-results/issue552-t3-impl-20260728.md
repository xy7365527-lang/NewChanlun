## 二、设计决策

### 1. 落新模块 `cand_sub.rs`，不塞回 `cand_event.rs`

`cand_event.rs` 已 1335 行（coding-style 上限 800）。N2 是与 N1 载体正交的独立能力（谓词 + 只读扫描），
塞回去等于往已超标文件继续堆。新模块的边界是清楚的：**`cand_event` 管候选是什么、生命史怎么走；
`cand_sub` 管两个候选之间的跨级几何关系**。

代价与限制照实：`interval_is_sub`（区间层）与 `candidate_is_sub`（跨级层）现在分处两文件。
这不是重复——后者调用前者，全仓只有一处区间不等式。

### 2. 两个合取分量各有单一来源

```rust
child.event_level < parent.event_level && interval_is_sub(child.interval, parent.interval)
```

- **区间分量**：唯一来源 `cand_event::interval_is_sub`（#550 已在案，闭区间含端点）。本模块不重写不等式，
  故 #246 相切口径无第二处可漂移。退化区间（`start > end`）的拒绝也由它承担——本模块的退化用例
  （`degenerate_interval_is_rejected_through_shared_interval_predicate`）锁的正是这条**传导**，不是本模块自判。
- **级别分量**：本模块新增，`<` 严格小于。严格性论证：同级两候选互不为对方的次级别（同级 = 同一 T 层，
  区间套是**逐级下降**关系）；级别大者更不可能是级别小者的子级。

### 3. 谓词不要求相邻级

`ℓ` 与 `ℓ+2` 之间同样可判。理由：**逐级缩小是链的性质，不是单条包含关系的前件**——把「相邻」写进谓词，
等于把 N3 链构造的约束提前硬编码进 N2 谓词。真值表 `cross_level_sub_truth_table_on_level_axis` 有跨两级一格。

（探针只扫**相邻**级，那是探针口径而非谓词口径，见 §八 登记 3。）

### 4. 扫描口径：每 key 最新 revision，不按 `state` 过滤

- **最新 revision**：包含判定问的是「当前几何是否相含」。同 key 的历史 revision 是同一候选的旧几何，
  计入会把一个候选按修订次数重复计数、污染分母。合成锁 `scan_reads_latest_revision_only`（流里 3 条 revision、
  扫描只见 1 个子级事件）。
- **不按 `state` 过滤（含 `Invalidated` 终态）**：`C⊆C` 是纯几何谓词，与候选活/死状态正交。
  「哪些候选有资格进链」是下游 N3 的裁量——在谓词层提前过滤 = 把未裁定的语义塞进 N2。

### 5. 同级门计数拆自反 / 非自反

首版把同级拦截合并报数（100k `same_level_blocked=296`），但其中 268 是**自反对**（事件与自己）——
自反包含是区间谓词自反性的复述，与级别门无关、零信息量。拆分后 `non_reflexive_blocked=28` 才是
「两个**不同**候选同级相含、被级别分支拒」的真实拦截数。

交叉校验（两窗口均成立）：`same_level_reflexive_blocked == 电池 identities`（100k: 268 == 268；
500k: 1565 == 1565）——自反对数恒等于候选身份数，两套独立计数对上。

### 6.5 扫描分组存借用，不是 `Rc<CandidateEvent>`（收口小修批 · 切片 3）

`latest_by_level` 首版逐事件 `event.clone()` 深拷，与 `cand_event.rs:142`「双层 `Rc` 让事件入口只克隆
引用，不深拷贝全簿」的设计意图相悖。收口时改为存**借用**（`BTreeMap<u32, Vec<&CandidateEvent>>`），
`count_pairs` / `count_same_level` 相应改 `&[&CandidateEvent]` / `&BTreeMap<u32, Vec<&CandidateEvent>>`。

**为什么不是 `Rc<CandidateEvent>`**：`CandidateStreams = Rc<Vec<Rc<Vec<CandidateEvent>>>>` 的内层是
**整条流一个 `Rc`**，不是每事件一个 `Rc`。改存 `Rc<CandidateEvent>` 必须先 `Rc::new(event.clone())`
——深拷次数与首版**完全相同**，只多一层间接。它只能换来「与簿的所有权风格一致」的观感，
不解决被点名的问题（Standards LOW-1）。

借用方案零拷贝，生命周期由调用方持有的 `streams` 担保（`Rc::deref` 把外层借用透传到内层事件，
借用链 `&'a Rc<Vec<Rc<Vec<E>>>>` → `&'a E` 由生命周期省略直接推出，无需显式标注）。
本模块下游只读 `interval` / `event_level` / `key` 三个字段，不需要所有权。
改后 `cand_sub.rs` 全文零 `clone()`。纯内部表示改动、无新行为，回归锁 = 既有单测全绿。

### 6. 探针与谓词同源（不是 bin 侧重算）

电池的 `print_containment_summary` 直调 `cand_sub::scan_adjacent_containment`，其内部逐对调
`candidate_is_sub`。故印出的每个数都是**谓词本身**在真实数据上的判定结果。
（对照：#551 报告点名的 `growth_revisions` 是 bin 侧对事件历史的独立重算，「同名不同源」——本票不重蹈。）

### 复杂度声明（收口小修批 · 切片 4）

`count_pairs` / `count_same_level` / `scan_adjacent_containment` 均为**二次复杂度——对数随窗口内
事件数平方增长**。首版代码与文档都没声明这条，收口时补进三个函数的 doc。

实测锚（本节窗口 B，BTC 500k bars）：

| 量 | 100k 窗 | 500k 窗 | 增长 |
|---|---|---|---|
| 事件身份数 `identities` | 268 | 1,565 | ×5.8 |
| 同级对 `same_level_pairs` | 48,870 | **1,593,865** | ×32.6（≈5.8²） |
| 相邻级对 `total_pairs` | 9,307 | 342,252 | ×36.8 |
| 电池耗时 | 10.1s | 10m30.7s | ×62 |

事件数 ×5.8 ⟹ 对数 ×33，平方关系在两窗口实测上直接可读。`same_level_pairs` 是复杂度主导项
（同窗比相邻级对数大 4.7 倍），因为低级别同级事件集最大。

**有效域**：这是**只读探针**的可接受代价——零消费，调用点仅单测与诊断 bin，不在任何回放热路径上。
若将来把本扫描接进逐 bar 循环，二次项直接主导，届时须改判据结构（如按区间端点排序后扫描线），
