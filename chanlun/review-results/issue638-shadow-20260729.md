### MEDIUM-1｜票面点名的 `spiral/signal.rs` 族未核，位置裁量候选集不完整

票面范围第 1 条逐字要求：「开工核当前信号通道权威：`spiral/signal.rs`、`trading/runner.rs` 族
——选与 #587 迟到过滤同侧的位置，说明理由」。

实测：模块头 §为什么落在这里（`rust/src/trading/third_point_book.rs:9-32`）与实施报告 §2.1 核查表
**只核了 `trading/` 一侧**（`lib.rs:49`、`runner.rs:1-6` 头注、`runner.rs:807`/`:824`、`tape.rs`、
`center_book.rs:35`——这五处我逐行复核，行号与内容全部精确命中）。两份交付物对 `spiral/signal.rs`
**零字提及**（grep 全文无该路径）。

而该文件不是无关文件：`rust/src/spiral/signal.rs:1` 头注自称「信号层消费：BarSig → 群事件映射」、
`:3` 称「信号层是操作层的**唯一定义域单元**」，且 `:26-29` 直接 `use crate::trading::center_book::CenterBook`
/ `crate::trading::tape::BarSig` / `crate::trading::types::{BspEvent, MAX_LADDER}`。它消费**结构化
`BspEvent`**，比 `runner` 读的布尔行（`sig.buy1`）更接近票面「`ThirdPointPack` → 三类点成立事件」
的形状。

后果：报告 §2.2 的候选集只有三个（A=`center_book`、B=新模块、C=`runner` 主循环），**缺「spiral 信号层」
候选**，因此「新独立模块隔离最净」这一裁量是在不完整候选集上做出的。裁量结论我倾向认可（spiral 是
群事件/操作层映射面，同样属判据侧，方向与观测登记侧相反），但这一步论证在交付物里不存在，属票面明文
要求的核查覆盖缺失，而非仅形式瑕疵。

**处置建议**：补核 `spiral/signal.rs` 族并把「为何不落 spiral 信号层」写进模块头 §为什么落在这里
（一段即可），使候选集与票面点名对齐。

### MEDIUM-2｜`sync_from_ledger` / `register_from_ledger` 的冲突早退语义零测试覆盖

`third_point_book.rs:204-206` doc 明文声明：「**首个冲突即返回，已登记部分保留**（如实声明，非疏漏）
——本账是登记账，无回滚语义」。实现见 `:217` 的 `self.register(pack)?`。

实测 8 条测试（`cargo test --lib trading::third_point_book` 全绿，逐条读过）：
`conflicting_pack_for_the_same_identity_fails_loud`（`:398`）只走 `register` 直路；
**没有任何测试驱动 `sync_from_ledger` 或 `register_from_ledger` 进入 `Err` 分支**。

这正是模块里唯一「带早退 + 留下部分副作用」的路径——也就是最需要钉的那条。同时暴露一处 doc 未声明
的行为：`?` 早退会把已累积的 `admitted: Vec` **整个丢弃**，调用方拿到 `Err` 时既不知道哪些身份已入册
（doc 只说「已登记部分保留」，没说「本次新登记清单丢失」），只能回头重扫 `established()`。

**处置建议**：补一条测试——账本产两条 Confirmed、先手工 `register` 其中一条的改口版本、再
`sync_from_ledger`，断言 `Err(ConflictingPack{..})` + 在册内容不被覆盖 + 另一条的登记状态如实。
并把「admitted 清单在 Err 路径上丢弃」补进 `:204` 那段 doc。

### MEDIUM-3｜禁区证明成色高于实际：两处措辞反了

票面验收第 2 条要求「备战档类型不出现在本票任何信号路径（**编译期或等价**）」。字面达标我确认：
生产段（`:1-262`）零 `StandbyWatch`——grep 实证，`StandbyWatch` 仅出现在模块头 doc 文字（`:61/:65/:68`）
与测试段（`:271/:457/:468`）。但两处「编译期强制」的措辞比实际强度高：

**(a) `third_point_book.rs:169-170`**：「泛型在此不是扩展点，是**把禁区写进签名**——具体型入参会让
闸门退回注释。」——**反了**。具体型入参 `fn register(&mut self, pack: ThirdPointPack)` 本身就是最强的
编译期闸门（传 `StandbyWatch` 直接类型不匹配，与任何 trait 无关）。泛型 `S: TradableSignal + Into<ThirdPointPack>`
严格**更宽**：它接受任何未来满足这两条 bound 的类型。泛型版本的真实价值是把 `TradableSignal` 显式写在
签名上作为可 grep 的教义锚，不是「更强的闸门」。

**(b) `third_point_book.rs:68-71`**：「`StandbyWatch` 结构性没有 `retest_end` / `confirmed_as_of` /
`death_certificate`，即便日后有人显式给它实现 `TradableSignal`……**也拿不出本入口所需载荷**。」——
拿不出**真实**载荷，但拿得出载荷：`retest_end := leave_end`、`confirmed_as_of := registered_as_of`、
自造一个 `CenterDeathCertificate { center: frame, issued_as_of: registered_as_of }` 即可凑出合法
`ThirdPointPack`。字段表全解构测试（`:468-474`）只保证「字段表变更 ⟹ 编译失败」，**不阻止伪造**。

**实质强度**（如实登记）：禁区靠的是「`TradableSignal` 目前无其它实现者」+「`StandbyWatch` 无
`Into<ThirdPointPack>`」，绕路需要显式新增 impl（可见的破坏性改动）。但还有一条**不需要任何新 impl**
的最短绕路：`ThirdPointPack` 字段全 `pub` 且无构造守卫（`retrace_ledger/book.rs:112-127`），任何
crate 内代码都能读 `StandbyWatch` 的字段、手搓一个 `ThirdPointPack` 喂 `register`——本票测试自己就
用了这个手法造 `tampered`（`:405-408`）。这是账本 S1 既有性质、非本票引入，且票面验收字面（「备战档
**类型**不出现在本票信号路径」）不被违反，故不升级为 HIGH；但「编译期不可绕」的成色不成立。

**处置建议**：把 (a) 改成「泛型在此把禁区 trait 显式写进签名（可 grep 的教义锚），闸门强度与具体型
入参同级」；把 (b) 的「也拿不出」改成「也只能用假值凑载荷——结构墙让绕路显式，不让绕路不可能」。

### MEDIUM-5｜「账本侧零参与」的验收钉子是恒真断言

票面验收第 1 条明文要求「账本侧零参与」。报告 §3 把它钉在
`late_pack_is_registered_verbatim_regardless_of_confirmed_clock` 的
`third_point_book.rs:437` `assert_eq!(late_ledger, ledger_before)` 上，并称「`RetraceLedger` 全值相等，
登记不回写账本任何一个 bit」。

实测该断言**在任何实现下都成立**：这条测试路径调用的是 `book.register(late)`，参数是
`ThirdPointPack`（`Copy` 值，`book.rs:111` derive `Copy`），`register` 的签名（`:179-182`）根本不接
`RetraceLedger` 引用——`late_ledger` 与被测代码之间无任何通路。断言无信息量，不构成「不回写账本」
的证据。

真正接账本的路径是 `sync_from_ledger(&mut self, ledger: &RetraceLedger)`（`:211`）与
`register_from_ledger`（`:228`），两者取 `&RetraceLedger`；在无内部可变性的前提下「零回写」由类型系统
保证（这条我认为可以直说，比一个恒真运行时断言诚实）。

**处置建议**：把该断言移到 `sync_from_ledger` 路径上（顺带覆盖 LOW-5 的构造改进），或在报告里把
「账本侧零参与」的兑现方式改述为「入口签名只取 `&RetraceLedger` / `Copy` 值 ⟹ 类型系统保证」，
不再声称有实测钉子。

### LOW-4｜「三通道互不代劳」是行为约定，非结构强制

模块头 `:91-95` 声明本账「**不递** `pack.death_certificate` 给 `CenterBook::consume_death_certificate`」。
但观测面 `pack()`（`:247`）返回整个 `ThirdPointPack`（含 `death_certificate`），任何 crate 内调用方都能
自行代劳通道 ②，本模块无守卫、无类型标记阻止。

「不递」的技术理由我独立复核**成立**：`consume_death_certificate(ladder, cert)`（`center_book.rs:403-407`）
按 `ladder` 消费（`MAX_LADDER = 11`，`types.rs:26`），而 `ThirdPointPack` 无 ladder；账本侧的级别在
`RetraceProvenance.level: u32`（`log.rs:86-88`，「该账本所属递归级别」），与 trading ladder 是两套引擎
坐标，仓内无对齐依据——与 #637 裁定 2A（`Tick` vs `f64` 跨量纲禁比，`center_book.rs:366-375` 在案）同族。
模块头 `:97-100` 也已如实登记「若后续票转投通道 ②，#664 盲区照旧适用」。故仅备忘，不要求改。

### LOW-5｜迟到测试的构造与 #587 迟到语义不同构，且两本账拼法非必要

`late_pack_is_registered_verbatim_regardless_of_confirmed_clock`（`:423-445`）用**两本独立账本**
（`fresh_ledger` / `late_ledger`，同 provenance）拼出「迟到」形态。两点如实登记：

1. 它钉的是「知情时先后」，而 #587 的迟到三类点（086:76 形态）是**相对走势位置**的迟到，两者不同构。
   本票按裁定一不造任何迟到判据，故无实害——但不宜把它读成「迟到场景已覆盖」。
2. 两本账非必要：倒退门是 **per-entry** 的（`book.rs:311` 取 `entry.last_as_of`），不同 `frame` →
   不同 anchor（`RetraceKey::anchor()` = `frame.start_index`，`mod.rs:201-203`）可并存，故单账本内跨身份
   `as_of` 递减在代码上无门禁。改用单账本 + `sync_from_ledger` 会顺带把 MEDIUM-5 的恒真断言变成实钉。

### LOW-8｜#587 原文适用域是迟到子集，用它给「全模块零信号」背书略越域

ADR-0001:273 逐字（我亲核）：「**迟到三类点**（086:76 形态）：不追……登记观测，不作独立信号消费。」

### 4. 登记语义正确性

**判定次序无反例**。`register`（`:184-196`）：① 在册 ∧ 全值相等 ⟹ `AlreadyRegistered` + `idempotent_repeats += 1`
（零写入）；② 在册 ∧ 不等 ⟹ `Err(ConflictingPack)`，`insert` 不执行 ⟹ 在册内容不被覆盖（测试 `:415` 钉住）；
③ 不在册 ⟹ `insert` + `registrations += 1`。三分支互斥穷尽，键取 `pack.identity` 且是唯一写入点 ⟹
模块头 `:146-147` 的两条不变量（`value.identity == key`、条数 == `registrations`）在方法层成立
（封装层瑕疵见 LOW-6）。比较用 `*seen == pack` 全字段 `PartialEq`（`book.rs:111` derive）⟹「同内容」
是逐字段相等，与 doc 一致。

`register_from_ledger`（`:233-236`）：`ledger.established_pack(key)` 已在账本侧过滤
（`book.rs:641-646`：`.filter(|e| e.state == Confirmed)`），非 Confirmed ⟹ `None` ⟹ `Ok(None)`。
「没有成立档不是事故」的语义正确，测试 `:516` 钉住。未决 / 判败 / 不存在三态我在
`provisional_and_failed_identities_never_reach_the_book`（`:484`）里确认覆盖了前两态。

`sync_from_ledger`（`:215-221`）：遍历 `ledger.established()`（按 `RetraceKey` 键序——`mod.rs:191`
derive `Ord`，`CenterFrame`（`:137`）亦 derive `Ord`，字典序 `zd,zg,start_index,end_index` 后接
`departure_move_index`），只把 `Registered` 者收进 `admitted`。**设计合理性**：登记账无回滚语义、
上游改口是事故——这个取舍我认可（回滚会让「在册事实」可撤回，与登记账名分矛盾）。**如实声明**：
doc `:204-206` 声明了「首个冲突即返回、已登记部分保留」，但漏了「`admitted` 清单丢弃」，且整条语义
零测试 ⟹ MEDIUM-2。复杂度声明（`:208-210`，O(条目数 × 调用次数)、非增量）如实且给了接入前的评估提示。

**观测面与「零判据」一致性**：`established`/`pack`/`contains`/`len`/`is_empty`（`:242-261`）全为直读
（`values().copied()` / `get().copied()` / `contains_key` / `len` / `is_empty`），无任何过滤、排序改写、
阈值比较；两个计数器只在 `register` 内 `+= 1`。**一致**——模块生产段 grep 无任何 `if` 涉及
`confirmed_as_of`/`registered_as_of`/价格字段。「零判据」声称成立。
