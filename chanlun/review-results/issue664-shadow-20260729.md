## 二、发现列表

### MEDIUM-1｜「先杀落位、后不覆写」纪律单侧成立，doc 断言失准（HIGH 风险面 / MEDIUM 定级：受 parity 约束、当前无生产驱动）

**证据**：
- `rust/src/trading/center_book.rs:156-177`：`ingest` 的 confirmed Type3 分支中，`dead.insert` / `dead_down` / `version` / `Terminated` 全在 `if !dead.contains(&cs)`（`:157`）守卫内，但 `if hard_type3 && ev.class.side() == Side::Buy { self.frozen[ladder] = Some(cs); }`（`:175-177`）在守卫**外**。
- `rust/src/trading/center_book.rs:416-428` doc：「死亡只发生一次，方向由**先杀通道**在死亡登记时落位」「`AlreadyBroken` 时若仍照 `cert.side` 写一遍……会把 `frozen` 从 `ingest` 从未置位的 `None` **静默翻成** `Some`——与本模块『同锚不同框 fail-loud』的改口纪律不对称」。

**失败场景**（可达，无测试覆盖）：cert 先以 `Sell` 杀锚 A（`dead_down[A]=true`，`frozen` 保持 `None`，`version+=1`，发 `Terminated{Down}`）→ 随后 `ingest` 收到同锚 A 的 confirmed `Buy3`（`hard_type3=true`）→ `dead` 已含 A，kill 块整块跳过，但 `:175-177` 无条件执行 ⟹ `frozen = Some(A)`，且 **`version` 不推进、不发第二次 `Terminated`**。这正是修复轮 S1/S2 判词所描述的危害（方向位静默翻转 + version 门控方感知不到），只是发生方向反了：由 `ingest` 通道对 cert 先杀的锚做。

**为什么本票该管**：#664 之前 cert 杀不写任何方向位，"谁先杀"无方向语义，该不对称无害；#664 让 cert 成为一等方向落位通道后，`ingest` 守卫外的 `frozen` 写就变成对称缺口。修复轮把「不覆写」写成了模块级纪律断言，而该纪律实际只在一个方向成立。

**建议处置**：`ingest` 的 `frozen` 置位是 Python parity 逐字对应（`center_book.rs:137` doc 内的 Python 片段 `if hard_type3 and side == "buy": frozen[lad] = cs` 同样在 not-in 守卫外），**不建议改代码**。改 doc：把绝对断言降为「cert 侧不覆写；`ingest` 侧的 `frozen` 置位按 Python parity 在 `dead` 守卫外，故 cert 先杀后到达的 `ingest` confirmed Buy3 仍会改写 `frozen`（不推 `version`、不发事件）——如实声明，检测/收口归后续票」。

### 3. 方向语义正确性（四种时序逐路径演算）
