## 一、交付 2：塔顶键结构性不可满足 6.85% 修复（装配缺陷）

### 成因（#740 拆账 / #797 实测，本报告只承接不重推）

`missing_cert` 三窗合池 n=7294 中 ④ 结构性不可满足 = 500（6.85%），三窗全部 500 格
`level == chain.top` 比例 = 100%——④ 恒发生在链顶那一级。机制：`sync_events` 只派生
`for level in 1..n_levels`（事件键级 1..n_levels-1，账本级 0..n_levels-2），而链查询
`chain_lookup` 对账本级 `book` 要 `event_level = book+1`（T1 移位 `event_bsp_book_level(ℓ)=ℓ-1`），
链顶 `book = n_levels-1` 要 `event_level = n_levels` ⟹ 塔顶键 `(n_levels, 极值价, 组锚)`
永不被生产（结构性恒不可满足，确证实现缺陷）。

### 修复（窄，不碰产出缺口 / 谓词有偏 / 锚解析）

| file:line | 改动 | 说明 |
|---|---|---|
| `rust/src/theta_v0/backtest/admission.rs:691-698` | `events_by_level`/`derived` 槽数 = `n_levels + 1` | 塔顶事件（键级 n_levels）存槽 n_levels |
| `admission.rs:699` | 派生循环 `1..n_levels` → `1..=n_levels` | 新增塔顶级别（level == n_levels）派生 |
| `admission.rs:700-712` | 塔顶分支：windows 与 legs 同取 `tower[n_levels-1]` | 无上级塔层可投影 ⟹ 塔顶拐点背驰由塔顶层自身趋势判定（与 bsp 一类点 `extract_first_third_for_level` 同源——趋势级别=本级，段=本级走势单元） |
| `admission.rs:756-758` | `windows = &tower[level.min(tower.len() - 1)]` | 塔顶级别 windows 退化为塔顶层自身（常规级别不变） |

**语义锚**：塔顶级别事件的拐点落在账本级 `n_levels-1`（`event_bsp_book_level(n_levels)=n_levels-1`），
与 bsp 一类点（`extract_first_third_for_level`，段=本级走势单元）同源。事件被 `absorb_exts`
按 `(n_levels, 极值价, 组锚)` 登记进 `by_triple_anchor`，`build_nest_certificate_index` 的
`exec` 循环 `1..events_by_level.len()` 自然覆盖塔顶槽（单级证书，`extend_typed_upward` 因
`level > top_level` 立即返回 ⟹ rungs 空 ⟹ `n_delta() = terminal.confirm_side`）。链查询对
链顶 `book=n_levels-1` 现在能查到塔顶证书 ⟹ 塔顶键结构性可满足。

**级别退化边界（照实）**：`n_levels == 1`（塔顶 = L0）时，塔顶派生对 L0 线段做投影
`project_extended_windows_carried_only` 恒失败（L0 线段 `sub_moves` 空 / `RMove::Segment`
无携带核）⟹ 优雅产 0 事件（不 panic）⟹ L0 塔顶键仍不可满足。此为「nest 不听 L0」（p105 §3）
的设计边界，非本修复范围（#797 的 L0 ④ 三窗合计 13/500 = 2.6%，且当时塔层数尚未长起来）。

### seam（/tdd 先定）

`NestChainGate::sync_events` → `derive_level_events`（塔顶级别派生：windows 与 legs 同取塔顶层）。

bullet 一次红→绿——单测试覆盖两断言。
