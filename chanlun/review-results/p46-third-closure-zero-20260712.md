## 0. 总结论

**最终归因：混合，以 `IMPLEMENTATION-BUG（证书生命周期/施用时机） + TIMING-FACT` 为主，伴随 `DEFINITION-TENSION`。不是高级别坐标系或级别对象错配。**

1. **IMPLEMENTATION-BUG（主机制）**：完整 `c_p` 是按 `B_p`/离开单元识别的持续结构对象，但闭合只在某个 `CandDeltaEvent` 发射时调用 `cp_event_objects`，扫描上界固定为该事件的 `event_end`，并把 `c_end_full` 固定写成该事件端点。旧事件此后不会随同一 `B_p` 的第三类完成而重新闭合。L0 冒烟的两例闭合都属于同一个 `B=L1#73`：第三类回试完成后恰好又发射了两个事件，才偶然得到 `Some`；L1–L4 的 31 个事件对应 31 个互异 `B_p`，没有后续事件替它们重新执行闭合。
2. **TIMING-FACT**：确认时 31/31 无合法第三类；其中 21 例连一对属于 `B_p` 的离开/回试相邻单元都尚未齐备，8 例已有相邻对但 leave 没有合法趋势 ownership 锚，1 例回试重入 `B_p`，1 例方向对不成立。到数据终点，同一生产判据下 **11/31（35.48%）** 已出现合法第三类；其余 **20/31（64.52%）** 仍没有。
3. **DEFINITION-TENSION（只登记，不裁决）**：第 37 课把“`c` 至少包含对 `B` 的第三类”作为趋势 `a+A+b+B+c` 的资格条件，并说否则可看作 `B` 的小级别波动、按盘整背驰处理；当前 `CandDeltaEvent.cand_delta=true` 却能在第三类尚未形成、乃至终点永远不存在时被确认为“趋势背驰段谓词”。这暴露的是“算法背驰候选确认”与“原文完整趋势 `c` 资格完成”两种时点/对象的张力，本报告不选择定义口径。

★ Insight ─────────────────────────────────────

- P45 的“2 例闭合”不是 2 个独立完整 `c_p` 样本，而是同一 `B_p/c_p` 在第三类完成后被两个后续事件重复观察；它不能证明每个事件在自身确认时都具备完整证书。
- L1+ 的判据并非不可用：终点回看在 L1/L2/L3/L4 都找到合法第三类，直接否定“高级别 ID/坐标整体错位”。真正的级别相关性来自事件稀疏度和证书只在事件发射时求值。
- `anchor=None` 的 8 例不是本轮新 bug；686 号已结算裁定明确禁止 Consolidation/endpoint fallback 方向充当一/三类方向锚。

### 1.2 判据原子

统计镜像不另造第三类定义，只展开 `judge_third_cert` 的现有条件：

1. leave/retest 是相邻同级递归单元；
2. leave 属于 `c_start_full` 之后，且 `nearest_confirmed_center_idx(leave.start)=B_p`；
3. leave 有 `anchor_direction=Some(dir)`；
4. leave/retest 方向相反；
5. leave 端点严格离开 `B_p` 核心；
6. retest 端点严格不重入/触及 `B_p` 闭区间。

下表“确认摘要”使用 `pairs; A/D/L/R`：`pairs` 是确认时属于 `B_p` 的相邻对数量；`A`=anchor None，`D`=方向不配对，`L`=leave 未严格离开，`R`=retest 重入/触及。最小失败原子按离成功最近的已到达门记录。

## 3. 实现层归因

### 3.1 已排除

1. **不是 `cp_ownership` 侧车在 L1+ 缺失**：31/31 均有 `B_p`、`c_structure.source_start` 和 departure ID/区间。
2. **不是递归 ID 级别错位**：每个 Lℓ 事件的 departure/leave/retest 都是 Lℓ ID，`B_p` 是 L(ℓ+1) ID；11 个高级别终点成功样本通过同一 span/ownership 条件。
3. **不是 source 坐标混用**：成功样本在 L1–L4 全部出现，且诊断镜像对 483 个终态事件与生产 `third_class_in_c` 0 mismatch。
4. **不是 `judge_third_cert` 只在 L0 调用**：`level_cand_delta` 每级都调用 `cp_event_objects`；L1+ 回看能命中同一判据。
5. **不是把 anchor None 简单回填方向即可修复**：686 号已结算裁定禁止 endpoint fallback 充当趋势方向锚；8 个确认时 anchor 失败必须保持失败，除非另有新定义裁决。

### 3.2 坐实的生命周期 bug

调用链的关键事实：

```text
cand_delta_tower_with_series (每级)
  -> level_cand_delta (每个候选 seg 产 CandDeltaEvent)
     -> cp_event_objects(... event_seg_idx=i, event_end=seg.end_index ...)
        -> 只扫描 1..=event_seg_idx
        -> c_end_full = is_complete_divergence && third_inside_span ? event_end : None
```

因此完整 `c_p` 的闭合时机被绑在“又有一个 `CandDeltaEvent` 发射”上，而不是绑在扫描侧车所代表的 `B_p -> c_p` 对象状态上。终态重算虽能看到后续单元，但对历史事件仍使用原来的 `event_seg_idx/event_end`，不会将后来出现的第三类合入旧事件。

#### 最小复现 A：P45 100k 的“成功”机制

同一 `B=L1#73`：

```text
event confirm=42704: c_end_full=None
later third: leave=L0#327 [42503,42704], retest=L0#328 [42704,42759]
event confirm=42841: c_end_full=42841
event confirm=42998: c_end_full=42998
```

第三类在 42759 完成；后两个事件因发生在其后而能扫描到同一 third。所谓 2 例闭合是同一 `B_p` 的后续事件重复触发，不是两个 `B_p` 独立闭合。

#### 最小复现 B：L1 无后续事件时永不回填

```text
B=L2#1508 [3303342,3305431]
event confirm=3306324, c_start=L1#6703 [3305536,3306324], c_end_full=None
later retest=L1#6704 [3306330,3306426]  -> 同一 B 下合法第三类（+102 bar）
data endpoint: 历史 event 仍 c_end_full=None
```

这是一条最小高级别反例：级别、ID、坐标和判据都能成功；唯一缺失的是第三类完成时没有新的 `CandDeltaEvent` 去重算/承载证书。

### 3.3 建议修法（不实施）

不改 `judge_third_cert`、不放宽闭合条件、也不回填历史 `None`；建议只修对象生命周期：

1. 将 `CpScanOwnership` 扩为按 `B_p/c_p` 持续推进的 pending/closed 结构状态，随着每个新同级递归单元更新；第三类完成时由对象状态闭合，而不是等待另一个背驰事件。
2. 分开保存两个不可互换的时点：`divergence_confirm_src`（现 `confirm_src`）与 `cp_certificate_confirm_src`（第三类/完整结构首次可证时点）。确认时快照仍可保持 `None`，终态对象另有版本化闭合证据；不得前视改写历史可用性。
3. `CandDeltaEvent -> c_p` 只保存稳定归属边；消费者明确选择“确认时快照证书”或“终态/事后完整证书”。不要以随后某个事件的 `seg.end` 充当旧 `c_p` 的右端。
4. 修复前的回归测试应锁定上面两条最小复现：同一 `B_p` 有/无后续事件时，最终 `c_p` 对象闭合结果必须一致；确认时快照则仍按因果窗口区分。

## 4. 时序层结论

**TIMING-FACT 成立，但不是全部解释。**

- 31 个事件在 `confirm_src` 的零闭合是结构性事实，不是报告遗漏：21 个尚无完整 leave/retest 对，另 10 个已有对但不满足 anchor/方向/回试门。
- 11 个事件只能在确认之后回看成立，占 35.48%；它们证明“背驰算法确认”早于“完整 `c_p` 资格证书可判”在当前对象图中真实存在。
- 20 个事件到终点仍不成立，不能用时序解释，也不能回填；它们进入定义张力而不是实现层自动修补。
- 回看统计是事后归因，不授权将未来 third 注入 `confirm_src` 时的因果证书。

## 5. 定义层张力（登记，不裁决）

一级权威第 37 课正文给出三条连续限定：

> “c 至少包含对 B 的一个第三类买卖点，否则，就可以看成是 B 中枢的小级别波动，完全可以用盘整背驰来处理。”

随后又要求上涨 `c` 创新高/下跌 `c` 创新低，并说明对 `c` 内部递归分析时，由于 `c` 包含第三类，`c` 至少包含两个次级别中枢。出处：`docs/chanlun/text/blog/037-第37课.md` 第 18、20、22 行。

与当前对象图的张力：

| 轴 | 当前实现 | 第 37 课资格条件 | 本轮数据 |
|---|---|---|---|
| 确认时点 | `judge_first_cached` 的背驰事件端点即 `cand_delta=true` | 完整趋势 `c` 至少已含对 `B` 的第三类 | 31/31 在事件确认时不含 third |
| 最终资格 | 历史事件不因后续 third 自动重开/闭合 | 缺 third 的 `c` 可视为 `B` 小级别波动 | 20/31 到数据终点仍缺 third |
| 分类命名 | `CandDeltaEvent` 文档称“趋势背驰段谓词” | 缺 third 时应与盘整背驰/中枢波动区分 | `cand_delta=true` 与完整趋势资格不等价 |

候选口径（全部待后续定义裁决，本报告不选）：

1. **严格资格口径**：`cand_delta=true` 仅命名为“算法背驰候选”；只有完整 third/certificate 后才升级为“趋势 `c` 背驰”。
2. **双时点口径**：保留早期 `divergence_confirm_src`，另设 `cp_certificate_confirm_src`；前者可用于因果信号，后者才承载第 37 课完整 `c` 资格。
3. **分类分流口径**：终点仍无 third 的事件进入“围绕 B 的小级别波动/盘整背驰候选”复核，但必须由独立盘整背驰证书决定，禁止仅凭 `third=None` 自动降类。
4. **完成态限定口径**：第 37 课“c 必然含 third”只施加于已完成趋势分解；当前事件是生成态，不应提前声明完整 `c_p`。这要求代码和报告显式区分生成态/完成态。

## 6. 分级最终判定

| 范围 | 判定 | 证据 | 后续边界 |
|---|---|---|---|
| `judge_third_cert` 几何/级别输入 | **非 bug** | L1–L4 均有终点成功；ID/坐标/ownership 对齐；全量镜像 0 mismatch | 不改判据，不给 anchor None 回填方向 |
| `c_p` 闭合生命周期 | **IMPLEMENTATION-BUG** | 闭合只在事件发射时求值；P45 两例共享 B；L1 最小复现后来合法但历史事件永远 None | 建议 per-`B_p/c_p` 持续状态 + 双时点，不实施 |
| 确认时 0/31 | **TIMING-FACT** | 21 无 pair + 8 anchor None + 1 retest 重入 + 1 方向错 | 保持确认时 `None`，不得前视回填 |
| 终点 11/31 | **TIMING-FACT** | L1/L2/L3/L4=`1/6/3/1`；延迟 102..103,750 bar | 只作事后能力/归因统计 |
| 终点仍无 third 的 20/31 | **DEFINITION-TENSION** | 第 37 课缺 third 应视为 B 波动；当前仍是 `cand_delta=true` | 登记候选口径，另行裁决 |

因此，P43 的“L1–L4 完整证书=0”不能再解释为“市场上没有高级别第三类”，也不能解释为“高级别判据整体失效”。精确结论是：**事件确认时确实 0/31；现实现又把完整对象闭合绑在事件发射时点，遗漏了 11 个确认后可闭合的 `B_p/c_p`；剩余 20 个暴露原文完整趋势资格与当前候选命名之间的定义张力。**
