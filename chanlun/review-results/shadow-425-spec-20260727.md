## 3. 分级发现

### MED-1｜AC2 字面覆盖的「不可验」子集被以教义理由排除

规格原文：「结构完成时，**从未写入首次可证时点的活假设**转入终态并挂新原因码」——**无例外条款**。

实测：`ForceCheck::Unavailable` 时第 6 步 `722` 行 `continue`，第 7 步整体不到达 ⟹ 该身份既不写 `structure_end_at` 也不转终态，**继续以活假设身份挂账**；且因非终态，桥迁移照旧延展（第 1 步 `623` 只吸收终态）⟹ 本票要消灭的「永久挂账」在该子集原样保留。

复核实装工位「不改行为」的判断：**方向对、覆盖面不对**。不从缺失数据造否证确与 #78 / 090 一致，我不主张改判负；但它落在 AC2 字面内，例外是实装侧自划、票体未授权，且只登记为 #426 的「观测面」而非验收项。#409 实测 0.00% 只说明当前不发生，不构成规格豁免。

**建议**：#426 挂一条显式验收项——「完成信号已到但力度不可验」的终局归属（补第四原因码 / 显式挂起桶 / 明确接受永久滞留，三选一并留档），不要只作观测。

### LOW-1｜`assert_invariants` release 下不自动执行，「钉死」措辞偏强

新增断言用真 `assert!`/`assert_eq!`（非 `debug_assert!`），且 `assert_invariants` 是 `pub fn` ⟹ 显式调用时 release 照跑，**不属「护栏被 cfg 关掉」那一类**。但 `advance` 末尾的自动核验是 `#[cfg(debug_assertions)]`（`786-787`，既有形态、本次未动），release 运行期无自动检查。commit message「invariant 钉死两码在 first_provable 上严格互补」读来像运行期护栏，实为测试期性质核验。建议 #426 接线时在 release 冒烟路径显式调一次，或措辞降为「测试期钉死」。

### LOW-2｜词汇表与代码判据两个口径，本次只在模块头免责

模块头 `45-47` 明确登记：「本模块的『从未构成』判据是**力度谓词从未可证**，不是逐字的『未创新高』——创新高预滤由产窗侧 `pan_div_structure_extreme` 承担」。该免责**属实且可核**：预滤确在 `948/956` 行的 `provide_pan_live_windows` 内 ⟹ commit message 声称的「已补工程口径免责」核实为真，必查项 3 的滑移已被诚实登记。
