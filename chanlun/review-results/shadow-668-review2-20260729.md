## 二、新增发现

### R2-HIGH-1 [裁定③ E2E-O] 同输入重跑非零 Delta：多物理点 episode 下幂等协议破，revision 无上界增长

**机制。** `resolve_first_class_episode_edges`（:412-461）对一个 episode 覆盖的 k 个物理一类点
产出 **k 条观察，全部共享同一 `BridgeKey`**（:452），按 `source_index` 升序 push。`apply`（:556）
用「prior 链头 vs 本次观察」二元比较判幂等，而 `bsp_source_index` 在 `BridgeProjection` 里（:174）：

- 第 1 次 `advance`：p₁ 落 rev0 → p₂ 与 prior(p₁) 投影不等 → rev1 → … → rev(k-1)，链头 = pₖ。
- 第 2 次 `advance`（**输入与 as_of 完全相同**）：观察序仍 p₁…pₖ，但 prior 已是 pₖ ⟹ p₁ 与 pₖ
  投影不等 → **append rev(k)**；p₂ 与 prior(p₁) 不等 → append …⟹ 每次重跑无条件追加 **k** 条。

k 个同时并存的物理点被当成 k 次时间序修订，而它们并不随 as_of 变化 ⟹ 循环永不收敛。

**实查（复核探针，生产 `advance`，真实 BTC 300k）。**

```
PROBE670B_IDEMPOTENCE bars=300000 as_of=299999 multi_point_episodes=5 covered_first_class_total=29
                      delta1=29 edges1=29 heads1=22 delta2=12 edges2=41 delta3=12 edges3=53 max_revision=11
```

- `delta2 = delta3 = 12 ≠ 0`：**同一 `(classification, streams, as_of)` 重跑，每次追加 12 条**。
  12 = Σ(多点 episode 的 k) = 5 个 episode × 各自 k，其中 (29 − 22) = 7 个非链头点 + 5 个链头点。
- 边数 29 → 41 → 53 线性增长，`max_revision` 0→11；调用 n 次即 29 + 12(n−1) 条边。
- 100k 窗 `multi_point_episodes=0` ⟹ `delta2=0` 幂等成立——**这就是报告三窗读数没能发现它的原因**：
  三个 bin 都只调用 `advance` 一次，且只有 300k 窗存在多点 episode。

合成夹具（同 `tests.rs` 两点 episode 构造）：

```
PROBE670B_SYNTH_CHURN same_as_of d1=2 d2=2 d3=2 d4=2 edges=8 heads=1 max_rev=7
```

**为何是 HIGH。** 裁定③ 明文「append-only + E2E-O 修订协议全套沿用」，模块头（:49-50）与
ADR「对象骨架（append-only、终态不复活、**幂等**、零消费接线）不动」把它当已成立的交付物；
`same_as_of_rerun_is_zero_delta` 单测只覆盖单点 episode，故全绿。**可达性照实**：本票零消费接线，
今日 `advance` 的调用点只有单测与验收 bin 且各只调一次 ⟹ 当前无外部影响；但这是裁定③ 的明文
验收项被实测证伪，且对象的去向（N7 消费并轨、增量路径）正是要反复 `advance` 的地方。

### R2-HIGH-2 [裁定④ / 裁定⑦ / #535③] 端死时终态只落遍历序首个物理点：链头回退、其余点失效不留痕、查询入口静默丢点

**机制。** `apply` 的终态挡（:558）是「prior 链头已终态 ⟹ return」。多物理点 episode 下失效那一步：
观察 p₁ 时 prior = pₖ（`Open`）⟹ 追加一条 `Invalidated` revision，**载荷是 p₁**；轮到 p₂…pₖ 时
prior 已终态 ⟹ 全部 `return None`。于是：

1. 链头 `bsp_source_index` 从 pₖ **回退到 p₁**——与 `tests.rs:274` 断言的「链头 = 最新物理点
   （pivot 是修订载荷）」在失效后正好相反，且模块头/CONTEXT.md 均声称「`heads()` 只见链头
   （最新物理点）」；
2. p₂…pₖ 这些物理点**永远没有 `Invalidated` 记录**——裁定④「任一端 Invalidated ⟹ 边判死、留痕」
   对它们失效（#535③「丢失 Invalidated 路径」禁令面）；
3. 裁定⑦ 的查询入口 `edges_for_bsp_point`（:533）过滤 `heads()` ⟹ 非链头物理点**查不到任何边**。

**实查。**

```
PROBE670B_SYNTH_TERMINAL head_si_before_invalidation=55 invalidation_delta=1
                         head_si_after_invalidation=40 edges_with_invalidated_state=[40]
                         total_edges=3 edges_for_point_40=1 edges_for_point_55=0
```

失效前点 55 可查（1 条边），失效后**变 0 条**——查询入口在事件失效时静默丢掉这个物理点。

```
PROBE670B_QUERY_ENTRY bars=300000 distinct_points_with_edges=29 query_reachable=22 query_lost=7
```

真实 300k 窗：29 个物理一类点在 `edges()` 里有边，但 `edges_for_bsp_point` 只查得到 **22** 个，
**7 个（24%）静默查无**——且这与失效无关，第一次 `advance` 后 `heads1=22` 就已如此。
验收 bin 之所以 cmp=0，正是因为它按修复轮的处置从 `heads()` 换成了 `edges()`；裁定⑦ 点名的
**查询入口本身**没有被任何验收物覆盖（唯一覆盖它的单测 `edges_for_bsp_point_finds_by_level_and_
source_index` 是单点 episode）。

### R2-HIGH-3 [裁定② / HIGH-1 验收门] 「episode 归属唯一」零机器保证；真值表检验域 20k=0、二类 0/280

**机器保证缺位。** 模块头（:18-20）、ADR 第三轮裁定 1、CONTEXT.md 新词条、真值表 bin 头注（:16）
四处口径一致地声称「`find_episode` 的 `debug_assert` 机器化此不变量」。实查 `find_episode` 全仓
**唯一**调用点 = `:381`（二类分支）：

- 一类路径（`resolve_first_class_episode_edges`）是**反向遍历**（episode → 点），根本不经
  `find_episode`，**无任何 assert**。若某个一类点被两个 episode 区间同时覆盖，它会安静地产出
  两条不同 `BridgeKey` 的边，没有任何机器信号；
- 二类分支在 BTC 生产数据上 **0/88、0/280** 全不可解（R2-MED-2）⟹ 该 `debug_assert` 的实际输入域
  为空。

即：唯一有真实数据的点类（一类）上零机器保证；有机器保证的点类（二类）上零数据。

**验收读数的检验域。** 三窗读数复现无误，但把它拆开看：

| 窗口 | bit_instances | 三类跳过 | 二类 `fingerprint_unresolved` | **真正进检验域** | `episode_owned_many` |
|---|---|---|---|---|---|
| 20,000 | 54 | 37 | 17（17/17，100%） | **0** | 0（空域） |
| 100,000 | 348 | 257 | 88（88/88，100%） | **3**（全一类） | 0 |
| 300,000 | 1199 | 890 | 280（280/280，100%） | **29**（全一类） | 0 |

- 报告 §一「三窗 `episode_owned_many=0`（覆盖一类/二类）」——**「覆盖二类」不实**，二类
  100% 被排除；
- 20k 窗检验域 = **0 个实例**，`exit=0`（SUCCESS）是空域重言式。这与前判 HIGH-3 点名的
  「20k 空对空」是同一个毛病，只是从对拍搬到了真值表；
- 前判 HIGH-1 的核心指控是「通过是检验域窄化的产物」。检验域从「11/29 有键的一类点」扩到
  「29/29 一类点」确是真实扩大 ✓，但同一份报告同时把二类从「进检验域」缩到「100% 排除」，
  且新增一个 0 实例的窗口报 PASS。

### R2-HIGH-4 [裁定⑥ 替代验收物①] 跨 as_of 平价锁是重言式，且实测跑穿两条新 HIGH 仍全绿

**重言式。** `bridge_book_incremental_equals_full_replay_across_as_of`（tests.rs:387）里
`inputs` 是一个**固定列表**；`incremental` 依次吃 `inputs[0..n]`，`replay` 从空簿吃 `inputs[..step]`
—— 同一确定性函数、同一输入序列 ⟹ `f(x₁..x_k) == f(x₁..x_k)` 恒真，**结构上不可能失败**。
它不是「两个驱动的平价」，只是同一驱动跑两遍。

**先例形态对照。**

| 先例 | 两侧是什么 | 能否失败 | 非真空锁 |
|---|---|---|---|
| N1 `candidate_event_stream_per_segment_full_replay_equals_incremental`（mod.rs:4567） | 增量 `TowerCache` vs **fresh cache** 重放——两个**不同驱动** | ✓ 能 | `identities` 非空 |
| N3 `chain_certificate_book_incremental_equals_full_replay`（mod.rs:4765） | 同一 `inputs` 列表两遍（**同 N4，同样重言**） | ✗ 不能 | `certificates>0`、`distinct_as_of>1`、`with_edges>0` **三条** |
| N4 本轮 | 同一 `inputs` 列表两遍 | ✗ 不能 | **零条** |

即：形态确实「对齐 N3」，但对齐的是 N3 最弱的一面，且连 N3 的三条补偿性非真空锁都没抄。

**它实际容忍了什么**（复核探针逐字复刻该测试的 4 步输入，跑生产 `advance`）：

```
PROBE670B_PARITY_TRACE step=1 as_of=40 delta=1 edges=1 heads=1 max_rev=0 head_si=40 b1_head_status=Open
PROBE670B_PARITY_TRACE step=2 as_of=55 delta=1 edges=2 heads=1 max_rev=1 head_si=55 b1_head_status=Open
PROBE670B_PARITY_TRACE step=3 as_of=80 delta=3 edges=5 heads=2 max_rev=3 head_si=55 b1_head_status=Open
PROBE670B_PARITY_TRACE step=4 as_of=90 delta=2 edges=7 heads=2 max_rev=4 head_si=40 b1_head_status=Invalidated
```

- step=3 只新增了一个二类点，`delta` 却是 **3**——多出的 2 条正是 R2-HIGH-1 的 churn（p40/p55
  被重新 append 成 rev2/rev3）；
- step=4 一类链头 `head_si` 从 **55 回退到 40**，正是 R2-HIGH-2。

两条新 HIGH 都在这条「验收物」的夹具里当场发生，而测试因两侧同构而全绿。作为裁定⑥ 的替代
验收门①，它关不住任何门。

### R2-MED-1 [MED-1 残余] 三类仍用右端等值：orphan 路径原样保留，且头注的安全性论证不成立

修复轮把一类/二类的 join 换成 episode 覆盖，**三类未换**（`:367` 仍 `trend_index.get(&(…,
entry.leave_interval.1))`）。`trend_index_by_interval_end` 头注（:211-216）的免责论证是：
「离开段右端是三类点自身**已闭合**的历史坐标，不随本 episode 后续生长而漂移」。

该论证混淆了匹配的两侧：等值匹配要求 `entry.leave_interval.1`（点侧，确实闭合）
`== event.interval.1`（**事件侧当前右端，恰恰是会生长的那个**）。一旦该 Trend 候选的区间生长过
`leave_interval.1`，索引里就再没有这个键 ⟹ 观察消失 ⟹ 边停 `Open`、事件后续失效不同步——
**与第 1 轮 MED-1 点名的 orphan 路径逐字同型**。修复报告 §四称「HIGH-1/HIGH-2 的 episode 覆盖
判据修复直接消解此问题的根因」——对一类/二类成立，**对三类不成立**，且无任何测试覆盖三类的
生长-失效序列（`third_class_point_pairs_with_leave_segment_trend_event` 只有单步）。

照实：三类在生产数据上 0/890 命中（§四），故该路径当前不可观测，同第 1 轮 MED-1 的「结构可达 /
未实测」定性。

### R2-MED-2 [接线] 二类桥接路径在生产数据上结构性不可解（0/280），「修复覆盖二类」不实

`resolve_second_class_anchor`（:315-345）要求：本点携 `OwnerRef::Type1Anchor(anchor_idx)`

## 六、处置建议（不动手修，交编排者裁）

1. **回炉重点从「键公式」移到「同 episode 多物理点的载体形态」（R2-HIGH-1/R2-HIGH-2 同根）**。
   第三轮 supersede ① 授权的语义（多物理点 = 同一身份的修订史）与 E2E-O 修订协议的**前提**冲突：
   修订协议假定同一 key 在任一 as_of 只有**一个**当前载荷（prior vs next 二元比较），而这里 k 个
   物理点是**同时并存**的。可选面（不预判，请编排者裁）：
   (a) 载荷升为集合——`bsp_source_index: usize` 换成有序集合 / 「链头 + 已覆盖点集」，一个 as_of
       一条 revision，幂等与终态自然恢复，`edges_for_bsp_point` 也能查全；
   (b) 保留一点一边——把 `source_index` 收回身份分量（即撤销 supersede ①），撞键回到台面另裁；
   (c) 维持现状但明确「同 as_of 内 k 条 revision 是规格」——那就必须同时改 `apply` 的幂等判据
       （改为「本次观察集合 vs 簿内已有集合」比较）与终态挡（终态需覆盖全部物理点）。
   无论选哪条，须补：多点 episode 的**重复 advance 零 Delta** 单测 + 多点 episode **失效后每个
   物理点都留痕且可查**单测。
2. **裁定②验收门第三次重定（R2-HIGH-3）**：
   (a) `debug_assert` 挪到/补到一类路径上（`resolve_first_class_episode_edges` 里对每个覆盖点核
       「它只被一个 episode 覆盖」），否则「机器化」四处文书断言须全部撤；
