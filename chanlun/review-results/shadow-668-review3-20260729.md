## 二、新增发现（5 条：MED 2 / LOW 3，无 HIGH）

### R3-MED-1 [文书正本] `CONTEXT.md` 两个词条冻结在修复轮 1——其中一句把 R2-HIGH-2 已修掉的破行为写成设计

`git log 1b7ba1a1a5..HEAD -- CONTEXT.md` → 最后触碰 = `a7e0415c5e`（修复轮 1 期）。修复轮 2 与
轮 3 的 4 个 commit（`efbf6405fe`/`1a82746ed0`/`fd83ce6431`/`7a18c7a3b2`）**没有一个碰过
`CONTEXT.md`**。于是「事件↔BSP 桥接边」与「BSP 结构身份键 v2」两个词条里有四处陈述与现行实现不符：

1. **最重的一处**——「`heads()` 只见链头（最新物理点），历史物理点见 `edges()`（append-only 全量）」。
   这**正是** R2-HIGH-2 的破行为本身（非链头物理点从 `heads()` 过滤后的查询入口静默消失，300k 窗
   7/29 查无）。第四轮 supersede 裁定 3 已把语义改成「`heads()` 携完整覆盖点集，
   `edges_for_bsp_point` 按集合成员判断」，查询完备性回到 29/29。词条现在把已被判为缺陷、并已修掉
   的行为登记为设计。
2. 「同 episode 多物理一类点……折叠为**同一身份的修订链**」——现行语义是「折叠为**一条** revision
   携有序点集」，不是每点一条的修订链（这个「链」形态就是 R2-HIGH-1 幂等破的根因）。
3. 「二/三类走点侧驱动……（三类=离开段候选，**判据未改**）」——第四轮 supersede 裁定 2 明文
   「撤销第三轮裁定 2『三类判据未改』的例外」，三类已迁移 episode 区间覆盖。
4. 「`find_episode` 的 `debug_assert` 机器化此不变量，**BTC 三窗实测零违反**」——20k 窗检验域为空
   （本报告 §一 1d：该窗 `episodes=0 b1_bits=0`）。「三窗实测」是 R3 专门引入 `exit=2` 要消除的
   那种表述，如今只剩在正本词条里。

`CONTEXT.md` 是全 harness 词条正本（下游 agent 的语义入口），且本票前三轮 FAIL 主因正是名实不符
——按 R2-LOW-1 已确立的 append-only 纪律（订正要落在原处，不能靠读者读到最后自己发现），这四处
应加删除线/订正段。**照实**：纯文书，零功能影响，`bsp_bridge.rs` 模块头本身已全部更新到第五轮。

### R3-MED-2 [验收物] 对拍 bin 参照集的三类判据未随生产迁移，头注声明与事实相反

- 生产（第四轮 supersede 后）：`bsp_bridge.rs:419` 三类走 `find_episode(...entry.leave_interval.1)`
  = **episode 区间覆盖**。
- 对拍参照集：`p_issue668_bsp_bridge_battery.rs:184` 三类走 `trend_by_exact_end.get(...)`
  = **右端精确等值**（第四轮 supersede 之前的老判据）。
- 该 bin 头注 `:127` 明写「三类 = `leave_interval.1` 精确等值（v2 三类锚**本轮未改**，评审 #670
  已验不空洞）」——`本轮未改` 这句在修复轮 2 之后已成事实错误。

即：号称「真独立参照集」的这一侧，对三类实现的是与生产**不同的判据**，而不是同一判据的独立实现。
「独立」的本意是代码路径不共享、判据共享；这里判据也分道了。

**当前影响 = 零**（独立探针三窗实测：`production_cover_hit=0`、`reference_exact_end_hit=0`、
`cover_only=0`、`exact_only=0`——三类两侧同为空集，两个判据都不命中任何点，故 `cmp=0` 成立）。
**风险**：一旦三类覆盖被打开（这正是 #688 的目标），生产按覆盖命中而参照按等值不命中 ⟹ 该门会报
`extra_in_bridge`（伪红），而不是验证；反向偏差同理漏验。

### R3-LOW-1 [文书] 对拍 bin `:188` 仍以正面事实携已撤回的「HIGH-2 修复覆盖二类」

### R3-LOW-3 [论证域] 「机器保证」只在 debug profile 生效，release 下 `find_episode` 静默取首个

`find_episode:318` 是 `debug_assert!`——release 编译为空操作。而三窗验收 bin **全部在 release 跑**。
若 episode 归属在新数据上不再唯一，库内路径会**静默取遍历序首个** episode（`episodes` 由 BTreeMap
折叠而来，序确定但语义任意），比旧实现（产两条边、至少在 `edges()` 里留痕）**更安静**。唯一 release
可见的探测是真值表 bin 的 `episode_owned_many`（独立实现的计数，**不在库内路径上**）。

模块头 `:36-42`、ADR 第三轮裁定 1、第五轮 Consequences、`CONTEXT.md` 四处均写「`debug_assert`
机器化此不变量」而未写明生效域。当前生产数据 `owned_many=0`（本报告独立复现），故无实际影响；
建议把生效域写明，或按 dispatch「若仍有撞键停手上报」的精神在库内改真 assert / 上报路径（**是否
改属编排者裁定，本报告不给方案**）。
