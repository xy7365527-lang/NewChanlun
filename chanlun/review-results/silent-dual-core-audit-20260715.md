# 静默双核审计：#148 重切子窗的继承核 vs 生产投影核（task #89）

日期：2026-07-15 ｜ 探针：`rust/src/bin/p89_dual_core_audit.rs`（只读，exit 0）｜ 数据：btc_1m_full（4,613,599 bars，merged 3,037,868）

## TL;DR

- 全塔 11,897 个上级窗中，**重切子窗 4,589 个**（38.6%，父窗 1,205 个），完整拆分为恒等式：
  **4589 = 1205（首子窗，核恒相等） + 215（InvalidSeed，#88 集合） + 3169（静默双核）**。
- **静默双核 = 3,169 窗**：offset-0 投影成功、econ 层拿到合法 seed 核，但 [ZD,ZG] ≠ 塔继承核（父 seed 三段交）。占重切子窗 69.1%，占全塔可投影窗（11,682）的 27.1%。
- **零反例 ×2**：`mismatch_normal=0`（普通窗投影核与塔核逐窗相等——双核严格 ⊆ 重切子窗）；`invalid_normal=0`（215 个 InvalidSeed 全为重切子窗，#88 结论复证）。
- **下游已实际分叉**：econ 层（projection seed 核 → `decompose`）与塔层（携带核 → `decompose`）的走势块在 166/209 个 run 上不一致（79.4%），方向不同的块 676 个；292 个双核窗落在 econ 层 Trend 块内（直接消费面下界）。

## 方法

与生产完全同参逐级重算检测：`units_0` = L0 线段（`segment_to_unit` 镜像）；`units_k` = `project_to_units(tower[k], levels[k-1].moves)`；`detect_centers_windowed_resume(units, build, 0)` 取 `WinMeta.emitted > 1` 标记重切子窗（#148 升级窗口共享父窗，`emitted = k`）。塔侧核直接读 `RMove::Compose.centers[0]`（compose 携带），并与重算 detect 产出逐窗核对——**逐窗 bit-equal（carried_center_match=OK）**，故对齐无漂移。econ 侧核 = `project_extended_windows`（生产 Production 路径）逐窗 seed。

守恒：bars=4,613,599；tower_levels=6；InvalidSeed 分布 [165,43,7,0,0]=215 与 #86/#88 基线逐级相等。

## 机制坐实：每个重切父窗恰好 1 个"真核"子窗

逐级 `ok_equal_recut == recut_parents`（957=957、212=212、34=34、2=2）：**首子窗**的前三段就是父窗 seed 三段，其 offset-0 自核 ≡ 继承核；其余 ⌊n/3⌋−1 个子窗的自有三段交要么不成立（215 InvalidSeed），要么成立但 ≠ 继承核（3,169 静默双核）。C1 继承语义的后果分布至此完整闭合：**重切子窗中只有 26.3% 携带与自身构成一致的核**。

## 遗留 → 裁决点（不在本审计内擅决）

3. 任一方案影响面 ≥ 3,169 窗 + 215 InvalidSeed 窗，且 L1–L4 全层触及；先裁决后动工。
