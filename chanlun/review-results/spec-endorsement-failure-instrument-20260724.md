## Problem Statement

P1 重议已把 Trend 域终端背书从「只收一类」放开为「同向一/二/三类全合法」（owner=B 身份合取保留），实装到位、测试 62/62 绿。但 m8 三窗同事件供给下证书装配量仅 +8/+7/+8（wf7 +8.6%），wf7 typed_found 仅 +2（71→73），与预期基数（Trend 族 465 案中 370 案二/三类）差约一个数量级（事实账 §2.1/§2.2/§2.4）。

差额机制在当前 dump 装置下**不可分账**，四个候选机制均缺读数：

- **C1（首要悬案）**：owner=B 合取可能掐住二/三类点——二类点 center = 次级别离开走势所破中枢、三类点 center = 其判定中枢，二者的 `start_index == 事件 b_center_start` 不构造性保证；该相等率**全库无任何测量**（事实账 §4.1）。
- **C2**：Trend 事件占确认事件比例可能本就低（p115 语料 trend 47/pan 418，但非 m8 语料）；m8 窗确认事件 kind 分布不落任何 dump。
- **C3**：窗口 `[c_start, t*]` / 方向谓词可能掐住二/三类点；无量级数据。
- **C4**：465/95 预期基数是 4.6M bar 全量普查口径，不是 m8 窗（~30 万 bar/窗）；缺 m8 实测分母，预期无法按语料重设。

装置缺口（事实账 §2.3）：NEST_GATE_INDEX 行仅六项聚合（base_events/assembled/indexed/rungs_0/1/2p），无逐事件背书失败原因字段、无按 base 事件 level 分解。

没有分账读数，#211（P1 后 owner 判据是否对二/三类另立口径）的烤制与 map #126 增产战线走向（继续烤 owner vs 转向值桥/表示层）都没有裁定事实基础。本票交付测量装置与三窗重放读数，不交付任何判定行为变更。

## Solution

给终端背书判定与证书索引构建加**只读测量装置**——零干预：只读计数，背书结果、索引内容、链闭合一个 bit 不变。

1. **判定核单一来源**：终端背书判定核保持唯一谓词来源（禁第二查法、禁 fork）；失败事件的桶分类与生产判定在**同一次账本遍历**中作为副产品产出，经新增通道带出，生产消费面原返回值形状与语义不动。
2. **三类计数**：
   - 事件级四桶（Trend 域，互斥完备）：owner_start 不等 / 窗口外 / 异向 / 无合法点（C1/C3 分账）；
   - 点级（点类 × owner 等值）二维计数（C1 的直接读数：wf7 二/三类点 `center.start_index == b_center_start` 相等率的分子与分母）；
   - base 事件 level × kind 分解（C2 分母：Trend/Pan 事件分布）。
3. **索引构建边界聚合**：assembled/indexed 按 base 事件 level 分解；既有 stats 六字段语义与索引内容不动，分解计数挂独立 sidecar。
4. **输出载体**：stderr 纯增量新行（NEST_GATE 行族「既有行 schema 逐字节不动、新行承担新读数」先例），m8 三窗（p3fold/wf7/wf8）重放落账。
5. **验收读数落票**：wf7 窗 Trend 域二/三类点相等率 + 三窗四桶计数表 + 各级产量分解表，连同可重算的分析校验脚本（断言全过、退出码 0）落 #214 resolution 评论；分析产物落 worktree `chanlun/review-results/`（文件名带 20260724 日期戳）。

## Implementation Decisions

模块与接口级决策如下（具体行号与代码片段由实装票定，本 spec 不锁）。

### ID-1 计数通道：判定核核化 + 副产品带出（推荐）

判定核保持单一谓词来源。三个选项：

- **A. 返回形状扩展**：判定核返回值携带桶分类。先例在案（关③ P3.2 `Option<BspBits>` → `TerminalEndorsement` 被裁定为「同函数语义内扩展」），但全部研究 bin 消费点需同步签名，改动面最大。
- **B. sink 参数**：判定核加可选计数器参数。生产签名变、消费点同步；可变状态穿过判定闭包，零干预的阅读成本高。
- **C. 私有核 + 双薄入口（推荐）**：判定逻辑收进私有核，核同时产出判定结果与失败分类；既有生产入口保持现签名现语义（薄包装、丢弃分类），新增测量入口（薄包装、保留分类）供索引构建器使用。生产消费点与研究 bin **零签名改动**；判定语义单一来源（共核），无 fork；失败分类与生产合取同一次遍历产出，口径结构性不可漂移。

推荐 C。理由：零干预纪律下改动面最小（生产调用点一个 bit 不动）、无第二查法风险、与「判定谓词唯一来源」纪律相容。

### ID-2 四桶归属规则（穿透序首因归属，互斥完备）

对 Trend 域 CWindow 事件，判定核在账本遍历时对窗内/窗外点按生产谓词的**既有合取序**（窗口 → 方向 `confirm_side` → owner `center.start_index == b_center_start`）逐点分类；事件级桶按穿透序从点级计数读出：

1. 窗口内点数 = 0：账本（该级别 BSP 全本）存在窗口外点 → **窗口外**；账本无任何点 → **无合法点**。
2. 窗口内有点、窗口内同向点数 = 0 → **异向**。
3. 窗口内有同向点、其中 owner 等值点数 = 0 → **owner_start 不等**。`b_center_start = None`（事件 B 身份缺失）或点 `center = None` 与「start_index 实不等」同归本桶，但**子计数分列**「身份缺失」与「实不等」（与生产 `is_some_and` 短路判负语义一致——身份合取不可证，诚实判负）。
4. 窗口内有同向 owner 等值点 → 判定必命中（最早性取点），**成功，不计桶**。

完备性断言（测试与 replay 校验共用）：Trend 域事件总数 = 成功 + 四桶合计。桶序与生产合取序同构，不引入任何新谓词。账本缺失/级别越界（nest 不听 L0 之外的结构性 None）归「无合法点」并子计数单列。

### ID-3 点级（点类 × owner）二维计数

对 Trend 域事件**窗口内同向点**，按（一/二/三类 × owner 等值/不等）做点级计数——这是 C1 相等率读数的分子/分母。口径 = **事件窗内点**（同一物理点落入多事件窗口时逐窗各计一次），与判定语义同构（每个事件独立判定）；「物理点去重」口径列为开放问题（见 Further Notes），推荐事件窗内口径为主读数。成功事件的命中点同样入点级计数（成功事件的窗内同向点亦按类×owner 分解），保证相等率分母覆盖成功+失败全体。

### ID-4 按级 × kind 分解（sidecar，不动既有六字段）

证书索引构建统计新增独立 sidecar 结构（既有 `NestCertificateIndexStats` 六字段及其语义、`single_level_share`、Copy 语义全保留；sidecar 经新访问器读出）：

- `base_events` / `assembled` / `indexed` 按 base 事件 level 分解（Vec 变长，级别数动态；打印沿用 NEST_GATE_T3 行 `top_dist={:?}` 的数组先例）；
- base 事件按 kind（Trend/Consolidation）分解（C2 分母）；
- ID-2 四桶计数（Trend 域）+ 成功数 + ID-3 点级二维计数；
- Pan 域仅计成功/失败总数（Pan 域无 owner 合取，`confirm_side` 即精确语义，四桶不适用）。

### ID-5 输出载体：stderr 纯增量新行（推荐）

- **选项 A：NEST_GATE_INDEX 行扩字段**——驳回。INDEX 行 13 项是 T3/T5a 红线对照面，先例（T3「NEST_GATE_STATS/CHAIN 行 schema 逐字节不动，红线对照直接可比；新读数落纯增量新行」）明确既有行 schema 冻结。
- **选项 B：纯增量新行（推荐）**——新增独立 stderr 行族承载本装置读数（建议两行：四桶+点级计数行、按级×kind 分解行），与 NEST_GATE_T3 行先例同构。红线对照面零漂移；聚合读数满足验收；落账点在既有 NEST_GATE_INDEX 行同侧（索引构建统计输出点），接线最小。
- **选项 C：逐事件 dump jsonl**——粒度更细但装置更重；票体验收读数均为聚合表，本票不需要逐事件行。列为可选增强，不进最小范围。

### ID-6 零干预保证的落实

1. **共核单一来源**（ID-1C）：生产判定路径代码的合取序、窗口、方向谓词、owner 判定式逐字保留；核化属同函数语义内重构。
2. **既有测试锁定**：nest 模块现有 62 个单测全部不改写、不删除；新测试纯追加。
3. **重放红线对照**：m8 三窗重放后，既有 stderr 行（NEST_GATE_STATS / CHAIN / T3 / INDEX 13 项）、tower_events MD5、候选流、trades 与本装置合入前逐字节一致（沿用 T5a `redline_compare.py` 对照惯例）。
4. **digest 面**：本装置计数结构为新增 sidecar，不进既有 GOLDEN/digest 面，预期零翻转；若任何既有 GOLDEN/digest 面受影响，按 #110 线先例诚实重算并登记，不得静默通过。既线失败 `extract_signals_bit_exact_digest_guard` 属 #110 工作线，与本装置无关，勿误归因、勿顺手修。
5. **声明=能力**（090）：票面读数全部来自全量测量（非抽样推断）；spec 与 resolution 中每条结论标确证/推断，不预写未确证的能力声明。

## Testing Decisions

**好测试 = 只测外部行为**：经公共接缝构造输入（合成账本/合成事件），断言计数输出与判定结果的外部可观察行为；不触私有状态、不锁实装形状、不测内部中间量。TDD：测试先于实装；最小接缝。

**测哪些模块**：classifier 的 nest（判定核副产品的外部行为）与 nest_index（聚合、按级分解、索引不变性）。

### 测试接缝清单（2026-07-24 编排者确认照此）

1. **主接缝（唯一必需）：`build_nest_certificate_index`**（nest_index 公共入口，既有接缝、最高可用接缝——事件账本进、索引+统计出）。一个接缝覆盖装置全部外部行为：
   - 四桶归属：构造 Trend 事件分别落入四种失败形状（窗内同向点全 owner 不等 / 窗内无点而账本窗外有点 / 窗内全异向 / 账本空），断言各归各桶；`b_center_start=None` 与 `center=None` 归 owner 桶且子计数正确；成功事件不计桶。
   - 完备性平账：Trend 事件总数 = 成功 + 四桶合计。
   - 点级二维计数：窗内同向一/二/三类 × owner 等/不等计数正确（含成功事件）。
   - 按级 × kind 分解：多级 events_by_level 输入下 base/assembled/indexed 按级正确；kind 分解正确。
   - **索引不变性（零干预断言）**：既有 stats 六字段读数与装置合入前语义一致；索引内证书张数、身份键集合、链深构成（rungs_0/1/2p）不受计数装置影响。
   - 构造先例：nest.rs `mod tests` 的 `book2`（两本合成账本）/ `pt`/`ptc`（合成点）/ `typed_event`/`trend_ev`/`s0_event`（合成事件）构造器族直接复用；`assemble_typed_certificate` 现有直测（nest.rs:1683/1890 区域）证明该层构造可行。
2. **产物校验接缝（非单测，replay 先例）**：m8 三窗重放 stderr + 分析校验脚本——断言新行可解析、四桶平账、按级合计对账 NEST_GATE_INDEX 行、红线对照（既有行/tower MD5/候选流/trades）逐字节一致。prior art：T3 分析脚本 60 项断言、T5a 114 项断言、`redline_compare.py`，全部退出码 0 留档。

设计说明：桶归属语义本可在判定层（`terminal_bits_at_event`）单测，但经主接缝可全覆盖，故不另立必需接缝；若实装中判定层构造显著更轻，实装者可自决加判定层单元测试，但不进验收接缝清单。

**prior art（测试风格）**：nest.rs `mod tests` 62 个测试——合成构造器 + 断言 `Option` 判定结果/bits/owner_center_start，注释标裁定出处与机制语义；replay 产物校验——分析脚本断言锚定已发表对照面、退出码 0、输出留档。新测试沿用同一风格（含裁定/票据出处注释）。

## Further Notes

### 与 #211 的衔接
