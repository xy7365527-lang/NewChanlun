## Problem Statement

P1 重议把 Trend 域终端背书放开为「同向一/二/三类全合法」（owner=B 身份合取保留）后，m8 三窗证书装配量仅 +8/+7/+8，与预期差约一个数量级。#214 实测坐实首要机制：wf7 窗内同向二/三类点 `center.start_index == b_center_start` 相等率仅 14.0%（二类 9/40、三类 14/124）；wf7 Trend 失败 22 件中 owner_start 不等桶 8 件（36.4%）。

#217 核查 + #211 烤制坐实的根因（归属/确认两层表述）：

1. **归属层混载确认层对象**：归属（点属于谁，同级别）与确认（点成不成立，次级别区间套背驰）是两层关系。一/三类归属参照是中枢（同级别，与事件 B 同型），**二类的归属参照是该走势的一类点**（其定义只要求回拉不破一类极值，与本级别中枢无关）——而二类载体错装了确认层对象 c1（次级别中枢），归属层被确认层污染 = 级别错配根因。
2. **判同机制锚错配**：`start_index` 序号判同撞 #206 身份教义（身份 = 同点递归，锚 =（极值价, 合并组锚），禁序号判同；XZD 双序号判同被 #44 证伪「同中枢序号 ≠ 同归属链」，反面先例在案）。

#211 终裁（路线 B）：owner 归属语义不动（owner = 点属于本事件所确认的走势，不换同点谓词）；载体修填为各类自己的同级别归属参照；判同机制换身份锚；GOLDEN 翻转诚实重算并登记。本票交付该裁定的实装与 delta 对账读数。

## Solution

按归属/确认分层实装两个**正交可叠加**的改动面，#214 测量装置同步新口径，验收走「上游不变 + 下游按账变」：

1. **面 A——归属载体修填（仅二类）**：二类点的归属载体从 c1（次级别中枢，确认层对象）改载**该走势的一类点身份锚**（结构识别出的 i1 第一类离开走势的起点 = 该走势终点极值点，区间套恰好存在）。**确认层一个 bit 不动**：结构识别照常用 c1 / i1 / i2 / 背驰判定。一/三类载体零改动（一类 = 被破 last_center、三类 = 所离开回抽中枢，归属参照已教义对齐）。
2. **面 B——判同机制换锚**：owner 判同从 `start_index` 序号判同换成精确等值判同，按参照物类型分两族（v3 硬禁令：全部精确等值无容差）：
   - 一类/三类（中枢参照）：**核心区间判同**——`点.center 的 (zd, zg) == 事件 B 的 (zd, zg)`（中枢身份 = 其定义内容 [zd, zg] 价格带；dd/gg 外包络作加强位；零序号、零假设）；
   - 二类（点参照）：`anchor(点侧该走势一类点) == (event.extreme_price, event.group_anchor)`（身份锚 =（极值价, 合并组锚），锚解析走 T1 供给线单查；事件自带 seg_c.1 两元锚，零新增解析）。
   点侧锚不可解（fractal/组锚供给缺失）= 身份合取不可证 = 诚实判负 + 子计数单列；中枢参照判同无「不可解」边角（价格带恒在场）。
3. **装置同步**：#214 探针 owner 分量换锚口径（与生产同一次遍历副产品），「身份缺失」子计数重定为「锚不可解」。
4. **验收对账**：上游（base events、tower_events、候选流）逐字节不变红线 + 不变量断言集 + 下游与 #214 基线的 delta 对账表逐项落账；GOLDEN 翻转按 #110 先例受控登记。

## Implementation Decisions

模块与接口级决策如下（具体行号与代码片段由实装票定，本 spec 不锁）。

### ID-1 面 A：二类归属载体修填（对象与取法）

- **改填对象**：二类点构造时的 `center` 载体（`make_second_point` 实参）所承载的**归属语义**——从「次级别中枢 c1」（确认层对象）改为「**该走势的一类点身份锚**」。
- **该走势一类点的取法**：`find_second_type_structure` 识别出的 `i1`（第一类离开走势）的**终点**——区间套恰好存在（i1 终点即该走势终点极值点 = 一类点；取起点则与事件锚永不匹配，教义不成立——实装按此口径，2026-07-24 编排者确认勘误）。坐标由既有 `index_of` / 上游塔供给，**零新入参**（parent、subs、structure 均在手）。
- **归属/确认两对象分离**：结构识别用判定中枢 c1、`i1/i2` 时间序、`divergence_of` 背驰判定**一个 bit 不动**（确认层）；仅归属载体的填载内容换（归属层）。
- **载体形态**：因归属参照从「中枢」变「点」，载体字段从 `Option<Center>` 适配为锚可比形态——优先不加字段：owner 判定在核内经 `anchor_at(一类点坐标)` 判定时解析（同 ID-2 oracle）；`BspPoint.center` 的既有消费面（止损不进 owner 载体，#210 §4.1 已盘点）若因形态变化受触，实装票逐点复核落票。若必须加旁挂字段（一类点坐标），按「不进 PartialEq/Debug 既有面」的旁挂先例（force 精神）评估，进 spec 修订。
- **一/三类载体零改动**（教义已对齐，裁定在案）。

### ID-2 面 B：判同机制换锚（接口形状）

- **判同分两族**（全部精确等值无容差，v3 硬禁令；零序号判同）：
  - **中枢判同**（一/三类）：`point.center.(zd, zg) == B.(zd, zg)`——中枢身份 = 其核心区间 [zd, zg]（中枢的定义内容，types.rs:112 `Center{zd, zg, dd, gg, ..}` 自带）；dd/gg 外包络作加强位（若带碰撞实测非零再收紧，见开放问题 1）。点侧从 `point.center` 直读；事件侧 B 由 `b_center_start` 在账本 `centers` 列表查出对象（**序号只当查找键、不当身份依据**——同一快照内一致；#206 禁的是序号作身份判据）。零假设：价格带恒在场，无「不可解」边角。
  - **点判同**（二类）：`anchor_at(点侧一类点坐标) == (event.extreme_price, event.group_anchor)`——身份锚 =（极值价, 合并组锚）；锚定义 = （`fractal_at_source(fractals, x).price`，`merged_group_anchor(merged_bars, x)`），projection.rs:143-145 同一 T1 供给线查法（单一来源，禁第二查法）。点侧一类点是拐点，锚原生可解；事件自带 seg_c.1 两元锚，零新增解析。锚不可解（点侧 fractal/组锚供给缺失）= 身份合取不可证 = 诚实判负 + 子计数单列。
- **oracle 形状与进核路径**：锚解析 oracle（`anchor_at(source_index) -> Option<(Tick, usize)>`，T1 供给两切片借用或等价闭包）经 `terminal_bits_at_event(_measured)` / `terminal_bits_in_book(_core)` 进核——**仅供点判同（二类）使用**；`build_nest_certificate_index` 加 oracle 入参（主接缝签名扩展），调用链从 T1 供给在手处透传（admission `resolve_foot` 判定时解析同款模式）。#214 私有核 + 双薄入口结构不动：共核单次遍历同时产出判定与新口径探针计数，禁 fork。
- **事件侧零改动**：一/三类 B 带由 centers 列表查出（b_center_start 作键）；二类参照直接用事件既有 `extreme_price/group_anchor` 字段——`NestCandidateEvent`/Ext 不加字段，tower_events.jsonl 逐字节不变（上游红线成立的前提）。
- **保留**：`TerminalEndorsement.owner_center_start` 字段（归因快照，非判定输入；语义不动，消费侧复核归实装票）。
- **不动**：`Exact` 臂（C-a 诊断常数）；窗口 `[c_start, t*]`、方向 `confirm_side`、最早性 `min_by_key`、点类分域逐字保留；`turn_source` 语义不动（确认时点 t*，非归属参照）。

### ID-3 两改动面正交性与切票结构

- **正交性**（#217 §五 在案）：面 A 只动 signal 填载（+mod.rs 实参一处），影响面 = 二类点载体内容（extract_signals 信号流 digest 面）；面 B 只动 nest 判定核 owner_eq + oracle 接线 + 探针口径，影响面 = 背书判定结果及下游。单面各自可成立；叠加 = 裁定全量。
- **切票建议**：若切两票，A 先 B 后（A 面小、digest 翻转面单一）；合一票则主接缝统一覆盖。归 /to-tickets 定，本 spec 不锁。

### ID-4 #214 测量装置同步（探针换锚口径）

- 探针 owner 分量（`in_window_owner_eq`/`owner_real_neq_pts`/`owner_identity_missing_pts`/`trend_pts`）谓词换锚口径——同一次账本遍历副产品，测量=生产结构性锁定不动；按类分参照（一/三类核心区间带判同、二类一类点锚判同）。
- `owner_identity_missing_pts` 语义重定为「锚不可解」（仅二类点侧锚供给缺失；中枢带判同无不可解边角）；`owner_real_neq_pts` = 判同两侧皆可判且实不等（带不等 / 锚不等）。
- 四桶归属规则（穿透序：窗口 → 方向 → owner）不变；桶名「owner_start 不等」改「owner 锚不等」（#214 新增行族、非冻结红线面，schema 演进随票登记）。
- 完备性平账断言保留：Trend 事件总数 = 成功 + 四桶合计。

### ID-5 验收口径：上游不变 + 下游按账变（钉死）

- **上游红线（逐字节不变）**：tower_events.jsonl MD5、候选流 t5a_chain_dump MD5、base 事件计数（NEST_GATE_INDEX `base_events`）。
- **不变量断言集（变即红旗）**：异向桶（wf7 13）、窗口外桶（wf7 1）、Pan 域全部计数、探针遍历计数（`book_total`/`in_window`/`in_window_same_side`）三窗逐项不变。
- **允许变 + delta 对账（对照 #214 基线留档逐项落账）**：
  - owner 桶 / success：预期 owner 不等桶缩小（wf7 ≤ 8）、success 上升（16 → ≤ 24）；
  - 点级相等率：二类显著上升（载体换该走势一类点锚直接消混载）；一/三类带判同与序号判同非包含关系（带等 ≠ 序号等，延伸改带不改序号；序号等 ≠ 带等，同带不同中枢存在）——方向不预设，如实落账；
  - assembled/indexed：增量上限 ≈ owner 桶翻转件数（wf7 ≈ +8 量级，88 → ≤ 96），超出须机制解释；
  - NEST_GATE 行族（STATS/CHAIN/T3/INDEX 13 项）、链构成、trades.jsonl：允许变，逐行/逐笔归因到翻转证书；零变化项记「零变化」（诚实落账）；
  - GOLDEN/digest 面：翻转走 ID-6 受控流程。
- **反向分量单列**：锚不可解导致的 success→owner 反向翻转逐事件落账；非零须解释。
- **逐事件双向翻转清单**（事件身份键）必落账。

### ID-6 GOLDEN 翻转受控流程（#110 线先例）

1. **事前基线**：#214 已留三窗 baseline 留档，直接复用为对照面。
2. **诚实重算**：全量测试 + 三窗重放跑出新 digest/GOLDEN 实际值，禁止沿用旧值放行。
3. **逐项归因**：每个翻转面归因到改动面（面 A → extract_signals 信号流 digest；面 B → 背书/链/trades 下游）；归不了因 = 停线排查，禁放行。
4. **登记**：翻转清单（面 / 旧值 / 新值 / 归因）落 resolution + worktree 留档（20260724 日期戳）；不静默。
5. **与既线失败切分**：`extract_signals_bit_exact_digest_guard` 已在 #110 线失败在案，勿修勿归因；若面 A 改变该 guard 实际输出，登记「既线失败在案 + 实际值二次漂移归面 A」。

## Testing Decisions

**好测试 = 只测外部行为**：经公共接缝构造输入（合成账本/合成事件/合成锚 oracle），断言判定结果与计数输出的外部可观察行为；不触私有状态、不锁实装形状。TDD：测试先于实装；最小接缝。

**测哪些模块**：classifier 的 signal（面 A 构造器外部行为）与 nest/nest_index（面 B 判定与计数行为）。

### 测试接缝清单

1. **主接缝（面 B 唯一必需）：`build_nest_certificate_index`**（nest_index 公共入口，#214 同一最高接缝；签名扩 oracle 后仍是它）：
   - 判同行为：一/三类核心区间带判等/判负（无不可解边角）；二类一类点锚 == 事件 extreme 锚判等/判负/锚不可解子计数；判负入 owner 锚不等桶。
   - **序号漂移用例**：一/三类载体与事件 B 的 `start_index` 不同但 (zd,zg) 相同 ⟹ 判等（序号判同必判负——换锚的直接行为证据）；二类点的一类点坐标与事件 extreme 锚一致 ⟹ 判等。

### 开放问题（v2 修订后剩余；推荐口径已写入对应 ID，最终归编排者确认）

1. **带碰撞边角（一/三类）**：两个不同中枢同 (zd, zg) 的可能性存在（同带不同中枢）。缓解：dd/gg 外包络为收紧预留位 + US-08 观察读数；碰撞实测非零则判同元组升级为 (zd, zg, dd, gg)。比序号判同更准的论证：延伸改带不改序号，序号判不出延伸前后是否同一个，带判得出。
2. **二类载体形态**：归属参照从「中枢」变「点」后，载体字段适配（不加字段、核内经 oracle 判定时解析为推荐；若必须加旁挂字段按 force 先例评估并回 spec 修订）。`BspPoint.center` 既有消费面（PartialEq/Debug/止损判据域外）受触风险归实装票逐点复核。
3. **一票还是两票**：ID-3 正交结构支持两种切法（建议 A 先 B 后），归 /to-tickets 定。
4. **三类点带判同相等率预期**：只钉「如实落账」，不钉方向与下界（带判同与序号判同非包含关系；B 与三类判定中枢无构造保证，#217 Q4）。
5. **GOLDEN 面与 #110 既线 guard 同面的归因切分**：「既线失败在案 + 实际值二次漂移归面 A」的登记口径（ID-6.5）。
