# ADR 0011：操作分解层是一等模块——纵向造级别、横向读级别的分层

**日期**：2026-08-01
**裁定人**：编排者，走 [[grilling] 操作分解层在架构里的位置：同级别分解是一等模块还是塔的投影 #827](https://github.com/xy7365527-lang/NewChanlun/issues/827)（map [#787](https://github.com/xy7365527-lang/NewChanlun/issues/787)）当场拍板
**状态**：已采纳。[#787](https://github.com/xy7365527-lang/NewChanlun/issues/787) 是纯决策图不带实装，本 ADR 只记名分与边界，实装归后续实施线。

## 背景

map [#787](https://github.com/xy7365527-lang/NewChanlun/issues/787)「缠论量化交易系统统一架构正本」是纯决策图，不带实装。本票 [#827](https://github.com/xy7365527-lang/NewChanlun/issues/827)「[grilling] 操作分解层在架构里的位置：同级别分解是一等模块还是塔的投影」要在图上定一件事：**第 38 课讲的"同级别分解"（操作分解），在架构里该是与构造塔并列的一等模块，还是塔的一个投影/查询接口？**

在案相关：[ADR 0010](0010-chong-persistent-operating-unit.md)（「重」的命名）、[#812](https://github.com/xy7365527-lang/NewChanlun/issues/812)（中枢教义正本）、[#804](https://github.com/xy7365527-lang/NewChanlun/issues/804)（总缝规则）、[#826](https://github.com/xy7365527-lang/NewChanlun/issues/826)（塔 vs 第 38 课实测）、[#840](https://github.com/xy7365527-lang/NewChanlun/issues/840)（三轴分离）、[#842](https://github.com/xy7365527-lang/NewChanlun/issues/842)（分区卷钱原型）、[#838](https://github.com/xy7365527-lang/NewChanlun/issues/838)（反向持仓坐标问题）、[#841](https://github.com/xy7365527-lang/NewChanlun/issues/841)（depth 即级别轴）。

### 核心分层

**纵向 = 造级别（构造），横向 = 读级别（操作）。两者依赖单向：横向消费纵向的产出，纵向从不消费横向。**

| 方向 | 干什么 | 是否递归 | 用不用延伸/扩展 |
|---|---|---|---|
| 纵向·往上 | 造级别：低级别段→低级别中枢→高级别段→… | 是，每级用下级造 | 用——全靠它判能否上一级 |
| 纵向·往下（区间套） | 在高级别的点上往下钻找更精确位置 | 是，每钻一层同一套判定 | 用 |
| 横向（同级别分解） | 读级别：选定一层，把市场切成一段段该层走势类型 | **否**——一次性切分，不自我调用 | **不用** |

## 裁定

### 一、操作分解层是一等模块

不是塔的投影。判据三样齐全：

- 输入 = 塔 + 操作级别 k
- 输出 = 第 k 层的不延伸分解序列（含并列盘整）
- 不变式 = **分解唯一性**，原文亲证：

  > `038-第38课.md:18`【正文】「一个好的分解，其分解规则下，必须保证分解的唯一性，否则这种分解就绝对不可能是好的分解」

  > `038-第38课.md:28`【正文】「按照以上的同级别分解规则，用结合律很容易证明，这种分解下，其分解也是唯一的」

### 二、操作级别的持有者 =「重」

操作级别的持有者 = **「重」**（ADR 0010 三要件 ⟨标的 S，操作级别 ℓ，专属筹码 Q⟩ 中的 ℓ）。**必须支持多个同时存在**——多重赋格 = N 个重各挂塔的一层。

### 三、`MoveBlock` 块链不是操作分解层的载体

实查 `rust/src/theta_v0/classifier/recursive_tower.rs:938-954`：块的唯一用途是经 `center_own_dir_at(blocks, idx)` 给单元定方向，喂塔往上爬 ⟹ 块站在构造链上。

### 四、`decompose.rs::fold_rel` 的合并属构造，不属读法

同时订正 [#827](https://github.com/xy7365527-lang/NewChanlun/issues/827) 票面一处措辞错误：代码里**没有**「不允许盘整+盘整」这条禁令，实际机制是 **maximal 同标签连段合并**（`rust/src/theta_v0/classifier/decompose.rs:56-74`，连续 LevelExpansion 关系被就地折成一个 Consolidation 块；模块头第 3 行自陈「切成 maximal 等标签 run」）。区别很实：禁令是拒绝接受，合并是接受了但把两个揉成一个、揉完拿不回来。

### 五、「避开下跌类型」这条操作纪律在本仓不存在

「操作中只选择上涨和盘整类型、避开所有下跌类型」这条纪律在本仓不存在——那是单向市场的约束，本仓多空双开。后果：操作分解层照样报「这段是上涨/下跌/盘整」这个事实，但下游**不需要一个"筛掉下跌段"的开关**（少一个概念，不是把它挪到别处）。在案一致：[#842](https://github.com/xy7365527-lang/NewChanlun/issues/842) R-4「多空双开是多重赋格在双向市场的自动结果」；map [#787](https://github.com/xy7365527-lang/NewChanlun/issues/787) 正文「前提第三次订正：跨级双向持仓是目标形态，不是缺陷」；[#837](https://github.com/xy7365527-lang/NewChanlun/issues/837) 实测 62.6%–72.0% 的 bar 有跨级反向持仓。

以下三条不在 [#827](https://github.com/xy7365527-lang/NewChanlun/issues/827) 票面原始五问之内，是 2026-08-01 走图当场浮出的新结论，与上面五条同为本次裁定的一部分。

### 六、（A）规则不按级别分，按角色分 —— 推断，非原文明文（★本次最承重一条）

第 38 课的表述是单操作级别视角下的：

> `038-第38课.md:26`【正文】「可以制定出这样的同级别分解规则：在某级别中，不定义中枢延伸，允许该级别上的盘整+盘整连接；与此同时，规定该级别以下的所有级别，都允许中枢延伸，不允许盘整+盘整连接；至于该级别以上级别，根本不考虑，因为所有走势都按该级别给分解了。」

多重赋格下同一层会同时既是某个重的天花板、又是更高那个重脚下的中间层，于是露出真正承重的维度：

- **中间产物**（要拿去往上造）→ **延伸**（把连续震荡吸收成"一个"中枢，因为高一级的走势段需要一整块完整震荡区间当构件）
- **最终产物**（要拿去下单）→ **不延伸**（摊成"好几个"并排的中枢，因为每一个都是一次买卖机会）

在只有一个操作级别的世界里，「是不是顶层」与「拿去干什么」重合，所以缠师能用「某级别／以下级别」表述；多重赋格打破这个重合，但底层规则没变，变的是"谁在消费它"。

这条同时保住了总缝规则 [#804](https://github.com/xy7365527-lang/NewChanlun/issues/804)（同一判定每级必须是同一个）：判定没有按级别分叉，是按角色分叉，而角色是数据（这个中枢被谁消费），不是分支。反过来说——若把同级别分解塞进构造层，就必然写出 `if level == operating_level` 这种分支，正踩总缝规则；分成两层是唯一不违规的划法。

**溯源标注**：「按角色分而非按级别分」是**推断**，不是原文明文，推自 `038:26` 的规则形态 + `038:30` 的多级别并行许可。原文对多区之间的协调是空白（[#832](https://github.com/xy7365527-lang/NewChanlun/issues/832) 已查出「多区之间除两句宣示外，分配规则／协调／仲裁／资金全空白」）。map [#787](https://github.com/xy7365527-lang/NewChanlun/issues/787) 的方法论裁定是「填空靠推断，不靠设计」，本条按推断入账。

### 七、（B）目标形态

见下方独立节「目标形态」。此处只记一句要点：**★ 旁路结果不回流主干**——主干只有一条、照常用延伸版往上爬，读法有 N 个但互不干扰主干。

### 八、（C）依赖方向与「横向递归」这个说法的订正

- 「不能直接同级别分解」——「30 分钟走势类型」这东西得先被造出来，造它靠的正是纵向递归和延伸/扩展规则。纵向先跑，横向才有东西可读；反过来不成立。
- 原文钉死依赖：

  > `038-第38课.md:22`【正文】「对30分钟来说，只要5分钟级别的三段上下上或下上下类型有价格区间的重合就构成中枢」

  > `038-第38课.md:24`【正文】「有人可能马上要问，同级别分解的次级别分解是否也是同级别分解的。答案是，不需要。……你完全可以采取这样的分解形式，就是只要某级别中进行同级别分解，而继续用中枢扩展、延伸等确定其次级别」——注意是"不需要"不是"不允许"，没堵死多重。

- **「横向递归」这个说法要订正**：横向方向上没有递归，同级别分解是一次性切分。真正递归的只有纵向；那个"多"来自纵向铺开的 N 个重。
- map [#787](https://github.com/xy7365527-lang/NewChanlun/issues/787) 正文 Destination 段那张"双向递归"表配错了一行（把"横向：同级别分解"配给了"塔"）：塔是纵向构造，同级别分解是横向读法，[#826](https://github.com/xy7365527-lang/NewChanlun/issues/826) 实测 BTC 461 万根 1 分钟 K、L0 仅 21.5% 窗口相同已把两者拆开。正确配法是三格：纵向向上=塔、纵向向下=区间套、横向=同级别分解（**本仓尚无实现**）。图正文订正由主控在 [#787](https://github.com/xy7365527-lang/NewChanlun/issues/787) 上改，本 ADR 只记这条订正的存在。

## 目标形态

- 一条主干塔，**全程延伸、从不停**——产中间产物，就是现在的构造层实现。
- 每个操作级别 k 挂一个**旁路读法**：拿第 k 层的元素用不延伸的规则重折，产该级别的操作序列。
- **★ 旁路结果不回流主干。** 主干照常用延伸版往上爬。这条必须明说，否则实现时把不延伸结果喂回塔，k 以上全乱。
- N 个操作级别 = 同一条主干上 N 个不同高度的挂载点。主干只有一条，读法有 N 个。

## 现状与差距

- 本仓的塔**没有"操作级别"这个概念**：[#826](https://github.com/xy7365527-lang/NewChanlun/issues/826) 实测每级延伸窗口占比 48%–55%，一级都没关过；塔无天花板一路爬到 L5。
- 认下这个形状意味着塔要能被告知"在第 k 层挂一个不延伸的旁路读法"——这是接口变更，不是加个查询函数。
- **改多大属实装，map [#787](https://github.com/xy7365527-lang/NewChanlun/issues/787) 是纯决策图不带实装**，故本 ADR 只记名分与边界，实装归后续实施线。

## 备选方案与取舍

| 方案 | 内容 | 判定 |
|---|---|---|
| **A（采纳）** | 一等模块：主干塔 + N 个旁路读法 | 输入/输出/不变式三样齐全（见裁定一）；主干与旁路依赖单向，互不污染 |
| B | 塔的投影/查询接口 | 被否——构造层的合并是有损的（连续震荡被吸收成一个，摊不回去），投影造不出被丢掉的信息 |
| C | 操作层完全独立造第二条中枢链 | 被否——`038:26` 明写"该级别以下的所有级别都允许中枢延伸"（那就是塔），另起一条要额外回答两条链的一致性谁保 |

## 未决

`038-第38课.md:36`【正文】那套操作程式的「向下段的运作刚好相反，是先卖后买」，在单向市场里是**减仓再补回**（仓位在 0～满之间动），在双向市场里是**开空再平空**（仓位在 −满～满之间动）——两者不是同一件事。正是 [#838](https://github.com/xy7365527-lang/NewChanlun/issues/838) 定性的「根因在坐标：决策变量是标量净持仓，反向在可行集里不可表示」。**归 [#839](https://github.com/xy7365527-lang/NewChanlun/issues/839) / [#834](https://github.com/xy7365527-lang/NewChanlun/issues/834)，不在本票。**
