# ADR 0012：推论层——未经裁定的设计文档，名分归主张不归文档

**日期**：2026-08-01
**裁定人**：编排者，走 [[grilling] analysis/ 文档层的名分：被代码当正本引、对 tracker 不可见的 309 份文档算什么 #845](https://github.com/xy7365527-lang/NewChanlun/issues/845)（map [#787](https://github.com/xy7365527-lang/NewChanlun/issues/787)）当场四问四答拍板
**状态**：已采纳。[#787](https://github.com/xy7365527-lang/NewChanlun/issues/787) 是纯决策图不带实装，本 ADR 只记名分与口径，落地动作限于本 ADR 自身 + `AGENTS.md` + `CONTEXT.md` 三处文本。

## 背景

map [#787](https://github.com/xy7365527-lang/NewChanlun/issues/787) 的立图根因是「**没有人（包括编排者）知道现在到底已经有什么**」。[#844](https://github.com/xy7365527-lang/NewChanlun/issues/844) 盘点时撞出该根因的一个机制成因：仓内存在一整层**被代码当设计正本引用、却对 tracker 完全不可见**的文档，任何既有规矩都不覆盖它。

本票要裁的不是「这些文档写得对不对」，是「**谁能拿它当依据说话**」。

**开票时的题面被本会话订正过一次**：票面写「四个载体、309 份」，实测是**六类载体、480 份**，且 [#844](https://github.com/xy7365527-lang/NewChanlun/issues/844) 报出的 X1 冲突两侧（`docs/adr/0010` vs `docs/three_phase_unified_design.md`）**根本不经过 `analysis/`**。订正的方式本身即本仓元判据的又一次应用——**拿目录当分类维度是错的**。

## 裁定

### 一、文档无名分，主张有名分

**能不能援引，看的是被援引的那条主张有没有完整推理链，不是看它写在哪个目录、哪种文件名下。**

四级溯源标签（[#787](https://github.com/xy7365527-lang/NewChanlun/issues/787) 2026-08-01「填空靠推断，不靠设计」裁定所立）**在援引的那一刻现场打**，不预先给文档批量标注：

| 标签 | 含义 |
|---|---|
| `[旧缠论]` | 缠师原文直接写了 |
| `[新缠论:推论]` | 原文未直接写，由某条原文按明示规则生成；**推理链必须写出来** |
| `[新缠论:选择]` | 原文与推导都够不着，本仓自由选择 |
| `[新缠论:候选]` | 未验证的经验断言 |

**援引方必须把推理链搬进票内重新过一遍，搬不出来就不算依据。**

**理由三条**：

1. **这批文档自己就是按推理链组织的。** `analysis/recursive_regularization_theory.md:2-4` 逐字：「每个命题标注原文锚定（一级权威：缠师博文）或数据支撑」「认识论标注：结构命题为 **L0**（定义推导），凡引用回测数据的经验命题为 **L2**」。它已在做 `[新缠论:推论]` 要求的事，只是没用本仓的标签名。
2. **按文档外形分档踩本仓已踩过三次的坑。** 实测：被 Rust 引为设计正本的那 20 份横跨四种外形——7 份 `_design`、5 份 `_research`、2 份 `_results`、还有 `why_not_profitable.md`。**「被代码引用」这个键切不出「够格当依据」的那一批。**
3. **拿「被代码引用」当授权键与 `AGENTS.md:29` 正面冲突**——那里已立「**生产代码没有发言权、只有否决权**」。代码在注释里引了某份文档，不能反过来让那份文档获得权威。

### 二、载体三段式：权威链 → 推论层 → 正本层

在 `AGENTS.md:19` 已有的两段之间补第三段（该处原文已按「裁没裁」切过一刀，本条只是补上中间那格）：

> **权威链管「证据从哪来」** —— 缠师博文 → chan99 → 思维导图，全是语料
> **推论层管「还没裁的推理」** —— `analysis/` + `docs/` 无名分散件，实测 480 份 **（本 ADR 新增）**
> **正本层管「裁完的结果是什么」** —— `.chanlun/definitions/`（缠论教义）／ `docs/adr/`（架构决策）／ `CONTEXT.md`（词）

**范围＝不在上述五类既有名分内的所有 `.md`**，不按目录列举（目录是外形，会漂）。

### 三、单向流动 + 不追溯更新，不迁不搬

1. **单向流动**：推论层的主张可被援引进裁定票（按裁定一，推理链现场重过）；裁完的结论落正本层。**反向不成立**——正本层不回头引推论层。
2. **不追溯更新**：一条推论被裁定覆盖之后，推论层那份原文**不动、不改、不加批注**。它是历史记录，不是活文档。
   同款判例在案：`docs/agents/wayfinder-workflow.md:172`「spec 是非持久件……从落地那刻起是历史记录」。反之若要求追溯更新，每裁一条就得回扫 480 份改相关段落——做不到的规矩等于没规矩。
3. **不迁并**。按裁定一文档位置已不承重；搬 480 份的收益是「目录看起来整齐」，代价是 16 个 `.rs` 里 20 条路径引用全失效、`git blame` 断链。

### 四、「开之前先搜」补第二路

`AGENTS.md:121` 原条款只写了 tracker 一路，而推论层对 tracker **结构性不可见**——纪律执行得再严也照不到。据此补第二路（本仓路径部分，见 `AGENTS.md`）。

**治法是补搜索动作，不是建索引。** 建索引/白名单这条路已被实证否掉，反证如下：

`analysis/bidirectional_nested_accounting.md` 是 [#844](https://github.com/xy7365527-lang/NewChanlun/issues/844) 报出的最强标本——

| 事实 | 读数 |
|---|---|
| 被代码引用 | **3 个 `.rs`、5 处**（`trading/ledger.rs:375`、`trading/types.rs:391`、`trading/positional.rs:56/599/696`），20 份里被引最密的之一 |
| 谁下的令 | 文档 `:2` 逐字「任务：**编排者 2026-06-12 指令**」 |
| 自带谱系 | `:6-7`「谱系位置：`bidirectional_nested_fugue_research.md` v2（`60b9e7081a`）的下游」 |
| 答了什么 | 逐条答 [#839](https://github.com/xy7365527-lang/NewChanlun/issues/839) 的 Q2/Q3/Q6；`:354` 的 `posted(t)=Σₖ nₖ/L_maxₖ` **正是 [#842](https://github.com/xy7365527-lang/NewChanlun/issues/842) R-12 与 [#834](https://github.com/xy7365527-lang/NewChanlun/issues/834) G1 的现成答案，早 7 周** |
| tracker 引用 | **0**（[#844](https://github.com/xy7365527-lang/NewChanlun/issues/844) 已用 `level_risk.rs` 做控制组排除搜索失灵） |
| 结果 | [#839](https://github.com/xy7365527-lang/NewChanlun/issues/839) 开票时不知道；**[#844](https://github.com/xy7365527-lang/NewChanlun/issues/844) 的开票清单——本仓自己写的——又漏了它** |

**它已站在最显眼的位置（编排者亲自下的令、被引最密、自带谱系声明），仍然漏了两次。** 所以「建一份清单让重要的东西显形」解不了问题——它早就显形了，没人去看。

### 五、[#844](https://github.com/xy7365527-lang/NewChanlun/issues/844) 的 X3 不成其为冲突——是同名异物

X3 原表述：`CONTEXT.md:21`「不得由赋格比喻推理声部的性质」 vs `analysis/recursive_regularization_theory.md` §2 命题 2.1 正由赋格比喻推出。**实为两边用同一个词指了不同的东西。**

逐字对照：

> `CONTEXT.md`（声部词条·已知错位段）：「在赋格里，声部恰恰是**贯穿全曲的持久线**，对应的是上条的**重**，不是本条这个一次性实体。**⟹ 不得由赋格比喻推理声部的性质**（比喻里持久的东西在本仓是一次性的）」

> `analysis/recursive_regularization_theory.md` §2.1 对照表第 2 行：「声部（voice） | **一个操作级别上的独立资金/筹码层（独立 FSM）** | 40课"每一重都对应着一定的资金与筹码"」

该文档的「声部」锚 40 课「每一重」＝ **[ADR 0010](0010-chong-persistent-operating-unit.md) 的「重」**，非 `CONTEXT.md` 那个一次性建仓实体。全篇一致——§2.3 第 3 条逐字「L 声部的**可操作筹码** ≤ L+1 声部卖出所释放的部分；更高声部持有的**底仓**对 L 不可见、不可动」，筹码与底仓均指持久层。

**⟹ 三句**：

1. **禁令维持，不让路。** 本仓词条「声部」（一次性实体）不得由赋格比喻推理其性质。
2. **命题 2.1 不受该禁令约束**——它讲的是「重」，而「重」正是赋格比喻里对得上的那个位置。**禁令的成因恰恰就是同名异物本身**（其括号理由逐字写着「比喻里持久的东西在本仓是一次性的」）：该文档用「声部」指持久筹码层，是**用对了赋格比喻、用错了本仓的词**。
3. **它仍然只是 `[新缠论:推论]`**——按裁定一，援引时推理链照样重过一遍，不因「不受禁令约束」而自动成立。

**X3 从「冲突」降级为「一次读解误判」**，且该误判本身又是元判据的实例：**拿词的外形（「声部」两个字）当同一性判据**。

**译注去向（不破裁定三）**：把词的对应写进 `CONTEXT.md` 声部词条（**正本层，允许改**），推论层原文一个字不动。

### 六、附带结论：喂 [#839](https://github.com/xy7365527-lang/NewChanlun/issues/839)（本 ADR 不裁其实体）

既然 `recursive_regularization_theory.md` 全篇「声部」＝「重」，则 [#844](https://github.com/xy7365527-lang/NewChanlun/issues/844) 的 **X4**（相位约束 `phase(L)=sign(父段方向)`，§2.3 第 1 条）与 **X5**（子声部休止，命题 4.1）讲的都是**「重」之间的约束**，不是「声部」之间的。[#839](https://github.com/xy7365527-lang/NewChanlun/issues/839) 接这两条时题面须按「重」重读——[ADR 0010](0010-chong-persistent-operating-unit.md) 已定义「重」，两边由此取得共同坐标。**实体内容仍归 [#839](https://github.com/xy7365527-lang/NewChanlun/issues/839)。**

## 被否掉的候选

| 候选 | 否掉的理由 |
|---|---|
| **一律判研究笔记、不可援引** | X3 自动消解、X4/X5 降为参考意见，最省事；但与「填空靠推断，不靠设计」的方法论裁定打架——推断出来的东西写在哪儿都不算数，就没地方写了。且裁定五那类发现会连同被扔掉。 |
| **建「可援引文档白名单」** | 键选不出来（见裁定一理由 2、3），且立完就得有人维护。**最强标本本来就在名单里，仍漏两次**（裁定四）。 |
| **按目录逐个立名分**（`analysis/` 一套、`docs/` 顶层一套……） | 正是元判据点名的错误。实证：`recursive_regularization_theory.md`（`analysis/`）与 `three_phase_unified_design.md`（`docs/` 顶层）是同一类东西——都是未经裁定票的设计推论、都被后来的 ADR 正面撞上——唯一差别是当年写的人存在了不同目录。按目录立名分＝把这个偶然固化成制度。 |
| **只裁 `analysis/` 309 份，`docs/` 那 137 份另开一票** | X1 的名分照旧悬空（其两侧不经过 `analysis/`），且下一张票会重推一遍同样的推理。 |
| **给推论层文档加译注/批注** | 破裁定三「不追溯更新」。改走裁定五的正本层译注。 |
| **不治「tracker 不可见」，接受漏检** | 论点不弱：重推一遍是**一个会话**（[#827](https://github.com/xy7365527-lang/NewChanlun/issues/827) 那次），每票加一次全仓扫描是**每票一个子代理**；一年只撞两次的话它更划算。**否掉的账**：map [#787](https://github.com/xy7365527-lang/NewChanlun/issues/787) 52 张票已撞 4 次（[#743](https://github.com/xy7365527-lang/NewChanlun/issues/743) 三雾悬空 ／ NT 适配层已实装但主人以为没接 ／ [#827](https://github.com/xy7365527-lang/NewChanlun/issues/827) 当场重推 `analysis/` 已有结论 ／ [#844](https://github.com/xy7365527-lang/NewChanlun/issues/844) 漏列）＝ **≈8%**。子代理几分钟对一个会话，治更划算。**该算法是粗的，样本只有本图一张——照实记。** |

## 代价（明写）

1. **按主张分档比按文档分档贵**：每次援引都要把推理链搬进票内重过一遍，不能像查白名单那样一眼定。且 480 份不会有人逐条标签化，**存量永远处于未标注状态**，标签只在被援引那一刻现场打。
2. **推论层会长期存在已被裁定推翻、却无任何标记的主张**。读者翻到 `docs/three_phase_unified_design.md:11` 那句「全局单例」，看不出它已被 [ADR 0010](0010-chong-persistent-operating-unit.md) 顶上。唯一缓解是裁定一的「重过推理链」，**那是薄的一层保护，不是硬门**。
3. **裁定四挡不住「搜了但词没想对」**：`bidirectional_nested_accounting.md` 讲「双向嵌套记账」，而 [#839](https://github.com/xy7365527-lang/NewChanlun/issues/839) 问「分区比例／总账口径」——**词根本对不上**。这条纪律降低漏检率，**不消除**。真要消除得靠语义检索，本仓没有。
4. **裁定四是有价钱的**：480 份 grep、还要试多个同义词，按 wayfinder 正本「票内查事实按代价分」就该派子代理 ⟹ **每张裁定票前多一个 AFK 子代理**。
5. **裁定五的译注是逐案补，不是通则**：只治「声部」这一个词，别的同名异物还得逐个撞、逐个补。**没有通则可给**——要有通则就得给 480 份做术语映射表，那正是裁定三否掉的那类工程。
6. **三段式只有一格装未裁定物**：`analysis/` 里 121 份 `_results`／`_backtest` 类实验读数报告按此分法也归推论层，但它们其实更接近 `review-results`（工作草稿）。**分层装不下这个差别，接受**——再切一刀就要回答「读数算不算推理」这种没意思的问题。

## 越界登记

会话中曾提出把「先搜第二路」的**通则那半**外移到全局 `~/.claude/CLAUDE.md`（理由：`AGENTS.md` 只管本仓，换个项目照样犯）。**编排者当场裁定为越出本票范围，不做、不挂票、无人跟进。**

本 ADR 只改 `AGENTS.md` 那一半——注意 `AGENTS.md:117` 自陈该段「把 Claude Code 侧全局 `~/.claude/CLAUDE.md` 的三段要点**复写为仓内口径**」，故改动落在本仓复写件上，**全局原件不动**。
