## 裁定一：穿越才成交，打平不成交

**买单 `low < 挂单价` 才成交（严格小于），`low == 挂单价` 不成交。卖单对称（`high > 挂单价`）。** 成交价见裁定二。

**理由**：

1. **价格是整数 tick 域**（`types.rs:52-55`）⟹「`low` 恰等于挂单价」不是浮点巧合，是高频事件。浮点世界里这一问不值得问，离散网格上它承重。
2. **这批挂单挂在 ZG/ZD——全市场盯着的关口**，正是排队最长的价位。价格擦一下即弹走时，队列根本轮不到你。「触及即成交」在**最不该乐观的地方最乐观**。
3. **否则等于按每根 bar 的极值给自己成交**，这是限价回测最经典的过拟合来源；而它伪造出的假 alpha 恰好长得像「短差做得准」——正是本图要验的东西。

**被否的候选**：

- **触及即成交（`low <= 挂单价`）**：见上。
- **触及 + 穿透 k 个 tick 的缓冲**：k **无数据可标定**（本仓无逐笔、无盘口）。`venue_fee.rs` 的 `uncalibrated_addon` 已是一个「看着合理的拍脑袋常数」被其自身文件登记为裂缝的前例，不加第二个。若日后要做，k 走 [#917](https://github.com/xy7365527-lang/NewChanlun/issues/917) 的标定线。

**代价**：实盘中排在队首者那一下**确实成交了**，本裁定判其未成交 ⟹ **系统性悲观**。接受，因为它与现状（close 成交）**偏差同向**，不翻边——而 (乙) 的最大风险恰是把偏差翻到乐观侧。

## 裁定二：开盘已越过限价时，按开盘价成交

**买单成交价 = `min(open, 挂单价)`；卖单 = `max(open, 挂单价)`。**

**理由**：

1. **这是撮合的真实语义，不是优待**。限价单的合约是「此价**或更好**」。开盘价已在 98 而你挂 100 买，你的单可立即成交，撮合按对手价给你。记 100 是**记了一个不存在的价格**。
2. **与裁定一同源**。裁定一判「打平不成交」的理由是队列；价格**已穿过**挂单价时队列问题消失（你前面的单被吃光，价格才走得过去）。「穿过必成交」与「穿过时得更优价」是同一逻辑的两半。

**⚠️ 本裁定的偏差方向与裁定一相反，二者必须分开裁**：裁定一取严，因为取松会**凭空造出**假 alpha；裁定二取松，因为取严会**凭空抹掉**真 alpha。

**最小反例**：BTC 插针，前一根收 100.5，本根 `open=98 / low=97 / close=99`，买单挂 ZD=100。一律按挂单价 ⟹ 记 100.00 买入，实盘 98.00。**每次插针少赚 2%**——而急跌插针正是「中枢下方如数接回」（`049:53`）最赚钱的那一类 bar。一律保守会把 [ADR 0017](0017-chong-quantity-numerator-shortdiff-amplitude.md) 那批规则判成**假阴性**：一个不报警、只让你放弃有效策略的错误。

**遗留有效域**：`open > 挂单价` 而 `low < 挂单价`（bar 内下探触及）时仍按挂单价成交——**bar 内价格路径不可知**，挂单价是唯一有依据的价。本假设不因本裁定改善。

## 裁定三：同一根 bar 内多订单的三级排序键

```
同一 exec_index 内：
  ① 平仓类 (Close/Reduce) 先于 开仓类 (Buy/Sell/Add)   ← canonical FULL §20，跨方向兜底
  ② 同类内按价格优先：买单价高→低，卖单价低→高          ← 中间值定理
  ③ 仍并列 → 保持出现顺序（稳定排序），注释标为未定义有效域
```

**为什么这不是洁癖**：`fill.rs:115` 的现金约束（「开多需 `cash ≥ 含费 cost`」）使**次序改账**——谁先成交谁吃掉现金，后者可能因没钱而不成交。次序不同 ⟹ 持仓量、成本基都不同。

**② 的理由**：价格从 `open` 走到 `low` **必然先经过高价挂单再经过低价挂单**——中间值定理，**不需要知道 bar 内任何路径细节**。这是本问里唯一不用编造信息就能得到的次序。

**① 的理由**：中间值定理只能给**同向**单排序。同 bar 内买单 99 与卖单 101 都被触及时，谁先取决于价格先上还是先下——那正是不可知的东西。故用既有正本兜底：canonical FULL §20「撤单→先平后开」（`fill.rs:106`）。**这是同一条规则换作用域，不是新口径。**

**③ 的理由**：同为开仓的一买一卖在单标的策略中**不应出现**。为一个从未发生的情形上运行时断言，是把理论问题换成真实崩溃风险，代价方向反了。照 `fill.rs:115` 那句「保证金约束…v0 未建模——**诚实有效域 L0**」的同款处理，一句注释写清即可。

**被否的候选**：**按 OHLC 形状推断 bar 内价格路径**（如「open 离 high 近就假设先上后下」）——bar 内路径**不可知**，推路径是在造数据。

## 裁定四：GTC，寿命绑中枢存续；撤单不得用预算到期 bar

**限价单挂出后一直有效，直到成交或被撤；撤单条件 = 生成它的中枢失效（延伸/升级/结束）。**

**原文依据**（`049-第49课.md:51`【正文】）：「在出现第三类买点之前，中枢未被破坏，当然有所谓的中枢震荡，**其后，中枢已经完成就无所谓中枢震荡了**」——挂单的寿命边界是原文自己划的。

**为什么「当根 bar 作废」会把裁定一~三全部作废**：那等于「只在这一分钟内跌到 ZD 我就买」。而价位驱动的**全部价值**在于「不知道它何时跌到，所以先挂着等」。中枢下沿离当前价通常有距离，一根 1min bar 振幅很小 ⟹ 信号 bar 当根恰好跌到 ZD 的概率极低，这类订单**几乎永不成交**，成交次数趋近 0，[ADR 0017](0017-chong-quantity-numerator-shortdiff-amplitude.md) 那批规则**又一次验不了**——与被否的 (甲) 档同一个结局。
（振幅那句是**未实测的量级判断**，但它不承重：`049:53` 讲的是中枢存续期间一直成立的持仓规则，语义上本就是 GTC。）

### ★ 本裁定的硬约束：撤单不可实现为「预算好的到期 bar」

strategy 层在挂单那一刻**算不出中枢何时失效——那是未来信息**。⟹ 照 `fill.rs:23` 那条既有分层（延迟在 strategy 层算好、fill 只消费 `exec_index` 一个数）给 `Order` 加一个 `expiry_index` 的做法，**用了就是前视**。

唯一可行路径：**strategy 层每根 bar 输出「此刻应挂的限价单集合」，fill 层每根 bar 取最新集合**。撤单变成隐式（不在集合里即撤），无需前视，无需新的撤单消息类型。

**代价是结构性的**：订单接口从**事件流**（「在第 N 根 bar 执行这一笔」）变成**状态流**（「第 N 根 bar 时挂单簿长这样」）。`Order.exec_index`（`types.rs:364`）的语义要重解，生产回路主循环要重写。**该改动不在本 ADR，另立子票承接**（见「移交」）。

## 裁定五：限价路径不扣 `slippage_bps`，配双口径报告纪律

**限价被动成交（裁定一路径）与开盘越过成交（裁定二路径）均不叠加 `slippage_bps`；现有 close 市价路径照旧叠加。**

**理由**：

1. **那 2bp 建模的东西在限价路径上物理不存在**。`uncalibrated_addon` 是**市价单吃穿盘口的冲击成本**（`venue_fee.rs:38`）；限价单不吃盘口，不产生冲击。照旧全扣 = 把市价单的成本模型套在不是市价单的东西上。
2. **限价的真实代价已在裁定一收过**。限价的代价不是滑点，是**没成交**（机会成本）——裁定一的严格穿越判据就在收这笔账，且收得偏保守。全扣等于**同一笔代价收两遍**。
3. **不为限价路径单独标定滑点值**：需要盘口数据，本仓没有（`venue_fee.rs` 自己把它登记为裂缝 3）。

### ⚠️ 本裁定的准入条件（不是可选补充）

本裁定让限价路径比市价路径**便宜 2bp/side**。而本图正在验的恰是「价位驱动的限价短差是否优于信号驱动的市价成交」——**这等于我们自己给结论送了一阵顺风**。

> **任何「限价短差优于市价」的结论，必须在 `slippage_bps = 0` 与照旧全扣两种口径下各跑一遍，两边都成立才算数。**

同一份代码换个常数，零成本；换掉的是一个会伪装成 alpha 的建模选择。**只裁前半不绑这条，本裁定不成立。**

### maker/taker 角色：附带收掉

- **判定规则**：订单在这根 bar **之前**就已挂在簿上 ⟹ **Maker**；信号 bar 当根新挂、挂上去时价格已在更优侧（裁定二路径）⟹ **Taker**。完全由裁定一/二/四推出，无新信息。
- **`PRODUCTION_LIQUIDITY_ROLE`（`venue_fee.rs:112`）须随实装改动**：它现锁死 `Taker`，理由写的是「无限价挂单语义 ⟹ 声称 maker 档是声明膨胀（090）」（`venue_fee.rs:58-59`）。**(乙) 落地后该理由即为假**，注释必须同步改，否则留下一句读起来通顺、实际已失效的溯源——正是本 ADR「上游引用订正」表里那类错的产生机制。
- **BTC 现货 maker == taker（10.0/10.0；BNB25 7.5/7.5）⟹ 本次启用对 PnL 零影响**，`venue_fee.rs:271` 早有登记。**不许拿「启用了 maker」当成本优势去论证任何东西。** 真有 maker 收益的场所（Binance 永续、VIP 高档）目前全是未核项，`VenueFeeBook::resolve` 对其返回 `Err`（fail-loud）。

## 有效域

- **L0（形态裁定）**：五条裁定均为口径选择，无实测背书。裁定一「排队导致打平不成交」、裁定四「振幅量级」两条的**经验依据未测**——本仓无逐笔、无盘口、无成交队列数据，(乙) 档的成交概率是**假设不是实测**（这是 (乙) 相对 (丙) 的既有代价，[#918](https://github.com/xy7365527-lang/NewChanlun/issues/918) 档位裁定时已明账）。
- **裁定二的遗留假设**：`open > 挂单价` 而 `low < 挂单价` 时按挂单价成交，因 bar 内路径不可知。
- **裁定三③**：同 bar 反向开仓单的次序**未定义**。
- **未在本 ADR 核实**：生产回路（`pi_theta_fill_loop_overlay` / `plan_and_fill_mtm` / `plan_and_fill_mtm_dual`）**现有的订单排序与订单寿命语义**。`fill.rs` 6575 行，本会话的只读复核未在会话内返回结论 ⟹ 该勘察随接口改动一并落到下游子票，**不得据本 ADR 假定其现状**。
