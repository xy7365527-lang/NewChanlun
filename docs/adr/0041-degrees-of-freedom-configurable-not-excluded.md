# 自由度通则：原文无定论的合法候选落为可调字段，不作排除

**日期**：2026-10-20　**裁定人**：用户（三条边界同日确认；签署门字段默认值同日批复 B-10）　**驱动票**：[#1586](https://github.com/xy7365527-lang/NewChanlun/issues/1586)

用户 2026-10-20 在 [#1557](https://github.com/xy7365527-lang/NewChanlun/issues/1557) 走票起始操作级别 ℓ_start 时立通则，原话：「A和B都可以，其实我们未必需要二选一，这个具有自由度的东西我们都应当可以调可以选，而不是写死」；同日在 /root 汇总时重申为「让很多有自由度的选择可以调、可以选，而不是单纯的排除」。三条边界由用户同日确认。本 ADR 是该通则的正本；逐项改造由审计票 [#1586](https://github.com/xy7365527-lang/NewChanlun/issues/1586) 驱动。

## 裁定

**一、适用范围。** 本通则只管**自由度**：正本标为 `[新缠论:选择]`、或属参数类且缠师原文无定论的量——构造选择、参数、档位、起点、阈值、场所 profile 等。缠师原文语义（`[旧缠论]`）与已裁教义推论（`[新缠论:推论]`）不是自由度，不变为可调：那是事实，不是偏好。一条量归哪类，以它所在正本的溯源标签为准；标签缺失时先补标签，再谈可调。

**二、与 [#799](https://github.com/xy7365527-lang/NewChanlun/issues/799) 收敛通则的关系。** 可调 ＝ 事前在版本化记录里单选一个值，运行中全程只走这一个值。#799 禁两件事：同一个判断存在宽严两档实现，以及让宽松那档接管严格那档的失败（「严格版判不出 ⟹ 换宽松版再判 ⟹ 放行」）。本通则只覆盖不同的合法取值（参数值、构造选择、档位、起点、profile），同一判断的松紧两个版本不是自由度，事前单选也不得落为可调字段。在这个范围内两者不冲突。

> **判别句**：先问候选是不是同一判断的两套松紧判据（两档实现；同一判据取不同参数值不算）——是 ⟹ #799 管辖，不是自由度，不得做成可调字段（哪怕事前单选）。不是 ⟹ 再看选值：发生在运行之前、写在版本化记录里、一次运行只读到一个值 ⟹ 合法的可调字段；运行中按前一个值的判定结果改走另一个值（同一 if-else 上的失败兜底）⟹ #799 违规，与是否「可配置」无关。

推论：可调字段不得有「主值失败时的备用值」；要换值只能改签新版本、从头重推导。

**三、落法。** 每个自由度落为：

1. **版本化记录字段**——放进该量所属的具名版本化记录（签署记录、policy 记录或场所 profile），不另建配置面；
2. **默认值**——每个字段必须有默认值，附推导依据（原文锚、ADR 或在案读数）；
   **签署门字段的默认值 ＝ `AwaitingPolicy`**（用户 2026-10-20 批复 B-10，见 [#1586](https://github.com/xy7365527-lang/NewChanlun/issues/1586)）。凡已裁定「签署前不给值、不得代填」的字段——资金 cap（[ADR 0029](0029-common-cap-contention-policy.md) 裁定四）、量档与逐级容量（[ADR 0034](0034-quantity-tier-policy-growth-equity-shift.md) 的 `AwaitingPolicy{tier:d}`／`AwaitingPolicy{capacity}`）、成本门 θ 与成本输入（[ADR 0035](0035-cost-stop-policy-instance-and-base-extension-evidence.md)）、闸门后参数槽位（[ADR 0036](0036-operating-statistics-sampling-and-post-gate-parameter-protocol.md) 裁定九），以及其他已裁定由用户签署的风险阈值——运行时默认值就是 `AwaitingPolicy{<字段>}`：未签署则该字段所阻的动作不跑，不回退任何备用值。数值默认值只以「推荐值＋出处」写进签署单供用户确认，签署前不自动生效。这样满足本条「每个字段有默认值」，也不违上述代填禁令；`AwaitingPolicy` 是等待签署的状态，不是第二个取值，因此不构成第二条所禁的备用值。
3. **出处**——字段说明写明可选值集合、各值的来源与代价；
4. **改签即新版本**——改值 ＝ 新版本，改后按新值重推导，不在旧版本内热改。

实现不得把自由度写成代码常数（与 [ADR 0034](0034-quantity-tier-policy-growth-equity-shift.md) 被否方案「常数表 `depth_weights`」同向）。

**四、合法候选保留，真错仍排除。** 裁决一个自由度时，被比较下去的候选分两种处置：

- **另一种合法取值**（不违原文、无实测否证，只是代价不同或当前不推荐）：作为可选值保留在字段说明里，写明代价与适用条件，**不删除、不写成「被否」**；
- **真正错误**（违反缠师原文、违反已裁教义推论、被实测否证、本身是 #799 兜底形态、或与现行判据构成同一判断的宽严两档）：照旧排除，写明排除依据。

## 被比较的方案

- **继续逐张二选一排除**：每次裁决都把并存的合法候选判「被否」，日后想换要重开裁定票重推一遍；且「被否」字样使后来者误以为该值违反原文。不采纳。
- **一切皆可调（含原文语义）**：把事实当偏好，等于允许用配置推翻缠师原文，违反「缠论教义正本」节的权威分层。不采纳——这正是第一条边界。
- **运行时按行情自适应切换取值**：值在运行中随判定结果变，落进 #799 禁区。不采纳——这正是第二条边界。

## 代价（明写）

1. 每个自由度多一个字段、一个默认值和一段出处，记录变长，签署面变大；默认值仍须有人推导和负责。
2. 可选值组合增多，验收与回放要标明所用版本；不同版本的读数不可直接比较。
3. 「合法取值」与「真错」的分界需要逐条判断，判错的方向两边都有：把真错当合法会放进违规值，把合法当真错就回到排除式。审查规则（graph-engineering R2）因此增一条 BLOCK 情形。
4. 签署门字段在用户签署前一直处于 `AwaitingPolicy`，对应动作不跑；推荐值写进签署单只降低确认成本，不缩短这段等待。
5. 既有裁定不追溯自动改写：#1586 只列候选，逐条另开票或并入既有票处理。
