## 决策顺序

Q4 金额/数量分维与定标先于 Q3 数量档；Q1 cap 原子激活和 Q2 引用身份可独立消费。数量方法获批不等于新实例已签署，也不改变已有 /2 账本与黄金证据。

### Q1：新 cap 小于现有责任
沿用已裁边界：不能使新 cap 生效后低于责任，不能强平或挪用旧责任。在同一原子生效点检查新 cap 与现有责任，冲突即拒绝该生效事件、保留原生效版本；失败不部分切换 funding/cap/policy。等于责任允许，低 1 拒绝。旧版本已过期时不能以“保留旧版”恢复新授信。
“先存未生效提案、释放责任后另发显式激活事件”是合法管理方式，不是死锁；它不等于让低 cap 生效，也不等于重新解释 ADR 0029 已裁的取出拒绝。本稿不新增自动排队协议。若需要自动待激活策略，归 #1599 统一处理，不能借本票静默改成已采纳。

### Q2：引用与逐重数值
q_ref 沿用 funding-record 形状，采用 C8 的“授权引用 + 逐重派生金额”：q_ref 定位 profile 的授权身份，另绑定 version；每重金额来自绑定同一签署版本与 (S,ℓ) 的确定性派生记录，C8 载体为 manifest.chongs[i].funding.Q。禁止把 funding-record.cap 的总金额当每重金额。
逐重派生引用也是合法候选，若选择须新 schema/book 版本、显式迁移消费者；不因 #1590 旧草稿而排除。沿用现形状以避免无收益迁移，但固定版本不能在运行中换解析策略。

### Q4：金额、数量与定标（先于 Q3）
量纲：`funding.Q` 为逐重资金金额，`fixed_q` 为固定资产数量；cap、C_amount、cash_g、P 为金额，units_g 与 tier_quantity 为数量。杠杆 L 无量纲，`ceil(Q_amount/L)` 仍为金额，不是股数或 BTC 数量。Q_total 的既有签署与三重分配金额不改。
已批准政策：动作基记 `Q_units`，容量/资金基记 `Q_amount`；正本和新合同显式区分，不能靠同一个 Q 自动推断。新域的数量定标放在具名版本化量档记录中，`quantity_basis` 可选 `signed_units`（直接签固定数量）或 `frozen_quote`（按一次冻结的、可审计报价与单位尺度换算）；未签默认 `AwaitingPolicy{quantity_basis}`，本次采用 `frozen_quote` 方法，减少用户手填股数且能复算。合法的 signed_units 保留，不作为错误排除。
对 frozen_quote，记录整数有理价格 `p_num/p_den`（货币计量单位/数量 quantum）、报价原件引用、时间、货币尺度、数量 quantum、舍入规则及版本。计算式 `Q_units = floor(Q_amount_scaled * p_den / p_num)`；必须先把 USDC 名义整数转为该报价的货币计量单位，p_num、p_den 均正。换算不再乘杠杆，因为 Q_amount 已是 ADR 0040 的名义动作资金基，L 只计算本金保证金。溢出拒绝，零数量不激活，余款留资金账且不得伪造 quantity。
首次报价取样另签具名 `quote_time_policy`，不交数据 owner 自选：候选 `activation_request_asof`（本次采用的方法）以已持久化的首次激活请求为锚；候选 `profile_signature_asof` 以绑定 profile 版本的签署事件为锚。两者都在量档版本中签一种；首次激活锚与 profile 签署锚不得混用。对后续 q_rebase，前者以已授权且持久化的 q_rebase 请求为新锚，后者以该次新量档版本的签署事件为新锚；不能继续引用旧 profile 的签署时点代替新版本锚。拆股按既有比例重基，不触发市场报价再选取。采用请求锚是为了让首次激活/重基按各自动作时点定标，签署锚保留为先签后执行的合法选择。
每个锚保存事件 ID、事件时间 `t_anchor` 和当时已封存的报价输入快照 ID；快照须固定于选价前。报价须与签署的市场/标的/来源/价格字段匹配，且发生时间与首次观察时间均不晚于 `t_anchor`、存在于该快照、报价年龄不超过政策签署的 `max_quote_age`；不在本稿猜定年龄数值。合格集合按发生时间、首次观察时间、来源内稳定报价 ID 的字典序依次取最大；同 ID 内容冲突拒绝定标。来源须有稳定 ID 与可验证首次观察时间，否则该源不满足此政策。没有合格报价、缺锚/快照/有效期签署则保持 `AwaitingPolicy` 或待数据状态，不选锚后报价、不读现价、不换另一时点规则兜底。恢复/重试沿用同一锚和快照；想换锚只能走明确的新版本/已授权 q_rebase，不能通过重复激活请求刷新定标。
本次批准 `activation_request_asof` 的时间策略方法；实例 `max_quote_age` 尚未签署。真实报价原件、发生/观察时间、货币尺度、quantity quantum 是数据 owner 按已签规则提交的事实。记录时间只是证据，不能代替上述选取政策。`signed_units` 不需要报价时点策略，不因 frozen_quote 的缺项被额外阻塞。
冻结粒度是重的量档版本，不是每 bar/每个新 Voice；之后只有已授权 q_rebase、新版本和拆股路径可改变数量。缺定标记录不得读当前市价兜底。数值尚未签，不能把现有测试 fixed_q=1 当真实金额的换算结果。
资金溢出时，quantity 路径比较 `Q_units + units_g` 与同单位 C_units；capital 路径比较逐重 Q_amount + cash_g 与 C_amount。q_ref 是引用字符串，不能参与加法。跨维容量须绑定同一定标记录。#1598 正在处理 overflow_trigger 的 units/capital/mark_value 选择；本票只提供分维接口，不先替它裁触发策略，也不删 mark_value 候选。
### Q3：L1 的冻结档量
沿用必须有版本内冻结 tier_quantity、`floor(Q_units*347/1000)`、不运行时现算、未定只挡该深度的规则。
订正：1,110,400 是 3,200,000 USDC ×347/1000 的金额结果，不能直接认定为 BTC quantum 数量。旧 ADR0040 的数字保留历史出处，新增订正说明；新记录需等 Q4 的定标证据和签署，才能产出 tier_quantity。不得机械补“tier_quantity:1110400”后宣称严格量档已验收。
例（仅量纲示范，不是签署值）：若 Q_amount=3,200,000 USDC、数量 quantum=0.001 BTC、冻结价格=100 USDC/quantum，则 Q_units=32,000 quantum，档量=11,104 quantum。报价、货币/数量尺度改变必须重新签版本，不能复用此例作为默认。

## 验收清单
1. 获批草稿第二轮独审 PASS，落文书后须另由非作者核一致性；受影响清单见下。事实缺口不以方法批准代替。
2. 本 ADR 和 ADR0034/0040 订正节存在，明确两种 Q 与杠杆 L；ADR0043:112 的冻结语义保留。旧文本按历史保留，不篡改旧签署。
3. 下游 cap 测试：责任大于/等于/小于新 cap；失败逐字比原活跃版本及账目无变化；并发新责任与生效在同一原子顺序下重判。
4. 下游引用测试：三重金额 1110000/3200000/690000、共同 q_ref；错 profile、错 (S,ℓ)、错版本拒绝，不能读总额5000000替代逐重金额。
5. 下游数量测试：金额尺度与 quantity quantum 非1，冻结有理报价，向下取整与残量；零/负价格、溢出、缺原件拒绝；改变现价/Voice 不改变 frozen Q_units 与 tier_quantity。
5a. 首次选价二值验收（合成时间/报价，不是签署市场值）：profile 签署锚 t=90、首次激活请求锚 t=100；同一测试行情集按各锚生成当时已知报价的封存快照；行情集含报价 A(发生/观察=89/89,价格80)、B(99/99,价格100)、C(101/101,价格120)、D(98/101,价格90)。有效期设为测试值且覆盖 A/B。签 activation_request_asof 必须选 B，签 profile_signature_asof 必须选 A；C 为锚后发生，D 为锚后观察，均不得进入首次定标。相同时间的两个合格报价按稳定 ID 排序选择，交换输入顺序结果不变；同 ID 冲突必须拒绝。过期/空集合/缺时点政策不得激活；signed_units 不受报价缺项影响。q_rebase 新请求锚 t=110 或新签署锚 t=105，各自只能读取对应封存快照的合格报价；若无其他报价且 C 在有效期内，两者均必须选 C；重试旧请求仍选旧报价，不能以重试时的新价刷新。各负控通过与否由选中报价 ID、锚 ID、快照 ID 和定标结果判断，不仅检查双跑相同。
6. 下游档量测试：量纲示范得到32000/11104；缺定标或档量只挡该依赖动作；已有已签基线及其他已定深度不被一概阻止。
7. 双跑/恢复核同一签署版本、报价原件与金额/数量结果逐位相同；旧 tb03c-book/2 黄金证据不改，新行为用新版本。这里列的是待实施验收，不声称已执行。
