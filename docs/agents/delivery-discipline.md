# 开票与关票的交付纪律

谁声明，谁把声明写成当场可核对的事实，并承担补齐指针或证据的成本。这里不设巡查、不设惩罚，也不设 CI 硬门；规则靠声明人自执行。

来源：SPEC #480；本单片 #482。

## 关票前，把「已经交付」说完整

关票结论不能只写「完成」。在关票的那一刻，下面六件事必须同时成立：

1. 关票结论（resolution）明确引用实际落地的 commit hash。
2. 该交付已经并入 `main`；合不进 `main` 就不关票。
3. 关票评论里的每一条声明，在关票时都已经为真，不能预写尚未执行的评审、测试或结论。
4. 一张票由多个 commit 交付时，逐个声明每个 commit 都可编译；纯文档 commit 不要求编译，但要明确标成纯文档豁免。
5. 关票时清理对应工位：本票关联的 worktree/branch 按世代宪法容器两态判定（`docs/agents/generation-constitution.md` §1.1），票关即残骸，残骸即删；有在制品未合入的不得关票，先处置在制品。
6. 关票时本票报告（测量/调研/评审等实体产物）已入 git，以仓内相对路径引用（如 `chanlun/review-results/`）；仅在评论或票体写「报告见某路径」而文件未入版本控制不算入仓，引 `/tmp` 或绝对路径视同未入仓。
7. 关票面 == 评审面：评审（两轴/影子）针对的 diff 快照之后新增的代码提交（收口包、修复轮、关票前小修），必须在关票前纳入评审范围——核对「最后一次评审覆盖的 diff」与「关票 resolution 引用的 commit 集合」一致；不一致则尾部 diff 先补评审（快速轴即可），不得以「大头已评」带过。

- **适用时机**：准备发布关票评论和填写 resolution 时；第 4 项只在多 commit 交付时触发；第 5 项只在该票开过工位时触发；第 6 项只在该票产出实体报告时触发；第 7 项只在评审完成后有新代码提交时触发。
- **声明一句话模板**：`关票声明：resolution=<落地 commit hash>，已并入 main；本评论各项在此刻均已为真；逐 commit 可编译性=<hash A：可编译，hash B：可编译，hash C：纯文档豁免>；工位=<已删 / 无工位>；报告=<仓内相对路径 / 无报告>；评审面==关票面（或：尾部 <hash> 已补评审 <报告路径>）。`
- **豁免面**：只有纯文档 commit 豁免「可编译」声明；落地 hash、并入 `main`、关票时声明为真这三项没有豁免，单 commit 交付不触发逐 commit 列举；长期工位（如 #59 线专属）以白名单登记豁免第 5 项；无实体报告的票（纯裁定/簿记/纯代码交付）豁免第 6 项，但须在关票声明写明「无报告」；评审完成后仅纯文档/注释提交豁免第 7 项（代码提交无豁免）。
- **出处票号**：#436 / #440 / #476 / #506 / #525（第 6 子句，缘起 #450 报告未入 git 致 #521 断粮重建）/ **#448（第 7 子句，2026-07-28 编排者立：缘起 #421 流程-H1——关票前 3 分钟的 `58672e2563` 与 468 行修复轮 `77d3554332` 落在所有零件评审范围外，「零件和=整体」不成立实锤）**。

## 开票时，先把对照物钉住

验收项若写「跟 X 一致」「不劣于基线」或其他对照说法，开票当场就附上能找到 X 的指针，例如 commit hash、文件路径或测试名。附不出来，说明这条验收还没写好：要么改写成不依赖缺失对照物、可以直接判定的条件，要么明确标「对照后补」，并按降级声明处理。

- **适用时机**：新建或改写任何对照型验收项（acceptance criterion，简称 AC）时。
- **声明一句话模板**：`AC-X 对照物：<commit hash / 文件路径 / 测试名>；若当前附不出，则写“对照后补：AC-X 当前无可用对照物，降级为不可按对照独立验收”，并将可直接判定的条件改写为 <条件>。`
- **豁免面**：非对照型验收项不触发；对照型验收项没有「先写了再说」的豁免，只能补指针、改写，或显式降级。
- **出处票号**：#477。

## 说豁免时，同时给出能验真的证据

豁免不是理由句，而是一个可以被检验的命题；声明时同时附上实际运行的命令和关键输出。没有证据的豁免不能越过票面明写的验收项，只能跳过默认要求，而且必须标「未检验」。

- **适用时机**：用「不适用」「无需执行」「可跳过」等豁免声明跳过一项要求时。
- **声明一句话模板**：`豁免声明：<可检验命题>；证据：<命令> → <关键输出>；因此豁免 <项目>；若未附证据则改写为“未检验：仅豁免默认项，不覆盖票面 AC-X”。`
- **豁免面**：证据充分时，只豁免证据实际覆盖的项目；未附证据时只可豁免默认项，票面显式验收项没有豁免。
- **出处票号**：#444。

## GitHub 用过的编号，不再拿去指别的课题

一旦 `#N` 已被 GitHub Issues 实际使用，commit message 里的 `#N` 就只指那张 GitHub Issue，不能再拿它表示内部课题。内部课题改用谱系号或日期标签。

- **适用时机**：给 commit message 或交付说明写课题编号时。
- **声明一句话模板**：`编号声明：本提交中的 #N 仅指 GitHub Issue；内部课题使用 <谱系号 / 日期标签>。`
- **豁免面**：引用真实 GitHub Issue 不受限制；已经被 GitHub 使用的 `#N` 没有改作内部编号的豁免。
- **出处票号**：#436。

## 多张票塞进同一个提交，就明说不能单独验

分票原本各有验收项，却被打包进同一个物理 commit，导致其中一张票无法脱离另一张票独立验证时，必须显式降级，不能继续声称每张票都能独立验收。

- **适用时机**：两个或更多分票合并进同一物理 commit，且某项验收无法按票独立验证时。
- **声明一句话模板**：`AC-X 因与 #YYY 合并交付降级为不可独立验证。`
- **豁免面**：没有豁免；若每张票仍有各自可独立验证的交付与证据，则本条不触发。
- **出处票号**：#440。

## 碰 CI 把关面的票，关票前必须推镜像

**成因是一次实事故（[#810](https://github.com/xy7365527-lang/NewChanlun/issues/810)，2026-07-30）**：本仓 `main` **不推 origin**——远端 `main` 是另一条祖传历史（与本地 `main` **零共同祖先**、独有 1171 个提交），本地这条重写过的线以 **`main-rewritten`** 这个名字发布，CI 触发器挂在它上面。于是存在一个静默失效模式：**提交落在 `main`、忘了推镜像 ⟹ CI 一直在旧树上把关，而且是绿的。**

实测查出时镜像已落后主线 **545 个提交**，期间 CI 全绿。追上后当场暴露三条此前不可见的红：`cargo fmt --check` 6 文件 11 处漂移（[#611](https://github.com/xy7365527-lang/NewChanlun/issues/611) 那道闸装了也响了，只是一直响在别处）、pytest `test_morse_landscape` 的 LFS pointer 分支炸而非 skip（[#818](https://github.com/xy7365527-lang/NewChanlun/issues/818)）、两条 Lean↔Rust 一类买点对拍断言（[#811](https://github.com/xy7365527-lang/NewChanlun/issues/811)）。

**这是「锁形同虚设」的第三种形态**，比前两种都隐蔽：

| 形态 | 表现 | 在案 |
|---|---|---|
| 一 | 锁打好了，没接进任何 gate | [#806](https://github.com/xy7365527-lang/NewChanlun/issues/806) |
| 二 | 接进 gate 了，但只编译不执行 | [#799](https://github.com/xy7365527-lang/NewChanlun/issues/799) 裁定十一 |
| **三** | **执行了，但看的不是这棵树** | **本条** |

**条款**：一张票若改动了 `rust/` / `.github/` / `formal/` / `src/` / `tests/` / `scripts/`（即 CI 实际把关的面），**关票声明须包含镜像已推 + 一条 CI run 链接**：

```
镜像：origin/main-rewritten @ <hash>（== 关票面）；CI run：<链接> → <结论>
```

CI 为红时**照实写红并说明去向**（哪张票接、为什么不当场修），**不许为了让声明好看而缩测试范围、加 `#[ignore]` 或改触发分支**。[#811](https://github.com/xy7365527-lang/NewChanlun/issues/811) 即一例**有意为之的红**：教义分歧未裁之前不许修绿。

**机械提醒（不阻断）**：`scripts/check_mirror_sync.sh` —— 镜像落后且落后面含把关目录时打印警告与推送命令。挂法见脚本头部注释（`.git/hooks/post-commit` 加一行，勿删已有的 git-lfs 行）。**只提醒不阻断**：推镜像是对外动作，按仓内纪律须人批准，脚本不替人决定推不推，只保证「落后」这件事不会没人知道。

**⚠ 为什么不做成 CI 检查**：CI 只看得到被推上去的树，**看不到本地工作线领先多少**——这道防线在 CI 里原理上就实现不了。原提议曾是「CI 加一步检查镜像落后即红」，复核后作废，记在此防止再提。

## 五案例边界样本表

| #111-112：两张分票打包进同一提交，AC 无法按票独立验证 | 降级声明 | `AC-X 因与 #112 合并交付降级为不可独立验证。`（#112 对应项同样指回 #111） |

| #435：多 commit 交付中存在不可编译的中间 commit | 关票门第 4 子句 | 不满足时不作可关票声明；满足后写：`逐 commit 可编译性：<hash A：可编译；hash B：可编译>。` |

## 只管新声明

本规范只约束生效后的新开票、关票、豁免、编号和降级声明，不追溯存量。
