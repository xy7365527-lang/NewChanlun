## 第一部分：原文操作方法提炼——38课同级别分解操作程式

### 1.1 操作骨架（逐条提取自38课正文）

38课正文（第36行）给出了完整的机械化操作程式。以30分钟级别同级别分解为例，逐步拆解如下：

**前提设定：**

- P0：选定操作级别（如30分钟），对所有走势按该级别的走势类型进行同级别分解（第18行）
- P1：同级别分解下，不定义中枢延伸，允许盘整+盘整连接（第22-26行）
- P2：该级别以下允许中枢延伸，不允许盘整+盘整连接（第26行）
- P3：该级别以上不考虑（第26行）

**操作程式（第36行，逐句拆解）：**

| 步骤 | 原文摘要 | 形式化标记 |
|------|---------|-----------|
| S1 | "从一个下跌背驰开始" | 入场前提：等待操作级别的下跌背驰 |
| S2 | "首先出现向上的第一段走势类型" | 买入第一段上涨（U1），这是1买 |
| S3 | "根据其内部结构可以判断其背驰或盘整背驰结束点，先卖出" | U1内部出现背驰/盘整背驰 → 卖出 |
| S4 | "然后必然有向下的第二段" | 等待第二段下跌（D2） |
| S5a | "不跌破第一段低点，重新买入" | D2.low > U1.low → 买入 |
| S5b | "跌破第一段低点，如果与第一段前的向下段形成盘整背驰，也重新买入" | D2.low < U1.low 但盘整背驰 → 买入 |
| S5c | "否则继续观望，直到出现新的下跌背驰" | D2.low < U1.low 且无背驰 → 回到S1 |
| S6 | "出现向上的第三段" | 第三段上涨（U3） |
| S7a | "低于第一段的高点，一定是先卖出" | U3.high < U1.high → 卖出（不创新高 = 最弱） |
| S7b-i | "超过第一段的高点 + 第三段对第一段发生盘整背驰 → 卖出" | U3.high > U1.high 但盘整背驰 → 卖出 |
| S7b-ii | "超过第一段的高点 + 不发生盘整背驰 → 继续持有" | U3.high > U1.high 且无背驰 → 持有 |
| S8 | "这个过程可以不断延续下去" | 循环：U(2k+1) vs U(2k-1) 比较 |
| S9 | "直到下一段向上的走势类型相对前一段出现不创新高或者盘整背驰为止" | 终止条件：不创新高 OR 盘整背驰 |
| S10 | "这就结束了向上段的运作" | 退出向上段 |
| S11 | "向上段的运作，都是先买后卖的" | 向上段 = Long-only |
| S12 | "一旦向上段的运作结束后，就进入向下段的运作" | 切换到向下段 |
| S13 | "向下段的运作刚好相反，是先卖后买" | 向下段 = Short-only |
| S14 | "从刚才向上段结束的背驰点开始，所有操作刚好反过来" | 镜像操作 |

### 1.2 操作程式的结构总结

```
向上段循环：
  while True:
    U = 下一段向上走势
    if U 不创新高 or U 对前一个向上段盘整背驰:
      卖出，退出向上段
      break
    else:
      持有（或在内部背驰点做短差后回补）
    D = 下一段向下走势
    if D 不跌破前低:
      买入
    elif D 与更早的下跌段盘整背驰:
      买入
    else:
      观望，回到等待状态

向下段循环：（镜像）
  while True:
    D = 下一段向下走势
    if D 不创新低 or D 对前一个向下段盘整背驰:
      买入平空，退出向下段
      break
    else:
      持有空仓
    U = 下一段向上走势
    if U 不突破前高:
      卖出做空
    elif U 与更早的上涨段盘整背驰:
      卖出做空
    else:
      观望，回到等待状态
```

### 1.3 原文关键约束

1. **同级别分解的唯一性**（第18行）：分解规则下分解是唯一的，不存在含糊乱分解
2. **永远只针对一个正在完成的中枢**（第22行）：一旦完成，关注下一个
3. **无所谓牛市熊市**（第28行）：30分钟上涨就是牛市，否则就是熊市
4. **分区卷钱**（第30行）：不同量的筹码按不同级别分解操作，机械化减成本

## 第二部分：区间套如何嵌入

### 2.1 区间套的定义（37课+29课）

37课第22行："对c的内部进行分析...c至少包含两个次级别中枢...这两个中枢构成次级别趋势的关系...就可以继续套用a+A+b+B+c的形式进行次级别分析确定c中内部结构里次级别趋势的背驰问题，形成类似区间套的状态，这样对其后的背驰就可以更精确地进行定位了。"

29课第52行（答疑）："已经反复强调，一定要从大级别往小级别看，用区间套的方法。1级别的背驰发挥大威力，是因为在大级别的背驰段里。"

### 2.2 区间套在38课程式中的嵌入点

38课程式中每个判断"背驰/盘整背驰"的决策点，都不是单一级别的判断，而是区间套递归展开：

| 程式步骤 | 判断内容 | 区间套展开方式 |
|---------|---------|--------------|
| S1 下跌背驰 | 操作级别出现下跌背驰 | 先确认操作级别趋势背驰段（a+A+b+B+c中c段），然后进入c的内部，用次级别定位精确买点 |
| S3 U1内部背驰 | 第一段上涨的结束判断 | 操作级别上看U1走势类型完成（盘整背驰或趋势背驰），次级别精确定位卖点 |
| S5b 盘整背驰 | D2与前面下跌段比较 | 操作级别MACD面积比较，次级别确认第一类买点 |
| S7a 不创新高 | U3 vs U1高点比较 | 价格直接判断，无需递归（最弱情况，连MACD都不需要——37课第20行） |
| S7b-i 盘整背驰 | U3对U1盘整背驰 | 操作级别MACD面积比较A段vs C段，次级别确认卖点 |
| S9 终止条件 | 不创新高或盘整背驰 | 同S7a/S7b-i |

### 2.3 区间套的实现原则

```
function 区间套精确定位(操作级别, 方向, 背驰段):
    # 第一层：操作级别确认背驰存在
    if not 操作级别.has_divergence(背驰段):
        return None  # 没有背驰，不操作

    # 第二层：次级别定位
    次级别走势 = 背驰段.get_sub_level_structure()
    次级别背驰点 = 次级别走势.find_first_class_point(方向)

    if 次级别背驰点 exists:
        # 第三层：次次级别（可选，精度更高）
        次次级别 = 次级别背驰点.get_sub_level()
        最终点 = 次次级别.find_first_class_point(方向)
        return 最终点 or 次级别背驰点

    return 操作级别背驰点  # fallback
```

**关键认识**：区间套不是独立的过滤层，而是38课程式中每个背驰判断的**内部递归展开**。操作级别确定"该不该操作"，区间套确定"在哪个精确价位操作"。

### 2.4 区间套 = 多级别联动（不是独立模块）

29课答疑明确说（第52行）："一个1分钟的背驰，可能就以一个盘中的震荡就化解了。针对该股，如果看大级别的图，用走势必完美，就知道第三段的下跌是必然的。所以，要先看大级别，知道大级别再干什么，再看小级别。"

这意味着：
1. **大级别决定方向和阶段**（是在上涨初期还是尾声？）
2. **操作级别决定操作决策**（该不该买/卖？）
3. **次级别精确定位**（在什么价位买/卖？）
4. 三者不是三个独立滤波器，而是同一个决策的三个层次

## 第三部分：PH如何融入

### 3.1 PH在系统中的角色定位

PH（Persistent Homology，持久同调）在本系统中不是独立的信号源，而是38课程式中以下判断的**拓扑化补充**：

| 38课判断 | 原文方法 | PH拓扑化补充 |
|---------|---------|-------------|
| "下跌背驰" | MACD面积比较 | PH settle事件：高persistence的拓扑特征settle = 结构性转折确认 |
| "不创新高" | 价格直接比较 | PH rank变化：主导persistence rank下降 = 上涨力度减弱 |
| "盘整背驰" | MACD面积A vs C | PH alive特征数变化：alive count收缩 = 结构趋于收敛 |
| "走势类型完成" | 中枢+背驰判定 | PH树settle阈值：当前级别PH树的主导特征settle = 该级别走势完成 |

### 3.2 三层PH的职责分工

PH树的级别由数据自然涌现（详见第六部分），但在操作中承担不同角色：

**方向级别PH（最高有效persistence）：**
- 对应38课程式的"向上段/向下段"切换
- rank-1 settle方向 = 大方向（向上段做多，向下段做空）
- 翻转频率最低（根据回测报告，L2方向翻转仅14-25次 vs L0的780次）

**操作级别PH（次高persistence）：**
- 对应38课程式中每段走势类型的"完成"判断
- PH settle事件 = 操作级别走势类型的一个结构性终点
- 配合MACD背驰共同确认操作信号

**短差级别PH（较低persistence）：**
- 对应38课"分区卷钱"中的减成本操作
- PH settle事件 = 短差级别走势类型的结构性转折
- 用于持仓期间的减仓/回补时机

### 3.3 PH与MACD的关系

PH不替代MACD，两者测量不同的东西：

| 维度 | MACD | PH |
|------|------|-----|
| 测量对象 | 价格动量的一阶导数变化 | 价格结构的拓扑生灭 |
| 判断内容 | "力度是否衰竭" | "结构是否settle（不可逆地完成）" |
| 适用场景 | 趋势背驰/盘整背驰的力度比较 | 走势类型完成/级别转换的结构确认 |
| 信号特征 | 连续的、可比较的 | 离散的、事件驱动的 |

**融合规则：**
- MACD背驰 + PH settle → 高置信度操作信号
- MACD背驰 + PH未settle → 可能是假信号（结构尚未完成），降低仓位或等待
- PH settle + MACD未背驰 → 结构完成但力度未衰竭，可能是中继而非转折
- 两者都不触发 → 持有不动

### 3.4 PH作为区间套的拓扑化实现

区间套要求"从大级别往小级别看"。PH树天然提供了这种层级结构：
- 方向级别PH settle → 确认大级别背驰段存在
- 操作级别PH settle → 确认操作级别走势完成
- 短差级别PH settle → 精确定位买卖价位

这与区间套的"操作级别确认→次级别定位→次次级别精确"完全对应。

## 第四部分：降成本如何融入

### 4.1 原文依据

38课第30行："你可以设定某个量的筹码按某个级别的分解操作，另一个量的筹码按另一个更大级别的分解操作，这样，就如同开了一个分区卷钱的机械。"

29课答疑（第53行）："像000858...这种级别的回调至少也该采取本ID所说的变成负成本后再长线持有。"

### 4.2 降成本的机械化设计

降成本操作发生在38课程式的**持有阶段**（S2到S3之间、S5a/S5b到S7之间），具体是：

```
在持有阶段，用短差级别PH做循环操作：

while 持有操作级别仓位:
    if 短差级别PH.settle(方向=卖) and MACD短差背驰:
        减仓（卖出减成本份额）
        减仓价格 = 当前价
    
    if 已减仓 and 短差级别PH.settle(方向=买):
        回补（买回减成本份额）
        本次差价利润 = 减仓价格 - 回补价格
        累计成本降低 += 本次差价利润
    
    if 操作级别出现退出信号:
        break  # 退出持有阶段，回到38课主程式
```

### 4.3 降成本的仓位管理

| 阶段 | 总仓位 | 主仓位（不动） | 短差仓位（循环） |
|------|--------|--------------|----------------|
| 初始建仓（S2/S5） | 100% | 70% | 30% |
| 降成本周期 | 70-100% | 70%（锁定） | 0-30%（循环减/补） |
| 加仓（S7b-ii确认） | 130% | 100% | 30% |
| 本金回收后 | 原仓位 | 全部 | 用利润继续循环 |

### 4.4 与38课程式的对应关系

降成本不改变38课程式的主流程，它是主流程中"持有"状态的内部活动：

```
38课程式主流程：
  S2: 买入 ──→ [持有阶段：降成本循环运转] ──→ S3: 卖出
  S5: 买入 ──→ [持有阶段：降成本循环运转] ──→ S7: 判断
```

## 第五部分：多空不对称

### 5.1 原文依据

38课第36行明确区分了两段：
- "向上段的运作，都是先买后卖的"
- "向下段的运作刚好相反，是先卖后买"

两段不是对称的镜像，而是两个独立的操作段，由"不创新高或盘整背驰"这个切换条件连接。

### 5.2 做多与做空的结构性不对称

| 维度 | 做多（向上段） | 做空（向下段） |
|------|-------------|-------------|
| 入场条件 | 下跌背驰（1买） | 上涨背驰（1卖） |
| 持仓方式 | 实盘持股 | 融券/期货空头 |
| 降成本 | 短差级别卖高买低 | 短差级别买低卖高 |
| 时间特征 | 上涨慢，持仓时间长 | 下跌快，持仓时间短 |
| 信号可靠性 | 更高（回测验证：长做多77.8%胜率） | 更低（回测验证：双向65.5%胜率） |
| 仓位管理 | 1买可全仓（38课答疑第42行：touchnet问答） | 不全仓，分批建仓 |

### 5.3 向上段→向下段的切换机制

```
向上段运作中：
  while True:
    ...
    if 不创新高 or 盘整背驰:
      卖出全部多头仓位
      记录切换点价格
      切换到向下段
      break

向下段运作中：
  # 从切换点开始，第一次次级别反弹结束时建空仓
  # 操作逻辑是38课程式的镜像
  while True:
    ...
    if 不创新低 or 盘整背驰:
      买入平空
      记录切换点价格
      切换到向上段
      break
```

### 5.4 回测教训：做空的实际处理

纯做多版（QQQ +71.7%）显著优于双向版（QQQ +58.26%）。这意味着：

**设计选择：做空作为可选模式，默认仅做多。**

| 模式 | 向上段 | 向下段 |
|------|--------|--------|
| 纯做多（默认） | 正常操作 | 空仓等待（不做空） |
| 双向操作 | 正常操作 | 做空操作（需要融券/期货支持） |
| 保守做多 | 正常操作 | 空仓 + 在次级别做极短线反弹 |

切换条件不变——向上段结束后一定退出。区别在于向下段是主动做空还是被动等待。

## 第六部分：级别涌现

### 6.1 核心原则

级别不预设。不写死"L0=1min, L1=5min, L2=30min"。级别由PH persistence从数据中涌现。

### 6.2 涌现机制

```
输入：1min bar序列
步骤：
  1. BiEngine 逐bar生成笔（最低级别结构）
  2. OnlineMergeTree 计算所有bar的persistence权重
  3. 按persistence权重自然形成层级：
     - 最高persistence特征 → 方向级别（L_dir）
     - 次高persistence特征 → 操作级别（L_op）
     - 较低persistence特征 → 短差级别（L_cost）
  4. RecursiveStack 按persistence阈值驱动递归深度
```

### 6.3 PH递归停止条件

递归不无限展开。停止条件：

1. **alive特征数不足**：当前级别PH树的alive特征数 < 3，无法形成有效中枢
2. **persistence增量过小**：上一级到当前级的persistence增量 < 阈值，信息增量为零
3. **数据量不足**：当前级别的bar数量不足以产生稳定的PH结构

### 6.4 级别映射到38课程式

| PH涌现级别 | 38课角色 | persistence特征 |
|-----------|---------|----------------|
| L_dir（最高） | 大方向（向上段/向下段） | rank-1 settle方向 |
| L_op（次高） | 操作级别走势类型 | 中等persistence settle |
| L_cost（较低） | 短差级别（降成本） | 低persistence settle |

**验证等级标注**：级别涌现机制本身是L0（纯定义推导），其在真实数据上的有效性需要L2+验证。回测报告中L2方向翻转14-25次（vs L0的780次）已提供部分L2验证。

## 第七部分：状态机设计

### 7.1 顶层状态：方向段

```
┌─────────────┐        不创新高/盘整背驰         ┌─────────────┐
│   向上段     │ ──────────────────────────────→ │   向下段     │
│  (Bull Leg)  │                                 │  (Bear Leg)  │
│              │ ←────────────────────────────── │              │
└─────────────┘        不创新低/盘整背驰         └─────────────┘
        ↑                                                ↑
        │                                                │
   入场：下跌背驰                                   入场：上涨背驰
   （系统启动点）                                   （从向上段切换）
```

### 7.2 向上段内部状态机

```
                    ┌─────────────────────────────────────────────┐
                    │              向上段 (Bull Leg)               │
                    │                                             │
                    │  ┌──────────┐     U1内部背驰    ┌────────┐ │
                    │  │ HOLDING  │ ─────────────────→│WAIT_DIP│ │
   下跌背驰        │  │ (持有U1) │                    │(等D2)  │ │
```

### 7.3 完整状态定义

#### 状态 WAIT_ENTRY（等待入场）

| 属性 | 值 |
|------|-----|
| 触发条件 | 系统初始化，或从OBSERVE/EXIT转入 |
| 允许操作 | 无（纯等待） |
| 退出条件 | 操作级别出现下跌背驰（向上段）或上涨背驰（向下段） |
| PH角色 | 方向级别PH settle判断大方向；操作级别PH settle确认背驰段结构完成 |

#### 状态 ENTRY（建仓）

| 属性 | 值 |
|------|-----|
| 触发条件 | WAIT_ENTRY中操作级别背驰确认（区间套精确定位后） |
| 允许操作 | 买入（向上段）或卖出做空（向下段） |
| 退出条件 | 建仓完成 → 进入HOLDING |
| PH角色 | 短差级别PH settle精确定位入场价位（区间套最内层） |
| 仓位 | 1买全仓（向上段）；分批建仓（向下段） |

#### 状态 HOLDING（持有）

| 属性 | 值 |
|------|-----|
| 触发条件 | 建仓完成 |
| 允许操作 | 降成本循环（短差级别）；加仓（新的买点确认）；无操作（等待） |
| 退出条件 | 操作级别走势类型出现背驰/盘整背驰/不创新高 → 进入EVAL |
| PH角色 | 操作级别PH监控走势完成度；短差级别PH驱动降成本 |

HOLDING状态内嵌降成本子状态机：

```
┌─────────────────────────────────────────────┐
│            HOLDING 内部                      │
│                                             │
│  ┌──────────┐   短差PH卖信号   ┌──────────┐ │
│  │ FULL_POS │ ────────────────→│ REDUCED  │ │
│  │ (满仓)   │                  │ (已减仓) │ │
│  │          │ ←────────────────│          │ │
│  └──────────┘   短差PH买信号   └──────────┘ │
│                   (回补)                     │
│       ↓ 累计利润 > 本金                       │
│  ┌──────────┐                               │
│  │PRINCIPAL │                               │
│  │RECOVERED │                               │
│  │(本金回收)│                               │
│  └──────────┘                               │
└─────────────────────────────────────────────┘
```

#### 状态 EVAL（评估）

| 属性 | 值 |
|------|-----|
| 触发条件 | HOLDING中操作级别走势完成信号 |
| 允许操作 | 比较当前段与前一个同向段 |
| 退出条件 | 根据比较结果进入WAIT_DIP（回补等待）或EXIT |
| PH角色 | 操作级别PH settle确认走势完成；MACD面积比较背驰力度 |

评估逻辑（对应38课S7）：

```python
def evaluate(current_up_seg, prev_up_seg):
    if current_up_seg.high < prev_up_seg.high:
        return EXIT  # 不创新高，最弱，必须退出
    
    if is_consolidation_divergence(current_up_seg, prev_up_seg):
        return EXIT  # 盘整背驰，退出
    
    return CONTINUE_HOLDING  # 创新高且无背驰，继续持有
```

#### 状态 WAIT_DIP（等待回调）

| 属性 | 值 |
|------|-----|
| 触发条件 | EVAL判断可继续，但需等待回调买入 |
| 允许操作 | 监控回调段的深度和结构 |
| 退出条件 | 回调结束 → 根据是否跌破前低决定买入或观望 |
| PH角色 | 操作级别PH监控回调段是否settle |

#### 状态 OBSERVE（观望）

| 属性 | 值 |
|------|-----|
| 触发条件 | 回调跌破前低且无盘整背驰 |
| 允许操作 | 无（纯等待新的背驰） |
| 退出条件 | 新的下跌背驰出现 → 进入ENTRY |
| PH角色 | 方向级别PH判断大方向是否已切换 |

#### 状态 EXIT（退出）

| 属性 | 值 |
|------|-----|
| 触发条件 | EVAL判断不创新高或盘整背驰 |
| 允许操作 | 清仓；记录切换点 |
| 退出条件 | 清仓完成 → 切换到反向段的WAIT_ENTRY |
| PH角色 | 方向级别PH settle确认方向切换 |

### 7.4 状态转移表（向上段）

| 当前状态 | 事件 | 下一状态 | 操作 |
|---------|------|---------|------|
| WAIT_ENTRY | 操作级别下跌背驰 + PH settle | ENTRY | — |
| ENTRY | 区间套定位完成 | HOLDING | 买入 |
| HOLDING | 操作级别走势背驰/盘整背驰 | EVAL | — |
| HOLDING | 短差级别PH卖信号 | HOLDING(REDUCED) | 减仓 |
| HOLDING(REDUCED) | 短差级别PH买信号 | HOLDING(FULL) | 回补 |
| EVAL | 不创新高 | EXIT | 卖出 |
| EVAL | 盘整背驰 | EXIT | 卖出 |
| EVAL | 创新高+无背驰 | HOLDING | 继续持有 |
| EVAL | 需要等回调 | WAIT_DIP | — |
| WAIT_DIP | 不跌破前低 | ENTRY | 买入 |
| WAIT_DIP | 跌破+盘整背驰 | ENTRY | 买入 |
| WAIT_DIP | 跌破+无背驰 | OBSERVE | — |
| OBSERVE | 新下跌背驰 | ENTRY | — |
| EXIT | 清仓完成 | 向下段.WAIT_ENTRY | 切换方向 |

### 7.5 向下段状态机

向下段的状态机结构与向上段**同构但不对称**：

| 差异维度 | 向上段 | 向下段 |
|---------|--------|--------|
| ENTRY操作 | 买入 | 卖出做空 |
| HOLDING方向 | 持有多头 | 持有空头 |
| 降成本方向 | 高抛低吸 | 低买高卖 |
| 新高/新低 | 比较高点 | 比较低点 |
| EXIT操作 | 卖出 | 买入平空 |
| 默认模式 | 总是执行 | 可选（空仓等待） |

## 第九部分：回测执行计划

### 9.1 回测架构

```
回放式回测（非向量化）：

for bar in historical_bars:
    # 1. 引擎更新
    orchestrator.on_bar(bar)  # 递归产出笔→线段→中枢→走势→BSP
    ph_manager.on_bar(bar)     # PH树更新

    # 2. FSM消费事件
    events = event_bus.drain()
    for event in events:
        fsm.on_event(event)   # 状态转移

    # 3. 执行操作
    actions = fsm.get_pending_actions()
    for action in actions:
        position_manager.execute(action, bar.close)

    # 4. 记录
    trade_recorder.snapshot(bar, fsm.state, position_manager.position)
```

### 9.3 评估指标

| 指标 | 计算方法 | 基准 |
|------|---------|------|
| 累计收益 | 期末净值/期初净值-1 | Buy & Hold |
| 年化收益 | (1+累计收益)^(252/交易日数)-1 | Buy & Hold年化 |
| 最大回撤 | max(peak-trough)/peak | — |
| Sharpe比率 | mean(daily_return)/std(daily_return)*sqrt(252) | > 1.0 |
| 胜率 | 盈利交易数/总交易数 | > 60% |
| 盈亏比 | 平均盈利/平均亏损 | > 1.5 |
| 交易频率 | 总交易数/年 | 参考：多级别PH版约10次/年 |
| 降成本效果 | 累计降成本利润/初始本金 | > 0 |
| 本金回收率 | 到达本金回收状态的交易占比 | > 20% |

### 9.4 分阶段回测计划

**阶段一：纯做多验证**
- 只实现向上段FSM + 降成本
- 向下段 = 空仓等待
- 预期基准：超过纯做多版的QQQ +71.7%

**阶段二：增加区间套**
- 在阶段一基础上增加多级别精确定位
- 预期效果：入场/出场价位改善，同等信号下收益提升

**阶段三：增加做空**
- 向下段从空仓改为做空
- 预期：在熊市阶段产生正收益，但总体收益可能低于纯做多

**阶段四：降成本优化**
- 调整降成本仓位比例、短差级别选择
- 预期：持有期间收益提升，成本下降加速

### 9.5 与之前版本的对比设计

每个阶段都与以下基准对比：

| 基准 | 来源 |
|------|------|
| Buy & Hold | 被动持有 |
| H组日线版 | analysis/fugue_full_fsm_backtest.md（全亏） |
| 多级别PH双向版 | analysis/fugue_multilevel_ph_backtest_1min.md（QQQ +58%） |
| 纯做多版 | analysis/fugue_longonly_backtest_1min.md（QQQ +71.7%） |

### 9.6 避免的陷阱（来自回测教训）

1. **不要用日线**：H组日线版全亏，降成本周期在日线上完成太慢
2. **不要单级别PH**：L0级别780次方向翻转产生大量噪声交易
3. **不要分段重初始化PH**：分段回测中Bear/V-Recovery阶段因PH冷启动产生零交易
4. **不要对称做空**：做空信号可靠性显著低于做多
5. **不要用全历史Buy & Hold作为唯一基准**：全历史压缩后"逊于buy-hold"的结论不可证伪（见memory: project_backtest_benchmark_falsifiability）
