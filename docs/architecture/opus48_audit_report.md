## 第一部分：回测代码中的潜在 Bug（最关键）

### A1 — 降成本被建模为"只赚不赔的提款机"【CRITICAL，未修复】

**位置**：`analysis/full_system_backtest_v3.py:208` `_cr_profit_dollars` 末行 `return max(0.0, profit - comm)`；累加点 `:767` `cumul_cr_dollars += profit`；并入收益 `:177/:182` `net = gross - comm + cumul_cr_dollars`。v1 同构（`cost_basis` 反复下调）。

**机制**：每一次降成本 trim 循环的"利润"被 `max(0.0, …)` 截断到非负——价格往哪个方向走，trim 都只贡献 ≥0 的美元，绝不扣减。`cumul_cr_dollars` 无上限累加，最后直接进入单笔 PnL 的分子。于是：

```
单笔 PnL% = (gross - comm + Σ max(0, trim_profit_k)) / INITIAL_CAPITAL × 100
```

OKLO 第 7 笔交易就是铁证（diagnosis 自己记录）：做多 $9.99 入场、$7.86 出场（**价格跌 21%**），本应是亏损单，却因 **155 次** trim 循环把 cost_basis 压到 $7.04，最终 PnL = **+8.20%**。一笔价格下跌 21% 的多头交易录得正收益——这在数学上只可能来自"只赚不赔"的 trim 累加。

**为什么这是 bug 而非"建模假设"**：`full_system_diagnosis.md` 把 +65178% 归因于"L0 事件密度高 + 无交易成本 → 微利复利膨胀"，并称"不改变修复的正确性"。这是**误诊**。真实价格序列里，高抛低吸的短差有赚有赔——把每次循环 clamp 成非负，等于假设交易员拥有完美的择时（每次 trim 都不亏）。这不是"零成本假设"的问题，是**前视式的完美短差假设**，属于隐性 look-ahead。加交易成本也救不了它：只要 `max(0.0, …)` 在，循环次数足够多，收益仍会膨胀。

**边界条件（结论翻转点）**：去掉 `max(0.0, …)`、让 trim 利润可正可负，并让 `cumul_cr_dollars` 在亏损 trim 时减少——OKLO/BTC/HK700 的天文数字会崩塌，很可能转负。这是验证本结论的唯一充分实验。

**修复方向**：删除 `max(0.0, …)`；trim 利润按真实成交方向计算（可正可负）；`cumul_cr_dollars` 双向累加。不要加分支补丁——重写 trim 利润计算。

### A2 — 空头降成本触发方向仍错（diagnosis 的"已修复"是表面修复）【CRITICAL】

**位置**：`full_system_backtest_v3.py` `_try_open_trim:736-753` / `_try_close_trim:755-773`。

**diagnosis 声称的修复**：在 `_cr_profit_dollars` 内对 `direction==1/-1` 分了符号支（`sell-buy` vs `buy-sell`）。这只修了**利润公式的符号**。

**未修的部分（触发逻辑）**：
- 空头 `_try_open_trim` 在 `cr_trigger_down`（价格下跌）时开 trim，记 `trim_sell_price = c`（低价）。
- 空头 `_try_close_trim` 在 `cr_trigger_up`（价格上涨）时平 trim，调用 `_cr_profit_dollars(direction=-1, sell_price=低, buy_price=高)` → `(buy-sell) = (高-低) = 正`。

但空头降成本的**正确**操作是：价格**下跌**（对空头有利、浮盈扩大）时**买回**部分空单锁盈；价格**反弹**时**重新卖空**。代码却在下跌时"卖"（open）、上涨时"平"——语义对空头是反的。subagent 实跑确认：`SHORT trim 90->100 (价格上涨): booked profit = 5455`——一个空头持仓在价格上涨（明明亏钱）时被记 +5455 美元利润。

**判定**：diagnosis 的"Bug 1 已修复"是**声明膨胀**。它修了能让代码"看起来对称"的符号，回避了真正的方向矛盾（触发条件 + trim 语义），并用 `max(0.0,…)` 把残余错误掩盖成正收益。**+65178% / +15021% 这些"修复后"的数字本身就是 bug 仍在的证据**——一个在涨 3.5 倍的 OKLO 上做 84 笔空头的策略，不可能合法地赚 650 倍。

**这违反两条蜂群语法规则**：`no-workaround.md`（模糊化处理让矛盾通过）+ `no-patch-mentality.md`（声明代码不具备的能力 / 补丁思维）。正确处理应是 `/escalate`：空头降成本的方向是定义问题（38 课"向下段降成本是低买高卖"如何精确映射到 trim 的 open/close 触发），不是实现 bug。

### A3 — "去掉加仓后收益暴增"是加仓 bug，不是金融发现【HIGH】

**位置**：`fugue_enhanced_addon_backtest_1min.py:713-721`（加仓时 `entry_bsp_ids.update(new_bsp_ids)`）；退出判据 `fugue_no_addon_backtest_1min.py:585`（`any(bid in entry_bsp_ids for bid in buy_invalidates)`）。

**根因（subagent 追踪 + 我复核）**：加仓把新的 BSP id 并入持仓的 invalidate 监控集 → HOLDING 态首要退出条件被更多 BSP 触发 → 交易被**提前砍断**。对比数据：
- 有加仓版：几乎全部 `exit=bsp_invalidate`，平均持仓 ~7121 bars。
- 无加仓版：大量 `exit=consolidation_divergence`，平均持仓 **17875 bars**（吃到完整趋势段）。

QQQ 交易#1 入场点相同（@45988），有加仓版 -0.35% / 3517 bars，无加仓版 +7.61% / 28576 bars——**同一笔交易因加仓被砍短**。

**判定**：背景声明"去掉加仓后暴增 → 加仓是负 alpha"是**误诊**。暴增暴露的是加仓实现的副作用 bug（污染 invalidate 集），不是"加仓无用"的金融结论。把 bug 现象解释成策略结论，会导致错误的设计决策（永久删除加仓）。

**修复方向**：加仓不应把新 BSP 并入主仓的 invalidate 监控集，或主仓退出判据只认建仓时的 BSP。修后重测加仓的真实贡献。

### C1 — ES 期货 15x 杠杆但永不强平【HIGH】

**位置**：`full_system_backtest_v3.py:87-89`（`max_contracts=6, point_value=50, margin=15000`）+ `:560`（`liq_move=0.0 → _check_liquidation return False`）。有效杠杆 ~15x（@5000 名义 150 万 / 本金 10 万），但任何回撤都不爆仓。所需保证金 90000 ≈ 全部本金，无波动缓冲。**修复**：按 margin/notional 设真实强平（约 6-7% 反向即爆）。

### C2 — 同 bar 收盘信号 + 同 bar 收盘成交【MEDIUM】

**位置**：`v3:644-700,724`。信号在 bar `i` 收盘判定，成交价也用 `closes[i]`。1min bar 的收盘只在 bar 结束时确定，实盘无法在确定收盘的同一瞬间以该价成交。**与 ROADMAP §关键设计原则 5「严格因果……零前视」声明直接冲突。** 未检测到使用 `i+1` 及以后数据（非未来 bar 前视），但同 bar 执行假设系统性高估可成交性，对数百笔/标的的高频策略累积偏差显著。**修复**：成交价改 `opens[i+1]`。

### 代码层其他确认项（已正确，记录在案）

- **加仓未引入额外退出触发器**（组合版无加仓，trim 不平主仓）：`v3:755-773` 正确。
- **手续费已计入**（v1 `FEE_RATE=0.001` 出入场各计 + trim 计费；v3 区分期货固定佣金/现货 0.1%）：正确。**但** v1 报告 `full_system_backtest.md:9` 写"0.1% 手续费"而 `:342` 写"无滑点/手续费"——报告自相矛盾（MEDIUM）；**滑点完全未建模**。

## 第二部分：设计层面的问题

### B3 — PH settle 被用作门控，违反系统自己的边界声明【HIGH，自相矛盾】

`ROADMAP.md:50` 和 `memory: project_ph_settle_usage_boundary` 都明确：**"PH settle 是买卖点 candidate 层的必要条件，不是操作充分确认。用作退出/入场门控是越界"**（521 号谱系：PH 纯拓扑无动量）。

但 `complete_fugue_design.md` 通篇把 PH settle 用作门控：
- `:157` "PH 树 settle 阈值 → 该级别走势完成"（走势完成 = 退出门控）
- `:170` "操作级别 PH settle 事件 = 操作级别走势类型的结构性终点"
- `:175` "短差级别 PH settle 事件 → 减仓/回补时机"（入场/退出门控）
- 状态机 `:514-528` 多处转移条件含"PH settle"。

**这是设计内部的硬矛盾**：系统一边声明"PH settle 用作门控是越界"，一边把整个 FSM 的转移建立在 PH settle 门控上。组合版甚至用 **L0 PH settle**（每 1min bar）触发降成本——这是最严重的越界（L0 噪声 + 门控 + A1 提款机 = 收益膨胀三重共振）。

**处理**：应 `/escalate`。要么修订 521 号边界（PH settle 可作门控的条件是什么），要么重构 FSM 不依赖 PH settle 作转移条件。当前是"两种矛盾理解都能通过"的模糊态。

### B4 — 走势方向代理陷阱（设计声明 vs 代码实现不一致）【MEDIUM】

`ROADMAP.md:118` + `memory: project_trend_direction_proxy`：**"走势方向用中枢定义（缠论正典），不用 swing 笔端点代理"**。

但代码 `full_system_backtest_v3.py:250-262` `_extract_sigma` 取 `rs.moves[-1].direction`（最后一个 move 的方向）作为 σ（K4 选股方向），且降成本 L1 触发用笔端点 `strokes_now[si].p1`（`:614`）。取"最后一个 move 的瞬时方向"代理"当前走势方向"，会把次级别回抽误判为走势反向，导致 σ 频繁翻转（ES sigma cache 显示 2024-01 一个月翻转十余次）。

**需先确认**：`a_move_v1.py` 的 `Move.direction` 究竟由中枢序列（中心位移）定义，还是由端点高低定义？若是后者，则是定义冲突（escalate）；若是前者，则取 `moves[-1]` 作瞬时 σ 仍是越级代理（实现层可修）。本审计未在 `.chanlun/genealogy` 逐条核对是否已有结算记录。

### B1 — M2 选股层的核心经济假设被真实数据反向证伪【HIGH】

`m2_selection_layer.md` 的 regime×polarity 决策矩阵建立在："ω 下降=信用扩张=利好股票（BULL_EQUITY）"。M2 把 `omega_regime 定义` 标注为 **L2**（"2025-02-20 regime 断点在真实数据中确认"）。

但 K4-subagent 补做了正经检验（statsmodels），结果**否证**了这个方向：
- ω 上升期 SPY 前瞻 20 日收益**反而更高**（1.41% vs 1.08%），方向与"信用收缩=美股谨慎"**相反**。
- Welch t 检验 p=0.069（不显著，且重叠窗口使 p 偏乐观）。
- regime 分组收益（1.29%-1.57%）与 SPY 无条件基准率（任意 20 日 mean=1.26%，70.3% 为正）**统计不可区分**。
- ω~SPY 日收益相关系数仅 -0.2164，60 日滚动在 -0.77~+0.78 间来回翻号（无稳定关系）。

**判定**：M2 把一个 **L2 否定性结果**（ω 方向预测在真实数据上被否证）标注成了 **L2 确认性结论**。这违反 `formalization-validity-domain.md` 禁止模式 1（有效域膨胀）。注意：M2 的 `asset_classifier`（指数 long_only）本身是稳健的 L2 结论；问题在 `omega_regime` 这一层。

**边界条件**：若换更长样本 / 不同代理变量后 ω 方向预测显著且方向正确，则 B1 翻转。当前数据上不成立。

### 设计文档其他问题

- **降成本的金融工程化 vs 缠论语言封闭性**（设计内部张力）：`ROADMAP.md:345` 声明"不引入外部金融工程概念（止损线、ATR）"，但"本金回收（PRINCIPAL_RECOVERED）""累计利润>本金"（`complete_fugue_design.md:456`、`:230`）是仓位管理金融工程概念。38 课确实讲"分区卷钱"和"变负成本"，但把它形式化为"`cumul_cr_dollars >= INITIAL_CAPITAL`"的数值状态转移，恰好制造了 A1 可被利用的提款机结构。建议：降成本状态应基于走势结构（短差级别走势完成），而非美元阈值。
- **设计↔回测时间线倒置**：`complete_fugue_design.md`（06-05）自称"纯设计，不编码"，却已引用大量回测数字（QQQ +71.7% / +58.26%），并据此下"默认仅做多"结论（`:303-305`）。而 06-05 之后的回测又大量启用做空。设计文档实为"事后合理化"，非"先设计后验证"——这削弱了"设计驱动"的声明。
- **测试标的漂移**（C4 关联）：设计 `:628-636` 列 QQQ/SPY/GLD/BRENT/HK700（2019-2025）；实际组合回测用 QQQ/OKLO/HK700/BTC（2024-2026）。设计列的 SPY/GLD/BRENT（稳健标的）被替换成 OKLO（2023 上市的小盘核电暴涨股）/BTC（3 年大牛）——幸存者偏差（见 A4）。

## 第三部分：K4 六边递归审计（B2）

`analysis/k4_ratio_recursive_report.md` 自标注 **L2**（`:188`）。实际：

- **拓扑提取部分 = L1**（管线验证，信息增量零）：脚本只对 6 条比价序列各跑一遍缠论引擎读出"当前 move 方向"再求和成极性指数 S。**无任何假设检验**。"真实数据"是 L2 的必要不充分条件——L2 的充分条件是"可证伪的假设检验"，此处缺失。
- **C(4,2)=6 是 L0 同义反复**：6 条边的"存在"是组合数学定义出来的，不是数据发现。报告把它当结构发现。6 条边中被真实验证过有协整关系的数量 = **0**（subagent 实测 Engle-Granger，全部配对 p>0.21，gld~uso 与 spy~uso p=1.0000）。
- **核心理论"L=M×ω 与 GDP 协整"从未检验**：grep 全部 K4 文件 + `omega_regime.py`，无 GDP、无 cointegration、无 ADF/Johansen、无 p-value、无 Bonferroni。"GDP 协整"只存在于 `omega_regime.py:8` 的 docstring。GDP 根本没进入任何计算。
- **"递归"名实部分相符但与理论脱钩**：缠论引擎的多级别递归（笔→线段→中枢→走势）在框架内是真自相似构造，但它是**每条边独立**跑的，没有跨边/跨尺度耦合，谈不上"K4 的递归"；且只输出趋势标签，与金油比经济理论的验证完全脱钩。
- **p-hacking**：L2 验证脚本做了 4 regime × 4 窗口 = 16 单元格 + 6 相关系数，**零多重比较校正**。唯一偏离基准的 bull_equity→neutral（2.47%, n=19）正是 16 格里挑出的那一个。
- **provenance 矛盾**：`fetch_k4_futures.py` 声称用连续期货（ES/GC/CL），但报告实际消费 ETF（SPY/GLD/USO/UUP）；期货文件在报告生成后才落盘，从未被使用（spec-execution-gap）。
- **节点定义不一致**（C5）：`ROADMAP.md:58` 写 K4=(E/Au/R/$)（第四锚是利率 R），K4 报告用 (E/Au/Oil/$)（第四锚是美元 $，油是 Oil）。两处定义冲突。

**判定**：K4 拓扑管线是 L1 真实有效的工程产出；但所有 L2 经济结论（协整 / regime 预测 / "流动性危机信号"）要么从未检验，要么在自己的数据上被否证，被以确认语气包装——有效域膨胀 + p-hacking。`report §5` 的"信用扩张期 / 流动性危机信号"等措辞无统计支撑，应删。

## 第六部分：对跨国 K4 拓扑与配置空间递归的独立思考（Opus 原创，L0）

> 本节是 Opus 4.8 应用户要求的独立理论思考，认识论等级 L0（理论构造），需 L2 验证。它同时是对当前 K4 设计的建设性重构方向。

### 6.1 当前 K4 的隐藏前提：单一美元区

当前 K4 = {E（股）, Au（金）, Oil（油）, $（美元）}，四节点全部以美元计价。这等于把"全球资本旋转"压缩进**单一货币区**。但卢麒元框架的核心——资本三流、金油两锚、空转压价——本质是**跨货币区**的：资本从一个主权货币区旋转到另一个，金/油是穿越所有货币区的两个全球不变锚。当前 K4 缺了"跨国"这一维，于是只能看见美元内部的资产轮动，看不见资本的国际旋转（这正是用户押注"金油比下降"背后的真实变量）。

### 6.2 跨国 K4 的正确拓扑：不是笛卡尔积，是共享 $ 顶点的纤维丛

朴素扩展是 K4_US × K4_CN × K4_EU（笛卡尔积），但这会把维度炸成 3×6=18 条边，落入 B2 的 p-hacking 陷阱。**正确的拓扑结构由卢麒元框架的约束给出**：

- **金（Au）和油（Oil）是全球公共节点**——它们不属于任何货币区，是穿越所有货币区的不变锚。
- **每个国家贡献两个本地节点**：股指 E_i 和本币汇率 FX_i（本币/$）。
- 于是结构不是 3 个独立 K4，而是一个**以 {Au, Oil, $} 为公共底、各国 (E_i, FX_i) 为纤维**的图——拓扑上是沿公共锚的 **wedge sum / 纤维丛**（ROADMAP 已有 `topology/fiber_bundle.py`，但当前未用于此）。

形式化：底空间 B = {Au, Oil}（两个全球锚构成的"温度计平面"），纤维 F_i = 国家 i 的 (E_i, FX_i)。资本的国际旋转 = 纤维在底空间上移动时的**和乐（holonomy）**——资本绕一圈（US→CN→EU→US）后，财富是否守恒，由这个和乐的非平凡性度量。**空转（MCM' 对 P 的寄生）= 和乐 ≠ 恒等**：资本旋转一圈不创造价值却改变了价格分布。这给了"空转"一个可计算的拓扑定义，远比当前的极性指数 S 深刻。

### 6.3 配置空间递归的真正含义（修正当前实现）

K4-subagent 正确指出：当前"递归"只是"在多个时间窗口重复跑同一引擎"，不是真递归。**真正的配置空间递归应该是：配置 Γ 的时间序列本身具有缠论结构。**

- 当前：Γ(t) = (σ_E, σ_Au, σ_Oil) ∈ {↑,↓,0}³，极性指数 S = Σσ。这是一个**瞬时快照**。
- 递归版：把 Γ(t) 的轨迹当作一条新的"价格序列"喂回缠论引擎——Γ 自己走出笔、中枢、走势。**"regime 切换"= Γ 序列的走势级别背驰**。这才是"递归"：缠论引擎作用于自己的输出（配置空间），层层上升。这与 526 号"a0 递归存在论区分"和 ROADMAP「五层递归」同构——只是递归的对象从价格升格为配置。
- 跨国版：底空间和乐 holonomy(t) 也是一条序列，对它再跑缠论 → 国际资本旋转的"超级走势"。

### 6.4 降维：卢麒元约束作为先验，避免 p-hacking

跨国会把边数炸开（B2 风险）。但卢麒元框架本身提供了**强先验降维**：不需要检验所有 C(n,2) 条边，只需检验**各国资产相对两个全球锚（Au、Oil）的投影**。即把每个国家 i 的状态投影到 (E_i/Au, E_i/Oil, FX_i/Au, FX_i/Oil) 四个比值——这是 4 个有经济含义的自由度，而非盲目的多重检验。两个全球锚 = 2 维底空间 = 把高维配置空间约束到一张曲面上。这正是 230 号"直积在概率度量下退化为 <3 自由度"的正面应用：**先验约束先于检验，而非检验后挑显著的**。

### 6.5 对用户交易方向的启示

用户押注"金油比 ω 下降（油涨）+ 超大级别周线线段一买"。在跨国 K4 框架下，这等价于一个明确的拓扑命题：**底空间从"金强"区域向"油强"区域的迁移，且这个迁移在最高递归级别（周线）的 Γ 走势上构成一买（下跌背驰后的第一段向上）**。这把一个宏观直觉转化为可在跨国 K4 配置空间上递归验证的结构命题——但前提是先修好第一部分的回测引擎，否则任何"验证"都被 A1 提款机污染。**注意 B1 的警告**：当前数据上 ω 方向预测被反向证伪，所以这个押注在统计上尚无 L2 支持——它可能是对的（样本/代理变量问题），也可能是需要修正的方向。跨国 K4 的真正价值是给出一个**可证伪的检验框架**，而不是为既有直觉背书。
