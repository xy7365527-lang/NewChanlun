## 2. 样本切分（日期冻结，不可事后调）

采用**固定日历切分 + walk-forward**双轨。所有日期为各品种数据可用范围内的日历日期，**对所有核心/扩展池品种统一**（OKLO 因短历史单独处理，见 §2.4）。

### 2.1 全局固定切分（按日历日，UTC）

| 段 | 区间 | 用途 |
|----|------|------|
| **In-Sample (IS)** | 各品种起始 → **2022-12-31 23:59Z** | Θ v0 已固定（无拟合自由度），IS 仅用于管线 sanity check 与 §6 扫描的训练窗 |
| **Out-of-Sample (OOS)** | **2023-01-01 00:00Z → 2025-06-30 23:59Z** | 主检验窗。§5 失败判据在此窗评估 |
| **Holdout（封存）** | **2025-07-01 00:00Z → 数据末尾** | 封存窗。**在 OOS 检验完成并归档前禁止访问**。仅用于最终一次确认，访问即记录于 §9 |

> 说明：Θ v0 本身**无可拟合参数**（所有数值是[设计选择]或[L3经验待标定]默认值），因此 IS/OOS 划分的作用不是"训练 vs 测试参数"，而是隔离 §6 Θ 空间扫描（会引入选择自由度）的训练窗与确认窗。Θ v0 原样运行时，IS 与 OOS 都是 out-of-sample（无拟合），核心判据看 OOS。

### 2.2 Walk-Forward 窗口（冻结）

对核心池每个品种，从各自起始日起，滚动执行：

- **训练窗（train）**：24 个日历月
- **检验窗（test）**：6 个日历月
- **步进（step）**：6 个日历月（test 窗不重叠）
- **anchored 模式**：train 窗起点固定为品种起始（扩张窗），test 窗滚动。同时跑 **rolling 模式**（train 窗固定 24 月滚动）作对照。

每个 test 窗独立计算 §3 全部指标，输出窗序列。Θ v0 无参数，walk-forward 的作用是检验**性能时间稳定性**（性能是否集中在个别窗），不是参数再优化。

### 2.3 切分防漂移约束

- 切分日期一旦写入本文件即冻结。看到结果后想改 OOS 起点/Holdout 边界 = 事后解释，**禁止**，走 §9。
- 不允许"挑选表现好的时段报告"。所有 walk-forward 窗的结果**全部报告**，不允许只报子集。

### 2.4 OKLO 特例（预注册）

OKLO 仅 2.1y，无法支撑 24+6 月 walk-forward。OKLO **不进入主判据**，仅做单段 OOS（2025-01-01 → 数据末尾）的探索性观察，结果标注"短历史，不计入强否证"。

## 3. 指标（全部预注册，全部报告）

每个检验窗（OOS 整窗 + 每个 walk-forward test 窗）计算下列**全部**指标。不允许只报有利指标。

### 3.1 收益与风险调整

| 指标 | 定义 | 备注 |
|------|------|------|
| CAGR | 几何年化收益 | 扣成本后 |
| Sharpe | 年化超额收益 / 年化收益标准差，rf=0 | 按 1min→日聚合 returns 计算，年化因子按各品种实际交易日 |
| Sortino | 年化超额收益 / 下行标准差 | 同上 |
| MaxDD | 最大回撤（峰谷） | 基于权益曲线 |
| Calmar | CAGR / |MaxDD| | |
| CVaR(5%) | 5% 尾部条件期望亏损（日 returns） | 尾部风险 |

### 3.2 交易行为

| 指标 | 定义 |
|------|------|
| 交易次数 | OOS 窗内完整开平仓次数 |
| 换手率 | 年化名义成交额 / 平均 NAV |
| 胜率 | 盈利交易 / 总交易 |
| 盈亏比 | 平均盈利 / 平均亏损（绝对值） |
| top-5 交易占比 | 收益最高 5 笔交易的盈亏和 / 总盈亏（§5 失败判据用） |

### 3.3 容量与成本敏感性

| 指标 | 定义 |
|------|------|
| 容量估计 | 在不使单笔成交额超过该 bar 成交量 X%（X=1，[设计选择]）前提下的最大可部署 NAV |
| 费用敏感性 | 在 commission/slippage 分别 ×{0.5, 1.0, 2.0, 3.0} 下重算 Sharpe 与 CAGR。基线 = Θ_exec 默认（commission 1bp/side、slippage 2bp/side、tax 0bp） |

> 费用基线引用 reference-theta-v0.md Θ_exec，标 [L3经验待标定]。费用敏感性曲线是 §5.4 失败判据的输入。

### 3.4 统计显著性

- 对每品种 OOS 的日 returns 序列，计算 Sharpe 的标准误（Lo 2002 调整，考虑自相关），报告 Sharpe 的 95% 置信区间。
- bootstrap（block bootstrap，块长 = 20 个交易日，n=1000）重采样交易序列，输出 CAGR/Sharpe 的经验分布与 p 值（H0：收益 ≤ 0）。

## 4. Benchmark（预注册对照）

每品种、每检验窗，Θ v0 策略必须与下列对照同窗对比：

| Benchmark | 构造 | 作用 |
|-----------|------|------|
| **Buy & Hold** | OOS 窗起点满仓多头持有至窗末，扣同等费用 | 收益基线。Θ v0 风险调整收益须显著超过 B&H 才有信息 |
| **随机入场对照** | 保持 Θ v0 的交易频次、持仓时长分布、仓位规模分布不变，但**入场时点随机化**（n=1000 次蒙特卡洛）。输出随机策略的 Sharpe/CAGR 分布 | 检验 Θ v0 的择时是否携带信息。若 Θ v0 的 Sharpe 落在随机分布的 95% 区间内 → 择时无信息（§5.3 触发） |
| **方向打乱对照**（补充） | 保持入场时点不变，随机翻转每笔交易方向（n=1000） | 隔离"方向判断"的贡献 |

随机对照的随机数种子在本文件冻结：**seed = 20260625**（codex 裁决日）。重跑必须用同一 seed 以保证可复现。

## 5. ★失败判据（预注册，关键）

**以下判据在看任何结果前冻结。** 对**核心池**（BTC/ES/CL/GC）的 **OOS 窗**评估。满足**任一**条即判定 Θ v0 **在该品种该市场失败**。判据按品种独立评估，然后按 §5.6 汇总。

### 5.1 风险调整收益不显著（扣成本后）

OOS 窗扣全部成本后 **Sharpe < 0.5**，或 §3.4 bootstrap 的 CAGR>0 单边 p 值 **> 0.05**（即无法在 5% 水平拒绝"收益≤0"）。

### 5.2 收益集中依赖少数交易

**top-5 交易盈亏占总盈亏 > 50%**（X=50%，预注册阈值）。收益由极少数交易支撑 = 不可重复 = 失败。
（补充报告 top-1 占比与去掉 top-5 后的 Sharpe，但判据锚定 top-5>50%。）

### 5.3 分支覆盖但不携带可交易信息

Θ v0 的 OOS Sharpe **落在 §4 随机入场对照分布的 95% 区间内**（即择时不优于随机）。结构分支被触发、状态机走完，但收益与随机择时无统计差异 = 分支不携带可交易信息 = 失败。

### 5.4 收益只来自不可执行假设

下列任一成立即触发：
- **费用悬崖**：§3.3 费用敏感性中，成本 ×2.0（= Θ_risk 的 κ=2.0 成本倍数对应的保守场景）时 **Sharpe 由 ≥0.5 跌至 < 0**——收益只存在于不现实的低成本假设下。
- **容量坍塌**：§3.3 容量估计 < 单笔最小可交易规模（即任何真实下单都会超过 bar 成交量 X%），收益不可部署。
- **执行延迟敏感**：将 Θ_exec 的"延迟 1 根 K，下一根 open 成交"改为"延迟 2 根 K"后，Sharpe 跌幅 > 50%——收益依赖不可实现的即时执行。

### 5.5 不可交易豁免（防伪失败）

若某品种 OOS 窗内**不可交易 bar 占比 > 20%** 或 Θ v0 产生的交易次数 **< 30**，该品种判据**不评估**（样本不足），标注"inconclusive"，不计入 §5.6 的成功/失败计数。这防止把数据缺陷误读为策略失败。

### 5.6 品种级汇总与 Θ v0 整体判定

- **单品种失败**：满足 §5.1–5.4 任一条。
- **Θ v0 在核心池失败**：核心池 4 品种中 **≥3 个失败**（OKLO 不计，inconclusive 不计入分母）。
- **Θ v0 在核心池存活**：≥2 品种通过全部判据（Sharpe≥0.5、p≤0.05、top-5≤50%、超越随机、成本/容量/延迟稳健）。存活**不等于**"缠论被验证"——只是"该 Θ 在该周期该成本下未被证伪"，进入 §6 稳健性扫描。

> **诚实声明**（强制）：核心池失败只否定"Θ v0 + 本协议 + 这四个市场 + 1min + 这套成本"。**不否定缠论**，**不否定其他 Θ**。只有 §6 系统扫描后无稳健区域才接近强否证（且仍受品种池/周期/成本边界约束）。

## 6. Θ 空间稳健性扫描设计（Phase 6）

仅在 §5 核心池存活后执行。**只扫有理论理由的维度**（拒绝无理由的网格暴搜 = 拒绝过拟合制造机）。

### 6.1 可扫描维度（每维附理论理由）

| 维度 | 扫描点 | 理论理由（为何这是合法自由度） |
|------|--------|-------------------------------|
| 分型确认 | 第 3 根 K 收盘确认 vs 第 3 根 K 触及即确认 | reference Θ_parse 标"第三根 K 收盘确认"为可导但确认时点是边界选择 |
| 笔的 K 数门槛 | 排除两端至少 {3, 4, 5} 根 | Θ_parse 新笔"至少 3 根"，松紧影响笔密度 |
| 线段缺口规则 | 67 课特征序列"有缺口等反向确认" vs 严格直接确认 | Θ_parse 线段缺口处理是可导但有实现自由度 |
| 结构止损位置 | pivot low vs pivot low − {0, 0.5, 1}×ATR 缓冲 | Θ_risk 结构止损触发是[设计选择] |
| 单声部风险 ρ | {0.0025, 0.005, 0.01} NAV | Θ_risk ρ 标 [L3经验待标定] |
| 父子仓位比 β | {0.3, 0.5, 0.7} | Θ_risk β 标 [设计选择] |
| 执行延迟 | {1, 2} 根 K | Θ_exec 延迟标 [设计选择] |
| 费用/滑点 | commission×{0.5,1,2}, slippage×{0.5,1,2} | Θ_exec 标 [L3经验待标定] |

**禁止扫描**：标 [缠论可导] 且无实现自由度的维度（如 K 线包含合并规则、中枢 ZD/ZG 公式）——这些是缠论真理不是参数，扫它们 = 篡改定义，走 /escalate 而非扫描。

### 6.2 扫描判读（三分类，预注册）

每个扫描配置在 OOS 上计算 §3 指标，将 Θ 空间分为：

| 区域 | 定义 | 判读 |
|------|------|------|
| **稳健区域** | 连通的参数子空间内，全部配置 Sharpe ≥ 0.5 且相邻配置性能平滑（无悬崖） | Θ v0 附近存在稳健盆地 = 弱支持 |
| **过拟合尖峰** | 孤立高 Sharpe 点，相邻配置性能急剧下降 | 高分是噪声 = 不可信，等同失败 |
| **全域失败** | 全部扫描配置 Sharpe < 0.5 | Θ 空间无可行域 = 接近强否证（受 §6.4 边界约束） |

判读基于 IS 窗扫描（训练）→ OOS 窗确认（§2.1 隔离）。仅 OOS 确认了 IS 选出的稳健区域才算稳健。

### 6.3 多重检验校正

扫描引入多重比较。报告的最优配置 Sharpe 必须经 **Deflated Sharpe Ratio**（Bailey & López de Prado）或等价的多重检验校正后仍显著。未校正的"扫出来的最高 Sharpe"无效。

### 6.4 强否证的边界（诚实）

§6 全域失败 + §5 核心池失败 ⟹ "Θ v0 家族在 {核心池四市场, 1min, 本成本结构, 2023–2025 OOS} 上无稳健可交易区域"。这是本协议能达到的**最强否定**，但**仍不否定缠论**——缠论可能在其他级别、其他 Θ 实例化、其他市场上成立。强否证的有效域 = 本协议的扫描域，不外推。

## 7. 分支有效性检验设计（Phase 5）

检验"条件决策质量"，**不是**"点预测准确率"。Θ v0 是状态机：每个未完成状态分支（`PendingFractal/PendingStroke/PendingSegment/AliveCenter/PendingMove`，见 reference Θ_parse §未完成尾部）的价值在于"在该状态下采取条件动作的期望收益"，而非"预测下一根 K 涨跌"。

### 7.1 每分支记录的量

对 OOS 窗内每个状态分支的每次激活，记录：

| 量 | 定义 |
|----|------|
| 出现频率 | 该分支在 OOS 窗激活次数 / 总 bar 数 |
| 后验分布 | 进入该分支后，结构如何收敛（确认/失效/超时）的经验分布 |
| 条件动作收益 | 在该分支触发的交易（或加减仓）的收益分布（均值、标准差、分位数） |
| 风险贡献 | 该分支贡献的回撤 / 总回撤；该分支交易的 CVaR |

### 7.2 分支有效性判据（预注册）

- **携带信息的分支**：条件动作收益均值显著 > 0（block bootstrap p ≤ 0.05），且 Sharpe 贡献为正。
- **无信息分支**：条件动作收益与随机择时无差异 → 标记为"分支被覆盖但不携带可交易信息"（喂回 §5.3 整体判据）。
- **负贡献分支**：收益均值 < 0 或风险贡献 > 收益贡献 → 标记，作为 §6 扫描的优先收紧目标（不在本协议内删分支——删分支 = 改 Θ，走 change-request）。

### 7.3 检验的诚实边界

分支有效性是**描述性**的（这些分支在 OOS 上表现如何），不是**规范性**的（不据此自动改 Θ）。任何"某分支没用所以删掉"的结论必须走 §9 重新预注册——否则就是用 OOS 结果反向拟合 Θ。

## 结果包（六要素）

1. **结论**：本协议预注册了 Reference Θ v0 在 8 个真实 1min 品种上的可证伪检验框架——固定数据快照（§1）、不可事后调的样本切分（§2，OOS=2023-01-01→2025-06-30，Holdout 封存）、全套指标（§3）、buy&hold+随机入场+方向打乱对照（§4）、4 条预注册失败判据（§5，Sharpe<0.5 / top-5>50% / 不优于随机 / 成本-容量-延迟脆弱）、分支条件决策质量检验（§7，非点预测）、只扫有理论理由维度的 Θ 稳健性扫描（§6，含 Deflated Sharpe 多重检验校正）。
