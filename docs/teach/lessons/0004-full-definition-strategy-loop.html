全定义策略闭环 S_Θ

第 0004 课 · 从「60 个零件并排放着」到「一条会自己转下去的环」

前三课讲的是分类（走势怎么被穷尽地分）。这一课讲分类之后—— 分类怎么驱动动作，动作怎么改变状态，状态怎么再喂回分类。 这是「策略」第一次被写成一个闭合的环，而不是一串互不相干的定理。 关键问题只有一个：把零件接成环，到底多买到了什么？这一课让你能逐字回答。

1. 病灶：我们有 60 个零件，但它们是「并排合取」的

蜂群已经形式化了一长串组件——解析、分类、赋格、风险投影、执行…… 它们被一条「链总定理」收口（Strict/Chain.lean:330）。但这条链的形状是这样的：

theorem chanlun_chain_total_unique (CC θ x z) :
  (∃ s, globalClassify CC.components x = s ∧ …)   -- C_Θ 侧
  ∧
  (∃ o, CC.family.π θ (CC.toHist x) z = o ∧ …)     -- π_Θ 侧
看那个 ∧。它把「分类唯一」和「策略唯一」并排放在一起，用合取拼起来。 但 π θ (toHist x) z 里根本没有 globalClassify x 的输出—— 策略不读分类。两侧各自成立，彼此不连接。这不是一个环，是两块各自合格的零件躺在桌上。

更具体：StrategyFamily.piTheta 的内部链是 recog → target → riskProj → exec（Strict/StrategyFamily.lean:334）—— 产出订单就停。没有「下一个状态」，没有 T，环不闭合。 分类在左边，策略在右边，中间是空的。

2. S_Θ：把六段接成一条强制穿过分类的环

第 0004 课的主角是 Strict/HybridStep.lean。它定义一个六段接口 HybridComponents，并把它们接成单一一步 hybridStep : HybridState → Event → HybridState（:103）：

recStruct x e → d   Rec：事件解析成结构
classify x d → c   C_Θ：结构分到类
intent x c → i   Intent：输入是类 c，决策真读分类
risk x i → u   RiskProj：意图投影到仓位控制
schedule x u → o   Exec：控制排成订单
transition x o e → x'   T：产出完整下一态，环闭合

对照第 1 节的并排合取，这里有两条 Chain 表达不出来的结构约束，各对应一条定理：

结构约束定理（file:line）它锁死了什么
π_Θ = π̄_Θ ∘ C_Θ
策略穿过分类		policy_factors_through_classify
HybridStep.lean:164		intent 的输入就是 classify 的输出——决策不能绕开分类
T 闭环写回
下一态由当前态产出		hybridStep_is_closed_transition
HybridStep.lean:183		x' = transition x (policyOutput x e) e——环闭合，x_t → x_{t+1}
这就是编排者那条公式的兑现： xt+1 = TΘ(xt, Schedule(xt, RiskProj(xt, Intent(CΘ(xt))))，e)。 Intent 套在 C_Θ 外面（策略读分类），T 套在最外面（写回状态）。并排的 ∧ 升级成了嵌套的 ∘。

3. 但要诚实：这两条「实质增量」是哪一层真理？

翻到证明体，你会发现 policy_factors_through_classify 和 hybridStep_is_closed_transition 的证明都是 rfl（:167、:185）。 rfl = 「定义上就相等」= L0。文件自己诚实标注了这一点（:161-162、:180-181）。

这里有个必须拆开的细节，否则会误判严格性：
「证明是 rfl」不等于「这条定理没价值」。它的价值不在证明难度，在它把什么钉进了类型签名。 intent : HybridState → Class → Intent（:84）——这个签名强制 intent 收一个 Class。 你无法写一个不读分类的 hybridStep，因为类型不让你接线。rfl 之所以平凡，正是因为约束已经前移到接口签名里了——这是「让非法状态无法表达」，不是「定理空洞」。

那它没买到什么，必须同样诚实（文件 :29-34 列了禁标项）：

S_Θ 闭环不声称为什么
策略盈利 / 最优 / 实盘有效T 只声明「闭环全定义」，盈利是 L3 经验，要真实数据否证
C_Θ 的标签有缠论语义classify 只给 fiber partition，语义逐 claim 承载（615）
决策充分性 L1（同类⟹同策略）same_policy_input_same_output（:201）只给「π 穿过 C ⟹ L1 可表达」的结构前提，不是 L1 本身——文件 :196-199 明说

所以这一课的天平是这样的：S_Θ 把分类和策略从「并排」接成「闭环」，这是真增量—— 但增量在L0结构层（让接线方式合法/非法可判定），不在经验层。 它买到的是「这个环结构上接对了、且接法被类型钉死」；它没买到「这个环转起来会赚钱」。 把前者当后者，就是 0002/0003 反复警告的声明膨胀。

4. 这对下游意味着什么（为什么闭环不是装饰）

闭环有一个非装饰性的下游推论，写在 HybridStep.lean:177-178： 没有 x_{t+1} = T(...) 这条形式契约，回测和实时根本没有共同的状态推进定义。 有了它，回测和实盘消费同一个 hybridStep——这是 L2 回测能不能对齐实盘的形式落点。 换句话说：闭环不闭合，「回测有效 ⟹ 实盘有效」这句话连陈述都陈述不了。 闭合了，这句话才有一个能被 L2 数据证伪的载体。

带走的锋利问题（拿去质询蜂群的「闭环已装配」声明）

「你说 S_Θ 闭环装配好了——给我看那两条增量（policy_factors_through_classify / hybridStep_is_closed_transition）除了 rfl 还有什么。 如果都是 rfl，那真增量是『类型签名强制 intent 读 Class、T 写回完整态』这一条—— 对不对？还是你其实只是把 Chain 的 ∧ 换了个写法，transition 仍是个抽象字段、 没有任何 adapter 真把 Dynamics.δ + Accounting 接进去（:264 说 transition 的实例化『后续』）？ 给我一个已实例化的 HybridComponents，它的 transition 真改了 ledger—— 给不出，闭环就还是空环，L2 形式落点就还是悬空的。」
