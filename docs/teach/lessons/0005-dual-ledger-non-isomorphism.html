两套账本不同构，以及「扩维」如何消解一个矛盾

第 0005 课 · 工程账 R=Π−A−W vs 缠论取本金三阶段 TW——为什么它们不能互相翻译，OQ-9 又怎么被消解

一个持仓系统里有两套账本同时在记。一套是工程师的利润表 R = Π − A − W（盈余 = 实现损益 − 分配 − 提取）。一套是缠师第31课的「取本金」三阶段 TW = free + holding + withdrawn，带一个单向不可逆的阶段机 降成本 → 退本金 → 增股数。直觉会说「这俩讲的不就是同一件事吗，换个变量名而已」。 这一课告诉你：它们不同构——不存在保守恒量又保操作语义的双向翻译——而且这个「不同构」 不是缺陷，是两个不同会计范畴的诚实分界。顺带，它教你一个比「打补丁」更深的招：扩维。

1. 两套账本，两种「守恒」

先把两个对象摆清楚。它们的守恒律长得像，骨子里是两回事。

模型 A · 财务账 LedgerComp模型 B · 取本金账 TWState
守恒量R = Π − A − WTW = free + holding + withdrawn
守恒的性质定义性恒等：R 由 Π/A/W 代数决定，任意赋值永真（ledger_inv_always）操作不变量：只在「同价 c 固定下池间转移」时成立（twStep_preserves_tw）
状态空间纯整数格 Z³，每个操作可正可负、可逆（ledger_realize_invertible）带一个单向不可逆的 stage 维度（earning_no_regress）
守恒律会变吗不变。R=Π−A−W 全程唯一会切换：降成本守 Σ\|units\|（股数），增股数守 K（外部投入）
关键的不对称在「stage」。模型 A 是一个可逆平移系统——你 realize 了 +5，再 realize −5 就回到原点，任意两个 (Π,A,W) 互相可达。模型 B 里藏着一个棘轮（latch）：一旦 stage 推到 earningShares，earning_no_regress 证明它再也回不去。 可逆系统和带棘轮的系统，状态空间结构就不一样。

2. 不同构的精确反例：stage 坍缩

「不同构」这种话很容易说得含糊。形式化逼你给出机器可检验的精确反例。 最强的一条（codex 标「不可反驳」）是 not_isomorphic_stage_collapses：

theorem not_isomorphic_stage_collapses : ∃ (s₁ s₂ : TWState),
  s₁.free = s₂.free ∧ s₁.holding = s₂.holding ∧ s₁.withdrawn = s₂.withdrawn
  ∧ s₁.stage ≠ s₂.stage          -- 一个 costReduction，一个 earningShares
  ∧ s₁.tw = s₂.tw

读法：存在两个 B 的态，TW 三量完全相同（free/holding/withdrawn 一字不差），仅 stage 不同。 任何只看 TW 三量的 B→A 投影 φ 都无法区分 s₁ 和 s₂（φ s₁ = φ s₂）——φ 非单射。 而 A 的全部信息就是 (Π,A,W)，没有第四个离散不可逆分量能承载这个区分。 所以 B 的信息塞不进 A，双向忠实映射不存在。这一条的算术由 by decide 机器封死。

另外两条反例同向加固：not_isomorphic_conservation_switches（B 的守恒律随 enterEarning 翻转 / A 的 R=Π−A−W 全程无翻转点）、not_isomorphic_exogenous_price （B 的 holding=Σunits·c 含外生价格 c，重估改变 TW = 盈亏 / A 是纯 Int 格无外生维度）。 裁定被钉进类型层——IsomorphismVerdict 只有一个构造子 notIsomorphic，没有 RoughlyCompatible。「大致兼容」在类型上不可表达，督导闸不收含糊裁定。

这是 0001 课「人造矛盾」的反面。0001 里，矛盾来自选错抽象（单参数装序列），换个表示就没了。 这里不一样：不同构是真实的结构差异，不是表示瑕疵。codex 还纠正过一次——理由1 原写「代数角色相反」， 那才是表示层差异；升级成「外生价格维度」后才是结构差异。会分辨「换表示能消的矛盾」和「换表示消不掉的结构差异」，是这门课的核心刀法。

3. OQ-9：一个看似无解的矛盾

同一个文件里还埋着一个更硬的矛盾，编号 OQ-9。它的两端都是真的，且看上去直接打架：

端声明性质
端 A（数值真相）进入 earningShares 后，闭合一条亏损的旧腿（profit<0），净现金口径成本（cumNetCash）会下降——「cost_basis 回正」算术事实，不可否认
端 B（相位锁死）三阶段单向相变（缠师第87课 INV-2），earningShares 不回退领域语义，不可违背

把这两端绑在一起，矛盾就来了：如果你用 stage = sign(cost_basis) 这种单一判据 （相位 = 数值符号的函数），那么「亏损闭合让 cost_basis 回正」就逼着 stage 回退—— 直接违反端 B。补丁思维到这里会做两件事之一：要么 try/except 吞掉那个数值变化（端A 被糊掉）， 要么硬编码「earning 阶段禁止回正」（端A 被否认）。两条都是声明膨胀。

4. 扩维消解：不是打补丁，是加一个正交维度

根因不在两端，在「把数值符号和相位绑成同一个判据」。解法不是在这条绑定上加例外， 而是把它解耦——给状态空间增一个正交维度，让相位不再是数值的函数。 这就是 OQ-9 扩维消解，五步：

① 解耦正交维 → stage（相位，路径依赖历史变量）⊥ cumNetCash（净现金口径，可正可负）⊥ openLegacyLegs（未闭合 legacy 腿计数）
② 拆 legacy/新腿 → 锁死的只是 legacy 降成本腿；earning 阶段开增股数新腿合法（不混入此计数）
③ 入口证书 → LegalEnterEarning s := (openLegacyLegs = 0)——非法性在进入锁死相位时强制，不是事后判违规
④ rawStep/legalStep 双层 → raw 层（全函数）保留端A 作 witness；legal 层（谓词）排除那条 trace
⑤ trace 级 invariant → 不是单步定理，是「合法 trace 全程保持 OQ9Inv」+ 初态满足 inv

第 ④ 步是这门课最该记住的存在论操作。两端不是被强行调和，是被分配到两个层。 raw 层的 twStep 是全函数，什么都允许发生——包括「带未闭合 legacy 腿进入 earning，然后亏损闭合让 cumNetCash 下降」。 这条端A 路径真实存在、不被吞、不被禁，它是 raw_earning_legacy_leg_closure_witness 机器见证的 violation witness。而 legal 层用 LegalTransition 谓词把这条 trace 排除在外。

「两端并存」是声明膨胀；「raw 层端A / legal 层不可达」才是严格的。 区别在哪？前者说「在同一个系统里两个矛盾的东西都成立」（含糊）；后者说「端A 在 raw 层成立， 但那条 trace 在 legal 层不合法，所以在合法系统里端B 锁死成立」（精确分层）。 这就是为什么 twStep 故意不给 enterEarning 加入口守卫——守卫加在 raw 层会抹掉 witness，那等于否认端A。诚实要求 raw 层保留它。

5. 物证：端B 必须是 trace 级，不是单步

codex review 第二轮抓到一个真实的漏洞，值得当反面教材。最初端B 只证了单步 （「合法进入 earning 的下一步不能闭 legacy 腿」）。但这不够——合法 trace 可以绕路： enterEarning → openShareLeg → closeShareLeg，照样到达「earning ∧ legacy 腿=1」的 witness 形状。 单步定理挡不住绕路。修法是把端B 升级到 trace 级，链条是：

OQ9Inv s := (s.stage = earningShares → s.openLegacyLegs = 0)   -- 不变量
oq9inv_preserved   -- 每个合法转移逐事件保持 inv
oq9inv_trace       -- 合法事件链归纳保持（generalizing s）
init_satisfies_oq9inv  -- 初态（costReduction）满足 inv ← 给合法起点
⟹ oq9_legacy_leg_unreachable_in_earning  -- witness 形状在任意合法 trace 不可达

注意 init_satisfies_oq9inv 那一行：没有它，对手可以注入一个非法初态绕过整个定理。 trace 级 invariant 必须有合法起点才闭合。还有两个堵漏定理——openShareLeg 合法性收紧为 stage.rank < earning.rank（earning 阶段不再开 legacy 腿）、zero_close_is_ghost （闭合不存在的腿是幽灵副作用，legal 层排除）——它们把绕路的每条小道都封死了。build 绿 ≠ review PASS：这些是正确性缺陷，不是编译错。

反 workaround 判准（记下来，通用）：判一条路径「非法」是忠实建模，当且仅当它在领域语义下本就不该发生。 如果它真实会发生、你只为了让锁死成立才宣布它非法——那是 workaround。OQ-9 里「earning 后还有未闭 legacy 腿」 本就违反缠师第87课「真正的拉抬不需要花钱」，所以判它非法是忠实的，不是凑的。

6. 对 Phase2 重锚的直接推论

这一课不是历史课。#89/#91/#93/theta_v0 正在向 Origin canonical base 重锚， 每个 port 都会声称「已重锚 / 闭环已接上」。扩维消解给了你一把尺：重锚不是换 import 路径，是要保住那个棘轮维度。 如果某 port 重锚后，HybridAssembly 的闭环里 OQ-9 的三个正交维度（stage / cumNetCash / openLegacyLegs） 有任何一个被压扁回单一判据，或者端A 的 witness 通道被「顺手」加了入口守卫抹掉——那就是重锚时偷偷退化了。 #101（双账本桥 + HybridAssembly 重锚）尤其要守住：单 owner 同时守 HybridAssembly + TotalWealth + 新桥， 正是因为这三者共享 OQ-9 的扩维结构，拆给三个人改必塌一个。

带走的锋利问题（拿去质询任何「账本/闭环已重锚」声明）

「你说这个账本闭环已重锚到 Origin——那个单向棘轮维度（stage）还在吗？ 给我两个 TW 三量完全相同、仅 stage 不同的态，证明你的投影没把它们塌缩成同一个（即 not_isomorphic_stage_collapses 仍可复现）。 再说 OQ-9：端A 的 violation witness（带未闭 legacy 腿进 earning、亏损闭合使 cumNetCash 下降）在你重锚后的 raw 层还保留着吗， 还是被『顺手』加了入口守卫抹掉了？端B 你给的是单步定理还是 oq9inv_trace 那种带初态的 trace 级 invariant—— 单步挡不住绕路。三样里缺一样，『不同构』和『矛盾已消解』就都是声明膨胀，你做的是把两个会计范畴糊成一个。」
