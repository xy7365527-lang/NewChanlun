怎么写 goal —— 锋利可证伪 acceptance

goal 写法三要素：可收敛（单一交付物）+ 可证伪（acceptance 机器判定）+ DECOMPOSE（sub_goals DAG）。这一课聚焦中间那个——你当前 goal 的 acceptance 复合了，不够锋利。

锋利 acceptance 三原则

  1. 单一条件：一个 acceptance 项 = 一个可判定 pass/fail 的断言。不把「A 且 B 且 C」塞一条。
  2. 机器可判定：reduce 时能跑一个命令/检查得出 bool。如 lake build Origin 零 sorry（grep 退出码）cargo test --lib 通过（退出码）。
  3. falsifiable=true：存在明确的反例能让它 fail。如「lake build 零 sorry」——有 sorry 就 fail，无 sorry 就 pass。

反例：复合 acceptance（你当前 goal）

你的 g-strict-mutex acceptance[1]：

"18类角色完全互斥Σ=1 + 区间套N^δ∃! + R_Θ总序唯一化 +
 AncOK闭合 + §16中心定理12假设→∀x∃!O + §18自相似等变
 lake build Origin 零sorry/admit/axiom"

问题：6 个定理 + 1 个 build 检查塞一条。如果 18 类证了但 §18 没证，这条整体 passed=false——你不知道进度（5/7 还是 1/7）。这就是 lesson 0011 锋利问题②的变体：复合验收 = 部分通过但整体黑箱。

怎么改：拆成单一条件

把复合 acceptance 拆成每条机器可独立判定的项。例：

[1] lake build Origin 零 sorry/admit/axiom（grep 退出码）
[2] 18类角色 Σ=1 Lean 定理存在（grep role18_count_one）
[3] 区间套 N^δ ∃! Lean 定理存在（grep N_exists_unique）
[4] R_Θ 总序唯一化 Lean 定理存在（grep rTheta_exists_unique）
[5] AncOK 闭合 Lean 定理存在（grep activeNext_anc_closed）
[6] §16 中心定理 Lean 定理存在（grep main_theorem）
[7] §18 自相似等变 Lean 定理存在（grep classify_equivariant）

每条独立 pass/fail → reduce 时 acceptance[i].passed 精确反映进度 → 0/7 → 3/7 → 7/7 closed。不再黑箱。

sub_goals 与 acceptance 的映射

你 12 个 sub_goals（lean-roles18/lean-nest/.../rust-strategy）每个完成 → 写 EVIDENCE + CHECK_PASS 事件。sub_goal 的 CHECK_PASS 应映射到 acceptance 项：

lean-roles18 CHECK_PASS  → acceptance[2]（18类Σ=1）
lean-nest CHECK_PASS    → acceptance[3]（区间套∃!）
lean-selfsim CHECK_PASS → acceptance[7]（§18等变）
...

reducer 算 passed_checks → acceptance 项 passed=true 当其映射的 sub_goal CHECK_PASS。goal closed = 所有 acceptance passed。

写法模板

GOAL_SET:
  acceptance:
    - check: "lake build Origin 退出码0 且 grep -c 'sorry\\|admit\\|axiom' Origin=0"
      falsifiable: true
    - check: "cargo test --lib 退出码0"
      falsifiable: true
    - check: "grep 'role18_count_one' SelfSimilarity.lean 命中"
      falsifiable: true

每条 check 是一个可执行的判定（命令 + 期望），reduce 时跑得出来 bool。

关键区分

acceptance = goal 级验收（机器判定 pass/fail，falsifiable）。sub_goals = 执行 DAG（desc 描述任务，blocked_by 依赖，不需 falsifiable）。EVIDENCE/CHECK_PASS = 事件（工位产出→记→acceptance passed）。
