# 使命：纵向递归 / 横向同级别分解

## 为什么

整个缠论量化交易系统（Rust + Nautilus Trader，已有 461 万根 BTC 1分钟K 的实测链路）的架构主干，
取决于一件事：纵向递归（造级别）和横向的同级别分解（读级别）到底是什么关系。这个想不透，
模块图画不出来，40 套重复口径收不拢。学习者原话：

> 「这个东西非常重要，连接到纵向递归、横向递归和同级别分解的问题上。」

学完这一组课，学习者要能亲手给 [issue #787](https://github.com/xy7365527-lang/NewChanlun/issues/787)
（架构正本地图）画一条不自相矛盾的模块边界，而不是继续凭直觉猜。

## 学习者

本仓的编排者/主控。不是缠论初学者——能读原文、能拍架构裁定，正在走一张 50 张子票的架构正本地图
（[#787](https://github.com/xy7365527-lang/NewChanlun/issues/787)）。这门课不用从头讲缠论基础，
直接进最难啃的关系问题。

## 成功长什么样

- 能一句话说清楚"同级别分解为什么不需要中枢延伸/扩展/升级"，并能指出这句话在第38课哪一段（`038:26`）。
- 能画出"纵向递归造塔 → 在塔上横切一刀 → 每一刀是一个操作级别"的依赖方向图，且不再把"横向"
  错叫成"横向递归"。
- 能在多重赋格场景下解释同一层楼板（延伸/扩展/升级）和走廊（同级别分解）两套规则为什么不冲突，
  从而给 #787 的模块图拍一条站得住脚的边界。
- 能区分"原文明文"与"推断"两类溯源标签——看到"推断"标注时，知道这条结论可能需要在查到新原文后修订。

## 约束

- **用人话，禁黑话**：先给直觉，再给原文；每个抽象说法后面必须跟一个具体后果。
- **课要短**：学习者是主控/编排者，时间稀缺，每课要能快速读完，但结论必须完整，不能为了短而漏关键分寸。
- **教学内容不自行发挥**：缠论知识的边界以已交付给这门课的原文引用为准，不额外"补充"缠论研究；
  引文必须逐字可查、给出 `文件:行号`。
- **他会当场拍裁定**：教学材料要能承接这些裁定，并标注日期与出处（见各课对应的学习记录）。

## 不在范围内

- 不重新研究缠论理论本身的正确性——内容以已给定的原文引用为准，不做独立考证或延伸阐释。
- 不涉及代码层面的具体实装细节（Rust 结构体、Nautilus 适配层等）——这是架构理论课，不是代码课。
- 暂不覆盖 [#787](https://github.com/xy7365527-lang/NewChanlun/issues/787) 地图上与"纵向/横向关系"
  无关的其他子票，除非学习者明确要求扩展。
