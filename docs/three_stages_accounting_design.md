## 0. 文档定位与认识论声明

### 0.1 本文档解决什么

`drain_and_three_stages.md` 已经确诊：drain 是"半条 recover"（单腿平仓、资金落 `free`、核心持仓期无回投路径），是三阶段的**反向退化算子**；系统止步于第一阶段（降成本），第二阶段（负成本）靠负 basis 涌现支持、第三阶段（增股数）**未实现**。

但它**只诊断不设计**。本文档承接它的诊断，回答：**如果要把三阶段真正设计进引擎，会计框架长什么样？** 核心结论提前给出：

> **当前引擎缺的不是 drain 的回腿，而是一个能表达"持仓成本随短差单调下降直至穿零"的状态量。** `Layer` 只有 `basis`（加权入场价），它是强平基准、**不是**缠师说的"成本"。缠师的"成本"是净现金流口径（"抽到的血"），可以为负；`basis` 永远是已付价格的加权、恒为正。**这两者必须物理分离**——这是整套三阶段会计框架的地基。drain 之所以"净抽干"，根因正是它产出的降成本现金没有一个 `cost_basis` 字段去承接，只能死在 `free` 里。

### 1.2 三阶段的操盘机制（从原文提炼，全程零杠杆现货）

- **基线 = 恒仓（股数 N）**：缠师"仓位"的所指是**股数**（第26课"数量""股"），不是市值、不是保证金。建仓时"一开始就买够"，确立股数基线 N。
- **第一阶段（降成本）**：用 1/3（或 1/4，"不熟练时"，熟练后"随心所欲"）的部分仓位，在**比核心仓低 1 级别**的图上做短差（第15课"按比中线图低1级别的图，拿部分仓位作短差"）。每次卖高买低的已实现差价**冲减持仓成本**；股数在固定 N 内"卖点减、买点补回原数"地振荡，**净股数不变**。成本单调递减、无下限。
- **第二阶段（负成本）**：成本穿零。这是缠师"绝对无风险/立于不败之地"的状态——本金已通过卖出全额回收，剩余持仓即使归零也不损失本金。
- **第三阶段（增股数）**：成本为负后，同样的中枢震荡短差产生的已实现差价**不再有成本可降**，转而兑现为**额外股数**（第48课"差价……筹码越多"）。资金来自标的自身差价（第87课"真正的拉抬，是不需要花钱的""差价都是自己的"），**不注入新外部本金**。

### 1.3 关键厘清：缠师原文是"两相位"，"三阶段"是过程-状态-过程的离散化 `[综合]`

这是本文档最重要的概念辨析，直接决定会计框架的状态机结构。

**原文证据**：第31课"成本为0**以前**，要把成本变为0；成本变成0**以后**，就要挣股票"（line 24）、"成本为0**前**……买入多少就是卖出多少不增加仓位。……成本为0**后**……仓位是增加的"（line 36）——**两相位**，分界在 `成本=0`。第48课"成本为0前不断降低成本，成本为0后不断挣筹码"是同一两相位的复述。第87课把它描述为"0成本→反复拉抬变纯负数→满手负成本"的**连续轨迹穿零**。缠师从未把它切成三个并列的离散态。

> **源出处一致性（修复对抗审查 H1，溯源诚实）**：`types.rs:348` 注释把 `LedgerPhase` 标为"**31课**两阶段的类型化"。本文档主锚 = **第31课**（line 24/36，与代码注释一致），第48课为复述补强。两课表述一致（都是"成本为0前/后"两相位），不存在源出处冲突。第31课更优——它逐字给出两条守恒律（line 36）、退出条件（line 30）、回投规则（line 169），见 §3.3/§1.4/§5.3。

**严格读法**：会计上有**两个不变量**（两个过程），由**一个状态**（负成本）分隔：

```
        阶段一（过程）           负成本（状态）          阶段二（过程）
  ┌──────────────────────┐   cost_basis = 0   ┌──────────────────────┐
  │   降成本               │ ───── 相变点 ──────→│   增股数               │
  │   cost_basis ↓ 趋零    │   ＝无风险性质获得    │   cost_basis < 0 锁定  │
  │   守恒：股数守恒        │   ＝增股数前置条件    │   守恒：外部资本守恒    │
  │   (ShareConserving)   │                     │   (AmountConserving)  │
  └──────────────────────┘                     └──────────────────────┘
```

- **降成本**和**增股数**是两个**过程**（phase），各有独立守恒律。
- **负成本**不是第三个并列过程，而是**状态**（cost_basis≤0 这个关系本身）：它同时是 (a) "绝对无风险"的性质获得（第48课），(b) "成本为0后挣筹码"的前置触发条件（第48课）。

> **编排者裁决（2026-06-20，OQ-1/OQ-3 已结算 → 三阶段）**：初稿的"两相位"读法**被否定**。决定性证据是第31课 line 28——退本金是缠师**显式命名的独立操作**（"在股票达到1倍升幅附近找一个大级别的卖点**出掉部分，把成本降为0。这样，原来投入的资金就全部收回来了**"），不是降成本与增股数之间的一条线。三个阶段的**守恒行为各不相同**，故是三态而非两态：

```
        ① 降成本（CostReduction）      ② 退本金（CapitalRecovered）     ③ 增股数（EarningShares）
  ┌──────────────────────────┐   realized≥notional   ┌──────────────────────┐   本金已退   ┌─────────────────────┐
  │ Σunits 不变（恒仓）         │ ─── 触发退本金 ────→│ 抽出本金 K 到安全池     │ ─── 切换 ──→│ Σunits ↑（增股数）   │
  │ 短差降 cost_basis          │   "原来投入的资金     │ 在险资本 ↓（free→sealed）│   守恒律切换  │ 纯利润买更多 units    │
  │ ShareConserving            │    全部收回来了"      │ 立于不败之地（不可逆）   │           │ AmountConserving     │
  └──────────────────────────┘                       └──────────────────────┘           └─────────────────────┘
```

- **三个阶段守恒行为不同** ⟹ 三态：① Σunits 守恒；② Σ现金抽出（在险资本↓，既非 ShareConserving 也非 AmountConserving）；③ Σunits 单调增。
- **退本金（CapitalRecovered）是独立阶段**，不是相变线——它是缠师"原来投入的资金就全部收回来了"的**操作**（把等于初始本金的现金移出在险池），是"立于不败之地"在会计上为真的前提（只有真把 K 拿走、不再复投，剩余仓位才是无风险的纯利润）。

> **存在论裁决（OQ-3 消解）**：267号"退本金"与第48课"增股数"是**两个不同阶段，非包含关系**（用户裁决）。267号是②，第48课是③，二者顺序排列，均正确。

**类型系统选择（定理，OQ-1 实装层）**：`types.rs::LedgerPhase` 是**两变体**（`CostReduction{cost_basis}` | `EarningShares`），被 `trading/ledger.rs::OrganicLedger` 用于与 Python 的 P5 bit-exact 契约——**不可加第三变体**（会破坏契约）。T 引擎是 standalone 架构，定义**自己的** `TStage` 三变体（`CostReduction | CapitalRecovered | EarningShares`），不污染共享类型。

> **开放问题 OQ-1（最高优先，/escalate）**：本任务命名为"三阶段"，但原文 + `types.rs` 是两相位。是否把"负成本"物化为独立的第三个枚举变体（3 变体），还是保留 `LedgerPhase` 两变体（`cost_basis≤0` 即进 `EarningShares`，"负成本"作为 `EarningShares` 的边界关系而非独立态）？这是**定义冲突**（改 `LedgerPhase` 变体数 = 改已结算类型语义），须 `/escalate`，不可凭工程便利硬切。本文档**默认采用两相位读法**（负成本=状态），并在每处标注若改三态会怎样。

## 2. 核心会计概念：`cost_basis` 与 `basis` 的物理分离

这是整套框架的地基，单独成节。三个独立设计面板（会计严格/缠论忠实/矛盾暴露）**全部收敛**于这一点。

### 2.1 当前 `Layer.basis` 不是缠师的"成本" `[L0，代码事实]`

`Layer`（`fugue_v3/layer.rs:22-28`）五字段：`ladder / direction / units / basis / entry_bar`。

`basis` 的逐字语义（`layer.rs:19`）："加权入场价（短差 P&L 锚 + 1x 强平基准）"。它的演化（`accounting.rs`）：
- `add_at` 时按 `basis=(basis·units+c·m)/(units+m)` **加权**（`accounting.rs:148`）——永远是已付价格的加权平均，**恒为正**（价格恒正）。
- `reduce_at` 时**不改 basis**，units 归零才重置为 `NaN`（`accounting.rs:113-119`）。

**关键事实**：`basis` 不随"卖高买低"单调下移。降成本赚的已实现差价只以现金形式落在 `mobile_realized_pnl_by_ladder[k]`（`accounting.rs:112`，一个纯观测累加器，**只读、不被引擎消费、不回投**）。所以 **T 引擎（`recursive_t/t_engine.rs`）没有一个字段在表达缠师的"成本"**（grep 确认无 `cost_basis`/`LedgerPhase`）。

> **边界声明（修复对抗审查 M2，避免低估既有实现）**：缠师"成本"的 cost_basis 演化机制（`cost_basis −= profit/total_shares → ≤0 单向相变 EarningShares`，含 ShareConserving/AmountConserving 两守恒律）**已在 `rust/src/trading/ledger.rs` 的 `OrganicLedger` 完整实装并经 P5 bit-exact 验证**（与 Python `organic_fugue.OrganicLedger` 逐位等价）。**本文档不是首次设计这套会计原子**——本文档的增量是把这套已验证机制**移植/接入到 `recursive_t/t_engine.rs` 的多层逐仓结构**（OrganicLedger 是单一共享账本，T 引擎是 11 层 ladder + 逐仓强平，二者结构不同，移植非平凡）。`ledger.rs` 已记录的 T5 守恒律相变可逆性疑点见 §3.3 / OQ-9。

### 2.2 缠师的"成本"是净现金流口径，可以为负 `[原文]`

第87课："股票只是一个凭证，一个**抽血**的凭证，**能把血抽到才是真本事**。"第26课："本ID最终……完全出掉时，当时的**成本是负的2块8毛多**。"

缠师的"成本"度量的是**净投入现金**：

```
缠师"成本"（持仓成本基，per share）
  = (累计买入付出的现金 − 累计卖出收回的现金) / 当前持仓股数
  = (名义投入 − 累计已实现差价) / units
```

- 做一轮卖高买低，已实现差价回流 → 分子下降 → cost_basis 下降。
- 累计已实现差价 > 初始投入 → 分子为负 → **cost_basis < 0**（负成本）。

这与 `basis`（加权入场均价，恒正）在做短差时**数值分叉**：你可以一边 basis（均价）仍为正、一边 cost_basis（净现金）已为负。**两者度量不同对象，必须是两个字段。**

### 2.3 物理分离同时修复"负成本永不强平"隐藏 bug `[L0，矛盾暴露]`

矛盾暴露设计面板给出一个决定性论证：

**若不分离**（让负成本 ≡ basis<0）：多头逐仓强平判据 `c > 0 && c ≤ basis/SUB_LIQ_FACTOR`（`t_engine.rs:352`，`SUB_LIQ_FACTOR` 当前取值 2.0，`mod.rs:110`）。当 basis<0 时 `basis/SUB_LIQ_FACTOR < 0`（除以正常数仍为负），而价格 `c>0`，故 `c ≤ 负数` **永不成立** → 该层**永不强平**（论证不依赖 SUB_LIQ_FACTOR 的具体值，只依赖其为正）。这表面上"涌现一致"地复现了缠师"负成本→无风险→不败"。

**但这是隐藏 bug，不是涌现一致**：
- 缠师"不败"是**现货**有效域命题（本金已通过卖出回收，剩余是白捡的筹码，下跌不损失本金）。
- 把"现金流为负成本"自动平移成"名义敞口免强平"是**有效域越界**（`formalization-validity-domain`）：保证金语境下，即使账户净现金流为负成本，名义敞口仍可触发维持保证金线 → 强平风险与 cost 维度**正交**。

**解法不是设计消化，是物理分离**（严格性，不掩盖矛盾）：

```
basis（恒>0）        → 唯一驱动逐仓强平判据（永远读 basis，不读 cost_basis）
cost_basis（可<0）   → 唯一驱动三阶段切换（永远不进强平判据）
```

这样"负成本"不再蕴含"basis<0" → 不触发"永不强平"退化。"负成本现货标的是否真免强平"这一命题本身（现货 vs 合约）是 §4.3 的 `/escalate` 项。

### 3.1 每层 `Layer` 需要追踪什么 `[L0]`

在现有 5 字段（`ladder/direction/units/basis/entry_bar`）基础上，三阶段需补 2 个状态量（`Layer` 是 `Copy`，新增字段须在 `idle()` 构造 `layer.rs:32-34` 与 `reduce` 清零 `accounting.rs:113-119` 两处同步初始化/重置，否则新不变量漂移）：

| **`cost_basis`** | `f64` | 缠师"成本"=净现金流口径 per share（可<0）。演化：每次 reduce 产生 realized 时 `cost_basis -= realized / units_remaining` | 第26/87课 + §2.2 |
| **`stage`** | `LedgerPhase` | 阶段判定。**直接 use 现成 `types.rs:351-356` 的 `CostReduction{cost_basis}` \| `EarningShares`**，不新造（避免"第三种守恒律静默引入"） | `LedgerPhase` `types.rs:351-356` / `ConservationLaw` `types.rs:340-346` |

> **诚实标注（声明边界）**：`types.rs` 的 `LedgerPhase`/`ConservationLaw` 是交易层为三阶段会计**预建**的类型，且已在 `trading/ledger.rs` 的 `OrganicLedger` **实装并 P5 bit-exact 验证**（§2.1 边界声明）。但 **T 引擎（`recursive_t/t_engine.rs`）当前未引用它们**（`t_engine.rs:56-63` 的 `use` 不含 `LedgerPhase/ConservationLaw`）。本设计 = 把 `OrganicLedger` 已验证的 cost_basis 会计**移植到 T 引擎的多层逐仓结构**，不是新造概念，也不是首次设计该会计原子。

### 3.2 三阶段之间的切换条件（严格不等式） `[原文 + L0]`

唯一精确判据是 `cost_basis`，**缠师明示**（第31课 line 24/36"成本为0前/后" + 第48课，是原文唯一被点名的标志数值）：

```
阶段一（降成本，CostReduction）：   cost_basis > 0
相变点（负成本，状态）：            cost_basis = 0   （数值上 |cost_basis| ≤ ε_cost）
阶段二（增股数，EarningShares）：    cost_basis < 0
```

切换是**单向相变**（`types.rs:349-350` 已断言"只有 CostReduction→EarningShares，逆向不可达 INV-2"，对应缠师第87课"反复拉抬变纯负数"不回头）：

```
若 stage==CostReduction 且某次 reduce/recover 后 cost_basis ≤ 0：
    stage ← EarningShares      （不可逆）
    conservation ← AmountConserving
```

切换判定的**插桩点唯一**：`reduce_at`（`accounting.rs:112`，唯一记 realized 的点）或其调用方（sink/recover/drain/clear/liq）。`add_at` 不产生 realized，故不是切换锚点。

- **进入第一阶段**：原文无独立精确触发条件（仅隐含"建仓完成且未到清仓卖点"，第15课）→ 用 `enter()`（`t_engine.rs:169`）作进入锚（延伸，标注）。
- **ε_cost 取值**：建议 `1e-9 × initial_basis`（相对阈值，避免绝对阈值的尺度失配——参考记忆 `project_p0_p1_dual_gate_verdict` 的 θ 相对化教训）。

> **开放问题 OQ-1（重申）**：上述是两相位切换（一个判据 `cost_basis=0`）。若任务坚持"负成本"为独立第三态，需在 `cost_basis=0` 处再设一个"负成本稳态"判据——但原文**没有**第二个阈值（"负成本阶段"是连续轨迹穿零后的延续，无离散进入边界）。强行加 = 后学自造，须 `/escalate`。

### 3.3 units 守恒律的重新表述

**核心张力**：第一阶段股数守恒与第三阶段股数单调增**不能用同一守恒律**。这正是 `types.rs` 的 `ConservationLaw` 两变体存在的理由（`ShareConserving | AmountConserving`）。**两守恒律有逐字原文**（第31课 line 36，对抗审查后补强）：

> "成本为0前……**买入多少就是卖出多少不增加仓位**。……成本为0后……**卖出多少资金就买入多少资金做短差赚股票，仓位是增加的**。"

- "买入多少就是卖出多少不增加仓位" = **ShareConserving**（股数守恒）逐字原文。
- "卖出多少资金就买入多少资金……仓位是增加的" = **AmountConserving**（金额守恒、股数净增）逐字原文。

守恒律按阶段分律（代数表述 `[L0]`）：

```
INV-1（阶段一，ShareConserving）：  Σ|units| = N_base
    第31课"买入多少就是卖出多少不增加仓位" / 第26课"绝对不加仓"。
    短差只在固定 N 内卖减/买补回（sink/recover 一减一加，Σ|units| 不变）。

INV-2（相变，单向）：              cost_basis ≤ 0  ⟹  stage = EarningShares （不可逆）

INV-3（阶段二，AmountConserving）： d(外部投入资本 K)/dt = 0
    K = Σ(units_k · cost_basis_k) + free_committed。
    第31课"卖出多少资金就买入多少资金……仓位是增加的" + 第87课"真正的拉抬不需要花钱"
    ——增股数所用现金 ⊆ realized_cum，不注入新外部本金。
    故 Σ|units| 单调增（"筹码越多"）而 K（净外部投入）守恒。
```

**守恒律从"股数守恒"扬弃为"外部投入资本守恒"**：第一阶段守 `Σ|units|`，第三阶段放弃股数守恒、改守"净外部投入不增"。"股价越涨筹码越多"不是凭空增值——它是已抽回的 realized 现金（已是 NAV 的 `free` 部分）转成 units（NAV 的 `units·c` 部分），是 NAV **内部再分配**，不是创造（第31课 line 121"把货出了当然要挣钱。只是拉抬并没花钱"）。

**NAV 守恒是否仍 per-bar 成立？** `[认识论分层，修复对抗审查 H2/H3]`：
- **同价操作 NAV 代数中性** = **L0**（定义直推）：阶段三同价加仓（用 realized 现金买 units）仍 NAV 中性（buy: `free−=m·c` 抵消市值 `+m·c`），与"Σ|units| 是否守恒"正交。
- **新增 stage 分流后 per-bar NAV 守卫全程零 panic** = **L2 守恒**（须真实数据跑过才成立，可被否证）。`prove.rs:14` 头表已把 `prove_nav_neutral`/`prove_conservation` 分类为"L2 守恒"——本文档的守恒律守卫继承此 L2 等级，**不是 L0**。

需**新增两个守卫**（现 `prove.rs` 套件无此二断言，代数表述 L0 / 守卫零 panic = **L2 守恒**）：
- `prove_units_monotone`：阶段三 Σ|units| 单调不减（否则"增股数"与"误加仓"不可区分）。
- `prove_external_capital_conserved`：增股数回投 ⊆ realized_cum（否则单池混账无法保证 INV-3）。

> **开放问题 OQ-9（/escalate，对抗审查补漏的真矛盾）**：**守恒律相变可逆性矛盾**。`trading/ledger.rs:11-18` 已在册记录：`earning=True` 后闭合 ShareConserving 旧腿且 `profit<0` 时 **`cost_basis` 数值会回正，但 `LedgerPhase` 单向相变（INV-2）不回退**——cost_basis 数值可回正 vs 相位锁死，二者张力。`ledger.rs` 取严格形式（EarningShares 下 ShareConserving 亏损闭合不改写成本）并以 `n_t5_shareconserving_after_earning` 计数器使该路径**可观测**；在册声明"若计数>0 且与 Python 对账分歧，这是定义冲突（守恒律相变可逆性），走矛盾上浮"。**本文档 §3.2 把单向相变当干净定理，遗漏了这个已在册的真矛盾**——现补登为 OQ-9，须 `/escalate`（守恒律相变可逆性=定义冲突，不可设计消化）。当前在册实证：该路径 earning 触发率=0 ⇒ 空有效域（L2 读数），但矛盾不因空有效域消失。

### 3.4 阶段一的 regime 门控（原文给出） `[原文]`

第26课"**除了日线的单边上扬走势，短线必须坚持**"——单边强趋势时暂停短差、纯持有；"周线级别的中枢，正是上下打短差的最好时期"——震荡/大级别中枢时短差最活跃。

## 4. 逐仓 / 全仓模式与三阶段耦合

### 4.1 决定性前置声明：整个 margin 论域在缠师原文之外 `[L0域外]`

**这是 §4 全节的认识论前提，不可省略**：缠师原文**三次**明确否定杠杆/借贷（考据逐字证实）：
- 第26课："你手中的钱，一定是能长期稳定地留在股市的，**不能有任何的借贷之类的情况**。"
- 第28课："基金，不过是所谓合法地借贷了很多钱而已……性质一样。"
- 第74课："借贷炒股……这是**绝对不允许**的，把资本市场当赌场的，永远也入不了资本市场的门。"（"透支"≈margin，被点名禁止）

逐仓/全仓都是 **margin（保证金）概念**，其存在前提是有杠杆。因此：

> **在缠论原文论域内，逐仓/全仓都没有对应物，更不存在二者之间的"切换条件"。** 缠师机制 = 零杠杆现货 + 恒定股数。§4 以下的"逐仓=阶段一/全仓=阶段三"映射，**全部是会计框架设计层引入的延伸建模（L0 域外）**，缠师原文既不支持也不反对（论域不重叠）。所有结论标注 `[L0域外]`，**不可宣称为缠师原意**。

但代码事实给出可锚定的结构：当前 `t_engine` **只有逐仓**（`t_engine.rs:347-360`，每层独立 basis 判强平，无全仓模式），这天然对应"级别隔离"。下面在这个延伸建模上设计。

### 4.2 逐仓 = 阶段一天然形态 `[L0域外 + 级别独立性]`

- **原文锚（结构层，非资金层）**：第5课"任意某级别，都是一套**独立系统，不同级别之间不得组合**"；第44课"选定了操作级别，30分以下的波动一概不考虑"。
- **代码对应**：每层独立强平（`t_engine.rs:351-354` 各层用各自 basis），强平一层不连累其他层 = 逐仓。
- **利润隔离规则**：第一阶段 sink 子腿的 realized 留在该子层的 `mobile_realized_pnl_by_ladder[sub]`（按 k 索引），**不上浮**——对应第49课"小级别不会出现成本为0"（次级别短差不积累到挣筹码）。

> **能指碰撞标注**：第5课"不得组合"的所指是**走势结构的组合**（下一句"由本级别的次级别组合而来"），**不是资金/盈亏的会计组合**。把"不得组合"读成"资金不得跨级别流动=逐仓"是把结构论域的能指搬到会计论域，属延伸应用，不是 L0 推导。

### 4.3 全仓 = 阶段三必要条件 —— 但任务前提被原文部分否证 `[L0域外 + 原文张力]`

任务的设计假设是："增股数需要利润跨级别流动（次级别利润变本级别新 units），全仓是其必要条件。"

**严格性要求我诚实 surface：这个前提被第49课部分否证，不能默认接受**（`no-workaround`：不绕过矛盾）。

- 第49课原文："那种中枢完成后的向上移动时的差价是不能做的，中枢向上移动时就应该满仓……而在围绕中枢差价时，在中枢上方仓位减少，在中枢下方仓位增加……（**成本为0后是筹码增加，当然，对于小级别的操作，不会出现成本为0的情况**）。"
- 解读：缠师把增股数**锁在操作级别自身的中枢震荡里**，并明确"**小级别不会出现成本为0**"——即次级别短差**不**上浮为本级别 units。

所以"次级别利润 → 本级别 units 的跨级别流动"是**设计层新增机制（原文外）**，与第49课直接张力。

**两个设计选项**：
- **保守设计（推荐，贴原文）**：增股数的 realized 现金回投**回到产生它的同一核心层**（不跨级）。即"全仓"退化为"单核心层内 realized→units"——既满足增股数（Σ|units|↑）又不违反级别独立性 + 第49课。
- **激进设计（跨级别流动）**：次级别 realized 上浮为核心层 units。与第49课"小级别不积累到挣筹码"冲突。

> **开放问题 OQ-4（/escalate）**：采用保守（同核心层回投）还是激进（跨级别流动）？涉及单一 `free` 池（`t_engine.rs:113`）下回投目标 ladder 的归属。激进设计违第49课，须裁决。**本文档默认保守设计**。

### 4.4 负成本 = 逐仓→全仓转换判据 —— 有效域越界，期货禁编码 `[L0域外，禁编码]`

设计命题：当某核心层 `cost_basis ≤ 0`（阶段二）时，该层从逐仓结算切入"全仓"结算（其 realized 现金允许回投增股数）。从缠师"0成本绝对无风险"推导：
- **为何 cost_basis≤0 后逐仓保护不再必要**：逐仓强平线本是防止亏损超过本金；负成本下本金已回收，**没有本金风险需要隔离**，强平线失去保护对象。
- **为何需要"全仓"释放利润流动**：逐仓隔离（保护性）在负成本后已无意义，隔离反而**阻碍**第48课要求的"挣筹码"。

**但这是有效域越界，必须按 §2.3 物理分离 + 期货禁编码处理**：
- 负成本"无风险"是**现货**命题。强平判据**永远读 basis（>0）**，**不因 cost_basis<0 豁免**（否则就是 §2.3 的隐藏 bug）。
- 本项目标的含 **CL/BTC/ES 期货**。第33课："**期货是可以随时开仓的，和股票交易凭证数量的基本稳定不同，所以在力度分析等方面有很多不同的地方，这在以后再说**"——**恒仓本体（INV-1 的根）是股票特性，期货打破恒仓前提，缠师自己标为留白**。

> **开放问题 OQ-5（/escalate，仅 a/b/c）**：(a) 会计框架是否接受"逐仓=级别隔离/全仓=利润跨级别流动"作为设计公理（标注 L0 域外）？(b) 切换是 per-layer（缠师级别独立 ⟹ 每层独立判 cost_basis 阶段，倾向此）还是全局（"全仓"本是账户级概念）？(c) 三阶段会计的 INV-1（恒仓）在期货标的上是否成立（第33课留白）？
>
> **(d) 已结算为定理（非 /escalate）**：禁止把 cost_basis<0 编码进期货逐仓强平豁免——这是 §2.3 物理分离（强平永远读 basis>0）的逻辑必然，有效域越界的硬约束，自动结算，不待裁决。

### 4.5 切换是 per-layer

缠师"级别独立"（第5课）+ 275号局部依赖（"附庸的附庸不是我的附庸"）⟹ 倾向 **per-layer**：每层独立判定自己的 `cost_basis` 穿零（第49课"小级别不会成本为0"明示不同级别相变时点不同）。核心层先达负成本（深层短差累积最快），其负成本触发该层逐仓→全仓；次级别层各自判定。精确条件：`layer.stage == EarningShares ⟹ 该 layer 切入全仓结算`。

> **实装解读（OQ-5(b)）**：当前 T 引擎是**单核心 + 短差对冲塔**架构，子级腿是降成本的**工具**（瞬态对冲）非被降成本的独立持仓，只有核心仓累积降成本。故 cost **阶段**实装为**引擎级单核心 campaign**（一个核心仓一个阶段），逐仓**风险**隔离（每层独立强平）引擎已有。若将来改多独立核心（`project_t_multiscale_independent_filters`），再 per-layer 化阶段。见 §4.6。

### 4.6 保证金模式与三阶段耦合（编排者裁决 2026-06-20）

**全仓/逐仓 = 保证金计算模式，不是利润跨级别流动**（与 §4.3 的"利润流动"是两个正交维度）。三阶段切换保证金模式：

| 阶段 | 保证金模式 | 强平判据 | 理据 |
|---|---|---|---|
| ① CostReduction | **逐仓** | 每层独立 `c ≤ basis/SUB_LIQ_FACTOR`（多）/ `c ≥ SUB_LIQ_FACTOR·basis`（空） | 本金在险，次级别短差亏损**不侵蚀核心仓保证金**（每层独立判，现状） |
| ② CapitalRecovered | **逐仓**（转换点） | 同上 | 退本金进行中，本金未完全退出安全池，保守保持逐仓 |
| ③ EarningShares | **全仓** | 账户级：in-system NAV（`free+Σsign·u·c`，**不含 withdrawn**）≤ 0 ⇒ 连锁全平 | 本金已退安全池、仓位由纯利润支撑，"立于不败"使连锁爆仓风险可接受（只损失利润不触本金）；短差腿回撤被共享池吸收、不被单层提前止损 |

**与 §2.3/§4.4 的一致性（关键，非矛盾）**：
- §2.3 的"basis<0 永不强平 bug"针对**逐仓**模式（判据读 basis）——逐仓在阶段一/二**保留，仍读 basis 不读 cost_basis**，无 bug。
- §4.4 OQ-5(d) 禁的是"把 cost_basis<0 编码进**逐仓强平豁免**"（静默让 c≤basis/2 永不触发）。本裁决**不是静默豁免**，是**按 stage 显式切换到全仓**（账户级 NAV≤0 判据），有明确理据。**区别**：静默-never-trigger（bug）vs 显式-账户级判据（设计）。**兼容**。

**会计正确性（1x 几何塔自洽，L0）**：核心多头主导（Σlong>Σshort）时账户 NAV = `free + (Σlong−Σshort)·c` **恒 ≥0**（价→0 时→free≥0；价→∞ 时核心主导→+∞）。故全仓的"NAV≤0 连锁全平"在 1x 下**几乎不触发** = 仓位自由骑乘（正是"立于不败"），且**总财富守恒不被破坏**（无需 floor）。

> **有效域标注（杠杆期货）**：账户级判据 `NAV≤0` 是 **1x 现货口径**（withdrawn 已隔离不作保证金）。杠杆期货上维持保证金 > 0，应为 `NAV ≤ maintenance`；且 withdrawn 是否真隔离于保证金账户取决于券商，须 L2 标注（OQ-5(c) 期货有效域）。

## 5. drain 的重新定义

### 5.1 drain 现状是泄漏点 `[L0，代码事实]`

drain（`t_engine.rs:280-287`）是**纯单腿 `reduce_at` 无 `add_at` 回腿**，减子级"同父向遗留仓" m=u/3，现金进 `free` 后**永不回到敞口**（`reinvest_absence` 全分支枚举证明：核心持仓期无任何代码把增长的 free 重新部署成 units）。**降成本 alpha 是死现金。** 这正是三阶段框架要修复的——drain 的钱缺一个 `cost_basis` 字段去承接。

### 5.2 三阶段框架下 drain 应该是什么 `[L0（条件于 OQ-7 读法 A）+ 第65课递归归属]`

> **有效域限定**：本节按 drain **读法 A**（减暴露、realized 计入降成本）展开。L0 的有效域**条件于 OQ-7 裁为读法 A**；若裁为读法 B（结构归位 relabel、零 P&L），则本节"阶段一降 cost_basis"分支失效（drain 改为不记 realized 的结构 merge），见 §5.4。

**第65课级别递归归属裁决 drain 的对象**：drain 触发于"子级 j 持**同父向遗留仓**"（`layers[j].direction == pdir`）。按第65课 `Move(k)≡Level-(k+1) 的笔`，子级持的同父向仓**本就是父级核心仓的级别构件**（不是反父向短差 mob，而是低级别同向走势散落的部件）。所以 drain 处理的对象**本质属于父级核心仓**。

drain 按父级 `stage` 分流：

```
父级 stage == CostReduction（cost_basis>0，阶段一）：
    drain 的钱 → 降 cost_basis
    会计原子：reduce_at(j, m=u_j/3)  [现有单腿，realized 已落 mobile_realized_pnl_by_ladder[j]]
             ＋ 同步 cost_basis_parent -= realized_drain / units_parent
    语义：drain 的 realized 不再死在 free，而是摊薄核心持仓成本（第26课"短线把成本降下来"）。
    这把 drain 从"减暴露"重定义为"merge 回父级的降成本贡献"——
    "merge 回父级"与"降 cost_basis"是同一会计动作的两面（回答 drain_and_three_stages §6 读法B）。

父级 stage == EarningShares（cost_basis≤0，阶段二）：
    drain 的钱 → 增 units
    会计原子：reduce_at(j, m) 产生 realized 进 free
             ＋ add_at(parent, m'=realized_avail/c, dir_parent)   [增股数回投]
    语义：cost_basis 已锁0，realized 现金转为核心层新 units（第48课"差价…筹码越多"）。
    资金来源严格约束：回投现金 ⊆ realized_cum，不动初始本金（INV-3）。
```

### 5.3 增股数回投时点 `[原文给出，对抗审查后修正]`

利润→新 units 的兑换时点**有原文**——第31课 line 169 直接定义（对抗审查发现，初稿误判为留白）：

> "成本为0后，**抛出后，跌回来，就把抛出的钱，全补进去**，这样买回来的数量一定多了，股票才会越来越多。"

逐字解读：(1) "抛出后，跌回来" = **卖点抛、回落到下一个买点再补**（不是立即）；(2) "把抛出的钱，**全补进去**" = 回投**全部** realized 现金（与第31课 line 36"卖出多少资金就买入多少资金"一致）。这是**选项 (b)（下一个同向买点回投全部 realized）**，**原文明确支持**，与第49课"中枢下方仓位增加"互证。

> **开放问题 OQ-6（已收窄为定理）**：回投时点 = **下一个同向买点回投全部 realized 现金**，有第31课 line 169 + line 36 逐字原文支撑，**不再是开放问题**，降级为定理。剩余细节（"下一个买点"具体取哪个级别的买点——核心层 type1 还是次级别 type2/3）属定位精度问题，由区间套定位（§3.4 / `unified_recursive_operator_T.md §3.4`）解决，非价值判断。

### 5.4 drain 读法 A vs B 仍是开放问题 `[/escalate]`

`drain_and_three_stages.md §6` 已登记的读法分叉，在三阶段框架下**仍未消解**，且新增了一层含义：

- **读法 A（减暴露，局部语义）**：反父向 BSP=减仓信号，drain 局部减 1/3。其 realized **是**降成本 alpha（§5.2 阶段一分支按此读）。
- **读法 B（结构归位，全局结构）**：drain 处理的"同父向遗留仓"是结构异常，应在结构重排时 merge 回父级（relabel，零 P&L），让 drain 分支自然死掉。

**定理 vs 选择的分类**（矛盾暴露面板）：
- drain 减暴露的**会计正确性**（NAV 中性、Σ|units| 减 m）= **定理**（`prove_nav_neutral` 守住，自动结算）。
- drain 触发条件（子持同父向仓 + 反父向 BSP）= **定理**（区间套自上而下逻辑必然）。
- 读法 A vs B 的**选择本身** = **选择类**：A 把 drain 现金当降成本利润（有 alpha 归因），B 把 drain 当零 P&L 结构 relabel（无 alpha）。这决定第三阶段增股数的现金来源**是否包含 drain**。

> **开放问题 OQ-7（/escalate）**：drain 读法 A（§5.2 假定）vs B（结构归位）。本体论分歧（局部减仓语义 vs 全局递归结构语义），同构 `project_spiral_closing_level_verdict` / `project_t_short_close_level_mismatch` 的闭合级别归属矛盾，不可设计消化。**本文档 §5.2 暂按读法 A 展开**，但标注此选择待裁决——若裁为 B，则 drain 不应记 realized（应是 relabel），§5.2 的阶段一分支改为结构 merge。

### 6.2 与 `reduce_at` / `add_at` 的关系 `[L0]`

- **插桩锚点唯一**：`reduce_at`（`accounting.rs:112`，唯一记 realized 点）或其调用方。`add_at` 不产生 realized，故"降成本 vs 增股数"判定不在 add_at。

### 6.3 对 NAV 守恒的影响 `[代数中性 L0 / 守卫零 panic L2]`

- 三阶段全部操作（sink/recover/drain 改造后 + 增股数回投 add_at）都是**同价 c** 操作，**代数上** NAV 中性（L0）；`prove_nav_neutral`（`t_engine.rs:383`）逻辑**无需改动**（容差 1e-4），但"改造后全程零 panic"是 **L2 守恒**（须真实数据验证，`prove.rs:14` 口径）。
- 降 cost_basis 是会计标签变更（cost_basis 不进 NAV 公式 `nav()=free+Σsign·u·c`），不动 free/units，NAV 代数不变（L0）。
- 增 units（add_at）同价 NAV 代数中性（L0）。
- **需新增两守卫**（§3.3，代数表述 L0 / 守卫零 panic L2）：`prove_units_monotone`（阶段二 Σ|units| 不减）+ `prove_external_capital_conserved`（回投 ⊆ realized）。

t_engine 的 `recover` 已从 σ-不变 1/3 改为**全量了结**（`t_engine.rs:270`，编排者 2026-06-19 方案②裁决），与 `fugue_v3::cycle::recover_chunk` 的 1/3 配额**有意分歧**，**不受 542号 `prove_sigma_quota` 约束**——t_engine recover 是"次级别走势了结范畴（0/1 事件）"非"σ-不变配额转移"。增股数的 `add_at` extra 部分同样是"兑现"范畴非配额转移，**不引入 σ-不变约束**。三阶段会计文档须注明此与 `operate.rs` 的 1/3 配额守卫不同（避免引 542 作 recover 守卫=范畴错误）。

## 8. 结果包（六要素）

### 1. 结论

设计了缠论持仓三阶段会计框架。核心结论：**当前 T 引擎缺的不是 drain 的回腿，而是一个表达"持仓成本随短差单调下降直至穿零"的状态量 `cost_basis`**（净现金流口径，可<0），它必须与 `basis`（加权入场价，恒>0，强平基准）**物理分离**。该 cost_basis 会计已在 `trading/ledger.rs` OrganicLedger 实装+P5 bit-exact 验证，本文档增量 = 移植到 T 引擎多层逐仓结构（§2.1 边界声明）。基于物理分离：
- 三阶段 = **过程（降成本，ShareConserving，cost_basis>0）— 状态（负成本，cost_basis=0 相变点+无风险性质）— 过程（增股数，AmountConserving，cost_basis<0，Σ|units|↑/外部资本守恒）**；
- 切换判据 = `cost_basis=0`（第31课 line 24/36 + 第48课，原文唯一精确阈值，单向相变）；
- 守恒律从"股数守恒"扬弃为"外部投入资本守恒"（两律有第31课 line 36 逐字原文）；NAV **代数中性 = L0**，**守卫全程零 panic = L2**；
- drain 重定义：阶段一→降 cost_basis（merge 回父级降成本），阶段二→增 units（realized 现金回投，资金 ⊆ realized_cum）；

### 9.3 退本金不可达的根因与修复（编排者 2026-06-20 裁决，已解决）

**根因 = 会计错误（编排者裁决，我初诊不完整被修正）**：初版 `realized_campaign` 把**所有** reduce 的 realized（含**短差对冲腿**的平空盈亏）都计入降成本。强趋势中短差对冲腿**亏损**（sink 高开短差、recover 在更高的下一买点平空 → "低点">"高点" → 空头亏），这些亏损**拖累** realized_campaign，封顶在本金的 0.006~0.40（BTC 0.38 / DX 0.006，初诊测量）。我初诊误判为"无 bug、经济现实"——**实为会计口径错误**。

**修复（编排者裁决 5 点，`account_reduce`）**：
1. **reduce_at 的 realized 立即计入 cost_basis**：`core_cost_basis -= realized / 剩余多头 units`（realized=(c−basis)×m）。
2. **退本金不产生额外交易**：cost_basis 穿 0 仅状态切换（CostReduction→CapitalRecovered），把 free 里 = 本金的钱标记 withdrawn。触发时机永远是某次卖点 reduce 之后。
3. **增股数不产生额外信号**：EarningShares 买点（recover）用 earning_cash 加仓（`deploy_earning`）。
4. **三阶段不产生任何新交易信号**，只改已有买卖点的会计处理。
5. **★关键：reduce 与短差分开核算**：核心**多头 reduce**（高位卖出核心）的 realized = 降成本主力 → cost_basis；**短差腿（Short reduce：做空→平空）**的盈亏**单独算（`short_leg_pnl`），不混入降成本**。

**结果（BTC 4.6M bar，修复后）——退本金从空域变为激活：**

| 模式 | strat% | 基线% | 退本金 | 增股数 | 降成本进度峰值 | 短差腿pnl |
|---|---|---|---|---|---|---|
| structural | +25.3% | +29.6% | **2** | 366 | **1.24×** | +5490 |

**与初诊"决定性矛盾"的和解**：初诊认为"纯短差不可达本金、需 OA-1 部分了结"。修正：缠师第31课 line 28 的"出掉部分核心"在引擎里**正是 sink 的核心 reduce**（高位卖核心 1/3）——只要把其 realized 正确计入降成本（不被短差腿亏损抵消），就等价于"部分了结收回本金"。**无需独立的 OA-1 升幅判据**，编排者点1/点5 的会计修复即实现了缠师 line 28 的本金回收语义。
