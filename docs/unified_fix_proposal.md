## 0. 一句话

**引擎的 alpha 在方向判断上产生（H⁰，7/8 标的 leg 方向赢），却在仓位管理上被销毁
（H¹，units 单调饿死）。根因是引擎丢失了缠论操作的核心状态变量 `cost_basis`——
它把"降低持仓成本"（股数守恒、成本下降）误执行成了"减仓 / 销毁仓位"（股数减少）。**

修复的钥匙是一个：**引入 cost_basis，把所有操作从「units 增减」重写为「cost_basis
演化 + units 守恒」。** 这一把钥匙同时打开 H¹ 的全部仓位病，并与 H⁰（走势动态化）、
groupoid（确认对称化）的修复正交组合。

## 1. 统一诊断：alpha 在方向，死在仓位

### 1.1 症状之王：信号对但 units 饿死（实证 5）`[L2]`

- 方向判断对了：8 标的中 **7/8 的 leg 方向是赢的**（H⁰ 构造轴健康）。
- 但没有钱押在判断上：**units 被单调饿死**（H¹ 操作轴失血）。

**根因链 `[as-is]`**（取证确认，`t_engine.rs`）：

```
reduce 2374 次（父级别卖点，频繁触发，每次下放 1/3 units）
   ├─ recover 1243 次（子级别买点 ∧ 父级别仍活跃 → 升回）   ≈ 半数
   ├─ drain   592 次（父级别已翻转/不活跃 → units 无处归 → 记入 realized 后移出账本）
   └─ 悬空    539 次（下放后既未升回也未排空）
净效果：2374 下放，仅 1243 升回 → 核心仓 units 单调萎缩 → 饿死
```

**drain 的本质 `[as-is]`**：次级别走势了结时，units 本应 recover 归还父级别；但当父级别
已翻转/不活跃，units 无处可归，被记入 realized_pnl 后**从 units 守恒账本移除**。它不是
凭空消失（转成了现金），但**违反「核心仓 units 守恒」**——股数被换成现金，持仓规模缩小。
**在缠论语境下，这等于「把底仓也卖了做差」，违反第26课恒仓原则。**

### 1.2 三轴病症表 `[L0+as-is]`

| 轴 | 缠论本质 | 引擎丢失了什么 | 后果 | 对应问题 |
|----|---------|--------------|------|---------|
| **H⁰ 构造** | 走势动态 open、中枢扩展/延伸/升级 | 中枢一次性固定、走势边界静态、分解唯一 | 最高级别误判盘整、c 段丢失、type1 不产 | C1/C6/C7 + 实证4 |
| **groupoid 确认** | 介入/离开对称、确认在时间里递归 | 确认无时间索引、离开右侧滞后、介入被弱化 | 信号滞后、踏空 | C2/C3/C14/C15 |
| **H¹ 操作** | 持仓 = cost_basis 演化、底仓守恒 | **无 cost_basis**、reduce/recover 不配对、drain 销毁 | **units 饿死（信号对没钱）** | 实证1/2/3/5 + C8/C13/C19 |

### 1.3 统一根因 `[L0]`：丢失了缠论操作的目标函数

缠论操作（第26课 `[原文]`）的目标函数**不是**"低买高卖赚差价"，**而是**"用差价降低
底仓成本，直到成本为负、立于不败"。缠师原话：

> "通过不断的高抛低吸，你的成本会越来越低，最理想的情况下，你最后持有的成本是负的，
> 这样就立于不败之地了。"（第26课 `[原文]`）

这意味着：**底仓（核心仓）一直持有骑趋势；机动仓的高抛低吸不是为了赚差价本身，而是
为了降低底仓的 cost_basis**，直到底仓成本为负——此时无论价格怎么跌都不亏。

引擎完全没有这个目标函数。它的操作是"卖点 reduce、买点 recover、了结 drain"，把
**底仓也当机动仓减/销毁**了。`cost_basis` 是这个目标函数的唯一载体；没有它，"降成本"
无从表示，只能退化为"减仓"。**这是 17 个问题（12 矛盾 + 5 实证）的同一个根。**

## 2. 第一性原理：缠论操作的会计本质

### 2.1 恒仓 = 底仓不动 + 机动仓中枢震荡高抛低吸 `[原文]`（第26课）

> "真正的操作是动态的，在中枢震荡中不断地高抛低吸，用一个底仓不动，其余部分进行短差。"

注意：缠师原文用"**底仓**"，本方案沿用（区别于引擎的"核心仓"）。底仓**永不**因短差而
减少——这是恒仓的硬约束，也是 drain/reduce 必须修复的红线。

### 2.2 降成本 = 高抛低吸的累积，units 守恒、cost_basis 下降 `[原文]`（第26课）

每次中枢震荡，机动仓**高卖低买**：卖出和买回的是**同一批机动仓股数**，所以 units 守恒；
但每次"高卖价 > 低买价"的差额，**摊薄到底仓上，降低 cost_basis**。降成本 = 这个摊薄的
累积效应。**关键：降成本操作 units 守恒，改变的是 cost_basis，不是持仓数量。**

### 2.3 持仓三阶段（诚实标注：半原文 + 综合层细化）

| 阶段 | 定义 | 标注 | 依据 |
|------|------|------|------|
| ① 降成本 | cost_basis 从入场价向 0 下降 | `[原文]` 状态 | 第26课"成本越来越低" |
| ② 负成本（立于不败） | cost_basis ≤ 0 | `[原文]` 状态 | 第26课"成本是负的，立于不败"；第15课"成本是0…立于不败之地" |
| ③ 增股数（挣股数） | 负成本后用利润扩大持仓数量 | **`[综合]`** | 缠师有"立于不败"状态描述，但**无"负成本后系统性增加股数"的操作纲领** |

> **诚实声明 `[L0+L2]`**：阶段①②的**状态**有缠师原文背书；但「把它形式化为离散三阶段
> 且以 cost_basis≤0 为相变阈值」是综合层建模；阶段③（增股数）是综合层推导。且
> `project_earning_shares_empty_domain` `[L2]` 实测：增股数在 QQQ/OKLO 1min 为 **0 笔
> 空有效域**——因为 **units 先被 drain 饿死了，根本到不了负成本**。所以阶段③能否非空，
> **前提是先修好 drain（§3.1）**。这是因果链，不是并列。

### 2.4 核心命题 `[L0]`

> **持仓是 cost_basis 的演化，不是 units 的增减。**

介入（一买）建立底仓（cost_basis = 入场价）→ 持有期底仓不动、机动仓高抛低吸把
cost_basis 摊低 → cost_basis≤0 立于不败 → 离开（一卖）时按 cost_basis 决定底仓去留。
**确认结构（介入/离开，前文的轴）与持仓结构（cost_basis 三阶段）在这里统一：介入建
底仓、降成本演化、离开清机动仓（底仓视成本决定）。**

## 3. 三轴修复（统一，按致命度排序）

### 3.1 H¹ 操作轴修复（最致命，P0 止血）

**修复 1：引入 `cost_basis` 状态变量 `[L0]`**（对应 C 实证2，根因）
- 每个 LevelEngine / 持仓单元增加 `cost_basis`（持仓成本基）。
- `fugue_v3/accounting.rs` 已有 `Position.basis` 概念 `[as-is]`——把它接入 `t_engine.rs`
  的操作层（当前未接入）。不重新发明，复用既有会计。

**修复 2：删除 drain，units 强制守恒 `[L0]`**（对应实证1，N8 守恒）
- **删除 drain 这个操作**——缠论里没有"销毁仓位"，只有买/卖/持有。
- 次级别走势了结时，units **必须** recover 归还父级别；若父级别已翻转/不活跃，则归还到
  **最近的活跃祖先**（`nearest_active_parent`，引擎已有此概念）或底仓，**绝不移出账本**。
- 验收：`Σunits = N_base` 每 bar 成立（N8 守恒，`prove.rs` 已有断言；当前 drain 路径
  绕过了它——堵死这个逃逸口）。

**修复 3：reduce/recover 重写为机动仓高抛低吸，底仓守恒 `[L0]`**（对应 C8/实证5）
- 区分**底仓**（恒仓，永不因短差减少）与**机动仓**（1/3 配额，σ-不变，第26课"其余部分"）。
- 父级别卖点 → 卖出**机动仓**（不是底仓！），记 `pending_rebuy`，cost_basis 不变（现金待回补）。
- 子级别买点 → 用 `pending_rebuy` 买回机动仓，**高卖低买的差额摊低底仓 cost_basis**。
- 底仓的减少**只在**离开（趋势顶背驰，§3.3）时发生，**不在**中枢震荡时发生。
- 这一条同时填补 C8（中枢震荡段操作空白）：中枢震荡的操作 = 机动仓高抛低吸降成本。

**修复 4：三阶段状态机 `[综合]`**（对应实证2）
- cost_basis 驱动的状态机：`降成本(basis>0) → 负成本(basis≤0) → 增股数(basis≪0)`。
- 阶段转移是 cost_basis 阈值穿越，金额守恒（`project_earning_shares_empty_domain`
  的 EARNING_SHARES 态要求）。
- 增股数阶段标注 `[综合]`，且其非空**依赖修复 2 先止血**（§2.3 因果链）。

**修复 5：逐仓/全仓切换 `[综合]`**（对应实证3）
- **诚实标注**：逐仓/全仓/杠杆/保证金缠论**无原文**（缠师在 A 股现货 T+1 无杠杆语境）。
  全是综合层期货扩展，**须独立验证有效域**（`project_leverage_triad_formalization` /
  `project_notional_leverage_research` 已有形式化但未进引擎）。
- 设计假设（待 L2 验证）：阶段①降成本（风险未消）→ **逐仓**（隔离单点爆仓）；阶段②③
  负成本（立于不败，下行风险已被负成本 buffer 吸收）→ **可全仓/加杠杆**。
- 依据 `project_leverage_triad` 的"升级负债定理（补保证金先于加仓）""单边律（只降不升）"。

### 3.2 H⁰ 构造轴修复（走势动态化，P1）

**修复 6：中枢扩展/延伸/升级 `[原文]`**（对应 C7 + 实证4，第9/18/29课）
- 中枢**延伸**（第18课）：同一中枢在震荡中纳入新的次级别走势，只要不脱离 [ZG,ZD]，
  中枢持续变长（参与段增加，仍是同一中枢）。
- 中枢**扩展**（第9课）：相邻两中枢有重叠区间时，合并为一个更大的中枢（区间取并）。
- 走势**升级**（第29课）：离开段 c 不背驰反而延伸出新同向中枢 → 趋势 2中枢→3中枢
  （趋势延续）；背驰-转折定理 → 背驰导致走势终结 → 转更大级别盘整（中枢扩展）或反趋势。
- `[as-is]` 病灶：`center.rs:find_centers` **一旦中枢成立就固定**（贪心，区间成立时确定，
  后续不扩展不延伸）；`trend.rs` 按固定中枢分组，无合并/升级。**中枢是"一次性识别"
  而非"动态生长"**——这是 C7 的代码层证据。
- to-be：中枢从"一次性识别"改为"动态生长对象"，支持延伸（变长）/扩展（合并）/升级（提级）。

**修复 7：BTC 最高级别盘整误判 `[L0+as-is]`**（对应实证4）
- `[as-is]` 机制确认：BTC 最高级别识别出 2 中枢，但 `same_direction_step` 用外缘
  [DD,GG] 判同向——两中枢外缘重叠则返回 `None` → 被切为两个独立单中枢盘整 → 最高级别
  无"2 同向中枢趋势" → 无趋势背驰 → 无离开段 c → **无 type1_buy**。
- 根因 = **中枢不扩展**（若扩展，2 中枢应合并为 1 个大中枢、或正确识别为升级中的趋势）
  + `same_direction_step` 外缘重叠判据过严。
- to-be：修复 6（中枢扩展）落地后，外缘重叠的两中枢应触发**扩展合并**判定或**走势升级**
  判定，而非简单切成两个盘整。

**修复 8：走势边界动态 open `[L0]`**（对应 C1）
- 走势在背驰确认前是 **open/未完成**的，边界随中枢增减动态移动。
- 引入 candidate 边界（当前最后中枢之后）vs confirmed 边界（背驰点）。这与 H¹ 的
  candidate/confirmed（介入/离开）同构（537号双重性）。

**修复 9：走势分解锚定 + a0=线段 `[L0]`**（对应 C6/C5）
- 分解非唯一（第17课），T 给出的是**锚定于上一个 confirmed 转折点**的分解，声明这一点。
- a0 = **线段**（最低级别走势类型），不是笔（笔无中枢、不是走势类型，C5）。"笔级别确认"
  通过区间套在线段之下用类背驰精确定位实现（第29课），不是把 a0 降到笔。

### 3.3 groupoid 确认轴修复（对称化、时间索引，P2）

**修复 10：介入/离开结构对称 `[L0]`**（对应 C15/C3）
- 介入和离开**结构对称**：都是趋势背驰（≥2 中枢）+ 区间套 + 左侧。介入 = 下跌趋势底
  背驰；离开 = 上涨趋势顶背驰。区别只是**方向**和**时间**。
- 撤销"介入只需次级别一个背驰（结构小）"的伪不对称——那个"次级别一个背驰"是区间套里
  **定位**一买用的类背驰精确点，不是一买本身。
- "确认的确认"是**时间因果**关系（后一个背驰回溯证明前一个），不是结构量级关系。

**修复 11：离开左侧化 `[L0]`**（对应 C14）
- 离开也区间套化：不等高层 confirmed（实测滞后 ~13694 bar），而在次级别背驰出现时在
  高层 candidate 上左侧离开。离开与介入对称——都是 candidate 层左侧动作 + 次级别确认。

**修复 12：确认时间索引 `[L0]`**（对应 C2）
- 把"确认下放给演化/未来"改为"确认下放给**已实现的次级别后续**"：`confirmed(k,t)`
  依赖 k-1 在过去 `[t', t]` 的已实现走势（t'<t）。构造 T 是因果的（k-1 已完成→k
  candidate），确认是事后的（k-1 后续反向走势→追认 k candidate 为 confirmed）。无循环。

**修复 13：盘整背驰离开 `[原文]`**（对应 C13，第24课）
- 区分趋势背驰离开（清机动仓 + 视 cost_basis 处理底仓）vs 盘整背驰离开（**减机动仓不清
  底仓**，因第24课"盘整背驰不一定转折，可能还在同一走势类型里"，力度弱）。

**修复 14：二三类买卖点操作位置 `[原文]`**（对应 C19，第17/29课）
- 三类买点（中枢离开确认）= 趋势加仓/底仓确立点；二类买点（次级别回抽）= 中枢震荡的
  机动仓补仓点。归约关系（理论）与操作位置（实战）分开陈述。

## 4. 统一状态机：做多生命周期

> 前提（实证，`[综合]`，编排者约束）：市场无限做多，本方案只走做多主线；做空镜像但
> 失血有效域问题搁置（§7）。

```
[空仓]
  │  介入 = 一买（下跌趋势底背驰，区间套左侧定位）        ← 修复 10/11/12
  ▼  建底仓 + 机动仓；cost_basis = 入场均价；逐仓        ← 修复 1/5
[降成本阶段 basis>0]
  │  中枢震荡：底仓不动，机动仓高抛(卖点)低吸(买点)        ← 修复 3/14（C8 填补）
  │  每轮高卖低买差额摊低 cost_basis；units 守恒          ← 修复 2/3
  │  中枢延伸/扩展 → 不离开，继续降成本                  ← 修复 6（C7）
  │  走势升级(2→3中枢) → 底仓 relabel 到更高级别          ← 修复 6/8
  │  盘整背驰 → 减机动仓，不清底仓                       ← 修复 13（C13）
  ▼  cost_basis 穿越 0
[负成本阶段 basis≤0 立于不败]                            ← 第26课原文状态
  │  可切全仓/加杠杆（综合层，待验证）                    ← 修复 5
  ▼  basis≪0
[增股数阶段（综合层，依赖 drain 已修才非空）]              ← 修复 4（§2.3 因果）
  │
  ▼  离开 = 一卖（上涨趋势顶背驰，区间套左侧）            ← 修复 10/11
[清机动仓；底仓按 cost_basis 决定去留]
   - basis>0：全清（保护本金）
   - basis≤0：可留负成本底仓骑更高级别趋势（立于不败，不必全清）
```

**这个状态机统一了 12 矛盾 + 5 实证**：确认结构（介入/离开，修复 10-12）定义生命周期的
两端；持仓结构（cost_basis 三阶段，修复 1-5）定义中间的演化；走势结构（中枢动态，
修复 6-9）定义边界何时移动、何时升级。三轴正交但在状态机里协同。
