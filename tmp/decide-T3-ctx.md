# Gemini Decide 上下文：T3 — 105号声明-能力不一致（090号违反）

**决断类型**: 选择（但分析后可能降级为定理）
**优先级**: P0
**日期**: 2026-02-22

## 问题精确描述

105号谱系（编排者INTERRUPT）声称：
> "永远默认严格使用真递归拓扑异步自指蜂群。Trampoline永久禁止。"

但系统的工程现实是：
- 所有蜂群（v30/v31/v32/v33）都是 Lead 直接 spawn 多个平行 worker 的扁平架构
- 这恰好是073b号定义的 **Trampoline模式**
- 073b平台约束"subagent 不能 spawn sub-subagent"仍然存在
- 095号确认 Agent Team 支持真递归但工程深度上限 ≈ 3-4 层

090号（严格性是蜂群的语法规则）的定义：
> 严格 = 概念清晰 + **声明与实际一致** + 没有未定义的模糊地带

105号违反090号的第二条——声明（Trampoline永久禁止）与实际（所有蜂群都是Trampoline）不一致。

## 谱系逻辑链

1. **105号** depends_on 095/097/104 → 编排者INTERRUPT："这就是我的架构"
2. **095号** negates 073b → 真递归是默认模式，Trampoline是退化特例
3. **073b** → Trampoline是平台约束下的递归近似（subagent不能spawn sub-subagent）
4. **090号** → 声明-能力一致性是严格性的核心维度
5. **104号** → "递归在093号中无对应约束——递归是功能选择而非物理约束"

## 各选项分析

### 选项A：修正105号声明匹配实际能力

**内容**：105号的"Trampoline永久禁止"修正为"Trampoline是退化特例（需要理由），真递归是默认模式（不需要理由）"。这与095号的表述完全一致。105号的"无条件"降级为"强默认"。

**优势**：
- 直接消除090号违反
- 与095号（修正后的表述：真递归是默认，Trampoline是退化特例）完全对齐
- 诚实——承认当前实现的限制，而不是声明不具备的能力
- 084号先例：声明-能力缺口的标准解法就是修正声明

**劣势**：
- 部分否定编排者INTERRUPT（但087号有先例——INTERRUPT可被后续系统演化修正）
- 编排者原始意图"永远不要用Trampoline"被弱化

**影响范围**：
- 105号 frontmatter 需要标注 negated_by（部分）
- CLAUDE.md 原则15 中的"Trampoline永久禁止"需要修正
- 不影响095号/097号的结论

### 选项B：实现真子蜂群嵌套

**内容**：让 L1 teammate 能 spawn L2 子蜂群，所有蜂群必须使用嵌套架构。

**优势**：
- 兑现105号声明
- 推进069号理想架构的实现

**劣势**：
- 073b平台约束仍然存在——095号承认工程深度上限 ≈ 3-4 层
- 即使实现了真递归嵌套，当任务不需要独立治理的子蜂群时（095号表述），强制嵌套是过度工程
- 不解决105号声明中"永久禁止"的过强表述——Trampoline在某些场景下仍然合理（095号明确允许）
- 实现工作量不消除声明-能力矛盾的逻辑本质

**影响范围**：
- 需要修改 ceremony skill、dispatch-dag、所有蜂群实现
- 需要验证真递归在实际场景中不引入过多开销

### 选项C：重新定义"真递归"

**内容**：声称当前的"Lead spawn多worker + 每个worker管理自己的5特征DAG任务列表"已经满足递归要求（递归的表现形式不是调用栈嵌套而是任务列表嵌套）。

**优势**：
- 不需要修改任何声明或实现

**劣势**：
- **违反 no-workaround.md**："模糊化处理让两种矛盾的理解都能通过"
- **违反090号**：重新定义概念让声明看起来成立 ≠ 声明与实际一致
- 073b号已经精确区分了"调用栈递归"和"Trampoline"——两者不是同一事物
- 本质上是语义修改而非问题解决

**影响范围**：
- 无修改但引入概念模糊——长期退化风险

## 推导分析

从已有谱系逻辑可以推导：

1. 090号是语法规则 → 声明-能力不一致是语法不合法的
2. 105号声明了系统不具备的能力 → 语法违反
3. 选项C试图通过重定义消除矛盾 → 违反 no-workaround.md
4. 选项B在工程上可行但不消除声明过强的逻辑问题
5. ∴ 选项A是逻辑必然——修正声明，保留意图

**这可能是定理而非选择**：
- 如果接受090号（声明-能力一致性）和105号（Trampoline禁止）同时为语法规则
- 且实际不满足105号
- 则105号必须修正（090号作为语法规则优先级等于或高于105号这个选择类决断）
- 选项A是唯一不违反其他语法规则的选项

**但存在真选择的维度**：105号是编排者INTERRUPT（人类决断），090号也是编排者INTERRUPT提升的语法规则。两个编排者决断冲突时，谁优先？这需要**价值判断**，不是纯逻辑推导。

## 推荐

**推荐选项A**——修正105号声明匹配实际能力。

理由：
1. 090号是从三次编排者INTERRUPT中提炼的**语法规则**，105号是单次INTERRUPT的**选择**。语法规则的约束力大于单次选择。
2. 095号（修正后版本）已经给出了正确的表述："真递归是默认模式，Trampoline是退化特例"。105号的"永久禁止"与095号自身矛盾。
3. 087号先例：编排者INTERRUPT可被系统演化修正（086号全C被087号否定后，编排者的方向意图被保留但具体方案被更严格的方案替代）。

具体修正：
- 105号的"Trampoline永久禁止"→"Trampoline是退化特例，使用需要理由"
- 105号的"无条件架构要求"→"强默认架构偏好"
- CLAUDE.md 原则15 相应更新
