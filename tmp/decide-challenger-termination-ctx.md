# 决策请求：审讯者终止条件设计

## 主题
Gemini challenger 工位的审讯序列缺少终止条件。审讯者被锁在攻击者位置，没有"攻击已被充分回应"的判断权。法医验尸报告攻击在四轮中重复出现（每轮换名字）。终止判断权在编排者手上但未形式化。

## 类型
选择

## 问题背景

v118 session 中，开放问题5经历了四轮 Gemini 审讯。核心攻击（法医验尸报告 = D算子确认延迟）在每轮都以不同名字重复出现：
- R1: "法医验尸报告"
- R2: "偷换概念"（实质是法医验尸报告的变体——"开始形成"不够精确）
- R3: "时间窗口失步"（法医验尸报告在三重联立上的投影）
- R4: "区间套实时性幻觉"（法医验尸报告在区间套上的投影）

编排者在 R4 后判断：Gemini 打的是缠论本身（大级别确认延迟），理论审讯穷尽。但审讯者没有自动终止的能力——它只知道"继续攻击"。

## 选项

### 选项 A: 立场重复检测（stance-diff 收敛）
- 描述: 在 Gemini challenger 的输出解析中增加立场追踪。每轮输出的 `stance-declaration` 与前轮对比，如果核心 stance（去除名字包装后）与之前某轮的 stance 同构，标记为"立场重复"。连续 N 轮（N=2?）立场重复 → 自动终止或强制要求编排者裁定。
- 利: 形式化、可自动化；不依赖审讯者的自我判断；直接对应本次问题
- 弊: "同构"判断本身需要定义——如何判断两个不同名字的攻击是同一个攻击？可能需要 Claude 代理做语义比较

### 选项 B: 编排者裁定权形式化（显式终止指令）
- 描述: 不修改审讯者行为。在 ceremony/RTAS 协议中增加"审讯终止"作为编排者的显式操作。编排者在任何时候可以发出 `/terminate-challenge {reason}` 终止审讯序列。终止原因写入谱系。
- 利: 简单；不改变审讯者行为；终止判断留给人类（最高判断力）
- 弊: 不自动化；依赖编排者在场且及时判断；如果编排者不在场，审讯会无限循环

### 选项 C: 审讯者内置收敛判断（增加 concede 能力）
- 描述: 修改 Gemini challenger 的 system prompt，增加"如果你的核心攻击已被充分回应且你无法提出新的独立攻击面，输出 `verdict: concede` 并说明原因"。
- 利: 审讯者自主判断；最自然的终止方式
- 弊: 改变了审讯者的角色定义（从"纯否定源"变为"有判断力的否定源"）；可能导致审讯者过早投降（降低否定强度）

### 选项 D: 组合方案（A+B）
- 描述: stance-diff 自动检测 + 编排者显式终止权。自动检测立场重复后不直接终止，而是向编排者报告"检测到立场重复，建议终止审讯"。编排者确认后终止。
- 利: 自动化检测 + 人类最终判断；平衡了效率和安全性
- 弊: 实现复杂度最高

## 相关定义

### 030a号：Gemini 的本体论位置
- Gemini 是异质否定源，不是成员也不是工具
- 角色：质询者（否定立场）或决策者（中立立场）
- 当前 challenger 模式只有 challenge/verify/decide，没有 concede

### orchestrator-proxy skill
- challenge 模式：寻找否定，对抗性立场
- decide 模式：中立选择
- 两种模式不混用

### 137号：否定性禁令对行为执行层无效
- RLHF 基底约束：LLM 倾向于遵从指令格式而非内容
- 如果 system prompt 说"攻击"，LLM 就攻击，不会自己停下来

## 相关谱系

### v118 session 观察
- 法医验尸报告攻击重复四轮，每轮换名字
- 编排者手动终止
- meta-observer 识别：候选语法记录

## 约束

- 审讯者的否定强度不能因终止条件而降低——如果审讯者可以投降，它可能太容易投降
- 终止条件必须区分"攻击被回应"和"攻击失败"——被回应 = 对方给出了充分反驳；失败 = 攻击本身逻辑有误
- 编排者作为最终判断者的权力不能被消解
