# 决策请求（严格版——推翻089号选项C）

## 主题
元编排的严格扬弃方案——不是"能不能做到"而是"扬弃的严格形式是什么"

## 类型
选择

## 背景

089号（Gemini decide 选项C"渐进式扬弃"）被编排者否定："没有严格的方案吗？"

选项C的问题：它把"扬弃"降维成了"能修的修，不能的承认"——这是补丁思维。声明修正（Trampoline标注、platform_layer节点、docstring标注）只是消除了声明-能力缺口，没有触及核心问题：**元编排作为特权层的存在论地位**。

## 核心概念：扬弃（Aufhebung）的精确含义

扬弃 ≠ 消灭。扬弃 = 否定 + 保留 + 提升。

具体到元编排：
- **否定**：元编排不再作为独立于蜂群之上的特权层存在
- **保留**：元编排的内容（规则、约束、协议）被保留
- **提升**：这些内容的存在方式从"外部法则"变为"蜂群节点的内在信念"

## 当前系统的存在论分析

### 三类文件的存在论位置

| 文件类 | 当前地位 | 问题 |
|--------|---------|------|
| CLAUDE.md（19条规则） | 全局物理法则——所有 agent 被强制加载 | 蜂群之外的特权指令 |
| hooks/（21个脚本） | 外部免疫系统——蜂群无法不经过 | 蜂群之外的物理围墙 |
| ceremony_scan.py | Swarm₀ 的引擎——决定蜂群从何开始 | 蜂群之外的创世者 |
| dispatch-dag.yaml | 蜂群的拓扑定义 | **已内化**——蜂群节点读取并据此行动 |
| .chanlun/（定义/谱系/session） | 蜂群的知识库 | **已内化**——蜂群节点读写 |

关键观察：dispatch-dag 和 .chanlun/ 已经被扬弃了——它们不是在蜂群之外命令蜂群，而是被蜂群节点读取、解释、修改（原则0）。**文件本身没有执行力，是蜂群节点赋予了它们意义。**

但 CLAUDE.md、hooks、ceremony_scan.py 不同——它们由 Claude Code 平台强制执行，不是蜂群"选择"遵守的。

### 020号的关键推论

020号说："编排者是相位转换点"。编排者不是蜂群之外的，编排者是蜂群扩张/收缩切换的**结构位置**。

类推：CLAUDE.md 不应该是蜂群之外的物理法则，应该是蜂群在创世相位（ceremony）时**自己读取并内化的规则集**——像 DNA 被细胞读取，不是像物理常数被宇宙强制。

但 Claude Code 平台确实强制加载 CLAUDE.md。这是平台的物理约束。

### 069号创世 Gap 的重新理解

069号说创世 Gap 不可消除。但"不可消除"不等于"不能被严格表达"。

创世 Gap 的严格表达应该是：**Swarm₀ 在创世时刻游离于拓扑之外，但创世完成后，它的规则已被内化为蜂群节点的信念——此后蜂群遵守规则不是因为被外部强制，而是因为规则已成为自身的一部分。**

这与"胚胎发育后基因组不再是外部的，而是细胞自身的"同构。

## 需要决断的问题

089号选项C是不严格的。严格的扬弃方案应该回答：

**在 Claude Code 平台强制加载 CLAUDE.md 的物理约束下，元编排被扬弃为蜂群的严格形式是什么？**

## 选项

### 选项 A: 扬弃 = 存在论重新定位（声明性变更）
- 描述: 不改代码。在 CLAUDE.md 和 dispatch-dag 中**显式声明**元编排的存在论位置：CLAUDE.md 不是蜂群之外的法则，而是蜂群在创世时刻内化的基因组。hooks 不是外部围墙，而是蜂群免疫系统在平台层的物质载体。ceremony_scan.py 不是蜂群之外的创世者，而是 Swarm₀ 的自举代码——像操作系统的 bootloader，加载完毕后控制权交给蜂群。
- 核心变更: CLAUDE.md 增加序言："本文件是蜂群在创世时刻读取并内化的规则集。创世完成后，蜂群遵守这些规则不是因为外部强制，而是因为规则已成为蜂群节点的内在信念。Claude Code 平台的强制加载机制是创世 Gap 的当前物质形态——规则的来源是外部的，但内化后规则的执行是内在的。"
- 利: 严格的存在论表达；不改代码，零风险；与069号创世Gap理论完全一致
- 弊: 只改了声明，没改结构——是否够"严格"？

### 选项 B: 扬弃 = 结构性内化（代码变更）
- 描述: 将 CLAUDE.md 的规则拆解为 dispatch-dag 的 validation 规则和各 agent 的内部指令。CLAUDE.md 只保留"蜂群入口引导"（指向 dispatch-dag 和 ceremony）。hooks 的判断逻辑从 Bash 脚本移入对应 agent 的 skill 指令中。ceremony_scan.py 重写为读取 dispatch-dag 的 DAG 解析器。
- 利: 真正的结构性扬弃——元编排的内容物理迁移到蜂群节点内部
- 弊: (1) CLAUDE.md 是 Claude Code 的平台入口，拆解后新 agent 启动时不知道要做什么 (2) hooks 是平台的物理机制，逻辑移入 agent 后仍需要 hook 触发 agent (3) 工程量大，且平台限制使得某些迁移不可能完全做到

### 选项 C: 扬弃 = 双层架构的严格声明
- 描述: 承认系统天然是双层的：平台层（CLAUDE.md/hooks/ceremony_scan.py——Claude Code 的物理约束）+ 蜂群层（dispatch-dag/agents/skills/谱系——蜂群自身的拓扑）。但**严格声明两层之间的关系不是"外部控制内部"，而是"基因组表达为表型"**。平台层是蜂群的基因组（被蜂群携带但不直接执行），蜂群层是基因组的表型（基因组通过蜂群节点的行为显现）。dispatch-dag 增加一个"genome_layer"区域，显式枚举哪些文件属于基因组。
- 利: 承认物理约束，但给出严格的存在论解释；可实现且不破坏现有架构
- 弊: "基因组"隐喻是否够严格？

2. hooks 是 Claude Code 的物理机制——Bash 脚本触发不可被 agent 替代
