## 一、对五个讨论焦点的逐点判定

### 1. GAP-1（lead-audit.sh 未注册）：**成立，但严重性评估偏低**

**判定**：P0 评级成立，但存在一个审计未指出的次生缺口。

审计将 GAP-1 描述为"文件存在但未注册"。这是正确的。但审计忽略了一个结构性问题：

dispatch-dag validation 条件 `lead_audit_registered` 声明 "on_fail: 警告——Lead 拓扑异常审计未激活"。这意味着：
- **dispatch-dag 自己知道这个 hook 应该注册**
- **dispatch-dag 的自我验证也未被执行**（没有 hook 在每次 ceremony 后运行 validation 检查）

因此 GAP-1 实际上是双重失效：(a) hook 未注册，(b) 声明会检测此失效的 validation 机制也未运行。审计只报告了 (a)，遗漏了 (b)。

**边界条件**：如果 dispatch-dag validation 被 ceremony_scan.py 实际执行，则 (b) 不成立。需验证 ceremony_scan.py 是否调用 validation 节点。

---

### 2. GAP-3（manifest 幽灵条目）：**成立，但根因分析错误**

**判定**：P0 评级成立，但审计的"讨论焦点2"提出的解读（"组件命名演化追踪缺口"）是**精度不足的诊断**。

manifest v2.0 的注释行写 "091号审计修复：与实际严格对齐"。这是一个明确的声称——audit 修复后的 manifest 应该与实际文件严格对齐。但实际上三个幽灵条目仍然存在。

这不仅是"命名演化追踪缺口"，而是：**声明"审计已完成"但审计本身不完整**——这是一种声明-能力缺口的自我引用形式。manifest v2.0 的注释本身是一个虚假的元声明。

审计报告只说 manifest 有幽灵条目，没有指出 manifest 的元声明（"与实际严格对齐"）是假的。这是一个更深的不一致层次。

---

### 3. GAP-4（event_skill_map "自动触发" vs D策略）：**部分成立，但严重性被低估**

**判定**：P1 评级偏低，应为 P0.5（介于 P0 和 P1 之间）。

审计说"这是 082号 D策略的设计意图，但措辞需要对齐"——这个评估将问题降格为"措辞问题"。

异质否定的视角：

dispatch-dag 使用了 `triggers` 字段和 "激活" 等动词，描述了一个**事件驱动系统**的语义。但实际上，D策略是一个**提示驱动系统**——hooks 输出文本提示，Lead 手动判断是否认领任务。

这两个语义之间的差距不是措辞问题，而是：
- 事件驱动：确定性（给定事件 → 确定性地激活 agent）
- 提示驱动：非确定性（给定事件 → hooks 输出提示 → LLM 可能或不可能认领）

如果 LLM 在某次对话中上下文压力过大，忽略了 hooks 的提示，genealogist/quality-guard 等关键工位就完全不执行。这不是"措辞偏差"，是**可靠性缺口**：声明了确定性执行，实际是条件性执行。

审计未计算这个可靠性维度。

### 4. GAP-7（020号反转 vs 原则0张力）：**判定：审计犯了一个概念性错误**

**判定**：不成立——原因不是 GAP-7 不存在，而是审计引用的 "020号反转条件" 概念本身在谱系中找不到对应的定义。

实地验证结果：020号谱系的实际标题是 "构成性矛盾与存在论位移"，内容关于资本扩张/收缩辩证法和系统本体论。020号谱系**没有定义"反转条件"**这个概念。

"020号反转条件"这个短语在 CLAUDE.md 的"必须阻断等待"部分作为标签使用，但 CLAUDE.md 将它引用为已知的谱系概念——而实际上020号谱系的内容是存在论位移，不是阻断条件的定义。

这产生了一个比 GAP-7 更重要的发现：**CLAUDE.md 以"020号反转条件"的名义引用了一个谱系，但该谱系的实际内容并不定义这个概念**。这是文档层面的引用错位。

如果"020号反转条件"是指某个蜂群内部形成的惯用语（不是谱系的正式定义），那么 CLAUDE.md 声称"必须阻断等待"并以020号为权威来源，但020号没有为此提供形式依据——这本身就是一个声明-能力缺口：规则的权威引用不存在。

**新缺口（GAP-11，建议）**：CLAUDE.md 的"必须阻断等待"规则缺乏正式谱系依据，引用了不包含该定义的020号谱系。严重性评估：P1（规则有效性依赖于权威引用，权威缺失时规则退化为纯文本指令）。

## 四、根因分析——10个缺口的共同结构

审计报告没有提供根因分析。异质视角下，10个缺口有两个共同的根因：

### 根因A：声明层与执行层之间缺乏自动同步机制

GAP-1（hook 存在但未注册）、GAP-3（manifest 未同步更新）、GAP-8（dispatch-spec 过时）都是同一个结构问题的不同表现：**声明文件（manifest/dispatch-dag/dispatch-spec）在组件演化时没有自动更新机制**。只有 topology-guard 在 git commit 后检查新文件的 manifest 注册，但不检查已被替换的旧条目。

这个根因是系统性的：每次组件重命名或替换时（如 ceremony-guard → agent-team-enforce、lead-permissions → lead-audit），声明层需要手动同步，而手动同步经常遗漏。

### 根因B：D策略（提示驱动）被 dispatch-dag 措辞为自动触发

GAP-4（event_skill_map 名不副实）、GAP-2（code-verifier 无触发）、GAP-5（build_failure 未实现）、GAP-6（topology-manager 无触发）都是同一个问题：dispatch-dag 描述了一个比实际存在的自动化程度更高的系统。

这不一定是错误设计——D策略是082号谱系的意图——但 dispatch-dag 的措辞创造了超出实际能力的声明。

因此，当前实现（advisory）不是"在张力中选择了一端"，而是**通过实践已经解决了这个张力**（选择了 advisory），但没有更新 CLAUDE.md 的声明来反映这个选择。

建议的解决方式：在 CLAUDE.md 中将"必须阻断等待"改为"advisory 警告 + 记录"，并引用 spec-write-guard.sh 的实际行为作为权威，移除对020号谱系的虚假引用。
