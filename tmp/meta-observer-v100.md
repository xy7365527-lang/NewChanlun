## 观察 1（编排者校准模式）：从"命题指定"到"换线"——编排者首次主动切换整条研究主线

### 现象

v100 的编排者校准与 v95-v99 五轮存在结构性断裂：

| 轮次 | 校准类型 | 内容 | 主线 |
|------|---------|------|------|
| v95 | 轻量提示 | "理论解优先" | K4→纤维丛→共振裁决 |
| v96 | 轮内校准×2 | 理论解优先 + "不测而测" | 同上 |
| v97 | 轮前完全指定 | manual_dispatch | 同上 |
| v98 | 前提否定 + 轮前指定 | 否定 242号裁决前提 | 同上 |
| v99 | 命题指定 | "验证 22.2% 分歧是否与 C-R 不一致完全重合" | 同上 |
| v100 | **换线** | "K4→纤维丛→共振裁决线已饱和，换线到多 TF 集成" | **多 TF 集成** |

v100 的校准类型不是对 v95-v99 五种校准类型的延续，而是一个更高层级的操作——**主线切换**。五轮（v95-v99）始终在同一条研究主线（共振裁决）上通过不同校准类型推进；v100 判断该主线已饱和（"需要真实策略运行积累，不是系统能自动给出的"），整体切换到另一条主线。

换线的依据是认识论阶段判断：
- v90-v99 的产出链：K4 嵌入（232）→ ker(D)（233）→ 三态分类（235）→ 45% 差异（236）→ 100% 锁定在 C-R 分歧（245）→ 平局（244）
- 编排者判断：裁决问题已缩小到"真实策略运行中的积累"——这不是代码系统能自动推进的，是需要外部数据输入的
- 因此换到一条可以系统内推进的线：238号组件接入 pipeline

### 判定

**正面——换线是合理的认识论判断。**

编排者的"饱和"判断有精确的证据链：244号平局排除了"哪个管道更好"的直接裁决路径；245号 100% 重合确认了分歧的结构是完全可预测的（不需要更多分析来理解它）；剩下的唯一推进路径是真实数据——这不在蜂群的即时行动域内。

### 语法记录候选

**编排者校准类型学扩展**：v99 meta-observer 已将五种校准类型标记为"实例充分，可结算"。v100 新增第六种——**主线切换**。这不是第五种"命题指定"的变体，而是一个更高层级的操作：它不调整当前主线内的方向/前提/命题，而是判断整条主线的认识论饱和度并切换到另一条。六种类型形成两层结构：

- 主线内校准（5种）：提示 → 轮内校准 → 轮前指定 → 前提否定 → 命题指定
- 主线间切换（1种）：饱和判断 + 换线

分类：**语法记录候选**（升级——从"可结算"到"需要区分两层结构"后再结算）。

## 观察 2（v100 执行模态）：从"分析"回到"工程"——模态回摆

### 现象

| 维度 | v98 | v99 | v100 |
|------|-----|-----|------|
| 工位数 | 2 | 2 | 1（multi-tf-integration） |
| 产出类型 | 工程修复 + 经验验证 | 纯分析 + 谱系写入 | **工程构建 + 测试** |
| 修复性质 | adapter 附加字段 | 无修复 | **新模块构建** |
| 新代码量 | ~50行修改 | ~347行分析脚本 | **~466行新模块 + ~527行测试** |
| 核心管道变更 | 是（附加字段） | 否 | **否（adapter 模式）** |
| 新测试数 | 7 | 0 | **26** |

v100 是 v95-v100 六轮中代码产出量最大的轮次。但与 v97（重写核心函数）不同，v100 的新代码全部在新模块中（multi_tf_pipeline.py），不修改任何既有模块。这是 adapter 模式的彻底执行。

执行模态序列：v95-v98（工程/经验交替） → v99（纯分析） → v100（工程构建）。v100 的工程模态与 v99 的分析模态形成互补——v99 确认了共振裁决线的认识论边界，v100 在另一条线上执行工程推进。

### 判定

**正面——模态回摆与编排者换线一致。**

换线到多 TF 集成天然是一个工程任务（238号组件已就绪，需要的是桥梁代码）。蜂群没有在工程任务上做分析（没有过度设计），也没有在分析完成后继续分析（v99 已经是共振裁决线的终结，v100 不重复）。

## 观察 5（代码审计）：multi_tf_pipeline.py 的严格性

### 正面

1. **adapter 模式执行彻底**：466行全部在新文件中，import 了但不修改 multi_tf_adapter / bsp / resonance 的任何代码
2. **immutability**：MultiTFPipelineResult 使用 frozen=True + slots=True。MultiTFPipelineAdapter 使用 `__slots__`
3. **方向性力度计算逻辑清晰**：`_directional_move_force` 两个组件（中枢密度倒数 + 方向持续性）均 ∉ ker(D)——不依赖价格振幅
4. **边界处理**：seg_span <= 0 返回 0.0（第66-67行）；snapshot is None 时 persistence 回退到 0.5（第75行）；force_high <= 0 时不产生背驰（第128-129行）
5. **类型转换无歧义**：_KIND_SIDE_TO_TYPE 映射表覆盖了所有 6 种 (kind, side) 组合，未知组合映射到 BSPType.NONE（第192-194行）

### 需注意

1. **density_force 数值范围无上界**：`1.0 / density` 在 density 极小时（如 1 zs / 100 segs = 0.01 → density_force = 100.0）会产生大值。由于力度只在 ratio 比较中使用（`force_low / force_high`），绝对值无上界不影响比较语义——但如果未来力度值需要跨场景对比或可视化，可能需要归一化。分类：边界观察，当前不影响正确性。

2. **T6 可达性判断简洁但粗粒度**：`recursive_levels_equivalent = 有走势输出的 TF 层数`。这是一个合理的简化（有走势 = 有完整构造 = 可比较），但与 237号诊断的 D2 递归压缩瓶颈不是同一层级的判断。237号说的是"单 TF 内递归深度不足"，246号说的是"多 TF 替代递归深度"。这两种"深度"的等价性在246号§4.2 中有讨论（"绕过 D2 递归压缩瓶颈"），但没有给出严格的等价论证。分类：下游可追踪项（当前 T6 可达性判断在合成数据上不可验证，需要真实数据确认）。

## 观察 8（v100 在 v90→v100 十一轮弧线中的位置）

### 现象

编排者在 session 中给出了 v90→v99 的弧线总结：

> 纤维丛结构（232）、ker(D)（233）、三态分类（235）——理论工具
> 45% 差异（236）→ 100% 锁定在 C-R 分歧（245）——经验定位
> 公平回测平局（244）——排除了一种裁决路径
> 剩下的裁决只能来自真实策略运行中的积累

v100 开始了第二条弧线。如果 v90-v99 是"理论→经验→饱和"，v100 是"基础设施"——不是回到理论，不是继续经验，是打通已有组件的系统集成。

弧线对比：
- v90-v99 弧线：概念推进型（每轮产出新定义/新诊断/新验证）
- v100 开始：工程集成型（已有组件就绪，需要管道连接）

这种模态转换是合理的：概念推进到"需要外部数据"的边界时，转向可在系统内推进的工程任务。这不是逃避概念问题——是在概念推进暂停期间推进基础设施。

### 判定

**正面——v100 的位置在弧线中是合理的过渡点。**

1. **编排者实施了第六种校准类型——主线切换**：判断 v90-v99 的共振裁决线已饱和（"需要真实策略运行积累"），整体切换到多 TF 集成线。这与主线内的五种校准类型（提示/轮内/轮前/前提否定/命题指定）是不同层级的操作。

2. **v100 从分析回到工程模态**——466行新模块 + 527行测试 + 26个测试用例。代码产出量是 v95-v99 五轮中最大的，但全部在新文件中（adapter 模式）。

3. **246号六要素完整**，影响声明特别列出了 7 个不修改的结构，使 adapter 模式声明可验证。

4. **v96 的两个遗留集成缺口被处理**：ker(D) 力度替换完全消解，238号与 239号集成缺口部分消解（简化版实现，完整版是可选升级路径）。

5. **无规则违反**。代码审计确认 immutability、行数上限、adapter 模式一致性均符合。
