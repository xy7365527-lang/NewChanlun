## 观察 1（方法论模式信号）：v91-v92-v93 三轮蜂群的功能分化——"概念发现 → 公理推导 → 经验验证"闭环

### 现象

三轮 swarm 在理论链上的功能分化：

| 轮次 | 谱系 | 功能 | 认识论层级 | 工位数 |
|------|------|------|-----------|--------|
| v91 | 232号 | 概念发现（纤维丛重构） | L2（数据驱动结构发现） | 1 |
| v92 | 233号 | 公理推导（ker(D) 定理） | L0（从缠论公理推导） | 1 |
| v93 | 234号 | 经验验证（L2 交叉验证） | L2（六条边全覆盖验证 L0 预测） | 1 |

这三轮形成了科学方法的完整周期：观察/建模（232号）→ 理论化（233号）→ 检验（234号）。编排者在每一轮的角色不同：
- v91：提供空间结构方向（"不是加条件度量，是改变空间结构"）
- v92：提供理论框架（"离散化 = 拓扑滤波器"、"ker(D)"）
- v93：提供验证策略（"让 ker(D) 暴露在它可能失败的地方"、"K4 完全图六条边全覆盖"）

### 判定

**正面——但揭示一个结构性模式**。每一轮 swarm 都是单工位完成的——v91 一个 fiber-bundle 工位，v92 一个 kernel-theory 工位，v93 一个 kernel-verify 工位。这不是"可以并行但选择了串行"（那会违反 lead-parallel-dispatch），而是任务本身在理论推进阶段具有严格的数据依赖链：234号依赖233号的分类器，233号依赖232号的经验数据。

三轮 swarm 的并行度 = 1 不是执行问题，是任务结构的反映。理论推进阶段的本质串行性与工程执行阶段的天然并行性是不同的工作模态。

### 语法记录候选

**理论推进阶段的合法串行性**：lead-parallel-dispatch（218号）的"并行是默认"原则在工程执行阶段成立（独立文件修改、独立测试运行）。但理论推进阶段（概念发现 → 公理推导 → 经验验证）存在不可消除的数据依赖链。分类：**语法记录**（已在运作——v91/v92/v93 事实上串行执行了，但218号规则文本未区分工程执行和理论推进两种工作模态）。

## 观察 2（方法论精确性信号）：234号验证脚本中的度量层级不对称——旧三条边用偏相关 + 232号 beta，新三条边用直接 Pearson + 234号 beta

### 现象

`kernel_l2_verify.py` 中 `classify_all_edges()` 对六条边采用了两种不同的连续层度量：

- **旧三条边**（E-R/C-R/E-C）：连续层用 232号偏相关（控制第三变量后），离散层用 232号已有的 beta（走势方向级别 softmax MLE）
- **新三条边**（E-$/C-$/R-$）：连续层用直接 Pearson（不控制第三变量），离散层用 234号新计算的 beta（笔方向级别线性回归）

两组边的连续层度量（偏相关 vs 直接 Pearson）和离散层度量（走势方向 softmax beta vs 笔方向线性回归 beta）都不同。

### 判定

**方法论不对称是有意识的，但234号谱系的边界条件描述不够充分**。

234号 §2 方法论部分声明了这一不对称："旧三条边沿用232号偏相关值；新三条边直接 Pearson（UUP 不在原直积底空间中，无需偏相关控制）"。理由是合理的——UUP 本身就是共同因子 $，控制 $ 后的偏相关对含 $ 边没有意义。

但边界条件 §3 中遗漏了一个更深层的问题：

1. **离散层度量差异**：旧三条边 beta 来自232号（走势方向级别，softmax MLE），新三条边 beta 来自234号（笔方向级别，线性回归）。这是两个不同的离散化层次——232号 beta 衡量 D3 输出的耦合，234号 beta 衡量 D1 输出的耦合。将两者传入同一个 `classify_coupling()` 分类器，假设了分类器对不同层次 beta 的鲁棒性。

2. **C-R 边的双重度量**：C-R 同时拥有两套 beta——232号 beta_cr = 0.688（D3 层），234号 beta = 0.009（D1 层）。234号选择了使用 232号 beta（因为 `_VERIFIED_232` 覆盖），这意味着 C-R 的分类结果实际上来自 D3 层度量而非 D1 层度量。如果使用 D1 层 beta = 0.009，C-R 将被分类为 independent 而非 direction。

234号发现了这个差异并在 §3.2 正确描述了其含义（"D 的层级放大效应"），但未在边界条件中声明："分类器对旧三条边使用 D3 层 beta，对新三条边使用 D1 层 beta——两组的分类不完全可比"。

### 下游含义

这不动摇234号的核心结论（六条边无反例），因为：
- 新三条边（E-$/C-$/R-$）使用 D1 层 beta 是唯一可用的度量（232号纤维丛不包含 $ 维度）
- 分类结果方向正确：强幅度耦合（|pearson| > 0.15）被 D1 层大量吸收（beta 接近 0），这本身就是 ker(D) 的表现

但如果要将六条边的分类结果作为统一表格呈现（如234号 §1），应标注两组边的 beta 来源层次不同。

## 观察 3（结构发现信号）：R-$ 弱吸收暴露 classify_coupling() 的分类边界模糊区

### 现象

R-$ (TLT-UUP) 的验证结果：
- pearson = -0.065（弱耦合）
- beta = 0.050（接近 kernel_threshold = 0.05）
- 被分类为 amplitude, ∈ ker(D)
- 吸收率 = 23.3%（远低于其他 ker(D) 成员的 92-97%）

234号 §3.1 正确识别了 R-$ 是"边界成员"，并指出 kernel_threshold 从 0.05 调到 0.04 就会翻转分类。

### 判定

**R-$ 暴露了 classify_coupling() 分类器在弱耦合区域的退化**。

问题的根源不是 R-$ 的吸收率低，而是 R-$ 的连续层耦合本身很弱（|pearson| = 0.065）。在弱耦合区域，"幅度耦合"和"独立"的区分变得无意义——一个 |pearson| = 0.065 的耦合在统计意义上可能不显著（需要检验 p-value），但 classify_coupling() 没有引入统计显著性判断。

v92 meta-observer 观察2 已经指出 classify_coupling() 的 0.8 吸收率阈值"应声明为参数而非硬编码"。R-$ 进一步揭示：不仅阈值需要参数化，**弱耦合区域本身可能需要独立的分类逻辑**（或者至少需要标注 "弱耦合，分类置信度低"）。

### 与 231号（有效域规则）的关系

这是有效域模式的第五例：classify_coupling() 的定义域是所有 (partial_corr, beta) 对，但其**分类有效域**在弱耦合区域退化。分类器在 |partial_corr| > 0.15 时分类清晰（E-R/E-$/C-$/C-R 四条边），在 |partial_corr| < 0.1 时分类退化（R-$ 和 E-C 恰好落在此区域——一个被分类为 ker(D)，一个被分类为 independent）。

## 观察 4（执行模式信号）：v93 工位严格执行编排者指令——"让 ker(D) 暴露在它可能失败的地方"

### 判定

**正面——执行严格性高**。蜂群在编排者划定的边界内完成了高质量验证，且在验证过程中识别出新现象（R-$ 边界、D 层级放大效应），未因验证结果是"无反例"就简化处理。

对比 v92 meta-observer 观察1 中的判定（"蜂群在指定方向上执行严格推导，但未自主发起抽象层级跃升"），v93 延续了这一模式。但 v93 的一个进步是：kernel-verify 工位在验证过程中自主识别了两个值得标记的现象（R-$ 弱吸收、C-R β 差异），而非仅输出"通过/不通过"。这是从纯执行向执行+洞察的微进化。

### 与 v92 观察3 的延续

v92 观察3 判定"编排者干预从方向选择进化为框架注入"。v93 增加了一个新层面：编排者提供了**验证策略的认识论指导**——"让理论暴露在它可能失败的地方"。这是波普尔证伪主义的直接应用。编排者在 v90→v93 四轮中的角色演变：

| 轮次 | 编排者角色 | 认识论性质 |

| v90 | 数据源 + 认识论判断 | "合成=同义反复" |
| v91 | 结构否定 + 空间重构方向 | "不是度量是空间" |
| v92 | 理论框架注入 | "ker(D) 可从公理推导" |
| v93 | 验证策略 + 证伪主义指导 | "让它暴露在可能失败的地方" |

## 核心发现

1. **v91→v92→v93 形成完整科学方法周期**。概念发现（L2 纤维丛）→ 公理推导（L0 ker(D)）→ 经验验证（L2 六条边）。三轮串行执行不违反218号——理论推进阶段存在不可消除的数据依赖链。编排者在每一轮覆盖了科学方法的不同环节（数据方法论/建模策略/理论框架/验证策略），蜂群在每个环节内严格执行。

2. **234号验证的度量层级不对称**。旧三条边用 D3 层 beta（232号 softmax MLE），新三条边用 D1 层 beta（234号线性回归）。分类器对两组边使用不同层次的 beta——这不影响核心结论（无反例），但六条边的分类结果不完全可比。234号 §3.2 正确发现了 C-R 的层级差异，但未在边界条件中显式声明两组度量的不可比性。

3. **R-$ 暴露 classify_coupling() 在弱耦合区域的退化**。|pearson| = 0.065 的耦合在分类器中被标记为 ker(D)（吸收率 23%），但这个分类的置信度远低于其他 ker(D) 成员。分类器缺少弱耦合区域的特殊处理或置信度标注。这是有效域模式（231号）的第五例。

4. **蜂群从纯执行向执行+洞察微进化**。v93 kernel-verify 工位在验证过程中自主识别了 R-$ 边界行为和 D 层级放大效应两个新现象，而非仅输出"通过/不通过"。编排者指令"让 ker(D) 暴露在它可能失败的地方"可能促成了这种更敏锐的观察态度。

## 下游推论

1. **理论推进阶段的合法串行性**：218号 lead-parallel-dispatch 的"并行是默认"原则可能需要区分工程执行和理论推进两种工作模态。后者的严格数据依赖链使得并行度 = 1 是合法的。分类：**语法记录**（已在运作但未显式化）。低优先级——当前 manual_dispatch 模式下编排者自然地控制了每轮的节奏。

2. **classify_coupling() 弱耦合区域处理**：需要引入统计显著性判断或置信度标注。|partial_corr| < 0.1 的区域应被标记为"弱耦合，分类不确定"。分类：**行动类**（方向明确），但优先级低于 233号 L0 精确化（v92 下游推论1）。

3. **L2→L3 的下一步**：v93 完成了 L2 全覆盖验证（K4 四标的六条边）。234号 §4.1 声明 L3（不同市场/时段交叉验证）仍待推进。下一步如果继续 ker(D) 验证线，方向是 L3：不同市场（非美股标的）或不同时段（分段窗口验证吸收率的时变性）。分类：**选择类**（需要编排者决定是否继续 ker(D) 验证线，还是转向其他方向如 D 的层级放大效应形式化）。

4. **API key 清理**：kernel_l2_verify.py 及可能的其他脚本中的 AlphaVantage API key 硬编码需要清理为环境变量模式。分类：**行动类**（低优先级卫生性修复）。

5. **v92 下游推论的累积**：v92 留下的三个行动类推论（233号 L0 精确化 / 阈值参数化 / ker(D)-ω 互补形式化）均未在 v93 中推进。这些不是遗漏——v93 的任务是验证而非理论深化。但四轮累积的待推进项清单已较长，编排者可能需要在下一轮决定优先级。
