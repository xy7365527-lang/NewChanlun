## 观察 1（理论链模式信号）：v91→v92→v93→v94 四轮连续理论推进——从"科学方法闭环"到"命题修正循环"

### 现象

v93 meta-observer 观察1 识别了 v91→v92→v93 的"概念发现 → 公理推导 → 经验验证"三环闭合。v94 在闭环之后又开启了新的理论推进：

| 轮次 | 谱系 | 功能 | 认识论层级 | 与前轮关系 |
|------|------|------|-----------|-----------|
| v91 | 232号 | 概念发现（纤维丛重构） | L2 | — |
| v92 | 233号 | 公理推导（ker(D) 定理） | L0 | 基于232号经验 |
| v93 | 234号 | 经验验证（K4 六条边） | L2 | 验证233号 L0 |
| v94 | 235号 | 命题修正（二元→三态） | L0+L2 | 基于234号验证中的异常 |

v94 的模式不同于前三轮的任何一个：它不是纯 L0 推导，也不是纯 L2 验证，而是**基于验证过程中发现的异常（C-R β 度量差异）修正原始命题**。具体地：

1. 233号命题：D 的作用是二元的（吸收/保留）
2. 234号验证发现：C-R 的 D1 β=0.009 vs D3 β=0.688——度量差异76倍
3. 235号修正：D 的作用是三态的（吸收/保留/放大），放大不是绝对放大而是噪声滤除后的相对放大

这构成了一个完整的**命题修正循环**：理论（233号）→ 验证（234号）→ 异常（C-R 层级差异）→ 修正理论（235号）。

### 判定

**正面——揭示了理论链的第二个模式**。

v93 meta-observer 识别的是"科学方法周期"（观察→理论→检验），v94 展示的是**拉卡托什式的研究纲领推进**——核心理论（D 是拓扑滤波器）不变，但辅助假说（D 的作用分类）在经验压力下被修正。233号的二元框架不是被否定，而是被扩展。

值得注意的是：异常信号（C-R β 度量差异）最早出现在234号谱系 §3.2 中，被标记为"D 的层级放大效应"。v93 meta-observer 观察2 进一步诊断了这个度量层级不对称的方法论含义。v94 将这个异常信号从"边界条件描述"提升为"正式的第三态"——异常从观察到理论化的过程完成了。

### 语法记录候选

**验证异常 → 命题修正的闭环模式**：四轮理论链展示了一个完整的理论修正周期。异常信号在验证轮次（v93/234号）中首次出现，在下一轮次（v94/235号）中被理论化。这个模式是否可结晶为蜂群的标准行为？分类：**语法记录**（已在运作——v94 事实上执行了这个模式，但蜂群规则文本中没有"验证异常 → 命题修正"的显式流程）。

## 观察 2（向后兼容设计模式）：beta_d3 可选参数——渐进式概念扩展的代码实现范式

### 现象

235号对 `classify_coupling()` 的修改采用了特定的向后兼容策略：

```python
def classify_coupling(
    partial_corr: float,
    beta: float,
    *,
    beta_d3: float | None = None,  # 新增，可选
    kernel_threshold: float = 0.05,
    independence_threshold: float = 0.05,
    amplification_threshold: float = 5.0,  # 新增
) -> CouplingClassification:
```

关键设计决策：
1. `beta_d3=None` 时完全退化为233号行为（C-R 被分类为 DIRECTION 而非 AMPLIFIED）
2. `CouplingType` 枚举新增 `AMPLIFIED` 成员，但不修改现有三个成员的语义
3. `DiscretizationOperator` 新增 `tristate_classify()` 和 `verify_234()` 方法，原有 `classify()` 和 `verify_232()` 不变
4. 235号谱系 §3.2 显式声明：向后兼容是"设计选择，不是理论局限"

### 判定

**正面——但需要区分两种不同的"向后兼容"**。

(a) **概念层向后兼容**：233号的 ker(D) 定义在235号中完全保留——ker(D) 仍然是纯幅度耦合的集合，三态分类扩展了分类空间但没有修改 ker(D) 的边界。这是理论扩展的自然属性，不需要特殊设计。

(b) **API 层向后兼容**：`beta_d3=None` 的退化行为使得233号的所有调用站点不需要修改。这是一个**工程选择**——用可选参数实现渐进式概念扩展。

工程层向后兼容的风险在于：`classify_coupling(partial_corr=0.166, beta=0.688)` 返回 `DIRECTION`，而 `classify_coupling(partial_corr=0.166, beta=0.009, beta_d3=0.688)` 返回 `AMPLIFIED`。**同一对资产在不同调用形式下返回不同分类**——区别取决于调用者是否知道双层 beta。这不是 bug（行为有明确定义且有文档），但它意味着分类结果不仅依赖数据，还依赖调用者的知识水平。

对比 v93 meta-observer 观察2 中识别的度量层级不对称问题——234号验证脚本中旧三条边用 D3 beta、新三条边用 D1 beta。235号通过 `tristate_classify` 提供了统一接口（同时接受 D1 和 D3），但**只有 C-R 被升级到 tristate**——其余五条边在 `verify_234()` 中仍然使用旧的 `classify()`。这是因为其余五条边确实只有单层数据，但这意味着 R-$ 的三态分类（如果将来获得 D3 数据）可能从 DIRECTION 变为 AMPLIFIED 或 AMPLITUDE，取决于其 D3 beta。

### 是否可结晶

可选参数渐进扩展模式本身是常见的 API 演化实践，不需要结晶为蜂群特有规则。但**概念扩展的向后兼容设计检查清单**可能有价值：

1. 新枚举成员不修改旧成员语义
2. 新参数 `None` 时退化为旧行为
3. 旧调用站点零修改
4. 显式声明退化是设计选择（在谱系 §边界条件 中）

分类：**行动类**（如果要结晶，写入 coding-style 或 domain-conventions）。低优先级。

## 观察 3（命题修正的谱系管理信号）：233号→235号的修正关系——depends_on vs supersedes

### 现象

235号谱系的 `depends_on` 列出了 233号和234号。dag.yaml 中 `235→233` 和 `235→234` 是 `depends_on` 边。

但 235号的实际关系比 `depends_on` 更精确：
- 235号**修正**了233号的命题（二元→三态）
- 235号**依赖**234号的数据（C-R 双层 beta）

在当前谱系管理中，`depends_on` 是唯一的边类型（除了 `triggered`）。233号→235号的关系是"命题被修正"——233号的二元分类不是错误的，而是不完整的。235号保留了 ker(D) 的定义并扩展了分类空间。

### 判定

**信号——但不构成当前阻塞**。

当前谱系 DAG 的边类型只有 `depends_on` 和 `triggered`。`depends_on` 涵盖了"前置知识"关系，但无法区分以下三种子类型：

| 子类型 | 含义 | 例子 |
|--------|------|------|
| 纯依赖 | A 需要 B 的数据/概念 | 234→232（数据来源） |
| 扩展 | A 扩展 B 的框架 | 235→233（二元→三态） |
| 验证 | A 验证 B 的预测 | 234→233（六条边验证 ker(D)） |

这三种关系在 `depends_on` 中被混为一谈。当谱系链较短时这不是问题——人类可以从谱系文本中读出关系类型。但如果 DAG 继续增长（当前已有 235 个节点），**检索谱系关系时缺乏边类型区分**可能降低效率。

分类：**语法记录**（现象已在运作，可能需要显式化）。不阻塞当前工作。

## 观察 4（代码质量信号）：235号代码扩展——204 行新增，向后兼容性高

### 现象

`discretization_kernel.py` 新增约 204 行（从 diff stat），涉及：
1. `CouplingType.AMPLIFIED` 枚举成员
2. `classify_coupling()` 新增 `beta_d3`、`amplification_threshold` 参数 + 放大检测分支
3. `AmplificationAnalysis` dataclass + `analyze_amplification()` 函数
4. `DiscretizationOperator.tristate_classify()` + `verify_234()`

测试新增 241 行，25 个测试覆盖三态分类（8）+ 放大分析（5）+ 234号验证（8）+ 边界条件（4）。

### 判定

**正面样本，有两个值得标记的点**。

1. **放大检测的条件逻辑**（第294-305行）：

```python
if beta_d3 is not None:
    abs_beta_d3 = abs(beta_d3)
    _epsilon = 1e-10
    ratio = abs_beta_d3 / max(abs_beta, _epsilon)
    if ratio > amplification_threshold and abs_beta_d3 >= kernel_threshold:
        return ...AMPLIFIED
```

双重条件（ratio > threshold AND abs_beta_d3 >= kernel_threshold）防止了噪声放大误判。测试 `test_beta_d3_below_kernel_threshold_not_amplified` 验证了这个防护。设计合理。

2. **R-$ 在 verify_234() 中的分类**：

```python
"R-$": self.classify(partial_corr=-0.065, beta=0.050),
```

R-$ 的 |beta|=0.050 恰好等于 kernel_threshold=0.05。`classify_coupling` 使用 `<` 而非 `<=` 进行 kernel 判断（第308行：`if abs_beta < kernel_threshold`），因此 R-$ 被分类为 DIRECTION 而非 AMPLITUDE。

但234号谱系 §1 表格将 R-$ 标记为 `amplitude, ∈ ker(D)`。这与代码行为不一致：

- 代码：|0.050| < 0.05 为 False → DIRECTION（not ker(D)）
- 谱系文档：amplitude, ∈ ker(D)

不一致源于234号使用了稍微不同的 beta 值或阈值判断。234号的 beta=0.050 来自真实数据计算，可能存在浮点精度使得实际值略低于 0.05。

测试 `test_rdollar_boundary_absorbed` 使用 `assert r.coupling_type in (CouplingType.AMPLITUDE, CouplingType.DIRECTION)` 的宽松断言回避了这个边界问题。

这与 v93 meta-observer 观察3 识别的 R-$ 弱耦合区域退化问题一致——R-$ 在分类边界上，任何微小变化都可能翻转其分类。

3. **`AmplificationAnalysis` 的 `amplification_ratio` 返回原始比值**：`analyze_amplification()` 返回的 `amplification_ratio` 是未限制的浮点数（beta_d1=0 时可达 1e10 以上）。测试 `test_zero_beta_d1` 验证了 epsilon 保护（ratio > 1e8），但没有测试 NaN/Inf 情况。当 beta_d1 和 beta_d3 都为 0 时，ratio = 0/epsilon ≈ 0，行为正确。这是防御性编程的正面样本。

## 观察 6（认识论信号）：放大的"相对性"表述——从物理量到信噪比

### 现象

235号对"放大"的定义采用了严格的相对性表述：

> "放大不是绝对放大，而是噪声滤除后的相对放大"（235号 §1）
>
> "C-R 放大比≈76 不意味着方向耦合的绝对强度增加了 76 倍。它意味着方向信号相对于噪声的比例增加了约 76 倍。"（235号 §3.3）

这个表述将"放大"从物理强度增加（绝对放大）重新定义为信噪比改善（相对放大）。机制推导是：D 的每一层从 ker(D) 中去除幅度噪声 → 剩余信号中方向分量的占比提高 → 信噪比增加。

### 判定

**正面——认识论诚实度高**。

235号在发现 C-R 放大比76倍时，没有直接声称"缠论放大方向信号76倍"（绝对放大），而是追问了放大的机制（噪声滤除 → 信噪比提升），并在边界条件 §3.3 中给出翻转条件（如果连续层方向耦合本身就很强，放大比会降低）。

这是 no-patch-mentality 的正面样本：面对一个可以包装为"重大发现"（76倍放大！）的数据，选择了严格表述（相对放大，非绝对放大），并声明了限制条件。

## 核心发现

1. **四轮理论链展示了完整的"理论→验证→异常→修正"循环**。v91→v93 完成科学方法周期（发现→推导→检验），v94 基于验证中的异常（C-R 层级差异）修正了原始命题（二元→三态）。这是拉卡托什式的研究纲领推进——核心理论（D 是拓扑滤波器）不变，辅助假说（D 的作用分类）在经验压力下被修正而非被否定。

2. **向后兼容设计是严格的**。beta_d3 可选参数使得 233号的所有调用站点零修改。但同一对资产在不同调用形式（单层 vs 双层 beta）下返回不同分类——分类结果依赖调用者的知识水平。这是渐进式概念扩展在 API 层的固有属性，不是 bug。

3. **R-$ 的边界行为在代码和谱系文档之间存在微不一致**。234号谱系标记 R-$ 为 `amplitude, ∈ ker(D)`，但 verify_234() 代码中 R-$ 的 |beta|=0.050 恰好等于 kernel_threshold=0.05，在 `<` 判断下被分类为 DIRECTION。测试用宽松断言回避了此问题。这不影响235号的核心结论（三态分类的三个代表边 E-R/E-C/C-R 分类明确），但 R-$ 的分类在谱系文档和代码之间需要对齐。

4. **235号对"放大"的认识论诚实度高**。将放大定义为信噪比提升而非绝对强度增加，并在边界条件中声明了放大比降低的条件。这是 no-patch-mentality 的正面样本——面对可包装的发现选择了严格表述。

5. **谱系 DAG 的边类型分辨力不足**。233→235 是"命题修正"关系，234→235 是"数据依赖"关系，两者在 DAG 中都记录为 `depends_on`。当前谱系规模下这不构成问题，但随 DAG 增长可能降低检索效率。

## 下游推论

1. **"验证异常 → 命题修正"的闭环模式**：四轮理论链中 v94 执行了一个未在蜂群规则中显式化的模式——验证轮次发现异常，下一轮次将异常理论化。分类：**语法记录**。低优先级——模式已稳定运作。

2. **R-$ 谱系-代码对齐**：234号谱系 §1 表格标记 R-$ 为 ker(D) 成员（amplitude），但 verify_234() 代码在默认阈值下将 R-$ 分类为 DIRECTION。需要在谱系文档中更精确地描述 R-$ 的边界行为，或在代码中使用 `<=` 而非 `<`。分类：**行动类**（方向明确）。低优先级——不影响核心结论。

3. **DAG 边类型扩展**：`depends_on` 可能需要子类型（纯依赖 / 扩展 / 验证 / 修正）。分类：**选择类**（需要编排者判断是否值得在当前阶段扩展 DAG 模型）。

4. **v92/v93 待推进项仍未消化**：四轮累积的待推进项（233号 L0 精确化 / 阈值参数化 / ker(D)-ω 互补形式化 / L3 验证 / API key 清理）均未在 v94 中推进。v94 的命题修正不是遗漏——它回应了更紧迫的理论问题（234号异常）。但待推进项清单继续增长的话，编排者可能需要在下一轮进行优先级排序。
