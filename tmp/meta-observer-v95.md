## 观察 1（弧线模式信号）：v91-v95 五轮完整弧线——从概念发现到集成+诊断的理论工程闭环

### 现象

v91-v95 五轮 swarm 构成一条完整的理论-工程弧线：

| 轮次 | 谱系 | 功能 | 认识论层级 | 与前轮关系 |
|------|------|------|-----------|-----------|
| v91 | 232号 | 概念发现（纤维丛重构） | L2 | 起点 |
| v92 | 233号 | 公理推导（ker(D) 定理） | L0 | 基于232号经验上溯 |
| v93 | 234号 | 经验验证（K4 六条边） | L2 | 验证233号 L0 |
| v94 | 235号 | 命题修正（二元->三态） | L0+L2 | 基于234号验证异常 |
| v95 | 236号+237号 | 集成+诊断 | L3(工程)+L2(诊断) | 基于235号工具回溯229号+集成232号 |

v95 与前四轮的本质差异：前四轮每轮产出一个谱系（单线推进），v95 产出两个谱系且方向分叉——236号向前（集成到 pipeline），237号向后（用新工具重新诊断旧问题）。这是理论链从**线性推进**转向**扇出应用**的转折点。

### 判定

**正面——弧线完整性高，转向时机合理。**

五轮弧线的完整结构是：

```
发现(v91) -> 理论化(v92) -> 验证(v93) -> 修正(v94) -> 应用(v95)
                                                         /      \
                                               集成(236号)   诊断(237号)
```

v95 的转向时机判断标准是什么？不是"理论做够了"这种模糊判断，而是两个具体的结构性条件同时满足：

1. **工具成熟**：235号三态分类器已经过234号数据校准（amplification_threshold = 5.0 来自 C-R 76倍放大比），具备对外输出能力
2. **集成通道存在**：232号纤维丛结构与现有 pipeline 的 Configuration 类型兼容（FiberBundlePoint.config 桥接），集成不需要修改已有代码

当且仅当工具成熟 AND 集成通道存在时，从理论推进转向工程集成是结构上合法的。v95 满足这两个条件。

对比一个假想的过早转向：如果 v93 后（未修正命题）就尝试集成，纤维丛修正中不会包含三态分类的放大检测——236号的 adapter 模式会遗漏 C-R 放大态信息。235号的命题修正不是"锦上添花"，而是集成的前提条件之一。

### 语法记录候选

**理论->集成转向的结构性条件**：理论推进阶段向工程集成阶段的转向不应基于"理论已经足够"的模糊判断，而应基于两个可验证条件：(a) 新建工具已通过经验校准，(b) 与已有工程结构的接口兼容性已确认。分类：**语法记录**（v95 事实上执行了这个判断，但蜂群规则文本中没有"理论->集成转向条件"的显式流程）。

## 观察 2（方法论泛化信号）：237号三态诊断方法——将分类工具反向应用于旧问题的诊断范式

### 现象

237号的核心方法论动作是：取 235号的三态分类工具（classify_coupling, analyze_amplification），反向应用于229号的旧问题（T6/T7 低贡献率），为每个判断步骤标注信息类型和三态位置。

具体操作：

| T6/T7 判断步骤 | 信息类型标注 | 三态位置 | 诊断结论 |
|---------------|------------|---------|---------|
| T6 递归深度检查 | direction | conditional（依赖 D2 累积吸收） | 瓶颈 |
| T6 高级别背驰力度 | mixed（振幅力度） | absorbed（振幅 in ker(D)） | 双重削弱 |
| T7 Type1 方向判定 | direction | preserved | 非瓶颈 |
| T7 Type3 回试范围 | amplitude（但拓扑实质） | preserved | 非瓶颈 |

这不是"用新工具重新跑旧数据"——三态分类器无法直接作用于 T6/T7 代码。237号做的是**手工标注每个步骤的信息类型**，然后用三态框架做归因。这是分类工具的**认识论层面应用**（逐步标注 + 归因），不是工程层面应用（代码调用）。

### 判定

**正面——但需要区分两种"泛化"。**

237号的方法论可以分解为两步：

**步骤A**：信息类型标注——为代码中的每个计算步骤标注 "direction / amplitude / mixed"。这是纯分析操作，不依赖235号的任何代码。任何人在任何时候都可以做这个标注。

**步骤B**：三态归因——用235号的 absorbed / preserved / amplified 框架解释步骤A的标注结果。这依赖235号的概念框架（ker(D) = 纯幅度耦合被吸收，方向信息被保留），但不依赖235号的代码。

237号的价值在步骤B——235号的三态框架将229号的经验观察（"递归深度不足"）精化为机制性解释（"D2 弱方向吸收的递归累积"）。229号说的是"what"（递归浅），237号说的是"why in terms of D's structure"（D2 每层吸收弱方向信号，递归叠加后数据指数衰减）。

**泛化潜力评估**：

这种"逐步信息类型标注 + 三态归因"方法是否可泛化为通用诊断工具？

| 适用场景 | 条件 | 可行性 |
|---------|------|--------|
| T1-T5（已有转换函数） | 需要标注每步信息类型 | 可行——与 T6/T7 同结构 |
| T8（scan_configuration） | 策略层操作，纤维丛已集成 | 不需要——236号 adapter 直接提供 |
| 非缠论系统 | 需要类 ker(D) 的滤波器概念 | 不直接可行——三态依赖离散化算子结构 |

结论：三态诊断方法在缠论 pipeline 的 T1-T8 范围内可泛化——任何构造层步骤都可以做信息类型标注 + 三态归因。但它不是通用诊断工具，因为三态分类的前提是存在结构化的离散化算子（D = D3.D2.D1）。

### 是否可结晶

**是，但范围有限**。可结晶为 "pipeline 步骤三态诊断清单"：对 T1-T8 每个转换函数，标注其每个判断步骤的信息类型和三态位置。这不是新代码，而是一份结构化文档。分类：**行动类**（方向明确，无需价值判断）。低优先级——237号已为 T6/T7 完成，T1-T5 可按需扩展。

## 观察 3（集成架构信号）：236号 adapter 模式——"不替换直积"的架构含义

### 现象

236号的核心设计决策是 **adapter 模式**：

```
直积 pipeline（现有） → Configuration → polarity_index
                                          ↓ (不修改)
FiberPipelineAdapter → FiberCorrection → kl_divergence, polarity_flipped, correction_magnitude
```

关键声明：
- 不替换直积——直积作为一级近似保留
- adapter 不修改现有 pipeline 的任何文件
- 45% polarity 差异是策略层信息，不反哺构造层

### 判定

**正面——但揭示一个架构层面的张力。**

adapter 模式的优势是明确的：零破坏、可选增强、降级安全（adapter 不工作时 pipeline 不受影响）。236号谱系 §3.3 也正确地标注了 polarity 翻转的策略意义——直积和纤维丛给出不同策略方向的交易日是分歧点。

但 adapter 模式内含一个架构张力：

**直积是"错的"还是"近似的"？**

- 232号谱系将直积描述为"一级近似"，纤维丛是"精确结构"
- 236号谱系的 adapter 模式将两者并列运行
- 45% 的交易日 polarity 翻转意味着：几乎一半的时间，两个模型给出相反的策略建议

如果直积是"近似"，那么 adapter 的修正应该逐步减小（更好的近似越来越接近精确解）。但236号的实测数据显示修正并不收敛——它取决于底空间位置（E,C 状态），在某些区域修正为零（E=FLAT, C=FLAT），在另一些区域修正很大（E=UP, C=DOWN）。

这意味着直积不是"劣化的纤维丛"（那样修正会是均匀的小量），而是"在底空间部分区域等价、部分区域不等价的替代模型"。adapter 模式事实上是**双模型并行比较**，不是"旧模型 + 修正项"。

这个张力不是 bug——236号的 adapter 设计正确地实现了并行比较。但谱系文本中"直积作为一级近似"的叙事与实际的"双模型并行"架构之间存在表述差异。一级近似暗示修正是小量扰动；45% polarity 翻转说明这不是小量扰动。

### 与 no-patch-mentality 的关系

adapter 模式是否违反 no-patch-mentality？需要区分：

- 如果 adapter 是"在直积上打补丁让它大致对"→ 违反
- 如果 adapter 是"并行运行两个独立模型，量化差异"→ 不违反

236号的实际实现是后者——FiberPipelineAdapter 不修改直积的输出，而是独立计算纤维丛分布并输出差异度量。这是比较，不是修补。判定：**不违反 no-patch-mentality**。但谱系叙事中的"一级近似 + 修正"措辞暗示了修补框架。建议后续叙事明确为"双模型并行比较"。

## 观察 4（诊断闭环信号）：237号对229号的精化——从 "what" 到 "why in terms of D"

### 现象

229号（v88-swarm）→ 230号/v90-swarm 否定边界条件 → 237号（v95-swarm）重新诊断。

三次诊断的演化：

| 版本 | 诊断表述 | 精确度 |
|------|---------|--------|
| 229号原始 | "递归深度不足" | 现象描述 |
| 229号自否定（v90 数据） | "不是数据量问题，是结构性约束" | 否定了错误归因 |
| 237号三态诊断 | "D2 弱方向吸收的递归累积——ker(D) 在递归维度的表现" | 机制性解释 |

同时，237号还完成了一个重要的**否定性判断**：纤维丛修正（236号）不打开 T6/T7 的新通道。代码审查确认 T6/T7 在构造层操作，纤维丛修正在策略层操作，两者无数据通路。

### 判定

**正面——诊断链闭合。**

237号完成了三件事：
1. 给229号的现象描述一个机制性解释（三态归因）
2. 排除了236号作为解决路径的可能性（无数据通路）
3. 确认了229号的路径建议（多 TF 输入是唯一可操作路径）

特别值得标记的是第2点——237号主动检查了236号的 45% polarity 差异是否为 T6/T7 提供新通道，并通过代码审查（import 链检查）给出了否定性结论。这是**假说排除**操作：不是假设"纤维丛能帮助 T6/T7"然后验证，而是检查是否存在帮助的物理通道，发现不存在。

这与 v93 meta-observer 观察4 判定的"从纯执行向执行+洞察微进化"一致——237号工位不仅回答了"三态位置是什么"，还主动回答了"236号是否相关"。

### 229号问题的状态更新

经过 v88→v90→v95 三轮诊断，229号问题的状态现在是：

| 维度 | 状态 | 来源 |
|------|------|------|
| 现象 | T6=0, T7<=1，递归深度=1 | 229号+230号 |
| 排除的归因 | 不是数据量不足 | 230号（v90 否定） |
| 排除的路径 | 纤维丛修正不打开新通道 | 237号 |
| 机制性解释 | D2 弱方向吸收的递归累积 | 237号 |
| 唯一可操作路径 | 多 TF 输入绕过 D2 递归 | 229号提出，237号确认 |
| 编排者判断 | 搁置——递归深度=1 可能是真实答案 | v91 编排者 |

229号问题在理论层面已完全闭合——现象、归因、排除、路径全部明确。剩余的唯一开放项是编排者的价值判断（是否推进多 TF 架构）。

## 观察 5（代码质量信号）：236号 adapter 代码 + 237号诊断脚本

### 236号代码

1. **FiberCorrection dataclass**：frozen=True，包含 kl_divergence/polarity_flipped/correction_magnitude 三个度量。KL 散度使用 P*log(P/Q) 求和（离散分布），加 epsilon 防零除。设计合理。

2. **FiberPipelineAdapter 类**：接收 Connection（232号校准），提供 `correct(config)` 单配置修正和 `batch_correct(configs)` 批量修正。`summary_metrics()` 返回全局统计。adapter 不持有对 pipeline 的引用——纯函数式设计，输入 Configuration 输出 FiberCorrection。

3. **30 个测试覆盖**：中心点退化、分歧点修正、向后兼容、KL 性质。测试验证结构性性质（KL >= 0、中心点 KL = 0、分歧点 polarity_flipped = True）而非具体数值。延续了 v91 以来的结构性测试风格。

### 237号代码

1. **t6t7_tristate_diagnosis.py**：诊断脚本，独立运行。对 T6 五个步骤和 T7 五个步骤逐一标注信息类型和三态位置。

2. **import 链审查**：237号通过检查 `a_nested_divergence.py` 和 `a_buysellpoint_v1.py` 的 import 确认 T6/T7 不导入 Configuration/polarity_index。这是简单有效的依赖分析方法。

### 判定

**正面样本，延续已有设计模式。** 236号 adapter 的纯函数式设计（无 pipeline 引用、frozen 输出）与232号 fiber_bundle.py 的设计风格一致。237号诊断脚本是独立分析工具，不修改核心代码。两者都遵守"新增不修改"原则。

## 观察 7（并行度转折信号）：v95 首次多工位并行——从理论链串行到应用层扇出

### 现象

| 轮次 | 工位数 | 并行度 | 原因 |
|------|--------|--------|------|
| v91 | 1（fiber-bundle） | 1 | 理论推进，严格数据依赖 |
| v92 | 1（kernel-theory） | 1 | 理论推进，依赖 v91 |
| v93 | 1（kernel-verify） | 1 | 验证，依赖 v92 |
| v94 | 1（tristate） | 1 | 命题修正，依赖 v93 |
| v95 | 2+（fiber-integrate + 229-reopen） | >=2 | 应用层，无数据依赖 |

v91-v94 的单工位串行是 v93 meta-observer 观察1 识别的"理论推进阶段合法串行性"。v95 的多工位并行标志着**工作模态从理论推进切换到应用扇出**。

### 判定

**正面——并行度转折与弧线阶段一致。**

理论推进阶段（发现->理论化->验证->修正）具有不可消除的数据依赖链，并行度 = 1 是结构性的。应用阶段（集成+诊断）的多个应用方向之间通常无数据依赖（236号不依赖237号，237号不依赖236号的最终结果——虽然237号 depends_on 236号，但实际上237号引用的是236号的结论"45% polarity 差异影响策略层"而非其代码输出）。

并行度变化可以作为**工作模态切换的信号**：从并行度=1 到并行度>1 提示理论链进入应用阶段。反过来，从并行度>1 回到并行度=1 可能提示新一轮理论推进的开始。

## 核心发现

1. **v91-v95 五轮构成完整的理论-工程弧线**：概念发现(v91) -> 公理推导(v92) -> 经验验证(v93) -> 命题修正(v94) -> 集成+诊断(v95)。v95 是弧线的终点——理论成果（纤维丛+三态分类）被分别应用到工程集成（236号 adapter）和旧问题诊断（237号 T6/T7 三态分析）。这条弧线从 L2 经验出发，上溯到 L0 公理，回落到 L2 验证和修正，最后扇出到 L3 工程和 L2 诊断。认识论层级的完整遍历是弧线完整性的标志。

2. **理论->集成转向的时机判断有结构性条件**：工具成熟（235号三态分类器已校准）AND 集成通道存在（FiberBundlePoint.config 桥接）。这两个条件的同时满足是 v95 从理论推进转向工程集成的结构性根据，不是模糊的"理论已经足够"判断。

3. **237号三态诊断方法在缠论 pipeline T1-T8 范围内可泛化**：逐步信息类型标注 + 三态归因。核心限制：方法依赖离散化算子 D 的分层结构（D1/D2/D3），不是通用诊断工具，是缠论 pipeline 专用诊断工具。

4. **236号 adapter 模式事实上是双模型并行比较，不是一级近似+修正**。45% polarity 翻转率说明纤维丛修正不是直积的小量扰动。谱系叙事中的"一级近似"措辞与实际的"双模型并行"架构之间存在表述张力。这不影响代码正确性（adapter 实现的确是并行比较），但影响对修正幅度的认知预期。

5. **229号 T6/T7 问题在理论层面完全闭合**。经过三轮诊断（229号现象->230号排除数据量归因->237号三态机制解释），问题的现象、归因、路径排除、机制解释全部到位。唯一开放项是编排者的价值判断（是否推进多 TF 架构）。

6. **并行度从 1 恢复到 >=2 是工作模态切换的信号**。v91-v94 的串行是理论链的数据依赖决定的。v95 的并行是应用层无交叉依赖决定的。并行度变化可作为理论->应用模态切换的可观测指标。
