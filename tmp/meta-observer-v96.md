## 观察 1（弧线后第一轮工作模态）：v96 是弧线完成后的应用扇出加速

### 现象

v95 meta-observer 判定 v91-v95 是完整的理论-工程弧线（发现->理论化->验证->修正->应用）。v96 是弧线完成后的第一轮。

v96 的工作模态与 v95 的显著差异：

| 维度 | v95 | v96 |
|------|-----|-----|
| 工位数 | 2（fiber-integrate + 229-reopen） | 3（directional-force + multi-tf + fiber-context） |
| 产出类型 | 1个集成 + 1个诊断 | 1个概念发现 + 1个工程架构 + 1个工程集成 |
| 与理论链关系 | 应用扇出起点 | 应用扇出的第二波 |
| 新代码量 | ~600行 | ~1886行（三个模块） |

v95 的两工位分别向两个方向扇出（集成 vs 诊断）。v96 在 v95 的基础上进一步分化——239号消费 237号的诊断结论（ker(D)），238号消费 237号的路径建议（多 TF），240号消费 236号的 adapter 扩展（FiberTradingContext）。

### 判定

**正面——弧线完成后的加速模式成立。**

v91-v95 弧线中，每轮产出 1-2 个谱系，方向单一（理论推进→应用）。v96 一轮产出 3 个谱系，3 个方向同时推进。这是理论积累（232-237号六个谱系提供了足够的工具和诊断）释放为多路径工程应用的典型表现。

加速的结构性前提：
1. 237号提供了两条可操作路径（方向性力度 + 多 TF），二者无数据依赖
2. 236号的 adapter 模式天然支持扩展（FiberTradingContext 不修改 236号代码）
3. 三条路径两两无数据依赖 → 可并行

v95 meta-observer 提出的"并行度从 1 到 >=2 是模态切换信号"在 v96 得到强化——并行度从 2 进一步升至 3，确认已进入应用加速阶段。

### 语法记录候选

**弧线完成后的工位数增长模式**：理论阶段并行度=1（数据依赖链），应用起步并行度=2（首次扇出），应用加速并行度>=3（理论积累释放）。并行度变化轨迹 1→2→3 是理论-应用转换的可观测指标。分类：**语法记录**（三轮数据点显示规律性模式，但样本量不足以确定为"定理"）。

## 观察 2（编排者中途干预）：运行中的方向校准——从力度验证转向回测

### 现象

v96 工位已在执行时，编排者发来两条消息：

**第一条**（方向优先级）：
- 方向性力度优先于多 TF（"理论解优于工程解"）
- "既然你知道 D 吸收什么、保留什么、放大什么，那就用被保留/放大的量来定义力度"

**第二条**（验证路径修正）：
- 236号 45% 差异的裁决标准 = 回测（"不测而测"）
- 前提：修共振筛选管道
- v97 方向预告：两种组装方式策略对比回测

编排者的干预发生在 v96 进行中，而非 v96 开始前。

### 判定

**结构性含义：编排者从"信任工位自组织"转向"运行中校准方向"。**

v91-v95 的五轮弧线中，编排者在每轮之间给出方向，但不在轮内干预。v96 编排者在轮内发出两条校准消息，这是工作模态的一个变化。

干预的结构性原因可以从编排者的两条消息中推导：

1. **理论解 vs 工程解的优先级判断**：238号多 TF 是工程解（绕过 D2），239号方向性力度是理论解（解决力度 ∈ ker(D)）。两者都回应 237号的诊断，但本质不同。编排者做了价值判断——理论解优先。这是**选择类**判断，蜂群无法自主做出（四分法分类正确：需要编排者价值判断的方向选择）。

2. **从"差异量化"到"回测裁决"的路径转向**：236号量化了直积 vs 纤维丛的差异（45%），但差异不等于"谁对"。编排者校准了验证方法——差异的裁决用回测（操作结果区分好坏），不用理论推导。这引入了缠论的"不测而测"方法论——缠论通过完全分类产生确定操作，操作的盈亏区分分类质量。

**对 v97 的影响**：编排者的两条消息为 v97 设定了明确方向：(a) 修共振筛选管道（_build_resonance_signals），(b) 两种组装方式对比回测。这不是弧线中的"下一步自然推进"，而是编排者指定的具体工程路径。

### 与 v95 观察的关联

v95 meta-observer 观察1 提出"弧线完成后的下一步方向"是选择类（需要编排者判断）。v96 编排者的干预正好回应了这个判断——弧线完成后，蜂群的应用方向需要编排者校准。

## 观察 3（239号 ker(D) 推论链闭合）：233→235→237→239 的四步推论链——形式化闭合

### 现象

depends_on 链：
- 233号（ker(D) 结构定理）→ 235号（三态分类：absorbed/preserved/amplified）
- 235号 → 237号（三态诊断：_amplitude_force ∈ ker(D)）
- 235号 + 237号 → 239号（方向性力度：三种 ∉ ker(D) 的替代指标）

四步推进的逻辑结构：

| 步骤 | 谱系 | 功能 | 类型 |
|------|------|------|------|
| 1 | 233号 | 什么是 ker(D)（定义核） | 存在性发现 |
| 2 | 235号 | ker(D) 之外有什么（三态分类） | 完备分类 |
| 3 | 237号 | 现有代码落在 ker(D) 中（诊断） | 归因定位 |
| 4 | 239号 | 用 ∉ ker(D) 的量替代（构造解） | 解的构造 |

### 判定

**正面——推论链在 239号处形式化闭合。**

闭合的含义：233号发现问题（ker(D) 存在），235号建立工具（三态分类），237号定位问题（_amplitude_force ∈ ker(D)），239号构造解（三种 ∉ ker(D) 指标）。从"发现核"到"构造核的补空间中的替代量"，这是完整的分析-构造闭环。

形式化验证：239号的三种方法确实 ∉ ker(D)——

| 方法 | 信息来源 | D 的作用 | 三态位置 |
|------|---------|---------|---------|
| A（directional_persistence） | 线段方向 | D1 编码方向不丢弃 | preserved |
| B（stroke_density_force） | D1 输出统计 | 密度是 D1 输出性质 | preserved |
| C（zhongshu_drift_force） | 中枢位置关系 | D3 保留相对位置 | preserved |

三种方法均在 preserved 态（不在 absorbed 态），这与 233→235 的理论框架一致。

**残留开放项**：239号构造了解但未验证其效果。编排者的第二条消息已指出验证方法（回测），但 v96 未执行回测。推论链在形式层面闭合（从定义到构造），在经验层面未闭合（构造的解是否比旧解更好未知）。

### 与 v95 观察的关联

v95 meta-observer 观察4 指出"229号 T6/T7 问题在理论层面完全闭合"。239号不是对 229号的进一步闭合——229号问题的解是"多 TF 架构"（238号），239号解决的是一个不同但相关的问题："力度度量 ∈ ker(D)"（237号诊断的核心发现）。两条推论链在 237号处分叉：

```
233 → 235 → 237 → 238（多 TF 绕过 D2 递归）    -- 229号问题的解
                   ↘
                    239（方向性力度 ∉ ker(D)）   -- 237号力度盲点的解
```

## 观察 4（代码质量）：三个新模块的设计模式审查

### 239号 directional_force.py（999行）

**正面**：
1. Protocol 接口（SegmentLike, StrokeLike, ZhongshuLike, MoveLike, LevelZhongshuLike）——避免直接导入具体类型，松耦合
2. frozen=True dataclass（DirectionalDivergence, ForceComparison, LevelForceComparison）——不可变输出
3. 纯函数设计——所有函数无副作用，输入→输出
4. 双层 API（L1 函数和高级别 level_ 函数分离）——高级别适配 Move-as-component 场景
5. `_amplitude_force` 复制为对比基线，标注 "仅用于对比" 和 "∈ ker(D)"

**关注点**：
1. 999行——接近 coding-style.md 的 800行上限。文件包含 5 个 Protocol + 3 个 dataclass + 15 个函数 + 高级别镜像，内聚性高但体量偏大。高级别镜像（level_directional_persistence, level_component_density_force 等）是低级别函数的结构性重复，但接口不同（SegmentLike vs MoveLike），提取为独立文件可能更好
2. composite_directional_force 权重（0.4/0.3/0.3 和 0.5/0.5）是硬编码常量，谱系 §4.3 承认可调——但当前未参数化

### 238号 multi_tf_adapter.py（470行）

**正面**：
1. adapter 模式——不修改现有 RecursiveOrchestrator, BiEngine, pipeline
2. frozen dataclass 全覆盖（TimeframeLevel, LevelResult, CrossLevelDivergence, BuySellPoint）；MultiTFResult 为 slots=True 但非 frozen（因为 list 字段）
3. 跨级别背驰检测逻辑清晰——三条件（双方有走势、方向一致、力度衰减）
4. align_bars_by_timestamp 独立为纯函数

**关注点**：
1. CrossLevelDivergence 的力度使用 `_move_amplitude`（= |high - low|），这正是 237号诊断的 ∈ ker(D) 指标。238号谱系 §3.2 标注了此限制（"力度度量的局限"），239号的 level_directional_force 可以替换此处。但 238号和 239号无数据依赖（并行产出），因此当前代码使用旧力度是时间上合理的——替换是 v97+ 的集成工作
2. BuySellPoint.kind 固定为 "type1"——跨级别背驰产生的买卖点确实是一类买卖点，这个硬编码是正确的

### 240号 fiber_pipeline_adapter.py 扩展（417行总计，新增约 160行）

**正面**：
1. FiberTradingContext 用组合而非继承（`ctx: object`）——避免侵入 pipeline.py
2. create_fiber_context 是工厂函数，纯函数式
3. FiberSignalFilter 的 should_override_polarity 条件清晰（polarity_divergence AND kl > threshold）

**关注点**：
1. `ctx: object` 类型注解——避免循环导入，但 type: ignore 注解较多（product_polarity, config, timestamp 三个属性）。这是 Python 类型系统的限制，不是设计缺陷，但降低了静态检查价值
2. FiberSignalFilter.__init__ 的 adapter 参数默认创建新 FiberPipelineAdapter()——每次实例化都构造新 adapter 可能导致不必要的重复，但由于 adapter 是无状态的纯函数式设计，实际无影响

## 观察 7（238号的内在张力）：多 TF 架构使用 ∈ ker(D) 的力度——结构性不一致

### 现象

238号 multi_tf_adapter.py 的跨级别背驰检测使用 `_move_amplitude`（|high - low|）。237号已诊断此指标 ∈ ker(D)。239号已构造了 ∉ ker(D) 的替代指标。

238号谱系 §3.2 标注了这个限制："当前跨级别背驰力度使用价格振幅（|high - low|），这是 237号诊断中标注的 ker(D) 成分。替代力度指标（如方向性指标）可能提升信号质量。"

### 判定

**这不是 bug，是时间窗口导致的已知限制。**

238号和 239号在 v96 中并行产出，238号无法使用 239号的力度指标。谱系 §3.2 正确标注了限制，§4.2 标注了"力度指标可独立升级"。

但从 v97+ 的视角看，238号的 `_move_amplitude` 应替换为 239号的 `level_directional_force` 或至少应添加双力度对比（如 239号的 compare_level_force）。这是一个 v97 集成项，不是 v96 的缺陷。

### 集成路径

```
238号 CrossLevelDivergence.force_high/force_low
    当前：_move_amplitude(move) = |high - low|
    替换：level_directional_force(components, start, end, direction)
```

替换需要：将 Move 的 seg_start/seg_end 传递给 level_directional_force。Move 已有 seg_start/seg_end 属性，接口兼容。分类：**行动类**（方向明确，无需编排者判断）。

## 核心发现

1. **v96 确认应用加速模态**：弧线后第一轮，并行度从 2 升至 3，产出从 2 个谱系升至 3 个。理论积累（232-237号六个谱系）在 v96 释放为多路径工程应用。并行度轨迹 1→2→3 是理论->应用转换的可观测指标，v96 的数据点强化了 v95 的初步观察。

2. **编排者在 v96 运行中做出两个结构性决策**：(a) 理论解优先于工程解，(b) 差异裁决用回测。这是弧线完成后编排者为蜂群校准方向的行为——弧线完成后应用方向的选择是编排者职责（v95 meta-observer 下游推论1 的验证）。

3. **233→235→237→239 推论链在形式层面闭合**：从 ker(D) 存在性发现到 ∉ ker(D) 的替代量构造，四步推论链完整。经验层面（回测验证）未闭合——这是编排者指定的 v97 方向。

4. **三个新模块设计一致性高**：均采用 adapter/附加模式、frozen dataclass、纯函数式设计。directional_force.py 的 999 行接近上限，可考虑拆分高级别镜像。

5. **238号与 239号的集成缺口**：238号使用 ∈ ker(D) 的力度（_move_amplitude），239号已构造 ∉ ker(D) 的替代。二者并行产出导致当前未集成，v97+ 应执行替换。

6. **测试数量声明不精确**：三个模块的 session/谱系声明与 git diff 实际测试函数数均有轻微偏差（+1~+12）。不影响功能但属 spec-execution-gap 的弱信号。

## 下游推论
