## 观察 1（工作模态）：v97 是编排者定向的验证轮——从"构造解"到"经验裁决"

### 现象

v96 编排者在轮内发出两条校准消息：(a) 理论解优先于工程解，(b) 差异裁决用回测（"不测而测"）。v97 精确执行了编排者的第二条指令：修共振筛选管道 + 两套组装方式对比回测。

v97 与 v96 的模态对比：

| 维度 | v96 | v97 |
|------|-----|-----|
| 工位数 | 3（directional-force + multi-tf + fiber-context） | 2（resonance-fix + backtest-compare） |
| 产出类型 | 1概念发现 + 1工程架构 + 1工程集成 | 1工程修复 + 1经验验证 |
| 编排者指导程度 | 弧线后首轮，轮内校准 | manual_dispatch——方向、步骤、约束均由编排者明确指定 |
| 新代码量 | ~1886行 | ~1127行（pipeline_backtest +165, dual_resonance_backtest 567, tests 560） |
| 新测试数 | 77-89（声明口径不一致） | 44（25+19） |
| 谱系层级 | L3（概念发现）+ L3（工程架构）+ L3（集成） | L3（工程修复）+ L3（经验验证） |

v97 的并行度从 v96 的 3 回落到 2。这不是退化——两工位之间存在数据依赖（backtest-compare 消费 resonance-fix 的 DualResonanceSignals 输出），编排者的两步计划本身就是串行结构（先修管道，再跑回测）。

### 判定

**正面——v97 完成了从"构造解"到"经验裁决"的转换。**

v91-v96 弧线及其应用扇出全部在理论/工程层推进（定义→形式化→工程落地），v97 是弧线完成后第一次引入经验裁决。242号用 27 配置 x 20 BSP 的全覆盖对比回测，产出的不是"更好的代码"而是"哪个模型更干净"的判定。

模态转换轨迹：理论发现(v91-v93) → 应用扇出(v95-v96) → 经验裁决(v97)。

### 语法记录候选

**"不测而测"路径在蜂群中的实例化**：编排者引入缠论"不测而测"方法论——通过完全分类产生确定操作，操作的结果区分分类质量。v97 是蜂群首次将此方法论落地为代码（dual_resonance_backtest.py 的四维度干净度评分）。分类：**语法记录候选**——需要更多数据点确认是否成为常规验证方法。

## 观察 2（241号核心修复质量）：双层简化 → 真实共振构建的设计严格性

### 现象

241号的核心修复将 `_build_resonance_signals` 从"复制同一 BSP 产生两层信号"改为"CONFIG 层由 polarity 决定、EDGE 层由 BSP 自身决定"。修复前共振检查形式上通过但实质不筛选。

代码审查要点：

1. **`_polarity_to_bsp`**（pipeline_backtest.py:144-165）：纯函数，polarity→BSPType 映射清晰。polarity=0 时退化为 BSP 自身方向——这是正确的边界处理（CENTER 配置下配置层无独立方向信息）。

2. **`_build_signals_for_polarity`**（pipeline_backtest.py:168-197）：CONFIG 和 EDGE 两层信号从不同来源构建。共振条件变为真实的"两个独立来源方向是否一致"检查，不再是恒真。

3. **`_build_resonance_signals`**（pipeline_backtest.py:200-246）：直积版和纤维丛版并行构建，通过 DualResonanceSignals 同时输出。纤维丛版在 `should_override_polarity` 返回 False 时退化为直积版——保证了两版信号的可比性。

4. **DualResonanceSignals**（pipeline_backtest.py:118-141）：frozen dataclass，tuple 字段确保不可变。同时携带原始 polarity 值和 divergence 标记——为下游对比提供完整上下文。

5. **`_pipeline_enter`**（pipeline_backtest.py:353-405）：入场决策使用 `dual.product_signals`（直积版），纤维丛版通过 `last_dual_signals` 暴露给调用方。这是保守且正确的选择——在经验裁决完成前不改变默认行为。

### 判定

**正面——修复严格，未引入补丁思维。**

修复的核心不是"在旧代码上加修补"，而是从概念层面重新定义了 `_build_resonance_signals` 的语义：从"伪造两层信号使共振恒通过"到"从两个独立来源构建信号使共振成为真实筛选"。这符合 no-patch-mentality 的要求——"如果逻辑是错的，删除并用正确逻辑替换"。

向后兼容性保持：所有 19 个现有 pipeline_backtest 测试通过。行为变化在边界条件处（polarity 与 BSP 方向一致时行为不变，不一致时新增了共振筛选阻断），变化方向是更严格而非更宽松。

## 观察 3（242号回测设计的结构性问题）：scan_configuration 是纤维丛版矛盾操作率的唯一来源

### 现象

242号报告纤维丛版矛盾操作率 17.65%（60/340），直积版为 0。根因分析指向 `scan_configuration` 仍使用直积 polarity。

代码级追踪确认了这个因果链：

1. `pipeline_backtest.py:344` — `self._ctx, directions = scan_configuration(self._ctx)`
2. `pipeline.py:139` — `s = polarity_index(ctx.config)`（直积 polarity）
3. `pipeline_backtest.py:346-351` — `if "buy" in directions` 决定是否尝试入场

即：入场的**前置门控**（scan_configuration）使用直积 polarity，而纤维丛版的**共振信号**使用 fiber_polarity。当两者方向不同时：
- scan 说 "sell"（基于直积）→ 不尝试 buy 入场 → 但 fiber 共振信号说 buy 应通过
- 或 scan 说 "buy"（基于直积）→ 尝试 buy 入场 → fiber 共振信号因 fiber_polarity = sell 而阻断

这不是纤维丛模型的缺陷，是集成的**层间不一致**——同一条管道中两个决策层使用了不同的 polarity 来源。

### 判定

**242号的诊断准确。但需注意：当前回测对比的纤维丛版实际上是一个"半集成"版本，不是纤维丛模型的公平测试。**

回测脚本 `dual_resonance_backtest.py:145` 也调用了 `scan_configuration(ctx)` 获取 scan_direction，并用它来计算矛盾操作率。这意味着对比的公平性前提是：两版共享相同的前置门控。但纤维丛版的共振信号使用了不同的 polarity 来源，导致门控和共振信号之间出现不一致。

242号谱系 §3.3 和 §4.2 正确标注了这个限制，并指出了修复方向（scan_configuration 也使用 fiber_polarity）。裁决"直积版更干净"在**当前集成状态下**成立，但不能推广为"直积模型优于纤维丛模型"。

### 下游推论

如果 v98 走方向1（修 scan_configuration 使纤维丛版完整集成），需要的改动是：在 `_try_entry` 中对纤维丛版使用 fiber_polarity 决定 directions，而非统一使用 `scan_configuration` 的直积 polarity。这是一个**行动类**改动——方向明确，无需编排者判断。

## 观察 7（DAG 边依赖检查）：241/242 的 depends_on 缺少对 237号的间接引用

### 现象

dag.yaml 中 241号的 depends_on 是 [236, 240]，242号的 depends_on 是 [236, 240, 241]。

241号谱系 frontmatter 写的也是 depends_on: [236, 240]。但 241号的修复动机来自 v96 编排者的校准（"修共振筛选管道"），而共振筛选管道修复的概念背景包括 237号（三态诊断——发现 _amplitude_force ∈ ker(D)）。

严格来说，241号的修复对象是 `_build_resonance_signals` 的双层简化——这个问题在 meta-observer-v88 中首次被观测到，与 237号的 ker(D) 诊断是两个独立问题。241号不依赖 237号的结论来完成修复。所以 depends_on: [236, 240] 是正确的。

### 判定

**depends_on 正确。** 241号修复的是共振信号构建的伪造问题（双层简化），不是力度度量的 ker(D) 问题。两者是同一管道中的不同层级问题。

## 核心发现

1. **v97 完成了从"构造解"到"经验裁决"的模态转换**：v91-v96 的弧线和扇出全部在理论/工程层推进，v97 首次引入经验裁决——用全覆盖对比回测产出"哪个模型更干净"的判定。模态轨迹：理论发现(v91-v93) → 应用扇出(v95-v96) → 经验裁决(v97)。这是缠论"不测而测"方法论在蜂群中的首次实例化。

2. **241号修复设计严格**：从概念层面重新定义了共振信号构建的语义（伪造→真实），而非在旧逻辑上加补丁。向后兼容性通过边界条件自然保持（polarity 与 BSP 同向时行为不变）。代码质量延续了 v96 的纯函数 + frozen dataclass + 不可变模式。

3. **242号诊断准确但裁决有作用域限制**：纤维丛版矛盾操作率 17.65% 的唯一来源是 scan_configuration（pipeline.py:139）使用直积 polarity 而纤维丛共振信号使用 fiber_polarity 的层间不一致。裁决"直积版更干净"在当前半集成状态下成立，但不等价于"直积模型优于纤维丛模型"。242号谱系正确标注了此限制。

4. **编排者主导性在 v97 进一步增强**：从 v96 的"轮内校准"到 v97 的"轮前完全指定"（manual_dispatch，方向 + 步骤 + 约束 + 明确禁令"不要在这一轮同时解决 T6"）。这与 v95 meta-observer 的判定一致——弧线完成后应用方向是编排者职责。
