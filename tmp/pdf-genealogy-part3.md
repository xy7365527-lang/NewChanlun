## 二、回测框架设计与实现

### 自上而下 vs 自下而上的选择
编排者被问及先验证单标的状态机（自下而上A）还是搭完整流程（自上而下B）时，选择了**B（自上而下）**。

### 完整框架架构
```
层0（结算尺有效性）→ 层1（K4比价配置）→ 层1.5（板块比价收敛）→ 层2（个股操作）
```

### K4配置模块的两次重大修正

**修正一：从顶点改为边**
- 原始实现：分别在 SPY、GLD、TLT 上跑 D 算子读各自方向
- 问题：读的是"股票在涨还是跌"，不是"资本从股票流向黄金还是反向"
- 修正：D 算子跑在六条比价边上（SPY/GLD、SPY/TLT、GLD/TLT 等）
- 编排者洞察："整个体系从上到下没有一个绝对量。全是比价。"

**修正二：三值逻辑**
- 原始实现：polarity=0 时完全不操作（20年93.6%时间空仓）
- 问题：中性 ≠ 反对
- 修正：支持（polarity>0）→扫描对应矩阵；中性（=0）→扫描所有矩阵；反对（<0）→排除

**修正三：层0缺失**
- 编排者指出回测框架跳过了层0（结算尺有效性检查）
- 层0是层1的前提，应串行依赖
- OQ5的全部工作本质上就是层0模块

### L2验证结果
- 5352 bars（2004-2026），仅2次操作（1买入+1止损），93.6%空仓
- 根因：K4 polarity 计算逻辑错误 + sigma映射与D算子方向是两套独立逻辑

### 框架模块清单（v124-swarm产出）
- `backtest/types.py`：类型定义
- `backtest/k4_config.py`：K4配置
- `backtest/scanner.py`：选股扫描

## 五、蜂群架构演进

编排者对三个议题的裁定：
1. **致命1（拓扑退化为语义检测）**：部分接受。拓扑+canonical form双层互补方案
2. **致命2（DAG不可消除）**：驳回，稻草人。并行原则="该串行的串行，该并行的直接并行"
3. **重要3（否定之否定映射错误）**：接受。不是边方向反转，是新节点的否定边使旧否定边失效
4. **重要4（通信/计算比）**：驳回。"效率和质量远比开销重要"

编排者新增架构原则：**"附庸的附庸不是我的附庸"**——局部依赖原则

### 273号：否定拓扑代数
- 否定边：有向边 (source, ¬, target)，对象否定对象（005b号）
- 边有效性标记：validity = active | invalidated，单向转移
- 否定之否定 = 新节点C否定A → A对B的否定边被invalidated → B被动复活
- 拓扑分类：树状展开（生产性）、成环（空转）、多重边汇聚（深层矛盾）、边被失效（扬弃）

### 274号：废除depth_budget
- 编排者裁定：depth_budget是全局截断，与局部依赖原则矛盾
- 递归终止条件改为结构性：
  1. 原子性：任务不可分解为≥2个独立子任务
  2. 不动点：rescan未产生新工位
- context window耗尽 → 触发compaction → 下一轮恢复，不是终止
- "和缠论完全同构：笔是原子性终止，不动点是区间套收敛终止"

### 275号：局部依赖原则
- 核心命题："附庸的附庸不是我的附庸"
- 每个节点只管直接依赖，全局DAG是局部依赖涌现的结果
- 与操盘方法同构：主级别持仓不管次次级别短差
