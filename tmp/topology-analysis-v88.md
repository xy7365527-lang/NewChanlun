### 2.2 Schema 分裂（两种区块格式）

259 个区块存在两种不兼容的 schema：

**Schema A**（243 个，迁移/早期创建）：
```json
{"id", "type", "timestamp", "source", "content": {嵌套}, "refs", "git_ref"}
```
谱系 ID 在 `content.id` 中。

**Schema B**（14 个，204-220 号区块）：
```json
{"id", "number", "source_file", "type", "created", "source"}
```
谱系 ID 在顶层 `number` 字段。无 `content` 嵌套、无 `refs`、无 `git_ref`。

**诊断**：Schema B 是后期创建的简化格式，缺少 `refs` 和 `git_ref` 字段。这导致：
- 关系查询逻辑需要同时处理两种格式
- Schema B 区块无法被 refs 引用追踪
- 类型字段值不一致（`概念発見` vs `概念发现` vs `concept-discovery`）

## 5. 建议

### P0：拓扑完整性修复

1. **短 hash 修复**：9 个截断 hash 区块（204-212）需要重新生成完整 SHA-256 hash，并更新 id_mapping 和 relations.jsonl 中的引用。当前拓扑对这些区块不可寻址。

2. **关系写入修复**：191/192/198/201/224/225 号区块的 content.depends_on 中声明了依赖但未写入 relations.jsonl。需要补写。

3. **畸形关系清理**：17 行非标准格式需要修复为 `{from, to, relation, order}` 标准格式，或标记为无效。

### P1：Schema 统一

4. **统一区块格式**：14 个 Schema B 区块应迁移为 Schema A 格式（含 content 嵌套、refs、git_ref）。两种并存增加下游解析复杂度。

5. **类型命名标准化**：`概念発見` → `概念发现`，`concept-discovery` → `概念发现`。统一为中文。

### P2：清理

6. **196 号重复**：删除旧版区块 `6c795ae0...` 或标记为 superseded。

7. **id_mapping 语义澄清**：meta.json 的 block_count=259 包含操作性区块（tension/residue/consensus/rewrite/genesis），但 id_mapping 只索引谱系区块。建议增加字段区分两类计数。

### P3：监控

8. **069 号集中度**：069 号作为拓扑中心的单点依赖需要关注。如果 069 号的定义发生变更，影响范围覆盖 35 个下游区块。

9. **142-152 空洞**：确认这些缺失 ID 是设计预期（跳号）还是数据丢失。
