### 2.2 236号：菱形汇聚（Diamond Pattern）

236 同时依赖 232（纤维丛结构定义）和 235（三态分类工具），形成菱形：

```
       230
        |
       232 ──────────┐
        |             |
       233            |
        |             |
       234            |
        |             |
       235 ──────→ 236
```

两条路径从 230 出发：
- 路径1（短）：230 → 232 → 236（纤维丛结构直接输入）
- 路径2（长）：230 → 232 → 233 → 234 → 235 → 236（三态分类工具输入）

最低公共祖先 = 230（K4 独立边独立性检验）。语义：236 将 230 数据驱动的两条理论产物（纤维丛结构 + 三态分类）合并为工程可用的 adapter。

### 2.3 237号：三流扇入（Fan-in Pattern）

237 汇聚三条独立语义流：

| 流 | 路径 | 语义 |
|----|------|------|
| A | 229 → 237（跳级） | 实证数据：T6/T7 低贡献率 |
| B | 235 → 237 | 理论工具：三态分类框架 |
| C | 236 → 237 | 工程产出：纤维丛 adapter 的 45% polarity 差异 |

关键结构特征：**237 → 229 是跳级依赖**。237 绕过了 230→232→233→234→235 整条链，直接回溯到 229。语义：237 不是从 235 往下推导，而是用 235 的工具回头重新审视 229 的问题——这是诊断回溯，不是线性推进。

## 7. 拓扑影响总结

1. **236号延伸了纤维丛理论链的工程出口**：232（理论）→ 236（工程 adapter），使纤维丛修正从理论构造落地为 pipeline 可用的策略层增强。

2. **237号形成诊断回溯环路**：229（实证问题）→ 230-235（理论工具建设）→ 237（用新工具重新诊断旧问题）。这不是简单的线性推进，而是"问题驱动理论，理论反哺诊断"的闭环。

3. **235从前沿退出是结构性信号**：235 作为三态分类工具，从"尚无消费者"变为"被两个下游节点同时消费"，表明三态框架已开始产生应用价值。

4. **237的跳级依赖（→229）是语义必需的**：237 需要直接引用 229 的实证数据，而不仅仅依赖 235/236 的抽象结论。跳级依赖保证了诊断的可追溯性。

5. **meta.json id_mapping 需要补全**：33 个区块（含 236/237）已在磁盘和 relations 中，但未注册到 id_mapping。
