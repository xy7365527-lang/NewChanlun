# 338号操作方法论 v2 信号来源映射

## 概述

本文档将 338号操作方法论 v2（基于 267号 v1 框架 + 268a 四项修正）的每条操作规则
映射到当前代码管线能力，标注信号可用性。

代码管线概况：
- **五层引擎链**：BiEngine → SegmentEngine → ZhongshuEngine → MoveEngine → BuySellPointEngine
- **递归栈**：RecursiveStack（自动递归至 level=6）
- **多TF调度**：TFOrchestrator（base TF + 高 TF 并行步进）
- **背驰检测**：趋势背驰 + 盘整背驰（MACD 三维度 OR 判定）
- **区间套**：nested_pipeline（跨级别背驰搜索）
- **小转大**：a_xiaozhuan_da（次级别背驰引发大级别转折检测）
- **买卖点**：Type1（趋势背驰）+ Type2（回调/反弹）+ Type3（中枢突破回试）+ 2B/3B 重合
- **比价分析**：ratio_engine（比价 K 线 → 标准管线）+ matrix_topology（四矩阵拓扑）+ flow_timeline（流转状态时序）
- **K4 监控**：k4_monitor.py（eff.dim + basis + 体制识别）

## 一、选股+定级别（§一）

### 1.1 缠论筛——标的在哪个级别上有完备的买卖点结构

| 信号需求 | 管线状态 | 说明 |
|----------|---------|------|
| 某标的某级别是否存在完备买卖点结构 | ⚠️ 管线有能力但未接通 | BuySellPointEngine 可计算 Type1/2/3 买卖点；RecursiveStack 可递归到多级别。但**无扫描入口**——当前管线处理单一标的，缺少"遍历标的池、逐标的跑管线、筛选有买卖点的标的"的编排层 |

| 级别确定（操作级别 = 买卖点所在级别） | ✅ 已能提供 | BuySellPoint.level_id + RecursiveLevelSnapshot.level_id；代码路径：`core/recursion/recursive_level_engine.py` |

### 1.2 比价筛——K4 配置是否支持该标的所在矩阵

| 信号需求 | 管线状态 | 说明 |
|----------|---------|------|
| K4 配置状态（27 种之一） | ⚠️ 管线有能力但未接通 | matrix_topology.py 定义了四矩阵拓扑结构（6 条边），flow_timeline.py 可构建流转时序并聚合顶点状态。但**K4 配置 = 27 种之一的编码器未实现**——当前 FlowSnapshot 给出 4 个 VertexFlowState，但未将其编码为 27 种 K4 配置之一 |

## 结果包六要素

### 1. 结论

338号 v2 操作方法论需要的信号来源分为三大类：

**当前管线已完备覆盖的**（✅ = 12 项）：
- 单标的五层管线完整链路（笔→段→中枢→走势→买卖点），含 Type1/2/3 + 背驰检测 + 区间套
- 多 TF 并行调度（TFOrchestrator）
- 递归级别构造（RecursiveStack，level=1→6）
- 小转大检测（XiaozhuanDa）
- K4 四节点 eff.dim + basis + 体制识别
- 比价六边走势结构 + 四矩阵拓扑 + 流转时序

**管线有基础能力但未接通的**（⚠️ = 5 项）：
- 小转大 → 级别升级编排、k4_monitor → 选股集成、大转小区分信号化、修正4 策略编排、K4 配置编码

**管线完全不具备的**（❌ = 8 项）：
- 仓位管理模块（G1）、赋格状态机（G2）、区间套收敛排序（G3）是三大核心缺口
- K4 配置编码（G4）、三态分类（G5）、层0 监控（G6）是 K4 层面的信号缺口
- 摩擦成本参数（G7）、标的池扫描（G8）是操作层面的辅助缺口

**核心判断**：当前管线在**层 2 单标的内操作**（建仓买点 + 短差买卖点 + 止损 + 小转大）的结构信号上已基本完备。主要缺口集中在两个方向：(1) **操作编排层**（仓位管理 + 赋格状态机 + 策略执行）；(2) **层 0/层 1 的跨标的选股链路**（K4 配置编码 + 区间套收敛排序 + 标的池扫描）。

### 3. 边界条件

- 本映射基于 338号 v2 的当前文本。若 267号后续版本新增操作规则，映射表需同步更新
- "管线有能力但未接通"（⚠️）的判断假设集成工作不需要修改引擎内部逻辑，只需要在编排层添加衔接代码。若集成过程中发现引擎接口不足，部分 ⚠️ 可能降级为 ❌
- 仓位管理模块（G1）和赋格状态机（G2）的开发复杂度标注为"高"，是因为它们涉及状态追踪 + 多循环并存 + 与结构信号的实时联动，不是简单的纯函数计算
- K4 相关缺口（G4/G5/G6）依赖 254号本体论定义的进一步工程化落地，可能需要谱系层面的补充定义

### 4. 下游推论

1. **开发优先级**：层 2 操作编排层（G1 仓位管理 + I1 小转大编排）是最直接的下一步——当前管线在单标的信号上已基本完备，缺的是"信号 → 操作决策 → 仓位变动"的闭环
2. **K4 层面的信号缺口**（G4/G5/G6）可以独立于操作编排层开发，属于层 0/层 1 的基础设施
3. **区间套收敛排序**（G3）是最复杂的缺口，涉及跨标的、跨层级的编排，且 267号标注收敛紧度量化"待定义"——需要先在谱系层面完成定义
4. **赋格状态机**（G2）被 267号标注为"待形式化"——开发前需要谱系层面的状态机定义
