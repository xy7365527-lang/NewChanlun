## 五、关键路径分析

### 关键路径 1：穿越基础设施（当前最活跃的工程路径）

```
312号裁定 → W14概念注册表 → W15 Morse地形 → (W16查询接口 ∥ W17偶遇记录) → W4完整交付
```

这是312号谱系裁定的直接下游。参数已全部确定（时序Kruskal、862临界边、997概念全量、tie-breaking规则）。四个组件的依赖链是 四→三→(一,二)。

**当前状态**：
- `concept_extractor.py` 已存在，需要按312号裁定改造导出格式
- `topology_scan.py`、`topology_operator.py` 已存在，是 Morse 地形的潜在基础
- `block_topology.py`、`migrate_to_block_topology.py` 是区块拓扑核心脚本
- 区块数：1026（blocks 目录），关系数：5200（relations.jsonl）

### 关键路径 2：核心回路闭合（最长依赖链）

```
W6缠论识别 → W8回测验证 → W9实盘接入 → W10 OpenClaw → W21本地模型 → W22分布式化 → ...
```

这是总方针八.七节"落地路径"的主线。**这是系统中最长的依赖链**——从识别层到编排者退出，每一步都严格依赖前一步。但：
- W6（缠论识别层）和 W4（穿越基础设施）之间**无依赖**——可以并行
- W8（回测）验证的是"区块拓扑结构能否承载核心回路"，这与 W4 有关但不阻塞
- W9→W10→W21→W22 是严格串行的——实盘利润是后续一切的物质条件

### 关键路径 3：知识谱系独立化

```
W1谱系积累 → W11评估触发条件 → 知识谱系独立运行（条目71）
```

312条谱系中已有大量属于知识谱系的内容（概念分离、形式化讨论、拓扑理论研究等）。条目71的触发条件是"理论问题积累到无法仅作为交易谱系的附注存在"。**这个条件可能已经接近满足**——当前谱系中知识谱系内容远多于交易谱系内容（交易谱系几乎为零，因为实盘尚未接入）。
